Workers message each other with `sendMessage({ to, text, inReplyTo? })` and hear one through the `onMessageReceived` entry, which `hireWorkforce` now requires on every worker flow on an installation (FIX-2238). A received message lands as a history line plus its own client item (`workforce:received`, with `from`, `id` and `inReplyTo`), and nothing is relayed: a worker answers by sending a message with `inReplyTo`, and its plain text reaches no one. An answer lands in the session its original was sent from, and a message to the worker that filed the sender's task lands in the filing conversation. One budget covers a typed message: 6 messages in all, 3 per request. A task filed held starts a fresh budget when released, and filing or a refused send spends nothing. Coordinators can be messaged whatever their routing, and a worker that hears only in its tasks' sessions (`hears: "task-sessions"`) is refused by name with `task_sessions_only`.

**Migration.** `messageWorker` is now `sendMessage`. `onWorkerMessage` is now `onMessageReceived`; build it with `messageReceivedEntry({ installation, flowKind, turn?, hears? })` (or spread the session kit's `entries`), and add `workerMessagesResources` to a flow without the kit. `replyTo` is now `inReplyTo`. The removed exports are `MESSAGE_WORKER_TOOL`, `WORKER_MESSAGE_ENTRY`, `messageWorkerInputSchema`, `sendWorkerMessage`, `SendWorkerMessage` and `takesWorkerMessages`, and the new ones are `SEND_MESSAGE_TOOL`, `MESSAGE_RECEIVED_ENTRY`, `RECEIVED_MESSAGE_COMPONENT`, `sendMessageInputSchema`, `sendMessage` and `SendMessageInput`. The refusals `takes_tasks_only` and `no_turn` are gone, `hop_limit` is now `budget`, and `per_turn_limit` is now `per_request_limit`. A message row no longer carries `answerTo`.
