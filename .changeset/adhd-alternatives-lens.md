Internal (skills/process): a divergent-ideation skill, wired in as `review`'s triggered alternatives lens and as `issue-spec`'s answer to a stalled necessity check.

**The gap.** Every review lens we have judges a candidate that already exists. Coherence asks whether it fits, restraint asks whether it should exist, correctness asks whether it works, completeness asks whether it's finished. `prototype` and `settle-claim` both operate on candidates you already hold — one because you can't pick between them, one because two parties disagree about a fact. Nothing generated the set. The failure mode that leaves is invisible by construction: a spec that weighed two shapes which were variations of the same idea, reviewed by four lenses that each confirmed it was a good instance of that idea. `issue-spec` Step 3.5 names the symptom directly — being stuck between *build* and *don't build*, with instructions to look for "the third move" — and then offers no instrument for finding one.

**The skill.** `adhd` adapts the MIT-licensed method from [UditAkhourii/adhd](https://github.com/UditAkhourii/adhd): fan out N isolated sub-agents, one per cognitive frame, under a hard instruction to generate without evaluating and to skip the first three obvious answers; then a separate critic pass scores on novelty/viability/fit, flags traps, clusters by underlying angle, and deepens the top three into sketches with a load-bearing risk and a first step. The load-bearing constraint is isolation — branches that see each other anchor each other, and the method collapses into one wider thought, so simulating the branches sequentially in one context is not running the skill. Four FSD frames join the fourteen general ones: **subtract-then-add** (what existing primitive, sharpened, dissolves this — tenet 2), **user-space only** (solve it with escape hatches, no framework change), **wrong block kind** (re-pose as a different kind, a capability, a resource, a scope, an item type), and **the trace** (design backwards from what shows up in the stream). The upstream CLI and library are deliberately not a dependency; the Agent tool runs the same loop.

**Two entries, two convergence gates.** In **spec context** it fires on the Step 3.5 stall and on a Step 4 design question where the candidates all feel like one idea — the cheapest possible moment, since no code exists yet. Survivors go back through Step 3.5's necessity bar rather than around it: an alternative that adds public surface clears the same normalization/observability/composition/vocabulary test as the original ask. Step 4 now also separates the two instruments explicitly — can't pick between named candidates is `prototype`, suspect the candidates aren't the only ones is `adhd`, and running them in that order wastes a day. In **review context** it is scoped to alternative shapes only, and gated by a switch test: materially different shape · concretely describable · wins on a named axis · switch cost stated honestly. Findings are **notes, never must-fix** — the code already shipped, so the lens informs the next change; an alternative that exists because the current shape is broken belongs to the correctness or coherence lens instead.

**Triggered, not standing.** At ~10 sub-agent calls it is 5–10x a normal lens, and after implementation most alternatives are expensive regret. `review` adds it only on request or when the change is genuinely shape-open — new public API surface, a new pattern/capability/block kind, a schema or scope decision, or a spec whose §3 weighed no real alternative. Bug fixes, mechanical refactors, and changes implementing a settled spec design don't get it.

**Kept separate from restraint on purpose.** `second-look`'s calibration gate drops any candidate that adds surface and its red-flag list kills "could be more flexible" on sight — which is most of what divergence produces. Folded into one lens the critic strangles the generator and both get worse, so `second-look` keeps its removal bias unhedged and gains only a lane note pointing at the new skill.
