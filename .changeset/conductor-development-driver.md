Internal: `@flow-state-dev/conductor` (private, unpublished) — a deterministic driver that runs a software development process, dispatching the coding work to a vendor harness. No published surface changes.

What the package is:

- **An entity model and a pure driver.** `decide` maps an entity kind, a signal and a world to actions; `reconcile` turns an observation into the signals that feed it. Neither reads the network or the disk, so every transition is a function call you can re-run — and every ledger row replays to the action it records when `decide` runs again from the row's own arguments.
- **A tick runtime.** `openConductor({ config, statePath })` returns a session with `manage`, `tick` and `read`. A tick reads the world, reduces each signal through `decide`, provisions and runs the phase work the actions call for, and appends the ledger. A tick against an unchanged world appends no row and dispatches nothing, and re-opening over the same `statePath` loses no gate, moves no phase and repeats no dispatch.
- **An observer seam.** `Observer` is how the world is read — `{ source, observe(request) }` — with nothing GitHub-shaped in it. Two implementations ship. GitHub reads a repository from the host its remote names, `api.github.com` or an Enterprise `/api/v3` (LAB-86). A local source reads a real git checkout, taking reviews, comments and check conclusions from files under `.conductor/local/`; it is exported at `@flow-state-dev/conductor/local`, and it is how the whole process runs with no credential, no issues burned and no pull requests opened.
- **A dispatch seam.** `Dispatcher` is how work gets done. Every workspace is cut off a remote-tracking ref, never a local branch, so parallel worktrees cannot collide on a shared ref.
- **A phase and gate table.** Each phase declares the artifact it works on, what completes it, and which gates hold it. The tick derives the outstanding gate on every pass rather than storing one.
- **A goal check conductor runs itself** (LAB-66). Declare the command that proves a work item and conductor appends the item's id, runs it with no shell, and reads the exit status — nothing it prints is read. The command is declared and never discovered, and a phase brief carries it outward only, so a dispatched agent can run the same check but cannot change which one runs. A command that could not run at all claims no verdict and asks a human, rather than reporting a broken runner as work that failed. A project that declares none proves nothing, and its issues are not held on proving it.

What it guarantees:

**A proof names the revision it was taken against and the ground it stood on.** A bare verdict reads as *this change was proved*, which is only ever true of the revision the check ran on. Conductor stores the verdict beside its SHA and its ground — `"branch"` for *this change does what the issue asked*, `"base"` for *what landed does what the issue asked* — and every implementation gate reads the standing verdict, so a head that moved with no dispatch behind it retires the proof instead of sailing under it. A human pushing one more commit is the ordinary case. The second ground is not implied by the first, because a merge can squash, resolve a conflict, or land on a base that moved, so what landed is re-proved rather than assumed. A verdict with no revision reads as not proved. And a workspace conductor re-enters is scrubbed before anything is checked out into it, so a check cannot pass against uncommitted leftovers that exist in no revision (LAB-107).

**An abandoned change escalates instead of settling.** An implementation PR closed without merging is not a finished issue. Completion accepts a merge, or no pull request at all — the nested multi-PR shape hosts its implementation at a file and has no merge of its own — and a closure reaches a human rather than quietly settling the entity, where every later signal would be absorbed. This is deliberately not the rule `SPEC` uses: there, closing the PR unmerged *is* the process.

**Feedback is answered exactly once.** A comment leaves the queue only when the ledger holds its reduction and the pass that reduction bought has settled, so a process killed between dispatching and persisting its cursor buys no second paid agent run over feedback already answered — and a row whose dispatch never ran leaves the comment outstanding rather than silently answered. A comment is identified by the pair of stream and id, because GitHub's two comment endpoints number independently and one pull request can carry the same number twice. A review round is counted only for a dispatch that actually ran, so the round budget that parks a stuck review is not spent by a harness that never started (LAB-111), and a dispatch that does fail escalates with the reason the dispatcher reported (LAB-112).
