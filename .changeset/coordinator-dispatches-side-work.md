Internal (skills/process): a lifecycle coordinator no longer does side work in its own session — including work the user hands it directly mid-run (FIX-1072).

The grounding already stopped a coordinator working on a **PR event** (`orchestration.md` → "PR events are wake signals, not work items"). It said nothing about the **user** channel, and that is the one that gets through: "fix this typo", "check whether that helper exists", "run the tests" doesn't look like an event, so the event rule never fires on it, and the harness's default posture — be useful, act — wins. An `epic-lifecycle` run reported handling every such request itself and believed it had been told to. It had not been told otherwise.

New canonical section **"The coordinator dispatches; it never does the work"** in `docs/contributing/orchestration.md`, on the framing that a request from the user is an instruction about *what* happens, not about *who* does it. It carries the closed list of what a coordinator touches with its own hands (`.orchestration/`, subscriptions, the Linear mirror, surfacing gates, dispatching, ending the turn, and answering from the table it already holds), a routing table for everything else — status answered directly, a read-only look to `scout`, a change an issue in the set owns onto that row's next dispatch, a change nothing owns to `issue-manager`, anything else to a bounded `isolation: worktree` sub-agent — and what doing it yourself actually costs. The severe cost is not tokens: work done in the coordinator bypasses every gate the lifecycle exists to enforce and lands on a branch no issue tracks, racing the worktrees doing the real work. An explicit user override stays available and costs one stated sentence.

`epic-lifecycle` and `issue-lifecycle` each gain a short "Your requests are dispatched too" delta pointing at it — the epic's is that the status table is the first place to look, since most side requests are about a file some row already owns, and that a dispatch here is always a worktree; the issue's is that the in-flight worker's branch is not the orchestrator's to edit from. `AGENTS.md`'s orchestration-reference note gains it as a third rule worth knowing without opening the doc.
