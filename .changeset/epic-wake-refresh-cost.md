Internal (orchestration tooling, FIX-1027): the epic wake stops paying for refresh scans that cannot change an answer.

One real wake dispatched **12 agents** and spent **5 of them refreshing rows it then refused to dispatch** — every one parked behind an unresolved `blocker`. About 40% of the spend, by construction, on reads nothing could act on. A wake that fails costs roughly 489k sub-agent tokens and returns nothing, so per-wake cost is what decides whether an epic can run at all. On that same shape `epic-wake` now dispatches **3**.

**Rows that cannot be dispatched get no scan.** `pendingAction` parks a row carrying an unresolved human decision, and parks a terminal one with nothing left to apply, *before* it reads a single scan-derived field — so `noScanNeeded` asks that question up front and those rows are carried forward verbatim. It has to decide from the carried row, because the Linear children query runs in the same barrier as the scan; that query is not per-row and stays, so blocked-ness, cancellation, Linear state and the route still refresh for every row either way.

The distinction that makes it safe is that **"carried forward on purpose" and "the scan never reached it" are now separate states**, not one absent map entry. The second voids every scan-derived field, because a read that did not happen is not evidence they still hold. The first applies the row verbatim, because nothing looked at it and nothing contradicted it. Folding them together would drop `specApproved` on a parked row — which decides membership of the cross-spec set, whose two halves deadlock the epic whenever they disagree about who is still coming.

Three things deliberately keep their scan, each because skipping them would be permanent rather than merely late: a **`closedBlocker`** (an observation, not an escalation — it clears when a scan sees the PR reopened, which is the recovery its own text advertises); a **terminal row with a landed verdict or an answered decision** (`pendingAction` still dispatches those); and **anything another row is blocked by**, since `openBlockers` clears a relation only on live merge evidence and reads a missing scan as "unobserved". The terminal test is keyed on `linearTerminal` rather than the carried phase, because only a scan moves a phase off DONE — keying on the phase would make the skip self-sustaining and a reopened issue would never be looked at again.

**One batched scan replaces one scout per issue.** Ten agents each reading one PR is the same information as one agent reading ten. The per-issue rules were the bulk of each prompt (the approval channels, the change-request veto, the owner-label provenance check), so stating them once makes the batched prompt smaller than the ones it replaces; the per-issue part is just handles and that issue's own activity cursor, which stays per-row because it is how a row tells new feedback from feedback a worker already handled.

Batching moves failure from per-row to per-batch, and that had to land on the safe side. A dead scan means **nothing was observed for any row it covered** — carried state stands, no cursor advances, no blocker clears — never "ten rows confirmed unchanged". Since a batch has no per-row null to return, each entry now carries a required `observed` flag: a scan that ran out of room reports the issues it never reached as unobserved, and those are discarded exactly as a dead scout's result was. Results bind **by position** with the reported `issueId` as a cross-check only; keying on the reported name is the natural thing to do with an array that names its entries and is precisely what would let one issue's approval land on another row's gate.

Evidence: `node .agents/workflows/verify.mjs` at 283/283 (was 274), with ten new checks. Every new guard was mutation-verified — stubbed out, suite confirmed red, restored — and that surfaced two things worth keeping: the batch's `observed` filter was initially pinned by a fixture that could not fail, and the phase-enum invariant was searching a fixed 1600-character window of each schema, so it reported the constraint missing the moment a property was added above it. It now reads the whole declaration.
