A session, user or org field that a block or capability declares with a default now reads as that default on a fresh or older record, with no restating on the flow (FIX-2576). Three upgrade refusals come with it. `defineFlow` throws when two declarations of one field (the flow's, a block's, a capability's) differ in type or default, naming the field and both declarers. It also throws on a default factory (`.default(() => ...)`) that would never run: one a block or capability declares that isn't the flow's own session factory, and any in user or org state, the flow's own schema included. Use a static default, or declare the factory on the flow's session schema. Reads now fill static defaults only and never run a factory, so a stored record always reads the same value: a factory default runs only when a new session is born. The one behaviour change from before: a stored session that lacks a field the flow defaults with a factory reads that field as missing, where it used to read a fresh value on every read. The server refuses to start when two flows type or default a shared user or org field differently. `hireWorkforce` no longer requires a manager flow to spread the board's `sessionStateShape` into its session schema.
