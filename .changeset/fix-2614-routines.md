Routines: one name, list and tool set for everything that fires on its own as a user (FIX-2614). A routine has one trigger: a clock (a schedule that files a task) or an event (a subscription to one thread). Stored schedules and subscriptions don't change.

- **workforce:** four verbs over both triggers, as roster-flow actions for the user and as a worker's tools: `listRoutines`, `saveRoutine({ name?, trigger: { clock } | { event }, task?, worker?, description? })`, `pauseRoutine({ id, paused })` and `deleteRoutine({ id })`, named by `ROUTINE_VERBS` and `LIST_ROUTINES_ACTION`. A routine's id is `clock:<key>` or `event:<subscription id>`. Each listed routine (`listedRoutineSchema`, `ListedRoutine`, also from `./browser`) says who made it (`madeBy`, `routineMakerSchema` / `RoutineMaker`: the user, a worker, or the app). A paused event routine leaves the thread index; a resume turns it back on from its saved subscription, checking read access, and keeps its task and tenant. The user reaches all their routines; a worker reaches only the ones that act through it (`not_yours`).
- **workforce:** `routineTools({ providers, index? })` replaces `subscriptionTools`; `hireWorkforce`'s `routines: { index?, providers?, declared? }` (`RoutinesOptions`) replaces `schedules: { index }`. `listedRoutineSchema` and `LIST_ROUTINES_ACTION` replace `listedScheduleSchema` and `LIST_SCHEDULES_ACTION`. The roster's `saveSchedule`, `listSchedules` and `deleteSchedule` are gone, with no aliases.
- **workforce:** `routines.declared` (`DeclaredRoutine[]`): the app's own routines, seeded into each user's collections when their roster flow runs a request (or only an entry's `owner`'s), under `declaredRoutineKey(entryId)` and written only when missing or changed. The user may pause one; save and delete refuse with `declared`. A config change keeps the pause. `hireWorkforce` throws on an entry that would never fire. `everyMinutes` must be one of `ROUTINE_CADENCES` (5, 10, 15, 20, 30, 60); a pushed provider ignores it.
- **workforce:** `subscribe(ctx, providers, input, target?, write?)` takes an optional server-side `SubscribeTarget` `{ sessionId, flow, worker, taskId?, tenantId? }` and `SubscribeWrite` `{ id?, madeBy? }`. Every subscription write and end (`subscribe`, `unsubscribe`, a task's ending) is now decided on the saved subscription: an end other than a pause is final until a fresh `subscribe`, and the thread index holds a subscription only while it is on, under a slot that names its owner. A task's failure or cancel also ends its paused subscriptions. Delivery re-runs the screens on the saved subscription and takes out an index entry it no longer backs. A delivery to a user's not-yet-open conversation with a worker opens it.
- **scheduled:** a schedule takes an optional `metadata` record, kept and never read by the resolver, the index or dispatch.
- **shift-manager:** *Scheduled work* is now **Routines** (`/routines`; `/schedules` still opens it): clock and event routines in one list, each with its maker, paused, resumed or deleted from its line. An app's routine can only be paused.
