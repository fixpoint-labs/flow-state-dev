Add `fsdev conductor` — a terminal operator surface for a `kind: "conductor"` flow. Open a live board whose transcript follows the action you ran, the selected row's request stream (tool calls named with the file or command they touched, kept on the live line while the call is still open, a compact hunk when a Write or Edit carries the new text, a checklist when a plan tool carries one, the first lines of a Read, and the last lines of a Bash, Grep, or Glob result once the tool finishes), and the row changes `status` reports, or run the same verbs headless (`seed`, `wake`, `status`, `answer`, `watch`, `abort`). The follow stays on the journal after the row leaves the running set, so the last hunks and the final message still land. Opening the board, or moving onto a finished row, catch-up that attempt from the store. A named `status ISSUE` or a `watch` that exits on a finished row reprints that attempt the same way. After a row settles, the board still shows that attempt's files, todo list, last tool, request id, and pull-request URL when `status` carried one. A supporting terminal can open that URL, and a Write / Edit / Read path, via OSC-8. Headless `status` and `watch` print the request id, branch, checkout, token counts, spend, last message, and pull-request URL the same way. A named issue also prints that attempt's last tool, files, last hunk, and current todo on stdout. An open question keeps a compact strip of that attempt (files, current todo, last tool, pull-request URL, token counts) under the ASK band. A failed attempt keeps that same strip under the FAIL band. You can change rows, start an answer, and type while a wake or seed is in flight. Enter queues that next action and runs it when the current one finishes. A long path keeps the filename when the checkout prefix will not fit. Each request keeps the newest two thousand transcript lines while another row is selected, so another row's tools do not wipe this one's. The selected attempt stays whole, and selecting a finished row reloads that journal, so `/find` can still match an early tool. The todo strip follows `TaskCreate` / `TaskUpdate` (and still reads a `TodoWrite` snapshot). A running row shows its checkout, what it is doing now, how long since it last wrote (`8s`, `3m` — rust after 30 seconds), the files that run has written, edited, or read, the last Write or Edit hunk, a Read peek when Read is still the last tool, the last Bash / Grep / Glob lines when that tool is still last, and the current todo on the RUN band (`t` expands the list, `h` expands the hunk); `x` or `Ctrl-C` stops that request. Every running row shows that current action in the ASK column when no question is open, so two live children are visible without selecting each one. A child's reasoning is a compact `think ·` line on the transcript and in that ASK column — including after the think line has committed, so ASK does not go blank before the first tool. `e` expands the last Read peek or Bash / Grep / Glob tail (three lines, or sixteen). Headless `--json` adds `now`, `files`, `hunk`, and `todo` on the same rows the text print loads (running journals on a full-board verb; the named attempt otherwise). When `status` already carries token counts on a running row, those counts (`12.0k→400`) replace the redundant `running` outcome on the board. Lab usage is written after the child returns, so a live implement usually still shows `running` until it settles. A target checkout missing the `.fsdev/` ignore rule is healed on that work branch so the run can start; the RUN band names what was repaired. Running `fsdev conductor` from a directory that has no `kind: "conductor"` flow says to `cd labs/conductor` or pass `--config` — that hint is the first line; import failures from other apps in the same repo stay off the page. At 80 columns that column still fits a tool and filename (`Write src/a.ts`). `}` / `{` jump to the next or previous row that is waiting on you, whose last attempt failed, or whose running child has gone silent. Headless `status` and `watch` print that same last-write age on a running row. A full-board `status` also prints each running row's current action on ASK (a named issue still prints last tool, files, hunk, and todo; settled journals stay off the full-board print). `wake`, `seed`, and `abort` reprints use the same ASK rule. Opening the board on an issue selects that row once; later polls keep whichever row you moved to. `/status ISSUE` in the board selects that row. `/find` searches the selected row's transcript (`n` / `N` step through matches). The footer offers `/find` and `r` on the board. `f` expands the file list (up to twelve paths). `h` expands the last hunk (up to sixteen changed lines). `H` steps to an older file's hunk on the same run. A settled row shows that attempt's session and child session ids. Tools that run while a sub-agent is open are indented under that `sub ·` line. A slash line lists matching verbs, then board issue or question ids after a space; Tab completes the selected one. An answer keeps its punctuation — `don't` stays `don't`, and `--` lets a reply mention `--json`. Every verb is a flow action except `abort`, which uses the same request abort the HTTP route already exposes. The board is whatever `status` returns. Type anything that is not a slash verb to talk to the coordinator (`steer`) — it sees the board and may file, wake, or answer; it does not implement. Opening the board still needs no model. A talk turn prints `you ·` for what you typed, and a long compose line keeps the end you are typing. While composing, ↑/↓ walk prior talk, answer, and seed lines (and move between wrapped lines first), ←/→ move in the line, Ctrl-J / Alt-Enter / Shift-Enter insert a new line, and a bracketed paste inserts without sending. Idle arrows still move rows or questions. An implement run now uses the workspace-agent chain on its checkout, so Bash writes the tree the board is watching and cannot relocate into a different worktree. (LAB-151)
