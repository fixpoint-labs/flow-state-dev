Add `fsdev conductor` — a terminal operator surface for a `kind: "conductor"` flow. Open a live board whose transcript follows the action you ran, the selected row's request stream (tool calls named with the file or command they touched, kept on the live line while the call is still open, a compact hunk when a Write or Edit carries the new text, a checklist when a plan tool carries one, the first lines of a Read, and the last lines of a Bash, Grep, or Glob result once the tool finishes), and the row changes `status` reports, or run the same verbs headless (`seed`, `wake`, `status`, `answer`, `watch`, `abort`). The follow stays on the journal after the row leaves the running set, so the last hunks and the final message still land. Opening the board, or moving onto a finished row, catch-up that attempt from the store. A named `status ISSUE` or a `watch` that exits on a finished row reprints that attempt the same way. After a row settles, the board still shows that attempt's files, todo list, last tool, request id, and pull-request URL when `status` carried one. Headless `status` and `watch` print the request id, branch, and pull-request URL the same way. An open question keeps a compact strip of that attempt (files, current todo, last tool, pull-request URL) under the ASK band. You can change rows while a wake or seed is in flight; those keys do not start another action. A long path keeps the filename when the checkout prefix will not fit. Each request keeps the newest two thousand transcript lines while another row is selected, so another row's tools do not wipe this one's. The selected attempt stays whole, and selecting a finished row reloads that journal, so `/find` can still match an early tool. The todo strip follows `TaskCreate` / `TaskUpdate` (and still reads a `TodoWrite` snapshot). A running row shows its checkout, what it is doing now, the files that run has written, edited, or read, and the current todo on the RUN band (`t` expands the list); `x` or `Ctrl-C` stops that request. Opening the board on an issue selects that row once; later polls keep whichever row you moved to. `/status ISSUE` in the board selects that row. `/find` searches the selected row's transcript (`n` / `N` step through matches). The footer offers `/find` and `r` on the board. A settled row shows that attempt's session and child session ids. Tools that run while a sub-agent is open are indented under that `sub ·` line. A slash line lists matching verbs, then board issue or question ids after a space; Tab completes the selected one. An answer keeps its punctuation — `don't` stays `don't`, and `--` lets a reply mention `--json`. Every verb is a flow action except `abort`, which uses the same request abort the HTTP route already exposes. The board is whatever `status` returns. (LAB-151)
