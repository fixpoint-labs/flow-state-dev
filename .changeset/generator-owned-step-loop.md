Generators now own their multi-step tool loop when the model supports single-step calls. `GeneratorModel` gains optional `generateStep`/`streamStep` methods (implemented by the built-in AI-SDK adapter and `createFallbackModel` groups): the framework makes one provider call per step, executes framework tools itself (same executor, cache, retry, and `tool_output` behavior as before), and threads results between steps — with raw provider response messages carried across steps so reasoning/thinking content round-trips. Models without the step methods (test mocks, older custom adapters) keep the existing SDK-driven loop unchanged. Behavior-preserving: same items, outputs, and aggregate usage; per-call tool messages replace the SDK's single multi-part tool message between steps, and `prepareStep.activeTools` now matches framework tool names (previously sanitized dictionary keys, which silently missed namespaced tools). Loop ownership is the substrate for suspending inside a generator's tool loop, which lands separately. New shared helpers: `computeToolAliases` (colliding tool names stay distinct in the model dictionary) and core-level LLM message builders reused by the engine's history conversion.
