Trusted GitHub reviewers come from one stored list, with `GITHUB_REVIEWERS` as its default (FIX-2873). A coding run acts only on comments from an account on that list: a listed bot, or a listed user who can also push to the repository.

- **workforce:** `githubTrustedReviewers({ operator, judgeModel })` builds the list a host installs. It reads `GITHUB_REVIEWERS` (comma-separated, a bot as `name[bot]`) once, when it is called, as the `github-reviewers` document's default. The default holds only until the list is first saved. After that the saved list wins, an empty one included, so emptying it stops all steering. It returns the `document`, a `read(ctx)` of the listed accounts, the `tool` that is the list's only writer, the same tool as a `capability` (`githubReviewers`, preset `tool`) for a worker that picks it under `capabilities:`, and `follow(github)`, the follower to hand the harness kit's `onPullRequestRecorded`.
- **workforce:** `setGitHubReviewers`, the tool, changes the list only on the operator's own typed message naming each account, after an evaluator reads that message, and after the operator approves the exact change in Inbox. No HTTP action writes the list.
- **workforce:** `operatorGitHub` takes `reviewers`, which declares the list's custom screen on the provider, and `interestModel`, the model a routine's `interest` screen is judged on.
- **workforce:** `githubTrustedReviewersScreen` now passes a listed bot (`name[bot]` in the list) without asking GitHub, and still asks GitHub whether a listed user can write. A bot is matched only against listed bots, and anyone else only against listed people, so a user who registers a listed bot's name isn't heard as that bot. `githubLoginsListed` keeps a bot's `[bot]`. `githubReviewersDocument(logins)` builds the document's body.
- **workforce:** a listed bot is heard only on the follow the list builds. `followPullRequest` takes `botsScreenedBy`, the custom screen a bot sender is handed on to past the sender screen. It must be one of the follow's `screens`, or the follow is refused. A model's `subscribe` can't set it, and a later write that doesn't list that screen drops it. The service flow's `trustedBots` is unchanged and stays service-wide.
- **shift-manager:** the trusted reviewers are workforce's list. Set `GITHUB_REVIEWERS` for the default: the folder's `github-reviewers.md` and its seeded login are gone, so with the setting unset, nobody is heard until the list is saved. A list already saved reads as it was. Listed bots are now heard. The public `setGitHubReviewers` action is gone; the Shift Coordinator's tool is the only way to change the list.
