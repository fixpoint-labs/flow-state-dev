Internal (skills/process): the mechanical half of the two orchestration lifecycles moves from prose into deterministic workflow scripts under a new `.agents/workflows/` directory (`.claude/workflows` symlinked, matching how `.agents/skills` already works).

**`epic-wake` is now one epic-lifecycle wake.** The coordinator's refresh → advance → collect steps were pure procedure it had to re-derive correctly every wake: the objective gate that holds the whole set, a two-round review budget with one conditional third round, a concurrency cap shared between issue workers and POC settlements, and a claim dedupe. Those are now `if` statements in `.agents/workflows/epic-wake.js`, including a single `atReviewBudget()` that covers issue specs and the epic PR alike — previously the same arithmetic was restated three times across the two skills. The epic-PR fold (`epic-agent`) runs under that same budget rather than a separately-tracked counter. `epic-lifecycle`'s loop drops from six steps to five and no longer restates the budget, cap, or dedupe mechanics.

**`issue-multi-pr` is now one step of a multi-PR issue's DAG.** Ready-set derivation, base selection (a sub-PR whose deps are all merged bases on fresh `origin/main`; one whose single dep is merely open stacks on that dep's branch so review can start early; two open deps are waited on rather than stacked arbitrarily), the rebase a merged dependency forces, and the assembled end-to-end goal that the last merge does *not* satisfy — all encoded rather than described. Single-PR issues are a one-node plan and deliberately don't use it.

**The split is fixed by what a workflow script cannot do:** it has no user prompting, cannot receive a PR webhook, cannot sleep or schedule, and has no filesystem. So every gate (spec approval, epic objective, merge), every PR subscription, the `.orchestration/` store, and turn-ending stay with the coordinator, which passes state in via `args` and persists what comes back. Documented once in `docs/contributing/orchestration.md` → "The pieces at a glance" and in `epic-lifecycle` → "Each wake is a workflow".

**Canonical rules stay in `orchestration.md`, which also now documents the workflow-script contract** (the injected `agent`/`parallel`/`pipeline`/`log`/`phase` API, the no-imports/no-filesystem/no-clock limits, and the fact that `verify.mjs` is a local mirror of that contract rather than proof of it). The scripts are an executable second implementation at the epic altitude; standalone `issue-lifecycle` still applies the same rules as written. Both skills say so, so a rule change goes to the doc first and then to both.

To be precise about what the dedup bought: the *arithmetic* consolidated — one `atReviewBudget()` replaces three prose restatements — while the *narration* only partly did. The skills still describe what the scripts decide (a coordinator has to know), and the scripts carry short pointers to the canonical sections rather than restating them. A rule change is now a doc edit plus two implementations, not five prose sites.

Two limits are recorded rather than papered over: a workflow's own concurrency ceiling is `min(16, cores − 2)` — 2 on a 4-vCPU cloud session, below the 3–4 active issues `epic-lifecycle` recommends, so queueing is expected and logged rather than silent; and whether a workflow consumes one of Claude Code's 5 agent-depth levels is untested, with the existing in-context mitigation noted if a real run hits it.

Both scripts **fail closed**, because the coordinator is their only memory and a script that guesses corrupts state it can't re-read. Two invariants carry that, stated in both file headers:

**A null agent result means nothing happened.** `agent()` returns `null` when a sub-agent dies or is skipped — infrastructure failure, not an outcome. So a dead POC agent requeues its claim instead of recording a fabricated `INCONCLUSIVE` (the "false evidence" `orchestration.md` explicitly forbids); a dead assembled-goal agent retries instead of filing a phantom Linear gap and repair PR; a dead folding worker leaves the verdict on the row rather than consuming it; and a rebase returning anything but success keeps both its `open` status and its stack marker so the retry is still scheduled.

**Never advance a cursor past work that didn't happen.** An activity cursor moves only when the wake actually consumed that activity — a worker ran *and* returned. A row the cap deferred keeps its old cursor, or the feedback just logged as "deferred to the next wake" would read as already-handled and vanish. The cursor is a **timestamp**, not just a head SHA, since a comment never moves the SHA.

The assemble phase is an explicit **state machine** (`NEEDS_GOAL → NEEDS_GAP → NEEDS_FIX → AWAITING_FIX`, with a merged repair returning to `NEEDS_GOAL` because a landed fix still has to be proven), and the per-row update in `epic-wake` is a single named `nextRow()`. Both replaced ad-hoc predicates and inline ternaries that produced opposite bugs in successive passes — first re-running work and filing duplicates, then blocking the rerun while dispatching no retry either. Enumerating the states is what makes "resume at the stage you reached" checkable rather than incidental.

**A row or sub-PR carrying an unresolved `blocker` is parked**, in both scripts. A worker that escalated a decision is waiting on a human, so re-dispatching it on the next unrelated event would either retry the dead end or push the worker to invent the answer at the fork it was told to escalate. The coordinator clears the field when it records the resolution — and the skill says so, because a `blocker` left set stalls the issue for good.

Also failing closed: a sub-PR declaring an unknown dependency is refused rather than treated as dependency-free; a node with a mix of merged and open dependencies waits rather than stacking on a base that may predate the merged one; a dead epic-gate scout reads as "not approved"; a carried `blockedBy` survives a failed Linear refresh; and a repair already in flight — by PR *or* by filed issue — blocks re-running a failed assembled goal.

Verification: `node .agents/workflows/verify.mjs` runs both scripts with stubbed `agent`/`parallel`/`pipeline`/`log`/`phase` hooks and asserts 86 behaviours — the budget edge cases (a zero-round batch consuming nothing, the third round authorized once and a fourth refused), the epic gate dispatching nothing, the cap deferring by name, one claim settling once and fanning to both issues, and the DAG's base/rebase/assembled-goal decisions. No agents, network, or git access.

**Every schema field that gates an action is REQUIRED, not optional — and an invariant enforces it.** Six separate defects across three rounds came from the same shape: an optional boolean whose omission was defaulted the permissive way. `specApproved` was the worst — a live scan reporting a pushed head without restating approval let a carried `true` survive, implementing on a head the human never approved, which is the one gate that must never be bypassable. It is now required in the schema *and* taken only from a live scan. Likewise `issue-manager`'s `ready` verdict, and the epic's `aboveBarFound` third-round authorization.

**Five of those checks enumerate the input space rather than sampling it**, because six rounds of example-based review kept finding the same shape of defect: a state combination nobody wrote a case for, which stalls the lifecycle or silently consumes work. They assert that no assemble state is a dead end (a waiting state must wait on a handle a human can act on), that a parked row is never dispatched whatever else is true of it, that the activity cursor never advances past unconsumed activity, and that a dead worker mutates nothing but its cursor. The harness loads each script's `Rules (pure …)` region directly, so this needs no test hooks in the scripts. It also **validates every stub response against that agent's schema** — the real hook returns only validated objects, so a fixture the schema would reject describes a branch that cannot happen. Adding that check failed 11 previously-green tests whose fixtures omitted fields made required in later rounds; they assert something real now. All four were mutation-tested — reintroducing the exact bugs review found makes them fail.
