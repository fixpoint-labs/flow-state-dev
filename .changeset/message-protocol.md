One message protocol replaces Workstreams (FIX-1302). Every arrival at a flow — a caller's action, a chat event, a webhook, a schedule, a task hand-off, an internal dispatch — is a message of one type delivered to one entry addressed by `(type, name)`, with no fallback between types.

- **`defineFlow` gains `internal` and `tasks` entry maps.** `internal` entries are reachable only from a `dispatcher()` inside the flow; `tasks` entries are produced by a task board (`tasks: board.tasks`) and wrap each handed-off seat's worker in the board's claim gate. Both are definition-only, like the transport maps. Every entry, of every type, accepts its own `concurrency`.
- **`dispatcher()` is the block that sends.** `dispatcher({ name, type: "internal", target, session: { key } | { id }, payload? })` returns a handler carrying its static address, and `defineFlow` refuses an address the flow does not declare — through composition, rescue handlers, and a generator's static `tools`. `{ key }` derives a child session of the running one (minted, then adopted on the same key); `{ id }` delivers into an existing session of the same flow and principal and refuses an unknown id rather than creating one. A refusal throws `DispatchRefusedError` naming the refusal (`no-entry`, `session-not-found`, `session-not-addressable`, `key-occupied`, `no-dispatch-operation`, `dispatch-rejected`).
- **`.forEach()` and `.forEachSideChain()` accept `blocks`.** A per-item factory declares the blocks it can produce, so they are walked for dispatch addresses and merged for resources like a block-shaped call's element. A task board's drain uses it, which is what lets `defineFlow` refuse a flow that reaches a board with handed-off seats but never declares `tasks: board.tasks`.
- **Task boards hand off by seat.** `workers: { name: { worker, session: "per-task" | "per-worker" | { key: (task) => string } } }` replaces `dispatch: { mode: "detached" }`, which is now refused by name. The board's handle exposes `tasks` (declare them on the flow) and `handedOff`. A `task` message carries `{ boardId, taskId, attempt, createdAt, incarnationId?, payload }`, and the entry re-reads the row and verifies the claim before the worker runs.
- **Renames.** Workstream → child session: `GET /api/flows/sessions/:id/children` returns `{ children }` (`ChildSessionSummary`, `ChildSessionStatus`, `maxChildSessionListLimit`); `sharedToWorkstream` → `sharedToLineage`; a dispatched request records `metadata.dispatch = { type, target, from, key?, ... }` under `source: "internal"` or `"task"` instead of `metadata.workstream`. On the client, `listWorkstreams` → `listChildSessions` (`ListChildSessionsOptions`); in React, `useSession`'s `workstreams` option and result become `children` / `childrenStale` (`SessionChildrenOptions`); the DevTool's Workstreams tab is now **Children**, and it links a board row to its child by the child's `coordinate` (`"task:<seat>"`) and `topic`.
- **Removed.** `ctx.requestHost.startDetached` and `StartDetachedInput`, `workstreamBindings` on block definitions, `buildWorkstreamCore`, `flow.workstream`, and the `/workstreams` route. `RequestHost` keeps `parentTask()`, `settleParentTask()` and `livenessOf()`. The dispatch seam is not a named member of the block context: reach it with `dispatcher()`, or in substrate code with `dispatchThroughSeam` and `markDispatcher`.
- **`task` and `internal` messages can never be re-entered** from a public route: retry, continue and resume refuse them, and `publicReentrySources` cannot re-open them.
