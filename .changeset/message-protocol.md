One dispatch protocol replaces Workstreams (FIX-1302). Every arrival at a flow — a caller's action, a chat event, a webhook, a schedule, a task hand-off, an internal dispatch — is a dispatch of one type delivered to one entry addressed by `(type, name)`, with no fallback between types.

- **`defineFlow` gains `internal` and `tasks` entry maps.** Both are declared like actions — `{ name: { block, ...policy } }` — and are definition-only, like the transport maps. `internal` entries are reachable only from a `dispatcher()` inside the flow; `tasks` entries are reachable only from a `dispatcher({ type: "task" })` seat on a task board the flow reaches, and `defineFlow` puts each one behind that board's claim gate (the row re-read, the claim verified, the task scope marked, the ticket re-minted) before the block runs. A task entry no board addresses, a task dispatcher no board holds, and two boards addressing one entry are refused at definition. Every entry, of every type, accepts its own `concurrency`.
- **`dispatcher()` is the block that sends.** `dispatcher({ name, type: "internal", target, session: { key } | { id }, payload? })` (`InternalDispatcherConfig`) returns a handler carrying its static address, and `defineFlow` refuses an address the flow does not declare — through composition, rescue handlers, and a generator's static `tools`. `{ key }` derives a child session of the running one (minted, then adopted on the same key); `{ id }` delivers into an existing session of the same flow and principal and refuses an unknown id rather than creating one. A refusal throws `DispatchRefusedError` naming the refusal (`no-entry`, `session-not-found`, `session-not-addressable`, `key-occupied`, `no-dispatch-operation`, `dispatch-rejected`).
- **`.forEach()` and `.forEachSideChain()` accept `blocks`.** A per-item factory declares the blocks it can produce, so they are walked for dispatch addresses and merged for resources like a block-shaped call's element. A task board's drain uses it, which is what lets `defineFlow` refuse a flow that reaches a board with a hand-off seat but never declares the entry it addresses.
- **A task board hands off through a dispatcher seat.** A seat under `workers` is a block; a `dispatcher({ name, type: "task", target, session: "per-task" | "per-worker" | { key: (task) => string } })` (`TaskDispatcherConfig`) in that position hands the seat's rows off to `flow.tasks[target]` in the child session the policy names, and the flow declares the block that runs there: `tasks: { [target]: { block } }`. This replaces `dispatch: { mode: "detached" }` and the `{ worker, dispatch }` seat, both refused by name. The board's handle exposes `handedOff`. A `task` dispatch carries `{ boardId, seat, taskId, attempt, createdAt, incarnationId?, payload }` (`taskDispatchInputSchema`, `TaskDispatchInput` from core), and the entry's gate re-reads the row and verifies the claim before the block runs. `TaskSessionPolicy`, `taskSessionKeyFor`, `bindTaskDispatcher` and `taskBindingOf` are exported from core for substrate code.
- **Renames.** Workstream → child session: `GET /api/flows/sessions/:id/children` returns `{ children }` (`ChildSessionSummary`, `ChildSessionStatus`, `maxChildSessionListLimit`); `sharedToWorkstream` → `sharedToLineage`; a dispatched request records `metadata.dispatch = { type, target, from, key?, ... }` under `source: "internal"` or `"task"` instead of `metadata.workstream`. On the client, `listWorkstreams` → `listChildSessions` (`ListChildSessionsOptions`); in React, `useSession`'s `workstreams` option and result become `childSessions` / `childSessionsStale` (`SessionChildSessionsOptions`); the DevTool's Workstreams tab is now **Children**, and it links a board row to its child by the child's `coordinate` (`"task:<entry>"`, the seat's `target`) and `topic`, preferring the child whose entry is named like the row's assignee when several fit.
- **Removed.** `ctx.requestHost.startDetached` and `StartDetachedInput`, `workstreamBindings` on block definitions, `buildWorkstreamCore`, `flow.workstream`, and the `/workstreams` route. `RequestHost` keeps `parentTask()`, `settleParentTask()` and `livenessOf()`. The dispatch seam is not a named member of the block context: reach it with `dispatcher()`, or in substrate code with `dispatchThroughSeam` and `markDispatcher`.
- **`task` and `internal` dispatches can never be re-entered** from a public route: retry, continue and resume refuse them, and `publicReentrySources` cannot re-open them.
