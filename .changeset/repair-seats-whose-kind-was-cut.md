`createSeatHireBlocks` now also returns `brokenSeats` (the stored seats the start skips, each with a reason: `kind-gone`, `refused` or `unreadable`) and `rehire` (keep a seat that no longer starts at its address, on a kind you name). With `defineHiredRosterPrivateCollection()` mounted under the new `HIRED_ROSTER_PRIVATE_RESOURCE`, `fire`, `brokenSeats` and `rehire` also reach the caller's own user-owned seats. `fire` now deletes the seat's inventory row after the roster row and the address; called again for a seat whose roster row is gone, it removes a leftover inventory row marked `hired: true` and answers `alreadyGone: true`, and a roster row that can't be read is deleted by its key with `address: null`. Roster rows gain `pendingRepair`, set while a `rehire` is unfinished so the same call run again can finish it. Seat inventory rows gain `hired` (`true` for a runtime hire, `false` for a declared seat, `null` on an older row), written by `openInventory` and the hire. `removeHiredSeat` exports the removal for an app's own fire handler; `listedSeatRows`, `isHiredSeatRow` and `HIRED_ROSTER_BROWSER_PATTERN` (from `@flow-state-dev/workforce/browser`) are the team-list join that hides an inventory row no roster row backs, and the org roster's collection pattern (FIX-1621).
