Skills can now bind to one generator instead of a session-global bag. `createSkillsLibrary()` returns a capability you install once and bind per generator: `skills.config({ active })` preloads a skill's body (and its declared tools) into that generator, `skills.config({ allowed }).presets({ dynamicActivation: true })` installs a `runSkill` load tool the model can call mid-turn, and `skills.config({ activeState: { scope, field } })` chooses where dynamic activations live. By default a dynamic activation lives in the generator's own block state, so it stays private to that generator and does not carry into the next turn; a missing/typo'd `active` skill fails loud at build time, and fork/pattern skills are rejected from the inline binding. `createSkillActivator` gains `activeState` and `allowed` options so an up-front matcher can feed a binding through an explicit shared field scoped to that binding's allowed set. The existing `createSkillsCapability` session-global path is unchanged and still available.
