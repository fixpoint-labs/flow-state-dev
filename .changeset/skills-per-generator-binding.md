Skills can now bind to one generator instead of a session-global bag. `createSkillsLibrary()` returns a capability you install once and bind per generator with `.with({ ... })`: `skills.with({ active })` preloads a skill's body (and its declared tools) into that generator, `skills.with({ allowed, dynamicActivation: true })` installs an inline `loadSkill` tool the model can call mid-turn, and `skills.with({ activeState: { scope, field } })` chooses where dynamic activations live. By default a dynamic activation lives in the generator's own block state, so it stays private to that generator and does not carry into the next turn — and the binding installs that block-state field for you, so no hand-declared `stateSchema` is needed on the generator. A missing/typo'd `active` skill fails loud at build time, and fork/pattern skills are rejected from the inline binding. `createSkillActivator` gains `activeState` and `allowed` options so an up-front matcher can feed a binding through an explicit shared field scoped to that binding's allowed set. The existing `createSkillsCapability` session-global path is unchanged and still available.
