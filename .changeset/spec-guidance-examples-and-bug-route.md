Internal (skills/process): spec guidance becomes example-led at both altitudes, and bugs stop needing specs.

**The templates now demonstrate instead of describing.** `docs/contributing/spec-template.md` was ~300 lines of prose about what each section owes its reader — dense exactly where the guidance mattered most (§5 usage examples, §6 Decisions, §12/§13 formats). Every section is now one line of instruction followed by a **worked example of that section filled in**, all drawn from a single running issue so the template reads end to end as a real spec. The rules that can't be shown — authored in one pass, approval means directionally correct, the anti-addenda rule, the reviewer contract that gets pasted into the PR description — stay as prose, tightened.

**Epics get a template at all.** The epic-spec was four bullets inside `orchestration.md` while issue specs had a 300-line template, so the artifact that keeps a whole set of issues coherent had the least guidance of anything in the process. `docs/contributing/epic-spec-template.md` gives it the same treatment: purpose & objective (with the holistic necessity check), themes & long-horizon direction, running index, open cross-cutting questions — each with a worked example — plus its own reviewer contract and evolution timeline. `orchestration.md` now points at it rather than half-restating it, and `epic-agent` is pointed at it as the document it is writing.

**A bug no longer gets a spec.** There are now **two routes into implementation**, canonical in `orchestration.md` → "Which issues get a spec": the **spec route** (features, enhancements — unchanged, still gated on an approving human comment or review on the spec PR) and the **direct route** (bugs — no spec, no spec PR, no spec-approval gate, straight to `issue-implement`). The hard part of a bug is the diagnosis, and `diagnose` does that in code with a real reproduction; a spec written before that loop exists guesses at a cause nobody has confirmed, and one written after it describes a fix that is already understood. So the fix goes to a PR and gets reviewed against the diff, next to the regression test that proves it.

Three things send a bug back to the spec route, and **who decides each is part of the rule**, since they surface at different moments: **a spec PR already exists** is the router's (re-derived every refresh, and re-checked by the worker with one cheap `gh pr list` before it builds, because a row discovered mid-wake was never PR-scanned and its spec handle is *unknown* rather than known-absent); **no reproduction** with an ambiguous symptom and **it isn't really a bug** are the worker's, decided before any code is written. A design *decision* found mid-diagnosis is deliberately none of them: the fix ships on best judgment with the decision surfaced on the PR, which is the point of debating it there rather than in a document.

**The route is derived, never asserted.** `epic-wake` reads the Linear category label on every refresh, so relabelling an issue re-routes it. Two different missing-category cases get opposite answers, deliberately: an issue the scan **observed with no category** fails closed to `spec` (its Bug label was *removed* — the one mutation a human makes to re-gate it), while a **dead scout** preserves the carried route rather than thrashing a live row on an infrastructure failure. The workflow script gains `routeFor` / `isDirectRoute` / `directRoutePhase`, and the guards that assume a spec exists (`approvalGatedPhase`, `jumpsTheApprovalGate`, the cross-spec hold) each exempt a direct row explicitly; a bug is never offered a spec-approval gate, and the cross-spec coherence pass neither waits for a bug's spec nor holds a bug behind one. The epic-objective gate still holds a bug — it just holds it at implementation instead of at spec. Relabelling a bug *after* its fix is built re-routes it but does not re-gate it: the code is already under review, so a spec written then settles nothing the PR review doesn't.

Covered by thirteen new checks in `.agents/workflows/verify.mjs` (266 total), including a property-based invariant that nothing but an actual `Bug` label can open the ungated route, and five route guards are individually mutation-verified. Writing them surfaced a real defect: `scoutPhaseFor` was deciding the approval-gate bypass from the *carried* row, so on the first wake that classified an issue as a bug the exemption was unreachable and a bug with an already-open PR would have had a second one opened for the same fix.
