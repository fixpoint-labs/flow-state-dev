A worker flow says what its tasks take on its `work` entry: `workerTaskEntry({ name, block, inputSchema: taskInputSchema(schema, { serverOwned, fill, refuse, check, stored, project }) })` (FIX-2894). Every write that files a task for one of its workers is checked against it before anything is written: `createTask`, a batch (refused whole), a routed task, a step filed `session: "new"`, `updateTask` (its input, and a move to another worker), and the raw ledger handles `filingConversationBoard()` and `conversationLedgers()` hand a task session. A misfit is refused `input_refused`, naming the delegate, its flow, the field and what was expected; nothing is filed. A field named in `serverOwned` is dropped from what a filer sends and written by the flow's `fill`; `updateTask` keeps its stored value; a `check` that changes one is refused as a bug in the flow. A value that would not survive being stored as JSON is refused by name, and a schema that can break the round trip (`.transform`, `.preprocess`, `.pipe`, `.catch`, `z.coerce.*`, `z.date`, `z.bigint`, `z.map`, `z.set`) is refused when the flow is built. Assigning an unassigned task, or moving one onto a worker on another declared flow, is a filing for that flow, its filler included. The claim parses the stored row again (through the flow's `stored` read, for a row in an old shape), fills the server-owned fields again when the row was filled under another declaration or flow (`fill` is called with `at: "claim"`), and hands the worker block the parsed input; a row that no longer fits fails its attempt, `Nothing ran.` A flow that declares nothing takes any object, as before. `listDelegates` gains `inputSchema` on each delegate: `{ jsonSchema, project }`, the fields a filer may write as JSON Schema draft-07 with every reference inlined, or `null`. A rule only `check` or `refuse` enforces belongs in the field's `.describe()` text, so a model reads it before it is refused.

**Breaking (pre-1.0):** the `needsProject` hire option is removed from `workerFlows` entries and `workerFlow(build, options)`, with no alias; passing it throws, naming the replacement. Declare `taskInputSchema(schema, { project: "required" })` on the flow's `work` entry instead (an open flow: `taskInputSchema(z.record(z.string(), z.unknown()), { project: "required" })`). The harness kit's `project: true` now does this for the `coder` flow. Code that wrote a misfit through a raw ledger handle is now refused.

Orchestration: `TaskSettingsPatch.ifRevision` writes an edit only while the row is still at that revision, else it is declined `revision-moved`; `TaskWriteRefusedError` is exported from `@flow-state-dev/orchestration/tasks`, for a flow's task-input hooks to throw.
