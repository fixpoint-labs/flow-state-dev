Workers can message each other. Every worker with a conversation (the built-in agent flow, every coordinator, and any flow that carries `defineSessionBoard`) gets a `messageWorker({ to, text, replyTo? })` tool. A message lands as a line under the sender's name in the recipient's own conversation (opened at the worker's derived address when absent) and wakes its turn after any turn it is running; an answer names the message it answers and goes back to the session that asked, or to the sender's own conversation when that was a task's session. A message makes no task row, adds no delegate and doesn't count against the task chain. Recipients are the user's roster workers with a conversation; a task-only worker is refused with "file a task", and a round-robin or everyone coordinator is refused. A chain of worker messages stops after 6 with no user's turn between them, and one turn sends at most 3: `hireWorkforce(installation, { messages: { hopLimit, perTurn } })` sets both. Every message is kept in a per-user message log that the roster flow exposes for an app to read (FIX-1989).

`findWorkerSession` and `ensureWorkerSession` with `{ worker }` (or `{ worker, projectId }`) now resolve to the session at the worker's derived address only, the one messages land in. A session an app opened for the worker at any other id stays in the store and in session lists, but these calls no longer return it.
