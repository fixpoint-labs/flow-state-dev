Child processes the workspace starts no longer inherit the host's whole environment (FIX-2687). A setup command, a project check (`runCheckoutCommands`, and harness-manager's `commandCheck`), and `run`/`runToEnd` now start from an allowlist: `PATH`, `HOME`, the shell's own variables, locale, proxy and CA settings (`WORKSPACE_BASE_PASS`), plus whatever the caller sets in `env`. A secret such as `GITHUB_TOKEN` or a model gateway key reaches one only when the host names it. To migrate, pass any variable a setup or check needs, a private registry token say, through `setup.env` (or the check's `env`): `setup: { command, env: { NPM_TOKEN: process.env.NPM_TOKEN! } }`.

The host's own git starts with its git settings (`HOST_GIT_PASS`: `GIT_CONFIG_GLOBAL`, identity including `EMAIL`, and the `GIT_CONFIG_COUNT` pairs less any `http.*`, `credential.*` or `url.*` one, which can carry a credential). Only its remote calls (fetch, push, `ls-remote`, `gh`) get credentials and transport settings (`HOST_REMOTE_PASS`: `GH_TOKEN`, `GITHUB_TOKEN`, `SSH_AUTH_SOCK`, gh's config, `XDG_CACHE_HOME`, git's `GIT_SSL_*` and HTTP proxy variables, every config pair), so landing and fetching work as before. `GIT_SSL_NO_VERIFY` and `GIT_ASKPASS` are not passed. `run` and `runToEnd` take `pass` (names to pass from the host's environment) and `gitCredentials` (the remote lane's config pairs). The lists themselves stay internal.
