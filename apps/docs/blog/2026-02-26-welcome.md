We've been building AI features for a while now. And every time, we end up writing the same infrastructure: orchestrate LLM calls, wire up SSE streaming, manage conversation state, handle retries, sync everything to the frontend. It's tedious. It's error-prone. And it has nothing to do with what the AI actually does.

Flow State Dev is our answer: a TypeScript framework that makes orchestration, streaming, state, and error handling **composable primitives** instead of application glue.

<!-- truncate -->

## The core idea

Four block types — **handler**, **generator**, **sequencer**, **router** — compose into any AI workflow. The framework handles execution, streaming, state persistence, retries, and client rendering.

```ts
const pipeline = sequencer({ name: "chat-pipeline" })
  .then(analyzeInput)
  .thenIf((result) => result.needsContext, enrichWithContext)
  .then(agentGenerator)
  .then(trackUsage)
  .rescue([{ when: [ModelError], block: fallback }]);
```

That pipeline analyzes input, conditionally enriches it, calls an LLM with tool access, tracks usage, and recovers from model errors. Every step streams results to the client in real time over SSE with automatic resume on disconnect.

## What's different

**You compose primitives, not configure a framework.** Most AI frameworks give you an opinionated agent architecture and ask you to fill in the blanks. Flow State Dev gives you four building blocks and a composition DSL. You decide what your AI does. The framework handles how it runs.

**Streaming is structural, not bolted on.** Items (messages, tool calls, state changes, custom components) stream as blocks execute, with sequence-number cursors for replay. This isn't an afterthought — it's the core delivery mechanism.

**State is scoped and typed.** Four isolation levels (request, session, user, project) with atomic operations and CAS concurrency. Each block declares only the state it needs. Projections are the only way to expose data to clients — security by architecture.

**One type system, server to screen.** Zod schemas defined once, validated at runtime, inferred at compile time. From block definitions through the client SDK to React hooks. No glue code.

## Where we are

Phase 1 (Foundation) is largely complete: core contracts, block builders, server runtime with stores and streaming, client transport, React hooks and renderers, and a testing package with deterministic generator mocks. Two canonical examples — [hello-chat](https://github.com/flow-state-dev/flow-state-dev) and [kitchen-sink](https://github.com/flow-state-dev/flow-state-dev) — demonstrate the full stack.

CLI and devtool are in active development.

## What's next
