01

What Workforce is

Three words. Do not collapse them. A seat is a roster slot that binds a worker. A worker is any flow on the contract — thin sequencers count (intake, coordinator, harness-manager). Agent (product) is an opinionated worker: sequencer + generators + persona + durable member memory. A seat can be any worker, not always an agent. Collaboration is the rooms and the dispatch spine. The product target is teams, plural. The build-out is §03.

Seat
roster slot · binds a worker

The slot on a team or project roster. It names a worker flow, not an Agent. Minimum contract (all today’s L1): named worker flow on a team/roster key + static DM session + dispatcher / settle / claim door. Same-flow DM address exists. Cross-flow seat wake is proposed, blocked on #1600.

Worker
any flow on the contract

A sequencer flow. Thin is allowed. Intake, coordinator, and harness-manager are workers. The factory is proposed. A hand-written defineFlow that keeps the contract is still a worker. See §05.

Agent
product = L2 opinion

The thick worker: sequencer + generators + persona + durable member memory. Thin L1 Agent / AgentRegistry types stay in core so skills can agent-ref / materialize without importing Workforce. defineAgent / registry impl is already L2. No second Agent type. Engine never sees AgentRegistry as product. See §04.

Not
invent kills

No Channel / Team / TeamFlow / MessageBoard L1. No second Agent model. No hot-dynamic kinds to paper over L1 gaps. Thin seats do not need AgentRegistry or member memory. Identity lives on agent/member scope, not on the seat. See §04 and §11.

04

Seat vs worker vs agent

The fence. Three words. A seat is a roster slot that binds a worker. A worker is any flow on the contract. Agent (product) is the opinionated worker — Layer 2. The thin Agent / AgentRegistry types stay in core as a seam. A team is still Layer 2: seats + shared rooms + dispatch. A roster is the seat-list (a team roster now; a project roster later if one earns it). Demote means do not grow the core types into collab, memory, or teams. It does not mean delete them.

Seat
roster slot · binds a worker

Not the agent. Minimum contract (all today’s L1): named worker flow on a team/roster key + static DM session + dispatcher / settle / claim door. Same-flow DM address exists. Cross-flow seat wake is proposed, blocked on #1600. Thin seats skip AgentRegistry and member memory. Identity is not stored on the seat.

Worker
any flow on the contract

A sequencer flow. Thin sequencers count: intake, coordinator, harness-manager. The factory is proposed. A hand-written defineFlow that keeps the contract is still a worker. See §05.

two altitudes

Engine never sees AgentRegistry as product.

Team
L2 · not a type

A roster (seats) + shared rooms + dispatch. Not an L1 Team type. Not a TeamFlow. The target is N of those, sharing rooms. No org graph on the core Agent type.

05

The worker contract

One factory. One flow per worker. Same shape every time. The worker is a sequencer flow. Product Agent is that flow when it also carries generators, a persona, and durable member memory — Layer 2 opinion, not a second type. Thin seats skip that opinion. The file tree that declares those workers is §06. SOP files are later. Do not grow the core Agent type or invent Team as Layer 1.

role / personality / tools / skills
proposed v1 factory inputs

Declared on teams/<teamId>/workers/<name>/. The factory emits one defineFlow. Org- and team-level skills/ / resources/ sit higher in that tree. Not fields to grow onto Agent. See §06.

keyed roster + harness seat
proposed compose

A roster is the seat-list. A team is that roster plus shared rooms plus dispatch. The harness name is a field on the seat. See §06 and §10.

SOP files
later · cut until process repeats

Default: the process is the worker’s job. A shared sops/ folder earns its place when the same process is copied across workers and starts to drift. Not v1.

File conventions

The product folders are teams/. A roster is a seat-list — a team roster today, later a project roster if one earns it. A team is the Layer 2 product: that roster plus shared rooms plus dispatch. Not an L1 Team type. Not a TeamFlow. Projects are not a folder. They live as resources, boards, sessions, and content — the same move as plan = board + readContent(). Scan feeds today’s AgentRegistry and defineFlow only. A TypeScript escape hatch emits those same shapes. A workforce tree loader is a named gap. Do not invent loadWorkforce().

Channels

Two channel kinds. A DM is one static session with that one worker, opened at bootstrap. A group is a message board plus one subscription session per subscribed member. Same-flow fan-out exists: a post is dispatcher() × N into those sessions. Reply-storm exclusion exists: today’s TaskCollectionRef.claim admits one holder per post. Who may reply is proposed Layer 2 policy. Ordered multi-reply is proposed Layer 2: a board coordinator — a team role, not a primitive — files N reply tasks with deps; settle unlocks the next; only an idle chain looks at newer posts. Cross-kind / cross-flow delivery stays proposed until that refuse goes away. Not a new primitive and not a shared room.

DM
one static session

One session with that one worker. Bootstrap opens it through today’s session API. Addressed by id after.

Group
exists · same-flow

The board is the shared working set. Each subscribed member has their own session on the same flow. A post is dispatcher() × N. Not one room they all enter. Cross-kind still refused.

Reply discipline
claim exists · who proposed

A wake is not a turn. Exclusion is TaskCollectionRef.claim — one holder per post. Who may attempt that claim (role, @, coordinator; default quiet) is proposed Layer 2. Not a Layer 1 lock. Not a room.

Ordered multi-reply

Who may speak is policy. In what order they speak is a chain of tasks. The proposed Layer 2 worker is a board coordinator — a team role, the same kind of built-in as librarian, not a Layer 1 type. It reads one post. It files N reply tasks with deps. Each task’s work is dispatcher() into that subscriber’s session. Settle marks the row completed; isClaimable already waits on deps[], so the next reply unlocks. Only when that chain is idle does the coordinator look at newer posts. The broke path is the existing machine: a lapsed lease is reclaimed, parked waits on a person, fail() retries when budget remains. Do not invent a MessageBoard sequencer, a coordinator Layer 1 type, or a new lease type to hold this.

Which room

Every talk is still dispatcher() into a session. The proposed Layer 2 matrix is which session — not a third channel kind, not a peer-edge graph, not a second bus. Team plus context — who is on the seat, which project or task is active — pick a session, then dispatch. Default: the project or task room, not a new pairwise or a DM. A coordinator or parent-star is optional policy, not Layer 1 law.

Room helpers — proposed wrappers, multi-team from day one

Same-flow N-rooms exist. Claim exclusion exists. Who may reply is proposed Layer 2. Ordered multi-reply is proposed. The helpers below wrap those facts. They take a team key. Rooms are addressable across teams. They are not a second session model, not a Channel package, and not a one-team-only API. If a helper would need a door that is still refused, it is a gap — see §18 — not a pretend export.

No one-team-only API

Foundation helpers take a team key. Rooms list subscribers as { team, seat }. You may store one team. You may not omit the key, take theTeam, or add fanOutAcrossTeams() later. If a second team needs a new argument, foundation shipped the wrong door.

No TeamFlow. No team-as-flow substrate. No team address type

Address-the-team is the intake seat’s static session. The intake is a worker. Do not add a TeamFlow kind, a team-as-flow substrate, or an address that is not a session id or a known channel. An inbox field on Agent is the same cut. See §11.

No second dispatch, session, or board model

Helpers wrap dispatcher(), create_session, and taskBoard. The intake inbox is that session, not a Workforce inbox product. They do not grow a Workforce session type or a Workforce board. A second surface would have to be unwound against the spine that already exists.

No Layer 1 Channel, Team, Project, MessageBoard, or OKF packages

Those words are convention over sessions, teams, and dispatcher(). Message board is Layer 2 convention only. A package that mints rooms, a MessageBoard sequencer, or a shared group session several workers enter, is a second architecture. Same cut: no peer-edge graph, no second send door, no route-resolver under the matrix, no coordinator Layer 1 type. Which room is Layer 2 — see §08. OKF stays an example, not a Workforce dependency.

No fake package export that is not a thin wrapper

A proposed name must show the Layer 1 call it wraps. sendAt, flowKind on a helper, or a cross-kind fan-out that hides the refuse are not wrappers. They are gaps. Package docs must not fork the §08 matrix. A loadWorkforce() that is not a call into createAgentRegistry + defineFlow is the same cut.

No second registry. No auto-reg of Team, Channel, or MessageBoard types. No sequencer-vs-agent as two types

Files declare into today’s AgentRegistry and defineFlow only. A TypeScript escape hatch emits those same shapes. The worker is a sequencer flow; generator calls do not mint a second type. See §05 fences and §12.

No Layer 1 board-lock type. No MessageBoard sequencer. No coordinator type

Same-flow group fan-out already wakes N sessions. Mutual exclusion is today’s TaskCollectionRef.claim — one holder per post. Who may attempt that claim is proposed Layer 2 (role / @ / coordinator; quiet unless addressed). Ordered multi-reply is proposed composition: a team-role coordinator files N reply tasks with deps; settle unlocks the next; idle before newer posts. The broke path is the existing lease / parked / retry. Inventing a board-lock, a MessageBoard sequencer, a coordinator Layer 1 type, or a new lease is a Layer 1 gap — wake Architect then, not now. Cross-kind fan-out is still proposed.

No Knowledge type. No OKF / knowledge hub in foundation. No parallel graph. No memory on Agent

No module-swap hooks

No file SOPs until a process repeats

No second harness-manager. No Layer 1 harness type
