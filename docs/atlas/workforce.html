Living design

One worker contract. Then compose.

Workforce is the general Layer 2 convention: one worker shape, one flow per worker. A possible v1 kick is a thin package: factory + file conventions + roster/harness seat + room helpers over today’s Layer 1. This page names that kick. It does not ship it. Not a Channel / Team / MessageBoard. Not a second dispatch, session, or board. Conductor does not wait on it.

01

What Workforce is

Opinions so people get going on Layer 1 without inventing their own. A worker is a flow. A DM is one static session with that worker. A group is a board plus one session per subscriber. Collaboration is the dispatch spine, not a second bus.

Today
exists · thin registry

Named agents, a registry, and materialization into a generator. Raw Layer 1 calls already work: create_session, dispatcher(), taskBoard, claim, { from: true }. That is the shipped surface.

Possible v1
proposed · thin package

Only factory + file conventions + roster/harness seat + room helpers. Each helper wraps a Layer 1 call already on this page. No second dispatch, session, or board model.

Later
not the kick

SOP files until a process repeats. Cross-flow helpers until the refuse goes away. Anything that would invent Channel / Team / MessageBoard / OKF.

Not
a product, a primitive

Not Layer 1 Channel / Team / Project / Agent-as-flow. Not a knowledge product. Not something Conductor waits on.

03

The worker contract

One factory. One flow per worker. Same shape every time. Proposed v1 factory inputs: role, personality, tools, skills. Roster + harness seat are proposed v1 compose, not files in the worker folder. SOP files are later — cut until a process repeats. A custom flow is allowed if it still adheres to the contract. Do not grow Agent or invent Team as Layer 1.

role / personality / tools / skills
proposed v1 factory inputs

The factory reads these and emits one defineFlow. Not a second runtime. Not fields to grow onto Agent.

roster + harness seat
proposed v1 compose

A list of worker flow kinds, plus an optional harness name on the seat. Not a file in the worker folder. Not a Layer 1 Team or Harness type. See §07.

SOP files
later · cut until process repeats

Default: the process is the worker’s job. A shared sops/ folder earns its place when the same process is copied across workers and starts to drift. Not v1.

Agent / Team as L1
cut

Do not invent either. Agent stays a named participant you materialize. A team stays a roster plus shared boards.

04

Memory via isolation

A worker does not get a new memory system. Its memory is org- and user-scoped resources on its own flow, isolated by flowIsolation. The session is the room. The resources are what the worker keeps.

Default shared; isolation is the worker opt-in

flowIsolation defaults to false: user/org rows are shared across flows. Session scope is already flow-bound; true there is rejected at build. The convention’s memory is the isolated case — the worker’s org/user resources, not a second store.

05

Channels

Two channel kinds. A DM is one static session with that one worker, opened at bootstrap. A group is a message board plus one subscription session per subscribed member. Same-flow fan-out exists: a post is dispatcher() × N into those sessions. Reply-storm exclusion exists: today’s TaskCollectionRef.claim admits one holder per post. Who may reply is proposed Layer 2 policy. Cross-kind / cross-flow delivery stays proposed until that refuse goes away. Not a new primitive and not a shared room.

DM
one static session

One session with that one worker. Bootstrap opens it through today’s session API. Addressed by id after.

Group
exists · same-flow

The board is the shared working set. Each subscribed member has their own session on the same flow. A post is dispatcher() × N. Not one room they all enter. Cross-kind still refused.

Reply discipline
claim exists · who proposed

A wake is not a turn. Exclusion is TaskCollectionRef.claim — one holder per post. Who may attempt that claim (role, @, coordinator; default quiet) is proposed Layer 2. Not a Layer 1 lock. Not a room.

Which room

Every talk is still dispatcher() into a session. The proposed Layer 2 matrix is which session — not a third channel kind, not a peer-edge graph, not a second bus. Roster plus context — who is on the seat, which project or task is active — pick a session, then dispatch. Default: the project or task room, not a new pairwise or a DM. A coordinator or parent-star is optional policy, not Layer 1 law.

06

Projects and tasks

Projects and tasks are dynamic sessions. Every message-board subscription gets its own action and its own session. A group channel is this pattern — the board plus one session per subscribed member — not a third session type. Same-flow, a post wakes N subscribers via dispatcher() × N — that exists. Exclusion is today’s claim. Cross-kind still waits. Who may reply is the proposed Layer 2 policy in §05, not a Layer 1 board-lock and not a shared room. That is a convention on the dispatch spine, not a second messaging product.

07

Teams and roster

A team is a roster plus shared boards. The board is the shared working set. Same-flow delivery is N dispatches into N per-subscriber sessions — that exists. Cross-kind delivery onto each worker’s own flow stays proposed until cross-flow lands. Built-ins — librarian, chief of staff, team coordinator — are roster entries, not packages. Cross-team work goes through those boards, not through a shared session. A seat can name which harness it runs on and inherit that harness’s subscriptions when those exist — proposed Layer 2, and only once Conductor’s manager path exists.

Harness on the seat
proposed layer 2

A roster entry can name which harness that worker runs on. Not a file in the worker folder. Not a third member kind.

Inherit subscriptions
when those exist

If that harness already has subscriptions, the seat inherits them. No new subscription primitive.

One manager stack
conductor track

The consumer path is Conductor’s harness-manager. Workforce does not get a second one. Proposed until that path exists.

No second dispatch, session, or board model

v1 helpers wrap dispatcher(), create_session, and taskBoard. They do not grow a Workforce inbox, a Workforce session type, or a Workforce board. A second surface would have to be unwound against the spine that already exists.

No Layer 1 Channel, Team, Project, MessageBoard, or OKF packages

Those words are convention over sessions, rosters, and dispatcher(). Message board is Layer 2 convention only. A package that mints rooms, or a shared group session several workers enter, is a second architecture. Same cut: no peer-edge graph, no second send door, no route-resolver under the matrix. Which room is Layer 2 — see §05. OKF stays an example, not a Workforce dependency.

No fake package export that is not a thin wrapper

A proposed name must show the Layer 1 call it wraps. sendAt, flowKind on a helper, or a cross-kind fan-out that hides the refuse are not wrappers. They are gaps. Package docs must not fork the §05 matrix.

No Layer 1 board-lock type

Same-flow group fan-out already wakes N sessions. Mutual exclusion is today’s TaskCollectionRef.claim — one holder per post. Who may attempt that claim is proposed Layer 2 (role / @ / coordinator; quiet unless addressed). Cross-kind fan-out is still proposed. Inventing a board-lock primitive is a Layer 1 gap — wake Architect then, not now.

No knowledge product on this page

A worker’s files and isolated resources are what it knows. That is not a knowledge hub, not an inbox product, not a second memory system. Held. Not designed here.

No seed-session field on defineFlow

Channels are opened by factory bootstrap through create_session. Declarative nonstandard sessions on the flow are cut. The field is absent on main; do not add it so the convention looks more like config.

No module-swap hooks

Later. The escape hatch is a custom flow that keeps the contract, not a plugin slot that swaps the factory’s guts. Adding hooks before a second implementation exists is bloat.

No file SOPs until a process repeats

Default: the process is the worker’s job. An engineering manager holds engineering process. A shared SOP folder earns its place when the same process is copied across workers and starts to drift. Until then it is a third place the job lives.

No second harness-manager. No Layer 1 harness type

A roster seat may name a harness and inherit subscriptions that already exist. The consumer is Conductor’s harness-manager track — one stack. Workforce does not get its own manager, and it does not invent a harness or subscription primitive. Marked proposed until that path exists. Triangulate; do not merge Conductor and Workforce harnesses on this page into one product.

Do not grow Agent until a factory needs a field

Today’s Agent is a definition you materialize. The intended worker is a flow. Growing the type to look like the second, before a build that staffs flows, is how Layer 1 absorbs a Workforce opinion.

When that build exists, the first question is still “is this a resource the worker’s flow declares, or a new field on Agent?” — and the cheaper answer is usually the resource.
