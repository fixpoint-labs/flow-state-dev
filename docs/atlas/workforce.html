01

What Workforce is

Opinions so people get going on Layer 1 without inventing their own. A worker is a flow. A DM is one static session with that worker. A group is a board plus one session per subscriber. Collaboration is the dispatch spine, not a second bus.

Today
a thin package

Named agents, a registry, and materialization into a generator. One example seats a skill. That is the shipped surface.

This cycle
this page

The convention, fully drawn. No runtime. No new package. Atlas-only may merge.

Intended
layer 2 factory

One contract, one flow per worker, same shape. Files configure the worker. Memory is isolated org/user resources. Teams are a roster plus shared boards. Delivery is N per-subscriber sessions, not one group room.

Not
a product, a primitive

Not Layer 1 Channel / Team / Project packages. Not a knowledge product. Not something Conductor waits on.

03

The worker contract

One factory. One flow per worker. Same shape every time. Files configure tools, skills, personality, and role. A custom flow is allowed if it still adheres to the contract.

// EXISTS — @flow-state-dev/workforce, the thin registry. Not a flow factory.
import { defineAgent, createAgentRegistry, materializeAgent } from "@flow-state-dev/workforce";

const engMgr = defineAgent({
  name: "eng-manager",
  description: "Staffs issues and holds engineering process.",
  persona: "You are the engineering manager.",
  model: "openai/gpt-5.4-mini",
  allowedTools: ["board", "search"],
});

const registry = createAgentRegistry([engMgr]);
// materializeAgent(engMgr, opts) → a generator. Not a worker flow.
// PROPOSED — factory input. Not an API on main. Not a workforce export.
createWorkerFlow({
  name: "eng-manager",
  role: "./workers/eng-manager/role.md",
  personality: "./workers/eng-manager/personality.md",
  tools: ["board", "search"],
  skills: ["staff-issue", "write-spec"],
})
// → one defineFlow({ kind: "eng-manager", ... }) of the contract shape
// a hand-written defineFlow is fine if it keeps that shape
04

Memory via isolation

A worker does not get a new memory system. Its memory is org- and user-scoped resources on its own flow, isolated by flowIsolation. The session is the room. The resources are what the worker keeps.

Default shared; isolation is the worker opt-in

flowIsolation defaults to false: user/org rows are shared across flows. Session scope is already flow-bound; true there is rejected at build. The convention’s memory is the isolated case — the worker’s org/user resources, not a second store.

05

Channels

Two channel kinds. A DM is one static session with that one worker, opened at bootstrap. A group is a message board plus one subscription session per subscribed member. Same-flow fan-out exists: a post is dispatcher() × N into those sessions. Cross-kind / cross-flow delivery stays proposed until that refuse goes away. Who answers is proposed Layer 2 policy, not a new primitive and not a shared room.

DM
one static session

One session with that one worker. Bootstrap opens it through today’s session API. Addressed by id after.

Group
exists · same-flow

The board is the shared working set. Each subscribed member has their own session on the same flow. A post is dispatcher() × N. Not one room they all enter. Cross-kind still refused.

Reply discipline
proposed layer 2 policy

A wake is not a turn. Who may reply: role, @, or the coordinator. One claim or turn per post. Default quiet unless addressed. Not a Layer 1 lock. Not a room.

Which room

Every talk is still dispatcher() into a session. The proposed Layer 2 matrix is which session — not a third channel kind, not a peer-edge graph, not a second bus. Roster plus context — who is on the seat, which project or task is active — pick a session, then dispatch. Default: the project or task room, not a new pairwise or a DM. A coordinator or parent-star is optional policy, not Layer 1 law.

Same-flow N-session fan-out is the runtime — board + one session per subscriber, dispatcher() × N. Reverse { from: true } already exists — reply to the stamped sender, same door. The matrix (which room) and cross-kind delivery still wait on the door crossing a flow kind. Do not invent a peer-edge graph, a route-resolver substrate, or a Layer 1 Channel / MessageBoard package to fill that wait.

06

Projects and tasks

Projects and tasks are dynamic sessions. Every message-board subscription gets its own action and its own session. A group channel is this pattern — the board plus one session per subscribed member — not a third session type. Same-flow, a post wakes N subscribers via dispatcher() × N — that exists. Cross-kind still waits. Who replies is the proposed Layer 2 policy in §05, not a Layer 1 board-lock and not a shared room. That is a convention on the dispatch spine, not a second messaging product.

07

Teams and roster

A team is a roster plus shared boards. The board is the shared working set. Same-flow delivery is N dispatches into N per-subscriber sessions — that exists. Cross-kind delivery onto each worker’s own flow stays proposed until cross-flow lands. Built-ins — librarian, chief of staff, team coordinator — are roster entries, not packages. Cross-team work goes through those boards, not through a shared session. A seat can name which harness it runs on and inherit that harness’s subscriptions when those exist — proposed Layer 2, and only once Conductor’s manager path exists.

Harness on the seat
proposed layer 2

A roster entry can name which harness that worker runs on. Not a file in the worker folder. Not a third member kind.

Inherit subscriptions
when those exist

If that harness already has subscriptions, the seat inherits them. No new subscription primitive.

One manager stack
conductor track

The consumer path is Conductor’s harness-manager. Workforce does not get a second one. Proposed until that path exists.

08

Sequencer vs agent

A roster seat is either a deterministic sequencer or a non-deterministic agent. Same contract. Different member. Do not pretend they are the same just because both are workers. Which harness a seat runs on is a separate proposed field on the roster, not a third member kind. See §07.

13

Cuts

Held on purpose. Do not invent these because the thought exists. The work that would make Workforce real is not on the Conductor spine, and it is not a Layer 1 package with a familiar name.

This cycle ships the page, not the factory

Updating this atlas is the work. Implementing a Workforce runtime is not. Conductor does not wait. Atlas-only may merge.

No Layer 1 Channel, Team, Project, or MessageBoard packages

Those words are convention over sessions, rosters, and dispatcher(). Message board is Layer 2 convention only. A package that mints rooms, or a shared group session several workers enter, is a second architecture. Same cut: no peer-edge graph, no second send door, no route-resolver under the matrix. Which room is Layer 2 — see §05.

No Layer 1 board-lock type

Same-flow group fan-out already wakes N sessions. Reply discipline is proposed Layer 2 policy: who may reply, one claim or turn per post, quiet unless addressed. Cross-kind fan-out is still proposed. If a later POC needs mutual exclusion, reuse the existing task/resource claim/lease. Inventing a board-lock primitive is a Layer 1 gap — wake Architect then, not now.

No knowledge product on this page

A worker’s files and isolated resources are what it knows. That is not a knowledge hub, not an inbox product, not a second memory system. Held. Not designed here.

No seed-session field on defineFlow

Channels are opened by factory bootstrap through create_session. Declarative nonstandard sessions on the flow are cut. The field is absent on main; do not add it so the convention looks more like config.

No module-swap hooks

Later. The escape hatch is a custom flow that keeps the contract, not a plugin slot that swaps the factory’s guts. Adding hooks before a second implementation exists is bloat.

No file SOPs until a process repeats

Default: the process is the worker’s job. An engineering manager holds engineering process. A shared SOP folder earns its place when the same process is copied across workers and starts to drift. Until then it is a third place the job lives.

No second harness-manager. No Layer 1 harness type

A roster seat may name a harness and inherit subscriptions that already exist. The consumer is Conductor’s harness-manager track — one stack. Workforce does not get its own manager, and it does not invent a harness or subscription primitive. Marked proposed until that path exists. Triangulate; do not merge Conductor and Workforce harnesses on this page into one product.

Do not grow Agent until a factory needs a field

Today’s Agent is a definition you materialize. The intended worker is a flow. Growing the type to look like the second, before a build that staffs flows, is how Layer 1 absorbs a Workforce opinion.

When that build exists, the first question is still “is this a resource the worker’s flow declares, or a new field on Agent?” — and the cheaper answer is usually the resource.
The one-sentence version

Workforce is one worker contract on Layer 1: a flow per worker, files for tools, skills, personality, and role, memory via isolation, DMs as static sessions, groups as a board plus one session per subscriber (same-flow fan-out exists; cross-kind still proposed), group replies as proposed Layer 2 policy (who may speak; one turn; quiet unless addressed), which room as proposed Layer 2 (roster + context; prefer the project room; no peer-edge graph), projects as dynamic ones, teams as roster plus shared boards (a seat may name a harness and inherit that harness’s subscriptions; one manager stack, Conductor’s), plans as board plus resource text, talk as dispatch. Today it is a thin registry. This cycle writes the convention. Conductor does not wait.
