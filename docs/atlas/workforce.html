01

What Workforce is

Workforce is the shippable product surface. Conductor is one team on it, not a sibling. Two lists. Do not collapse them. A seat is a roster slot that binds a worker — a flow instance, the dispatch target. Skills and task boards assign from a different list: name → BlockDefinition. A worker is any flow on the contract — thin sequencers count (intake, coordinator, harness-manager). Agent (product) is an opinionated worker: sequencer + generators + persona + durable member memory. defineAgent is how that opinion becomes a block, not a catalog row. A seat can be any worker, not always an agent. Collaboration is the rooms and the dispatch spine. The product target is teams, plural. The build-out is §03.

Seat
roster slot · binds a worker

The slot on a team or project roster. It names a flow instance, not an Agent catalog row. Minimum contract (all today’s L1): named worker flow on a team/roster key + static DM session + dispatcher / settle / claim door. Same-flow DM address exists. Cross-flow seat wake exists (dispatcher({ flowKind })). Hire-by-id and dynamic addresses still wait on INST (FIX-1320), not on #1600. Do not stuff seats into AgentRegistry.

Worker
any flow on the contract

A sequencer flow. Thin is allowed. Intake, coordinator, and harness-manager are workers. The factory is proposed. A hand-written defineFlow that keeps the contract is still a worker. See §05.

Agent
product = L2 opinion

The thick worker: sequencer + generators + persona + durable member memory. defineAgent is a block factory — proposed to emit a BlockDefinition (agent-shaped sequencer/generator). Today it returns an Agent config; materializeAgent / agentBlock then build that block. Collapse those into the factory. Park the code kill behind W2. Do not grow agentRegistry / agent-ref. See §04.

Not
invent kills

No Channel / Team / TeamFlow / MessageBoard L1. No second Agent model. No stuffing seats into an Agent catalog. No hot-dynamic kinds to paper over L1 gaps. No second control plane — MCP is a client door onto intake / boards / dispatcher(), §15. Thin seats do not need member memory. Identity lives on agent/member scope, not on the seat. See §04 and §11.

Ordered multi-reply

Who may speak is policy. In what order they speak is a chain of tasks. The proposed Layer 2 worker is a board coordinator — a team role, the same kind of built-in as librarian, not a Layer 1 type. It reads one post. It files N reply tasks with deps. Each task’s work is dispatcher() into that subscriber’s session. Settle marks the row completed; isClaimable already waits on deps[], so the next reply unlocks. Only when that chain is idle does the coordinator look at newer posts. The broke path is the existing machine: a lapsed lease is reclaimed, parked waits on a person, fail() retries when budget remains. Do not invent a MessageBoard sequencer, a coordinator Layer 1 type, or a new lease type to hold this.

Which room

Every talk is still dispatcher() into a session. The proposed Layer 2 matrix is which session — not a third channel kind, not a peer-edge graph, not a second bus. Team plus context — who is on the seat, which project or task is active — pick a session, then dispatch. Default: the project or task room, not a new pairwise or a DM. A coordinator or parent-star is optional policy, not Layer 1 law.
