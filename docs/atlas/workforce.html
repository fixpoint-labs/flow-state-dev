Living design

One flow per worker, on the dispatch spine

Workforce is Layer 2 opinion on Layer 1 that already exists. Eve-style files configure a worker. A factory turns those files into one standard flow. Channels are sessions that factory opens with today’s APIs. Collaboration is dispatcher() — including reverse, and cross-flow when it lands. Relay and Workstream are superseded names for that job.

exists — the shape shown is the real one proposed — design, not built

Sibling atlas: Conductor — this-cycle thin on Layer 1. Conductor-as-L3-on-Workforce is a horizon, not this cycle. This page does not ship a package.

01

What Workforce is

Opinions so people get going. Not a fifth block kind. Not a second Agent runtime. Not Channel / Team / Project packages in Layer 1.

Today
a thin package

defineAgent, a registry, materializeAgent, a persona helper, a stub capability. One example seats a skill. That is the shipped surface.

Intended
layer 2 conventions

Files configure tools, skills, personality, role. A factory emits one flow per worker. Teams are a roster plus shared sessions. Boards subscribe and post on the dispatch spine.

Eventually
a grok-bot-like surface

You talk to the engineering manager you already know. That identity has a flow, memory on that flow, and named channel sessions. Proposed. No UI exists.

Superseded
relay · workstream

Those words taught a second send door and a leftover child-session architecture. The door is dispatcher(). This page does not teach them as the plan.

02

Worker contract

One standard flow shape. One flow per worker. Files configure the worker. The factory emits the flow. A custom flow is allowed only if it keeps that contract — it is not a second Agent runtime.

The contractStatusWhat it means, narrowly
One standard flow shapeproposedEvery factory-built worker exposes the same action surface: a talk/inbox action, a way to receive a dispatch, a way to send one. Authors do not invent a new inbox per worker.
One flow per workerproposedThe worker’s flowKind is the worker. Not a field on a shared runtime.
Files configure, factory emitsproposedPersonality, role, tools, skills are files. The factory calls today’s defineAgent / defineFlow / createSession.
Custom flow escape hatchproposedYou may hand-write a defineFlow instead of taking the factory output. It must still be one flow for that worker and expose the same actions. It is not a licence to invent a second Agent type.
03

Channels are sessions

Every worker flow has static sessions that act as channels. The factory opens those named sessions with createSession({ sessionId }). There is no seed-session fixture on defineFlow.

Do not invent a session kind

A session record already carries a flowKind. That is enough. A channel is a convention: this session id, on this worker’s flow, is the Slack room, or the web room, or the CLI room. dispatcher({ session: { id } }) already delivers into an existing session of the same flow. That is how another worker reaches a channel once they know the id.

04

Projects, tasks, boards

A project or a task is a dynamic session — minted when the work appears, adopted on retry. Every message board a worker subscribes to gets its own action and its own session. Subscribe and post ride dispatcher().

Do not invent a thread on Layer 1

The board opinion needs a working set and, for long history, a read-through store. Both exist. What it does not need is parent-pointer edges, a thread type, or a MessageBoard package. If a later build cannot page an external collection the way Slack needs, that is an L1 gap to file — not a primitive to sketch here, and not a POC in this PR.

PieceStatusWhat it is, narrowly
Child session from a keyexistsdispatcher({ session: { key } }) mints or adopts a child. That is the dynamic-session mechanism. Use it for a project or a board subscription.
Deliver into an existing sessionexistsdispatcher({ session: { id } }). Same flow, same principal. Refused otherwise.
Collection + reactTo + writeContentexistsEnough to store a brief, keep a working set of posts, and fire a block on a post. The board opinion is how those are assembled, not a new store.
External collectionexistsdefineExternalResourceCollection — read-only, app-owned store. Slack-scale history goes here, not into an unbounded FSD working set.
One session per subscribed boardproposedThe worker’s flow grows a session (and the contract action) for each board it joins. Isolation stays per worker.
Edges as a thread / MessageBoard packagerejectedReplies are collection instances. Do not invent a thread type. Do not open a Layer 1 package.
05

Teams and the roster

A team is a roster plus the sessions that roster shares. Built-ins — librarian, chief of staff, coordinator — are roster entries. A deterministic sequencer can sit on the same roster. It is not an agent.

What the team folder buysWhen to skip it
A default answer to “who is on this” — agents and sequencers, listed once.One worker and no shared session. Then the folder is a namespace. Do not create it.
Shared sessions the roster can address — a team room, a team board.If the only shared thing is a file prefix, use a collection topic. That already works.
A place to borrow a built-in by name, instead of pasting a specialist into every team.If nobody else needs that specialist, it has a home team. Borrowing is for the shared ones.
06

Identity and memory

An agent is a persistent identity with memory. That memory is ordinary resources on that worker’s flow. flowIsolation already keys user- and org-scoped resources per flowKind. One flow per worker is what makes that isolation mean “this worker.”

flowIsolation is the isolation, not a team scope

Set flowIsolation: true on a user- or org-scoped resource and the store key includes flowKind. Session scope is already flow-bound; the flag is rejected there. That is enough for “the engineering manager’s notes are not the librarian’s.” A team security boundary is a later Layer 1 question, and it is not a blocker for this convention.

07

Collaboration rides the dispatch spine

A worker talks to another worker by dispatching into a session. Reverse is the same door, aimed at the sender. Cross-flow is the same door, once the host accepts another flowKind. Relay and Workstream are superseded names for this job.

WordStatusWhat to do with it
dispatcher()existsThe send door. Handler, not a fifth block kind. Address is (type, target). Session is { key } or { id }.
Dispatch stamp fromexists{ block, sessionId } on the recipient. Enough to aim a reverse send.
{ from: true }L1 gapProposed session target: “the session on the stamp.” The stamp exists. The target does not. File it on dispatcher(). Do not invent a Relay verb. Not a POC here.
Cross-flow dispatchL1 gapSame door, other flowKind. Decided, not in the tree. Needed the moment two workers talk. Until it lands, same-flow boards still work. Not a new primitive. Not a POC here.
RelaysupersededA second send door that was never a package. Do not teach it. Do not wait for packages/relay.
WorkstreamsupersededA leftover child-session architecture beside dispatch. Leftover names remain in the client (listWorkstreams) and in sharedToWorkstream. Workforce collaboration does not ride them.
No second bus

Boards fan out by looping dispatcher(). Reverse is { from: true }. A custom worker flow that cannot be reached this way is not on the contract. If the door is missing a field, that is a Layer 1 gap on dispatcher(), not a Workforce messenger.

08

Plan as content

The plan capability is Layer 2 opinion on the task board that already exists. The spec is resource text. The tasks are the structured half of the same plan. There is no document store and no second planner.

// proposed opinion — not an API in the tree
ctx.cap.plan.read()          // readContent on the board (or sibling) resource
ctx.cap.plan.write(markdown)  // writeContent — the spec is text
ctx.cap.plan.addTask({…})    // the structured half; today’s board sugar
ctx.cap.plan.listTasks()

The package is not the harness

@flow-state-dev/workforce is agent registry and materialization. CLAUDE.md still calls it Layer 2 on orchestration. What landed is the first cut — name a participant, look it up, turn it into a block — without the contract, the factory, the channels, or the surface. Read every “Workforce” claim against this inventory.

10

Triangulate Conductor

Same Layer 1. Different opinions. Separate tracks. This-cycle Conductor is thin on Layer 1 and does not wait on a Workforce product. Conductor-as-a-coding-extension-on-Workforce is a proposed horizon, not a merge, and not this cycle.

11

Layer 1 gaps

When a Layer 2 opinion needs something Layer 1 does not have, say so. File the gap. Do not invent a primitive on this page, and do not prove it with a POC in this PR.

Cross-flow is an L1 gap

One flow per worker means two workers are two flowKinds. Same-flow dispatch exists. The host still refuses another flow. That refusal is the gap. The fix is on the existing door. It is not a Relay, not a new block kind, and not a throwaway POC on this atlas PR.

Reverse is an L1 gap on the stamp you already have

metadata.dispatch.from.sessionId is shipped. session: { from: true } is not. Growing the session target is the cheap close. Inventing a reply bus is the expensive one.

A missing convenience is not a missing primitive

If Layer 2 wants a factory, a roster file, or a plan capability, those are opinions on pieces that exist. If it wants a thread type, a Channel package, or seed-session on defineFlow, those are inventions. Only the first column above is a gap.

12

Off this page

Held on purpose. A thought is not a section.

Not Layer 1 packages

Channel, Team, Project, and MessageBoard are opinions — roster, sessions, collections, dispatch. If a build starts wanting a new store, a new scope, or a new block kind, file a Layer 1 gap. Do not open a package.

Not designed here

Knowledge Hub, OKF, this-cycle Workforce package implementation, module-swap hooks, watches, mailbox, token gates, and the Grok-versus-Cursor process we use to build FSD. Those are how we work, or a later product, not how a Workforce is run.

SOPs are not a second file convention

Default no. Start as a worker’s job — the engineering manager does the thing. Promote to a shared file only when more than one worker must run the same steps. Do not design that file on this page.

No seed-session on defineFlow

Named channel sessions are opened with createSession({ sessionId }). Adding a fixture map to defineFlow so channels can exist is how a convention becomes a primitive.

Do not merge the harnesses

Conductor and Workforce share a substrate. They do not share a spine. Conductor-as-L3-on-Workforce is a horizon, not a this-cycle dependency. Later reuse is earned by both tracks staying on dispatcher(), sessions, and the board — not by writing one harness that pretends to be both.

The one-sentence version

Workforce is Eve-style files that a factory turns into one flow per worker, with channels as sessions it opens, teams as a roster plus shared sessions, plans as text on the board you already have, and collaboration as dispatcher() — including reverse, and cross-flow when it lands. Today it is a thin registry. This page is the opinion. It is not the package.
