Living design

One worker contract. Then compose.

Workforce is the general Layer 2 convention: one worker shape, one flow per worker. The target is the RC collaboration story — teams, plural. N rosters, shared rooms, cross-roster dispatch. Address-the-team is an intake seat, not a TeamFlow. Agent already exists as the seat. Collaboration stays on the rooms, not on Agent, and not on a Team type. Implement is phased. Foundation leaves the plural door open. RC gates are proposed until they are true. This page teaches the target. It does not ship it. Conductor does not wait on it. GTM timing is Strategy, not this page.

01

What Workforce is

Opinions so people get going on Layer 1 without inventing their own. A worker is a flow. Agent is the participant you seat. A DM is one static session. Collaboration is the rooms and the dispatch spine, not a field on Agent and not a Team type. The product target is teams, plural — see §03. Foundation is the first cut, not the story.

Today
exists · Agent + raw L1

Agent is a named participant: persona, model, tools, capabilities, materializeAgent, registry / agent-ref. Not a session, room, or team. No durable memory on the type. Rooms already work as raw L1 calls.

Foundation
proposed · thin L2

Agent seat, roster(s), rooms, helpers on today’s L1. Every roster has a team intake seat. Helpers are multi-roster from day one — keyed roster, rooms addressable across rosters. One roster in the map is fine. A one-team-only API is not.

Teams plural
target · still L2

N rosters + shared rooms + cross-roster dispatcher(). Cross-flow when #1600 lands. No Team substrate. No org graph on Agent.

Not
invent kills

No Channel / Team / TeamFlow / MessageBoard L1. No second Agent model. No fake package surface. No members, channels, or inbox on Agent. See §04 and §10.

04

Agent vs team

The fence. Agent already exists as Layer 1. A team does not. Foundation seats that Agent into keyed roster(s) and rooms. The target is teams, plural — still Layer 2, still no Team type. Grow Agent only after the three proofs at the bottom of this section. Honesty over a prettier type.

Agent
exists · L1 participant

Name, persona, model, tools, skills (reserved), capabilities. materializeAgent turns it into a generator. Registry / agent-ref look it up. Not a session. Not a room. Not a team. No durable memory store on the type — packages/core/src/types/agent.ts has no resources field.

Seat
foundation · proposed

Materialize that participant into a DM or a project room. The Agent is who sits there. The session is the room. Collaboration is the room helpers, not a field on Agent. The seat is addressed as roster + row, never as “the team.”

Team
L2 · not a type

A roster plus shared rooms plus dispatch. The target is N of those, sharing rooms. Do not invent a Team primitive to hold what the roster and the rooms already name. No org graph on Agent.

Not on Agent
cut

No members. No channels. No inbox. Putting collaboration on the participant is how Agent becomes a second Workforce.

These are not L1 substrate refuses. They are questions this page will not paper over by adding a field. Until each is proved, Agent stays the participant you already have.

05

The worker contract

One factory. One flow per worker. Same shape every time. The worker is a sequencer flow. “Agent” is that flow when it calls generators — not a second type. Declare at the level they mean so the tree is the scope story: org, team/roster, worker. Files are Layer 2 declare into today’s AgentRegistry and defineFlow only. SOP files are later. A TypeScript escape hatch must emit those same shapes. Do not grow Agent or invent Team as Layer 1.

role / personality / tools / skills
proposed v1 factory inputs

Declared on workers/<name>/. The factory emits one defineFlow. Org- and team-level skills/ / resources/ are the same files, higher in the tree. Not fields to grow onto Agent.

keyed roster(s) + harness seat
proposed compose

A keyed map of rosters, each a list of worker flow kinds, plus an optional harness name on the seat. One roster in the map is fine. A singleton with no key is not. See §09.

SOP files
later · cut until process repeats

Default: the process is the worker’s job. A shared sops/ folder earns its place when the same process is copied across workers and starts to drift. Not v1.

Agent / Team as L1
cut

Do not invent either. Agent stays a named participant you materialize. A team stays a roster plus shared boards. Sequencer vs agent is not two types — §11.

07

Channels

Two channel kinds. A DM is one static session with that one worker, opened at bootstrap. A group is a message board plus one subscription session per subscribed member. Same-flow fan-out exists: a post is dispatcher() × N into those sessions. Reply-storm exclusion exists: today’s TaskCollectionRef.claim admits one holder per post. Who may reply is proposed Layer 2 policy. Cross-kind / cross-flow delivery stays proposed until that refuse goes away. Not a new primitive and not a shared room.

DM
one static session

One session with that one worker. Bootstrap opens it through today’s session API. Addressed by id after.

Group
exists · same-flow

The board is the shared working set. Each subscribed member has their own session on the same flow. A post is dispatcher() × N. Not one room they all enter. Cross-kind still refused.

Reply discipline
claim exists · who proposed

A wake is not a turn. Exclusion is TaskCollectionRef.claim — one holder per post. Who may attempt that claim (role, @, coordinator; default quiet) is proposed Layer 2. Not a Layer 1 lock. Not a room.

Which room

Every talk is still dispatcher() into a session. The proposed Layer 2 matrix is which session — not a third channel kind, not a peer-edge graph, not a second bus. Roster plus context — who is on the seat, which project or task is active — pick a session, then dispatch. Default: the project or task room, not a new pairwise or a DM. A coordinator or parent-star is optional policy, not Layer 1 law.

Rooms are addressable across rosters. They are not a second session model, not a Channel package, and not a one-team-only API. If a helper would need a door that is still refused, it is a gap — see §17 — not a pretend export.

Team intake

Address-the-team without picking a person. That is a capability, not a new flow kind. Every keyed roster has a team intake seat — a coordinator or a thin sequencer — with a static DM. “Talk to eng” is that session. The intake worker routes with claim, ordered replies, or fan-out. The team board stays for broadcast. Still one flow per worker. The intake is a worker.

Cuts

Held on purpose. Do not invent these because the thought exists. Foundation is a thin wrapper over today’s Layer 1, keyed for N rosters, with an intake seat on each. A TeamFlow or a second dispatch surface is how that kick fails. A one-team-only API is how Phase 2 becomes a rewrite. RC gates stay proposed until they are true. Conductor does not wait on the package. GTM is not this page.

This page teaches the RC target. It does not ship the package

Updating this atlas is the work. Implementing helpers is a later kick, if Jake takes it. Conductor does not wait. Atlas-only may merge. Strategy owns GTM timing.

No one-team-only API

Foundation helpers take a roster key. Rooms list subscribers as { roster, seat }. You may store one roster. You may not omit the key, take theTeam, or add fanOutAcrossTeams() later. If a second roster needs a new argument, foundation shipped the wrong door.

No TeamFlow. No team-as-flow substrate. No team address type

Address-the-team is the intake seat’s static session. The intake is a worker. Do not add a TeamFlow kind, a team-as-flow substrate, or an address that is not a session id or a known channel. An inbox field on Agent is the same cut. See §10.

No second dispatch, session, or board model

Helpers wrap dispatcher(), create_session, and taskBoard. The intake inbox is that session, not a Workforce inbox product. They do not grow a Workforce session type or a Workforce board. A second surface would have to be unwound against the spine that already exists.

No Layer 1 Channel, Team, Project, MessageBoard, or OKF packages

Those words are convention over sessions, rosters, and dispatcher(). Message board is Layer 2 convention only. A package that mints rooms, or a shared group session several workers enter, is a second architecture. Same cut: no peer-edge graph, no second send door, no route-resolver under the matrix. Which room is Layer 2 — see §07. OKF stays an example, not a Workforce dependency.

No fake package export that is not a thin wrapper

A proposed name must show the Layer 1 call it wraps. sendAt, flowKind on a helper, or a cross-kind fan-out that hides the refuse are not wrappers. They are gaps. Package docs must not fork the §07 matrix. A loadWorkforce() that is not a call into createAgentRegistry + defineFlow is the same cut.

No second registry. No auto-reg of Team, Channel, or MessageBoard types. No sequencer-vs-agent as two types

Files declare into today’s AgentRegistry and defineFlow only. A TypeScript escape hatch emits those same shapes. The worker is a sequencer flow; generator calls do not mint a second type. See §05 fences and §11.

No Layer 1 board-lock type

Same-flow group fan-out already wakes N sessions. Mutual exclusion is today’s TaskCollectionRef.claim — one holder per post. Who may attempt that claim is proposed Layer 2 (role / @ / coordinator; quiet unless addressed). Cross-kind fan-out is still proposed. Inventing a board-lock primitive is a Layer 1 gap — wake Architect then, not now.

No Knowledge type. No OKF / knowledge hub in foundation. No parallel graph. No memory on Agent

See §06. Knowledge is resource scope plus who you are seated as. Foundation writes and reads team goals and lessons as resources. OKF later indexes those rows. It is not an RC gate. Do not mint a Knowledge type, stand up a graph beside the resources, or put memory on Agent to close the member-identity gap.

No seed-session field on defineFlow

Channels are opened by factory bootstrap through create_session. Declarative nonstandard sessions on the flow are cut. The field is absent on main; do not add it so the convention looks more like config.

No module-swap hooks

Later. The escape hatch is a custom flow that keeps the contract, not a plugin slot that swaps the factory’s guts. Adding hooks before a second implementation exists is bloat.

No file SOPs until a process repeats

Default: the process is the worker’s job. An engineering manager holds engineering process. A shared SOP folder earns its place when the same process is copied across workers and starts to drift. Until then it is a third place the job lives.

No second harness-manager. No Layer 1 harness type

A roster seat may name a harness and inherit subscriptions that already exist. The consumer is Conductor’s harness-manager track — one stack. Workforce does not get its own manager, and it does not invent a harness or subscription primitive. Marked proposed until that path exists. Triangulate; do not merge Conductor and Workforce harnesses on this page into one product.

OKF, a Slack-style web face, Pi, and paid packaging are not RC gates

They are later or Strategy. Do not stall §18 on them. GTM timing stays off this page.

No collaboration on Agent. No Team type. No second Agent model

See §04 proofs A/B/C. Do not re-litigate the fence here.

Do not grow Agent until a factory needs a field

Today’s Agent is a definition you materialize. The intended worker is a flow. Growing the type to look like a team, before the three proofs, is how Layer 1 absorbs a Workforce opinion.

When that build exists, the first question is still “is this a resource the worker’s flow declares, or a new field on Agent?” — and the cheaper answer is usually the resource.
