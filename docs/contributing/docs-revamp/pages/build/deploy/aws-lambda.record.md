## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You've written a hello-chat flow and want it running as a Lambda function. What does the file you point Lambda's handler at contain?
   Answer: It imports createLambdaHandler from @flow-state-dev/node/aws-lambda and createFlowState from @flow-state-dev/engine, builds a FlowState with flows passed as an array (flows: [helloChat]) and a Postgres store, then does `export const handler = createLambdaHandler(flowstate)`. The handler wraps the same Hono app that serve() uses, so it serves GET /healthz and the flow API under /api/flows. With the file at src/handler.ts, Lambda's handler setting is handler.handler: file handler, export handler. (Facts Q1.1-Q1.5, Steps 2-3; contradiction ruling on flows being an array.)
2. You call `curl -N` on /api/flows/hello-chat/requests/REQUEST_ID/stream through the Function URL. Nothing shows up until the flow finishes, then every event arrives together. What do you check? *(edge case)*
   Answer: Check that the Function URL's invoke mode is RESPONSE_STREAM (aws lambda create-function-url-config ... --invoke-mode RESPONSE_STREAM). A streamed reply needs both createLambdaHandler and that invoke mode. In buffered mode the response is held until the function returns, capped at 6 MB. Also check that no API Gateway stage sits in front and re-buffers the stream; call the Function URL directly. (Facts Q1.9, Q1.10, Q1.13, Steps 4.)
3. What limits how long one streamed reply can last on Lambda, and what happens to a hello-chat reply that runs longer than that?
   Answer: Lambda's limits do: the function timeout, and anything sitting in front of the Function URL. A reply that outlives the timeout is cut off partway. The framework doesn't set or read the timeout, so you set one longer than your longest flow. A flow that streams for minutes belongs on a long-lived host such as Railway or Docker. In buffered mode there is also the 6 MB response cap. The 15-second `: ping` heartbeat is the engine's default; the adapter adds nothing, and the page shouldn't claim it gets around a timeout. (Facts Q1.9, Q1.11, Q1.12, Q1.16.)
4. Which store should the Lambda deployment use, and why not the default or SQLite?
   Answer: Use postgresStores({ connectionString: process.env.DATABASE_URL }) from @flow-state-dev/store-postgres, under stores: { default: { primary: ... } }. Don't use vercelPostgresStores: it skips schema creation. The default inMemoryStores() loses everything when the process exits, and a Lambda process lives only as long as its execution environment. The filesystem store and SQLite don't work on serverless. You need a database the function reaches over the network. Open the store at module scope: the pool is created on first resolve and memoized, so warm invocations reuse it. (Facts Q2.1-Q2.4, contradiction on vercelPostgresStores.)
5. The function has been idle and the first POST to /api/flows/hello-chat/actions/chat triggers a cold start. Does that caller get a 503 while the store starts up, and what does that first request cost? *(edge case)*
   Answer: No 503. On a serverless host the API waits for store init to finish before answering, and only returns 500 if init failed permanently. /healthz is different: it answers 503 { status: "initializing" } until init is ready. The first request after idle pays for store init. By default that includes schema creation, about 30 idempotent DDL statements plus an advisory lock on every cold start. To skip it, create the schema once as a deploy step and pass skipSchemaInit: true. (Facts Q1.5, Q1.8, Q2.6.)
6. You deployed the Function URL with --auth-type NONE to test it. A second person who knows the URL sends {"userId": "alice", ...} to the chat action. What happens, and what should you change before real users arrive? *(edge case)*
   Answer: The request runs as alice. The flow API takes userId from the request and treats it as authoritative, so with auth NONE any caller can act as any user and run model calls you pay for. Verifying the caller is the app's job. Use NONE only for a smoke test. Before real traffic, put IAM auth, an API Gateway authorizer or your own auth proxy in front, or give createFlowState a resolvePrincipal. Link to the authentication page for the details. (Facts Q1.17, Q1.18.)
