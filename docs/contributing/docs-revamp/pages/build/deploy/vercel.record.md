## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You have a Next.js 15 app with a flowstate handle from createFlowState and want it on Vercel. What do you write in app/api/flows/[...path]/route.ts, and what do you pass the handler?
   Answer: Import createVercelNextHandler from @flow-state-dev/vercel/next and write `export const { GET, POST, PATCH, DELETE } = createVercelNextHandler(flowstate);`. Pass the FlowState handle itself, not flowstate.getRouter(): the router is resolved on the first request, so async store setup needs no top-level await (facts Q1.1-Q1.4; nt:7-42). It also unwraps Next.js 15's async params and adds the no-buffer SSE headers (Q1.5-Q1.6). It requires Next.js 15 or later.
2. A chat answer takes three minutes of tool calls. What keeps that stream open on Vercel, and what must the route file contain?
   Answer: Three things together: the engine sends `: ping` comment frames every 15 s on live and attached streams (the engine does this, not the adapter); the adapter adds `Cache-Control: no-cache, no-transform` and `X-Accel-Buffering: no` so the proxy does not buffer the stream; and the route sets `maxDuration`. The route file must carry literal `export const runtime = "nodejs"`, `export const maxDuration = 300` and `export const dynamic = "force-dynamic"`. Re-exporting them from another module does not work, because Next.js reads them by static analysis at build time (Q2.1-Q2.3, contradiction ruling on heartbeats).
3. Where do the model key and the database connection string go, and which variable names does the app read?
   Answer: Set them in the Vercel project under Settings, Environment Variables, for the right environment (Production, Preview, Development). `.env.local` is not synced. AI_GATEWAY_API_KEY is the AI Gateway key (a provider key such as OPENAI_API_KEY works for openai/... models). FSD_DB_URL is the connection string for vercelPostgresStores(), falling back to DATABASE_URL. Set FSD_ENV=prod to pick the prod store profile, since NODE_ENV is not read. Tick Build for FSD_DB_URL, because the build-time migration needs it (Q3.1-Q3.4, Q3.6).
4. After deploying, the first request fails with 'vercelPostgresStores: no connection string', even though the build passed and FSD_DB_URL is in your .env.local. What happened, and why did the build not catch it? *(edge case)*
   Answer: The variable was set only locally, or only for another environment, so the function has neither FSD_DB_URL nor DATABASE_URL. Set it in the Vercel dashboard for that environment. The store throws when the stores first resolve on the first request, not at import (st:142-145). The migration script exits 0 with a log line when no DB URL is set, so a deployment with no database does not fail its build (Q3.5, store item 5, deploy item 4).
5. A teammate sets FSD_ENV=production on the Vercel project, but the app declares only the profiles `prod` and `dev`. What happens? *(edge case)*
   Answer: Startup throws FlowStateConfigError, listing the declared profiles. An unknown FSD_ENV name is an error, not a fallback. Resolution order is FSD_ENV, then defaultProfile, then the first declared profile, and the fallback applies only when FSD_ENV is unset (Q3.4; fsc:918-940).
6. Users trigger fire-and-forget actions whose work continues after the 202 response, and some of that work never finishes. Separately, a flow sometimes stops with a function timeout even though maxDuration is 300. What fixes each? *(edge case)*
   Answer: For the background work, pass `onBackgroundWork: (promise) => after(() => promise)` (after from next/server) to createFlowState. Without it Vercel can freeze the function once the response is sent. It is a createFlowState option, not a handler option. For the timeout, the plan's own limit wins over maxDuration. A flow that routinely outruns the function's maximum duration belongs on a container host (Railway or Docker, with @flow-state-dev/node) (Q2.4, Q2.6, Q2.7).
