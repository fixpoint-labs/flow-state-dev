## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Your support desk wants to record that ticket 4821 duplicates ticket 4790. What does the edge you add actually connect, and does the framework look up either ticket when you add it?
   Answer: An edge connects two node ids, plain strings you choose (by convention "<namespace>:<key>", e.g. "ticket:4821" and "ticket:4790"), with a direction (from -> to) and a type ("duplicates"). Nodes are not declared anywhere; a node exists only because an edge names it, and the framework never follows the id to a record. add does not check that either endpoint exists (ed:13, ed:35-39, re:196-223; correction 4).
2. You want the `ticketLinks` resource to hold links between tickets. What do you add to its definition, and do you have to put an `edges` field in its state schema yourself?
   Answer: Pass `edges` to `defineResource` (`true` for defaults, or `{ vocabulary, maxEdges }`). The framework adds the `edges: Edge[]` field to the state schema and its default for you; the edges live in the resource's own state, with no separate storage. A resource without `edges` has no `.edges` API (rs:351-352, rs:656-685, rt:164-175, re:52-60).
3. In the `linkDuplicate` block you write `ctx.resources.ticketLinks.edges.add({ from, to, type: "duplicates" })` and TypeScript fails with "possibly undefined". Why, and what is the fix? *(edge case)*
   Answer: `edges` is optional on the resource handle (`edges?: ResourceEdgeApi`), since only resources that declared edges have it. Take it once with a non-null assertion into a local, `const links = ctx.resources.ticketLinks.edges!;`, then call `links.add(...)` (rs:404, rs:529-530; correction 1, [tsc]).
4. `ticketLinks` declares `vocabulary: ["duplicates", "blocks"]`. An agent calls `add` with `type: "related_to"`. What happens? And if the same duplicate link is added twice, how many edges are stored? *(edge case)*
   Answer: `add` throws because "related_to" is not in the declared vocabulary (re:197-201, ret:71-77). Adding the same { from, to, type } twice stores two edges with two different ids, because add does not dedupe (re:203-211; correction 4).
5. The `findRelated` block calls `links.neighbors("ticket:4790")`. Ticket 4790 is only the target of 4821's "duplicates" edge. Does that edge come back, what is the return value made of, and how would you get only the links 4790 points at?
   Answer: Yes. Traversals default to `direction: "both"`, so the edge is returned even though 4790 is its `to`. `neighbors` returns an array of `Edge` objects, not node ids or ticket records. Pass `{ direction: "out" }` for only outgoing edges. The reads are synchronous over the in-state array (tr:23, tr:62-79, trt:59-75, re:99-106).
6. Later an agent finds that 4821 actually duplicates 4802, not 4790. How do you change the link so the history survives, and what do `neighbors`, a bare `all()` and `all({ at })` with a time before the change each return? Separately, if 4790 must link to a ticket three hops away, what does `shortestPath` return by default? *(edge case)*
   Answer: Call `links.supersede(oldEdgeId)` (sets validUntil to now, keeps the edge stored) and then `add` the new edge; `remove` would delete it outright. `neighbors`, `egoGraph` and `shortestPath` ignore the superseded edge, since they read edges active now by default. A bare `all()` returns every stored edge, the ended one included; `all({ at })` with a past time returns the old edge. `shortestPath` returns null for a three-hop target because the default depth is 2; pass `{ depth: 3 }` (re:225-244, tr:30-53, ret:184-194, tr:82-86, trt:143-146; corrections 2 and 3).

- Page: `shortestPath` returns null "if there isn't one" (no chain exists between the nodes). Untrue: It returns null when no chain is found within the traversal depth. Depth defaults to 2 and is clamped to a maximum of 6 (MAX_DEPTH), so a connected pair further apart than that also gets null. Callers must pass a larger `depth` for longer chains. `from === to` returns `[]`. (packages/core/src/graph/traverse.ts:16,83-85,156,174-191)
- Reference row 3: Row 3: `edges: Edge[]` "must not be declared in `stateSchema`". Untrue: The framework adds `edges` to the state schema and to the default value only when they lack one. A stateSchema that already declares `edges` is kept as is, so declaring it is allowed, just unnecessary. The stateSchema must be a `z.object`, or `defineResource` throws. (packages/core/src/types/resource.ts:661-679) The row is recorded corrected.
- Reference row 6: Row 6: `shortestPath` "returns null when no chain exists"; traversal options listed with defaults. Untrue: `shortestPath` returns null when no chain exists within `depth` (default 2, clamped to 6), and `[]` when from equals to. Defaults: `depth` 2 (clamped to 0..6), `direction` "both" (also "out" or "in"), `relationTypes` unset means all types, `at` now (only edges active at that instant). (packages/core/src/graph/traverse.ts:16-28,81-86,156-192) The row is recorded corrected.
