## Read this first: corrections the page must carry

1. **The existing page's `resolvePrincipal` example returns no organization, and the framework refuses that.** `m:108` returns `{ userId: await lookupUser(token) }`, and `m:210` returns `{ userId: grant.userId }`. The resolver contract says "the framework requires a verified organization before any effect: a resolver that yields no `orgId` ... is refused at principal resolution", and `null` "is refused for the same reason" (`at_:126-131`). `ResolvedPrincipal` is `{ userId: string; orgId: string }` (`at_:89-92`). `auth:156` returns `{ userId, orgId }` and `auth:292-294` rejects a token with no org. **[contradiction: the code wins. Every resolver on the page returns both `userId` and `orgId`.]** The page's own example is a flow, so use `createBearerSecretPrincipalResolver` (below), whose `principal` is a full `ResolvedPrincipal` (`bs:39`).
2. **A `null` from the resolver is not "401 if the flow requires a user".** `m:221-223` says `null` plus `requireUser` gives HTTP 401 with `WWW-Authenticate`. The adapter produces the 401, `WWW-Authenticate: Bearer realm="MCP"` and JSON-RPC `-32001` only when `resolvePrincipal` throws a `PrincipalResolutionError` (`ad:247-259`; status defaults to 401 when the error carries none, `ad:249`) **[test: `at:520-540`]**. What `null` does is decided by the host's principal resolution, which refuses it (see 1). **[page: say "Throw `PrincipalResolutionError` from the resolver to refuse a caller"; do not state what a bare `null` returns.]**
3. **"Every action you want exposed needs a `description`" is narrower than it reads.** The description is the action's own, else its block's: `defineFlow` resolves it once (`ft:279-284`: "Defaults to `block.description`"). Registration throws, naming the action, when an exposed action has neither (`df:1357-1370`). An action with `mcp: { enabled: false }` is skipped by the check (`df:1356`). **[page]**
4. **The opening claim that a flow exposes "its actions" is exact only for `actions`.** A flow's webhook handlers and internal actions live off `flow.actions` and are not tools **[test: `at:112`, "does not expose webhook handlers as MCP tools"]**; `ft:588-590` says `public` entries are what a caller may name over "HTTP, MCP or voice". **[page: "every action in `actions`"; the webhook and internal maps are not mentioned.]**
5. **The knowledge-base example's `fsdev.config.ts` mounts the adapter in `createFlowState({ adapters })`** (`kbc:36`), the same shape as `m:30-40`. **[page: use this shape; `createFlowState` and `inMemoryStores` are as `m` imports them from `@flow-state-dev/engine`; verify the import against `packages/engine/src/index.ts` at pass 3.]**

## Step 1: Turn it on

- **A flow is exposed only when it sets `mcp.enabled: true`.** `mcp` on the flow is `McpConfig { enabled?, exposeResources? }`, "Master enable. Default: false" (`ft:330-342`). A flow without it answers every method except `initialize`, `ping` and `notifications/initialized` with JSON-RPC `-32601` `Flow "<kind>" is not exposed via MCP.` (`ad:222-229`) **[test: `at:502`]**. `initialize` and `ping` answer for any `kind` and do not check the flow (`ad:219-224`). **[page: "Without it, the endpoint answers every tool request with `-32601`."; the `initialize`/`ping` detail is [ref].]**
- **One server per flow.** The endpoint is `POST /api/flows/:kind/mcp`, so the flow is the MCP server and the tool name carries no flow prefix (`ad:1-6`, `tc:5-8`). `initialize` returns `serverInfo.name` = the flow's `kind` and `version` `"1.0.0"` (`ad:328-331`) **[test: `at:318`]**. **[page: the URL; `serverInfo` is [ref].]**
- **Mount the adapter once, on the app's `createFlowState`.** `adapters: [createMcpTransportAdapter()]` (`m:30-40`, `kbc:36`); the adapter's doc comment shows the lower-level `createFlowApiRouter({ registry, stores, adapters: [...] })` (`packages/mcp/src/index.ts:9-16`), which a recipe does not need. Install: `pnpm add @flow-state-dev/mcp` (`m:21`). **[page]**
- **Next.js needs the catch-all route unchanged.** `app/api/flows/[...path]/route.ts` exports `createVercelNextHandler(flowstate)` from `@flow-state-dev/vercel/next` (`m:44-48`; `packages/vercel/src/next.ts:17`). The MCP route is under the same prefix, so nothing new is mounted. **[page: one sentence and a link to the Next.js recipe/S-5; verify the destructured exports at pass 3 against `packages/vercel/src/next.ts`.]**
- **`GET` and `DELETE` on the endpoint return `405` with `Allow: POST`** (`ad:162-171`, `ad:597-602`) **[test: `at:266`, `at:274`, `e2e:130`]**. The endpoint shadows the HTTP catch-all at that path **[test: `e2e:110`]**. **[ref]**
- **Where the endpoint lives is configurable.** `basePath` defaults to `/api/flows`; `dedicatedBasePath: true` mounts at `<basePath>/:kind` with default `/mcp`, so `POST /mcp/billing`, and mounts only that layout (`ad:82-94`, `ad:138-156`; `at:211-258`; `e2e:141`). A root-only dedicated base throws `TypeError` "dedicated basePath must include a non-root prefix." (`ad:141-145`; `at:212`). In a Next.js app a dedicated prefix needs its own route file `app/mcp/[...path]/route.ts` exporting the same handlers; `serve()` from `@flow-state-dev/node` and `fsdev serve` mount dedicated paths themselves (`m:77-85`). **[ref: options table; page: one sentence and the link.]**
- **`fsdev serve` stands up the flow API and MCP routes from a committed `fsdev.config.*`**, with no DevTool (`m:54-56`; `apps/docs/docs/api/cli.md:165`, `:183`). It binds `$PORT` then `3000` on `$HOST` then `0.0.0.0` (`cli.md:183`). **[page: one sentence; the rest is `reference/cli`.]**

## Step 2: Choose which actions are tools (answers Q1)

- **Every action in the flow's `actions` is a tool unless it opts out.** `resolveExposedActions` skips an action only when `action.mcp?.enabled === false` (`tc:76`; `ft:134-139`: "Default: true") **[test: `at:106`]**. **[page]**
- **The tool name is the action key, decamelized.** `recordPayment` becomes `record_payment`; `URLParser` becomes `url_parser`; `getHTTPSProxy` becomes `get_https_proxy`; `IOError` becomes `io_error`; a key with a hyphen or underscore is kept (`event-queue`, `event_queue`) (`tc:31-40`) **[test: `at:92-103`]**. **[page: `recordPayment` to `record_payment` and one more; the table of five is [ref].]**
- **`mcp: { name: "log-payment" }` on an action overrides the name** (`ft:140-145`; `tc:78-82`) **[test: `at:138`, and a `tools/call` by override name `at:333`]**. A name must match `[A-Za-z0-9_.-]{1,128}`; otherwise the flow throws naming the action, "Rename the action." (`tc:42-55`). **[page: the override; the charset is [ref].]**
- **Two actions that resolve to one tool name throw when the exposed actions are resolved**, naming both keys and suggesting `mcp.name` (`tc:85-92`) **[test: `at:155`, `at:175`]**. It also applies to an override colliding with a derived name (`at:175`). **[page: one sentence.]**
- **When the throw happens: at the first `tools/list` or `tools/call`, not at flow definition.** `resolveExposedActions` is called from `listTools` and `handleToolsCall` (`ad:339`, `ad:384`); `defineFlow`'s MCP check only covers descriptions (`df:1348-1375`). The `tc:62-64` doc comment says "must surface at startup" and `m:161-162` says "throws at flow registration"; the code does not do that. **[contradiction: the code wins. The page says "the first request fails with an error naming both actions" or says nothing of timing. Do not state "at registration" for collisions.]**
- **A description is required on every exposed action** (see correction 3), and it is the tool's LLM-facing description (`tc:10-11`, `ft:279-284`). **[page]**
- **The tool's input schema is the action's input schema**, `action.inputSchema ?? action.block.inputSchema`, converted to JSON Schema (`tc:103-109`). A Zod `.describe()` on a field shows up in the schema (`m:190-192`; `zod-to-json-schema` is what `schema.ts:13`, `schema.ts:30` uses). A schema with no properties, or one that is not an object, becomes `{ type: "object", properties: {}, additionalProperties: false }` (`packages/mcp/src/schema.ts:38-52`) **[test: `at:198`, `at:204`]**. **[page: the first sentence; the parameterless case is [ref].]**
- **What a tool call returns: one text block.** If the action's terminal output is set it is stringified (a string as is, anything else as JSON); otherwise the text of the most recent `message` item, or the output of the most recent `block_trace` item; otherwise an empty string (`rf:1-13`, `rf:29-39`, `rf:56-76`) **[test: `e2e:87`, the text contains `4200`]**. An error result is the error's message as text with `isError: true` (`rf:30-34`, `rf:41-54`). No `outputSchema`, `structuredContent` or progress notifications (`tc:13-14`, `m:378-383`). **[page: first sentence; the order and `isError` are [ref].]**
- **Every call is a new session unless the action opts in.** By default a `tools/call` dispatches with `sessionId` undefined, which is a fresh flow session, and no `Mcp-Session-Id` is issued (`ad:9-11`, `ad:408`; `m:281-282`) **[test: `at:728`]**. `mcp: { session: "conv_*" }` mints an id per call, replacing the first `*` with a random token or appending it; `mcp: { session: { fromInput: "conversationId" } }` uses the string at that input field; a missing, blank or non-string value falls back to a fresh session (`ad:481-507`; `ft:151-175` is the type) **[test: `at:734-780`]**. **[page: one sentence and a link; this is `reference/mcp-server` and C-04/C-05.]** The id is a flow session id grouping key only, not an auth decision, and a caller-chosen id can be read by anyone who guesses it unless keys are namespaced (`m:305-327`). **[ref]** Not part of the four steps. **[page: omit; one line under "next".]**
- **`forwardQueryParams` fills an input field from the endpoint URL, overriding what the model sent.** `createMcpTransportAdapter({ forwardQueryParams: ["source"] })` merges `?source=claude-desktop` into the `tools/call` input; the value wins over a same-named argument; a param not in the list is ignored; forwarding nothing is the default (`ad:103-120`, `ad:390-406`, `ad:628-651`) **[test: `at:591-680`]**. It takes effect only if the action's input schema accepts the key (`ad:115-117`). It is not an authentication mechanism (`m:273-277`). **[ref; the page may mention it once as the way to tag an installation.]**
- **Resources are not exposed.** `resources/list` returns an empty list; `resources/read` answers `-32002` for everything; `resources/subscribe` and `resources/unsubscribe` answer `-32601` (`ad:277-290`, `ad:513-565`; `m:384-388`) **[test: `at:565`, `at:577`]**. `McpConfig.exposeResources` exists (`ft:338-341`) and reads "exposes flow-scoped resources ... Default true", which promises more than the adapter delivers. **[contradiction: the code wins. [ref]; the page does not mention resources.]**

## Step 3: Connect a client

- **The URL is `http://localhost:3000/api/flows/<kind>/mcp`** for a flow of that `kind` on the dev server (`m:138-142`). With a dedicated base path it is `.../mcp/<kind>` (`ad:153-155`). **[page]** The port depends on how the app runs: `fsdev dev` binds `4200` on loopback and `fsdev serve` binds `$PORT` then `3000` (`cli.md:183`); `m:138` uses `3000`, the Next.js default. **[contradiction: m's `3000` is for a Next.js dev server. Say "your server's URL" and use `https://app.example.com/api/flows/support/mcp` as the example, as `m:253` does.]**
- **`tools/list` returns the exposed tools, each with `name`, `description` and `inputSchema`** (`tc:25-29`, `ad:264-265`) **[test: `at:437`]**. `tools/call` takes `params.name` and `params.arguments` (`ad:379-382`). `ping` returns `{}`; `notifications/initialized` returns `202` with no body (`ad:216-221`). **[page: `tools/list` returns the tools; the rest is [ref].]**
- **Transport: Streamable HTTP, stateless, single JSON response per request** (`ad:3-4`, `ad:8-13`). Protocol versions understood: `2025-06-18` and `2025-03-26`; a client that asks for another gets `2025-06-18`, a client that asks for none gets `2025-03-26` (`ad:78-80`, `ad:310-320`) **[test: `at:292`, `at:305`]**. **[ref]**
- **Claude Desktop and Cursor are named as clients** (`m:12-17`). The page may name them as examples of "an MCP client". No config-file syntax for either client exists in the repo's docs or code, so the page does not show one. **[page: a sentence saying "point the client at this URL, with the bearer token as its `Authorization` header"; no client-specific JSON.]** There is no client-side config in `examples/` or `labs/` to cite. **[left out: "how to add the server in Claude Desktop's config".]**
- **A browser-originated request is refused with `403` unless its `Origin` header matches the request's own origin**; clients that send no `Origin` (Claude Desktop, Cursor, most non-browser clients) are unaffected. `allowedOrigins: ["https://app.example.com"]` allows listed origins, `"*"` allows any and is for local development (`ad:95-102`, `ad:604-620`; `m:354-367`). **[ref; page: one sentence only if the reader is connecting from a browser.]** No test pins this check in `at:` or `e2e:`. **[note: stated from `ad` only.]**
- **The request shows up with `source: "mcp"`.** `tools/call` stamps `RequestRecord.source = "mcp"` (`ad:70`, `ad:413`) **[test: `e2e:87`, `stores.request.list` returns `source` `"mcp"`]**, and the DevTool marks the request with an MCP badge (`m:144-147`, `m:392-398`). The tool name and method ride in the request's metadata: `{ mcpMethod: "tools/call", mcpToolName: name }` (`ad:423`). **[page: one sentence: how to tell an MCP call from a chat call.]**
- **Errors a client sees, each a JSON-RPC error body** (`er:2-22`): `-32700` bad JSON; `-32600` bad envelope or no flow kind; `-32601` unknown method, unknown or opted-out tool, flow not exposed; `-32602` bad `params`, a dispatch failure, or "Unknown session" for a session another user or organization owns **[test: `at:409`]**; `-32000` server busy, with `data: { retryable: true }`, for a concurrency `reject` or a `queue` that times out **[test: `at:359`, `at:381`]**; `-32001` authorization; `-32002` resource denied. **[ref: the table; the page mentions `-32601` for an opted-out tool and the 401 below.]**
- **An opted-out action is not a tool, and calling it by name answers `-32601` "Unknown MCP tool"** (`ad:384-388`) **[test: `at:489`]**. **[page]**

## Step 4: Who the caller is (answers Q2)

- **The caller is whoever the flow's `authentication.resolvePrincipal` says it is.** The adapter resolves the principal once per request, for `tools/list` and `tools/call` and every other method past the flow check, through the same `host.resolvePrincipal` that HTTP requests use (`ad:231-246`; `m:198-200`). **[page]**
- **The resolver gets `ctx.source === "mcp"`, the native `Request`, and an envelope** `{ flowKind, action, input, metadata: { mcpMethod } }`; `action` is the tool name's mapped value for `tools/call` (`ad:236-245`) and `"(metadata)"` for every other method. The `tools/call` value is the tool name the client sent (`extractToolName`, `ad:241`, `ad:622-626`), which for a renamed tool is the override name and not the action key. `PrincipalResolutionContext` is `{ source, request?, envelope, rawBody? }` (`at_:102-118`). **[page: source and `request`; the envelope detail is [ref].]**
- **Credentials go in the `Authorization` header.** `createBearerSecretPrincipalResolver({ secret, principal })` compares `Authorization: Bearer <secret>` in constant time and returns the fixed `principal` on a match; a wrong token throws `PrincipalResolutionError` with status 401; a missing header or non-Bearer scheme returns `null` (`bs:47-88`). It throws at construction when `secret` or `principal.userId` is empty (`bs:57-69`) **[verify: no test cited; read from source.]** The `headerName` option reads a different header (`bs:40-44`). **[page: the resolver in the example and "a wrong token is a 401"; the empty-secret throw is what the example guards against with `process.env` (`kb:163-174`) and may get one sentence.]**
- **One secret gives one principal: every caller is the same user.** That fits a personal server, which is what `kb` is (`kb:1-10`, `kb:168-172`: "the single personal user the corpus binds to"). **[page: say so.]** For a different user per client, write the resolver: read the token, look up its owner, return `{ userId, orgId }`. `createHs256JwtVerifier` and `extractBearerToken` from `@flow-state-dev/engine` are usable inside it (`m:229-237`; `auth:265-300` is a complete JWT example including the `orgId` check). The framework keeps no table of tokens (`m:233-235`). **[page: one sentence and a link to C-17 and `reference/auth`; `auth:265-300` is the example, not reprinted.]**
- **A resolver refuses a caller by throwing `PrincipalResolutionError`.** The adapter answers HTTP `401` (or the error's `status`), JSON-RPC `-32001` with the error's message, and, for a `401` only, the header `WWW-Authenticate: Bearer realm="MCP"` (`ad:247-259`) **[test: `at:520-540`]**. `PrincipalResolutionError` is exported from `@flow-state-dev/engine` (`ad:42`) and takes a message and `{ status }` (`at:526`). **[page]**
- **Query-string credentials are not read.** The adapter reads no credential itself; a resolver may read the URL, but the page says "put the token in the `Authorization` header" (`m:218-219`: "Per the MCP spec, tokens must be in the `Authorization` header — the adapter does not honor query-string credentials"). The first half is a protocol statement the repo's docs make, not an adapter check; the adapter has no credential code to honor or reject one (`ad` has no query-credential handling). **[page: "Send the token in the `Authorization` header."]**
- **Every user and organization the principal names owns what the call writes.** The action runs under the resolved `userId` and `orgId`, and the framework refuses a session whose stored owner differs: the client sees `-32602 Unknown session "<id>"` and never the owner's name (`ad:467-475`) **[test: `at:409-433`]**. The `orgId` and `userId` an action runs under come from the resolver alone; a value in the request body does not change them (`auth:41-42`). **[page: one sentence; the rest is C-17.]**
- **No bundled OAuth.** Authentication is whatever the resolver returns (`m:379`). **[ref: limits row.]**
- **If `resolvePrincipal` is not set, the flow uses the default resolution and `requireUser` defaults to true** (`ft:575-578`). What the default resolution accepts on an MCP request is not documented on any page and not tested in `packages/mcp`; `kbc:25-31` says a missing secret "would leave `resolvePrincipal` undefined and fall back to the unauthenticated default body-userId resolver". **[page: tell the reader to set a resolver before exposing a flow beyond localhost; cite `kbc:25-31`. Do not describe the default's behavior further.]**
- **Fail closed in the app's config.** `kbc:30-32` throws at config load when a hosted deploy has no secret, and `kh:21-33` mounts the MCP adapter only when the secret is set. **[page: one sentence, optional; both are patterns, not framework behavior.]**

## Stored data: the four questions

The page tells a reader to configure an endpoint and a resolver, and stores nothing of its own. The one stored thing a call touches is the flow session a call creates.

| Part | Who owns it | Who can see it | Where it is stored | How many exist |
| --- | --- | --- | --- | --- |
| The session a `tools/call` runs in | The principal the resolver returned (`userId`, `orgId`); a later call with a different user or org is refused as an unknown session (`ad:467-475`; `at:409`) | The flow's own readers under its normal session rules; the MCP client sees only the tool result text (`rf:29-39`) | The flow's session store, the one `createFlowState({ stores })` names (`m:33-37`) | One per call by default (`ad:408`; `at:728`); with `mcp.session`, one per distinct minted id or `fromInput` value (`ad:493-507`; `at:734-780`) |
| The request record | The same principal | DevTool, with source `"mcp"` and the MCP badge (`m:144-147`) | The request store, `stores.request` (`e2e:87-108`) | One per `tools/call` (`e2e:97-100`). `initialize`, `ping`, `tools/list` and `resources/*` dispatch no action and make none (`ad:216-224`, `ad:263-290`) |
| The tool list, tool names, descriptions | The flow definition's author: derived at request time from `flow.actions` | Anyone who can pass the resolver | Not stored; computed each `tools/list` (`ad:335-345`) | One per flow |
