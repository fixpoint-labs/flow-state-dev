## Stored parts: the four questions

The page does not store anything. It reads three stored parts through the debug view, and each answer below is what the reader needs to read the panel correctly.

33. **A resource's state** (one record). *Owns:* its scope identity, `session`, `user` or `org` (`rc:19-24`, `:199-204`); the Resources panel groups by that scope (`rt:49-64`). *Sees:* the DevTool's Server tab sees all of it except `secret` fields (`ds:449`); the browser sees the `client` projection of it, and only if the definition carries one (fact 1); blocks on the server read everything through the handle. *Stored:* the resource store, one record keyed by scope then storage key (`srt:98-102`: `stores.resourceState.get("session", SESSION, "keys/linear")`); the same SQLite file in the default `fsdev dev` setup (`b06` fact 90). *How many:* one per scope identity: one per session at session scope, one per user at user scope, one per org at org scope (`res` figure and facts; `rc:199-204`). **[page: one clause; detail is `reference/resources`.]**
34. **A collection's items** (one record per item). *Owns:* the collection's scope identity. *Sees:* the DevTool lists every item the session's user may read, 50 per page (fact 12); the browser's snapshot carries `count` always and an inline window only under `prefetchWindow`, with per-item state only under `state.read` (`ru:481-513`). *Stored:* the same resource store, one record per item, under the pattern prefix and the item key (`ds:576-607`; `res` "Collections"). *How many:* as many as are created, up to `maxInstances` if the collection sets it (`cc:115`). **[page: "47 items" is the example's number.]**
35. **A resource's content body** (a string beside the state). *Owns:* the same scope identity as its state. *Sees:* the DevTool fetches it on demand with `View content` and tags it `server-only` when `client.content.read` is not true (`rt:414-460`); the browser reads it only under `client.content.read` (`rr:171`, `:221`: 403 `Content read not permitted for "<ref>"`). *Stored:* the content store beside the state store (`srt` setup shows both stores are separate: `ctx.stores.resourceState`; the content store is `ds` `persisted.content`, `:450-451`). *How many:* at most one per resource or item. **[page: a sentence that content has its own switch; the 403 string is [ref].]**
