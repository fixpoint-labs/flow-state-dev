## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You run a support desk app on Flow State and a colleague says a package on npm "has a community kit" for ticket routing. What is that thing, technically, and what do you take from the package?
   Answer: It is an ordinary kit, not a special type: the factory that `defineKit` (from `@flow-state-dev/core`) returns, exported by a package outside this repository. The app calls the factory with the kit's config and lists the result in `createFlowState({ kits })`. Facts 1.1, 1.2, 1.3, 2.2; section 1 intro (no "community" distinction in the surface).
2. You run `pnpm add` on that routing kit's package and restart the support desk app, but nothing new shows up. Why, and what is the missing step? *(edge case)*
   Answer: Installing a package adds nothing by itself. An app uses only the kits in its own `kits` list, so you call the kit's factory with its config and add it to `createFlowState({ kits: [...] })`, in any order. Facts 2.1, 2.2, 4.2, section 6.
3. Is there a Flow State registry or `fsdev` command you can use to search for kits, or to install one?
   Answer: No. `fsdev` has no kit command, and the framework keeps no list of kits. Nothing reads a package's metadata to find kits. An app uses only the kits it lists in `kits`. Facts 4.1, 4.2, 4.3.
4. You open the "From the community" shelf hoping to find a published kit to try. What will you find there today?
   Answer: The shelf has no entries. The three kits that ship with Flow State (`workforce`, `harnesses`, `claudeCode`) sit on the Catalog page above it. The page doesn't claim that no other kits exist anywhere, only that none are listed here. Facts 3.1, 3.3, section 6.
5. You want to publish your own kit and get it on this shelf. Where do you go, and what can the page tell you about getting listed?
   Answer: For writing and publishing a kit, the page links to B-04 and doesn't explain it itself. Nothing citable says how a kit gets listed on the shelf: there is no submission path, review or naming convention, so the page must not invent one (flag 1, section 7). How an app installs a published kit is stated: install the package, then list the factory in `kits` (fact 2.2).
6. The community routing kit adds an entry to the workforce kit's slot, but its author forgot to list `workforce` in its `requires`, and your app only lists `routing(...)`. What happens when the app starts? *(edge case)*
   Answer: A community kit meets the same start-up checks as a kit that ships. A kit that fills another kit's slot must require that kit, otherwise start-up fails with `kit "<name>" fills slot "b.order", but does not require kit "b"`. A required kit must also be listed in `kits`, otherwise `kit "c" requires kit "b", which is not installed.` The kit's name must also be unique in the app. Facts 2.3, 2.4, 2.5, section 6 (`claudeCode` with `requires: [harnesses]` is the shipped example).
