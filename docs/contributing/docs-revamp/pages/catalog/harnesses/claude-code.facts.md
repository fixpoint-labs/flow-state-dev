## Q1 · What credential does it need, and how do you check before a run?

25. **Three ways a run can have a credential: an API key, an OAuth token, or a `claude` sign-in.** The pass-list names `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN` (`ep:23`; `ep:12-15` "the two ways it can be given a credential"). A sign-in is "a file under the home folder, or the keychain on macOS" (`ap:101-103`). The remedy sentence is `CLAUDE_CODE_SIGN_IN_REMEDY` = "Sign in with `claude`, or set ANTHROPIC_API_KEY" (`ap:201`). **[page]**
26. **Ask Claude Code, do not look at variables.** The probe opens one `query()` with streaming input that never yields (no user message, no model turn), asks `accountInfo()`, closes; "About half a second on Linux" (`ap:92-99`). It asks Claude Code because a sign-in is found "the way the run finds it" (`ap:101-104`). **[page: one sentence; "no model turn"]**
27. **`probeClaudeCodeAccount({ env, timeoutMs?, signal?, importSdk? })` returns one of three, and never throws.** `ap:133-146`, `ap:116-130`, `ap:164`: `{ status: "account", apiKeySource?, tokenSource?, email?, subscriptionType? }`, `{ status: "none", reason, unanswered?: true }`, `{ status: "sdk-missing", reason }`. Default `timeoutMs` 10 000 (`ap:155`). Tests: `apt` (scripted: `account` with an API key source, token source, subscription sign-in; installed-SDK cases with an empty home read `none`). **[page: the three statuses in a short table or one sentence; the option table ref]**
28. **A subscription sign-in comes back as `email` and `subscriptionType`, not a source.** `ap:122`, `ap:181-187` ("Claude API" is the no-plan label, not a sign-in); `apt:56-64` (`email: "a@b.c"`, `subscriptionType: "Claude Max"` reads `account`). **[ref]**
29. **Pass the same `env` the run gets.** "so a credential the run can't see isn't counted" `ap:135-138`; `ap:104-105`. **[page: one sentence, with the example below]**
30. **It checks where a credential would come from, not that it works.** "a key that is set but rejected reads as `account`" `ap:104-106`; `old:878`. The failure lands on the run's first turn. **[page: one sentence; a limit]**

## Q2 · How do you continue yesterday's session?

There are two paths. They answer differently, and the page says which one the reader is on.

54. **Kit path: nothing to do for a task's own retries and answers.** The manager supplies `resume` and records `onSession`; a retry, an answered question, a steering line and a review's "ask for changes" each resume the same coding session. `hm:120` ("the task takes one more turn on the same attempt, and that turn's run picks up the same coding session"), `hm:355-357` (steer), `hm:159-160` (changes), `hm:215` (approval). "A talk line" after a task finished resumes the task's confirmed session (`hm:357`). **[page: one paragraph; mechanism ref to C-23 and `hm`]**
55. **Kit path: a session the agent cannot find is replaced.** "The manager records only a session the harness *confirmed* it was in. If the agent can't find the session a run asked to continue, the next run starts a fresh one, with the brief, the question and the answer in its prompt." `hm:128`. The block classifies the failure: `ClaudeCodeAgentRunError.harnessFailure` is `"unknown-conversation"` when Claude Code refused to continue the id; `harnessFailureKind(error)` from core reads it; the match is on the exact requested id (`err:324-342`, `err:393-410`; `ukt:27-48`). **[page: one sentence; the classification ref]**
56. **Kit path: a finished run whose harness never confirmed a session cannot be talked to.** `hm:725` (`cannot-continue`), `hm:427`. **[ref]**
57. **In-session path (the block on its own, the default): the next request in the same session continues it.** The block reads the saved `sdkSessionId` from session state, resolves it through its session provider, and hands the SDK `resume`; after the run it writes the new id back and appends the handle to `sdkAgentRuns`. `ag:1017-1030`, `ag:1618-1630`; keys `CLAUDE_CODE_SESSION_ID_KEY = "sdkSessionId"`, `CLAUDE_CODE_AGENT_RUNS_KEY = "sdkAgentRuns"` (`ag:161-169`); test: `agt:1700-1730` (`resumeHandedToSdk`: with `session.state.sdkSessionId = "sess_prior"` the SDK is handed `resume: "sess_prior"`; `agt:2961-2985`). The session record is `createClaudeCodeSessionProvider()`; `resolve("")` is a fresh session, a non-empty key resumes that id; `release` does nothing (`ses:287-296`; `test/sdk/session.spec.ts:5-26`). **[page: answers Q2 for a block in your own flow; one short example reading the saved id: `ctx.session.state.sdkSessionId`]**
58. **"Yesterday" holds as long as the session does.** The resume id lives in session state, so a request that arrives in the same session on another day resumes the same Claude Code conversation (it is stored with the session; where the session is stored depends on the store). The default session provider is "resume-by-id" and keeps nothing itself (`ses:1-10`). Claude Code must still have the conversation: a session the SDK no longer has fails as item 55. **[page: one sentence: "same session, same id"; and that persistence follows the store, linking Persistence]**
59. **Detached path: the host passes the id.** With `detached: true` nothing is read from or written to session state (`ag:1017-1019`, `ag:1618`; `old:131-137`). Two options continue a run: `resume: (ctx) => string | null | undefined` says which session to continue; `onSession: (id, ctx) => void` is called "the moment the SDK names the session" with the id the agent confirmed. `ag:612` (`resume`), `ag:634` (`onSession`), doc comments above each; `old:165-205`. `null` and `""` both mean start fresh and reach the SDK as no `resume` (`ag:1063-1070`; `agt:1819-1835`). **[page: the pair, with an example; typed with `resume: (ctx) => … ` and `onSession: (id, ctx) => …`]**
60. **`onSession` fires during the run, not at its end,** so a run that is cancelled or throws, which returns no handle, still gave the host its id; it fires once per distinct id; it reports the session the agent *confirmed*, which can differ from the one asked for; "treat the hook never fired as there is nothing to continue". `ag:634` doc comment; `old:189-200`. A slow hook slows the run and a throwing one fails it. **[page: one sentence on "during"; the rest ref]**
61. **`resume` and `onSession` without `detached: true` throw at construction.** Message begins "`claudeCodeAgent`: `resume` … background-path only" and ends "Set `detached: true` … or drop …". `ag:927-946`; `agt:2125-2129`. **[page: one sentence; a limit]**
62. **Do not read `resume` from the block's input.** The input is `{ prompt, attachments? }`; `cwd`, `resume`, `sandbox`, `model` resolvers are handed the context alone, never the prompt, so a caller (or a model holding the block as a tool) cannot choose them. `ag:580` (`cwd`) and `ag:1040-1062` (comment); `ca` "The prompt is the input, everything else is configuration". **[page: one clause as the reason `resume` is an option]**
63. **The session id stays on the handle either way.** The handle carries `sessionId` for every run, in-session or detached (`ag:1601-1603`; `old:140-146`). **[page: one clause]**
64. **A throwaway directory and a resumed conversation do not go together.** A `resume` handed to the SDK for a conversation made in another directory picks up mid-task in an empty tree; `agt:2961-2990` ("does not resume a prior conversation into a fresh throwaway directory"). **[ref: the working-directory page; or one sentence here since the page shows `resume`]**
