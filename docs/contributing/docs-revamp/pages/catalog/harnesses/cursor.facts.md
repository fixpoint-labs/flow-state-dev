## What it is

7. **`@flow-state-dev/cursor` runs Cursor's coding agent as a block.** The block starts or resumes a Cursor agent in a directory the host resolved, sends one prompt, mirrors what the run says and does into the item stream, and returns the framework's neutral harness handle plus Cursor's extras. `agent:1-9`; `idx:1-12`; `pkg:4`; `cu:9-13`. **[page]**
8. **It drives Cursor's local runtime through the Cursor SDK.** The editor is not needed; the SDK brings its own runtime. `cu:46-47`; `agent:3-4`. **[page]**
9. **Cursor owns its own loop.** The framework does not drive it step by step or re-implement its tools. `cu:25-30`. **[page: one sentence]**
10. **It is one of three coding agents that return the same handle.** Claude Code and Codex are the others, and a step that reads the handle runs any of them. `cu:20-24`, `cu:431-433`; `ca:31`. **[page: one clause, link to the harness model on C-23]**
11. **Local agents only.** A `cloud` bag on `agent` or `send` is refused when the block is built. `agent:376-379`, `agent:388-392`; `cu:425-426`; `cu:123`. **[page: one sentence]**
12. **One run per call.** The block sends a prompt, watches the run to its end, and returns. `cu:423-424`. **[page: fold into "limit" sentence]**

It never throws. `sign:35-36`, `sign:48-75`; `readme:200-204`. **[page: one sentence, since the slot runs it for the reader; signature ref] [Q1]**

## As a step

43. **`cursorAgent(options)` is a handler block.** Import `{ cursorAgent }` from `@flow-state-dev/cursor`; step it in a sequencer. `cu:90-109`; `agent:434-449`, `agent:472`. **[page]**
44. **Its input is the prompt and nothing else.** The input schema is core's `harnessRunInputSchema`: `prompt: string` and optional `attachments` (stored file references; bytes never ride on the input). `agent:480`; `packages/core/src/types/harness.ts:139-143`. An empty or whitespace-only prompt throws `CursorAgentRunError` before anything opens. `agent:493-496`. **[page: the input is the prompt; the empty-prompt row is ref]**
45. **Where a run writes, which conversation it continues and which model it runs are configuration, not input.** The block is also exposed to a model as a tool by its capability, and a field on the input is a field the model could set. `agent:11-14`; `cu:111-114`. **[page: one sentence]**
46. **`cwd` is a function of the block context, called once per run before anything opens.** It is handed the context and never the prompt. `agent:136-146`; `agent:707`; `cu:202-205`. **[page]**
47. **The output is `CursorAgentHandle`**: the neutral handle (`source: "cursor/sdk"`, `status`, `sessionId`, `url`, `dispatchedAt`, `outcome`, `finalMessage`, `usage`, `cost`) plus `cursorUsage` and `failureMessage`. `types:84-90`, `types:99-112`; `agent:1011-1026`; `readme:206-210`. `url` is always `null` (`agent:1015`). **[page: the neutral fields in a clause; the Cursor extras one sentence; fields ref]**

## Continuing a session [Q2]

55. **Cursor calls the durable conversation an agent, and each prompt is one run inside it.** `sessionId` on the handle is the agent id, not a run id, and the agent id is what `resume` takes. `agent:993-995`; `cu:296-298`; `readme:212-214`. **[page] [Q2]**
56. **Continuing one is two halves you write: `resume` reads the agent id, `onSession` writes it.** `resume: (ctx) => ...` returns the id, or `null`, `""` or `undefined` to open a fresh agent. `onSession: (id, ctx) => ...` is called with the id the moment the SDK opens the agent, before the prompt is sent. `agent:147-167`, `agent:707-722`; `cu:300-314`. **[page] [Q2]**
57. **The package keeps no session state of its own.** The agent id lives wherever the app puts it. `cap:11-20`; `cu:309`, `cu:323-325`. **[page: one sentence]**
58. **A run that is later cancelled is still resumable,** because `onSession` runs before the prompt is sent and the thrown error also carries the agent id. `agent:15-18`, `agent:168-170` (comment: "the only carrier that survives a cancelled run"), `agent:155-166`; `err:210-212`; `cu:313-314`, `cu:414-415`. **[page: one sentence] [Q2]**
59. **A resume Cursor refuses throws instead of opening an agent, so the id you hold is left as it was.** When Cursor doesn't know the agent, the error is a `CursorAgentRunError` and `harnessFailureKind(error)` reads `"unknown-conversation"`; any other failure reads `null`, including one after Cursor has resumed the agent. `agent:743-760`, `agent:161-166`; `err:145-173`, `err:175-189` (matches Cursor's code `agent_not_found`); `cu:316-321`, `cu:401`. **[page: the `"unknown-conversation"` sentence; `harnessFailureKind` import is `@flow-state-dev/core/harness`, **[verify]** check its export before the page shows it] [ref: other codes]**
60. **`HOME` must be the same for the run that made the agent and the run that resumes it.** Cursor keeps its agents and stored login under it. `agent:268-270`; `cu:250-252`. **[page: one sentence, since `cursorHarness()` always passes `HOME`]**
61. **Cursor's per-workspace state is kept under `~/.cursor/projects/<name>`, `<name>` being the working directory flattened.** A directory whose flattened name is over 255 bytes is handed to the SDK through a short link: `<tmpdir>/fsd-cursor-<uid>/<digest of the path>`, pointing at the real directory. The agent's files and commits land in the real directory. The same path makes the same link, so a resumed agent finds its state. `alias:1-18`, `alias:20-23`, `alias:34-61`. **[ref; page: nothing, or one clause "deep checkout paths work"]**
62. **A different agent on a different `cwd` doesn't continue the old one.** Not claimed anywhere; do not state.

## What it emits while it works [Q3]

63. **Item table.** Assistant text becomes `message`; thinking becomes `reasoning`; a tool call becomes `tool_output`, opened when the call starts and settled with its result; a change to Cursor's to-do list is a `tool_output` like any call; run and task lifecycle become transient `status`; run end becomes a kept `status`; errors become `error`. `cu:129-137`; `packages/cursor/src/translate.ts:48-94` (message types), `translate.ts:60-62` (thinking), `translate.ts:65`, `translate.ts:151-162` (tool call and result). **[page: the table is ref; the page names message, reasoning, tool output and status in one sentence] [Q3]**
64. **Run end statuses:** `Cursor run completed in <duration>.` on a finished run; `Cursor run errored (<reason>).` otherwise, both kept in session history. `agent:1028-1033`; `cu:136`. **[page: one sentence with the finished form]**
65. **On open, a status `Cursor agent <id>` names the agent.** `agent:731`. **[ref]**
66. **Every item carries provenance, so the devtool shows the trace of what the run did.** `cu:139-140`. **[page: one sentence, **[verify]** not run in the devtool here]**
67. **Output the package doesn't recognise becomes a status note rather than an error.** `translate.ts:89-94` ("Cursor emitted an unrecognised message: ..."). `cu:142-143`. **[ref]**
68. **Token counts never reach the stream; they ride the handle.** `cu:145`. **[page: one clause]**
69. **Cursor's own `onStep` and `onDelta` observers pass through `send` untouched, and the item stream is built from the run's messages, not from them.** Taking both shows the same run twice. With `env` set a function in `send` is refused. `cu:147-151`; `agent:403-425`. **[ref]**
