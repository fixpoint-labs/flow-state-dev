## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You want a whole working app, say the Teammates app with its list of workers and their long conversations, that you can open, run and reshape into your own. Which shelf do you go to?
   Answer: Starters. A starter is a whole app you copy and change. Teammates lives in labs/teammates, which the labs README describes as "A Grok Bot-style app on the workforce package" (labs/README.md:24). Labs are "past the 'minimal example' stage but not a shipped product: still research software" (labs/README.md:3-7). Fact sheet sections 2 and 6.
2. You already have an app and only want one tool block, such as fetch, to pass to a generator's tools array. Which shelf, and does anything go into createFlowState({ kits })?
   Answer: Libraries. You install @flow-state-dev/tools and import the block; nothing is listed in kits. The tools README says "Each tool is a handler block that can be passed directly to a generator's `tools` array" (packages/tools/README.md:3). A library has no slots and no folder; a kit may have both (define-kit.ts:6-9). Fact sheet sections 4 and 6.
3. You want your existing app to have workers, plus coding runs through Claude Code, without wiring the flows yourself. Which shelf is that, and which entries do you pick?
   Answer: Kits. A kit "packages a feature so an app installs it with one config object" (define-kit.ts:4-6). The app lists kits in createFlowState({ kits }), "each a kit's factory called with its config, in any order", and they install in requires order (engine flowstate/types.ts:126-130). You would pick workforce (@flow-state-dev/workforce), harnesses (@flow-state-dev/harness-manager) and claude-code (@flow-state-dev/claude-code). Those three are the only kits there are. Fact sheet 3.3, 3.5-3.7, 3.9.
4. You look on the Kits shelf for a Codex kit and a Cursor kit and find neither. Did you miss them, and how do you add Codex to your app? *(edge case)*
   Answer: You did not miss them. Codex and Cursor are not kits: "Codex and Cursor are plain harness values, since they install nothing" (packages/claude-code/src/sdk/kit.ts:4). You import codexHarness from @flow-state-dev/codex (or cursorHarness from @flow-state-dev/cursor) and put it in the harnesses slot that the harnesses kit opens. Claude Code, by contrast, is a kit. Fact sheet 3.8, flag 5.
5. You add the claude-code kit to an app that has no other kits, and it does not work. What is missing? *(edge case)*
   Answer: The claude-code kit requires the harnesses kit (claude-code kit.ts:74), and harnesses in turn requires workforce (harnesses-kit.ts:98). Claude Code fills the slot harnesses opens, so the app also has to list harnesses and workforce in kits. Order in the list does not matter; they install in requires order (engine flowstate/types.ts:129). Fact sheet 3.3, 3.6, 3.7.
6. You copied the Claude Code-style starter and its threads mode does nothing. Is your copy broken? *(edge case)*
   Answer: No. The starters are research software with parts not yet wired: for both the Claude Code-style app and Teammates, "Session mode runs on the real packages with a real model; threads mode waits on its wiring" (labs/README.md:21, :24). Shift Manager likewise has placeholder screens (packages/shift-manager/README.md:9). Fact sheet sections 2 and 7. It is dropped here and marked as a gap for the owner to settle before the page can answer it.)
