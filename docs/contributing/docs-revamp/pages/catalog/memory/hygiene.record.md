## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Your support assistant is built with `system()` with semantic and episodic memory and no `hygiene` option. A user told it eighteen months ago that they are on the annual plan, stored at confidence 0.8, and has not mentioned it since. A second fact from the same day was stored at 0.9. What has happened to each?
   Answer: Hygiene is on by default when `system()` has a semantic or episodic tier (`ms:418-422`, `ms:847-848`). A fact's effective confidence is `confidence x 0.5 ^ (days since last reinforcement / halfLife)`, halfLife 180 days by default, computed when read; the stored score does not change (`jn:55-91`). At 548 days the factor is about 0.12. The 0.8 fact is at about 0.097, below the default `cullFloor` of 0.1, so the next janitor run deletes it; it is not archived (`sh:151-169`). The 0.9 fact is at about 0.109 and survives, but ranks far below a fresh fact of the same stored confidence in recall (`rc:55-68`). (Figures computed from the formula, not taken from a test.)
2. The same user restated their plan last week, which reinforced the old fact. Separately, a permanent episode was recorded a year ago and the assistant recalled it yesterday. How old is each as far as hygiene is concerned? *(edge case)*
   Answer: Reinforcing a fact sets `lastReinforced` to now, so its decay clock restarts and it is back at full strength (`sh:44-68`, `jn:80`). Episodes age from when they were recorded (`encodedAt`), and recalling one does not reset that (`eh:155-176`). The year-old permanent episode is past `permanentStaleDays` (180 by default), so it gets `stale: true`. It is never deleted by the janitor, and nothing else about it changes (`eh:100-105`, `jt:322-386`).
3. You want old memories to sink in ranking but never be deleted. Later you decide to turn hygiene off entirely. What do you set in each case, and what changes?
   Answer: For ranking-only decay, set `hygiene: { confidenceDecay: { cullFloor: 0 } }`. Effective confidence never drops below 0, so no fact is removed, but old ones still rank lower; the other defaults stay because partial overrides keep them (`sh:161`, `hc:36-62`). To turn it off, set `hygiene: false` on `system()`: no janitor is built, `mem.janitor` and `mem.janitorResource` are `undefined`, the `janitor` session resource is gone, recall ranks by raw `fact.confidence`, and stores grow except for their own caps (`ms:418-422`, `ms:902`, `rc:55-58`, `jt:527-537`). You can also turn off one branch: `confidenceDecay: false` or `episodicTTL: false` (`hc:33-34`, `jt:485-512`).
4. A user has a short conversation, two turns and three new episodes, then leaves. Did hygiene run? And if you want cleanup to happen nightly no matter how a conversation goes, what do you do?
   Answer: By default (`schedule: 'onConsolidation'`) the janitor runs as part of consolidation, after new facts are written and before the digest is rebuilt (`msb:1428-1440`). Consolidation runs after 5 new episodes, at most once every 4 turns, or when persistent items are evicted from working memory (`ms:178-183`), so this short session did not trigger it. The janitor does not run every turn by default. For your own timing, set `schedule: 'manual'` and call `mem.janitor` yourself. It is a handler block that takes any input and returns nothing, so it can be a step in a sequencer: `sequencer({ name: 'cleanup', inputSchema: z.any() }).step(mem.janitor!)`. The `!` is needed because `mem.janitor` is typed optional (`jb:62-65`, `ms:462`, `hy:129-131`). (`'onCapture'` runs it on every capture, every turn.)
5. A user writes in saying the assistant has forgotten their shipping address. An operator opens the session in DevTool to see what hygiene removed. What can they find, and why might the record be empty even though the fact is gone? *(edge case)*
   Answer: Each session has one `janitor` resource, overwritten on every run: `lastRunTurn`, `lastRunAt`, `totalRuns`, `lastCulledFactIds`, `lastCulledEpisodeIds`, `lastMarkedStaleEpisodeIds` (`jn:101-137`). It holds IDs only, not content, so the text of a culled fact cannot be recovered (`jn:108-111`, `sh:157-169`). It is a snapshot, not a history: a run that removes nothing resets the `last...` arrays to `[]` (`jb:139-147`). And facts and episodes are shared across the user's sessions while the janitor resource is per session, so a pass that ran in a different session deleted the fact for every session but left its record only in that session. This session can show an empty or default snapshot (`jn:125-135`, `sm:75-76`, `ep:69-84`).
6. A user's stored fact is now wrong (they moved), but they reinforce it often by mentioning it. Will hygiene remove it? And will a culled fact come back on its own? *(edge case)*
   Answer: No. Hygiene does not look at content or truth; only stored confidence and age since the last reinforcement count, and reinforcement keeps resetting the clock (`jn:80`, `sh:44-68`). Reviewing facts for contradiction or redundancy is prune, a separate, model-driven step that is off until the fact count reaches its threshold (`ms:287`, `hy:164-169`). Hygiene makes no model call (`jb:75-148`). A culled fact is deleted and does not come back (`sh:157-169`).
