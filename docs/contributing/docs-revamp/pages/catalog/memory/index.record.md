## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You are building a support-desk agent: a generator called `reply` that answers customers. You want it to remember things between turns. What do you install, and what line on `reply` gives it memory?
   Answer: Install `@flow-state-dev/memory` (`pnpm add @flow-state-dev/memory`). Build the capability with `const mem = createMemoryCapability({ model: "openai/gpt-6-luna", working: true, ... })`, where `model` and `working` are required, and put `uses: [mem]` on the generator. A capability bundles the resources, context and tools a block picks up from one `uses` entry. If you build with `system()` instead, the line is `uses: [mem.capability]`. Facts: fact sheet sections 3, 4 and 7.1 (ov:62-73, mc:65-85, mc:405-412, ov:84).
2. A customer, Dana, says in one chat that she prefers email to phone calls. Last week she also reported a failed refund in another session. Which tier holds the preference as a fact about her, which holds the refund conversation, and what does working memory hold?
   Answer: The preference ends up in semantic memory as a consolidated fact about the subject `user`, with a confidence. The failed refund from last week's session is an episode in episodic memory, which records things that happened and the session they came from. Working memory holds only recent observations from the current session, and their salience fades as turns pass. The digest is a single model-written paragraph summing up what the agent knows about her. Facts: sections 2 and 7.2 (ov:34-36, sm:17-37, ep:6-53, dg:2-10).
3. You install `createMemoryCapability` on `reply` and talk to it for a while, but nothing is ever remembered. What is missing, and how do you fix it? *(edge case)*
   Answer: `createMemoryCapability` only reads memory: it supplies the `<memory>` context block, the `memory/recall` tool and typed helpers, and nothing writes entries into memory automatically. To capture what is said, use `system()`. It builds the same capability, available as `mem.capability`, and adds a capture pipeline that you run after the reply with `.sideChain(mem.capture)` (or `mem.captureFromItems`). Capture is a model call that reads the new messages and keeps what is worth keeping. The other route is a handler writing through `ctx.cap.*` helpers. Facts: flag 2 and section 4 (mc:1-18, ov:84, ms:765-775, cf:93-95).
4. Two customers, Dana and Sam, both use the support desk, and Dana also uses a separate billing flow in the same app. Whose memory is it? Can Sam's conversation see Dana's facts, does the billing flow see them, and can Dana's browser read her memory directly? *(edge case)*
   Answer: By default memory belongs to the user. Episodic, semantic and digest are user-scoped and stored at each user's id, so Sam never sees Dana's facts. Working memory belongs to the session. Dana's user-scoped memory is shared by every flow she uses, the billing flow included, unless a flow isolates it (`isolateUserState`, or the tier's `flowIsolation`). With `scope: "org"` the stored tiers belong to the organization instead. Clients cannot see any memory resource, because none declares a `client` projection. The agent reaches memory only through the context block and the recall tool. Facts: section 6 (rd:199-226, ms:172-176, cfg:171-195, rd:323-324).
5. You restart the server overnight and Dana comes back the next morning. The agent remembers nothing about her. Why, and what changes that? *(edge case)*
   Answer: Memory lives in the server's configured store. The default store is in-memory, so everything is lost on restart. Memory survives a restart only on a persistent store such as SQLite, Postgres or the filesystem store. Facts: section 6 (pr:7, pr:25-39).
6. You change the config to `createMemoryCapability({ model, working: true, episodic: true, digest: true })` so that `reply` gets a summary paragraph, and leave out semantic. What happens? After you fix it, what does the agent see in its prompt by default, and how does it get at past episodes? *(edge case)*
   Answer: It throws at construction, because digest requires semantic (and semantic requires episodic). Add `semantic: true`. With the defaults, the `<memory>` block carries the digest and the working-memory entries, and the `recall` preset adds the `memory/recall` tool. The semantic and episodic sections are off in the prompt by default. The agent searches facts and past episodes on demand through `memory/recall`, which does not search working memory. Facts: sections 1 and 2 (mc:164-172, ct:847-850, mc:316-377, mc:352-362).
