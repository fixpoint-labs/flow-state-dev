## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You put `uses: [mem.capability]` on a support-agent generator. A user asks about a detail from a session three weeks ago that is not in the memory summary at the top of the prompt. What tells the model to search, and what can that search return?
   Answer: The `recall` preset is on by default (default-on set: digest, working, recall; mc:373-376), so the generator gets the `memory/recall` tool and the `<memory>` section gains a line saying more memories exist than are shown and to check memory before saying it doesn't know (mc:357-361). The tool description says to call it for a specific detail not in the summary, and not to re-fetch facts already shown (ty:210-219). It searches semantic facts, past episodes and, with relations on, graph edges. It does not search working memory or the digest (ty:1-8, ms:643-648). Whether to call it is up to the model; nothing forces a call (ex:66).
2. How does the tool decide which memories come back, and in what order? Is the `score` on each result a relevance probability?
   Answer: There are three steps (rt:1-28). Prepare makes no model call: every semantic fact is a candidate, episodes are ranked by significance and recency and the top 30 are kept, and an older episode that contains a distinctive phrase from the query is added back (lf:228-308). Filter is one model call (`tool.model`, else the memory system's model) that returns the relevant candidate IDs, most relevant first. It may return fewer than `limit` and never pads (lf:326-336). Format returns those items in the filter's order. An ID the filter invents is dropped (fh:157-163, rtt:412-429). `score` is the rank rescaled (top item = 1), not a probability (fh:95-98). A fact's age does not by itself keep it out; the filter model decides (lf:239-240).
3. Your agent looks up order history only occasionally. Should you turn on the `episodic`/`semantic` presets to inject those tiers into every prompt, or rely on the recall tool?
   Answer: Use the tool. Injected context is always on and adds no extra call, but you pay for it every turn. The tool costs a tool call plus a follow-up turn, and only when the model decides to use it (ex:62-66). The episodic and semantic presets are off by default because the tool covers them (cf:272). Keep injected context for what the agent should always see, like the digest and working memory. Use the tool when what's relevant depends on what the user just asked (ex:64-65). The defaults already give you both (mc:373-376). No measured cost figure exists, so don't quote one.
4. The generator declares its own `tools: [lookupOrder]` and also has `uses: [mem.capability]`. The model never calls recall. Why, and what is the fix? *(edge case)*
   Answer: A generator that declares its own `tools:` gets exactly that list, so the capability's tool is dropped (cap:146-160, cf:274). Add it by name: `tools: [lookupOrder, mem.tool.recall()]`. `mem.tool.recall()` returns the same block the capability holds (ms:643-654, ms:907-908).
5. Mid-conversation, the filter model call fails (say, a rate limit). What does the generator see? And what happens when a brand-new user's stores are empty? *(edge case)*
   Answer: On failure the tool does not throw into the generator. It returns `{ error, query, strategy }` as an ordinary result (rt:125-143, rtt:388-399), and the model reads `Recall failed: <error>` (fh:19-43). With empty stores it returns `{ results: [], totalMatched: 0, truncatedTo: 0 }` and makes no model call (fh:142-150, rtt:271-288). The model reads `No memories matched "<query>".`
6. You configured the memory system with working memory only (no episodic or semantic tier), and you edit the tool to return up to 50 results. What happens in each case? *(edge case)*
   Answer: With working memory only, the tool is still installed and still describes itself as a memory search, but it always comes back empty (mc:357-362, fh:142-150). Leave it off with `mem.capability.with({ recall: false })` (cf:261). `limit` tops out at 20. A model call that asks for more fails the input schema (ty:75-81, rtt:316-317), and a configured `defaults.limit` above 20 is clamped to 20 (rt:102). Change the default with `tool: { defaults: { limit } }`. The default is 5.

- A retrieval strategy is a block factory that produces a handler-shaped block; the custom strategy example is `const myStrategy: RetrievalStrategy = handler({...})` with `execute` returning `{ results }`. Untrue: `RetrievalStrategy` is an interface (an object), not a handler block. It has `name`, a required `prepareBlock` (input is the tool input with limit resolved, output is a `PrepareEnvelope`), an optional `filterBlock` (`{query, limit, candidates}` to `{selectedIds}`) and an optional `formatBlock`. A bare handler does not satisfy the type. The tool then runs prepare, an optional filter and merge, then format. Result items are `RecallResultItem` (`id, content, source, score, metadata, truncated`), and the tool wraps them in an envelope. The example's `relevance` field and `{ results: ranked }` output are not the contract. (docs/contributing/docs-revamp/pages/catalog/memory/recall-tool.md:44-62; packages/memory/src/tools/types.ts:117-169)
- To plug in something else, pass a different `strategy` to `system()`. Untrue: `system()` has no top-level `strategy` option. The strategy goes under the recall tool config, as `tool: { strategy }` (a built-in name or a `RetrievalStrategy` object). `createMemoryCapability` takes the same `tool` option, and `createRecallTool({ strategy })` takes it directly. (docs/contributing/docs-revamp/pages/catalog/memory/recall-tool.md:44; packages/memory/src/memory-system.ts:352-371,414; packages/memory/src/memory-capability.ts:76,248-256; packages/memory/src/tools/recall-tool.ts:48-51)
- Reference row 8: Recall strategy contract: `RetrievalStrategy` is a handler block; input `{ query, limit, candidates: MemoryItem[] }`, output `{ results: RecallResultItem[] }`; set through `strategy` on `system()` or on the recall tool directly. Untrue: `RetrievalStrategy` is an object with `prepareBlock`, optional `filterBlock` and optional `formatBlock`. It is set through `tool.strategy` on `system()` or `createMemoryCapability`, or through `strategy` on `createRecallTool`. (packages/memory/src/tools/types.ts:117-169; packages/memory/src/tools/recall-tool.ts:48-51; packages/memory/src/memory-system.ts:353-358,415) The row is recorded corrected.
