## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. A research agent's memory already holds facts about NVDA ("buys most of its chips from TSMC") and about TSMC ("fabs are in Taiwan"). A user asks, "How exposed is NVDA to Taiwan?" Why are these facts alone not enough to answer it, and what does turning on relations add?
   Answer: A fact is a statement about one subject (B2), so neither fact links nvda to taiwan, and a query worded about NVDA need not match the TSMC fact. Relations store typed, directed links between two subjects (nvda depends_on tsmc, tsmc located_in taiwan), which adds traversal: memory/connect with from nvda and to taiwan returns the shortest path, those two edges (B3, F1, K). The existing fact category `relationship` is still a fact, not an edge (B3).
2. How do you turn relations on for this agent, what must already be configured, and what does the agent's generator get as a result?
   Answer: Set `semantic.relations` on `system()` (or createMemoryCapability): `true` for defaults, or an object with `vocabulary`, `maxEdges`, `createImplicitEntities` (C1). Relations needs semantic memory, which needs episodic; semantic without episodic throws "Semantic memory requires episodic memory to be configured" (C2). With `uses: [mem]` the generator gets memory/recall and, with relations on, the memory/connect tool, which joins the default-on presets (K, C5). Defaults: no vocabulary, no cap, createImplicitEntities false (C3).
3. What does relations cost you, in model calls, storage and query work, and what does it cost when it is off?
   Answer: No extra model call: the existing consolidation call also returns an `edges` array, so its prompt and output get longer; nothing is added per turn (E1, G1). Recall does an in-process scan for named endpoints and may add up to 10 edge candidates, again with no extra model call (G2). Every edge is stored in the semantic resource's state and loaded with it, unbounded unless `maxEdges` is set (G3, D). Traversal is in memory, sized for hundreds to low thousands of edges, not a graph database (G4). Off, it costs nothing: no edges field, no prompt text, no tool (G5).
4. Who decides the relation types? If you leave the vocabulary unset and later set it to ["depends on", "located in"], what happens to an edge the model proposes as "supplied by", and to edges already stored with other types? *(edge case)*
   Answer: The app developer sets the vocabulary in config; the model cannot change it at runtime (D part 2, H4). Unset, the model writes free text, so one relationship can come out as `works at` one run and `employed by` the next (H1). Set, the list goes into the consolidation prompt and is enforced on write: an off-list type such as "supplied by" is dropped with a console warning, matched exactly, not lowercased (E6, H2, H3). Edges already stored with other types are not removed (H4).
5. The model proposes an edge "nvda depends on samsung", but memory has no stored fact about Samsung. What happens, and does it break consolidation? Separately, would an edge to "Nvidia" join the existing "nvda" node? *(edge case)*
   Answer: Endpoints are trimmed and lowercased and must equal the subject of a stored fact; otherwise the edge is dropped with a console warning and consolidation carries on, not failing (E5, E10). With `createImplicitEntities: true` the endpoint is kept as a new node instead (E5). There is no alias merging: "NVDA" and "nvda" are one node, but "Nvidia" is a separate subject string and would not join it (A1, J2).
6. TSMC moves its main fab out of Taiwan, and a later consolidation supersedes the old link. What does memory/connect return for nvda to taiwan afterwards, and is the old edge gone? What if relations had been off when the agent called connect? *(edge case)*
   Answer: Supersede closes the old active edge with the same from and type (sets validUntil) and adds the new one; it is not deleted (E9). Traversal walks only edges active now, so connect no longer finds the path and returns empty results with totalMatched 0, not an error (F4, F6). The closed edge stays stored as history until maxEdges evicts it or the janitor prunes it as dangling (J6, A4, I1). With relations off, connect returns (not throws) an error envelope: "The relations graph is not enabled for this memory. Enable the relations tier to use connect." (F5)
