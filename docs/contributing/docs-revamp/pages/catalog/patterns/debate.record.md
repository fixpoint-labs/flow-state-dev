## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You build `feature-debate` with two debaters, `advocate` (stance "ship now") and `skeptic` (stance "do not ship now"). You set no `maxRounds` and pass no moderator or `terminateWhen`. How many rounds run, who speaks in each, and what ends the debate?
   Answer: Two rounds, because `maxRounds` defaults to 2 (fact 4.3). With no moderator, every debater speaks every round in the order you declared them, so advocate then skeptic, and skeptic sees advocate's argument from the same round (5.1, 1.5). The loop ends when the round count reaches `maxRounds` or `terminateWhen` returns true. Those are the only two stops when there is no moderator, and either one ends it (4.1, 4.2). The judge then runs once, after the loop (1.3).
2. You want the judge to always name either advocate's or skeptic's stance as the winner, never a blend. Is there a config flag for that? Who decides between picking a winner and synthesizing, and how can you tell which one happened?
   Answer: There is no flag. The judge decides. The default judge is told to say which position is best supported, and it may instead combine the strongest points of several stances, in which case it sets `winner` to null (6.1, 6.2). `winner` holds the stance the judge sided with, or null when it combined stances (6.2, flag 6). Your levers are `instructions`, which reach only the default blocks, or a custom `judge` block that returns `{ verdict, winner, reasoning }` (6.3, 6.4). After the judge, the default synthesizer writes the final answer to your `outputSchema` without mentioning the debate (6.5). If you want the verdict and transcript themselves, set `synthesizer: false` and you get `DebateRawOutput` (6.6).
3. You add a moderator built with `createModerator`, set `maxRounds: 5`, and in round 1 the moderator returns `done: true` with `nextSpeakers: ["advocate", "skeptic"]`. Does round 1 still get played? How many rounds run? And what stops a moderator that never says `done`? *(edge case)*
   Answer: Round 1 is played: both named speakers speak, then the loop exits, so `rounds` is 1, there are two transcript entries, and the judge runs once (4.7). The moderator runs at the top of each round and sees only prior rounds (5.2, 5.3). `maxRounds` still caps a moderator that never returns `done: true`: with `maxRounds: 3` you get 3 rounds and 3 decisions (4.8). If the moderator returns `done: false` with an empty `nextSpeakers`, the schema rejects it with "Moderator must return non-empty nextSpeakers when done is false." (4.9).
4. Halfway through round 2, the skeptic's model call throws (or your moderator names a debater called "critic" who isn't on the roster). Does Debate skip that turn and let the judge decide on what it has? *(edge case)*
   Answer: No. A debater or moderator that throws fails the whole run, and `result.error` carries the thrown message. Nothing skips a turn and carries on (4.10). A moderator that names a debater not on the roster also fails the run, with a message that quotes the bad name and lists `Available: ...` (5.6). A `terminateWhen` that throws fails the run the same way (4.6). Debate returns no verdict from a partial debate.
5. A teammate edits the config: they drop the skeptic so only advocate is left, and they give a new debater an empty `stance` so the model can figure out its own side. What happens? *(edge case)*
   Answer: Both edits throw when the block is built, with a `[debate] ...` message. Debate needs at least two debaters, and every debater needs a non-empty stance (3.4, 1.4). Debate never works stances out from the question; you supply them (1.4, 9.4). Other construction errors: duplicate names, `maxRounds <= 0`, `moderator: false`, and an `outputSchema` combined with `synthesizer: false` (3.3, 3.4). A judge always runs (3.5).
6. Your user asks a question with one clear right answer, your budget allows about one model call, and you're thinking of running a 6-round debate to be safe. Is Debate the right tool, and what does a run actually cost? *(edge case)*
   Answer: Probably not. Each turn's prompt includes every earlier argument, so prompts grow as turns go by. One run makes debaters x rounds calls, plus one judge call, plus one synthesizer call unless `synthesizer: false`, plus one moderator call per round if you set a moderator (9.1). Setting `maxRounds` above 4 logs a console warning about diminishing returns and fast token growth, though it doesn't throw (4.4, 9.1). The page gives as the author's advice, not as a measured result, that debate is a poor fit for one-answer lookups, uncontroversial questions and one-call budgets (9.3). If you want a deliverable more than a winner, Round Robin is the sibling to reach for (9.2).
