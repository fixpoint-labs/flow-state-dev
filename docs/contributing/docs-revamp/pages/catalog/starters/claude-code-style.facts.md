## Where a coding run makes its changes (Q1)

26. **In a git worktree of the project's repository, on a branch of its own.** `readme:143-145`; `host:143-154` (`localWorkspaceHost({ root: join(data, "runs"), remotes: { allow: ["file"] }, localRepositories: [...] })`); `wsr:254-259` ("`checkout/` a git worktree on the run's branch"); `repositoryDisclosure("worktree")`: "Coding runs work in their own git worktrees of this repository, each on its own branch. 27. **The branch is in the repository, so the user can find it; their checked-out branch and files do not change.** `readme:144-145` ("on a branch of its own that you'll find in the repository, so your checked-out branch and files don't change"). The workspace README adds: "The repository's own branches, index and working tree are never touched." (`wsr` section "A repository on this machine", the sentence after the first example.) **[page; Q1]**
28. **A repository outside the list gets a clone instead.** A repository not in `CLAUDE_CODE_STYLE_REPOSITORIES` gets a clone under the data folder, each run on its own branch; the repository itself is only read. `readme:145-146`; `first-run.ts:40`. **[page: one sentence; Q1]**

## The four questions, answered from this sheet

1. **Where does a coding run make its changes?** In its own git worktree of the project's repository, on its own branch, under `<data>/runs`, with the branch in the repository. Your checked-out branch and files do not change. A repository not on the lab's list is cloned under the data folder instead. A repository must be a `file://` address that ignores `.fsdev/` in its committed `.gitignore`. A run that changed files is done only when the project's checks pass (items 26 to 34).
2. **How do you add Codex beside Claude Code?** Fill the harness kit's slot with `codexHarness()`, add a worker with `flow: coder` and `harness: codex`, list it in a `delegates` line and say when to use it in the main brief, and sign Codex in on the machine. A worker naming a harness nobody filled is refused. The lab already does all of this for Codex and Cursor; its Coder chip has a fixed list of choices (items 18, 22, 46, 48).
3. **What is not wired yet?** File diffs of a run; permission prompts (a run works in `acceptEdits` with no one to approve a tool call); setting a project's checks (no field in the form); non-`file://` repositories; more than one user (no sign-in). Not "linked pull requests" and not "harness readiness", which the README's scope line wrongly lists (items 2, 69 to 74).
