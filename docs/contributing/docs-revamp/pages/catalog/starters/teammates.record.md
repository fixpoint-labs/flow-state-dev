1. You open Teammates and want a web search done, plus copy drafted from what it finds. Which worker do you go to for each part, and what can each of Chief of Staff, researcher and writer do that the others cannot?
   Answer: Chief of Staff (`delegates: all`) runs the team's work with you: it hands a quick fact to researcher and copy to writer by message, files real work as a task, and starts coding tasks. It has no `tools:` line; it gets the routine tools and `consultSessionHistory` through its `capabilities:`. researcher reads files and searches the web, and says where each fact came from, a file path or a URL. Its `tools:` line includes `search`. writer drafts from files and fetched pages; its `tools:` line has `fetch` but no `search`, so the web search is researcher's job. Facts §2 table, tree/workers/*/WORKER.md:1-10; tree/workers/chief-of-staff/WORKER.md:12-17; researcher WORKER.md:9-12; writer WORKER.md:9-11.
2. You ask Chief of Staff "Ask researcher for our launch date, and help me outline the post." Where on the screen do you see Chief of Staff message researcher, and where does the answer show up?
   Answer: A line **Messaged researcher** appears in Chief of Staff's conversation, and the message lands in researcher's conversation marked *From* Chief of Staff. Clicking the line opens researcher's turn in a popup: what it read, what it did and the reply it sent. researcher's reply lands in Chief of Staff's conversation under researcher's name. You see all of it because both workers' sessions are yours. readme:85-90; g1:7-8; mw:63.
3. In the middle of that exchange you type a second line to Chief of Staff before researcher has replied. Does researcher's reply interrupt the answer Chief of Staff is giving you? *(edge case)*
   Answer: No. A message never interrupts the turn in progress. While Chief of Staff is answering you, researcher's reply shows as a pending line. Chief of Staff reads it right after that answer and uses it in its next line. readme:88-90; mw:59; g1:8.
4. You ask Chief of Staff to "Fix the typo in the README's first line" and name Codex, but this machine has never run `codex login` and has no CODEX_API_KEY. What happens? And what happens if you name no agent? *(edge case)*
   Answer: The task fails at once, with a line naming the agent and what to run: "Codex isn't set up on this machine: Codex has no credential: Not logged in. Run `codex login`, or set CODEX_API_KEY. Then start the task again." It never falls back to another agent. The context strip shows which agents are ready, and Chief of Staff starts coding tasks only on an agent marked ready and tells you what to run for one that isn't. If you name no agent, Cursor runs the task and there is no question first. A run works in its own worktree under `.fsdev/teammates-runs/`, so your checkout's branch and working tree are never changed. readme:154-160; tree/workers/chief-of-staff/WORKER.md:38-44; readme:228-231.
5. You click **Edit** on writer's panel and replace its instructions. Is `workforce/teams/teammates/workers/writer/WORKER.md` changed? When do the new instructions take effect? What does a second user in the same organization get, and how do you undo the change? *(edge case)*
   Answer: The file is untouched. The edit makes your own copy of writer under the same id, stored as a row in your scope in the app's store. A turn already running keeps the instructions it started with; the new ones apply from writer's next turn. Another user in the same organization still gets the file's writer. **Reset to default** deletes your copy, and the file's version is read from the next turn. The conversation and its history stay as they were. A blank instructions box keeps the current instructions. The alternative, editing the WORKER.md body and restarting, changes writer for everyone who hasn't edited it, because the folder is read once at startup. ad:526-533; TeammateForms.tsx EditForm doc comment; g2:3-11; wf/workers/standard-workers.ts:1-9.
6. You want writer to search the web too, and you want a new worker. What is the smallest change for each, and what is not wired in this app yet? *(edge case)*
   Answer: Tool: add `search` to writer's `tools:` line. `search` is already in the `agent` flow's catalog in host.mts, beside the working folder's source tools and `fetch`. Search also needs a search provider's key, such as TAVILY_API_KEY. A written `tools:` list is everything the worker can call, and a key nothing registers is refused, naming the key. A tool outside the catalog needs a catalog entry in host.mts or a `blocks/` folder beside the worker. New worker: add `workforce/teams/teammates/workers/<name>/WORKER.md` with at least a `description` and restart. Its id is `teammates.<name>`, it runs on `agent`, and Chief of Staff can hand it work because of `delegates: all`. Or use *Hire a teammate* in the screen, which needs no restart. Not wired yet: no tool writes files, so writer answers with its draft instead of saving it. The panel's Routines list reads "None yet." There are no group chats, no new-chat button and no session list. The app serves one user (TEAMMATES_USER) and takes every request as that user. bw:45, bw:49; host:371-375; readme:222-224; wd:76, wd:148-152; readme:172-174, readme:77-79, readme:293-294; panel:276-281; host:407-408.
