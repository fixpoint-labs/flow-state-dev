## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You are building a research generator and want the model to look things up on the web and then read the pages it finds. What do you add to the generator, and what must be true of your environment for the search part to work?
   Answer: Add the shipped blocks to its tools array: generator({ name, model: "openai/gpt-6-luna", prompt, tools: [tools.search(), tools.fetch()] }). The model decides when to call each tool and the framework runs the tool-call loop. Search needs at least one search provider key set (e.g. TAVILY_API_KEY, EXA_API_KEY, PARALLEL_API_KEY, SERPER_API_KEY, BRAVE_SEARCH_API_KEY, PERPLEXITY_API_KEY) or passed via search({ keys: { ... } }); fetch needs no key. (Facts: gen:613 tools slot; ov 'Using tools in generators'; sr:19-27, sr:64-68; fr:32-45.) The generator's own provider-native search option is a separate thing that needs nothing from this package (gen:614-618).
2. You deploy that generator to a fresh environment where no search key was set. The app starts and the flow builds fine, but a user's first question that needs a web lookup goes wrong. What happens, and when? *(edge case)*
   Answer: search() with no keys still returns a block, so building the flow succeeds; the failure comes when the tool runs: it rejects with 'No search provider available. Configure at least one of: ... or pass keys explicitly via search({ keys: { tavily: '...' } })'. There is no keyless fallback for search. (Facts: sr:64-68; st:242-252.)
3. A teammate asks which of the shipped tools needs a provider key before it will work at all. What do you tell them about search, fetch, crawl, bash and MCP?
   Answer: Only search. Fetch works with none (Firecrawl if FIRECRAWL_API_KEY, then Jina if JINA_API_KEY, else a built-in fetch with Readability and Turndown); crawl works with none (Firecrawl if keyed, else a built-in breadth-first crawler). Bash and MCP take no key from this package; an MCP server may need its own, which is the MCP page's subject. (Facts: sr:64-68; fr:32-45; cr:30-37; section 4 q2.)
4. You already have a handler block you wrote, readArtifact, in the same generator's tools array as tools.search(). Is the shipped search tool a different kind of thing from your block, and does the generator treat them differently?
   Answer: No. search, fetch and crawl are each built with handler() (name, description, inputSchema, outputSchema, execute), the test asserts kind === 'handler', and the generator's tools slot takes any BlockDefinition, so both sit in the same array the same way. What a shipped one adds is a provider chosen from your keys. (Facts: si:38-58; st:134-147; gen:422, gen:613.)
5. You want the model to run shell commands in a sandbox too, so you edit the generator to tools: [tools.search(), createBashTool()]. Is that right? If not, how does bash attach? *(edge case)*
   Answer: No. createBashTool is not a block: it is async and returns { tools, sandbox } of AI SDK tool objects, which go in providerTools (e.g. providerTool('bash', tools.bash)). The recommended form is createBashCapability, wired with uses: [bashCap], whose tools preset holds three handler blocks (bashCommand, bashReadFile, bashWriteFile). MCP likewise attaches through uses via createMcpCapability. Only search, fetch and crawl go in tools: [...]. (Facts: bt:1-24, bt:63-65; bc:203-224; mcp/index.ts:1-7.)
6. Your environment has both TAVILY_API_KEY and PARALLEL_API_KEY set, but you want this one generator to use Tavily with a key from your secrets store instead of the environment. What decides the provider, and how do you override it? *(edge case)*
   Answer: Auto-selection picks the first keyed provider in order Parallel, Tavily, Exa, Perplexity, Serper, Brave, Perplexity Sonar, so Parallel would win. To force Tavily use tavilySearch (forced providers exist for each), and pass the key in config, search/tavilySearch({ keys: { tavily: '...' } }); a config key wins over env. A forced provider with no key throws 'Search provider "X" requested but no API key found'. Tavily also needs the optional peer @tavily/core installed, or it errors 'Install @tavily/core to use the Tavily search provider'. (Facts: sr:9-17, rt:142; sr:75, rt:47; si:62-88; sr:33-40; pj:105-126, tavily.ts:20.)
