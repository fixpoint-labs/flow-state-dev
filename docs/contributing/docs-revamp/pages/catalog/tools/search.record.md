## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You build a research flow in src/flows/research/blocks/ whose generator has tools: [tools.search()] and you name no provider. The host has EXA_API_KEY and SERPER_API_KEY set. Which provider runs the search, and how would you make Serper run it instead?
   Answer: Exa. With no provider named, the tool checks keys in a fixed order (Parallel, Tavily, Exa, Perplexity, Serper, Brave, Perplexity Sonar) and takes the first one with a key, reading config.keys[<provider>] first and then the provider's environment variable (F7, F8). To force Serper, pass provider: "serper" or use serperSearch(), and auto-selection is skipped (F13, F17).
2. The research agent should only cite arxiv.org and nature.com. How do you restrict it, and can the model widen the list from inside a tool call?
   Answer: Set includeDomains: ["arxiv.org", "nature.com"] on the config, e.g. tools.search({ includeDomains: [...] }). excludeDomains works the same way for a denylist. Both are config only, so the model cannot set or change them (F29). All seven providers apply them: Serper and Brave do it by rewriting the query as (site:arxiv.org OR site:nature.com) (F30, F33).
3. What does a search call hand back to the model, and which parts can you not count on being there?
   Answer: { query, results, answer? }. Each result always has title, url, snippet (these may be empty strings) and source, the provider that produced it. content, score and publishedDate are optional and depend on the provider (F35-F37). answer comes only from Tavily, Serper (when Google shows an answer box) and Perplexity Sonar (F37). Sonar results carry only a url, with empty title and snippet (F38). Results are cut to maxResults, which the model sends and which defaults to 5 (F20, F39).
4. A teammate deploys the research flow to a new environment where no search API key is set. The app starts fine. What happens when a user asks a question that makes the model call search? *(edge case)*
   Answer: Building the block does not fail. The error comes when the tool runs (F15): the call throws "No search provider available. Configure at least one of: <env vars>..." (F14). There is no built-in fallback for search, unlike fetch and crawl (F16), and the tool throws rather than returning an error-shaped result (F41). If you had named a provider with no key, the message names that provider and its env var instead (F13).
5. You set PERPLEXITY_API_KEY, expecting the synthesized-answer behaviour of Perplexity Sonar, but results come back with no answer field. Why, and how do you get Sonar? *(edge case)*
   Answer: Perplexity and Perplexity Sonar read the same variable, and Perplexity comes earlier in the order, so that key alone always selects Perplexity, never Sonar (F10). Name it: provider: "perplexity-sonar" or perplexitySonarSearch() (F10, F17). Sonar is the one that returns the model's reply as answer (F37).
6. You edit the research block to tools.search({ tier: "deep", includeDomains: ["arxiv.org"], excludeDomains: ["blog.arxiv.org"] }) with PERPLEXITY_API_KEY and BRAVE_SEARCH_API_KEY set. Which provider runs, and can blog.arxiv.org pages still show up? *(edge case)*
   Answer: Perplexity runs: it comes first in the order and supports deep (Brave serves only fast and balanced) (F7, F11, F12). Yes, blog.arxiv.org can still appear: Perplexity takes an allowlist or a denylist, not both, so with any includeDomains only the include list is sent and excludeDomains is dropped (F31).
