## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Your trip concierge's generator should be able to answer "tell me about Lisbon" with a card and not only text. What two pieces do you add, and where does each one go?
   Answer: The starter pack. On the server, spread `generativeTools()` (from `@flow-state-dev/ui/generative/tools`) into the generator's `tools`, for example `tools: [...generativeTools(), webSearch]`. In the browser, pass `generativeRenderers()` (from `@flow-state-dev/ui/generative/renderers`) to `FlowProvider` as `renderers={{ component: generativeRenderers() }}`. Each shape is a tool and a renderer, and the two travel together (facts 1, 10-12). The model picks the shape by calling the tool (fact 3).
2. The model calls `emitInfoCard` for Lisbon. Follow that call to the screen: what does the tool emit, and how does the page find the component that draws it?
   Answer: The tool runs `ctx.emit.component("info-card", input, { key: input.id })` and returns `{ rendered: true, kind: "info-card", id }` as its tool result. That emits an item of type `component` with `component: "info-card"`, the `data` and the key. On the page, `FlowProvider` looks up `renderers.component["info-card"]` and renders it with `{ item }`. The block is named `emitInfoCard`, but the tool and the renderer are linked only by the component name `"info-card"` (facts 4-8).
3. The concierge runs on a small model, and you only want it to show link cards for hotel and flight pages. How do you limit what it can emit, and what name do you pass?
   Answer: Use `generativeTools.pick("link-card")` in the generator's `tools`, and `generativeRenderers.pick("link-card")` on the page. `pick` takes component names (`"link-card"`), not block names (`emitLinkCard`). Fewer tools helps a smaller model choose (facts 16, 19).
4. A teammate picks `"info-card"` on the tool side but only `"link-card"` on the renderer side, and also types `"linkcard"` with a typo somewhere. What does a user see when the model emits an info card, and what does the typo do? *(edge case)*
   Answer: The two `pick` calls are separate and nothing links them. The info-card item has no renderer, so the page shows the dev fallback: a `<pre>` of JSON with `type`, `component` and `status`, without the card's `data`. An unknown name passed to `pick`, like the typo, is ignored without an error, so that shape is just missing (facts 9, 17, 18).
5. The model calls `emitInfoCard` for Lisbon with eleven facts. What happens? Later in the same run it calls the tool again with the same `id` and fewer facts. How many cards does the user end up with? *(edge case)*
   Answer: More than 8 facts fails the tool's input schema check, so the tool run throws and no card is emitted (facts 21, 22). The second call with the same `id` uses the same key, because info cards are keyed by `id` by default. It replaces the earlier card on the client, and the stored record keeps one entry per `(requestId, key)` with the latest data, replaced and not merged. So there is one card (facts 24, 26). To key some other way, pass `keyFrom` to `emitInfoCardTool` (fact 28).
6. You want the info card to match your app's design, and you want a new `"weather-card"` shape for the forecast. Where does each renderer go, and what makes the tool and the renderer find each other? *(edge case)*
   Answer: For the info card, run `fsdev ui add info-card` to copy the renderer into `components/flow-state/generative/info-card.tsx`, which you now own, or write your own. Register it by spreading the pack and overriding the entry: `renderers={{ component: { ...generativeRenderers(), "info-card": InfoCardRenderer } }}`. For the new shape, write a `handler` tool whose `inputSchema` is a Zod object and whose `execute` calls `ctx.emit.component("weather-card", input, { key })`, and add it to `tools: [...generativeTools(), weatherCardTool]`. Then write a React component that takes `{ item }` and reads `item.data`, and put it in `renderers.component` under `"weather-card"`. Nothing else registers the pair. The tool's first argument to `ctx.emit.component` must equal the renderer key (facts 30-35). Import tools on the server and renderers in the browser (fact 36).
