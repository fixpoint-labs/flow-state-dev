1. You run `fsdev ui add message` in your Next.js app. Where does the Message component's code end up, what else arrives with it, and how do you import it on a page?
   Answer: It is copied into your project as plain source at `components/flow-state/message.tsx`; nothing is imported from an `@flow-state-dev/ui` package (each item's files map to a `target` in your project, br:112-118, rj; ov:11). The item's registryDependencies come too, so `attachments.tsx` and `message-response.tsx` land beside it in `components/flow-state/`, and shadcn's own `button`, `button-group` and `tooltip` resolve from shadcn's registry (rj message item; br:8-14). You import it as `@/components/flow-state/message` (ov:98). The command delegates to `npx shadcn@latest add <registry>/message.json` (cli:56-85).
2. Your designer wants the 'needs your action' highlight (for example a tool call waiting for approval) to be purple instead of the default yellow, in both light and dark mode. What do you change, and do you have to edit any copied component file?
   Answer: Set `--attention` and `--attention-foreground` in your own stylesheet under `:root` and under `.dark`. Components never name a colour directly; they read tokens (CSS variables), and the `tokens` defaults sit in `@layer base`, so your values win wherever you declare them (ov:29, ov:49-60; rj:10, rj:44-46,75). No component file is edited; every component that reads the token follows.
3. You last added components months ago, before the status tokens existed. You re-add `task-plan` to get a fix, and its status badges now render with no colour. No error is thrown. Why, and what fixes it? *(edge case)*
   Answer: The fresh copy reads status tokens (`success`, `warning`, `info`, `attention`) that your stylesheet does not define, and a missing token renders as no colour, not an error (ov:62). Run `fsdev ui add tokens` once (and re-add the other components you use). Normally `tokens` is added with the first component that needs it (rj:10).
4. You edited your copy of `components/flow-state/message.tsx` to change its layout. Later the registry ships an improved Message. Do you get it automatically, and how do you pick it up without losing your change? *(edge case)*
   Answer: No. Upgrades are not automatic; the copy is your source code. To pick up the new version you re-add the component (`fsdev ui add message`), which replaces that file, then replay your local edits on top (ov:13, ov:115; section 6, one copy per name per project).
5. You render chat with `FlowProvider renderers={chatAssistantRenderers}` and `ItemsRenderer items={session.items}`. A teammate drops a standalone `<ModelBadge model={item.model} />` and an `<Approval>` card elsewhere on the page outside any session-items provider. Which of these need the flow's session wiring, and what does the approval card see without it? *(edge case)*
   Answer: `ModelBadge` takes a typed item value as a prop and needs no provider (fa:95-105; rj model-badge depends only on `@flow-state-dev/core`). `approval` reads the session's items through `SessionItemsProvider` (and calls `useApproval`); without a provider `useSessionItems()` returns an empty list, so its receipt will not show on reload. Wrap the item list in `SessionItemsProvider` (rc/session-items-context.tsx:6-12; rc/approval.tsx:21,30,44). Other session-aware pieces: `task-plan`, `debate`, `evented-actors`, `routed-specialists` (session items), `request-group` and `suspension-card` (FlowProvider's renderer map), `conversation` and `session-overlay` (React hooks).
6. You want to stop drawing the default task-board card in chat but keep every other default renderer. You write `{ ...chatAssistantRenderers, component: { "task-board-meta": false } }` and the audit annotations disappear too. What went wrong, and what is the right override? *(edge case)*
   Answer: Replacing `component` outright drops its other keyed entries (such as `audit-annotation`). Spread the existing map first: `{ ...chatAssistantRenderers, component: { ...chatAssistantRenderers.component, "task-board-meta": false } }` (ov:109; fa:30-38; rc/chat-assistant.tsx:47-86). The renderer map is yours to own; `false` means 'do not draw'.
