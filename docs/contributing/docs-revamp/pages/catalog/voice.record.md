## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Your app has two flows on one server: the support chat flow, to which you added `voice: { tts: { voice: "alloy" } }`, and a billing flow you left alone. The server config now sets `voice: { provider: new OpenAIVoiceProvider({ apiKey }) }`. Does the billing flow behave any differently, and does the support chat flow's own blocks need changing to speak?
   Answer: No and no. Synthesis starts only when the flow definition has `voice.tts`, so the billing flow runs exactly as before (runAction.ts:1895). In the support chat flow `voice` sits on the flow definition only; its `run` sequencer and blocks are unchanged. The flow streams text as before and the server listens to that text (content.delta / content.done events) and turns it into speech (runAction.ts:1903-1906; kitchen-sink chat-agent/flow.ts:46-53).
2. A customer holds the mic button on the support page and speaks. Where does the speech become the text the flow receives: in the browser or on the server? And what is the browser's own speech recognition doing meanwhile?
   Answer: On the server. When the button is released, `stopListening` sends the recording to the server's transcribe route (`/api/flows/transcribe`), which calls the voice provider's `transcribe` and returns the text; that text is sent as the action input, by default `{ message: text }` (useVoice.ts:256-270, client.ts:824-833, stream-routes.ts:476-486). The browser's Web Speech recognition only supplies the live interim text shown while the button is held. Without it `useVoice` still works, just with no interim text.
3. Which browser features does `useVoice` use to record the customer and play the reply, and what does a page see on its first render, before it knows whether the browser supports them?
   Answer: It records with `MediaRecorder` over `navigator.mediaDevices.getUserMedia({ audio: true })` and plays replies through the Web Audio `AudioContext`, decoded and queued in order (audio-recorder.ts, audio-player.ts). `isAvailable` is `false` during server render and the first client render. It turns `true` only once an effect finds both `getUserMedia` and `MediaRecorder`. While it is `false`, `startListening` does nothing (useVoice.ts:85-93, 208).
4. An agent types a reply into the same support chat with `sendAction`, and a teammate's page mounts `useVoice` with `autoPlayTTS: false`. The flow has `voice.tts` and the server has a provider. Does either of them get spoken audio? *(edge case)*
   Answer: Neither. Synthesis also needs the request to ask for it: `metadata.voice.ttsEnabled === true`, and TTS is off by default (runAction.ts:1255-1267). `useVoice` sends `ttsEnabled: autoPlayTTS` with its voice-originated actions, and `autoPlayTTS` defaults to `true` (useVoice.ts:82, 247-254). A typed `sendAction` without that metadata gets text only. `autoPlayTTS: false` turns off playback and also sends `ttsEnabled: false`, so the server skips synthesis.
5. The deploy forgot the OpenAI key, so the server is started with no voice provider, but the support flow still declares `voice.tts`. A different day the provider is set up but OpenAI fails on one sentence. What does the customer see in each case, and what happens to a recording sent to transcribe with no provider? *(edge case)*
   Answer: With no provider, the run keeps going text-only: the text still streams and synthesis is skipped (runAction.ts:1895-1898; createFlowApiRouter doc, 'flows requesting TTS silently skip synthesis'). The transcribe route returns 501 (details on Reference). Note that `OpenAIVoiceProvider` needs a key when it is constructed, so you wire it only when a key is present (kitchen-sink fsdev.config.ts:171-179). When one sentence fails to synthesize, the failure is reported as a non-fatal item and the text is not stopped (tts-pipeline test). If server transcription throws, `useVoice` sends the interim browser transcript if it has one, and otherwise sends nothing. An empty transcript is never sent (useVoice.ts:268-278).
6. You want the support flow to speak with your own in-house speech service while every other flow keeps OpenAI. What do you write, and which part of voice does your provider not take over? *(edge case)*
   Answer: Write an object that satisfies `VoiceProvider` from `@flow-state-dev/core`: `id`, `providerName`, `abilities` (for example `speak: true`, the others `false`), and a `speak(options)` that returns `{ audio: Uint8Array, mediaType }`. A `true` ability guarantees that method is present. Put it on the flow as `voice: { provider, tts }`. A per-flow provider beats the server's provider for that flow's synthesis (speech.ts:18-26; host-voice-provider test). It does not apply to transcription: the transcribe route belongs to no flow and always uses the server-level provider (stream-routes.ts:377-386). If the provider advertises `speakStream`, the pipeline uses it over `speak` for each sentence.
