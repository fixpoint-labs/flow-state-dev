## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Alice wants to start the Apollo project for her team. Does she create a folder for it, or write a file under workforce/ the way she wrote her workers?
   Answer: Neither. A project is a row of data created while the app runs, by app code or by a worker acting for a user (pg:13, col:7-9). Workers are WORKER.md files; projects are rows. Its repository field is a git remote, not a path (col:106-110). The folder in the picture is a coding run's checkout, and that is covered on the project-code page, not here.
2. Alice creates a shared project apollo and names Bob as a member. Both of them ask it "How is the project going?". Whose worker answers each of them, and can Bob read Alice's conversation? *(edge case)*
   Answer: Each user gets their own project coordinator: a session of the one coordinator worker the installation names with projectCoordinator, one session per user per project (pc:1-6, inst:119-126, pct:269-281). Alice's session answers Alice and Bob's answers Bob. They run the same worker file but are separate sessions. Bob posting to Alice's coordinator session is refused (pct:283-292). Both coordinators read the whole project, every workstream entry included (pc:31-36).
3. Alice opens a workstream checkout in apollo with eng-lead as its lead. What does that workstream have exactly one of, and what happens if she later opens checkout again naming a different lead, or two of her opens run at the same time? *(edge case)*
   Answer: It has one owner (Alice, named in its key workstreams/apollo/~alice/checkout), one lead chosen at open and never changed, and one session of that lead (we:221-239, we:201, ww:6-21). Opening it again naming another lead is refused (lead-differs, ww:366-368, wst:301-320). Two opens at once still leave one entry and one session (wst:281-299). Bob can have his own checkout in apollo, because a workstream is unique per project and owner (we:228-239).
4. Bob is a member of apollo. What can he see of Alice's checkout workstream, and what happens if he tries to change its status or open its session? *(edge case)*
   Answer: Anyone who can read the project can read every workstream entry: its title, lead, status, due date, objectives and latest report (pg:15, wc:81-91, wst:577-595). Only the owner writes an entry. Bob's write is refused and nothing changes, whichever flow sends it, because the store enforces it (wc:14-19, wst:452-488). Alice's workstream session (the lead's board and tasks) belongs to her alone, and Bob's GET or respond on it is refused (wst:577-595).
5. Bob asks his project coordinator to get guest checkout shipped, but checkout is Alice's workstream. Bob owns billing. Where does his request go? *(edge case)*
   Answer: The coordinator hands work only to the leads of the asking user's own workstreams, inside that workstream's session. A task aimed at Alice's workstream is refused like an unknown assignee and nothing is routed (pc:31-36, pct:546-562). Bob's coordinator can hand the ask to his billing lead, or he can read Alice's entry or ask her (pg:403). A user with no workstreams can still read the project and get answers, but has nobody to hand work to (pct:564-582).
6. Alice made a private project notes in her org, and the org also has a shared apollo. Who can see notes? Can she share it later or add Bob? And what does Bob get if he names notes in a call? *(edge case)*
   Answer: A private project lives with its creator, and nobody else can list it, open it or read it, its entries and files included (col:199-220, vis:26-54). It shows only in the org it was made in (col:202-204). Visibility is chosen at create, a create that names none is shared, and it cannot change later (col:56-60, col:11-19). Members are set when the project is created, and a private project has only its owner (pw:16-19, pw:354). Bob naming Alice's notes is refused no-such-project, exactly as if it did not exist, and starting a coordinator on it gives 404 (pr/project-address.ts:376-387, pct:294-328). Alice's private apollo, if she made one, would be a separate project from the shared apollo (vis:91-110).
