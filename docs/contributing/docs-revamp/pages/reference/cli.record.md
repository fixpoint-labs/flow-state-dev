## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You ran `fsdev run support handleTicket -i '{"message":"Where is my order?"}'` and want the next run to continue the same conversation instead of starting over. Which flag do you add, what do you pass it, and what happens if you leave it off?
   Answer: Add `-s, --session <id>` with the same id on both runs. Without it, `fsdev run` creates a new session id (`sess_<time>_<random>`) on every run, so state does not carry over. `--session` exists on `run` and `chat` only (fact sheet section 2, `run:138,374`).
2. You want to check one block, `blocks/draft-reply.ts`, on its own without running the support flow. What does `fsdev block` take, what must the file export, and what does it print?
   Answer: It takes the block file's path (absolute, or relative to the working directory), input as `-i <json>` or `-f <path>`, an optional `-m <model>`, and `--format` (only `json` exists). The file must default-export the block: an object with a `kind` (handler, generator, evaluator, sequencer or router), a `name` and a `run` function. It runs the block with no flow and no session, as user `cli-user`, and prints one JSON document on stdout: `success`, `block {kind, name}`, `output`, `schemaValidation.input/.output {passed, errors?}`, `execution.durationMs` (section 3, fsdev block).
3. A script reads `fsdev run support handleTicket` output and has to know when the run is over and whether it worked. What does stdout contain, which line is the last one, and what exit codes can it get?
   Answer: stdout is NDJSON, one JSON object per line, each with a `type` (`item_added`, `item_updated`, `item_done`, `content_delta`, `state_change`). Logs go to stderr. Every run that reaches the engine ends with exactly one final event: `flow_complete` (with `output`, `durationMs`, `items`), `suspended`, or `error`. The exit code is 0 for `flow_complete` and for `suspended`, and 1 for `error`. A failure before the engine starts (unknown flow, bad input, refused identity) prints only to stderr, sends no event, and exits non-zero (section 7).
4. Your support flow stops to wait for a person to approve a refund. The run prints `suspended` and exits 0. Is the run finished, and where does the person answer it? *(edge case)*
   Answer: No. `suspended` means the run is held, not finished. Exit 0 only means nothing failed. Unless you passed `--quiet`, stderr shows a waiting report (`[fsdev] waiting for a person: ...`, the suspension, request and session ids, where to answer it, and the note that its deadline fires only while a server runs on this store). With the default store, the answer goes through `fsdev dev`, which reads the same `.fsdev/data/fsdev.db`. With a config, you answer it in a server on the app's stores (sections 3 and 7).
5. Your teammate started session `sess_abc` as user `alice`. You run `fsdev run support handleTicket -s sess_abc -u bob`. What happens? *(edge case)*
   Answer: The run is refused before anything is written, and it exits 2: `Session "sess_abc" belongs to user alice in organization <o>; this run is bob in <o2>. Nothing was written. A session keeps the user and organization it was created with; use a new session id.` In `fsdev chat` the same check fails that turn instead and switches to a fresh session (section 6).
6. You add `fsdev.config.ts` to the project and keep your old command `fsdev run support handleTicket --flow-dir src/flows --store filesystem`. What happens now, and how do you get the old behaviour back? *(edge case)*
   Answer: Once a config loads, the registry, stores and model resolver come from its default-exported `FlowState`, so `--flow-dir` and `--store` are both refused with exit 2 (`--flow-dir bypasses fsdev.config.*; pass --no-config to use directory discovery.`). Pass `--no-config` to ignore the config and go back to directory discovery. The config is looked for only in the working directory, as `fsdev.config.ts`, `.mts`, `.js`, `.mjs` in that order. If it does not default-export a `FlowState`, the command exits 3 (sections 2, 4, 5).
