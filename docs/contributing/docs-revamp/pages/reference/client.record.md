## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You are wiring up the hello-chat app. What must `createClient` be given, and what happens if you leave something out?
   Answer: It must be given a non-empty `userId`, plus either a `baseUrl` or a `fetcher`. `CreateClientOptions` has exactly four fields: `userId`, `baseUrl`, `apiPath` and `fetcher` (1.1-1.10). A blank or whitespace `userId` throws `ClientHttpError` "userId is required" with `status: 0` (1.2). With neither `baseUrl` nor `fetcher`, `createClient` throws "createClient requires baseUrl, or a fetcher" when you build it, not on the first call (1.4).
2. The hello-chat page is a Next.js app with `basePath: "/portal"`, served from the same origin as its API. The same flow is also called from a Node script on the server. What `baseUrl` does each need, and why does `baseUrl: "/api"` give 404s? *(edge case)*
   Answer: The browser page uses `baseUrl: "/portal"`, so requests go to `/portal/api/flows/...` (1a.2). The Node script needs an absolute origin such as `"http://localhost:3000"`, because there is no page to resolve a relative path against (1a.3). A script running next to the engine can pass `createInProcessFetch(flowState)` as `fetcher` and leave `baseUrl` out (1b.1). `baseUrl` must never contain the mount. `/api/flows` is added after it, so `baseUrl: "/api"` requests `/api/api/flows/...` and gets a 404 (1a.7).
3. The server is started with the Node host's `serve(flowstate, { basePath: "/flows" })`, and every client call now 404s. What do you change on the client and on a `FlowProvider`? *(edge case)*
   Answer: Set `apiPath: "/flows"` on `createClient` and on `FlowProvider`, and keep the origin as `baseUrl`. The Node host's `basePath` replaces `/api/flows`; it is not a prefix in front of it (1a.6, 1.7). `apiPath` reaches every call and stream of the client (1.9), and every hook under the provider uses the provider's `apiPath` (2.5). Hooks cannot set their own `apiPath`, except `useVoice` (3.4). An in-process fetch must use a matching `createInProcessFetch` `basePath` (1b.2).
4. Your app needs to send a bearer token and a tenant id with every request, the subscribe socket included. Which option do you set?
   Answer: `fetcher`: a wrapper that adds the headers. `createClient` has no option for headers, tokens or a tenant (1.16, section 14). Every call and stream from the client goes through the one `fetcher`, and the `subscribe` socket's ticket is requested through it too, so its credentials prove who the socket belongs to (1.13, 1.14). The tenant is sent as the `x-tenant-id` header by default (1.16). On `FlowProvider`, pass a stable `fetcher` reference. A new function on every render builds a new client each time and drops its open streams and socket (3.5).
5. On one page, a support agent's view and a supervisor's view sit under one `FlowProvider`. One `useSession` passes `userId: "supervisor"` and the rest inherit the provider's `userId`. Do they share a client and socket? What happens if no `userId` is set anywhere? *(edge case)*
   Answer: No. Under one provider, hooks with the same `userId`, `baseUrl`, `apiPath` and `fetcher` share one client and one `subscribe` socket. A hook that overrides `userId` gets a different client (3.6, 3.7). Two providers never share a client (3.6). If no hook and no provider names a `userId`, `useSession`, `useFlow` and `useRequestStream` act as `"devuser"`, but `useAction` throws `useAction requires userId (option or FlowProvider)` (3.3).
6. You nest a second `FlowProvider` inside the first one to give one panel its own renderers, with `baseUrl=""` and `renderers={{ message: false }}`. What does the inner panel inherit, and what changes? *(edge case)*
   Answer: The inner provider inherits each of `flowKind`, `sessionId`, `userId`, `baseUrl`, `apiPath` and `fetcher` that it does not set. The check is `??`, so `baseUrl=""` counts as set and resets the panel to the page's own origin. `apiPath` and `fetcher` can only be replaced, never unset (2.9). Renderers are merged one slot at a time. The inner provider's `message: false` turns off the outer provider's message renderer, while `component`, `container` and `data` are merged by key (9.2). The `sessionId` prop can be read with `useFlowContext()`, but no built-in hook reads it (2.2).
