## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. A teammate's message says "the worker picked up the refund task". In a support-desk app built on Workforce that also runs a task board, what are the two things "worker" can mean, and how do you tell which one they mean?
   Answer: Two senses, told apart by the package. In Workforce, a worker is a configuration with an owner: it names the flow it runs on, carries its own instructions, skills and tools, and belongs to one user and acts as them. On a task board, a worker is a block that runs one claimed task. "Picked up a task" from a board points to the task-board sense. (Fact sheet 0.7 and section 5, from OLD "Words that mean two things" and G:484.)
2. You are setting up the support-desk server and install `workforce({ model })` and `harnesses({})`. Is each of those a flow or a kit, and what is the difference?
   Answer: Both are kits. A kit is the unit an app installs, made with `defineKit` and passed to `createFlowState({ kits: [...] })` in any order; its `install` returns flows. A flow is the unit the server runs, made with `defineFlow`. A kit sits above flows and has no client half. (Fact sheet section 2, Kit layer; section 5; `core/kit/define-kit.ts:1-18`.)
3. Two users in the same org, Ana and Ben, both see the standard "triage" worker on their rosters. Ana wants to change its instructions. Can she edit it, and if she makes a change, does Ben see it? *(edge case)*
   Answer: No one edits a standard worker. It is read from the installation's files and is the same for every user. Ana forks it, which copies it into a worker of her own; her worker belongs to her, acts as her, and is stored in her user-scope collection, so Ben keeps seeing the unchanged standard worker. (Fact sheet section 2, App layer: Standard worker, Fork, Worker; section 4: `workforce/workers/*` at user scope vs `workforce/standard-workers/*`.)
4. Two kits both contribute an entry under the same key to a keyed slot. What happens, and how would an app remove one contribution it does not want? *(edge case)*
   Answer: A keyed slot (`slot.keyed(schema)`) refuses a key given twice, and the refusal names both contributors. An app drops a contribution with `kit.without(slot, key?)`. A list slot (`slot.list(schema)`) would instead append contributions in install order, each kit's `requires` first and the app's last. (Fact sheet section 2, Kit layer: Slot; `core/kit/define-kit.ts:20-70`.)
5. A support agent's coordinator dispatches a refund check and its turn waits on it with `getTask({ id, wait: true })`. The deadline passes before the check finishes. Is the check cancelled? *(edge case)*
   Answer: No. A wait pauses the turn until the work ends or the deadline; the deadline cancels nothing. (A board's `onIdle: "wait"` is a different setting.) (Fact sheet section 2, App layer: Wait; G:189.)
6. A run in the support desk needs a person to approve a refund before continuing. What is that stop called, and what is the narrow meaning of "ask" here, as opposed to a hand-off?
   Answer: The run is suspended (a suspension, `ctx.suspendForUser`): it stops to wait for a user's approval or answer, then resumes where it stopped; on a task, a hold keeps the task open for the user, and a question is one kind of hold. An ask is only a question to a person, such as an approval or clarifying question, never delivering work. A hand-off is different: a session doing the work passes it to another session mid-work. (Fact sheet section 2: Suspension, Hold, Ask, Hand-off; G:203, G:242, G:325.)
