## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. The support flow's reply drafter is a generator built from a prompt file. Its `<system>` section says `Order note: {{ input.orderNote }}`, and a customer's message arrives with no `orderNote`. What happens, and when? How do you make the note optional? *(edge case)*
   Answer: The render throws an error whose text includes "undefined variable". `<system>` and `<user>` render with strict variables (facts section 6, pf:298-300; test pft:141, pft:359). The file loads fine, because this is not a `PromptFileParseError`. The failure happens when the generator runs and renders the section, and it travels through the generator's normal error path (section 6, pf:357-364; gp:347). To make the note optional, use the built-in `default` filter: `{{ input.orderNote | default: "" }}` (pft:146).
2. The same reply drafter's prompt file also has a `<context>` section that tests `{% if config.context.orderHistory %}`, and this run has no `orderHistory` entry. Does it throw? Which context entries reach the model?
   Answer: No. `<context>` renders leniently (`strictVariables: false`). A missing variable renders as empty and the `if` skips cleanly, for any variable in that section, not only `config.context` keys (section 6, pf:308-311; test pft:343). Having a `<context>` section turns off the default append of the aggregated context. The rendered section, wrapped in `<context>...</context>`, takes its place, and any key the section does not render is dropped. The section can reorder and prune entries but cannot add one, because entries are still declared on the generator's `context:` slot and by capabilities (section 5, ma:186-188; tests gpt:67, gpt:89). An unknown filter is still an error at parse time, even in `<context>` (pft:159).
3. A teammate adds `temperature: 0.7` and `owner: support-team` to the reply drafter's frontmatter. The generator spreads `...definePromptFile(pf)` and then sets `temperature: 0.2`. What happens to each key, and what does `config.temperature` show in the template? *(edge case)*
   Answer: `owner` fails. Prompt-file frontmatter is strict and allows only `name`, `description`, `intent`, `model`, `caching`, `maxTokens` and `temperature`, so loading throws `PromptFileParseError` with `Invalid frontmatter: <path>: <issue>` (section 2, pf:60-70, pf:265-273; test pft:63). Without `owner`, `temperature: 0.7` is valid (0 to 2), but the `temperature: 0.2` written after the spread replaces it, and `config.temperature` shows 0.2 (section 11, gen:3117-3121; test gpt:228). Frontmatter `model` would be metadata only. The generator's own `model` slot decides the model (pf:65; gp:24).
4. The support desk has a resource whose content comes from a template, for example a customer summary rendered from the resource's state. Can that template read `ctx.session.state`, the generator's `input`, or another resource? What happens if it reads `{{ state.tier }}` and the state has no `tier`?
   Answer: No. `state`, the resource's current state, is the only top-level variable. There is no `ctx`, `input`, `config`, session state or other resource (section 4, rtp:245; rp:498-504). Nested objects and arrays can be read, for example `{% for item in state.items %}` (rtt:100). A property that does not exist throws `ResourceTemplateRenderError` with `Template render failed: <cause>` (rtt:116). Rendering happens on every `readContent()`, so the failure shows up on the read, not when the resource is defined (rr:2270-2271). For an optional value, use `| default: "..."` (rtt:108). The `fsd_` filters and custom filters are not available in resource templates. LiquidJS's own filters are (section 7).
5. The reply drafter is loaded with `loadPromptFile("./prompts/draft-reply.md", import.meta.url)`, and its `<system>` contains `{% render 'tone' %}`. Where is the file looked up? What happens if there is no `tone.md` next to it? And how does the same prompt work in a browser bundle? *(edge case)*
   Answer: A relative specifier resolves against `importerUrl` (`new URL(specifier, importerUrl)`). It never uses the working directory. An absolute specifier is used as-is (section 8, pl:184-186). If the file cannot be read, loading throws `PromptFileLoadError`: `Failed to read prompt file "<specifier>": <cause>` (pl:188-196). Partials are the other `.md` files directly in the prompt's own directory, or in `partialsDir` instead when one is given, registered under their filenames without `.md` (pl:143-160, pl:198-199). If `tone` is named as a quoted literal and is not registered, parsing fails with `PromptFileParseError`: `Referenced partial "tone" is not registered. Add a sibling tone.md (Node) or pass it in the partials map (browser).` (pf:326-338; test pft:278). In a browser, `loadPromptFile` is not available. Import the raw text (for example Vite `?raw`) and call `parsePromptFile(text, { sourcePath, partials })` from `@flow-state-dev/core/prompt-file` (pl:6-13; pft:271).
6. The support desk's reply-summary resource uses `contentTemplateRef` to point at a template resource that an admin edits at runtime. The admin saves a new version that contains a Liquid syntax error. When does the edit take effect, and what does a read return? And if the template is stored under Alice's owner-private key, what does Bob get from the content route? *(edge case)*
   Answer: Edits take effect on the next read. The template resource's content is written with `writeContent()`, and each read looks the content up again, in session scope, then user, then org, and parses it with `parseResourceTemplate`, with no partials. It is then rendered against the referencing resource's own state (section 8, rr:2273-2284, ec:3010-3022; rp:490-492). A syntax error in the edited template therefore throws `ResourceTemplateParseError` on that read. If no scope holds the template, `readContent()` returns `null` (rr:2279-2281). On the content route, a template stored under another user's owner-private key is not rendered for Bob, and `content` is `null`. Alice sees her own. A key the scope serves to everyone, or a key with no owner segment, renders for anyone (test fence:75-95).

## 5 · Fact check

Checked against the code: the page as pass 4 read it after the draft, sha256 714e309f09f4, and the 3 Reference row(s) pass 6 moved.

- A contentTemplate path is found "At startup", and "A path that fails to load throws at startup". Untrue: String and anchored contentTemplate paths are loaded by resolveStringContentTemplates. It runs inside createExecutionContext, which builds a run's execution context, and nothing at process start or flow registration calls it. A bad path therefore throws when the first run's execution context is built. Later contexts find the config already resolved in place. The same applies to the `Failed to resolve contentTemplate ... Tried:` error. (packages/engine/src/context/createExecutionContext.ts:723 (also packages/engine/src/context/resource-registry.ts:614-630))
- A key not in the frontmatter table is a PromptFileParseError with the message `Invalid frontmatter: <path>: <issue>`. Untrue: `<path>` is the Zod issue path inside the frontmatter, not a file path. An unknown key gives `Invalid frontmatter: (root): Unrecognized key(s) in object: 'x'`. When there is no issue path the text is `(root)`. The file path is on the error's `sourcePath` property, not in the message. (packages/core/src/prompt/prompt-file.ts:~262-268 (the Invalid frontmatter template string in parsePromptFile))

- "For an optional value, give a fallback: `{{ input.note | default: "" }}`" (line 125), and the example prompt's `Note: {{ input.note | default: "none" }}` (line 29) with `note: z.string().optional()` (line 44). This presents `default` as the way to handle an absent value in a prompt file. Untrue: In a prompt file's `<system>` and `<user>` sections, `default` does not rescue an absent property. Those sections render under `strictVariables: true` and without `lenientIf`, so an absent `input.note` still throws `undefined variable: input.note`. I ran `parsePromptFile` with `{{ input.note | default: "none" }}` and an input without `note`, and it threw that error. A bare `{% if input.q %}` on an absent key also throws. The example flow would therefore fail whenever `note` is omitted. Make the optional field always present (for example a schema default or a `.map` step), or move the value into `<context>`.
