## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Your support app's flow (src/flows/support/flow.ts) builds its memory with system({ model, working: true, episodic: true, semantic: true, digest: true }) and leaves hygiene unset. A teammate asks: "What is the default decay?" What is the full answer?
   Answer: There are two decays, with different units. Working-memory salience decays per turn: decay.strategy "power-law", decay.rate 0.5, so salience is importance * (1 + turns since last access)^-0.5. Semantic fact confidence decays per day under hygiene: confidenceDecay.halfLife 180 days, with cullFloor 0.1. Leaving hygiene unset is the same as hygiene: true, so both are on. (Fact sheet section 0, 2.1, 4.1, 11: wh:21-26, wh:43-64, jn:44-53, hc:24-31.)
2. A customer told the support agent "I'm on the Pro plan" eight months ago, and that fact was stored at confidence 0.8 and never reinforced. With default hygiene, what has happened to it, and does the stored confidence field show anything different?
   Answer: Effective confidence is confidence * 0.5^(elapsedDays / 180), counted from lastReinforced, else extractedAt. After about 540 days (180 * log2(8)) a 0.8 fact falls below the 0.1 cull floor, so at eight months (about 240 days) it is still kept, at roughly 0.8 * 0.5^(240/180), about 0.32. The stored confidence never changes: effective confidence is computed when read. A fact exactly at the floor is kept, and only one below it is deleted by the janitor. Reinforcing the fact resets lastReinforced and adds 0.05. (Section 4.2, 4.3: jn:55-91, sh:161, sh:82-102. The worked figure is derived from the formula, not a test.)
3. Your flow builds a memory with system({ model, working: true, digest: true }) and leaves out episodic and semantic, or alternatively builds it with semantic: true and no episodic. What happens? *(edge case)*
   Answer: Construction throws, from both system() and createMemoryCapability. Digest without semantic throws "Digest requires semantic memory to be configured". Semantic without episodic throws "Semantic memory requires episodic memory to be configured". A missing model throws "createMemoryCapability requires a `model` for the recall tool". Working alone is allowed. (Section 1.2: mc:164-183.)
4. To keep things light, the support flow is set up with working memory only, and the recall preset is left at its default. During a chat the model calls memory_recall for something the customer said three turns ago. What does it get back, and what should you do? *(edge case)*
   Answer: The recall tool still installs (the preset is on by default and installs whatever tiers are configured), but the built-in llm-filter strategy reads only semantic facts and episodes, never working memory. So every call returns no results, and the model reads No memories matched "<query>". Turn recall off for a working-only setup: mem.capability.with({ recall: false }) or .presets({ recall: false }). (Section 5.1, 6: mc:352-362, lf:165-190, ft:30-36, T:recall:271.)
5. The same customer has two open support chats, session A and session B. The janitor runs in session A and culls one of their old facts. What does session B see in its memory and in its janitor resource? *(edge case)*
   Answer: Semantic facts and episodes are user-scoped (by default), so they are shared across that user's sessions. The fact is gone for session B too. The janitor resource is session-scoped and is written only by the session that ran it, so B's janitor resource shows nothing about the cull (lastCulledFactIds stays as B's own last run, or [] by default). Session A's janitor resource lists the culled fact's id only, not its content, and the next run there overwrites the list. (Section 4.6, 10: jn:93-137, jn:125-128, sm:69-83, ep:85-92, jb:139-147.)
6. You edit the support flow's config to hygiene: false to stop memory being deleted. Which limits on stored memory still apply, and what changes about ranking? *(edge case)*
   Answer: No janitor is built (mem.janitor is undefined): no confidence decay, no cull, no episode TTL, no stale marking. Stores are not unbounded, though: episodes are still capped at maxEpisodes (200, evicting the oldest consolidated episode first), and prune still runs when the fact count reaches pruneThreshold (20). mem.recall() ranks on raw fact.confidence instead of effective confidence. (The built-in llm-filter recall tool shows raw confidence either way.) To change only part of hygiene instead, pass a partial object, which merges field by field onto the defaults, for example confidenceDecay: false or episodicTTL: false. (Section 1.3, 4.2, 4.3, 12 item 3: ms:847-849, ms:172-176, msb:1485, rc:59-61, hc:36-62, lf:339-347.)
