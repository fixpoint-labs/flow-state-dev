## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. The support desk's skills folder holds `refund-request/`, `plan-change/` and `outage-status/`. A teammate adds a fourth folder named `Refund_Request/`, and the repo also has a stray `.git/` folder in the skills root. What does `readSkillsDirectory` return, and do the other skills still load? *(edge case)*
   Answer: It does not throw. Each folder whose name breaks the naming rules gets its own entry in `errors`. Here that is both `Refund_Request` and `.git`, each with `Skill name "<name>" must be lowercase letters, digits, and single hyphens (not at the start or end)`. The three good skills still come back in `skills`, because one bad skill never stops the rest from loading. A name is refused when it is empty, longer than 64 characters, `_meta`, outside `^[a-z0-9]+(?:-[a-z0-9]+)*$` (uppercase, `_`, `.`, a leading or trailing hyphen, `--`), or a lowercase Windows device name (`con`, `nul`, `com1`-`com9`, `lpt1`-`lpt9`). The checks run in that order, so `CON` gets the lowercase message. To keep `.git` out of `errors`, pass it in `exclude` or `ignore` (exact names, not globs). Facts: section 5, rows 1-5 and the note on CON; section 3, rows 'One bad skill', 'Folder name breaks the naming rules' and `ignore`.
2. A customer types `/refund-request the March 3 charge`. `refund-request` also has `keywords: [refund]`, and the activator uses the default classifier. Which tier activates the skill, is a model called, and what do `$ARGUMENTS` and `$1` become in the body?
   Answer: The slash tier, tier 1, matches. The message starts with `/` and the skill name, the skill is in the collection, it is in `allowed` (if one is set), and it is not disabled. A slash match resolves the turn, so the keyword tier and the classifier are skipped and no model is called. The trimmed text after the name becomes the activation's `input`: `$ARGUMENTS` is `the March 3 charge` and `$1` is `the`, the first whitespace-split token. A keyword or classifier match would have left `$ARGUMENTS` empty. The apply step writes the activation with `source: "slash"` and replaces whatever the field held from the turn before. Facts: section 9, tiers 1-4; section 1 Body, substitutions.
3. An author edits `refund-request/SKILL.md` to add `when-to-use: The customer disputes a charge` (with hyphens), rebuilds, and sees no error or warning. Does the classifier now see that text? If not, what is wrong? *(edge case)*
   Answer: No. The key is spelled with underscores, `when_to_use`. `when-to-use` is an unknown key, and an unknown or mistyped frontmatter key is never an error. It is kept under `_preservedFields.whenToUse` and sets nothing. `readSkillsDirectory` throws parse warnings away anyway. Spelled `when_to_use`, the text is added on its own line after the description wherever a catalog lists the skill: the classifier prompt, the evaluator's options, the load listing and discovery. Facts: section 1, the `when_to_use` row and 'any other key'; section 13, row 1.
4. Last month the app seeded the org's skills collection. Today an author rewrites the body of `refund-request/SKILL.md` on disk and drops a supporting file from it. Meanwhile an admin deleted `outage-status` from the collection. After a restart, what does the model see, and how do you pull the edit through? *(edge case)*
   Answer: The old body. The seeded copy is a copy: a later edit to the folder on disk does not reach a collection that already holds the skill, and a deleted skill is not put back. Ordinary seeding only adds and never deletes a file. To pull the edit through, call `refreshSeededSkills(collection, sources)`. For each name whose manifest is still in the collection, it writes the source and deletes every key in that skill's folder that the source lacks, so the dropped file goes. A file a holder added inside the folder is lost too. `outage-status` is skipped and stays deleted. The call returns `{ refreshed, skipped, removed, failed }`. With `scope: "user"`, each user holds their own copy. Facts: section 0, bullets on the seeded copy, refreshSeededSkills and additive seeding.
5. To keep the model from pulling `plan-change` on its own, the author writes `disable-model-invocation: yes` in its frontmatter. Does it work? What does the flag do when it is set correctly? *(edge case)*
   Answer: No. The flag must be a boolean. A non-boolean value such as `yes` or `"true"` is ignored silently, with no warning, so nothing is disabled. With `disable-model-invocation: true` the skill stays in the collection but leaves every activation path: slash, keyword, classifier, evaluator, the prompt listings and discovery. `loadSkill` refuses it with `Skill "plan-change" has \`disable-model-invocation: true\` and cannot be loaded by the agent`. Even a name listed in `with({ active })` renders nothing, because the live manifest decides at render time. Facts: section 1, `disable-model-invocation` row; section 1 Body; section 7, load tool refusals; section 13, row 3.
6. The desk swaps the default classifier for `createSkillActivator({ evaluator: skillEvaluator("openai/gpt-6-luna") })`. The model provider goes down mid-turn on a message with no slash and no matching keyword. What happens to the turn, and how do you carry on with no skill? And on a good day, if the model picks `refund-request` with confidence 0.3, does it activate? *(edge case)*
   Answer: Any evaluator failure, here a provider error, fails the activator. There is no fallback to the default classifier, which is never built when an evaluator is passed, and no skills are written. Wrap the activator in `.rescue` to carry on with no skill. On a good day the pick is final and no confidence threshold applies, so a 0.3 pick activates with `source: "classifier"`. The generator classifier would drop it, because it keeps only matches at or above `confidenceThreshold` (default 0.65). The evaluator activates at most one skill, a pick carries no `input`, and the no-skill answer activates nothing. Passing `classifierModel`, `confidenceThreshold` or `enableLlmClassifier: false` together with `evaluator` throws at build time. Facts: section 10, Semantics; section 9, activator options table and build-time refusals.
