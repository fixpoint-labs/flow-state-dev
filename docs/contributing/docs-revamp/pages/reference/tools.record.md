## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. A team building a research assistant wants to know which web search providers `tools.search` supports. Their only key is `PERPLEXITY_API_KEY`, and they name no provider. Which provider answers, and how would they get Perplexity Sonar instead?
   Answer: There are seven: Parallel, Tavily, Exa, Perplexity, Serper, Brave and Perplexity Sonar (`searchProviders`, S-1). With no provider named, auto-selection walks the list in the order Parallel, Tavily, Exa, Perplexity, Serper, Brave, Sonar, and picks the first provider that has a key and supports the tier. Perplexity (rank 4) and Sonar (rank 7) share `PERPLEXITY_API_KEY`, and Perplexity supports every tier, so Perplexity answers. Auto-selection never picks Sonar. They reach it only with `provider: "perplexity-sonar"` or `perplexitySonarSearch()` (S-1, S-4).
2. The assistant is deployed to a fresh environment with no API keys set at all. The flow builds `tools.search()`, `tools.fetch()` and `tools.crawl()` at startup. What happens at startup, and what happens when the model calls each tool? *(edge case)*
   Answer: Startup succeeds: none of the three throws when it is built. `search` throws a plain Error when the tool runs: `No search provider available. Configure at least one of: ...`. `fetch` falls back to the built-in provider and never throws for lack of a provider. `crawl` falls back to the built-in crawler, which also never throws for lack of a provider. Keys are read when a tool is called, so setting one later takes effect without rebuilding (T-1, S-4, F-3, K-2).
3. The model asks the built-in fetch for `http://10.0.0.5/admin`, and on a second call for a public page that returns 503. What does each call throw, and which one is worth retrying? *(edge case)*
   Answer: Both throw a `FlowError`. The private address is refused before any socket opens. The error has code `fetch_blocked_url`, message `builtin fetch blocked: <reason>`, `details.errorType: "blocked"` and `retryable: false`. The 503 gives code `fetch_http_error`, `errorType: "http"` and `retryable: true`, because 5xx, 429 and 408 are retryable. Its `details` carry `httpStatus`, `httpStatusText` and `url`, plus `responseBody` when the body is not empty, cut to 1000 characters (F-5, F-6). Only the 503 is worth retrying.
4. The team has keys for Serper, Brave and Exa and sets `tier: "deep"` on `tools.search`. Which provider runs? Later they remove the Exa key and keep only Serper and Brave. What happens to the deep tier then?
   Answer: With all three keys, Exa runs. Serper and Brave support only `fast` and `balanced`, so the deep tier skips them, and Exa sends `type: "deep"`. With only Serper and Brave left, no keyed provider supports `deep`. Selection then falls back to the first keyed provider in priority order, which is Serper, and the tier is ignored, since Serper ignores tier entirely. The search runs; it does not fail (S-3, S-4).
5. A developer edits the config to `tools.crawl({ maxPages: 5, maxDepth: 1 })` to cap crawl cost, and sets `tools.search({ maxResults: 2, topic: "news" })`. Do these limits take effect? *(edge case)*
   Answer: No. The crawl limits come from the tool call: `maxPages` defaults to 20 and `maxDepth` to 2, and the model can set both, so the config values never apply. Only `includePatterns`, `excludePatterns`, `waitForJS`, `provider` and `keys` are config. For search, `maxResults` and `topic` are declared on `SearchConfig` but never read. The model's call parameters decide them, defaulting to 5 results and `general` (S-2, K-1).
6. The team adds `createBashCapability()` with no `provider` option and has not installed any optional packages. Which sandbox providers could they choose, which one do they get by default, and what does the model see when it runs `ls`? *(edge case)*
   Answer: There are six `SandboxProvider` types: `local`, `just-bash`, `vercel`, `upstash`, `moat` and `custom`. `upstash` is not implemented: resolving it throws `Upstash Box adapter is not yet implemented.` The capability defaults to `just-bash` (`createBashBlocks` defaults to `local`). Without the optional `just-bash` peer dependency, the adapter silently falls back to an in-memory sandbox that runs no commands. `ls` returns exit code 1 with `In-memory sandbox: install just-bash for full bash support`; only `find ...` works (T-1, B-1, B-3).
