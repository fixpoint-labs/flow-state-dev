## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. You are adding approval and question cards to a chat app's screen. Which of the registry components need a FlowProvider around them, and what does each one read from it?
   Answer: Approval reads flowKind from FlowProvider (or uses a SuspensionResolverProvider instead). Question, Form and Selection read the same flowKind or resolver. SuspensionCard and RequestGroupRenderer read renderers from FlowProvider: SuspensionCard needs it to honour render.component, and RequestGroupRenderer draws with no custom renderers without it. chatAssistantRenderers is a value you pass to FlowProvider's renderers prop. TaskPlan, Debate, EventedActors and RoutedSpecialists need a SessionItemsProvider, not a FlowProvider. Every other component reads nothing from context. FlowProvider's context default is {}, so none of them throws outside one. They just lose that one job. (Table P-1; RC/context/FlowContext.ts:64,108)
2. A developer renders <Approval item={...}/> but forgot to give FlowProvider a flowKind and added no SuspensionResolverProvider. What does the user see, and what does the developer see? What changes if the stop is a Question or Form card instead? *(edge case)*
   Answer: Approval still draws, but Approve and Reject are disabled, and console.warn fires once on mount: "Cannot resume suspension without flowKind on <FlowProvider>...". Nothing throws. On Question, Form or Selection, Submit shows the error line "Cannot resume without flowKind on <FlowProvider> or a SuspensionResolverProvider." and sends nothing. (Table P-1; RC/hooks/useApproval.ts:152-190, RC/hooks/useSuspensionForm.ts:183-260)
3. You run `fsdev ui add tool`. Where do the files land, what else gets installed with it, and does it need any @flow-state-dev package at runtime?
   Answer: fsdev ui add runs npx shadcn@latest add against the registry (default https://ui.flow-state.dev/r). Files land under components/flow-state/ (tool.tsx and tool-grouping.ts), and you import them as @/components/flow-state/<file>. Its registryDependencies come with it: tool-naming, tokens and code-block. tool value-imports isSuspensionWait from @flow-state-dev/core, so it needs core at runtime, unlike the components that import only item types. (CLI:60-80; RJ:118,179-199; Table I-1)
4. You use chatAssistantRenderers, but you don't want the task board drawn in the chat. What exact override hides it? And if a nested FlowProvider sets only that, does it wipe out the parent's other renderers? *(edge case)*
   Answer: The board is the task-board-meta entry in the data slot, not in component: renderers={{ ...chatAssistantRenderers, data: { ...chatAssistantRenderers.data, "task-board-meta": false } }}. false draws nothing. A nested FlowProvider merges onto its parent. For each slot the child wins, false included, and component, container and data merge key by key, so the parent's other data entries stay. (ChatAssistant section; RC/context/FlowContext.ts:66-103)
5. A teammate drops <TaskPlan collectionId="plan" /> into a page with no SessionItemsProvider and no items prop. What appears? What do they need to add, and does wrapping it in a FlowProvider help? *(edge case)*
   Answer: It reads an empty list and shows its empty state, "No tasks yet" (unless hideEmpty), and it does not throw. It needs a SessionItemsProvider (value is an OutputItem[]) or an explicit items prop. A FlowProvider does not help, because TaskPlan reads no FlowProvider. (Table P-1; TaskPlan section; R/task-plan.tsx:201-215, R/session-items-context.tsx:3-10)
6. A user drags a file onto a PromptInput whose app passed no client. What happens to the file? And what happens to a ReviewSuspension card drawn with no SuspensionResolverProvider when a second person opens the session to answer the review? *(edge case)*
   Answer: With no client, PromptInput refuses the attached file by name (refusal codes include unavailable and upload), so it is not uploaded. A client is anything with upload({ data, mediaType?, filename? }), such as a @flow-state-dev/client client or a flow handle from one. ReviewSuspension with no SuspensionResolverProvider shows the review and the line "This review can't be answered here: the app draws it without a SuspensionResolverProvider to send the answer through." It draws no buttons, so nobody who opens the session can answer from it. (Table P-1; R/prompt-input.tsx:280-330, R/attachments.tsx:43-53; R/review-hold.tsx:448-500)
