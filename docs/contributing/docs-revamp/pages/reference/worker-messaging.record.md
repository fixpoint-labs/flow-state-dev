## 2 · Cold-read questions

Written by an agent that had seen no draft. Pass 9 got these unchanged.

1. Alice's `engineering.lead` asks her `researcher` a question with `wait: true` and no `deadline`. How long does it wait, what can the `sendMessage` tool return, and what ends the wait?
   Answer: Left out, the deadline is the host's default of 5 minutes (300,000 ms) (6.1, 6.3). The wait ends in one of three ways (6.2). If the answer comes in time, the tool returns `{ "status": "answered", "sent": "<asking id>", "reply": "<text>" }`. That happens as soon as the answer is given, even if the researcher's turn carries on afterwards. If the deadline passes first, it returns `{ "status": "running", "sent": "<id>" }`. If the row reads `refused` or `undeliverable`, it returns `{ "status": "failed", "sent", "error" }` (that case is flagged [read], flag 3). A deadline stops nothing: the researcher keeps working, the lead goes on, and the answer arrives later as a message that wakes a turn in the lead's session, sent once (6.2, test t3:388-475). By the existing doc only, the wait also ends if Alice stops the lead's request.
2. Alice's `engineering.lead` tries to message a worker on Bob's roster by its id. What happens, and can Alice's worker tell that the worker exists? *(edge case)*
   Answer: The send is refused `no_worker` with the text `no worker "<to>" on your roster.`, the same text an unknown id gets, so the sender can't tell another user's worker from one that doesn't exist. Nothing is written and no budget is spent (section 4, test t1:1027-1037; section 7: a refused send spends nothing).
3. The lead waits on the researcher, and the researcher's turn throws before it says anything. What does the lead get back, and does the researcher's failure disappear? *(edge case)*
   Answer: A message that asked for a reply always gets exactly one answer. Here the framework sends it as the researcher, with `noAnswer: true` and the text `No answer came back: the turn failed before it could answer.` The waiting lead's tool returns `{ "status": "answered", ..., "noAnswer": true }` with that reason in `reply`. The researcher's turn still fails and its error goes on (5.5, test t2:406-423; 6.2). The sibling cases each have their own text: a turn that ends with no text, a flow that runs no turn on messages, and a server stop partway through the turn.
4. The researcher is in the middle of a turn, and its conversation is stopped waiting for Alice's approval, when the lead's waited message arrives. Is the turn interrupted? What does the log row show, and what does the lead get if the deadline passes? *(edge case)*
   Answer: A message never interrupts a turn. It is heard after the running turn ends, and nothing is dropped (5.3, test t1:1074-1117). While Alice holds the conversation, the message waits until that stopped request ends, not merely resumes. The row stays `unconfirmed` with `queuedBehind: "user"` (5.1, 5.3). If the deadline passes meanwhile, the tool returns `{ "status": "running", "sent": "<id>", "recipient": "waiting_on_person" }` (6.2, test t3:388-432).
5. When is a send refused before anything is sent? Say what happens to a call that passes `deadline: 30` with `wait: true`, one that passes `deadline` without `wait`, and a `wait: true` on a host with no sweeper.
   Answer: A refused send answers `{ ok: false, error: "<code>: <text>" }`, writes nothing and spends no budget (section 4). The deadline is in milliseconds and must be from 1,000 ms to 86,400,000 ms unless the host changed the bounds with `waitDeadlines`. A deadline of 30 ms is refused `wait_deadline_out_of_range` and is never clamped (6.3, 6.4, test t3:324-335). A `deadline` without `wait` is `deadline_without_wait`. A host that can't hold a wait answers `wait_unavailable`, and the send is never turned into a plain send. There, a send with `replyRequested` and no `wait` is the way, and the answer comes back as a message (6.5, test t3:284-305). Text that is blank or over 8,000 characters is refused as an input error before the send runs (flag 1).
6. Alice types one line and her workers start passing messages around in a ring. How many messages can they send, what does the seventh send get, and when can they send again? *(edge case)*
   Answer: Each line a user types starts a budget of `messages.budget` worker messages (default 6). It covers everything that descends from that line across every worker, parallel branches included. The seventh send is refused `budget`, and its text tells the worker to stop passing messages on and say so. Separately, one request sends at most `messages.perTurn` messages (default 3), and the fourth gets `per_request_limit`. A refused send spends nothing, and the framework's own answers are exempt. A fresh budget starts on Alice's next line in that conversation (section 7, tests t1:432-554).
