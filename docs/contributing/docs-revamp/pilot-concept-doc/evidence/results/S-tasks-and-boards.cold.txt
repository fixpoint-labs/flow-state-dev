**R4. What is a block?** A block is the framework's unit of work: a model call, a function, or a chain of them. Examples are `analyst`, `writer`, and `board.drain` itself, and a block can be an action or one step in a longer chain.

**P2.1 One research task fails.** The failed task is marked `errored`. The other two research tasks are unaffected and run to completion, since the board carries on with whatever else is ready. `compare` is marked `cancelled` and never runs because a task it depends on failed. The drain then stops and emits an item with `terminationReason: "blocked-by-failures"`, which your flow reads to decide what to tell the user.

**P2.2 A task added after the request finishes.** No, it does not run on its own. The drain exists only while a request is running `board.drain`, so the task waits where it is until a drain runs again. To keep tasks across requests, store the board in a resource in session, user, or org scope instead of the default request storage, and then have some later request run `board.drain`. A board is not a background queue.

**P2.3 How compare gets the results.** Its block receives what the three research tasks produced on `input.deps`, keyed by task id (`acme`, `globex`, `initech`).
