**R1.** An app is one server plus the pages that talk to it. It has a host file (the one call that builds the server), React pages that read and write through typed hooks, and a store for sessions, state and tasks. The builder owns it, and one server can serve many users.

**R2.** A kit is one feature packaged so an app installs it with a single config object. It has a name, config, requires, slots, contributions, an optional folder and an install step. It is imported in one half (the package with its flows, views, hooks, blocks and components) and owned in the other (the folder it scaffolds into the app).

**R3.** A flow is what the server serves. It has an id and declares actions (the only way in, each running one root block), state at session, user or org scope, resources, capabilities and views. Each id is registered once, and many sessions can be opened against one flow.

**R4.** A block is a typed unit of work with an input shape, an output shape and something that runs. There are exactly five kinds: handler, generator, evaluator, sequencer and router. A tool a model can call is an ordinary block.

**R5.**
(a) A worker's instructions: the body of its `WORKER.md` in the kit folder (owned).
(b) A whole feature such as coding agents: a kit. Install the harnesses kit in the host file. Write your own kit only if two apps will share the feature.
(c) One step inside how a request is handled: edit that block in your own flow.
