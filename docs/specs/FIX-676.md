# FIX-676: Trading-desk — Synthesis-Phase Web Search (Google-Style Lookups Beyond Phase 1) — Implementation Spec

## 1. TLDR

**Plain-language summary.** Today the trading-desk demo only does "Google-style" web lookups at the very start (the analysts) and, in one narrow case, at the very end. The middle of the pipeline — where the desk actually decides what to trade and how much — can't look anything up, so it either skips a relevant recent fact or leans on the model's memory. This change lets the deciding agents (the trader, the risk officers, and the portfolio manager) search the web to double-check a specific claim before they commit, while a shared "sources we already looked at" list keeps them from googling the same thing twice. It only switches on for the higher-quality run mode, and every fact they pull is cited.

**Deliverables:**

- **Capability (`labs/trading-desk/src/flows/analysis/capability.ts`):** two new presets — `corroborate` (cost-gated `search`+`fetch` + clause) and `reviewReferences` (cost-gated `fetch`-only + clause). Both also carry the shared "references consulted" ledger context under the same `full` gate (a persisted citation can't leak the tag onto a `fast` re-run). Two new clauses (`CORROBORATION_CLAUSE`, `REVIEW_REFERENCES_CLAUSE`). `search` is dropped when no provider key is configured (probed via the tools package's own `resolveProvider`, so the check can't drift).
- **Shared ledger (`lib/format.ts`):** `formatReferencesConsulted(memos)` — derives the references list from the `citations` already on every memo (dedup by URL, attribute by agent, null when empty). No new resource.
- **Generators:** `corroborate` on the trader (P3), all three risk personas (P4), and the PM (P5b); `reviewReferences` on the scenario forecaster (P5a) and the risk consolidator (P4). The ledger context comes with each preset (no separate opt-in).
- **Schemas:** nullable `citations` added to `tradeProposalOutputSchema`, `personaCritiqueOutputSchema`, `riskAssessmentOutputSchema`, `scenarioForecastOutputSchema`, `portfolioDecisionOutputSchema`.
- **Writers:** scenario + PM writers pass `citations` through (the spread-everything writers already do).
- **Docs:** "The `corroborate` preset" section in `labs/trading-desk/CLAUDE.md`. No `apps/docs` change (lab example).
- **Tests:** `test/references-consulted.spec.ts` (ledger dedup/attribution/empty); existing strict-schema spec auto-covers the new fields; test mocks updated for the new required field.

**Size:** Medium–Large (single package, single PR; ~250–350 LOC incl. test-mock updates).

## 2. Overview

Linear issue: [FIX-676](https://linear.app/fixpoint-labs/issue/FIX-676). The desk's synthesis phases reason only over Phase 1's output plus training priors; on `full` runs they cannot look up a fresh fact (a peer comp, a recent downgrade) to corroborate a claim. This adds a cost-gated, agent-initiated web search affordance to the synthesis agents that most need it, plus a shared references ledger so they reuse what the desk already surfaced — preserving the existing citation and cost discipline.

**The issue was a month stale.** Since it was filed: Phase 6 (thesis validator) already has full agent-initiated search+fetch via the `verify` preset, and Phase 2 bull/bear open-web was *deliberately rejected* (FIX-679, debate-asymmetry). So the real gap was the trader, risk, forecaster, and PM — and this spec scopes there, leaving the debaters out (tracked separately) and the lenses out (independence guarantee, FIX-655).

## 3. Background & Research

### Current web-search/fetch footprint (verified in code)

| Stage | Web search/fetch today | Mechanism |
|---|---|---|
| P1 analysts | fetch only, gated `full` | `investigate` preset + `discover_*` tools |
| P2 bull/bear | closed-world only | `counterEvidence` → `find_counter_evidence`; open-web **rejected** (FIX-679) |
| P2b lenses | none | — |
| P3 trader / P4 risk / P5a forecaster / P5b PM | **none** (the gap) | — |
| P6 thesis validator | search + fetch, ungated | `verify` preset (user-thesis only) |

### Reusable precedents this composes

- **`verify`** (`capability.ts`): `tools: () => [searchWeb, fetchArticle]` — the synthesis-time tool set, with `searchWeb`/`fetchArticle` already declared as shared instances.
- **`investigate`** (`capability.ts`): `tools: (ctx) => costPreset === "full" ? [...] : []`, context `null` on `fast` — the cost-gate idiom. `corroborate` is the intersection: `verify`'s tools + `investigate`'s gate.
- **Citation surface:** `memoStateSchema.citations` (`resources.ts`) is a shared nullable field; the renderer shows a "Sources" footer for any memo with non-null citations (Phase 1 + Phase 6 rely on this).

### Why the references ledger is derived from memo citations (not a new resource)

Generators cannot write a resource mid-output, and wrapping `@flow-state-dev/tools` `search`/`fetch` to record into a resource would either call a block from a handler (BP-011) or duplicate provider logic. But every corroborating agent already emits `citations` on its memo, and the memos collection is already shared and readable. So the ledger is a read-time projection over memo citations — zero new resource, no tool wrapping. This is the BP-038 (build the least) choice: the same value with no new persisted surface.

### Caching note (scope boundary)

`@flow-state-dev/tools` `search`/`fetch` have no cache (confirmed: `fetch/resolver.ts` resolves a provider and calls it every time). The references ledger removes the duplicate *search*; a cheap duplicate *fetch* would require caching at the tool level — a `@flow-state-dev/tools` change, deliberately deferred (the synthesized claim + URL is already in the upstream memo, so raw re-fetch is rarely needed).

### Key Decisions & Ramifications (top 5)

1. **Ledger derived from memo `citations`, not a new resource.** Alt: a `researchLedger` resource written by a wrapped tool. Locks in zero new persisted surface and no BP-011 tension; captures *cited* links (not bare unfetched queries). Ramification: an exploratory search that found nothing isn't recorded — acceptable, since the reusable artifact is the URL.
2. **All three risk personas corroborate, or none.** Alt: only the conservative officer (the original spec). Locks in symmetry — arming one side would tilt the desk's already conservative-leaning synthesis (the FIX-679 symmetry principle applied to P4). Cost: three more agents can search on `full`.
3. **Two tiers — search+fetch (`corroborate`) vs fetch-only (`reviewReferences`).** Alt: one tier. Lets the forecaster + consolidator pull a surfaced link without initiating new searches (the user's "read search results" capability). Cost: a second preset + clause.
4. **Hard-gate on `costPreset === "full"`.** Alt: ungated like `verify`. Keeps `fast` byte-identical (zero web fetch); the existing fast goal check proves no regression. The affordance is invisible on `fast`.
5. **Cache-wrap deferred.** Alt: wrap fetch in `getOrFetch` now. The clean wrap needs a `@flow-state-dev/tools` change; the ledger already delivers the de-dup-search benefit, so the marginal cheap-refetch is out of scope (BP-038).

## 4. Technical Design

All within `labs/trading-desk/`.

### 4.1 `corroborate` / `reviewReferences` presets (capability.ts)

Two presets, each declaring `resources: { memos }` and carrying the ledger context under the same `full` gate as its tools/clause (folding the ledger into the tool presets — rather than a standalone `referencesConsulted` preset — makes the `fast` no-op structural, so a persisted citation cannot surface the tag on a `fast` re-run):

- `corroborate`: `tools: (ctx) => full ? webLookupTools() : []`; `context.corroboration: full ? CLAUSE : null`; `context.referencesConsulted: full ? formatReferencesConsulted(memos) : null`.
- `reviewReferences`: `tools: (ctx) => full ? [fetchArticle] : []`; `context.reviewReferences: full ? CLAUSE : null`; `context.referencesConsulted: full ? formatReferencesConsulted(memos) : null`.

`webLookupTools()` returns `[searchWeb, fetchArticle]` when a search provider key is configured, else `[fetchArticle]` — `hasSearchProvider()` probes the tools package's exported `resolveProvider({})` in a try/catch (no hand-copied env list; can't drift).

`CORROBORATION_CLAUSE` instructs: corroborate a *specific* claim (not re-run discovery); check `<referencesConsulted>` first; cap 2 searches + 2 fetches; cite every fetched URL; inconclusive → say so, don't raise conviction; if `<data>`/memos already answer, emit `citations: null`. `REVIEW_REFERENCES_CLAUSE`: no search; you may `fetch` a URL already in `<referencesConsulted>`; cite what you fetch; a miss is not license to fabricate.

### 4.2 The ledger formatter (lib/format.ts)

`formatReferencesConsulted(memos)` walks `ALL_MEMO_KEYS`, reads each memo's `citations`, dedups by URL (first citer wins), attributes via `AGENTS[agentName].role`, returns a `<referencesConsulted>`-body string or `null` when nothing has been cited.

### 4.3 Generator opt-ins

- Trader (P3), aggressive/conservative/neutral risk (P4 — via the shared `tradingMemos` helper), PM (P5b): `corroborate: true`.
- Scenario forecaster (P5a), risk consolidator (P4): `reviewReferences: true`.

### 4.4 Schemas + writers

Add `citations: z.array(memoCitation).nullable()` to the five output schemas. Spread-everything writers (trader, persona, consolidator) pass it through automatically; the scenario and PM writers (which reshape) pass `citations` explicitly. The memo state field already exists, so no `memoStateSchema` change.

### 4.5 Grounding interaction

`GROUNDING_CLAUSE` already permits "data provided by … tools," so a corroborate fetch is permitted; the new clauses are the explicit carve-out + citation requirement (the `INVESTIGATION_CLAUSE`/`VERIFICATION_CLAUSE` pattern). No `GROUNDING_CLAUSE` edit.

## 6. Edge Cases & Error Handling

| Case | Behavior |
|---|---|
| `fast` preset | tools `[]`, clauses + ledger suppressed (`null`); memos emit `citations: null`; identical to pre-change |
| `full`, no search key | the `search` tool is **dropped** (the resolver throws with no provider key — `hasSearchProvider()` guard); the agent keeps `fetch` (builtin fallback always works) and corroborates only via surfaced URLs; `citations: null` if nothing fetched. Applies to `verify` too (same guard). |
| Ledger empty | `formatReferencesConsulted` returns `null` → tag suppressed |
| URL cited by two agents | deduped to one line (first citer wins) |
| Reviewer fetches non-listed URL | prompt-discouraged; harmless if it happens (still cited) |
| Aggressive/neutral persona doesn't fetch | emits `citations: null` (shared schema, inert) |

All corroborate failures degrade to a blind spot; generator failures use the existing per-step rescue.

## 7. Testing Strategy

**Discipline:** `fsd:tdd` (Feature).

**Goal & goal check (manual, out-of-CI):** observable outcome — on a `full` run, a synthesis memo cites a web source it actually fetched (or records the lookup inconclusive). Goal check: a `full`-preset `fsdev run analysis analyze` on a real-data ticker with a search key, then a memo read asserting a corroborator memo has non-null `citations` or an inconclusive note. The existing `goals/trading-desk-headless/fixture-run-clean` (fast) doubles as the no-regression proof (corroborate is a no-op on `fast`).

**CI specs (mocked, deterministic):**
- `references-consulted.spec.ts`: ledger returns `null` when nothing cited; renders URL+title+role; dedups a shared URL.
- `output-schemas-strict.spec.ts` (existing): auto-covers the five schemas with the new `citations` field staying strict-compatible.
- Test-mock updates: every mock of the five outputs now provides `citations: null` (a new required field).
