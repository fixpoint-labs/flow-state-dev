## 1. TLDR

**Plain-language summary.** Right now the desk can size a single trade against your current holdings, and it can size against a risk-appetite dial you pick per run — but nowhere does it record *what you're actually aiming for*: your target mix of stocks/bonds/cash, your rules ("never more than 5% in one name, keep 10% cash, no tobacco"), your time horizon, and how far you'll let things drift before rebalancing. Without that, "is my portfolio balanced?" has no answer, because there's no target to be balanced against. This adds a durable, editable **portfolio mandate** (an Investment Policy Statement): you write down your policy once, it sticks, and the analysis reads it so the position-sizing respects your standing rules. It also unifies the existing per-run risk dial into this one policy object so there's a single place your intent lives, not two.

**Technical statement.** Add a durable, user-scoped **portfolio-mandate (IPS) resource** to the `portfolio` flow — objectives (risk tolerance + optional return target), a target asset-class allocation with rebalancing bands, standing constraints (max position weight, min cash, exclusions), and time horizon — editable from the Portfolio UI, read at analysis seed, injected into the PM, and gating PM sizing deterministically; the FIX-752 risk-appetite mandate becomes the appetite facet of this one object.

## 2. Overview

Linked issue: [FIX-761](https://linear.app/fixpoint-labs/issue/FIX-761). The desk can size one position against the live portfolio (FIX-728, Done) and against a per-run risk-appetite dial (FIX-752, Done), but there is no durable statement of portfolio intent — target allocation, standing constraints, horizon, rebalancing policy. So "how balanced is my book?" is unanswerable (balanced against what?), rebalancing signals are impossible (drift is distance from a target that doesn't exist), and PM sizing can't respect standing rules (max single-name %, min cash, exclusions) because none are recorded. This spec adds a durable, user-editable **portfolio mandate** — the classic IPS (objectives → constraints → target allocation → rebalancing policy) — as a user-scoped resource, and folds the FIX-752 risk-appetite mandate into it as the appetite facet so there is **one policy concept, not two**. The analysis flow reads it at seed and the PM commit gates size against it deterministically (the FIX-752 clamp seam). Drift *measurement* (FIX-762) and the *review loop* (FIX-763) are downstream consumers that read this object; they are out of scope.

## 3. Background & Research

### 3.1 What the desk holds today (codebase, verified)

- **Risk-appetite mandate (FIX-752, Done).** `analysis/lib/risk-mandate.ts` exports `MANDATE_PACK` (three presets), `riskMandateSchema` (the dial bundle), `resolveMandate(id)`, `mostConservativeMandate(ids)`. The effective mandate is resolved at seed (`orchestration/guards.ts:151-153`): per-run override (`analyzeInputSchema.riskMandate`) → most-conservative selected-account default (`account.riskMandate`, an **opaque string** the analysis flow validates via `resolveMandate`) → null. It is frozen onto `state.riskMandate` and the PM commit (`agents/portfolio-manager/writer.ts:193-257`) derives a worth-it verdict and clamps `portfolioFit.targetWeightPct` (hard capacity veto, then soft worth-it cap). **This is the concept FIX-761 must reconcile with, and the exact commit seam the constraint gate extends.**
- **Per-position thesis records (FIX-760, in progress/Done).** `portfolio/thesis-schema.ts` + `thesesCollection` (`portfolio-resources.ts`) is the structural template: a durable, user-scoped resource (`flowIsolation: false`, keyed household), browser-safe schema leaf, editor validates client-side + action re-validates server-side (`thesis-actions.ts` `saveThesis`/`deleteThesis`), read at seed (`getOptional`) and **frozen onto `state.standingThesis`**, injected via a `standingThesis` capability preset (`<standing-thesis>`, suppressed to null when absent), live client read via `useResourceCollectionList` (`use-theses.ts`), UI editor `thesis-dialog.tsx` + `thesis-form.ts`. **The IPS is the portfolio-level analog of this per-name document.**
- **Asset-class taxonomy (FIX-773, Done).** Every holding carries `assetClass ∈ {equity, fixed_income, cash, crypto, alternative}` (`portfolio-schema.ts:30`) — described in-code as "the NOT NULL field every drift/exposure/mandate consumer groups on." The classifier (`classify-instrument.ts`) is already the producer. **This is the ready-made target-allocation bucket taxonomy — no parallel classification layer needed.**
- **Portfolio snapshot at seed (FIX-728, Done).** `seedSession` already reads accounts via `getRepository().getPortfolio(uid)` + `toAccountStates` and builds the snapshot (`build-portfolio-context.ts`), frozen onto `state.portfolio` with per-holding `weightPct`. The PM emits a strict `portfolioFit` object and derives echo fields at commit (`currentWeightPct`, `hasPortfolioContext`, a validated `suggestedAccount`). **The mandate's constraint gate slots into this existing commit path; the snapshot supplies current weights the constraints measure against.**
- **Account record.** `accountStateSchema` (`portfolio-schema.ts:132`) carries `riskMandate: z.string().nullable().default(null)` (the per-account appetite default) and `type` (taxable/IRA/Roth/401k). Accounts/holdings are app-owned relational tables (FIX-772) reached through the repository; `accountStateSchema` remains the domain type. Resource-state schemas allow `.nullable()`/`.default()` (BP-016 only constrains generator outputs).
- **No durable portfolio policy exists** (grep-confirmed): no target allocation, no constraints, no bands, no objectives, no horizon anywhere. FIX-752's dials are the only "standing" policy, and they are appetite-only.

### 3.2 Industry research → the v1 IPS shape

(Sources: CFA Institute IPS elements (RRTTLLU); AnalystPrep IPS study notes; Vanguard/Bogleheads sample IPS; Kitces/Daryanani on rebalancing corridors; White Coat Investor on the 5/25 rule.)

- **IPS core is a four-part chain**: objectives → constraints → target allocation → rebalancing policy. Governance/roles are prose; that chain is the structured, machine-usable part. Model the chain.
- **Objectives are conventionally a return objective + a risk tolerance** (ability ∧ willingness, lower governs). The retail shorthand is a single conservative/moderate/aggressive label. **The issue's "growth/income/preservation *mix*" has no practitioner precedent** — a weighted objective mix is non-standard. v1 uses a **risk-tolerance enum + an optional return target** (§3.4, decision 3).
- **Target allocation is a flat asset-class array** — Equity / Fixed income / Cash / Alternatives — each with a target weight and an optional min/max range (the policy corridor). Sub-asset-class and sleeves are elaborations. Sector/position targets are *not* how allocation is expressed — sectors appear only as **constraint caps**.
- **Rebalancing bands (the crux) come in two forms** that must not be silently blended: **absolute** (percentage-point drift from target) and **relative** (percentage of the target weight). The 5/25 rule combines them (whichever fires first); the evidence-based advisor lean (Daryanani via Kitces) is ~**20% relative**, because relative bands scale across bucket sizes. The **drift computation itself differs** between the two, so `bandType` must be an explicit, first-class field. v1 default: **relative bands, 20%** (§3.4, decision 5).
- **Constraints reduce to**: `maxPositionWeight` ("at time of purchase" is the convention), `minCashWeight`, `exclusions[]`, optional `sectorCaps[]`. Real IPS documents mix **hard limits** (position/liquidity) with **advisory guidelines** (ESG/values screens). Model an optional per-constraint enforcement level only if the desk branches on it.
- **Time horizon** is conventionally stated in **years**, sometimes with a short/intermediate/long category. Store `years` as the primitive; derive the category.

### 3.3 Why this approach fits the codebase

The design reuses four load-bearing precedents verbatim, so implementation is mechanical:

1. **Durable, user-scoped, seed-injected policy document** (FIX-760 `standingThesis`): a browser-safe schema leaf + a `flowIsolation: false` user-scoped resource + seed `getOptional`/freeze + a frozen-state capability preset + a client-side editor. The IPS follows this shape one-for-one, at the household (not per-ticker) grain — a single resource, the `portfolioQuotes` cardinality.
2. **Deterministic gate + interpretive narration at PM commit** (FIX-752 / FIX-728): the constraint clamp and the derived `policyVerdict` are computed at commit from the frozen mandate + the snapshot (never trusted from the LLM — the `agreesWithTrader` precedent); the PM's `policyFit` narrative passes through.
3. **Downward-only size clamp at the existing seam** (FIX-752): the `maxPositionWeight` clamp is another `min(targetWeightPct, cap)` applied right after the FIX-752 mandate clamp in `writer.ts` — same idiom, same seam, no new machinery.
4. **Additive resolution chain** (FIX-752 seed): the risk-appetite fold-in is one `?? resolveMandate(mandate?.riskAppetite)` appended to the existing chain — the account field keeps working (BP-030), the IPS adds a household layer above it (BP-038).

### 3.4 Key Decisions & Ramifications (top 5)

1. **One policy object; FIX-752 appetite folds in as a facet (additive), not a rewrite.** *Decision:* the IPS carries `riskAppetite` (an opaque `MANDATE_PACK` id, the `account.riskMandate` decoupling precedent); the resolution chain becomes `run override → account default → IPS household → null`. *Rejected:* moving appetite entirely onto the IPS and deprecating `account.riskMandate` (Q1 option B) — cleaner "one field" but drops the retirement-vs-taxable differentiation FIX-752 deliberately built and the issue itself motivates. *Ramification:* three resolution layers coexist (run/account/household). This is a policy hierarchy, not two competing concepts — but it means the account field's semantics shift from "the default" to "a per-account exception above the household default." Locks in a precedence order the health view (FIX-762) and review loop (FIX-763) must read consistently.
2. **A resource, not an `app.*` table.** *Decision:* the mandate is a user-scoped FSD resource (the FIX-760 thesis reasoning — a flat household document, no FK/join/aggregation, agent-facing state read at seed). *Rejected:* an `app.mandates` relational table (the FIX-772 accounts/holdings path). *Ramification:* buys the live client read path + `resource_change` streaming for free (no bespoke route). Rules out cheap relational rollups — but the IPS needs none (it's one row per household). If FIX-771 later needs per-sleeve mandates with relational sleeve↔account joins, that is *its* call to make; today's resource does not foreclose it (a sleeve container can hold N mandate documents).
3. **Objectives = risk-tolerance enum + optional return target, not a growth/income/preservation mix.** *Decision:* follow practitioner convention; correct the issue's sketch. *Rejected:* the weighted growth/income/preservation mix (no practitioner precedent; invents drift-like math with no consumer). *Ramification:* simpler, honest schema; the enum maps cleanly to how the desk already reasons about posture. If a future consumer genuinely needs a growth/income split, it's an additive field — not a v1 shape we must guess now.
4. **Target allocation over the existing `assetClass` enum; custom buckets deferred.** *Decision:* targets/bands are per `assetClass` (equity/fixed_income/cash/crypto/alternative) — the field every holding already carries and FIX-762 will group on. *Rejected:* custom user buckets ("AI infra", "income") in v1 — most honest for real users but needs a name→bucket classification layer that doesn't exist and complicates drift math. *Ramification:* drift math (FIX-762) is mechanical (group by an existing NOT-NULL column). Custom buckets and sector targets are a clean additive follow-up (§8), and align with FIX-771 sleeves.
5. **Constraints: `maxPositionWeight` + analyzed-ticker exclusion are hard PM-commit clamps; min-cash + allocation drift are advisory.** *Decision:* mirror the FIX-752 soft/hard split — a single-position cap and an exclusion of the *analyzed name* are clean deterministic size clamps at commit; min-cash and allocation drift are portfolio-level (not single-position) and drift is FIX-762's math, so the PM gets them as context to address in prose. *Rejected:* hard-gating everything (min-cash isn't a single-position clamp; it would fabricate a portfolio-level action the single-ticker run can't take) and advisory-only for everything (a non-compliant PM could size past a stated hard cap — the FIX-678 lesson). *Ramification:* the desk's show-the-reasoning character is preserved for portfolio-level policy while the two enforceable single-name limits are deterministic. Rebalancing *execution* (sell-to-rebalance) is never produced — the desk analyzes one ticker at a time.

### 3.5 Alternatives considered and rejected

- **Build the sleeve container now (Q2 option B).** FIX-771 (multi-strategy sleeves) proposes the durable mandate eventually become a container of per-sleeve mandates and asked to reconcile before FIX-761 is specced. Rejected for v1 on YAGNI/BP-038 grounds: sleeves are unbuilt and unscheduled; a container adds speculative structure. Instead v1 ships a flat household mandate and documents the seam (a future `sleeves: Mandate[]` wraps today's object, which becomes the household/default policy). FIX-776 (blocked by this) will want a `weightingProfile` reference on the mandate — v1 does **not** pre-add the field (that would be the speculative surface BP-038 warns against); because `portfolioMandateSchema` is a plain object, FIX-776 adds it in one additive line when it builds the mechanism (§8).
- **A second "portfolio mandate" concept beside the risk mandate.** Rejected — this is exactly the "two overlapping concepts" the issue forbids. Resolved by decision 1 (one object, appetite as a facet).
- **Custom / sector-level target buckets in v1.** Deferred (decision 4, §8).

### 4.2 Data flow

```
savePortfolioMandate: validate + upsert portfolioMandateResource (durable household policy)
seedSession (analysis):
   mandate = ctx.resources.portfolioMandate.state            // nullable single-resource read
   riskMandate =
       resolveMandate(input.riskMandate)                     // per-run override
       ?? mostConservativeMandate(scoped.map(a => a.riskMandate))  // per-account default
       ?? resolveMandate(mandate?.riskAppetite ?? null)      // IPS household appetite  (NEW)
       ?? null                                               // mandate-blind
   freeze state.portfolioMandate = mandate                   // full IPS object, or null
   freeze state.riskMandate = riskMandate                    // unchanged shape
   … guards, portfolio snapshot, spine …
portfolioStage (PM):
   generator reads <portfolioMandate> + <portfolioContext> + <riskMandate> + <rewardToRisk>;
     emits narrative policyFit (allocationRead, constraintRead)
   commit (writer.ts), after the FIX-752 mandate size clamp:
       if mandate != null:
         excluded  = mandate.constraints.exclusions includes ticker(canonical)  // ticker match only (§4.3)
         posCap    = mandate.constraints.maxPositionWeightPct
         capped    = posCap != null && targetWeightPct > posCap
         if excluded:            targetWeightPct = min(targetWeightPct, currentWeightPct ?? 0)  // no-add, downward-only
         if posCap != null:      targetWeightPct = min(targetWeightPct, posCap)                 // hard cap
         policyVerdict = excluded ? "excluded" : (capped ? "capped" : "within-policy")
         // min-cash + allocation drift are advisory: surfaced in <portfolioMandate>, PM narrates; NOT clamped
       echo { mandatePresent, positionCapClamped, excluded, policyVerdict } → memo + snapshot + runSummary
```

### 4.3 API surface

`portfolio/portfolio-mandate-schema.ts` (browser-safe leaf):

```ts
/** The allocation buckets ARE the existing holding asset classes (FIX-773) — so
 *  drift (FIX-762) groups on a field every holding already carries. */
export const mandateAssetClassSchema = z.enum([
  "equity", "fixed_income", "cash", "crypto", "alternative",
]);

export const riskToleranceSchema = z.enum(["conservative", "moderate", "aggressive"]);
export const bandTypeSchema = z.enum(["absolute", "relative"]); // pp-drift vs %-of-target
export const timeHorizonCategorySchema = z.enum(["short", "intermediate", "long"]);

/** One target-allocation bucket: a target weight (fraction 0..1) over an asset
 *  class, with an optional explicit min/max corridor overriding the global band. */
export const allocationTargetSchema = z.object({
  assetClass: mandateAssetClassSchema,
  targetPct: z.number().min(0).max(1),
  minPct: z.number().min(0).max(1).nullable().default(null),
  maxPct: z.number().min(0).max(1).nullable().default(null),
});

export const mandateConstraintsSchema = z.object({
  maxPositionWeightPct: z.number().positive().max(1).nullable().default(null), // hard, at-purchase
  minCashPct: z.number().min(0).max(1).nullable().default(null),               // advisory
  // Canonical upper-case tickers. v1 matches the ANALYZED ticker only — a sector
  // string here is inert (no sector classification yet; deferred with sector caps, §8).
  exclusions: z.array(z.string()).max(200).default([]),
});

export const rebalancingPolicySchema = z.object({
  bandType: bandTypeSchema.default("relative"),
  bandWidthPct: z.number().positive().default(0.2), // 0.2 = ±20% relative (evidence-based default)
});

export const portfolioMandateSchema = z.object({
  /** Free-text label for the policy (e.g. "Household IPS 2026"). */
  label: z.string().min(1).max(120).default("Portfolio mandate"),
  objectives: z.object({
    riskTolerance: riskToleranceSchema,
    returnTargetPct: z.number().nullable().default(null),           // annual %, optional
    returnBasis: z.enum(["nominal", "real"]).nullable().default(null),
  }),
  targetAllocation: z.array(allocationTargetSchema).max(5).default([]), // one per asset class
  constraints: mandateConstraintsSchema,
  rebalancing: rebalancingPolicySchema,
  timeHorizon: z.object({
    // Years is the stored primitive; the short/intermediate/long CATEGORY is
    // DERIVED (in the formatter + UI via `timeHorizonCategorySchema`), never
    // persisted — so a record can't carry an inconsistent years/category pair.
    years: z.number().positive().nullable().default(null),
  }),
  /** The risk-appetite mandate id (FIX-752 MANDATE_PACK) this policy adopts as
   *  the household default. OPAQUE string (the `account.riskMandate` decoupling):
   *  the analysis flow validates via `resolveMandate` at seed. Null → no household
   *  appetite; a per-account default or per-run override still applies. */
  riskAppetite: z.string().nullable().default(null),
  createdAt: z.string(),
  updatedAt: z.string(),
});
export type PortfolioMandate = z.infer<typeof portfolioMandateSchema>;

/** Non-throwing validation for the editor + action boundary. Returns the list of
 *  human-readable issues (empty = valid). Checks: target weights sum to ≤ 1
 *  (cash is the implicit remainder — a strict ==1 would force the user to state
 *  cash); each bucket appears at most once; min ≤ target ≤ max where set;
 *  band width in (0, 1]. NOT a generator output — plain validation. */
export function validatePortfolioMandate(m: PortfolioMandate): string[];
```

### 4.4 State management

- **Durable store:** `portfolioMandateResource` — user-scoped single resource, `flowIsolation: false`, written by `savePortfolioMandate`, read at seed and by the UI (`useResource`). Null → mandate-blind (identical to today).
- **Per-run freeze:** `state.portfolioMandate: portfolioMandateSchema.nullable().default(null)` (`analysis/state.ts`), frozen at seed (the `portfolio`/`riskMandate`/`standingThesis` precedent — store the resolved object so the PM commit reads it without re-fetching). Does **not** join the session keying tuple (the `riskMandate`/`selectedAccountIds` precedent — policy is a refinement, not a new report identity).
- **Appetite resolution:** one line appended to the existing chain in `guards.ts` (§4.2). The `account.riskMandate` field and the per-run override are untouched (BP-030 additive).
- **Decision snapshot + run summary:** the four echo fields for the durable, machine-scoreable record and the headless goal check.

### 4.5 Error handling

- **Malformed / absent mandate → mandate-blind.** Two layers keep bad policy out: the write action runs `validatePortfolioMandate` and rejects invalid input (business rules — sum ≤ 1, min ≤ max), so bad policy never persists; and at seed a schema-invalid persisted record fails the framework `stateSchema` parse and reads as null. Either way the run degrades to no policy and behaves exactly as today — never throws (the spine `if (!fundamentals) return;` discipline, BP-020 spirit). Seed does **not** re-run the business-rule `validatePortfolioMandate` — a write-time-valid record is trusted (the `standingThesis` precedent); the gate math is null-safe on any individually-absent field regardless.
- **Unknown `riskAppetite` id** resolves to null via `resolveMandate` (mandate-blind for appetite) — never throws (the `account.riskMandate` precedent).
- **All clamps are downward-only.** The constraint gate never inflates size or the rating; `maxPositionWeight` and exclusion only reduce. The rating is untouched (the FIX-715/FIX-752 orthogonality).
- **No hard throw anywhere in the commit path** — every policy projection is a deterministic, idempotent commit-time computation.

## 6. Edge Cases & Error Handling

| Case | Expected behavior |
| -- | -- |
| No mandate (resource null) | Mandate-blind: `<portfolioMandate>` suppressed, `policyVerdict = "no-mandate"`, no clamp, no exclusion. Identical to today. |
| Mandate set, no `maxPositionWeight`, no exclusions | Advisory-only: allocation/min-cash surfaced to the PM; size never clamped; `policyVerdict = "within-policy"`. |
| Analyzed ticker on the exclusion list | Hard no-add: `targetWeightPct` clamped to `min(target, currentWeightPct ?? 0)`; `excluded: true`; `policyVerdict = "excluded"`. PM prompted to narrate the exclusion. |
| Target exceeds `maxPositionWeightPct` | Hard cap: `targetWeightPct = min(target, cap)`; `positionCapClamped: true`; `policyVerdict = "capped"`. |
| Both exclusion and cap apply | Exclusion (no-add) is the tighter/stronger line; `policyVerdict = "excluded"` (cap subsumed). |
| Appetite: run override + IPS `riskAppetite` both set | Run override wins (existing FIX-752 precedence, unchanged). |
| Appetite: account default + IPS `riskAppetite`, no override | Account default wins (per-account exception above household default). |
| Appetite: only IPS `riskAppetite` | IPS household appetite binds. |
| Invalid mandate saved via action | Rejected at write time with `issues[]`; nothing persists. A pre-existing invalid record (schema drift) → mandate-blind at seed, never throws. |
| Allocation weights sum < 1 | Valid — cash is the implicit remainder; drift math (FIX-762) treats the unstated remainder as cash target. |
| `minCashPct` set | Advisory: surfaced in `<portfolioMandate>`; the single-ticker PM cannot mechanically enforce a portfolio cash floor, so it narrates. Enforcement is a rebalancing concern (FIX-762/out of scope). |
| Rating under any mandate | Unchanged — the mandate never touches `finalRating` (FIX-715/FIX-752 orthogonality). |

**Error taxonomy:** all mandate paths are deterministic, idempotent commit-time projections — none retryable or fatal. The only external failure surface is a malformed persisted record, handled by null-degradation at seed.

## 7. Testing Strategy

**Goal & goal check (required).** *Goal:* a user's standing portfolio policy visibly steers the desk's position sizing — set a policy and the recommended size respects it. *Goal check:* a real-model, out-of-CI run under `goals/trading-desk-mandate/policy-steers-sizing/` reading only fields the RunSummary echo carries (`mandatePresent`, `policyVerdict`, `positionCapClamped`, `targetWeightPct`). Two runs, both `fsdev run analysis analyze … → runSummary`:
- **Cap run** — seed a mandate with `maxPositionWeightPct = 0.03` on a name whose unconstrained target would exceed it; **PASS** when `mandatePresent === true && policyVerdict === "capped" && positionCapClamped === true && targetWeightPct ≤ 0.03`. This is fully machine-readable from the echo (no `currentWeightPct` needed).
- **Exclusion run** — seed `exclusions: ["NVDA"]` and analyze `NVDA`; **PASS** when `policyVerdict === "excluded"`.
A third run with no mandate asserts `policyVerdict === "no-mandate"` and no clamp, so the check distinguishes "gate fired" from "gate always fires." This mirrors the FIX-752 RunSummary-mandate-gate goal check; the echo fields added in step 7 are its read path.

**Discipline:** `fsd:tdd` (Feature → red-green-refactor, tracer bullets). Offline CI suite; generators mocked. Mirror `test/phase-5-writer.spec.ts` / `test/portfolio-fit-commit.spec.ts` (commit projections), `test/seed-portfolio-snapshot.spec.ts` (seed freeze), `test/risk-mandate.spec.ts` (config/resolution). Use `fsd:write-block-tests` for the mock-context idiom.

Behaviours to test (each a tracer-bullet cycle):

- `validatePortfolioMandate`: valid mandate passes; over-100% allocation, duplicate bucket, min>max, band width 0 / >1 each report a specific issue.
- `savePortfolioMandate` / `clearPortfolioMandate`: round-trip; invalid rejects with issues; `createdAt` preserved on edit; clear → null.
- **Seed resolution:** the full appetite precedence (run → account → IPS → null); `state.portfolioMandate` frozen; a stale/invalid persisted mandate → mandate-blind.
- **PM commit — position cap:** target above cap clamps to cap (`positionCapClamped: true`, `policyVerdict: "capped"`); target below cap untouched.
- **PM commit — exclusion:** analyzed ticker excluded → target ≤ current (`excluded: true`, `policyVerdict: "excluded"`); non-excluded untouched.
- **PM commit — advisory:** `minCashPct` / allocation drift never clamp size; surfaced only.
- **PM commit — orthogonality:** the mandate never alters `finalRating`; interaction with the FIX-752 mandate clamp composes (both downward-only, tighter wins).
- `policyFit` round-trip: narrative passes through; the verdict + flags are derived, not trusted.
- **Strict-output:** `portfolioDecisionOutputSchema` (incl. nested `policyFit`) passes `assertStrictCompatible`.

## 8. Non-Goals

- **Drift measurement / the health view (FIX-762).** This spec *defines* the target allocation + bands (the policy); computing actual-vs-target drift and band-breach flags is FIX-762, which reads this object. Not built here.
- **The review loop (FIX-763).** Temporal violation flagging over time is FIX-763; it consumes this mandate. Not built here.
- **Multi-strategy sleeves (FIX-771).** v1 is a single flat household mandate. Per-sleeve mandates, capital caps, and sleeve↔account routing are FIX-771. The schema leaves a clean seam (a future container wraps this object) but builds no container.
- **Configurable factor/lens weighting (FIX-776).** No `weightingProfile` field is added here. By this spec's own reasoning (a nullable field is cheap to add later — the argument used to defer custom buckets), reserving it now would be the speculative surface BP-038 warns against. FIX-776 adds the field to `portfolioMandateSchema` when it builds the mechanism; the schema is a plain object, so that is a one-line additive change with no reshape.
- **Custom / sector-level target buckets.** v1 targets the existing `assetClass` enum only. Custom buckets ("AI infra") and sector caps need a classification layer — additive follow-up.
- **Rebalancing execution.** The desk analyzes one ticker at a time and never produces a sell-to-rebalance plan; `minCashPct` and allocation drift are advisory context, not enforced.
- **Per-account (rather than household) target allocation.** Asset-location says allocation is a household target (bonds in the IRA, stocks in taxable, one household target); per-account appetite exceptions are retained (via `account.riskMandate`), but target allocation is household-level in v1.
- **Deepening opportunities flagged during analysis (follow-ups, not this spec):**
  - The PM commit (`writer.ts`) is now a ~230-line handler doing six deterministic jobs (valuation clamp, portfolio-fit echoes, FIX-752 mandate gate, and now the policy gate). Flag: extract the commit's deterministic projections into testable `lib/` pure functions — handle via `fsd:improve-codebase-architecture`.
  - `formatRiskMandate` / `formatPortfolioMandate` / `formatStandingThesis` / `formatPortfolioContext` are four frozen-state context formatters with the same suppress-to-null shape; a shared factory is a candidate consolidation.
