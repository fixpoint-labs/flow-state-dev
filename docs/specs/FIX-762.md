# FIX-762: Trading-desk household portfolio-health view — aggregate exposure, concentration, and drift — Implementation Spec

> Linear: [FIX-762](https://linear.app/fixpoint-labs/issue/FIX-762/trading-desk-no-household-level-view-aggregate-exposure-concentration)

## 1. TLDR

Today the trading desk shows your holdings one account at a time — the same stock held in three accounts looks like three unrelated rows, and nothing answers "how balanced is my portfolio as a whole?". We're adding a Health view to the portfolio page that does that math across every account: what you actually own in total, how it splits by asset class and sector, whether too much is riding on one name, how much cash you're holding, and — once you've written down a target mix — how far you've drifted from it. All of it is plain arithmetic over data the desk already has; no AI involved. The same numbers also get handed to the desk's analysts so their advice is grounded in your real book.

**Technical statement:** Add a pure, browser-safe household-aggregation leaf (`portfolio-health.ts`) that ticker-merges holdings across accounts and computes weights, asset-class/sector exposure, concentration metrics + flags, cash level, coverage, and mandate drift/compliance; back its sector axis with a new durable `app.instrument_classifications` table filled lazily from the existing Yahoo sector resolver; render it as the third portfolio-pane perspective FIX-885 reserved; and inject a compact aggregate block into the trader/PM `<portfolioContext>`.

**Deliverables:**

- **Math:** Add `src/flows/portfolio/portfolio-health.ts` — `summarizePortfolioHealth(...)` + `computeAllocationDrift(...)` pure leaf, with `test/portfolio-health.spec.ts`
- **Classification:** Add `app.instrument_classifications` table (migration + `schema.ts`), repository reads/writes, `GET /api/portfolio/classifications` route filling misses via the existing `resolveSector`, and a `use-classifications.ts` hook
- **UI:** Append `health` to `PortfolioSection`/`SECTIONS` in `components/portfolio/portfolio-section-nav.tsx`; add `components/portfolio/health-section.tsx`; branch in `portfolio-pane.tsx`
- **Analysis:** Extend `portfolioContextInput` with a nullable `health` summary, populate the dead `holdings[].sector` field, compute at `seedSession`, render a compact block in `formatPortfolioContext`
- **Docs:** `labs/trading-desk/README.md` "Portfolio view" bullet, replace the FIX-762 placeholder in `labs/trading-desk/CLAUDE.md`, file headers (BP-034), empty-front-matter changeset, `goals/trading-desk-portfolio/household-health/` goal

**Size estimate:** Large — single package (`labs/trading-desk`), one PR, ~600–900 LOC including tests. The drift/compliance slice (§5 step 5) is gated on FIX-761 PR 1; if that hasn't merged at implementation time, ship it as a small follow-up PR rather than holding the rest.

## 2. Overview

Issue: [FIX-762](https://linear.app/fixpoint-labs/issue/FIX-762/trading-desk-no-household-level-view-aggregate-exposure-concentration).

The unit of analysis today is one ticker, and the portfolio pane is per-account: `allocationByClass` on the toolbar is the only household rollup, there is no ticker-merged exposure, no sector axis, no concentration measurement, and no drift — the only "concentration" signal is the PM's per-decision narrative string. This spec adds the deterministic household layer: one pure aggregation leaf consumed identically by a new Health perspective (the slot FIX-885 built) and by the analysis seed (superseding FIX-728's raw-list-only context), plus the one missing data source (per-ticker sector classification, cached durably).

## 3. Background & Research

### Codebase findings

- **The plug-in point exists and is documented.** `portfolio-section-nav.tsx:10-11` (header): *"FIX-762's household health view lands by appending one `SECTIONS` entry and one union member."* The pane branches on `section` with totals/toolbar pinned above all perspectives (`portfolio-pane.tsx`).
- **The valuation rule is already centralized — don't fork it.** `value-holding.ts` (`holdingMarketValue`, per-type: quote / par / statement) is the single copy of "what is this holding worth", used by the pane rollups (`portfolio-pane.tsx:276-343`) and `build-portfolio-context.ts`. Both also skip `dataQuality === "inconsistent_history"` rows from money math. Any household NAV computed anywhere else (e.g. SQL) would be a second copy of this rule (BP-034/028).
- **The repository reserved this seam** — `repository.ts:76-80`: *"the cross-account aggregate queries (household rollups, concentration, per-sleeve cash) are added by the consuming issues (FIX-762/771/763)."* This spec deliberately does **not** take the SQL route (Key Decision 1); the seam stays available for FIX-771/763.
- **Sector does not come from Finnhub** (correcting the issue's premise). `finnhub.ts:199` returns `sector: null` — Finnhub profile2 only carries `finnhubIndustry`. Sector comes from **Yahoo**: `src/flows/analysis/lib/sector-resolution.ts` `resolveSector(ticker, date)` → `{sector, industry, sectorEtf}`, cache-deduped via `getOrFetch`, returning Yahoo's 11-sector taxonomy — the same strings `GICS_TO_ETF` already keys on. No new provider and no mapping table needed.
- **Asset class needs no new source.** Since FIX-773, every holding carries `assetClass` (`equity/fixed_income/cash/crypto/alternative`) and `assetType` (`equity/etf/mutual_fund/bond/money_market/crypto/option/other`); the toolbar's `allocationByClass` (`portfolio-format.ts`) already buckets by it. Only the sector axis is missing data.
- **The analysis context has a dead field waiting.** `flow-schema.ts` `portfolioContextInput.holdings[].sector` has been an "honest null" since Slice 4 (`build-portfolio-context.ts:110`). This spec provides its first producer.
- **Quotes are an input, not a dependency.** The health math takes a `ticker → quote` map. Today that's the `portfolioQuotesResource` snapshot (client: `useResource`; seed: cross-flow read); when FIX-823's `app.quotes` lands, the map's source changes but the leaf doesn't.

### Industry research

- **Concentration:** single-position rules of thumb converge on warn ≥ 10% / act ≥ 20–25% ([J.P. Morgan](https://privatebank.jpmorgan.com/nam/en/insights/wealth-planning/worried-you-may-own-too-much-of-one-stock), [T. Rowe Price](https://www.troweprice.com/personal-investing/resources/insights/actions-can-take-if-your-portfolio-is-too-concentrated-in-one-equity.html)); sector rule of thumb ~25–30% max. Top-5/top-10 weight is the universal factsheet convention. Effective number of positions = 1/HHI = 1/Σwᵢ² ("22 positions but effectively 6") is standard portfolio analytics and costs one line ([Breaking Down Finance](https://breakingdownfinance.com/finance-topics/finance-basics/effective-number-of-stocks/), [Bridgeway](https://bridgeway.com/perspectives/how-many-stocks-are-effectively-in-the-sp500/)); raw HHI means nothing to users, so we surface effective-N only, display-only.
- **Drift:** two coexisting conventions — per-class band breach (banded rebalancing, e.g. Swedroe's 5/25 rule: [A Wealth of Common Sense](https://awealthofcommonsense.com/2014/03/larry-swedroe-525-rebalancing-rule/), [Bogleheads](https://www.bogleheads.org/wiki/Rebalancing)) and a portfolio-level scalar, Betterment's total drift = Σ|actual − target| / 2 ([Betterment](https://www.betterment.com/help/portfolio-rebalancing)). We report both — but band *configuration* comes verbatim from the FIX-761 mandate (`bandType` relative/absolute + `bandWidthPct` + per-target `minPct`/`maxPct`), not from a second band vocabulary (Key Decision 4). The mandate's relative default (±20% of target) is the same family as the 5/25 rule's relative arm.
- **Classification handling without look-through** (the Ghostfolio / Portfolio Performance convention): classify by asset class first; sector applies only to single-name equities; funds/crypto/bonds/cash appear as their own buckets. Classification data is near-immutable → persist per-ticker with no TTL and refresh manually, don't re-fetch per view ([Ghostfolio market-data model](https://deepwiki.com/ghostfolio/ghostfolio/7.1-market-data-management), [Portfolio Performance taxonomies](https://help.portfolio-performance.info/en/reference/view/taxonomies/)).
- **Weight denominators:** allocation views are % of total NAV including cash (cash is an asset class; weights sum to 100); exposure/concentration views are % of invested (ex-cash) NAV, otherwise a 20%-cash book looks artificially diversified ([PortfoliosLab](https://portfolioslab.com/docs/portfolio-fundamentals/asset-allocation-basics)). Unpriced holdings: exclude from denominators and surface a coverage indicator, never mix valuation bases.

### Why this approach

The candidate solution in the issue ("aggregation layer computing from holdings + live quotes, per-ticker classification cached, Health view renders it") survives research intact, with three refinements: (1) the math is one pure TS leaf shared by UI and seed rather than SQL or per-surface copies, because the per-type valuation rule already lives in TS; (2) the classification source is Yahoo via the existing `resolveSector`, not Finnhub (whose profile carries no sector); (3) the cache is a durable global `app.*` table, not a user resource, because a ticker's sector is a public per-ticker fact — exactly the reasoning FIX-823's spec applies to quotes.

### Key Decisions & Ramifications (top 5)

1. **Aggregation is a pure browser-safe TS leaf (`portfolio-health.ts`) reusing `value-holding.ts`; no SQL aggregate queries in v1.** *Rejected:* repository `GROUP BY ticker` over `holdings ⋈ app.quotes`. *Ramification:* one copy of the valuation + `inconsistent_history` rules (BP-034); works today without FIX-823 (the leaf takes a quote map from any source), removing FIX-823 as a hard prerequisite. Locks household math to "load the household, compute in JS" — fine at household scale (tens–hundreds of rows), and the repository's reserved aggregate-query seam stays available for FIX-771/763 if scale ever demands SQL.
2. **Sector classification lives in a new durable, global `app.instrument_classifications` table (ticker PK, no TTL), filled lazily through the existing Yahoo `resolveSector`; failures are returned as null but not persisted.** *Rejected:* a user-scoped resource (session-coupled, wrong scope — a ticker's sector is not per-user, and not joinable later); ephemeral per-view fetching (burns provider quota on near-immutable data). *Ramification:* the lab gets its first per-ticker reference table — a minimal security-master seam FIX-801 (ETF profiles) and FIX-823 (quotes) can sit beside; global scope means classification is shared across households (acceptable: public facts). Manual refresh/override is deferred (Non-Goals).
3. **Health is computed client-side in the pane (leaf in `useMemo`), like every other money figure; there is no `/api/portfolio/health` endpoint.** *Rejected:* a composite GET route (the `tax/route.ts` precedent). *Ramification:* zero new read plumbing for the UI, and degradation is identical to the existing totals (no quotes → "—" + counts-only). The analysis seed computes server-side with the same leaf. If a headless consumer (e.g. the FIX-768 MCP surface) later needs health over HTTP, a thin route can wrap the leaf then — the leaf is the contract, not the transport.
4. **Drift and compliance semantics come verbatim from the FIX-761 mandate; health reports, never enforces.** Band per class = `bandType`-dependent (`relative`: `bandWidthPct` × target, where `bandWidthPct` is a fraction; `absolute`: `bandWidthPct` percentage points), overridden by per-target `minPct`/`maxPct` when set; empty `targetAllocation` = no allocation policy (skip drift, constraints still checked); implicit cash target = 100 − Σ non-cash targets. *Rejected:* the research's 5/25 hybrid rule and a separate rebalance threshold — either would fork the mandate's band vocabulary into a second policy language. *Ramification:* one policy concept (the FIX-761 goal); drift quality is bounded by mandate quality; `rebalanceSuggested` = any band breach, with Betterment-style total drift (Σ|Δ|/2) reported as the headline scalar but not a trigger.
5. **Fund positions (`assetType` etf/mutual_fund) are exempt from single-name concentration flags and appear as their own bucket ("Funds — no look-through") in the sector view.** *Rejected:* flagging a 30% SPY position like a 30% NVDA position (false alarm that erodes trust); inline look-through (heavy; owned by FIX-801). *Ramification:* an all-ETF book shows low single-name concentration by construction — so the payload carries an explicit `lookThrough: "none"` marker and the UI and context formatter surface the caveat. FIX-801 refines this without reshaping the payload.

## 4. Technical Design

All paths under `labs/trading-desk/` unless noted.

### 4.1 New: `src/flows/portfolio/portfolio-health.ts` (pure leaf)

Browser-safe, imports only types + `value-holding.ts` + `portfolio-format.ts` helpers. Two exported functions and their types (schemas as plain zod in the domain regime — **not** strict generator schemas; must not be added to `output-schemas-strict.spec.ts`).

```ts
import type { AccountState, Holding } from "./portfolio-schema";

/** Quote map as the pane and seed already hold it: UPPER ticker → { price, asOf }. */
export type QuoteMap = Map<string, { price: number | null; asOf: string | null }>;
/** UPPER ticker → Yahoo sector string, or null when unresolved. */
export type ClassificationMap = Map<string, string | null>;

export type HealthPosition = {
  ticker: string;                    // canonical UPPER
  assetClass: AssetClass;
  assetType: AssetType;
  quantity: number;                  // summed across accounts (excluded rows not summed)
  marketValue: number | null;        // Σ holdingMarketValue over included rows; null if none priceable
  allocationWeightPct: number | null; // % of totalNav
  exposureWeightPct: number | null;   // % of investedNav (null for cash-class positions)
  sector: string | null;             // equities only; null otherwise
  accounts: Array<{ accountId: string; label: string; quantity: number; marketValue: number | null }>;
  excludedRows: number;              // inconsistent_history rows skipped (⚠ semantics)
};

export type HealthFlag =
  | { kind: "single_name"; level: "warn" | "alert"; ticker: string; weightPct: number }
  | { kind: "sector"; level: "warn"; sector: string; weightPct: number };

export type PortfolioHealth = {
  asOf: string | null;               // pass-through quote snapshot as-of
  lookThrough: "none";               // explicit v1 caveat (Key Decision 5)
  totalNav: number | null;           // Σ priced MV + Σ account cash; null when nothing priceable and no cash
  investedNav: number | null;        // totalNav − cash bucket
  cash: { amount: number; pct: number | null };   // account cashBalance + cash-class holdings MV
  coverage: {
    pricedPositions: number;
    totalPositions: number;          // ticker-merged count, including unpriced + excluded-only
    unpricedTickers: string[];
    excludedTickers: string[];       // positions whose every row is inconsistent_history
  };
  positions: HealthPosition[];       // sorted by |exposureWeightPct| desc, unpriced last
  assetClassAllocation: Array<{ assetClass: AssetClass; marketValue: number; pct: number | null }>; // of totalNav
  sectorExposure: Array<{ bucket: string; marketValue: number; pct: number | null }>;               // of investedNav
  concentration: {
    maxPosition: { ticker: string; weightPct: number } | null;  // single-name eligible only
    top5Pct: number | null;
    top10Pct: number | null;
    effectivePositions: number | null;  // 1 / Σ(exposureWeight²), priced non-cash positions
    flags: HealthFlag[];
  };
};

export function summarizePortfolioHealth(
  accounts: AccountState[],          // holdings inline, the `toAccountStates` shape
  quotes: QuoteMap,
  classifications: ClassificationMap,
  asOf: string | null,
): PortfolioHealth;
```

**Rules (each pinned by a spec test):**

- **Inclusion gate:** rows with `dataQuality === "inconsistent_history"` are skipped from all money math (the exact gate the pane rollups and `buildPortfolioContext` apply); they are counted in `excludedRows`/`excludedTickers` so the view can show the ⚠ semantics rather than silently shrinking the book.
- **Valuation:** every market value via `holdingMarketValue(h, quote)` — never a local `quantity × price`. Unpriced rows contribute nothing to any numerator or denominator; coverage reports them.
- **NAV:** `totalNav = Σ included-row MV + Σ account.cashBalance` (matches the pane's `totalValue` memo — a reconciliation test pins this). Cash bucket = Σ `cashBalance` + MV of `assetClass === "cash"` holdings (MMF at par). `investedNav = totalNav − cash`.
- **Ticker merge:** group by `ticker.toUpperCase()` across accounts; per-account sub-rows preserved for the drill-down.
- **Denominators:** `allocationWeightPct` and `assetClassAllocation` are over `totalNav` (cash is a class; sums to ~100 given full coverage). `exposureWeightPct`, `sectorExposure`, and all concentration metrics are over `investedNav`. Guard every division: denominator ≤ 0 → null, never NaN/Infinity.
- **Sector buckets** (deterministic off `assetType`): `equity` → its classification sector, or `"Unclassified"` when null; `etf`/`mutual_fund` → `"Funds (no look-through)"`; `crypto` → `"Crypto"`; `bond` → `"Fixed income"`; `option`/`other` → `"Other"`; `money_market` sits in the cash bucket, not the sector view.
- **Concentration eligibility:** single-name metrics (`maxPosition`, single-name flags) consider only `assetType ∈ {equity, crypto}` positions. `top5Pct`/`top10Pct`/`effectivePositions` are over all priced non-cash positions (funds included — top-N is a "biggest lines" read, not a single-name read). Fewer than N positions → topN = sum of what exists.
- **Flag thresholds** (exported constants; configurability deferred): single-name warn > 10, alert > 25; sector warn > 30 (`"Unclassified"` and `"Funds (no look-through)"` buckets never flag — a data gap and a known caveat are not concentration findings).
- **Negative quantities** (shorts aren't producible by today's import paths, but don't divide-by-surprise): signed values flow into allocation math; concentration uses |weight|; a test pins no-NaN behavior.

```ts
export type DriftEntry = {
  assetClass: AssetClass;
  actualPct: number;                 // of totalNav
  targetPct: number;                 // explicit, or the implicit cash remainder
  implicit: boolean;                 // true only for the derived cash entry
  driftPp: number;                   // actual − target, signed percentage points
  bandLowPct: number;                // resolved band edges (min/max overrides applied)
  bandHighPct: number;
  breach: "low" | "high" | null;
};

export type MandateComplianceFinding =
  | { kind: "max_position"; ticker: string; weightPct: number; limitPct: number }
  | { kind: "min_cash"; cashPct: number; minPct: number }
  | { kind: "excluded_holding"; ticker: string };

export type DriftReport = {
  entries: DriftEntry[];
  totalDriftPct: number;             // Σ|driftPp| / 2 (Betterment convention)
  rebalanceSuggested: boolean;       // any band breach
  compliance: MandateComplianceFinding[];
};

/** Null when mandate is absent. `entries`/`totalDrift` empty/0 and no breach when
 *  `targetAllocation` is empty (no allocation policy ≠ 100% cash target) — the
 *  FIX-761 semantics; compliance findings still computed from `constraints`. */
export function computeAllocationDrift(
  health: PortfolioHealth,
  mandate: PortfolioMandate | null,
): DriftReport | null;
```

- **Band resolution** (Key Decision 4): `band = bandType === "relative" ? bandWidthPct * targetPct : bandWidthPct` (relative `bandWidthPct` is a fraction, e.g. 0.2; absolute is percentage points — the FIX-761 units). Edges = `[minPct ?? targetPct − band, maxPct ?? targetPct + band]`, clamped to [0, 100].
- **Implicit cash:** when no explicit `cash` target exists and `targetAllocation` is non-empty, append an implicit entry with `targetPct = 100 − Σ` (floored at 0), banded like any other class.
- **Presence:** the caller detects mandate presence per FIX-761 (`createdAt != null` on the resource state, since a cleared single-resource normalizes to `{}`), and passes `null` when absent.
- **Coverage honesty:** drift compares priced allocation to targets; when coverage < 100%, the UI and context formatter must show the coverage line next to any breach claim (the math itself doesn't gate — a mostly-priced book still gives a useful read).
- **Compliance findings** are advisory reporting of the FIX-761 standing constraints against the *current* book: max single-name weight vs `constraints.maxPositionWeightPct` (single-name-eligible positions only, consistent with Decision 5), cash % vs `minCashPct`, and any held ticker in `exclusions` (FIX-761 blocks *adding* excluded names; already-held ones are exactly what the health surface should expose). Enforcement stays FIX-761's.

### 4.2 New: instrument classification storage + fill path

**`src/db/schema.ts`** — add to `appSchema`:

```ts
export const instrumentClassifications = appSchema.table("instrument_classifications", {
  ticker: text("ticker").primaryKey(),               // canonical UPPER
  sector: text("sector"),                            // Yahoo sector string; null never persisted (see route)
  source: text("source").notNull(),                  // "yahoo"
  fetchedAt: timestamp("fetched_at", { withTimezone: true }).notNull().defaultNow(),
});
```

Migration `src/db/migrations/000X_instrument_classifications.sql` (next number at implementation time), following the existing migration style. No `user_id` — a ticker's sector is a global fact (Key Decision 2; the same scoping FIX-823 chose for `app.quotes`). `industry` is deliberately not stored: no consumer (BP-038).

**`src/db/repository.ts`** — two methods + row type, mirroring the existing shapes (numeric coercion N/A here; `safeParse` not needed for plain text):

```ts
export type InstrumentClassificationRow = { ticker: string; sector: string | null; source: string; fetchedAt: string };
getInstrumentClassifications(tickers: string[]): Promise<InstrumentClassificationRow[]>;
upsertInstrumentClassifications(rows: Array<{ ticker: string; sector: string; source: string }>): Promise<void>;  // onConflictDoUpdate on ticker
```

These are plain keyed reads/writes, not household-scoped — document in the interface comment that this table is global reference data, an exception to the `userId` guard that every *portfolio* method keeps.

**New route `app/api/portfolio/classifications/route.ts`** — `GET ?tickers=A,B,C` (`dynamic = "force-dynamic"`; 400 on missing/empty param; cap the list at the union-of-held-tickers scale, reject > 200):

1. Normalize + de-dupe tickers to UPPER; read the table.
2. For misses, resolve via the existing `resolveSector(ticker, today)` from `src/flows/analysis/lib/sector-resolution.ts` with bounded concurrency (`mapLimit`, 4 — the `getQuotes` idiom; `getOrFetch` inside `resolveSector` already de-dupes in-process, so a burst of requests won't hammer Yahoo).
3. Persist only successful resolutions (`sector !== null`); a failed resolution returns `{ ticker, sector: null }` in the response but is **not** persisted, so a transient provider outage doesn't permanently blank a ticker (retried on a later request, in-process-deduped meanwhile).
4. Respond `{ classifications: Array<{ ticker, sector: string | null }> }`.

A GET that lazily fills a cache table deviates from "routes only read" — the write is an idempotent cache fill of global reference data, the same spirit as `getOrFetch`; the route header documents this deliberately. Cross-flow import note: the portfolio surface importing `resolveSector` from `analysis/lib` follows the established direction (`get-quotes.ts` already builds on the analysis tool runtime); do not copy the function (BP-028).

**New hook `components/portfolio/use-classifications.ts`** — thin `lib/use-api-query` wrapper keyed on the sorted ticker list; mounted by the Health section only (§4.3), so opening Accounts/Gains never triggers a Yahoo fan-out.

Layout, top to bottom, container-query responsive (`@container` grid like the account cards; inline CSS bars, no chart lib):

1. **Allocation vs target** — one bar per asset class (actual % of totalNav), with target marker + band shading + breach badge per `DriftReport` when a mandate exists; actual-only bars plus a one-line "Set a mandate to see drift" hint otherwise. Headline: total drift % + "rebalance suggested" chip when breached.
2. **Concentration** — stat row (max single name, top-5, top-10, effective positions) with flag chips; ticker-merged top-positions table (ticker, class, exposure weight, # accounts, per-account split on expand), `"Funds (no look-through)"` caveat line when fund positions exist.
3. **Sector exposure** — bars over investedNav including the `Unclassified` bucket; caption for the funds bucket.
4. **Cash & compliance** — cash $ + % card; mandate-compliance findings when a mandate exists (max-position / min-cash / excluded-holding), each rendered as an advisory line, not an error.
5. **Coverage & provenance** — "priced X of Y positions" + excluded-⚠ count + quotes as-of (the pane's existing staleness vocabulary).

Degradation: no session or no quotes → weights/NAV render "—" (the pane-wide gate), the section shows position/class *counts* and an inline prompt wired to `onRefreshPrices`; no accounts → the existing empty-state idiom. Missing figures are `DASH`, never fabricated (BP-020).

## 6. Edge Cases & Error Handling

| Case | Expected behavior |
|---|---|
| Same ticker in N accounts | One merged position (quantity/MV summed over included rows), N per-account sub-rows; N reflected in "# accounts" |
| Same ticker, one row `inconsistent_history` | That row skipped from money math, counted in `excludedRows`; the other rows aggregate normally; ⚠ shown |
| Every row of a ticker excluded | Position appears in `excludedTickers` / coverage, not in weights |
| Unpriced holding (no quote, no mark) | Out of every numerator and denominator; listed in `unpricedTickers`; coverage line shows "priced X of Y" |
| Cash-only portfolio | `investedNav` = 0 → exposure/sector/concentration all null/empty, no NaN; allocation shows 100% cash |
| No accounts | Existing empty-state idiom; no fetches fired |
| No quotes / no session | NAV/weights "—", counts-only view + refresh-prices prompt (matches pane totals behavior) |
| Mandate absent | `computeAllocationDrift` → null; actual-only bars + hint; no compliance card |
| Mandate `targetAllocation: []` | No drift entries, no breach, totalDrift 0 (no policy ≠ 100%-cash target); constraints still checked |
| Mandate without explicit `cash` target | Implicit cash entry, target = 100 − Σ non-cash, `implicit: true`, banded normally |
| `bandType: "relative"` vs `"absolute"` | Fraction-of-target vs percentage-points band; per-target `minPct`/`maxPct` override the derived edges |
| Held ticker in mandate `exclusions` | `excluded_holding` compliance finding (report, don't enforce) |
| ETF at 35% of book | No single-name flag (fund-exempt); appears in top-N and the funds bucket with the no-look-through caveat |
| Bond ETF (class `fixed_income`, type `etf`) | Funds bucket in sector view; `fixed_income` in allocation view (class comes from the holding, unchanged) |
| Equity with unresolved sector | `Unclassified` bucket (visible, never dropped, never flagged); not persisted, retried on a later view |
| Yahoo outage during fill | Route returns nulls for misses, persists nothing, 200 with partial data; UI shows Unclassified |
| > 200 tickers requested | 400 (sanity cap; the union of held tickers is far below this) |
| Negative quantity (short, not currently producible) | Signed in allocation; \|weight\| in concentration; pinned no-NaN test |
| Coverage < 100% with a mandate breach | Breach shown alongside the coverage line — never a confident claim over an unpriced book |

Retryable vs fatal: only the classification fill has retry semantics (transient provider failure → retry on next request; in-process de-dupe prevents hammering). Everything else is pure math or standard route error handling.

## 7. Testing Strategy

**Goal:** a user with holdings spread across multiple accounts opens Portfolio → Health and sees their true household picture — merged exposures, asset-class and sector splits, concentration reads with honest caveats, cash level, and (with a mandate) drift and band breaches — computed deterministically from stored quantities and sourced prices; and the desk's trader/PM see the same aggregates in their context.

**Goal check:** the context-injection outcome has a real path — the `fsd:verify-trading-desk` approach: seed a multi-account fixture portfolio (+ mandate once FIX-761 lands), run `fsdev run` analysis `analyze` (fixture mode) then the zero-model `runSummary` read, and assert from the capture that `<portfolioContext>` contains the health block (allocation lines, concentration line, drift/no-mandate line). PASS = block present with figures matching the leaf's output for the fixture; FAIL = block absent, fabricated figures, or drift claimed with no mandate. The UI outcome is a browser pass with seeded data (desktop + phone widths, screenshots as evidence — the FIX-885 precedent; the vitest config is node-env, no jsdom, and none should be added). The deterministic math itself is CI-covered; `goals/trading-desk-portfolio/household-health/run.mts` re-drives those specs as the goal harness entry (the `multi-asset-import` pattern).

**Discipline:** `fsd:tdd` (Feature). Tracer-bullet behaviors, observable terms:

1. Two accounts holding the same ticker produce one Health position whose value/weight equals the sum, with both accounts listed.
2. Allocation weights (incl. cash) sum to ~100% of totalNav at full coverage; exposure weights exclude cash and re-normalize.
3. An `inconsistent_history` row changes no total but increments the excluded count (reconciles with the pane's totals memo on the same fixture).
4. A 12% single-name equity yields a warn flag; a 12% ETF yields none; `Unclassified`/funds buckets never flag.
5. Effective positions = 1/Σw² on a hand-computed fixture; top-5 = sum of the five largest exposure weights.
6. Drift: relative and absolute band types, min/max overrides, implicit cash remainder, empty-targets no-op, absent-mandate null — each against hand-computed expectations.
7. A held excluded ticker produces an `excluded_holding` finding; cash below `minCashPct` produces `min_cash`.
8. Classification repository round-trips and upserts on conflict (PGlite); the route persists successes only.
9. `buildPortfolioContext` with classifications populates `holdings[].sector` and the health block; the formatter renders it and still suppresses on absent portfolio.

Existing suites must stay green — reference patterns: `test/tax-estimate.spec.ts` (pure-math fixtures), `test/portfolio-repository.spec.ts` (PGlite), `test/build-portfolio-context.spec.ts`, `test/format-memos.spec.ts` (formatter).
