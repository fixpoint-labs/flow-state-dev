# FIX-781: Mandate gate can clear on thin/no evidence — Implementation Spec

## 1. TLDR

Today the desk can say a trade is “worth it” and clear a position to add capital
even when the numbers behind that call rest on thin or missing evidence. Missing
data has also been narrated as if it were a directional signal. This change makes
evidence sufficiency a hard stop on *new capital*: the rating can still summarize
what was observed, but thin evidence cannot clear the mandate, cannot initiate or
add, and cannot increase exposure.

**Technical statement:** Extend the FIX-752 mandate gate (`computeMandateGates` /
`clampTargetWeight`) to consume valuation-spine and reward-to-risk evidence layers,
emit a distinct non-overridable `insufficient-evidence` verdict with FIX-761-style
no-add sizing + action downgrade, and thread that verdict through memo, snapshot,
RunSummary, eval invariants, mandate UI, and the PM prompt.

**Deliverables:**

- Extend `computeMandateGates` / `clampTargetWeight` in `labs/trading-desk/flows/analysis/lib/mandate-gates.ts` to consume spine + R/R evidence and apply no-add sizing
- Widen mandate verdict enums to `"clears" | "fails" | "insufficient-evidence"` across memo / snapshot / RunSummary schemas
- Wire evidence inputs + action downgrade in `agents/portfolio-manager/writer.ts`
- Update PM prompt: missing/`unavailable` is non-evidence, not directional support
- Surface `insufficient-evidence` in MandatePanel / mandate-helpers (PolicyPanel multi-verdict idiom)
- Extend FIX-790 `mandate/*` invariants for evidence gate + no-add size/action rules
- Add BHYP-shaped and SPCX-shaped vitest fixtures pinning thin cannot clear/initiate
- Extend lab docs (`CLAUDE.md` FIX-752, `docs/run-quality-eval.md`, README) + one walkthrough paragraph

**Size:** Medium (multi-file / 1 PR / ~200–400 LOC in `labs/trading-desk`, docs-only outside the lab).

## 2. Overview

- **Linear:** [FIX-781](https://linear.app/fixpoint-labs/issue/FIX-781/trading-desk-mandate-gate-can-clear-on-thinno-evidence-reward-to-risk)
- The FIX-752 mandate gate clears or fails from reward-to-risk, hurdle, and
  confidence alone. It ignores `evidenceBasis` on the reward-to-risk figure and
  the valuation spine. A narrative override can still lift the soft appetite bar
  into `clears`. Absolute `unclearedCapPct` can leave a no-portfolio initiate
  above 0%. BHYP-shaped (thin spine, scenario-only R/R) and SPCX-shaped (missing
  structured statements treated as bearish) runs expose this.
- This spec makes evidence sufficiency a **hard, non-overridable, no-add** capital
  gate beside capacity, while preserving soft appetite override and rating
  orthogonality.

## 3. Background & Research

### Industry

Selective / reject-option prediction: emit a directional signal, abstain from
capital when a selector fails
([arXiv:2110.14914](https://arxiv.org/abs/2110.14914),
[Geifman & El-Yaniv SelectiveNet](http://proceedings.mlr.press/v97/geifman19a/geifman19a.pdf)).
Grinold-style IC vs transfer coefficient separates forecast quality from capital
expression. Missingness literature treats missing indicators as masks, not
imputed directional fills
([arXiv:2211.09259](https://ar5iv.labs.arxiv.org/html/2211.09259)). Soft vs hard
portfolio constraints: hard defines the feasible set; soft is appetite.

### Codebase

- **FIX-752** (`mandate-gates.ts`, `reward-to-risk.ts`, PM writer): soft appetite
  (overridable) + hard capacity (non-overridable); `evidenceBasis` computed but
  advisory only (`formatRewardToRisk` “indicative”).
- **FIX-761** (`policy-gate.ts`): exclusion no-add = `min(target, householdWeight)`
  + initiate/add → hold — the sizing/action template to reuse.
- **FIX-790** (`eval/invariants.ts` `checkMandate`): recomputes the same leaf;
  must stay in lockstep.
- **FIX-715 / rating orthogonality:** thin spine widens the rating *band* upward
  only; never clamps `finalRating` for mandate reasons.
- **FIX-678-shaped PM discipline:** missing data lowers confidence, does not
  default rating/size; rule 11 currently documents soft override without an
  evidence hard line.

### Why this approach

Chosen: **hard evidence-sufficiency gate + missing≠direction**, framed as signal
vs actionability. Alternatives rejected:

| Alternative | Why not |
|---|---|
| Soft-scale thin (halve size) | Still authorizes new capital; override could restore size |
| Fail → existing `fails` + `unclearedCapPct` only | Absolute cap can still initiate (e.g. 0.5–1.5%); no distinct verdict |
| Wait for FIX-898 recovery | Parallel track; residual thin must still gate |

### Key Decisions & Ramifications (top 5)

1. **Decision:** Evidence insufficiency is a **third hard verdict**
   (`insufficient-evidence`), not folded into `fails`.
   **Rejected:** Reuse `fails` with a flag.
   **Ramification:** Schemas, UI, RunSummary, and eval must widen the enum;
   BP-030 dual-read for legacy `"clears"|"fails"` sessions. Distinct UX and
   invariant targeting.

2. **Decision:** Sufficiency fails closed if **either** reward-to-risk
   `evidenceBasis === "thin"` **or** valuation-spine `evidenceBasis === "thin"`
   (spine already folds `expectedReturn.lowConfidence`).
   **Rejected:** R/R-only, or requiring both thin.
   **Ramification:** BHYP (thin spine + scenario-only R/R) and SPCX-shaped thin
   fundamentals both gate. Spine must be passed into the pure leaf (structural
   subtype, no resource import).

3. **Decision:** Evidence insufficiency is **non-overridable** (capacity-class).
   Soft appetite override still lifts only soft rr/hurdle/confidence fails.
   **Rejected:** Allow override to clear thin evidence.
   **Ramification:** Override cannot manufacture evidence; narrative may explain
   thinness but cannot authorize adds.

4. **Decision:** Size effect is **FIX-761-style no-add** against
   `householdTickerWeightPct` only (0 if not held, `null` if held-but-unpriced),
   plus initiate/add → hold — **not** the absolute `unclearedCapPct`.
   **Rejected:** Reuse soft uncleared cap for thin; rejected scoped
   `currentWeightPct` fallback when household is null (null means unpriced —
   a scoped partial weight can understate and force-trim, BP-020).
   **Ramification:** No-portfolio 1.5% proposal becomes hold @ 0%. Soft
   `unclearedCapPct` is **skipped** while evidence is insufficient (so a held
   @ 2% thin name is capped at 2%, not force-trimmed to 0.5%). Ordinary soft
   fails (evidence ok) still use `unclearedCapPct`. Unpriced-held (`null`)
   skips numeric clamp; action still downgrades.

5. **Decision:** Rating / directional summary stays free; gate is capital-only.
   **Rejected:** Force Hold rating on thin evidence.
   **Ramification:** Observed bearish evidence can still yield Sell/Underweight
   while capital stays gated — matches acceptance and FIX-715 orthogonality.

## 4. Technical Design

### Architecture

All changes live in `labs/trading-desk` (analysis flow). No framework package
API change.

```
valuationSpineResource ─┐
rewardToRiskResource  ──┼─► computeMandateGates ─► verdict + flags
riskMandate (frozen)  ──┤         │
decisionConfidence    ──┤         ▼
override (soft only)  ──┘   clampTargetWeight (capacity → evidence no-add → soft)
                                  │
                         PM writer applies weight + action downgrade
                                  │
              memo mandateDecision / decisionSnapshot / RunSummary / UI / eval
```

### Sufficiency predicate

```ts
type EvidenceInputs = {
  /** Reward-to-risk figure evidenceBasis (required when gate runs). */
  rewardToRiskEvidenceBasis: "sufficient" | "thin";
  /**
   * Valuation-spine evidenceBasis. When the spine resource is absent/unusable,
   * treat as "thin" (fail closed) — a mandate-aware run without a spine cannot
   * underwrite new capital.
   */
  spineEvidenceBasis: "sufficient" | "thin";
};

function evidenceSufficient(e: EvidenceInputs): boolean {
  return (
    e.rewardToRiskEvidenceBasis === "sufficient" &&
    e.spineEvidenceBasis === "sufficient"
  );
}
```

Do **not** invent a third thin detector. Do **not** fold scenario-forecaster LLM
`evidenceBasis` into the gate in this issue (Non-Goals) — R/R already derives
thin from bucket shape; spine covers fundamentals/setup.

### API surface — `mandate-gates.ts`

```ts
export type RewardToRiskFigure = {
  noDownside: boolean;
  lossAdjustedGlr: number | null;
  expectedValuePct: number | null;
  worstCaseReturnPct: number | null;
  evidenceBasis: "sufficient" | "thin"; // NEW — required for gate
};

export type MandateGates = {
  rrCleared: boolean;
  hurdleCleared: boolean;
  confidenceCleared: boolean;
  cleared: boolean; // soft appetite only (unchanged meaning)
  capacityCleared: boolean;
  evidenceSufficient: boolean; // NEW
  /** Bright-line capital verdict. */
  verdict: "clears" | "fails" | "insufficient-evidence";
};

export function computeMandateGates(args: {
  mandate: RiskMandate;
  rr: RewardToRiskFigure;
  spineEvidenceBasis: "sufficient" | "thin";
  decisionConfidence: number;
  override: boolean; // soft appetite only
}): MandateGates {
  // soft gates unchanged...
  const evidenceSufficient =
    rr.evidenceBasis === "sufficient" &&
    args.spineEvidenceBasis === "sufficient";

  // Soft verdict ingredients (override may lift soft bar only when evidence ok
  // AND capacity ok — override never clears insufficient-evidence or capacity).
  let verdict: MandateGates["verdict"];
  if (!evidenceSufficient) {
    verdict = "insufficient-evidence";
  } else if (!capacityCleared) {
    verdict = "fails";
  } else if (cleared || override) {
    verdict = "clears";
  } else {
    verdict = "fails";
  }
  // ...
}

export function clampTargetWeight(args: {
  targetWeightPct: number;
  mandate: RiskMandate;
  gates: MandateGates;
  override: boolean;
  /** Known household weight in pct points; null = held-but-unpriced. */
  householdTickerWeightPct: number | null;
}): { targetWeightPct: number; sizeClamped: boolean } {
  // 1. Capacity veto — absolute capacityVetoCapPct (unchanged)
  // 2. Evidence no-add — if !evidenceSufficient:
  //      if householdTickerWeightPct != null: target = min(target, weight)
  //      if null: skip numeric clamp (no fabricate exit)
  // 3. Soft unclearedCapPct — only when evidenceSufficient && !cleared && !override
}
```

**Weight source at the writer (authoritative):** Pass
`ctx.session.state.householdTickerWeightPct` only — same field FIX-761
`computePolicyGate` uses.

| Value | Meaning | Clamp |
|---|---|---|
| `0` | Not held (or portfolio-blind / no priced mass) | no-add → target `0` |
| positive | Held + priced household weight | `min(target, weight)` |
| `null` | Held but unpriced | skip numeric clamp (never fabricate exit); still downgrade initiate/add → hold |

Do **not** fall back to scoped portfolio `currentWeightPct` when household is
`null`.

**Soft-cap interaction while thin:** Step 3 of `clampTargetWeight` (soft
`unclearedCapPct`) runs **only when `gates.evidenceSufficient`**. Thin + held @
2% with a soft-fail figure stays at ≤ 2% (no-add), not force-trimmed to
`unclearedCapPct` 0.5%. That is an intentional change from today's thin → soft
clamp path.

**`cleared` flag meaning:** Remains soft-appetite-only. Under
`insufficient-evidence`, `cleared` may still be `true` if rr/hurdle/confidence
numbers pass — the capital verdict is the evidence/capacity line, not `cleared`.

### Writer (`commitPortfolioManagerMemo`)

After computing gates + clamp:

1. Pass spine evidence: read `valuationSpine.state.evidenceBasis`; if spine
   unusable (`evidenceBasis` absent), pass `"thin"`.
2. Pass `householdTickerWeightPct` into `clampTargetWeight` as above.
3. **Action downgrade:** OR with the existing exclusion downgrade — when
   `!gates.evidenceSufficient` **or** `gate.excluded`, and action is
   `initiate` | `add` → `hold`. Leave `trim` | `exit` | `hold` intact.
4. Mirror `verdict: gates.verdict` onto `mandateDecision`; keep storing
   `evidenceBasis: rr.evidenceBasis` (R/R layer). Do not expand the memo schema
   with spine evidence unless the panel needs it — verdict is the capital
   signal. If `overrideReason` is non-empty under `insufficient-evidence`, still
   mirror it (honesty) but UI/copy must not imply it lifted the gate.

### Schema widen (BP-030)

| Location | Change |
|---|---|
| `flows/analysis/resources.ts` `mandateDecisionSchema.verdict` | add `insufficient-evidence` |
| `flows/analysis/decision-snapshot-resource.ts` `mandateVerdict` | same |
| `flows/analysis/run-summary.ts` `mandateVerdict` | same |
| UI `components/theses/mandate-helpers.ts` / `mandate-panel.tsx` | `VERDICT_LABEL` map (PolicyPanel idiom) + distinct label for `insufficient-evidence` (warn color ok; label is the differentiator from `fails`) |
| `eval/invariants.ts` | see eval wiring below |

Legacy sessions with only `clears`/`fails` continue to parse. New value is
additive.

### Soft vs hard matrix (authoritative)

| Condition | Verdict | Override lifts? | Size effect | Action |
|---|---|---|---|---|
| Evidence thin (spine or R/R) | `insufficient-evidence` | No | no-add to known current (0 if none) | initiate/add → hold |
| Capacity fail (evidence ok) | `fails` | No | `capacityVetoCapPct` | unchanged by this gate |
| Soft fail only | `fails` | Yes → may become `clears` | `unclearedCapPct` unless overridden | unchanged |
| All soft + capacity + evidence ok | `clears` | n/a | none | unchanged |

All effects remain **downward-only**. Never touch `finalRating`.

### PM prompt

In `portfolio-manager.prompt.md`:

- Strengthen missingness discipline: **absent / `unavailable` / thin inputs are
  non-evidence**. They may lower `decisionConfidence` or support abstention
  (hold/no-add); they must **not** justify Buy or Sell on their own, and must
  not be narrated as bearish or bullish support.
- Update rule 11: `mandateOverrideReason` lifts only the soft appetite cap; it
  **cannot** clear `insufficient-evidence` or capacity.
- Keep FIX-678 rules: Hold is not a missing-data dump; thin spine does not force
  a lower rating.

### Error handling

Pure functions; no throws. Unusable spine → treat as thin. Null R/R resource →
remain **mandate-blind** (existing behavior; see Non-Goals / Open Questions).

## 6. Edge Cases & Error Handling

| Case | Expected |
|---|---|
| Thin R/R, sufficient spine, soft numbers clear, override set | `insufficient-evidence`; no-add; override ignored for verdict/size |
| Sufficient R/R, thin spine (`lowConfidence` folded), soft clear | `insufficient-evidence` |
| Soft fail only, override set, evidence sufficient, capacity ok | `clears`; size unclamped (unchanged) |
| Capacity fail + thin evidence | Verdict `insufficient-evidence` (evidence-first so thin is never masked as a pure capacity fail); size = tighter of capacity absolute cap and no-add |
| No portfolio / weight 0, initiate 1.5% | hold @ 0% |
| Held+priced 2%, thin, proposed add to 4% | target ≤ 2%; action hold if was add |
| Held+priced 2%, thin, proposed trim to 1% | target 1%; action trim kept |
| Held-unpriced (`null` weight), thin, initiate | no numeric fabricate-to-0; action → hold |
| Mandate-blind (null mandate or null R/R) | unchanged: no mandateDecision |
| Sufficient evidence run that previously cleared | unchanged verdict + sizing |
| Rating Sell on observed bearish evidence + thin capital evidence | Sell may stand; capital gated |

**Error taxonomy:** none retryable — pure commit-time derivation. Fatal only if
schemas reject (test/typecheck catch).

block on a new live ticker corpus. Pass signal: summary JSON fields match; FAIL
if verdict is `clears` or target > current on thin substrate.
