# FIX-781: Thin or missing evidence can still authorize new exposure — Implementation Spec

## 1. TLDR

Right now the trading desk can turn thin or missing data into a real trade. If the
numbers behind a "worth it" call rest on almost nothing — no observable
fundamentals, a scenario-only reward-to-risk read, or financial statements the
desk marked "unavailable" — it can still recommend opening or adding to a
position, and it has even narrated *absent* data as if it were a reason to buy or
short. This change adds a deterministic safety check that always runs: when the
evidence behind a call is too thin, the desk may still say what direction it
leans, but it will not add capital — it caps the position at what's already held
(zero if nothing is held) and marks the run "insufficient evidence." The check
runs on every analysis, whether or not the user set a risk mandate or connected a
portfolio.

**Technical statement:** Add an always-on, deterministic `computeEvidenceGate`
leaf (modeled on FIX-761's `computePolicyGate`), applied unconditionally at PM
commit, that reads the valuation-spine and reward-to-risk `evidenceBasis`
(fail-closed on an absent layer), emits a distinct non-overridable
`insufficient-evidence` verdict, applies FIX-761-style no-add sizing +
initiate/add→hold, and threads that verdict through the PM memo, decision
snapshot, RunSummary, eval invariants, UI, and the PM prompt — independent of the
optional FIX-752 risk mandate.

**Deliverables:**

- **Gate:** Add `computeEvidenceGate` in `labs/trading-desk/flows/analysis/lib/evidence-gate.ts` (pure leaf) with unit tests.
- **Writer:** Apply the gate unconditionally in `agents/portfolio-manager/writer.ts` after the FIX-752/FIX-761 clamps; supersede the published action + size; mirror `evidenceDecision` onto the PM memo.
- **Schemas:** Extract `portfolioActionSchema`/`PortfolioAction`; add `evidenceDecisionSchema` + `evidenceDecision` memo field in `flows/analysis/resources.ts`; make `portfolioFit.targetWeightPct` nullable (withheld-target branch); add `evidenceVerdict` to `decision-snapshot-resource.ts` (+ `client.expose`) and `run-summary.ts`.
- **Eval:** Add standalone `checkEvidenceGate` to `eval/invariants.ts` (register in `checkRun`) **and** retrofit the existing `decision-consistency/policy-recompute` to compare against the pre-evidence weight + tests.
- **UI:** Extract a shared `GatePanelShell` (dedup `mandate-panel.tsx` + `policy-panel.tsx`); add an always-on `EvidencePanel` in `components/theses/` rendered in `pm-hero.tsx`; thread `evidenceDecision` through `components/summary/aggregate.ts` for the Summary surface.
- **Prompt:** Strengthen `agents/portfolio-manager/prompts/portfolio-manager.prompt.md` — absent/`unavailable` inputs are non-evidence (neither bullish nor bearish support); the mandate override cannot manufacture evidence.
- **Tests + docs:** BHYP-shaped and SPCX-shaped fixtures; extend `CLAUDE.md`, `docs/run-quality-eval.md`, `README.md`, and the published `apps/docs/guides/trading-desk-walkthrough.md`.

**Size:** Medium (single PR, ~250–400 LOC in `labs/trading-desk`, docs-only outside the lab). Mirrors the FIX-761 policy-gate slice in shape and blast radius.

## 2. Overview

- **Linear:** [FIX-781](https://linear.app/fixpoint-labs/issue/FIX-781/trading-desk-thin-or-missing-evidence-can-still-authorize-new-exposure)
- The desk computes an `evidenceBasis` (`"sufficient" | "thin"`) on both the
  FIX-715 valuation spine and the FIX-752 reward-to-risk figure, but nothing
  gates *capital* on it — the signal only nudges `decisionConfidence`. So a
  BHYP-shaped run (thin spine, scenario-only reward-to-risk) can emit
  `mandateVerdict: "clears"`, and an SPCX-shaped run (financial statements marked
  unavailable) can narrate that absence into an active 1.5% short.
- This spec makes evidence sufficiency an **always-on, non-overridable, no-add**
  capital gate that runs whether or not a risk mandate or portfolio is present —
  a new decision surface beside (not inside) the optional FIX-752 mandate gate.
  The rating stays free (a bearish rating on observed negative evidence is still
  allowed); only *new exposure* is gated.
- **Evidence layers.** The issue's acceptance criteria name two layers (valuation
  spine + reward-to-risk `evidenceBasis`). Review surfaced that reward-to-risk's
  bucket-count `evidenceBasis` can read `sufficient` on thin substrate (the
  forecaster's prompt forces ≥3 buckets even when thin), so the gate also folds in
  a **third, deterministic** `criticalDataThin` signal derived from the Phase-1 data
  resources' tool-set `source: "unavailable"` markers — approved as a refinement
  beyond the two listed layers (owner decision on the spec PR). It deliberately does
  **not** trust the forecaster's LLM-emitted `evidenceBasis` or the analyst memo's
  LLM-emitted `dataQuality`.

## 3. Background & Research

### Industry

The pattern is **selective prediction / reject-option**: a model may emit a
directional signal while a separate *selector* abstains from acting when its
inputs are inadequate (Geifman & El-Yaniv, *SelectiveNet*, ICML 2019;
[arXiv:1901.09192](https://arxiv.org/abs/1901.09192)). The complementary discipline
from the missing-data literature is that a **missing observation is a mask, not an
imputed value** — you do not fill an absent feature with a directional default
([Rubin, *Inference and Missing Data*]; the mask-vs-impute distinction). Both map
cleanly onto the issue's core claim: *a missing observation is neither positive
nor negative evidence; it reduces actionability.* Portfolio practice draws the same
hard/soft line — hard constraints define the feasible set (here: may we add at
all), soft constraints express appetite (the FIX-752 mandate).

### Codebase

- **FIX-761** (`lib/policy-gate.ts`, `computePolicyGate`) is the direct template:
  a pure leaf that runs **unconditionally** at PM commit, returns a `no-mandate`
  verdict when absent, applies no-add via `min(target, householdWeight)` +
  initiate/add→hold, and threads its own `policyVerdict` through memo / snapshot /
  RunSummary / eval / UI — *independent of the FIX-752 mandate*. This spec clones
  that shape for evidence.
- **FIX-752** (`lib/mandate-gates.ts`) is the anti-pattern to avoid embedding
  into: `computeMandateGates` only runs `if (mandate != null && rr != null …)` in
  the writer, so a gate folded into it is silent on mandate-blind and
  portfolio-blind runs — exactly what the issue forbids.
- **Evidence substrate already exists and is always computed:** `compute-spine.ts`
  and `compute-reward-to-risk.ts` are unconditional `.tap`s (only the lens pack is
  `full`-gated); reward-to-risk is mandate-blind (λ defaults to 1). Both resources
  carry a stored `evidenceBasis`; the spine additionally exposes
  `expectedReturn.lowConfidence`. Both are `null` **only** when the underlying data
  is genuinely absent (spine: any of the four statements missing;
  reward-to-risk: no usable scenario buckets) — never merely because of cost
  preset or a missing mandate.
- **FIX-715 / FIX-752 orthogonality:** neither the mandate nor the policy gate ever
  touches `finalRating`. This spec extends that invariant to evidence.
- **FIX-790** (`eval/invariants.ts`, `run-artifacts.ts`): the artifacts bundle
  already carries `valuationSpine`, `rewardToRisk`, `householdTickerWeightPct`, and
  the full memo bodies (`portfolioFit`, action) — so `checkEvidenceGate` needs only
  **one** new frozen field (`scopedTickerWeightPct`) to recompute the no-add cap in
  the run's own NAV basis without trusting the record under test.

### Why this approach

Chosen: a **standalone always-on gate** cloned from `computePolicyGate`, with an
independent verdict surface. Alternatives rejected:

| Alternative | Why not |
|---|---|
| Fold into `computeMandateGates` (older mandate-scoped FIX-781 spec, `dd5834dc`) | Only runs when a mandate is present → silent on the mandate-blind and portfolio-blind runs the issue explicitly requires protected |
| Downgrade `mandateVerdict` to `fails`/new value on thin evidence | Re-couples to the mandate; unnecessary given the existing orthogonal-gate precedent (see Decision 3) |
| Soft-scale thin (halve size) | Still authorizes new capital; an override could restore it |
| Wait for FIX-898 (source recovery) | Parallel track; residual thin/absent evidence must still gate regardless of recovery |

### Key Decisions & Ramifications (top 5)

1. **Decision:** A **standalone always-on `computeEvidenceGate` leaf**, applied
   unconditionally at PM commit — *not* folded into `computeMandateGates`.
   **Rejected:** Extend the FIX-752 mandate verdict enum (mandate-embedded spec).
   **Ramification:** Fires on mandate-blind and portfolio-blind runs (the issue's
   central requirement). Adds a fourth orthogonal decision surface
   (`evidenceDecision`) beside mandate/policy/portfolio-fit. The gate neither reads
   nor writes mandate state. Mirrors the FIX-761 precedent exactly (BP-028: fix at
   the layer that owns it — a new evidence layer).

2. **Decision:** **Fail-closed** — a `null` (absent) spine *or* a `null` (absent)
   reward-to-risk figure counts as insufficient, as does either carrying
   `evidenceBasis: "thin"` or the spine's `expectedReturn.lowConfidence`.
   **Rejected:** Require both resources present to gate (skip when absent).
   **Ramification:** Directly catches SPCX (statements unavailable → spine
   null/thin) and BHYP (scenario-only → thin reward-to-risk). Does **not**
   over-gate healthy runs: both resources populate whenever data exists (cost
   preset and mandate are irrelevant to their presence), so a normal fixture run
   stays `sufficient`. A completed run can legitimately have a null spine, so the
   gate must not assume presence.

3. **Decision:** **Verdicts stay orthogonal — the FIX-752 mandate gate is
   untouched.** `mandateVerdict: "clears"` may coexist with
   `evidenceVerdict: "insufficient-evidence"`.
   **Rejected:** Force the mandate verdict to reflect evidence thinness.
   **Ramification:** This is the *existing* architecture — today
   `mandateVerdict: "clears"` already coexists with `policyVerdict: "excluded"` (a
   hard no-add); no one reads that as a bug because the capital outcome is governed
   by the independent gate. "Mandate behavior on sufficiently evidenced runs is
   unchanged" is honored trivially (the mandate leaf is not modified). The run's
   capital outcome is governed by the evidence no-add, not the appetite verdict.

4. **Decision:** The no-add reference is a single **basis-consistent
   `currentWeightPct`** — a frozen `state.scopedTickerWeightPct` computed as
   `householdTickerWeight(scopedSnapshot, ticker)` in the run's own NAV basis.
   **Rejected:** Reusing FIX-761's household `householdTickerWeightPct` on scoped
   runs, or capping against a partial sum of only the priced scoped rows.
   **Ramification:** the PM target is a % of the *scoped* NAV, so measuring no-add
   against the *household* NAV would fabricate trims/authorizations — a ticker held
   only in another account (household 2%, scoped 0%) could authorize a new 2%
   scoped position, and a 10%-scoped holding could be force-trimmed to a 2%
   household figure (both refuted by review). Reusing the pure `householdTickerWeight`
   on the run's own snapshot gives the correct three-value contract: **0** =
   not-held-in-basis / portfolio-blind (portfolio-blind 1.5% initiate → `min(1.5, 0)`
   = **0%**, the acceptance test); **positive** only when *every* scoped row is
   priced; **null** when *any* row is unpriced → **withhold** the numeric target
   (`portfolioFit.targetWeightPct: null`, `targetWithheld: true`) so no partial or
   uncapped positive % is published beside `hold`. `householdTickerWeightPct` stays
   the FIX-761 household *cap* reference (unchanged); the two coincide on unscoped
   runs. The frozen field is added to the FIX-790 artifacts bundle so the eval
   recomputes from a trusted input, not the record under test.

5. **Decision:** The gate is **non-overridable** and **rating-free**.
   **Rejected:** Let `mandateOverrideReason` lift it; force a Hold rating on thin
   evidence.
   **Ramification:** A narrative override lifts only the FIX-752 *soft appetite*
   cap — it cannot manufacture evidence. Observed negative evidence can still yield
   Sell/Underweight while capital stays gated (extends the FIX-715/752
   orthogonality to /781; the gate never touches `finalRating`).

## 4. Technical Design

### Architecture

All changes live in `labs/trading-desk`. No framework package API changes.

```

rewardToRiskResource  ──┼─► computeEvidenceGate ─► verdict + clamped size + action
```

### Sufficiency predicate — `lib/evidence-gate.ts` (new pure leaf, BP-019)

```ts
// No `PortfolioAction` type exists in the repo today — the action enum is inlined
// in `portfolio-manager.ts` (`portfolioFit.action`) and `resources.ts`. Introduce
// a shared type as part of this change: export
// `export type PortfolioAction = z.infer<typeof portfolioDecisionOutputSchema>["portfolioFit"]["action"]`
// (or a small `portfolioActionSchema` leaf) and import ONLY the type here so this
// stays a pure BP-019 leaf. The five values are "initiate" | "add" | "trim" | "exit" | "hold".
import type { PortfolioAction } from "../agents/portfolio-manager/portfolio-manager";

export type EvidenceVerdict = "sufficient" | "insufficient-evidence";

export type EvidenceGateInput = {
  /** Valuation-spine evidenceBasis; null when the spine resource is absent
   *  (fail-closed → treated as thin). */
  spineEvidenceBasis: "sufficient" | "thin" | null;
  /** Spine expectedReturn.lowConfidence. The spine's evidenceBasis already folds
   *  this (valuation-spine.ts:99), but read it explicitly so the gate stays
   *  correct if that fold ever changes (acceptance criterion lists both). */
  spineLowConfidence: boolean;
  /** Reward-to-risk evidenceBasis; null when the figure is absent (→ thin). */
  rewardToRiskEvidenceBasis: "sufficient" | "thin" | null;
  /** DETERMINISTIC missing-substrate signal (third layer). True when critical
   *  upstream data was unavailable/errored — see the writer for the derivation.
   *  This closes the "forecaster emits ≥3 buckets on thin substrate → reward-to-risk
   *  reads `sufficient`" hole WITHOUT trusting the forecaster's LLM-emitted
   *  `evidenceBasis`. */
  criticalDataThin: boolean;
  /** The action entering the gate (post-FIX-761 downgrade). */
  action: PortfolioAction;
  /** Size entering the gate (pct points), post-FIX-752 + post-FIX-761 clamps. */
  targetWeightPct: number;
  /** The analyzed ticker's current weight **in the same NAV basis as
   *  `targetWeightPct`** — the frozen `scopedTickerWeightPct` (see writer): on an
   *  unscoped run this equals the household weight; on a scoped run it is the
   *  weight in the *scoped* NAV. Three-value contract, identical to
   *  `householdTickerWeight`: `0` = not held (portfolio-blind or not in this
   *  book), positive = held+priced, `null` = held-but-**any**-row-unpriced
   *  (unknown → withhold, never a partial/understated sum). */
  currentWeightPct: number | null;
};

export type EvidenceGateResult = {
  verdict: EvidenceVerdict;
  sufficient: boolean;
  spineSufficient: boolean;
  rewardToRiskSufficient: boolean;
  /** Downward-only clamped weight; null when `targetWithheld`. */
  targetWeightPct: number | null;
  sizeClamped: boolean;
  /** initiate|add → hold when insufficient; trim|exit|hold preserved. */
  action: PortfolioAction;
  actionDowngraded: boolean;
  /** False when the current weight was unknown (held-unpriced) → clamp skipped. */
  currentWeightKnown: boolean;
  /** True when insufficient and the current weight was unknown → published
   *  `targetWeightPct` is null (no numeric authorization). */
  targetWithheld: boolean;
};

export function computeEvidenceGate(input: EvidenceGateInput): EvidenceGateResult {
  const spineSufficient =
    input.spineEvidenceBasis === "sufficient" && !input.spineLowConfidence;
  const rewardToRiskSufficient = input.rewardToRiskEvidenceBasis === "sufficient";
  const sufficient =
    spineSufficient && rewardToRiskSufficient && !input.criticalDataThin;

  const known = input.currentWeightPct != null;

  if (sufficient) {
    return {
      verdict: "sufficient", sufficient: true, spineSufficient, rewardToRiskSufficient,
      targetWeightPct: input.targetWeightPct, sizeClamped: false,
      action: input.action, actionDowngraded: false, currentWeightKnown: known,
      targetWithheld: false,
    };
  }

  // Insufficient → no-add. Cap to the (basis-consistent) current weight when
  // known; else withhold the numeric target (never publish an uncapped positive %,
  // never fabricate a trim/exit from a partial or wrong-basis weight).
  let targetWeightPct: number | null = input.targetWeightPct;
  let sizeClamped = false;
  let targetWithheld = false;
  if (known) {
    const capped = Math.min(input.targetWeightPct, input.currentWeightPct as number);
    if (capped < input.targetWeightPct) { targetWeightPct = capped; sizeClamped = true; }
  } else {
    targetWeightPct = null;
    targetWithheld = true;
  }
  const action: PortfolioAction =
    input.action === "initiate" || input.action === "add" ? "hold" : input.action;

  return {
    verdict: "insufficient-evidence", sufficient: false, spineSufficient, rewardToRiskSufficient,
    targetWeightPct, sizeClamped,
    action, actionDowngraded: action !== input.action, currentWeightKnown: known,
    targetWithheld,
  };
}
```

Pure, IO-free, never throws, idempotent, downward-only.

### Writer wiring — `agents/portfolio-manager/writer.ts`

Insert **after** the FIX-761 policy-gate block (which produces `gatedAction` and
the post-policy `targetWeightPct`) and **before** `weightDeltaPct` is computed:

**Freeze `scopedTickerWeightPct` at seed (basis-consistent no-add reference).**
`householdTickerWeightPct` is a % of the FULL household NAV, computed from the
pre-scoping snapshot for the FIX-761 household *cap*. The evidence no-add must
instead measure against the ticker's weight **in the run's own NAV basis** — the
scoped snapshot on a scoped run, the household snapshot on an unscoped run. Add a
frozen `state.scopedTickerWeightPct = householdTickerWeight(portfolio, ticker)`
alongside `householdTickerWeightPct` in `seedSession` (`orchestration/guards.ts`),
where `portfolio` is the run's scoped snapshot (which *equals* the household
snapshot on an unscoped run, so the two fields coincide there). Reusing the same
pure `householdTickerWeight` gives the correct three-value contract for free: `0`
not-held, positive when every scoped row is priced, `null` when **any** scoped row
is unpriced (never a partial/understated sum). This freezes the value so the eval
recomputes from a trusted input, not the record under test.

- `portfolioFit.action` publishes `finalAction` (was `gatedAction`);
  `portfolioFit.targetWeightPct` is the evidence-gated value (nullable when
  `targetWithheld`); `weightDeltaPct` is `null` when the target is withheld, else
  `target − currentWeightPct`. Extend the `sizeWasClamped` / hero metrics sync to
  treat an evidence clamp like FIX-752/761 (downward-only).
- **Clear the hero size on the withheld branch.** The existing `sizeWasClamped`
  sync only fires when `targetWeightPct < proposal`; on the withheld branch
  `targetWeightPct` is `null` and `sizeClamped` is `false`, so that sync would
  leave `metrics.size` showing the model's original add-sized % — which
  `pm-hero.tsx:226-244` renders unconditionally next to a null target. So when
  `targetWithheld`, explicitly overwrite `metrics.size` with a **non-numeric
  withheld marker** (`"—"`), not the model's number. Cover this in the writer test
  (metrics.size === "—" on the withheld branch) and the PM-hero test.
- `evidenceDecision` is mirrored onto the PM memo (always written on a completed
  run — never null on new runs; the memo field is `.nullable()` only for BP-030
  legacy tolerance).
- Snapshot write adds `evidenceVerdict: evidence.verdict`.
- **Ordering:** the evidence gate runs *last* among the three downward-only clamps,
  so `preGateEvidenceTargetPct` is the fully mandate+policy-clamped size and the
  eval can attribute the final clamp. The three action downgrades compose (policy
  exclusion → evidence no-add).
- **Deliberate divergence from a verbatim `computePolicyGate` clone:**
  `computePolicyGate` leaves the initiate/add→hold downgrade in the writer
  (`writer.ts:286-290`); this gate pulls the downgrade *into* the leaf so it is
  unit-testable in isolation. Consequence: `actionDowngraded` is measured against
  the action *entering* the gate (the post-policy `gatedAction`), not the LLM's raw
  action. If the policy exclusion already downgraded add→hold, the evidence gate
  receives `hold`, leaves it, and reports `actionDowngraded: false` even though the
  run is a no-add — consumers must read the flag as "downgraded *by the evidence
  layer*," and the capital no-add is authoritative via `targetWeightPct`, not the
  flag.

### Eval invariant — `eval/invariants.ts`

Add **`checkEvidenceGate(bundle, c, memos)`** as a **standalone** top-level check
(registered in `checkRun`, matching `checkMandate` — **not** mirroring a
`checkPolicyGate` sibling, because FIX-761 policy recompute lives inside
`checkDecisionConsistency` as `decision-consistency/policy-recompute`).

Recompute `computeEvidenceGate` from the bundle (`valuationSpine`, `rewardToRisk`,
the frozen **`scopedTickerWeightPct`** as `currentWeightPct`, the **deterministically
recomputed `criticalDataThin`** from the bundle's persisted critical data-resource
`source` tags via the shared `deriveCriticalDataThin` helper — not the memo's stored
flag, so drift is caught — and **`evidenceDecision.preGateEvidenceAction`** +
`preGateEvidenceTargetPct` — never the post-gate `portfolioFit.action`, which is
already `hold` when insufficient, and never the memo's `currentWeightPct` echo,
which would trust the record under test) and assert:

- `evidence/verdict` (hard): recomputed verdict equals both the memo
  `evidenceDecision.verdict` and the snapshot `evidenceVerdict`.
- `evidence/no-add` (hard): when insufficient and a cap applied (`!targetWithheld`),
  committed `portfolioFit.targetWeightPct ≤` recomputed cap; committed action is not
  `initiate`/`add`. When `targetWithheld`, committed `targetWeightPct` is `null`.
- `evidence/present` (hard): on **completed** PM runs first completed at or after
  this feature, `evidenceDecision` (and the snapshot `evidenceVerdict`) must be
  present. The feature-era discriminator must be an **independent** persisted
  marker — a pinned schema/feature-version field bumped by this change, or the
  existing `decisionSnapshot.decidedAt` compared to a pinned rollout-floor
  timestamp — **not** `evidenceVerdict != null` or `evidenceDecision != null`
  themselves: those are exactly the fields a new-run writer regression would drop,
  so keying legacy-detection on them would misclassify a broken new run as legacy
  and silently skip the check (the snapshot↔memo comparison would also see two
  matching nulls). Runs below the floor / without the version marker legitimately
  parse with `evidenceDecision: null` and **skip** this check (BP-030 — do not fail
  re-eval of persisted pre-feature sessions); a run at/after the floor with a null
  gate write is a hard failure.
- Extend **`decision-consistency/snapshot-pm`** with `evidenceVerdict` ↔ memo mirrors
  (same pattern as mandate/policy fields).
- **Retrofit `decision-consistency/policy-recompute`:** compare recomputed policy
  output to **`evidenceDecision.preGateEvidenceTargetPct`** (post-policy,
  pre-evidence weight) for feature-era runs, so thin-evidence clamps do not
  false-fail FIX-790. **Legacy fallback:** when `evidenceDecision == null` (no
  evidence clamp ever ran), keep comparing against the final
  `portfolioFit.targetWeightPct` as today — the pre-evidence value doesn't exist,
  and the two are equal on those runs anyway.

**Two `run-artifacts.ts` additions** (so `checkEvidenceGate` recomputes both derived
inputs from trusted persisted facts, not memo echoes): (1) the frozen
`scopedTickerWeightPct` (the no-add cap, basis-consistent); (2) the critical
data-resource **`source` tags** (or a compact pre-derived availability summary) that
`deriveCriticalDataThin` consumes — the same tool-set markers the writer reads. Both
go on `runArtifactsStateSchema` + `buildRunArtifacts` alongside the existing
`householdTickerWeightPct`. The data resources already exist in the flow; the bundle
just needs to project their `source` availability.

### PM prompt — `agents/portfolio-manager/prompts/portfolio-manager.prompt.md`

The prompt today frames missing data as *confidence-lowering only* and repeatedly
warns "missing data is not bearish." It lacks the symmetric rule. Add it:

- **Absent / `unavailable` / thin inputs are non-evidence.** They may lower
  `decisionConfidence` or support abstention (hold / no-add); they may **not** be
  cited as affirmative support in **either** direction — not as bullish support
  (a manufactured `asymmetricEdge` / `nearTermCatalyst`, or a `mandateOverrideReason`
  resting on data the desk never obtained) and not as bearish support. Keep the
  existing FIX-678 rules intact (thin data does not force a lower `finalRating`;
  Hold is not a missing-data dump).
- **Deterministic backstop, stated for honesty:** note that the desk applies a
  deterministic no-add when the evidence layers are thin, so the PM should express
  the gap through confidence and narrative, not by inventing conviction from
  absence.
- **Override scope (rule 11):** `mandateOverrideReason` lifts only the FIX-752 soft
  appetite cap; it **cannot** clear `insufficient-evidence`.

The prompt shapes the LLM's *rating and narrative*; the gate is the deterministic
capital clamp. They are not in tension: the LLM proposes an honest size from the
signal it has, the gate caps new exposure when the underlying evidence is thin.

### Error handling

Pure functions; no throws. An absent spine or reward-to-risk resource → treated as
thin (fail-closed). A `null` current weight (any scoped row unpriced, or the ticker
not measurable in the run's NAV basis) → withhold the numeric target
(`targetWithheld`), still downgrade the action.

## 6. Edge Cases & Error Handling

| Case | Expected |
|---|---|
| Thin reward-to-risk, sufficient spine, soft numbers clear, override set | `insufficient-evidence`; no-add; override ignored by the gate |
| Sufficient reward-to-risk, thin spine (or `lowConfidence`) | `insufficient-evidence` |
| Both layers sufficient | `sufficient`; pass-through; mandate/policy behavior unchanged |
| Spine resource null (SPCX: statements unavailable) | Fail-closed → `insufficient-evidence` |
| Reward-to-risk resource null (no usable buckets) | Fail-closed → `insufficient-evidence` |
| Reward-to-risk `sufficient` (≥3 buckets) + sufficient spine, but a critical data resource has `source: "unavailable"` | `criticalDataThin: true` → `insufficient-evidence` (deterministic third layer, from tool-set `source` tags; does not trust the forecaster's LLM self-report or the LLM `dataQuality`) |
| Portfolio-blind, initiate 1.5% | `scopedTickerWeightPct` `0` → target `0%`; action initiate→hold |
| Unscoped, held+priced 2%, thin, proposed add to 4% | `min(4,2)` = 2%; action add→hold (no-add) |
| Unscoped, held+priced 2%, thin, proposed trim to 1% | 1%; action trim preserved |
| Scoped run, held 10% in selected account (all rows priced), thin, add to 12% | cap to the **scoped** 10% (basis-consistent), not the household weight — never forced to a household % |
| Scoped run, ticker held only in *another* account (0% in scope), thin, initiate | `scopedTickerWeightPct` `0` → target `0%` (no household leakage) |
| Any scoped row unpriced (partial), thin | `scopedTickerWeightPct` `null` → `targetWithheld: true`, `targetWeightPct: null`, action→hold; UI honesty note (never a partial/understated sum) |
| Mandate present + thin evidence | `mandateVerdict` unchanged (may be `clears`); `evidenceVerdict: insufficient-evidence`; capital no-add (orthogonal gates, the FIX-761 precedent) |
| Sufficient run that previously cleared + sized | Unchanged verdict + sizing (mandate leaf untouched) |
| Observed bearish evidence + thin capital evidence | Sell/Underweight rating may stand; capital gated |
| Excluded name (FIX-761 already downgraded add→hold) + thin evidence | Evidence gate receives `hold`, leaves it; `actionDowngraded: false` but capital is still no-add via `targetWeightPct` — read the flag as "by the evidence layer," not "overall" |
| Mandate present but reward-to-risk null (forecaster errored) | `mandateVerdict: null` (mandate block guards on `rr != null`) AND `evidenceVerdict: insufficient-evidence` — both surfaced |
| Guard-stopped run (never reaches PM commit) | No `evidenceDecision` / `evidenceVerdict` written (null in snapshot/RunSummary) — same as mandate/policy; the gate runs on **completed PM runs** only |

**Error taxonomy:** none retryable — pure commit-time derivation. Fatal only if a
schema rejects (typecheck/test catches).

## 7. Testing Strategy

**Discipline:** Bug → **`fsd:diagnose`** (build feedback loop → reproduce →
hypothesise → instrument → fix + regression test). Seam for the feedback loop:
vitest on `evidence-gate` (pure), `phase-5-evidence` (writer commit), and
`eval/invariants` (recompute); `fsdev run` + `runSummary` for headless
confirmation. Regression-test seam: the same three vitest levels.

**Goal:** Thin or absent evidence cannot authorize new exposure — on any run,
mandate or not, portfolio or not; missing inputs are never directional capital
justification.

**Goal check (real path, out of CI):** via `fsd:verify-trading-desk`. Run a
portfolio-blind, thin-substrate analysis (a fixture whose financial statements are
recorded `unavailable` so the spine is null/thin, or whose scenario set has < 3
buckets), then read `runSummary` and assert `evidenceVerdict ===
"insufficient-evidence"` **and** `targetWeightPct === 0` (portfolio-blind no-add).
Held+priced thin runs may show `targetWeightPct > 0` capped to the current weight.
A control NVDA fixture run (pin `costPreset: "fast"`, `dataSource: "fixture"` — the spine is deterministic and
the forecaster publishes ≥3 buckets, so `sufficient` holds on `fast`) asserts
`evidenceVerdict === "sufficient"` and its prior sizing is retained. Pass
signal: both summary JSONs match; FAIL if a thin-substrate run reports `sufficient`
or a portfolio-blind thin run has `targetWeight > 0`. If no fixture is thin enough,
vitest commit harness for CI and record a one-off session for the goal script under
`goals/trading-desk-eval/` — do **not** block on a new live-ticker corpus.

**Behaviours / regression cases (diagnose Phase 5 tracer bullets):**

1. Thin/absent spine or reward-to-risk → `insufficient-evidence`, never
   `sufficient`.
1b. Sufficient spine + ≥3-bucket reward-to-risk but a critical data resource has

2. Portfolio-blind 1.5% initiate → hold @ 0%.
3. Override cannot clear thin evidence.
4. Observed bearish rating can stand while capital is gated.
5. Sufficient-evidence control retains prior verdict + size (mandate untouched).
6. Eval recomputation agrees with the stored memo + snapshot mirrors.
7. Any scoped row unpriced + thin → action→hold, `targetWithheld` (never a partial/uncapped positive target); scoped-priced → cap to the scoped weight; scoped run never leaks the household %.

## 8. Non-Goals

- Recovering missing upstream financials (**FIX-898**) — parallel track; this
  issue gates residual/absent evidence regardless of recovery outcome.
- Changing the FIX-752 mandate verdict math or the FIX-761 policy-gate internals.
- Replacing the FIX-752 absolute `unclearedCapPct` for soft fails with dynamic
  no-add (a separately deferred CLAUDE.md item).
- Trusting the scenario-forecaster's **LLM-emitted** `evidenceBasis` (or the analyst
  memo's LLM-emitted `dataQuality`) as a gate input. We instead fold in a
  **deterministic** missing-substrate signal (`criticalDataThin`) derived from the
  Phase-1 data resources' tool-set `source` markers, persisted in the artifacts
  bundle — see §4.
- Restructuring the Phase-4 triad or any framework package / architecture contract.
- Clamping or rewriting `finalRating` for thin evidence.

**Known limitation — the FIX-761 upstream scoped-basis trim (out of scope).** On a
**scoped** run **with a durable portfolio mandate**, the FIX-761 policy gate runs
*before* this gate and clamps the scoped-NAV target against the *household*-NAV
weight (`writer.ts:263-277`, a pre-existing behavior FIX-761 documents as
"over-restricts, the safe direction"). Because every gate is downward-only, this
evidence gate cannot *undo* a wrong-basis trim the policy gate already applied — so
an excluded/capped name held at, say, 10% scoped / 2% household can still be
force-trimmed to 2% on such a run. This spec makes the *evidence* gate
basis-consistent and introduces no new wrong-basis trim, but does **not** fix the
FIX-761 clamp (a Non-Goal). Follow-up: make FIX-761's exclusion no-add
basis-consistent by reusing the same frozen `scopedTickerWeightPct` (via
`fsd:improve-codebase-architecture`).

**Deepening opportunities** (follow-up via `fsd:improve-codebase-architecture`,
not in scope): the gate now folds three deterministic inputs (spine
`evidenceBasis`+`lowConfidence`, reward-to-risk `evidenceBasis`, and the derived
`criticalDataThin`) — a future unification of the desk's several evidence signals
into one sufficiency checklist is worth considering. Making FIX-761's exclusion
no-add basis-consistent on scoped runs (the limitation above) is a second
follow-up. Separately, `computeMandateGates`, `computePolicyGate`, and
`computeEvidenceGate` are three sibling no-add/clamp leaves applied in sequence in
the writer; a single "size-gate pipeline" composition could reduce the writer's
per-gate plumbing.
