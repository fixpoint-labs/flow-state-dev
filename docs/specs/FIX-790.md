# FIX-790: Trading-desk: run-quality evaluation suite — deterministic invariants + LLM-judge rubrics — Implementation Spec

## 1. TLDR

After the desk finishes an analysis run, nothing today says whether the result was any *good* — a person has to read the report. This adds an automatic report card with two layers: a set of exact, free-to-run checks that catch internal contradictions (scenario probabilities that don't add up, a rating outside its allowed band, a position size that ignores the risk mandate), and a second layer where a separate AI grader scores what only judgment can assess — evidence quality, whether the bear actually argued with the bull, whether the manager's confidence matches the evidence. Every evaluated run appends one line to a growing results file, so "improve the desk" becomes "move the number" — and we measure the grader's own noise so a score change can be trusted over run-to-run randomness.

**Technical statement:** Add a run-quality evaluation suite to `labs/trading-desk`: a zero-model `runArtifacts` read action exposing a full scored-artifact bundle per session, a pure deterministic invariant layer over that bundle, an LLM-judge layer (four rubric dimensions via `@flow-state-dev/testing`'s `analyzerScorer`, blinded, judge model distinct from the desk's generators, k-repeat), a batch sweep runner, and a JSONL quality scoreboard — plus a judge-variance characterization mode.

**Deliverables:**

  - Add `runArtifacts` zero-model action in `src/flows/analysis/orchestration/run-artifacts-action.ts`, registered in `src/flows/analysis/flow.ts`

## 2. Overview

Linear issue: [FIX-790](https://linear.app/fixpoint-labs/issue/FIX-790/trading-desk-run-quality-evaluation-suite-deterministic-invariants-llm)

The desk's 129 offline specs verify wiring with every generator mocked; whether a *real* run was good is judged by a human reading the report. This spec turns that judgment into numbers: a deterministic layer that asserts internal consistency of the stored decision records at zero model cost, and a bounded LLM-judge layer for the qualitative dimensions code can't check. Scores accumulate in a per-run JSONL scoreboard so the M3 improvement loop has a corpus-wide quality read in one artifact.

**Premise correction vs the issue text:** FIX-788 shipped *single-run* headless verification only (the `runSummary` action, the `verify-trading-desk` skill, one goal check). Its batch scripts and JSONL scoreboard were removed before merge and explicitly deferred here (`.changeset/trading-desk-headless.md`: "batch sweeps belong to the eval-suite (FIX-790)"). This spec therefore *builds* the batch sweep and the scoreboard; it does not append to an existing one.

## 3. Background & Research

### Industry findings (sources linked)

- **Deterministic-first layering is universal.** Code-based assertions run first and constantly; LLM judges are reserved for what code can't measure ([Hamel Husain](https://hamel.dev/blog/posts/evals/), [Anthropic eval guide](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests), [Braintrust](https://www.braintrust.dev/articles/what-is-llm-as-a-judge)). Checks record `{id, pass, expected, actual, detail}` — never a pre-aggregated number.
- **Rubric shape: binary where decidable, anchored 1–5 where graded.** Binary checklist decomposition minimizes judge variance and makes each fail self-explaining ([Hamel on judges](https://hamel.dev/blog/posts/llm-judge/), [Rulers](https://arxiv.org/html/2601.08654)); for genuinely graded qualities, an anchored 1–5 with concretely described extremes, reasoning-before-score, and mean-of-k aggregation correlates best with humans ([empirical design-choice study](https://arxiv.org/html/2506.13639v1), [G-Eval](https://arxiv.org/abs/2303.16634)) — this design maps those five anchor levels onto the scorer's native 0–1 scale (§4.5).
- **Judge noise is real and measurable.** Temperature 0 does not make judges deterministic (a few % of scores still flip: [Rating Roulette](https://arxiv.org/html/2510.27106v1)); repeats beyond k≈3 have diminishing returns ([Hidden Measurement Error](https://arxiv.org/pdf/2604.11581)); delta is signal when |Δmeans| > 2·SE_diff; Krippendorff's alpha (target ~0.8) flags unreliable rubrics ([Reliability without Validity](https://arxiv.org/html/2606.19544)).
- **Bias mitigations:** blind the judge to identity/provenance, use a judge from a different model family than the generators (self-preference), instruct length-neutrality ([Eugene Yan](https://eugeneyan.com/writing/llm-evaluators/), [Justice or Prejudice](https://arxiv.org/html/2410.02736v1)).
- **Keep scores separable.** A weighted composite hides exactly the regression you care about ([Braintrust eval guide](https://www.braintrust.dev/articles/llm-evaluation-guide)). The scorecard keeps the deterministic section and per-dimension judged `{mean, std, k}` side by side.
- **Calibration without outcomes** is judged as *epistemic congruence* — is stated conviction proportionate to the evidence presented, with extractive quotes required, and hedging language itself neither rewarded nor penalized ([Epistemic Integrity](https://arxiv.org/pdf/2411.06528), [judge-hedging caveat](https://arxiv.org/pdf/2410.20774)).

### How this codebase already solves the pieces

- **LLM-judge primitive:** `analyzerScorer` in `packages/testing/src/eval/analyzerScorer.ts` — per-criterion 0–1 findings via a strict output schema, `scoreMapping` (mean/min/weighted), threshold, `costUsd` accounting, judge executed through `testBlock` with an injected real `modelResolver`. The FIX-614 benchmark (`packages/testing/src/benchmark/runBenchmark.ts`) is the shipped consumer and establishes the discipline this spec follows: rubric locked in code, judge built per task, judge model pinned via `forceModelResolver`, self-preference warning when judge == executor, blinding by *withholding identity from the judge input*, k-repeat cells with `meanStddev` + 2·SE credibility (`packages/testing/src/benchmark/report.ts`).
- **Headless read-back:** `goals/trading-desk-headless/fixture-run-clean/run.mts` shells `pnpm fsdev run analysis analyze … --session <id> --capture` then `… runSummary --session <id> --capture` and reads `capture.result.output`. Actions attach to whatever `--session` id is passed, so a second process can read a past session — the seam this spec's `runArtifacts` action reuses.
- **Pure-check style:** `labs/trading-desk/test/composite-math.spec.ts` (fixture object in, result object out, null-honesty asserted) is the model for invariant tests; scorers return result objects, never throw (`ScoreResult`, `analyzerScorer` catch-to-failed-score, `evalBlock` per-case try/catch).
- **Scoreboard:** no JSONL/append pattern exists anywhere in the repo — that write path is net-new here.

### Why this approach

The alternative shapes considered: (a) golden-output diffing — rejected, it's FIX-791's axis and needs these scores as input; (b) re-running the pipeline under the judge — rejected by the issue's own cost boundary (judges read stored artifacts only); (c) building the judge on raw Vercel AI SDK `generateObject` — rejected, no precedent in the repo and `analyzerScorer` already provides schema, cost accounting, and FIX-614 consistency for free (BP-029).

### Key Decisions & Ramifications (top 5)

1. **This spec builds the batch sweep + JSONL scoreboard (premise correction), rather than assuming FIX-788's.** Alternative rejected: splitting the sweep into its own issue. FIX-788's changeset already assigned it here, and the eval layers are unusable without a corpus artifact to land in. *Ramification:* FIX-790 owns the scoreboard schema; FIX-791 (golden diffing) and FIX-792 (cost accounting) consume and extend it, so its record shape gets an `evalVersion` field and additive-only evolution (BP-030).
2. **Deterministic layer asserts only on computed records; all LLM-emitted content routes to the judge layer.** Fixture mode pins data tools but generators still call real models, so memo prose/ratings are nondeterministic run-to-run. Alternative rejected: snapshot-style assertions on memo text (would be permanently red). *Ramification:* layer 1 is stable on any session including fixture replays; it can never validate prose claims — the null-honesty *prose* discipline is judged, not asserted.
3. **Judges run through `analyzerScorer` with a pinned, injected `modelResolver`, reading a blinded stored-artifact bundle — never re-running the pipeline.** Alternative rejected: raw AI SDK calls from the script. *Ramification:* judge cost is bounded (4 dimensions × k=3 = 12 calls/run), consistent with FIX-614, and swappable per `--judge-model`; it also means judges can't probe beyond what the bundle serializes.
4. **Hybrid rubric shape — binary checklists for decidable criteria, five-level anchored grading (recorded on the scorer's native 0–1 scale) with mean-of-k for graded dimensions — and scores stay separable (no composite).** Alternative rejected: single 1–10 holistic score (industry consensus against; hides regressions). *Ramification:* the scoreboard line carries per-dimension `{mean, std, k}` + deterministic pass/fail counts; any consumer wanting one number must derive it downstream, deliberately. Swapping the judge model requires re-baselining.
5. **A new zero-model `runArtifacts` action is the read seam, not direct store access from scripts.** Alternative rejected: reading PGlite/postgres tables from `eval-runs.ts`. *Ramification:* evals read through the same resource API the app uses (works against any store backing, honors schema dual-reads); the bundle action is also the fixture source for offline invariant tests. `runSummary` stays untouched as the cheap projection.

`eval-runs.ts` shells `fsdev` exactly the way `fixture-run-clean/run.mts` does (cwd = `labs/trading-desk`, `--capture <file> --quiet`, read `capture.result.output`). ### 4.3 The `runArtifacts` action

Sibling of `runSummary` (same zero-model handler shape, `inputSchema: z.object({})` — callers pass `-i '{}'`, matching every established invocation), registered as `runArtifacts` in `flow.ts`. It projects via `ctx.resources` / `memos.getOptional` over `ALL_MEMO_KEYS` (24 keys on `full`: 20 static entries + 4 lens keys built dynamically from `LENS_IDS`), plus `ctx.session.state` for the two session-state fields (`riskMandate`, `citationIntegrity` live on `sessionStateSchema`, not the resource set — the action declares `sessionStateSchema` exactly as `run-summary-action.ts` does):

```ts
export const runArtifactsStateSchema = z.object({
  summary: runSummaryStateSchema,                    // reuse buildRunSummary verbatim
  valuationSpine: valuationSpineStateSchema.nullable(),
  rewardToRisk: rewardToRiskStateSchema.nullable(),
  lensConvergence: lensConvergenceStateSchema.nullable(),
  decisionSnapshot: decisionSnapshotStateSchema.nullable(),
  riskMandate: riskMandateSchema.nullable(),         // the frozen dials from session state
  citationIntegrity: citationIntegritySchema.nullable(),
  hasUserThesis: z.boolean(),                        // state.userThesis !== null — makes p6 expectedness deterministic
                                                     // (a completeness check can't otherwise tell a valid no-thesis run
                                                     // from a run that silently dropped the thesis-alignment memo)
  p2Contributions: phase2Contributions.stateSchema.nullable(),
                                                     // Phase 2 round-robin turn transcript ({ entries: [...] }) — the
                                                     // debate-engagement judge grades actual turns, not just the
                                                     // consolidated bull/bear/RM memos. `phase2Contributions`
                                                     // (resources.ts:415) exposes no standalone schema export; reuse the
                                                     // resource's stateSchema (or export a named alias if that reads better)
  memos: z.array(z.object({ key: z.string(), state: memoStateSchema.nullable() })), // full bodies;
  // state null when the memo was never created (fast preset omits p2b/*, no-thesis runs omit p6) —
  // mirrors runSummaryAction's getOptional-miss handling so completeness checks can tell absent from malformed
});
```

`buildRunArtifacts` is pure (same discipline as `buildRunSummary`); the action just feeds it resource reads. Two normalization rules from the `run-summary.ts` precedent carry over: `getOptional` misses become `null` entries, and a `decisionSnapshot` that surfaces as `{}` (stopped / pre-PM sessions on the defaultless resource) is normalized to `null` by gating on a required field (the `hasDecision` guard, `run-summary.ts:126`) — otherwise output validation would reject exactly the stopped runs the suite must record. Existing sessions missing newer fields dual-read as null (schemas already `.nullable().default(null)` — BP-030). Resource-state schemas stay out of `output-schemas-strict.spec.ts`, matching the existing exclusion.

### 4.4 Deterministic invariant layer

`checkRun(bundle: RunArtifactsBundle): InvariantReport` — pure, total, never throws; missing substrate degrades to a failed/`skipped` check with a reason.

```ts
export type CheckResult = {
  id: string;                       // e.g. "rating-envelope/final-within-band"
  severity: "hard" | "soft";        // hard = internal contradiction; soft = flagged signal
  status: "pass" | "fail" | "flag" | "skipped";  // flag only for soft; skipped = substrate absent (n/a)
  expected?: unknown; actual?: unknown; detail: string;
};
export type InvariantReport = {
  hard: { passed: number; failed: number };
  soft: { passed: number; flagged: number };
  skipped: number;
  checks: CheckResult[];
};
```

Check groups (exact substrate fields per the codebase map; implementer reuses the desk's own pure libs for recomputation rather than duplicating formulas — all `lib/` references below are `labs/trading-desk/src/flows/analysis/lib/`):

| Group | Checks (severity) |
|---|---|
| `memo-completeness/*` | Expected memo set for the run's `costPreset` (lens pack only on `full`) and thesis presence (p6 expected iff the bundle's `hasUserThesis` is true — deterministic, not inferred from the memo's absence) — every expected memo `published`, or `error` with non-empty `errorMessage` (hard). No memo left `pending`/`writing` on a `completed` run (hard). |
| `rating-envelope/*` | `decisionSnapshot.finalRating` within `[envelope.floor, envelope.ceiling]` tier order (hard). PM memo, one-directional checks only — the raw pre-clamp LLM rating is never persisted, so a clamp biconditional is not computable from the bundle: `ratingClamped` ⇒ `finalRating ∈ {floor, ceiling}` (a clamp lands on a band edge); `finalRating` outside `ratingBand` ⇒ `ratingOverrideReason` non-empty (hard). Band recomputation: rebuild floor/ceiling from `envelope.implied` + `evidenceBasis` with the `lib/rating-engine.ts` helpers (floor = implied − 1 tier; ceiling = implied + 1, widened to +2 on thin evidence) and compare to the stored band (hard). |
| `scenario/*` | 3–5 scenarios; each `probability ∈ [0,1]`; recomputed sum of the *stored* probabilities within `[0.98, 1.02]` (hard — the forecaster commit normalizes them, `agents/scenario-forecaster/writer.ts`). Stored `probabilitySum` records the raw pre-normalization sum and is a **separate** check: assert `∈ [0.8, 1.2]`, never equality with the recomputed sum (hard). `expectedReturnPct` number-or-null, never string (hard). |
| `reward-risk/*` | Recompute via `computeRewardToRisk` (`src/flows/analysis/lib/reward-to-risk.ts`) from the stored scenarios + mandate dials; stored `rewardToRisk` matches (hard). Snapshot mirrors (`rewardToRiskLossAdjustedGlr`, `worstCaseReturnPct`) match the resource — gated on `mandateDecision` non-null (they are sourced from it and stay null on mandate-blind runs even though the resource is populated; skipped otherwise) (hard). |
| `mandate/*` | Skipped when `mandateDecision` null (mandate-blind run). Recompute soft gates (`rrCleared`/`hurdleCleared`/`confidenceCleared`) and hard capacity gate via the helper extracted to `src/flows/analysis/lib/mandate-gates.ts` (§4.1 — the math currently lives inline in the PM commit handler and must be extracted, not duplicated); stored `verdict`/`capacityVetoed` match (hard). `sizeClamped` is **not** recomputable — the raw pre-clamp target is never persisted — so check only the directional implication `sizeClamped` ⇒ `targetWeightPct` equals the applicable cap (hard). Committed `portfolioFit.targetWeightPct` ≤ `capacityVetoCapPct` when vetoed; ≤ `unclearedCapPct` when uncleared and no override; dial sanity `capacityVetoCapPct ≤ unclearedCapPct` (hard). |
| `decision-consistency/*` | Snapshot ↔ PM memo mirrors equal (`finalRating`, `decisionConfidence`, `mandateVerdict`, …); snapshot trade fields ↔ trader memo mirrors (`direction`, `sizePct`, `stopPrice`, `targetPrice`, `holdingPeriod`) (hard). Echo fields: `weightDeltaPct = targetWeightPct − currentWeightPct` ±0.01 (hard). `hasPortfolioContext` is *not* checked — the bundle deliberately omits the portfolio state it would need to verify against, and trusting the memo's own echo would be circular. |
| `valuation/*` | Abstention honesty: `dcf.available === false` ⇒ `unavailableReason` non-null; same for `fairValue.method === "none"` (hard). `terminalValueShare > 0.85` ⇒ `reliability === "tv-dominated"` (hard). `triangulation.methodsUsed`/`divergence`/`spread` consistent with the per-method margin-of-safety values (hard). Dexter-style bounds as **soft flags**: `tv-dominated` reliability; `expectationsGap` beyond a generous band; DCF intrinsic (equity, $B) vs market cap divergence beyond ±50%. |
| `citations/*` | Analyst memos: `dataQuality` non-null on published memos (hard). Citation arrays well-formed (`{url,title}`, parseable URL) where non-null (hard). Phase-2 `citationIntegrity.invalidTags` empty (**soft** — it records LLM tag quality, not a code bug). |
| `null-honesty/*` | No `"NaN"`/`"undefined"`/`"null"` strings in `metrics` values; numeric mirrors are number-or-null (hard). |

Recomputation checks (reward-risk, mandate) reuse the same pure libs the pipeline used — they catch stored-record drift and partial writes, not formula bugs; that's their job.

### 4.5 LLM-judge layer

Four dimensions in `rubrics.ts`, each `{ key, kind: "graded" | "checklist", criteria: string[], anchors?, inputs }`:

1. **`evidence-quality`** (graded, five anchor levels): Phase-1 analyst memos — are claims specific, sourced, and consistent with each memo's `dataQuality`; anchors describe the bottom level (generic filler, unsourced numbers) and top level (specific, quantified, provenance-aware) concretely.
2. **`debate-engagement`** (checklist): over the Phase 2 round-robin **transcript** (`p2Contributions` in the bundle) plus the consolidated bull/bear/research-manager memos — bear rebuts ≥1 specific bull claim (quote required); bull's strongest claim is addressed rather than strawmanned; `unresolvedDisagreements` reflects real unresolved points; neither side fabricates numbers absent from the data memos. The transcript is the primary substrate — consolidated memos can summarize away the very rebuttals this dimension measures. If `p2Contributions` is absent (older session), the dimension is `skipped` with reason, not judged from summaries.
3. **`pm-coherence`** (graded, five anchor levels): decision summary follows from the cited upstream memos; when `agreesWithTrader === false`, the disagreement is addressed; `acceptedAdjustments` traceable to risk memos.
4. **`confidence-calibration`** (graded, five anchor levels, epistemic congruence): `decisionConfidence` + conviction language proportionate to evidence presented (scenario spread, `evidenceBasis`, acknowledged risks); judge instructed that hedging language is neither rewarded nor penalized.

**Score scale:** `analyzerScorer`'s finding schema scores each criterion on its native **0–1** scale. Graded rubrics express their five anchor levels *on that scale* (anchors at 0, 0.25, 0.5, 0.75, 1); checklist criteria are 0-or-1. Every recorded score, mean, and std in the quality record is 0–1 — the scoreboard never mixes scales.

Mechanics (`judge.ts`), following `runBenchmark.ts`:

- One `analyzerScorer({ name: dimension.key, criteria, model: judgeModelId, modelResolver })` call per dimension per repeat; the blinded bundle serialization is passed as the scored `output`. `modelResolver` is `createModelResolver()` from `@flow-state-dev/core` (already a lab dependency); `analyzerScorer` forwards `config.model` to its analyzer block, which is what pins the judge. Do **not** reference `forceModelResolver` — it is module-private to `runBenchmark.ts`; if hard pinning beyond `model` is wanted, replicate the ~6-line wrapper locally in `judge.ts`.
- Caveat: the shipped `evalFindingSchema` emits `score` *before* `assessment`/`evidence`, so reasoning-before-score is **not** delivered by the schema. The rubric preamble must instruct per-criterion evidence-gathering before deciding, and v1 accepts the field-order limitation (reordering is a `packages/testing` change — flagged as a deepening follow-up in §8).
- **Blinding** (`blinding.ts`): serialize only role labels (`bull`, `bear`, `pm`…), memo bodies/typed fields, and the computed records the rubric needs; strip `sessionId`, timestamps, model/agent identity, capture paths. Length-neutrality instruction included in criteria preamble.
- **k = 3** repeats per graded dimension (mean + std recorded; checklist dimensions also k=3 in v1 until variance data justifies k=1). 4 × 3 = 12 judge calls per run; `--max-cost-usd` budget guard mirrors the benchmark's early-stop.
- **Judge model**: `--judge-model` flag; default pinned in `eval-runs.ts` to a cheap model from a different family than the desk's generators (see Open Question 1). If judge family == executor family, push a self-preference warning into the record, exactly like `runBenchmark`.
- Judge failures return `{score: 0, passed: false, reason}` per the `analyzerScorer` catch convention — a failed judge is a failed score, never a crashed sweep.
- Judges are **skipped** for runs with `status !== "completed"` (deterministic layer still records).

### 4.6 Scoreboard record

One JSONL line per evaluated run (`scoreboard.ts`; append-only, `O_APPEND` single-line writes; sweep evaluates sequentially even when runs execute concurrently, so no interleaving):

```ts
export const qualityRecordSchema = z.object({
  evalVersion: z.literal(1),
  sessionId: z.string(),
  // identity fields are nullable ONLY so a runStatus:"error" line can still be appended when the
  // runArtifacts read itself failed (eval mode has no manifest to fill them from); sweep mode
  // always fills them from the manifest tuple
  ticker: z.string().nullable(), date: z.string().nullable(),
  costPreset: z.enum(["fast", "full"]).nullable(), dataSource: z.enum(["fixture", "live", "record"]).nullable(),
  mandateId: z.string().nullable(), runStatus: runStatusSchema,
  // ranAt = when ANALYZE originally ran, never when the read action ran: sweep mode takes it from
  // the analyze capture; eval mode takes it from session metadata / decisionSnapshot.decidedAt;
  // null when neither is available. (The runSummary action stamps its own invocation time — do not use it.)
  ranAt: z.string().nullable(), evaluatedAt: z.string(),
  finalRating: ratingSchema.nullable(),   // ratingSchema = five-tier enum newly exported from lib/rating-engine.ts (§4.1)
  decisionConfidence: z.number().nullable(),
  targetWeightPct: z.number().nullable(),
  invariants: z.object({
    hardPassed: z.number(), hardFailed: z.number(),
    softPassed: z.number(), softFlagged: z.number(), skipped: z.number(),
    failures: z.array(z.object({ id: z.string(), detail: z.string() })), // hard failures only, inline
  }),
  judges: z.array(z.object({
    dimension: z.string(), kind: z.enum(["graded", "checklist"]),
    status: z.enum(["scored", "skipped"]),            // per-dimension: budget cap or missing substrate → skipped
    skipReason: z.string().nullable(),
    mean: z.number().nullable(), std: z.number().nullable(),
    k: z.number(), scores: z.array(z.number()),       // all 0–1 (§4.5); empty when skipped
    costUsd: z.number().nullable(),
  })).nullable(),                                     // null only when the whole judge layer was skipped (--no-judges, non-completed run)
  judgeModel: z.string().nullable(),
  warnings: z.array(z.string()),                      // e.g. self-preference
  detailPath: z.string(),                             // full CheckResult[] + judge reasoning
});
```

Deterministic and judged results stay separable (no composite). The per-run detail sidecar (`details/<sessionId>.<evaluatedAt>.json`, timestamp in the filename so re-evaluating a session — different judge model, k, or rubric version — never overwrites the sidecar an earlier scoreboard line points to) carries the full `CheckResult[]` and every judge repeat's findings/reasoning — the scoreboard line stays grep-able and small.

### 4.7 Variance characterization mode

`pnpm eval variance --session <id> [--session <id> ...] [--k 5]`: fixed session(s), k=5 repeats per dimension, no scoreboard append. Emits a variance report JSON: per-(session, dimension) `{mean, std, k, scores}` and the derived noise band (`2·SE`). **Krippendorff's alpha is computed only when ≥2 sessions are supplied** — items = sessions, raters = repeats; with a single item the expected-disagreement denominator is degenerate and alpha is meaningless, so single-session runs report std/2·SE bands only and omit alpha. With multiple sessions, any dimension with α < 0.8 is flagged as an unreliable rubric needing rework. The measured bands get recorded in `docs/run-quality-eval.md` so future score deltas can be read against them. `stats.ts` implements `meanStd`, `seDiff`, and ordinal `krippendorffAlpha` locally (~30 LOC each; the benchmark's equivalents are package-internal, and promoting them is deliberately out of scope — see Non-Goals).

### 4.8 CLI surface

```
pnpm eval sweep    --manifest <file.json> [--concurrency 2] [--out .fsdev/eval] [--judge-model <id>] [--no-judges] [--max-cost-usd <n>]
pnpm eval eval     --session <id> [--session <id> ...] [same flags]
pnpm eval variance --session <id> [--session <id> ...] [--k 5] [--judge-model <id>]
```

**Sweep concurrency and PGlite:** embedded PGlite is single-process (`lib/portfolio-db.ts` documents that two `fsdev run` children must not share one data dir). The sweep therefore gives **each run its own isolated `TRADING_DESK_DATA_DIR`** (a per-session subdir under `--out`) and passes the same env to that session's `runArtifacts` read — which makes `--concurrency > 1` safe and keeps sweep runs out of Past Reports as a side effect. Runs against a real Postgres backing (`DATABASE_URL`/`FSD_DB_URL`) have no such constraint and may share the store.

**Session ownership:** `fsdev run` executes as the CLI user, and stored sessions are bound to their creator — so v1's `eval` mode reads sessions created by the harness (the sweep path, or any prior `fsdev run` session). Evaluating UI-created sessions (owned by the app's dev user) needs a user-id seam in `fsdev run` that doesn't exist today; that's a named limitation (see §6), not something this suite works around.

Manifest: `[{ ticker, date?, costPreset?, dataSource?, riskMandate?, userThesis? }]` — field names match `analyzeInputSchema` exactly (the per-run mandate override is `riskMandate`, not `mandateId`; a wrongly-named key would be silently stripped and the sweep would run mandate-blind). The scoreboard's `mandateId` field is read back from the run summary, which records the resolved mandate. Exit code: non-zero when any run errored or any **hard** invariant failed (soft flags and judge scores never gate; thresholds are a consumer decision, per the industry guidance).

### 4.9 Error handling

| Failure | Handling |
|---|---|
| `analyze` child process error / non-zero exit | Record run with `runStatus: "error"`, skip judges, continue sweep |
| `runArtifacts` capture unreadable | Scoreboard line with `runStatus: "error"`, `detail` in warnings; continue |
| Judge call throws / times out | `analyzerScorer` catch → score 0 + reason; recorded, sweep continues |
| Budget cap hit | Stop launching judge calls, mark remaining dimensions skipped with warning (benchmark precedent) |
| Missing substrate (old session, mandate-blind, fast preset) | Checks `skipped`, never `fail` (BP-030/BP-035 second-path) |

## 5. Implementation Sequence

1. **`runArtifacts` action** — `run-artifacts-action.ts` + `buildRunArtifacts` (pure) + registration in `flow.ts`; vitest: bundle shape from mocked resources; verify via `pnpm fsdev run analysis runArtifacts -i '{}' --session <id>` against a fixture-run session.
2. **Invariant layer** — first the two behavior-neutral extractions (`lib/mandate-gates.ts` out of `writer.ts`; `ratingSchema` exported from `lib/rating-engine.ts` and adopted at every five-tier-enum site per §4.1, so a future ladder change has exactly one edit point — existing tests stay green), then `src/eval/types.ts` + `invariants.ts` (+ the recompute imports from `lib/`); capture one fixture-run bundle as a sanitized test fixture; vitest per check group in `test/eval-invariants.spec.ts` (composite-math style: pass case + violated-fixture case + skipped case each).
3. **Judge layer** — `rubrics.ts`, `blinding.ts`, `judge.ts`; vitest with mocked model (write-block-tests idiom: scripted `resolveModel`, assert blinded input contains no sessionId/timestamps and criteria assembled per dimension) in `test/eval-judge.spec.ts`.
4. **Scoreboard + CLI** — `scoreboard.ts`, `stats.ts`, `scripts/eval-runs.ts`, package script; vitest for record schema round-trip + append semantics; `eval` mode end-to-end against the step-1 session with `--no-judges`, then with judges.

6. **Goal check + docs + changeset** — `goals/trading-desk-eval/fixture-batch-scored/`; `docs/run-quality-eval.md`; CLAUDE.md section; `run-summary.ts` comment touch; empty changeset.

Steps 1→2 and 1→3 are ordered (both consume the bundle); 2 and 3 are independent of each other; 4 needs 2+3; 5 needs 4; 6 last.

## 6. Edge Cases & Error Handling

| Case | Expected behavior |
|---|---|
| Run stopped early (`unsupported-asset-type`, `phase-1-no-data`, …) | Scoreboard line with `runStatus: "stopped"`; completeness checks assert only pre-stop expectations; judges skipped |
| `costPreset: "fast"` (no lens pack) | `p2b/*` memos excluded from the expected set; `lensConvergence` checks skipped |
| Mandate-blind run (`mandateDecision` null) | `mandate/*` checks skipped, not failed |
| Pre-FIX-807 session (`dcf`/`triangulation` null) | `valuation/*` DCF checks skipped; justified-PE checks still run |
| No thesis supplied | `p6/thesis-alignment` excluded from expected set |
| Memo honestly errored (`status: "error"`, message set) | Completeness check passes (honest error is the contract); judge dimensions that need that memo get `skipped` with reason |
| Judge == executor model family | Warning recorded on the QualityRecord (never blocked) |
| Two eval processes appending concurrently | Single-line `O_APPEND` writes; lines are self-contained JSON — a torn read is detectable by JSON.parse failure and that line is skipped by readers |
| Fixture missing for a manifest tuple | `analyze` fails with `FixtureMissingError` → `runStatus: "error"` line, sweep continues |
| `probabilitySum` stored but scenarios array empty | `scenario/*` hard fail with detail (contradiction, not absence) |
| Session created by the UI (different owner than the CLI user) | `runArtifacts` read is rejected by session-ownership checks → `runStatus: "error"` line with the reason in warnings; documented v1 limitation (needs a user-id seam in `fsdev run`) |
| Local PGlite backing with `--concurrency > 1` | Safe: each sweep run gets an isolated per-session `TRADING_DESK_DATA_DIR`; children never share a PGlite dir |
| Judge returns identical reasoning across repeats | Valid low-variance outcome (low temperature / provider caching) — recorded as-is, never treated as failure |

## 7. Testing Strategy

**Goal & goal check (required).** Goal: *a maintainer (or agent loop) can run one command over the fixture corpus and get a trustworthy per-run quality read — contradictions caught for free, qualitative scores with known noise.* Goal check: `goals/trading-desk-eval/fixture-batch-scored/run.mts` — runs `pnpm eval sweep` over a 2-tuple fixture manifest (NVDA + AAPL, `fast`, isolated `TRADING_DESK_DATA_DIR`), real models end-to-end including judges, then asserts: 2 scoreboard lines parse against `qualityRecordSchema`; all hard invariants pass on both; every judge dimension is `scored` with k scores in `[0, 1]` and non-empty reasoning in the detail sidecar (identical reasoning across repeats is a valid low-variance outcome and must NOT fail the check); then runs `variance` (k=3 to bound cost) across both sessions and asserts std recorded per dimension (alpha too, since two sessions supply ≥2 items). Prints `PASS —`/`FAIL —`, exit 0/1. **Anti-game:** the check reads the detail sidecar, not just counts — empty reasoning, missing per-criterion evidence, or all-skipped checks fail it; the manifest uses two different tickers so a hardcoded record can't pass twice, and the two runs' bundles must differ (same-bytes bundles indicate a stubbed read path).

**Discipline:** `fsd:tdd` (Feature) — tracer bullet is step 1+2 on a single fixture session: bundle action → invariants → printed report, before any judge or scoreboard exists.

**Behaviours to test (CI, mocked — `labs/trading-desk/test/`):**
- `buildRunArtifacts` projects every resource + every `ALL_MEMO_KEYS` entry (24 on `full`: 20 static + 4 lens keys built dynamically from `LENS_IDS`); absent resources/memos → null (not throw); `{}` decision snapshot → null
- Each invariant group: passing fixture / violated fixture / skipped-substrate fixture (e.g. mandate-blind)
- Envelope check catches a snapshot rating outside `[floor, ceiling]`; clamp-flag one-directional checks (clamped ⇒ band edge; outside band ⇒ override reason)
- Scenario probability sum tolerance edges (0.98 / 1.02 exact)
- Mandate recompute catches a `targetWeightPct` above an applicable cap
- Blinded serialization contains no sessionId/timestamps/agent identity; role labels preserved
- Judge wiring: criteria assembled per dimension; k repeats invoked; failed judge call → score 0 + reason (mocked model throwing)
- `qualityRecordSchema` round-trip; append writes exactly one line; reader skips torn lines
- Stats: `krippendorffAlpha` on known ordinal fixtures; `seDiff` credibility math

Existing patterns to follow: `test/composite-math.spec.ts` (pure checks), `.agents/skills/write-block-tests` mock-context idiom (judge wiring), `test/report-summary-aggregate.spec.ts` (projection tests).
