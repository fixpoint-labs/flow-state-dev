# FIX-791: Trading-desk run-diff and golden-baseline regression scorecard — Implementation Spec

> Canonical repo copy: `docs/specs/FIX-791.md`. Mirrored to the Linear issue
> document — keep the two in sync (BP-037). Linear: [FIX-791](https://linear.app/fixpoint-labs/issue/FIX-791/trading-desk-run-diff-and-golden-baseline-regression-scorecard).

## 1. TLDR

When someone changes a desk prompt or pipeline step, there is no way to see what the change *did* — two runs of the same ticker always differ a little because the models are nondeterministic, so a real regression hides inside ordinary wobble and the only way to tell is reading two reports side by side in a browser. This adds three things that turn "did my change break anything" into a command. First, a **run-diff**: point it at two runs of the same input and it prints a field-by-field comparison — the rating moved, the position weight changed, a risk gate flipped, the quality scores dropped — as both a JSON file and a skimmable table. Second, **golden baselines**: a small set of committed reference results for the fixture tickers; one command re-runs them against the current build and diffs against the reference, and updating the reference is a deliberate, reviewed commit whose diff *is* the PR evidence. Third, **variance calibration**: run the same fixture several times to learn each field's natural spread, so the diff can label a change "within normal noise" instead of crying wolf on every model wobble. Together these make the M3 improvement loop — change, re-run, diff, keep or revert — mechanical.

**Technical statement:** Add a run-diff + golden-baseline regression layer to `labs/trading-desk/eval/` that projects the already-shipped `RunArtifactsBundle` + `QualityRecord` into a reduced, identity-blind `RunScorecard`, computes a typed field-level `RunDiff` classified against a calibrated `NoiseProfile`, commits golden scorecards for the fixture corpus, and adds `diff` / `golden` / `calibrate` modes to the existing `scripts/eval-runs.ts` CLI.

**Deliverables** (mirrors the Implementation Sequence, §5):

## 2. Overview

Linear issue: [FIX-791](https://linear.app/fixpoint-labs/issue/FIX-791/trading-desk-run-diff-and-golden-baseline-regression-scorecard).

FIX-788 gave the desk headless single runs (`runSummary`); FIX-790 gave it a quality read (`runArtifacts` bundle, deterministic invariants + LLM judges, the `QualityRecord` JSONL scoreboard, and a *judge*-variance mode). What is still missing is the comparison layer: nothing composes two runs (or a run vs a committed reference) into a field-level regression report that separates a real behavioral change from ordinary LLM noise. This spec builds that layer — a reduced per-run scorecard, a typed diff classified against a calibrated per-field noise profile, and a committed golden corpus with a reviewed update path — so the M3 self-improvement loop (which this issue **blocks** via FIX-794) becomes a mechanical "change → re-run → diff → keep/revert."

## 3. Background & Research

### What already exists (this is a compose, not a greenfield build)

Everything below is shipped and merged; the diff layer composes it (BP-029). **Note the real layout: the package has no `src/` — everything is package-root** (`eval/`, `flows/`, `scripts/`, `lib/`).

* **`RunArtifactsBundle`** (`flows/analysis/run-artifacts.ts`, `runArtifactsStateSchema`) — the full per-session scored-artifact bundle, produced by the zero-model `runArtifacts` action and read in-process by the harness. Carries `summary` (a `RunSummary`), `valuationSpine`, `rewardToRisk`, `lensConvergence`, `decisionSnapshot`, `riskMandate`, `portfolioMandate`, `householdTickerWeightPct`, `citationIntegrity`, `hasUserThesis`, `p2Contributions`, and `memos[]` (full bodies). `buildRunArtifacts` is pure and already normalizes unwritten resources to `null` (absent vs malformed) — exactly what a diff needs.
* **`RunSummary`** (`flows/analysis/run-summary.ts`) — the decision projection: `finalRating` (post-clamp), `decisionConfidence`, `targetWeightPct` (read from the PM memo's `portfolioFit`), `direction`/`sizePct`/`stopPrice`/`targetPrice`, mandate gates (`mandateVerdict`, `capacityVetoed`, `rewardToRiskLossAdjustedGlr`, `worstCaseReturnPct`), policy gates (`policyVerdict`, `positionCapClamped`, `excluded`, `preGatePolicyTargetPct`), per-memo status + `memoErrors`.
* **`QualityRecord`** (`eval/types.ts`, `qualityRecordSchema`) — the JSONL scoreboard line: `invariants` (`hardPassed`/`hardFailed`/`softPassed`/`softFlagged`/`skipped` + `failures[{id, detail}]`) and `judges[]` (per-dimension `{mean, std, k, scores, costUsd}`). This is the "quality-score" input the diff compares.
* **`stats.ts`** — `meanStd(xs)` (n−1 std), `standardError(xs)` (std/√n), `krippendorffAlpha(items)`. **Reuse these — do not re-implement.** (There is no `seDiff`; the FIX-790 variance band is inline `2 * standardError`.)
* **`withEvalRuntime` + `EvalRuntime.run`** (`eval/runtime.ts`) — the framework-native execution boundary. The harness runs `analyze` and `runArtifacts` in-process via `runAction`, **not** `fsdev run --capture`. It masks `FSD_DB_URL`/`DATABASE_URL` and sets `TRADING_DESK_DATA_DIR` for per-command PGlite isolation. New modes reuse it verbatim.
* **`scripts/eval-runs.ts`** — the `sweep`/`eval`/`variance` CLI. `parseArgs`, `evalOptions`, `fetchBundle(sessionId, runtime, outDir)`, `writeBundleSnapshot` (persists `<out>/artifacts/<sid>.json`), `mapLimit` (from `lib/concurrency.ts`, default concurrency 2). New modes are added to the same `main()` dispatch.
* **`scoreboard.ts`** — `assembleQualityRecord`, `appendScoreboardLine`, `readScoreboard`, `artifactSnapshotPath`, `detailSidecarPath`. Golden mode reuses `assembleQualityRecord` and the artifact snapshots.
* **`deepEqual` / `looseDeepEqual`** (`@flow-state-dev/core/helpers`, source `packages/contracts/src/helpers/deep-equal.ts`) — the shared equality primitive. There is **no** structural object-diff util in the repo; the diff walker is net-new but domain-specific (a typed field registry, not a generic differ).

### Industry findings (sources)

* **Golden = reduced artifact, not transcript.** For nondeterministic LLM systems the consensus is to snapshot derived fields (scores, ratings, gates, distributions), not the raw output, and compare with tolerance — [Braintrust eval guide](https://www.braintrust.dev/articles/llm-evaluation-guide), [Evidently LLM regression](https://www.evidentlyai.com/blog/llm-regression-testing-tutorial). Naive full-transcript snapshots rot into "just run `--update`" rubber stamps ([Why I stopped writing Jest snapshots](https://dev.to/dorshinar/why-i-ve-stopped-writing-snapshots-tests-in-jest-376d)); the mitigations are (a) a small field-addressable artifact where every field *means* something and (b) treating a golden update as a reviewed act, immutable in CI ([Jest #9235](https://github.com/jestjs/jest/issues/9235)). This is exactly the issue's "summaries + quality scores, not full transcripts."
* **Statistic by field type.** Numeric → mean ± std band from calibration, t-multiplier for small N ([t vs z](https://towardsdatascience.com/a-case-for-the-t-statistic/)); categorical → empirical mode-frequency stability, a first-seen category is *flag for review*, never a hard fail ([Prompt Stability Scoring](https://arxiv.org/pdf/2407.02039)); distribution → total-variation distance (= ½·L1), bounded [0,1], calibrate a per-field TV floor ([TV distance](https://en.wikipedia.org/wiki/Total_variation_distance_of_probability_measures)). No universal magic threshold — calibrate it.
* **Dual output.** One JSON source of truth, Markdown rendered *from* it (never two hand-maintained artifacts); mark four states — `within_noise` / `significant` / `new` / `removed` — not two; signed deltas + a per-field `goodDirection` so "down" reads as improved (cost) or regressed (quality) correctly ([Markdown+JSON](https://mfyz.com/all-you-need-is-markdown-and-json/)).
* **Corpus roll-up + regression budget.** Lead with an aggregate (runs regressed, per-field regression frequency, net improved/regressed) over collapsed per-run detail; gate on a small declarative budget object, not scattered thresholds ([Lighthouse CI budgets](https://unlighthouse.dev/learn-lighthouse/lighthouse-ci/budgets)). Suppress within-noise by default to avoid a wall of flags.

### Why this approach over alternatives

* **A reduced `RunScorecard`, not diffing raw bundles.** Diffing full `RunArtifactsBundle`s would flag every prose wobble (LLM nondeterminism) — permanently red, zero signal. The scorecard keeps only fields that *mean* something and are stable enough to gate. Memo prose is carried as an informational content fingerprint (status + length), never a gating field.
* **A typed field registry, not `deep-object-diff`/`json-diff-ts`.** The fields are a known fixed schema; a static registry (path → kind → `goodDirection` → gating) gives each delta a semantic type and direction that a generic object-differ can't. It also avoids a new npm dependency (CLAUDE.md forbids casual deps; `deepEqual` already covers equality). Generalizing into a framework primitive waits for a second consumer (Non-Goal).
* **Two noise sources, each gating its own field class.** *Run-to-run* structural noise (rating, weight, gates, scenario distribution) is calibrated by the new `calibrate` mode into `NoiseProfile`. *Judge* noise (quality-score deltas) is already characterized per-dimension on the `QualityRecord` (`judges[].std`, FIX-790's variance work) — the diff reuses that `std` as the band for quality fields rather than re-measuring it. This keeps `calibrate` cheap (`--no-judges`) and avoids conflating the two.
* **Reuse `withEvalRuntime` + `assembleQualityRecord`, not a new runner.** Golden mode is sweep-then-project-then-diff; the per-tuple "run analyze → fetch bundle → invariants → (optional) judges → assemble record" is extracted into one `evaluateSession` helper both sweep and golden call.

### Key Decisions & Ramifications (top 5)

1. **The diffable unit is a reduced, identity-blind `RunScorecard` projected from `RunArtifactsBundle` + `QualityRecord`, not the raw bundle.** Alternative rejected: diff bundles directly. *Ramification:* the diff is stable across nondeterministic re-runs and every gating field is semantically meaningful; the cost is a maintained projection (a new field on the bundle isn't diffed until added to the scorecard + `FIELD_REGISTRY`) — an intentional gate, not an omission. Memo prose is informational-only.
2. **Two noise sources: `calibrate` measures run-to-run *structural* spread; quality-score deltas reuse the judge `std` already on the `QualityRecord`.** Alternative rejected: one calibration pass over everything (would re-measure judge noise FIX-790 already records, and pay judge cost during calibration). *Ramification:* `calibrate` runs `--no-judges` (cheap, structural only); a quality-score delta is gated by its dimension's recorded judge std. Locks a dependency on FIX-790's per-dimension `std` being present — absent (older `--no-judges` record) ⇒ quality fields degrade to the `uncalibrated` status (reported, never gates).
3. **"Model vs clamped" rating diffs `modelImpliedRating` (deterministic envelope) vs post-clamp `finalRating` + the `ratingClamped` flag — the raw pre-clamp LLM rating is not recoverable.** The PM discards its raw pick; only the envelope-implied rating and the clamped result persist (confirmed in code). *Ramification:* the diff faithfully shows envelope-vs-final and clamp flips, but cannot show "the LLM wanted X, got clamped to Y" beyond the boolean. Documented in the scorecard's field doc and in Non-Goals; recovering it would need a persistence change out of scope here.
4. **Cost delta is deferred to FIX-792; v1 diffs duration (harness wall-clock) + judge cost only.** No run-level cost field exists on any record. `durationMs` on the bundle is null in-process, so the harness stamps its own wall-clock around the `analyze` `runAction`. *Ramification:* the scorecard reserves a nullable `costUsd` (additive, `null` until FIX-792 fills it) so the diff picks it up later without a schema break; `judgeCostUsd` (sum of `QualityRecord.judges[].costUsd`) is the one cost signal available now.
5. **Goldens are committed under `eval/goldens/` and updated only via an explicit `golden --update`; a hardcoded default budget (passed through `evaluateBudget` as the extension seam) gates the exit code.** Alternative rejected: goldens under `.fsdev/` (gitignored — no PR evidence) or reflexive auto-update; a committed `budget.json` override was also cut (no present consumer, BP-038 — the constant + param seam is enough until a second corpus needs it). *Ramification:* the golden diff is real PR evidence and CI-immutable by construction; the update is a reviewed commit. Multiple-comparison false-flags are handled in v1 by within-noise suppression + the small fixed field set + the budget default (Benjamini–Hochberg FDR is flagged as a follow-up, not built — the corpus is 3 tickers).

### 4.2 Data flow

```

                  { bundle, qualityRecord } per tuple ──buildScorecard──▶ current scorecards
```

### 4.3 `RunScorecard` — `eval/scorecard.ts` (new)

A non-generator zod schema (so `.nullable()`/`.default()` are fine; **do not** add to `output-schemas-strict.spec.ts` — the established resource-schema exclusion). Reduced, identity-blind (no `sessionId`/timestamps; the tuple is the only identity, and it is the golden match key, not a diffed field).

```ts
export const runScorecardSchema = z.object({
  scorecardVersion: z.literal(1),
  // Tuple — match key, NOT diffed
  ticker: z.string(), date: z.string().nullable(),
  costPreset: z.enum(["fast", "full"]).nullable(),
  dataSource: z.enum(["fixture", "live", "record"]).nullable(),
  mandateId: z.string().nullable(),

  runStatus: runStatusSchema,                       // completed | stopped | error

  // Rating (see Decision 3: raw pre-clamp LLM pick is not recoverable)
  modelImpliedRating: ratingSchema.nullable(),      // deterministic envelope
  finalRating: ratingSchema.nullable(),             // post-clamp
  ratingClamped: z.boolean().nullable(),
  decisionConfidence: z.number().nullable(),

  // Sizing
  targetWeightPct: z.number().nullable(),
  preGatePolicyTargetPct: z.number().nullable(),
  direction: z.enum(["long", "short", "flat"]).nullable(),
  sizePct: z.number().nullable(),
  stopPrice: z.number().nullable(),
  targetPrice: z.number().nullable(),

  // Gates (flips are always significant / gating)
  mandateVerdict: z.enum(["clears", "fails"]).nullable(),
  capacityVetoed: z.boolean().nullable(),
  policyVerdict: z.string().nullable(),
  positionCapClamped: z.boolean().nullable(),
  excluded: z.boolean().nullable(),
  rewardToRiskLossAdjustedGlr: z.number().nullable(),
  worstCaseReturnPct: z.number().nullable(),

  // Lens convergence
  lensClassification: z.enum(["convergent", "mixed", "divergent"]).nullable(),
  lensMajorityStance: z.enum(["bullish", "neutral", "bearish"]).nullable(),
  lensNetLean: z.number().nullable(),
  lensAgreementScore: z.number().nullable(),
  lensDissenters: z.array(z.string()).nullable(),   // set field

  // Scenario distribution (names are LLM-unstable → NOT name-matched; §4.3 note)
  scenarioDistribution: z.enum(["concentrated", "balanced", "barbell", "long-tail"]).nullable(),  // the shift signal (categorical)
  scenarioCount: z.number().nullable(),                    // bucket-count change (numeric)
  scenarioProbabilities: z.array(z.number()).nullable(),   // sorted desc; INFORMATIONAL-ONLY in v1 (not gated/classified)
  scenarioEvidenceBasis: z.enum(["sufficient", "thin"]).nullable(),

  // Memos — status per key + content fingerprint (informational, never gates)
  memos: z.array(z.object({
    key: z.string(),
    status: z.enum(["pending", "writing", "published", "error"]).nullable(),
    contentLength: z.number().nullable(),           // body char length; a coarse "content changed" signal
  })),

  // Quality (from QualityRecord; null when no eval / non-completed run)
  quality: z.object({
    hardPassed: z.number(), hardFailed: z.number(),
    softPassed: z.number(), softFlagged: z.number(), skipped: z.number(),
    hardFailureIds: z.array(z.string()),            // set field — a NEW id is significant
    judges: z.array(z.object({
      dimension: z.string(),
      mean: z.number().nullable(),
      std: z.number().nullable(),                   // judge noise band for THIS field (Decision 2)
      k: z.number(),
    })),
  }).nullable(),

  // Cost / duration
  durationMs: z.number().nullable(),                // harness wall-clock (bundle field is null in-process)
  judgeCostUsd: z.number().nullable(),              // Σ QualityRecord.judges[].costUsd
  costUsd: z.number().nullable().default(null),     // RESERVED for FIX-792 (additive)
});
export type RunScorecard = z.infer<typeof runScorecardSchema>;
```

`buildScorecard(bundle: RunArtifactsBundle, qualityRecord: QualityRecord | null, runMeta: { durationMs: number | null }): RunScorecard` is **pure** (the `buildRunSummary`/`buildRunArtifacts` discipline). Field sources, pinned so step 1 doesn't re-derive them:

* **Decision / gate / sizing fields** — **compose the existing `RunSummary` projection**: read `bundle.summary` directly (`finalRating`, `decisionConfidence`, `targetWeightPct`, `direction`, `sizePct`, gates, `preGatePolicyTargetPct`, …) rather than re-deriving from scattered reads (avoids drift).
* **Rating-envelope fields** (`modelImpliedRating`, `ratingClamped`) — **not on `RunSummary`.** They live on the PM memo's resource state (`resources.ts:334`, written as `spine.envelope.implied`; `run-summary.ts` carries only post-clamp `finalRating`). `buildScorecard` reads them off the PM entry in `bundle.memos[]` — the same place `targetWeightPct`'s `portfolioFit` note (above) reads from — **not** off `bundle.summary`.
* **Lens fields** — `bundle.lensConvergence`.
* **Scenario fields** — the scenario memo body: `scenarioDistribution` (enum), `scenarioCount`, `scenarioEvidenceBasis`, and `scenarioProbabilities` (sorted descending, **informational-only** — see the note below).
* **Memos** — `bundle.memos[]` for per-key status + `contentLength`.
* **`quality`** — from `qualityRecord` when present, else `null`.

`scorecardTuple(sc)` and `goldenStem(tuple)` (a filesystem-safe `<ticker>.<date>.<costPreset>.<dataSource>` stem, mandate suffix when set) are exported for golden lookup.

**Why `quality` is nested here (not diffed as a separate `QualityRecord`):** nesting keeps a golden a single self-contained committed file per tuple — one artifact a reviewer reads end to end, one `readGolden`, one match key. The alternative (diff two `QualityRecord`s directly, reusing FIX-790's schema, and avoid mirroring judge dimensions in a third projection) is reasonable and cuts a small amount of projection surface; it is left to the implementer if the self-contained-golden benefit is judged not worth the mirror. Only the fields the diff needs are copied (tallies + per-dimension `{mean, std, k}`), not the whole record.

**Scenario names note:** the LLM names scenarios freely, so the diff's shift signal is the `scenarioDistribution` enum (categorical — `concentrated`→`balanced`, etc.) plus `scenarioCount` (numeric — bucket-count changes). `scenarioProbabilities` (a sorted vector) is carried **informational-only** in v1: reported in the diff output, never gated or classified. This deliberately drops a `distribution`/total-variation NoiseProfile kind that would serve exactly one field — `scenarioDistribution` + `scenarioCount` already answer "did the distribution shape change" (BP-038; per the spec-PR second-look). If the categorical enum proves too coarse in practice, promoting `scenarioProbabilities` to a gated distribution field is a self-contained follow-up.

### 4.4 `NoiseProfile` — `eval/noise.ts` (new)

Per-field run-to-run spread, keyed by tuple with a pooled fallback.

```ts
export const fieldSpreadSchema = z.discriminatedUnion("kind", [
  z.object({ kind: z.literal("numeric"), mean: z.number(), std: z.number(), n: z.number() }),
  z.object({ kind: z.literal("categorical"), freq: z.record(z.number()), mode: z.string().nullable(), n: z.number() }),
]);
export const noiseProfileSchema = z.object({
  noiseVersion: z.literal(1),
  calibratedAt: z.string(),
  perTuple: z.record(z.record(fieldSpreadSchema)),  // stem -> field path -> spread
  pooled: z.record(fieldSpreadSchema),              // field path -> spread, across all tuples
});
export type NoiseProfile = z.infer<typeof noiseProfileSchema>;
```

`buildNoiseProfile(scorecards: RunScorecard[]): NoiseProfile` groups by `goldenStem`, and for each field in `FIELD_REGISTRY` computes the kind-appropriate spread over that group (and over all cards for `pooled`):

* **numeric** → `meanStd(values)` (reuse `stats.ts`); band later = `k · std` (default `k = 2`, with a t-multiplier note for small N in the doc).
* **categorical/boolean** → `categoricalFrequency(values)` → `{ freq, mode, n }`.

Only two kinds — there is no `distribution` kind (dropped per the second-look; see the scenario note in §4.3). One new local helper (small, pure, in `noise.ts`): `categoricalFrequency(values: (string|null)[])`. `standardError`/`meanStd` come from `stats.ts`; `krippendorffAlpha` is available for an optional corpus-wide categorical-stability roll-up in the golden report (not required for gating).

### 4.5 `diff.ts` — the typed field diff (new)

A static `FIELD_REGISTRY: FieldSpec[]` — one entry per diffed field: `{ path, kind: "numeric"|"categorical"|"set", goodDirection?: "up"|"down"|"neutral", gating: boolean }`. `diffScorecards` walks it, reads `golden[path]` / `current[path]`, and emits a `FieldDelta` per changed field:

```ts
export const fieldDeltaSchema = z.object({
  path: z.string(),
  kind: z.enum(["numeric", "categorical", "set"]),
  before: z.unknown(), after: z.unknown(),
  delta: z.unknown(),          // numeric: signed number+pct; categorical: {from,to}; set: {added,removed}
  status: z.enum(["unchanged", "within_noise", "significant", "uncalibrated", "new", "removed"]),
  goodDirection: z.enum(["up", "down", "neutral"]).nullable(),
  regressed: z.boolean(),      // status significant/new/removed in the bad direction (goodDirection-aware); uncalibrated never regresses
  evidence: z.string(),        // the band/floor that produced status ("|Δ|=0.04 > 2·std=0.02", "TV=0.31 > floor=0.12", "first-seen category", "uncalibrated — no noise profile")
});
export type RunDiff = {
  tuple: ScorecardTuple;
  fields: FieldDelta[];
  summary: { unchanged: number; withinNoise: number; significant: number; uncalibrated: number; added: number; removed: number };
  gateFlips: FieldDelta[];     // gating fields that changed at all
  regressed: boolean;          // any gating flip, status regression, or new hard-invariant failure
};
```

**Classification per kind** (noise-aware; `noise` is the tuple's spread, falling back to `pooled`, else `null`):

| Kind | unchanged | within_noise | significant | new / removed |
| -- | -- | -- | -- | -- |
| numeric | `looseDeepEqual` / `|Δ| == 0` | `|Δ| ≤ k·std` (from `NoiseProfile`) | `|Δ| > k·std` | value ↔ null (`removed`/`new`) |
| categorical / boolean | equal | new value present in `freq` with non-trivial frequency | changed to a calibrated-but-different value | value never seen in `freq` ⇒ **`new`** (flag for review, never a hard fail — research caveat) |
| set (dissenters, hardFailureIds, memo keys) | equal sets | — | — | added elems ⇒ `new`, removed ⇒ `removed` |

(No `distribution` kind — `scenarioProbabilities` is informational-only, §4.3.)

**Gating fields never need calibration.** A `gating: true` field (the gates `mandateVerdict`/`capacityVetoed`/`policyVerdict`/`positionCapClamped`/`excluded`, `runStatus`, `ratingClamped`, and the `set` fields — `hardFailureIds`, `dissenters`, memo keys) is exact-match: any change is `significant` (or `new`/`removed`) and `regressed`, **with or without a noise profile**. Calibration only governs the *magnitude* question for **non-gating** numeric fields and the *is-this-value-normal* question for non-gating categoricals. This is load-bearing: it means a two-run `diff` with no `noise-profile.json` still flags a gate flip / status regression / new hard-failure and exits non-zero — the `uncalibrated` fallback below applies **only to non-gating numeric/categorical fields**, so the no-profile path can never exit 0 on the clearest regressions.

**Quality fields** use the judge `std` carried on the *current* scorecard's `quality.judges[].std` (Decision 2), not the `NoiseProfile`. **Without any noise input** (a two-run `diff` with no `noise-profile.json`), a **non-gating** numeric/categorical field that actually changed is classified **`uncalibrated`** — the dedicated status in the enum above, always `regressed: false`, `evidence: "uncalibrated — no noise profile"`. It surfaces the delta honestly (not hidden as `within_noise`) without asserting significance, and never gates. The output header notes the profile was absent. `regressed` respects `goodDirection`: a lower `judge mean` or a higher `hardFailed` regresses; a lower `judgeCostUsd`/`durationMs` does not.

### 4.6 `golden.ts` — golden IO, report, budget, render (new)

* `GOLDENS_DIR = <package>/eval/goldens`. `readGolden(tuple): RunScorecard | null` (parse `<stem>.json`), `writeGolden(tuple, sc)` (pretty JSON, stable key order for clean PR diffs). `readNoiseProfile()` / `writeNoiseProfile(np)`.
* `buildGoldenReport(diffs: RunDiff[]): GoldenReport` — corpus roll-up: `runsRegressed` count, `perFieldRegressionFreq` (field path → how many runs regressed it — the systemic-vs-one-off signal), `netImproved` / `netRegressed`, and the per-run `diffs` (collapsed). Leads with the aggregate.
* `evaluateBudget(report, budget): { pass: boolean; reasons: string[] }` — a pure function taking the budget as a param (the extension seam). v1 passes a **hardcoded `DEFAULT_BUDGET` constant** in `golden.ts` (no committed `budget.json` — a single 3-ticker corpus has no present need to vary it, BP-038; reintroduce the file the day a second corpus or a real threshold change appears). The default: fail on any **gate flip**, any **status regression** (`completed`→`stopped`/`error`), any **new hard-invariant failure id**, or `significant` field regressions `> maxSignificantRegressions` (default `0`). `within_noise`, `uncalibrated`, and first-seen categorical `new` never gate (the rare-but-normal caveat).
* `renderDiffMarkdown(report | runDiff): string` — rendered *from* the JSON (single source of truth). Significant-first table, `within_noise` folded, signed deltas with ▲/▼ and improved/regressed coloring via `goodDirection`, the corpus roll-up header on top.

### 4.7 CLI — `scripts/eval-runs.ts` (edit)

Extract the sweep inner loop into `evaluateSession(input, runtime, opts): { bundle, qualityRecord, durationMs }` (wall-clock stamped around the `analyze` `runAction`; runs `checkRun` always, `runJudges` unless `--no-judges`; `assembleQualityRecord`). `sweep` calls it; the new modes reuse it.

```
pnpm eval diff      --a <sessionId> --b <sessionId>  [--out ...] [--data-dir <path>] [--json <path>] [--md <path>]
pnpm eval golden    --manifest <corpus.json> [--update] [--no-judges] [--out ...] [--concurrency 2] [--json <path>] [--md <path>]
pnpm eval calibrate --manifest <fixed.json> --n <N>  [--out ...] [--concurrency 2]     # writes goldens/noise-profile.json
```

* **`diff`** reads two stored sessions' bundles (`runtime.run("runArtifacts", {}, id)`, the `fetchBundle` idiom) or two `<out>/artifacts/<sid>.json` snapshots. **Quality fields come from the `QualityRecord`, which is not in the bundle** (it lives in `scoreboard.jsonl`), so `diff` also resolves each session's `QualityRecord` before `buildScorecard`: read `<out>/scoreboard.jsonl` via `readScoreboard` and match by `sessionId` (or re-run the eval layer for the session). If no matching record is found, `quality: null` and the header notes the diff is **structural-only** for that side (so a dropped quality signal is explicit, never silent). It then builds scorecards, loads `goldens/noise-profile.json` if present, and prints `RunDiff` JSON + Markdown. Exit non-zero when `diff.regressed`.
* **`golden`** runs the corpus via `evaluateSession` under `mapLimit`, builds current scorecards. **Isolation follows the exact `sweep` model** (`eval-runs.ts:221-227`): one `withEvalRuntime({ dataDir })` backing per command (`<out>/data`), each run keyed by a distinct session id (`golden_<ticker>_<index>_<stamp>`) — one framework runtime owns the backing and session ids isolate each run's state under `mapLimit`. No per-tuple `mkdtemp`. `--update` ⇒ `writeGolden` each (no gate, reviewed act). Else ⇒ diff each vs `readGolden`, `buildGoldenReport`, render, `evaluateBudget` → exit code. A missing golden with no `--update` is a hard error (CI-immutable, the Jest `--ci` rule), not a silent pass.
* **`calibrate`** runs the fixed manifest `--n` times each (`--no-judges`), builds scorecards, `buildNoiseProfile`, writes `goldens/noise-profile.json`. Same isolation model as `golden`/`sweep`: one backing per command, distinct session id per repeat under `mapLimit`. Records the measured bands into `docs/run-regression.md` (manual, like FIX-790's variance bands).

## 6. Edge Cases & Error Handling

| Case | Behavior |
| -- | -- |
| Two-run `diff` with no `noise-profile.json` | Non-gating numeric/categorical deltas get the `uncalibrated` status (`regressed: false`); **gating fields (gates, `runStatus`, `ratingClamped`, set fields) still flag `significant`/`regressed` and exit non-zero** — the no-profile path never passes a real gate flip; header notes the profile is absent |
| `diff` over sessions with no matching `scoreboard.jsonl` entry | `QualityRecord` unresolved ⇒ `quality: null`, header marks the diff **structural-only** for that side (quality-score deltas explicitly dropped, never silent); pass `--out <sweep-out>` to point at the scoreboard |
| Golden missing for a corpus tuple, no `--update` | Hard error, non-zero exit (CI-immutable) — never a silent pass |
| Golden present but scorecard schema drifted (`scorecardVersion` mismatch) | Fail loudly with a "re-run `golden --update`" message; never diff across versions |
| Stopped run (`runStatus: "stopped"`) vs completed golden | `runStatus` gate flip ⇒ `regressed`; decision/quality fields diff null-vs-value as `removed`; budget fails on the status regression |
| `quality` null (`--no-judges` or non-completed) on one side | Quality fields diff null-vs-value as `new`/`removed`; judge-mean fields skipped (no `std` to gate); noted in evidence |
| Scenario bucket count changed (3↔5) | caught by the `scenarioCount` numeric delta + a `scenarioDistribution` enum shift; `scenarioProbabilities` is informational-only (no per-name churn, no TV gate) |
| First-seen categorical value (rating/classification never in calibration) | Status `new`, flagged for review, **does not** hard-fail the budget (small-N rare-but-normal caveat) |
| Memo prose changed but status same | `memos[].contentLength` delta reported as informational; never gates (LLM prose always wobbles) |
| `modelImpliedRating` vs `finalRating` when clamped | Both diffed + `ratingClamped` flip shown; the raw pre-clamp LLM pick is not available (Decision 3) |
| `calibrate` with N=1 | Std = 0 for numeric (single sample) → every later delta reads `significant`; the mode warns and requires N≥3 |
| Concurrent `golden`/`calibrate` runs under `mapLimit` | Safe by the sweep model: one in-process framework runtime + one backing per command, each run keyed by a distinct session id (`eval-runs.ts:221-227`) — no per-tuple dirs, no cross-process PGlite contention (all runs share the single in-process backing) |
| `durationMs` null (bundle field) | Harness stamps wall-clock around the `analyze` `runAction`; if a run errored before timing, `durationMs: null` and the duration field is skipped |
| Cost delta requested | Not available in v1 — `costUsd` reserved null (FIX-792); only `judgeCostUsd` diffs |

Error taxonomy: a per-run evaluation failure inside `golden`/`calibrate` records a `runStatus: "error"` scorecard and continues the corpus (sweep precedent); only manifest/golden-IO/version-mismatch is fatal. `diff`/`golden` exit non-zero on regression (agent-loop + CI gate); `calibrate` exits non-zero only on IO failure.

## 7. Testing Strategy

**Discipline:** `fsd:tdd` (Feature label) — red-green-refactor, vertical tracer bullets. Tracer bullet: step 1+3 on two hand-authored scorecards → a printed `RunDiff`, before any golden IO or CLI exists.

**Goal & goal check (required).** *Goal:* a maintainer (or agent loop) can tell a real behavioral regression from ordinary LLM noise with one command, and updating the reference is a reviewed act. *Goal check (real-model, out-of-CI):* `goals/trading-desk-regression/golden-diff-flags-regression/run.mts`. It exercises the real path once, then proves both diff directions deterministically:

1. `pnpm eval golden --manifest <2-tuple fixture (NVDA + AAPL, fast)> --update --out <tmp>` — real `analyze` runs end-to-end (fixture stubs data, real models), writing current scorecards as goldens into a **temp** dir (never the committed `eval/goldens/`).
2. Re-diff the same scorecards vs those goldens → assert **0 significant regressions, 0 gate flips, budget passes** (no false alarm on identical input — the diff engine + render path).
3. Load one golden scorecard, **programmatically mutate** it (flip `mandateVerdict` `clears`→`fails` and bump `targetWeightPct` beyond a synthetic band), diff the real current scorecard vs the mutated golden → assert the gate flip is `significant`/`gateFlips` non-empty, `regressed === true`, and `evaluateBudget` **fails** (non-zero).

Pass/fail: print `PASS — no false alarm + regression detected` / `FAIL — <detail>`, exit 0/1. **Anti-game:** step 2 reads the real scorecards (a stub that emits identical bytes for both tickers is caught because the two tuples' scorecards must differ — the FIX-790 goal's anti-stub idiom); step 3's mutation is on a real field the budget gates, so a no-op diff engine fails it. This is the real-path judge the unit specs can't provide. (Follows `goals/README.md` + the `goals/trading-desk-eval/fixture-batch-scored/run.mts` shape: `execFileSync("pnpm", ["eval", …], { cwd: APP })`, import eval helpers by relative path, PASS/FAIL + `process.exit`.)

**CI specs (mocked, deterministic, `labs/trading-desk/test/`):**

1. `buildScorecard` — completed / stopped / memo-error / mandate-blind / scenario-sorted / quality-filled (unit, offline). *(step 1)*
2. `buildNoiseProfile` — numeric mean/std, categorical freq+mode, per-tuple vs pooled (unit, pure). *(step 2)*
3. `diffScorecards` — numeric in/over band, categorical mode-known vs first-seen `new`, set add/remove, gate flip ⇒ regressed, new `hardFailureId`, quality gated by judge `std`, uncalibrated degrade (unit, pure). *(step 3)*
4. `golden.ts` — golden round-trip, report roll-up, budget pass/fail, markdown-from-JSON significant-first (unit). *(step 4)*
5. **Registry↔schema sync** — every `FIELD_REGISTRY` path resolves on `runScorecardSchema` (a `.shape` walk), so a scorecard field rename can't silently drop a diffed field (projection-drift guard). *(step 3)*

Reference patterns: `test/composite-math.spec.ts` + `test/report-summary-aggregate.spec.ts` (pure projection/check tests), `eval/stats.ts` (the reuse target), `goals/trading-desk-eval/fixture-batch-scored/run.mts` (goal-check shape).

## 8. Non-Goals

* **Cost deltas** — no run-level cost field exists until FIX-792; v1 diffs duration (harness wall-clock) + `judgeCostUsd`. `costUsd` is reserved null so FIX-792 lights it up additively.
* **Recovering the raw pre-clamp LLM rating** — not persisted (Decision 3); the diff shows `modelImpliedRating` vs `finalRating` + `ratingClamped`, not the LLM's discarded pick.
* **CI wiring / nightly fixture-batch + diff** — explicitly not v1 (the issue's own boundary); a natural follow-up once the golden corpus is stable.
* **Live-mode goldens** — goldens cover fixture-mode runs only (live inputs are non-reproducible; the issue's boundary).
* **Benjamini–Hochberg / FDR multiple-comparison correction** — v1 relies on within-noise suppression + the small fixed field set + the budget object; FDR across the corpus's significance tests is a flagged follow-up (the corpus is 3 tickers, so false-flag pressure is low). Recorded so a later scale-up knows where to add it.
* **Memo prose diffing as a gate** — LLM prose wobbles run-to-run; `contentLength` is informational only. A semantic prose-similarity judge would be an eval-suite (FIX-790) extension, not a diff gate.
* **Generalizing the diff into a framework primitive** — the `FIELD_REGISTRY` is desk-shaped; lifting a generic "scorecard diff" into the CLI or a shared package waits for a second consumer (BP-024/BP-038).
* **A `distribution` NoiseProfile kind + total-variation gating** — cut in v1 (second-look): it would serve exactly one field (`scenarioProbabilities`), and `scenarioDistribution` (categorical) + `scenarioCount` already signal the scenario-distribution shift the issue asks for. `scenarioProbabilities` stays informational-only; promote it to a gated distribution field if the categorical enum proves too coarse.
* **A committed `goldens/budget.json` override** — cut in v1 (second-look): a single 3-ticker corpus has no present need to vary the budget. `evaluateBudget(report, budget)` keeps the param seam; the default is a constant. Reintroduce the file when a second corpus or a real threshold change appears (and its shape will be known then).
* **Deepening opportunities flagged during analysis** (follow up via `fsd:improve-codebase-architecture`):
  * No repo-wide structural object-diff/golden-file util exists — each consumer (FIX-790's `blindBundle`/`stripRunIdentity`, now this diff) hand-rolls its comparison. A shared `@flow-state-dev/testing` golden-diff primitive is worth considering once a second non-desk consumer appears.

  * FIX-790 flagged `analyzerScorer`'s finding-schema field order + dropped per-finding evidence in `packages/testing`; unrelated to this diff but adjacent when quality-score provenance is surfaced.
