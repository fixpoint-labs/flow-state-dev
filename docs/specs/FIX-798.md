# FIX-798: Trading-desk: add Alpha Vantage as a data provider — Implementation Spec

## 1. TLDR

**Plain-language summary.** The trading desk pulls market data from several outside services (Finnhub, Yahoo, FRED, and others). A few of its data tools have only one source, so when that source has no key or fails, the desk gets nothing. Two tools were half-built against a service that was never finished and return empty in live mode. This adds **Alpha Vantage** as a new data source that fills those gaps: it finishes the two half-built tools (earnings-call transcripts and analyst estimates) and gives the insider-trades tool a second source to fall back on. Alpha Vantage's free plan only allows 25 requests a day, so this also adds a simple in-process daily-usage guard that stops calling it once the day's budget is spent (one setting, `ALPHAVANTAGE_DAILY_LIMIT`, turns it off by setting it to 0 for a paid plan). It does **not** try to make Alpha Vantage the *preferred* source anywhere, or wire it into every tool — that's deliberately left to follow-up work.

**Technical statement.** Add an `alpha-vantage` provider module (key gate, a shared request helper that treats AV's HTTP-200 `Note`/`Information`/`Error Message` rate-limit bodies as failures, and a race-free in-process daily-budget guard governed by a single `ALPHAVANTAGE_DAILY_LIMIT` knob), then wire it as the live provider for the two stubbed tools (`get_earnings_transcript`, `get_analyst_estimates`) and as a terminal fallback for `get_insider_transactions`.

**Deliverables:**

- **Provider (foundation):** Add `labs/trading-desk/lib/providers/alpha-vantage.ts` — `hasAlphaVantageKey()`, a shared `alphaVantageRequest()` helper (rate-limit-body → throw + race-free budget reserve), a single-knob (`ALPHAVANTAGE_DAILY_LIMIT`, `0`=off) in-process daily-budget guard (`_resetBudget()` test hook), and the fetch functions for transcript, analyst enrichment, and insider transactions.
- **Schema:** Add `"alphavantage"` to the `sourceTag` enum in `labs/trading-desk/flows/analysis/tools/schemas.ts`.
- **Stub 1 — transcript:** Rewrite `get_earnings_transcript.ts` to fetch AV `EARNINGS_CALL_TRANSCRIPT` (latest reported quarter resolved via an `EARNINGS` probe) in live mode.
- **Stub 2 — estimates:** Extend `get_analyst_estimates.ts` to enrich the Finnhub baseline with AV `OVERVIEW` (price targets) + `EARNINGS_ESTIMATES` (forward consensus).
- **Fallback — insider:** Add AV `INSIDER_TRANSACTIONS` as the terminal fallback in `get_insider_transactions.ts`, before `emptyPayload`.
- **Tests:** Add `test/alpha-vantage.spec.ts` (request helper, rate-limit-body, budget guard) + per-tool live-path specs.
- **Docs:** Add `ALPHAVANTAGE_API_KEY` + `ALPHAVANTAGE_DAILY_LIMIT` (with the burst/serverless caveats) to `labs/trading-desk/README.md`; update the three tool-inventory bullets; add `ALPHAVANTAGE_API_KEY` to the provider-keys paragraph in `apps/docs/guides/trading-desk-walkthrough.md`.

**Size estimate.** **Medium** (1 provider module + 3 tool edits + schema + tests + docs; ~350–500 LOC; 1 PR). Optionally splittable as *provider module + budget → then tool wiring*, but cohesive enough for one PR.

## 2. Overview

Linear issue: [FIX-798](https://linear.app/fixpoint-labs/issue/FIX-798/trading-desk-add-alpha-vantage-as-a-data-provider-fallback-coverage)

The desk's live data layer has single-provider dead-ends (a tool degrades straight to an empty payload when its one provider fails) and two tools that were scaffolded against FMP but never wired, so they return `unavailable` in live mode. This spec adds Alpha Vantage — a NASDAQ-licensed source whose free tier covers company overview, the three statements, earnings estimates, earnings-call transcripts, insider transactions, news sentiment, and economic indicators — as the foundation that closes those gaps, under a daily-budget discipline that keeps the free tier's 25-requests/day cap from being silently burned. It is deliberately the **foundation**: it establishes the provider module, the budget machinery, and the `alphavantage` provenance tag that the whole AV follow-on family (FIX-799/800/801/802/803/804) builds on.

## 3. Background & Research

### The Alpha Vantage free-tier constraint (the reason this is not "just add a provider")

The AV free tier is **25 requests/day, 5 requests/minute** (verified June 2026; the daily cap fell 500 → 100 → 25 over time). A full-preset desk run fans ~20 generator calls across nine analysts; naive wiring would exhaust 25/day in a single multi-ticker session. Two facts shape the design:

1. **AV signals rate-limit/exhaustion with an HTTP 200 body**, not an error status: `{ "Note": "...call frequency..." }`, `{ "Information": "...premium..." }`, or `{ "Error Message": "..." }`. A fetcher that trusts the status code would treat a throttle message as data. The shared request helper must detect these bodies and throw. This is the single most important correctness property of the provider.
2. **The fetch cache (`lib/cache.ts`) is process-scoped, 120s TTL** — it collapses concurrent same-key reads within a run but does not persist across runs, so AV calls are unprotected day-over-day.

The Note-body handling already gives **honest degradation** on real exhaustion (the tool sees a throw → degrades to the next fallback / `emptyPayload`, tagged `unavailable` in the transcript — visible, not silent). The budget guard adds *proactive* avoidance: stop spending calls that will fail anyway, and keep a single process's usage bounded. Cross-run/persistent budget enforcement is a bigger concern that belongs with the composition/procurement work (FIX-675) and the (now-shipped, but per-session) spine (FIX-758) — out of scope here (see §8, §11).

### Verified AV endpoint shapes (against the live `demo` endpoint)

- **`INSIDER_TRANSACTIONS`** → top-level `data[]`; each element `{ transaction_date, ticker, executive, executive_title, security_type, acquisition_or_disposal, shares, share_price }` (all strings). No SEC transaction code (P/S/A/M) and no separate filing date — the map to the desk's `insiderTransactionItem` is lossy and approximated (see §4).
- **`EARNINGS_CALL_TRANSCRIPT`** → `{ symbol, quarter, transcript[] }`; each element `{ speaker, title, content, sentiment }`. Requires a `quarter` query param (e.g. `2024Q1`) — the fetcher resolves it via an `EARNINGS` probe (see §4), and the fiscal-vs-calendar label needs confirming against the live API.
- **`OVERVIEW`** → includes `AnalystTargetPrice` and `AnalystRatingStrongBuy/Buy/Hold/Sell/StrongSell` (all strings). Supplies the price-target consensus.
- **`EARNINGS_ESTIMATES`** → forward EPS / revenue consensus with analyst counts. Supplies `consensusEstimates`.

### How the codebase already solves this

The desk has a mature **single-provider module convention** (`lib/providers/{finnhub,fred,massive,xai,fmp}.ts`): each reads its own env key, exposes `hasXKey()`, and its fetch functions **throw on any failure** so a calling tool falls through with one `try {} catch {}`. `finnhub.ts` is the closest template (reads `FINNHUB_API_KEY` itself, throws on non-2xx/parse). The tool dispatch convention is `resolveToolPayload(tool, input, ctx, fetchLive)` (`runtime/resolve.ts`) branching fixture / live / record; the live closure gates on `hasXKey()`, tries providers in order, and ends in `emptyPayload`. `get_fundamentals` (Finnhub → Yahoo → empty) is the canonical multi-provider chain; AV simply becomes the terminal link where its shape fits.

### Why this approach over alternatives

- **AV as terminal fallback, never primary.** "AV as candidate primary" and per-signal preference are the **FIX-675** bake-off's call (Backlog). Making AV primary here would pre-empt a data-quality decision this spec has no evidence for. AV stays last in each chain (and *completes* the two stubs, where it's the only live provider).
- **Do not consume the FIX-805 resolver.** The generalized availability resolver (FIX-805) is Backlog; consuming it would block FIX-798 on unbuilt work. Use the established per-tool `try/catch` convention — FIX-805 later refactors all chains uniformly (this tool included).
- **In-process daily-budget guard, not DB-backed.** The provider layer is currently pure HTTP with no persistence, and the desk's DB (PGlite/Postgres) is reached only from `db/` + server. A process-scoped counter (reset on UTC-day roll, disabled by setting `ALPHAVANTAGE_DAILY_LIMIT=0`) is proportionate: the Note-body handling is the real exhaustion safety net; persistent cross-run accounting is FIX-675/procurement territory. Documented limitation, not a silent gap.
- **Fallback list scoped to clean, unowned shape matches.** Insider (`INSIDER_TRANSACTIONS`) maps 1:1 and no follow-on owns it. Macro-via-AV is deferred to **FIX-802** (AV covers only ~4 of the 9 FRED series `get_macro_indicators` needs, each a separate endpoint — budget-expensive for a partial fill), and social/news-via-AV to **FIX-799** (`get_social_sentiment` is X/Twitter chatter; AV `NEWS_SENTIMENT` is news articles — a different modality, dishonest to merge). Confirmed with the issue owner.

### Key Decisions & Ramifications (top 5)

1. **AV is terminal fallback + stub-completer, never a primary or preferred source.** *Alternative rejected:* make AV primary for fundamentals/overview per the paid-tier framing. *Ramification:* keeps FIX-798 independent of the FIX-675 bake-off (Backlog) and evidence-free of a data-quality claim; the "AV as primary" upside is unrealized until FIX-675 lands.
2. **Rate-limit detection lives in one shared `alphaVantageRequest()` helper.** *Alternative rejected:* per-fetcher Note checks. *Ramification:* every AV fetch (this issue's and all follow-ons') inherits correct exhaustion handling for free; the helper is the load-bearing contract the AV family depends on.
3. **Process-scoped daily-budget guard, single `ALPHAVANTAGE_DAILY_LIMIT` knob (0=off); no DB, no tier concept.** *Alternative rejected:* DB-backed cross-run counter, and a separate `ALPHAVANTAGE_TIER` flag. *Ramification:* simple, no new provider-layer dependency, no speculative tier vocabulary (BP-038); correct-enough given Note-handling; does **not** enforce 25/day across process restarts (documented). Cross-run persistence deferred to FIX-675.
4. **Complete the two stubs via AV, not FMP.** *Alternative rejected:* finally wire the FMP module the stubs were scaffolded for. *Ramification:* one provider (AV) covers both stubs + insider, so we don't stand up a second new provider (FMP) in this issue; the `fmp.ts` key-check stub becomes dead code (left in place, not removed — pre-existing, out of this diff's ownership) and README FMP-required wording is corrected to AV.
5. **Fallback list = insider + the two stubs only; macro and social deferred.** *Alternative rejected:* wire all of outcome #3's insider+macro+social. *Ramification:* avoids modality-dishonest social wiring and budget-expensive partial macro fills, at the cost of `get_macro_indicators`/`get_social_sentiment` keeping their current single-provider dead-ends until FIX-802/FIX-799. Confirmed with the owner.

### API surface — the provider module

```ts
// lib/providers/alpha-vantage.ts

const AV_BASE = "https://www.alphavantage.co/query";

/** True when an Alpha Vantage key is configured. */
export function hasAlphaVantageKey(): boolean {
  return Boolean(process.env.ALPHAVANTAGE_API_KEY?.trim());
}

/** Shared request. Injects `apikey=ALPHAVANTAGE_API_KEY` (callers pass only
 *  the endpoint params — `function`, `symbol`, etc.), reserves one unit of the
 *  daily budget synchronously (atomic check-and-increment, before any await —
 *  see below) then fetches, and treats AV's HTTP-200 rate-limit / exhaustion /
 *  error BODIES as failures (throw). Throws AlphaVantageBudgetError when the
 *  day's budget is already spent, and on non-2xx, JSON parse failure, or a
 *  Note/Information/Error Message body. */
export async function alphaVantageRequest(
  params: Record<string, string>,   // endpoint params only; apikey is added here
): Promise<Record<string, unknown>>;

// Fetchers — each throws on any failure so the calling tool falls through
// with one try/catch, per the provider convention.
export async function fetchAlphaVantageEarningsTranscript(
  input: { ticker: string; date: string },
): Promise<ToolOutput<"get_earnings_transcript">>;

export async function fetchAlphaVantageAnalystEnrichment(
  ticker: string,
): Promise<Pick<ToolOutput<"get_analyst_estimates">, "consensusEstimates" | "priceTargets">>;

export async function fetchAlphaVantageInsiderTransactions(
  input: { ticker: string; date: string },
): Promise<ToolOutput<"get_insider_transactions">>;

/** Test hook — reset the in-process daily counter between specs. Not in the barrel. */
export function _resetBudget(): void;
```

**Budget guard (in-process, race-free) — one knob, no tier concept.** A single env `ALPHAVANTAGE_DAILY_LIMIT` governs the guard: default `25`, and **`0` disables it entirely** (the "unlimited" sentinel for a paid plan). There is deliberately no `ALPHAVANTAGE_TIER` / `isAlphaVantagePaidTier()` — a tier vocabulary would be marketing surface with one internal consumer (BP-038); "set the limit to 0" both honors the issue's "no-op on a paid tier" and keeps the provider's public API to `hasAlphaVantageKey()` + fetchers + `_resetBudget`.

The check-and-reserve must be **atomic — a synchronous block with no `await` between the read and the increment** — because the desk fans analysts out concurrently; a check-then-increment-on-success design would let several parallel calls all pass `count < limit` before any increments (a TOCTOU race that burns past the cap). At the very top of `alphaVantageRequest`, before the `await fetch`:

```ts
// Parse defensively: ONLY a literal "0" disables the guard. A blank, negative,
// non-integer, or non-numeric value must NOT silently switch protection off —
// it falls back to the 25 default. (Naïve `Number(env ?? 25)` fails here:
// Number("") === 0 and Number("typo") === NaN both make `limit > 0` false,
// disabling the guard on a misconfiguration.)
const raw = process.env.ALPHAVANTAGE_DAILY_LIMIT?.trim();
const parsed = raw === undefined || raw === "" ? 25 : Number(raw);
const limit = Number.isInteger(parsed) && parsed >= 0 ? parsed : 25;
if (limit > 0) {                             // exactly 0 → guard disabled (paid/unlimited)
  const today = new Date().toISOString().slice(0, 10);   // UTC day
  if (budget.dayUtc !== today) { budget.dayUtc = today; budget.count = 0; }  // day roll
  if (budget.count >= limit) throw new AlphaVantageBudgetError(limit);
  budget.count += 1;                         // reserve synchronously — before any await
}
// ...then await fetch(...)
```

The parse is **fail-safe, not fail-open**: the only way to turn the guard off is to set the value to exactly `0`. Everything the env could hand us that *isn't* a clean non-negative integer — empty string, whitespace, `"twenty"`, `"-5"`, `"25.5"` — resolves to the `25` default rather than to "disabled," so a typo tightens protection instead of removing it.

The reservation is **not rolled back** on a downstream fetch failure. This is deliberate and cuts two ways in our favor: (a) it's race-free (the whole check-increment is synchronous); (b) **every attempted call counts — including one that comes back as a `Note`/`Information` throttle body** — so the counter never shows headroom after AV's server-side quota is actually spent (it errs toward stopping slightly early, never toward over-spending). A rare transport error that never reached AV costing one reserved unit is the acceptable trade. Callers catch `AlphaVantageBudgetError` like any other AV failure → degrade.

**Per-minute limit (5/min) is a real, separate constraint.** In normal dev the 5/min cap binds *before* 25/day: a single disclosure fan-out can fire the transcript probe + transcript (2) and the estimates enrichment (2) within seconds, and two back-to-back runs inside 60s will throttle on a later call via a `Note` body — degrading honestly, but with no proactive guard. v1 does **not** add a token bucket; it documents the burst pattern (README + §6) and uses `Promise.allSettled` for the independent enrichment calls so one throttle doesn't reject the other. A per-minute token-bucket / inter-call delay (via `lib/concurrency.ts`) is a named v2 follow-up, not required here.

**API key injection (required):** `alphaVantageRequest` appends `apikey=process.env.ALPHAVANTAGE_API_KEY` to every request — callers pass only the endpoint params (`function`, `symbol`, `quarter`, …). AV lists `apikey` as required for all query endpoints; a request that omits it comes back as an HTTP-200 `Information` body (which the helper then throws on), so a configured key that never reaches the URL would make every live branch degrade to `unavailable` despite the key being set. Centralizing the key here (not per-fetcher) means every AV fetcher — this issue's and all follow-ons' — inherits it. The `hasAlphaVantageKey()` gate stays the caller's cheap pre-check; the helper is the single place the key is actually attached.

**Rate-limit body detection:** after `JSON.parse`, if the object has any of the keys `Note`, `Information`, or `Error Message` → `throw new AlphaVantageRateLimitError(body[key])`. Otherwise return the parsed object.

### Data flow — per tool

**`get_earnings_transcript`** (was: always `emptyPayload` in live mode):
```
resolveToolPayload → live closure:
  if (hasAlphaVantageKey()) { try { return await fetchAlphaVantageEarningsTranscript(input); } catch {} }
  return emptyPayload("get_earnings_transcript", input);
```
`fetchAlphaVantageEarningsTranscript`: **resolve the latest *reported* fiscal quarter as-of `input.date`, not the calendar quarter.** Calendar-quarter derivation is wrong for companies with offset fiscal years and for as-of dates that fall before the current quarter's call — it would request an unreported quarter and return `available: false` even when a recent transcript exists, and the disclosure prompt expects the *latest* call. So: (1) call `EARNINGS&symbol` → pick the most recent `quarterlyEarnings[]` entry whose `reportedDate` is on-or-before `input.date`; (2) call `EARNINGS_CALL_TRANSCRIPT&symbol&quarter` for that quarter.

**Quarter-label caveat (verify at implementation):** the transcript endpoint's `quarter` param uses AV's *fiscal-quarter* label (`YYYYQn`), and for issuers on a non-calendar fiscal year a naïve `fiscalDateEnding`→calendar-quarter mapping is wrong — e.g. Apple's FY2024 Q1 ends Dec 2023, so mapping the date gives `2023Q4` while AV expects `2024Q1`, returning empty even though the call exists. The `fiscalDateEnding` date alone doesn't carry the fiscal-year label. So the implementer must **confirm AV's expected label format against the live API during the record step** and derive the fiscal label accordingly; as a robustness fallback, if the first label yields an empty `transcript[]`, retry once with the alternate (calendar-quarter) label before concluding `available: false`. If the `EARNINGS` probe itself fails or is budget-blocked, fall back to the most-recent-completed calendar quarter as a best-effort. Map: `content` ← the `transcript[]` entries joined as `"{speaker} ({title}): {content}"`, capped to a prompt-safe length; `quarter` ← the resolved quarter; `callDate` ← the resolved `reportedDate` when available, else `null`; `available` ← `transcript.length > 0`; `source` ← `"alphavantage"`. **Budget note:** this is two AV calls (probe + transcript) — acceptable for once-per-run reference data, and both pass through the budget guard.

**`get_analyst_estimates`** (was: Finnhub ratings + surprises; consensus/targets hard-null):
```
resolveToolPayload → live closure:
  fetch Finnhub ratings + surprises (as today);
  if (hasAlphaVantageKey()) {
    try { const enr = await fetchAlphaVantageAnalystEnrichment(input.ticker);
          merge enr.consensusEstimates, enr.priceTargets } catch {}   // partial: each field independent
  }
  // Provenance: PRIMARY-WINS. Keep source: "finnhub" whenever the Finnhub
  // baseline answered (ratings or surprises present) — a payload that is
  // mostly Finnhub with an AV price-target should not read as "alphavantage".
  // Tag "alphavantage" only when Finnhub is absent and AV filled something;
  // else emptyPayload.
```
`fetchAlphaVantageAnalystEnrichment`: **two independent `alphaVantageRequest` calls (so a `get_analyst_estimates` invocation costs 2 budget units, not 1)** issued via `Promise.allSettled` so one throttle doesn't reject the other — `OVERVIEW` → `priceTargets = { consensus: num(AnalystTargetPrice), high: null, low: null, median: null }` (AV gives a single target); `EARNINGS_ESTIMATES` → `consensusEstimates = { fyEpsAvg, fyRevenueAvg, numAnalysts }`. Each field is independent: OVERVIEW filling while EARNINGS_ESTIMATES rejects (throttle / budget) yields `priceTargets` set, `consensusEstimates` null. `recentRatingActions` stays `[]` (AV has no dated rating-action feed). **Budget accounting:** transcript = 2 units (probe + transcript), estimates = 2 units (overview + estimates), insider = 1 — so a full disclosure fan-out can spend ~5 AV units; size `ALPHAVANTAGE_DAILY_LIMIT` accordingly.

**`get_insider_transactions`** (was: Finnhub-only → empty):
```
resolveToolPayload → live closure:
  if (hasFinnhubKey()) { try { return await fetchFinnhubInsiderTransactions(input); } catch {} }
  if (hasAlphaVantageKey()) { try { return await fetchAlphaVantageInsiderTransactions(input); } catch {} }
  return emptyPayload("get_insider_transactions", input);
```
`fetchAlphaVantageInsiderTransactions`: `INSIDER_TRANSACTIONS&symbol`. AV returns the full transaction history by default, which is wasteful in this quota-conscious path — **if the endpoint supports a server-side `from=YYYY-MM-DD` date filter (verify at implementation), pass the 90-day-window start** to shrink the response, and always keep the client-side upper-bound filter (`transactionDate <= input.date`, for back-dated as-of dates). Filter `data[]` to the 90-day window ending `input.date`, map each row to `insiderTransactionItem`:
- `filingDate` ← `transaction_date` (AV has no separate filing date — documented approximation)
- `transactionDate` ← `transaction_date`
- `insiderName` ← `executive`; `insiderTitle` ← `executive_title`
- `transactionCode` ← **`""` (unknown).** AV's `acquisition_or_disposal` is only a direction flag (A/D), *not* the SEC transaction code the schema documents (P/S/A/M/G/F). Do **not** synthesize `P`/`S` from it — the news analyst prompt weighs open-market buys/sells against grants, option exercises, and tax-withholding sales, and a fabricated `P`/`S` would mislabel an award or a tax sale as an open-market trade. Leave the code unknown and carry *direction* in the sign of `shares` instead.
- `shares` ← signed: `+Number(shares)` for `A`, `-Number(shares)` for `D`
- `pricePerShare` ← `Number(share_price)`
- `isDerivative` ← concrete rule: `security_type` (case-insensitive) contains `"deriv"` **and not** `"non-deriv"` → `true`; otherwise `false`. (AV's `security_type` commonly reads `"Derivative"` / `"Non-Derivative"`; any other/blank value → `false`.) No open-ended heuristic — an explicit, testable predicate.
- `windowDays` ← `90`; `source` ← `"alphavantage"`.

The AV fallback is deliberately **coarser than the Finnhub primary** — direction + derivative flag, but no SEC-code granularity. That is the honest shape of AV's data, and the fallback is reached only when Finnhub (full fidelity) is unavailable.

### State management

None. The provider module holds one process-level budget counter (module scope, not session state). No new session state, resources, or scopes. The counter is orthogonal to the FIX-758 session spine (per-session) and the `lib/cache.ts` process cache (120s TTL) — it neither reads nor writes either.

### Error handling

| Failure | Behavior |
| --- | --- |
| No `ALPHAVANTAGE_API_KEY` | AV branch skipped; tool degrades to the next fallback / `emptyPayload`. |
| AV `Note`/`Information`/`Error Message` body (HTTP 200) | `alphaVantageRequest` throws `AlphaVantageRateLimitError` → tool catches → degrade. |
| Daily budget spent | `alphaVantageRequest` throws `AlphaVantageBudgetError` **before** fetching → degrade. Guard disabled **only** when `ALPHAVANTAGE_DAILY_LIMIT` is exactly `0`. |
| Malformed `ALPHAVANTAGE_DAILY_LIMIT` (blank / negative / non-integer / non-numeric) | Fail-safe: value is ignored and the guard falls back to the `25` default — a misconfiguration never silently disables protection. |
| Non-2xx / network / JSON parse | Fetcher throws → tool catches → degrade. |
| Partial (one AV call succeeds, another fails) — analyst-estimates | `Promise.allSettled` per field; the succeeding field fills, the failing one stays `null`. |
| Empty transcript for the resolved quarter | `available: false`, `content: null` — a valid "no transcript" result, `source: "alphavantage"`. |

All AV failures are non-retryable at the tool layer and collapse to degrade-to-next. No retry/backoff inside the fetchers (a throttled AV key won't recover within a run; retrying burns budget).

## 6. Edge Cases & Error Handling

The provider-failure → degrade paths (no key, `Note`/`Information` body, budget spent, non-2xx/parse) are the §4 error table; this section covers only cases §4 doesn't:

| Case | Expected behavior |
| --- | --- |
| **Per-minute throttle (5/min) before the daily cap** | The likelier binding limit in dev — a disclosure fan-out fires transcript-probe+transcript (2) + estimates (2) in seconds; back-to-back runs within 60s throttle on a later call via a `Note` body → honest degrade. No proactive per-minute guard in v1 (documented; token-bucket is v2). |
| Concurrent calls near the daily limit | The synchronous check-and-reserve (no `await` between read and `count += 1`) makes the guard race-free: N parallel `alphaVantageRequest`s never collectively exceed the limit; every attempted call (incl. throttled ones) counts. |
| Process restart / serverless cold-start resets the counter | Per-process limitation — on Vercel every invocation may start fresh, so the daily guard is best-effort, not a hard cross-run 25/day circuit breaker. AV's server-side throttle (→ Note body → throw) is the real-exhaustion backstop. |
| `ALPHAVANTAGE_DAILY_LIMIT` override | Default 25; lower for testing; **`0` disables the guard** (paid / metered plan). |
| Insider row with unparseable `shares`/`share_price` | That row's numeric coerces via a null-safe helper; a fully unparseable row is dropped (ticker-level data, not a nullable field, so a bad row can't stay). |
| Transcript: non-calendar fiscal year | The `EARNINGS` probe + fiscal-label resolution (§4) targets the latest *reported* quarter; if the first label yields empty, retry with the alternate label before `available: false`. |
| Insider row from AV (fallback) | `transactionCode` is `""` (unknown — AV lacks the SEC code); direction carried by the sign of `shares`. Coarser than the Finnhub primary by design. |
| AV `AnalystTargetPrice` is `"None"`/`"-"` | `num()` → `null`; `priceTargets.consensus` null, rest of the estimates payload intact. |
| Finnhub answers insider, AV never called | AV fallback is terminal — reached only when Finnhub throws/has no key. No extra budget spent on the happy path. |

Error taxonomy: all AV-layer failures (rate-limit body, budget, network, parse) are non-retryable and collapse to degrade-to-next-or-empty. The tools never throw.

## 7. Testing Strategy

**Goal & goal check (real provider).** *Goal:* with a real `ALPHAVANTAGE_API_KEY`, the two previously-dead stub tools return real live data and the insider tool has a working second source — without silently burning the 25/day quota. *Goal check (out-of-CI, real key):* a record-mode run (or a small `scripts/record-alpha-vantage.ts`) against a real key that fetches transcript + estimates + insider for one ticker. **Assert per the provenance rules, not a blanket `source: "alphavantage"`:** transcript has no competing primary, so it returns `source: "alphavantage"` with a populated `content`. Estimates (primary-wins) and insider (terminal fallback) stay `source: "finnhub"` whenever a `FINNHUB_API_KEY` is present — so the run either (a) unsets/forces-off Finnhub so all three exercise the AV path and tag `"alphavantage"`, or (b) keeps Finnhub and asserts the **AV-contributed fields** directly (estimates: `consensusEstimates`/`priceTargets` non-null; insider: AV-shaped rows with `transactionCode === ""`) rather than the top-level `source`. A blanket `source: "alphavantage"` assertion would either fail the check or wrongly pressure the implementation to mis-tag mixed payloads. A second assertion drives `alphaVantageRequest` past the configured limit and confirms it throws `AlphaVantageBudgetError` rather than calling AV. No LLM is involved (data + provider plumbing), so the "real-model" facet doesn't apply, but a real-provider observable outcome does — the record run is the real-path evidence (BP-003), and it doubles as the step-5 fixture generator.

**CI specs** (`fsd:tdd`, vitest, deterministic — `testBlock` per AGENTS.md rule 4, mock `globalThis.fetch`, `_resetBudget()` + `_resetCache()` in `beforeEach`, `chdir` to app root):

Behaviors to test (each a tracer-bullet cycle):
1. **Request helper — apikey + rate-limit body** — a successful call asserts the outgoing `fetch` URL carries `apikey=<ALPHAVANTAGE_API_KEY>` (the key is injected by the helper, not the caller); a mocked `fetch` returning HTTP 200 `{ "Note": "...frequency..." }` → `alphaVantageRequest` throws `AlphaVantageRateLimitError`; same for `{ Information }` and `{ Error Message }`.
2. **Budget guard (incl. concurrency)** — with limit 2 and free tier: 3rd `alphaVantageRequest` throws `AlphaVantageBudgetError` without calling `fetch`; **5 `alphaVantageRequest`s fired in parallel (`Promise.all`) against a slow-`fetch` mock resolve to exactly 2 fetches + 3 `AlphaVantageBudgetError`s** (proves the reserve-before-await is race-free); with `ALPHAVANTAGE_DAILY_LIMIT=0` the guard is disabled (the 3rd call proceeds); a **malformed limit (`""`, `"  "`, `"-5"`, `"25.5"`, `"twenty"`) falls back to the 25 default — the guard stays ON**, not silently disabled; UTC-day roll resets the counter.
3. **Insider fallback** — Finnhub mocked to throw, AV mocked to return the `data[]` shape → `source: "alphavantage"`, 90-day window applied, `A`→positive shares / `D`→negative, `transactionCode` is `""` (not fabricated to `P`/`S`).
4. **Transcript** — `EARNINGS` mocked → picks the latest reported quarter; `EARNINGS_CALL_TRANSCRIPT` mocked with a `transcript[]` → `available: true`, `content` joined and capped, `quarter` + `callDate` set; empty `transcript[]` → `available: false`, `content: null`; `EARNINGS` probe fails → calendar-quarter fallback path taken. **Non-calendar fiscal year (regression against a naïve calendar mapper):** an issuer whose latest `fiscalDateEnding` is Dec (fiscal label `YYYYQ1`, not the calendar `YYYYQ4`) — the transcript-mock keys on the **fiscal** label and returns empty for the calendar label, so a calendar-only mapper would yield `available: false`. Assert the fetcher resolves the fiscal label (or, if it requested the calendar label first, exercises the alternate-label retry) and reaches `available: true` — proving the fiscal-label/retry path, not the calendar guess.
5. **Estimates enrichment (primary-wins provenance)** — Finnhub baseline present, AV `OVERVIEW`+`EARNINGS_ESTIMATES` mocked → `consensusEstimates` + `priceTargets` filled but **`source` stays `"finnhub"`** (the Finnhub ratings/surprises baseline answered — §4 primary-wins); OVERVIEW-only (EARNINGS_ESTIMATES throws) → `priceTargets` filled, `consensusEstimates` null, `source` still `"finnhub"`. Separately, **Finnhub absent (ratings + surprises both throw) + AV enrichment present → `source: "alphavantage"`** (AV is the only contributor); Finnhub absent + AV absent → `emptyPayload`.
6. **No-key degrade** — `ALPHAVANTAGE_API_KEY` unset → AV branch skipped, `fetch` not called for AV, tool degrades exactly as today.

Reference patterns: `test/finnhub-insider.spec.ts` / `test/finnhub-fundamentals.spec.ts` (provider-fetch mock idiom), `test/get-insider-transactions.spec.ts` (tool degrade paths), `test/get-futures-curve.spec.ts` (single-provider live/degrade), `fsd:write-block-tests` for the mock-context idiom.

**Resolved during spec review (were open, now decided):**

- **Insider `transactionCode` fidelity — RESOLVED: leave it unknown (`""`), don't fabricate `P`/`S`.** AV gives only A/D (direction), not the SEC code; synthesizing `P`/`S` would mislabel awards/exercises/tax-sales as open-market trades and skew the news analyst's derivative-vs-open-market weighing. Direction is carried by the sign of `shares`; the AV fallback is honestly coarser than the Finnhub primary (§4).
- **Transcript quarter — RESOLVED: probe the latest *reported* quarter via `EARNINGS`, don't derive the calendar quarter.** Calendar derivation breaks on offset fiscal years and back-dated as-of dates and would return `available: false` when a recent call exists; the prompt expects the latest call. Two AV calls (probe + transcript) is acceptable for once-per-run reference data; probe failure degrades to a calendar-quarter best-effort (§4).
- **Budget guard concurrency — RESOLVED: atomic synchronous check-and-reserve before `await fetch`.** The original check-then-increment-on-success design had a TOCTOU race under the analyst fan-out; reserving synchronously closes it (§4, tested in §7).
- **Budget-limit env validation — RESOLVED: fail-safe parse, only a literal `0` disables the guard.** A naïve `Number(process.env.ALPHAVANTAGE_DAILY_LIMIT ?? 25)` is fail-open — `Number("")` is `0` and `Number("typo")` is `NaN`, both making `limit > 0` false and silently disabling protection on a misconfiguration. The guard now trims, parses, and rejects any non-negative-integer value back to the `25` default, so a typo tightens protection instead of removing it (§4, §6 error table, §7 test #2).
- **Paid-tier bypass (was escalated) — RESOLVED by collapsing to one knob.** Instead of an `ALPHAVANTAGE_TIER` env + `isAlphaVantagePaidTier()` (speculative tier vocabulary with one internal consumer, flagged YAGNI in review), the guard uses a single `ALPHAVANTAGE_DAILY_LIMIT` where **`0` = unlimited**. A paid user sets `ALPHAVANTAGE_DAILY_LIMIT=0` — which honors the issue's "no-op on a paid tier" outcome *and* removes the marketing surface from the provider's public API (BP-038). No separate tier concept ships. *(Confirm at review if a distinct `ALPHAVANTAGE_TIER` label is still wanted for readability; default is the single knob.)*
- **`get_analyst_estimates` provenance — RESOLVED: primary-wins.** `source` stays `"finnhub"` whenever the Finnhub baseline answered (it's the bulk of the payload); `"alphavantage"` only when Finnhub is absent and AV filled something. Avoids tagging a mostly-Finnhub payload as AV (§4, §7 test #5).
