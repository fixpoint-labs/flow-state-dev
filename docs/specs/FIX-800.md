# FIX-800: Trading-desk: market-wide movers feed (Alpha Vantage TOP_GAINERS_LOSERS) — Implementation Spec

## 1. TLDR

**Plain-language summary.** Right now the trading desk can only look at a stock you hand it — it has no way to see what's moving across the market on its own. This adds one small data tool that asks Alpha Vantage for the day's biggest gainers, biggest losers, and most-traded US stocks and hands back a clean list. That's all it does: it fetches and tidies the raw list. Deciding which of those names are actually worth a full deep-dive (screening, ranking, running the analysis pipeline) is a separate, harder job that belongs to the opportunity-scanner work (FIX-902), not here.

**Technical statement.** Add a `get_top_movers` data tool that calls Alpha Vantage `TOP_GAINERS_LOSERS`, normalizes its three string-typed arrays into a canonical numeric payload, and plugs into the desk's existing fixture / live / record data-mode machinery — with no screening, ranking, or analyst binding.

**Deliverables:**

- **Provider:** Add `fetchAlphaVantageTopMovers()` to `labs/trading-desk/lib/providers/alpha-vantage.ts` (the module FIX-798 creates), consuming FIX-798's shared AV request helper (key gate, `Note`/`Information` rate-limit-as-failure handling, daily-budget accounting).
- **Schema:** Add the exported `topMoversSchema` (with a private `moverEntry` row schema), the `get_top_movers` input schema, and the `"alphavantage"` `sourceTag` value (if FIX-798 has not already added it) to `labs/trading-desk/flows/analysis/tools/schemas.ts`.
- **Tool:** Add `get_top_movers` handler in `labs/trading-desk/flows/analysis/tools/data/get_top_movers.ts` and export it from `labs/trading-desk/flows/analysis/tools/index.ts`.
- **Empty payload:** Add the `get_top_movers` builder to `labs/trading-desk/flows/analysis/tools/empty-payloads.ts`.
- **Fixture:** Add `top-movers.json` under `labs/trading-desk/fixtures/_macro/2026-05-06/` and register `"top-movers.json"` in `TOOL_FILE_NAMES`.
- **Tests:** Add `labs/trading-desk/test/get-top-movers.spec.ts` mirroring `get-futures-curve.spec.ts` (fixture load, no-key degrade, live happy path, rate-limit-body degrade).
- **Docs:** Update the tool inventory and Provider keys section in `labs/trading-desk/README.md`; update the tool list in `labs/trading-desk/CLAUDE.md` if it enumerates tools.

**Size estimate.** **Small** (1 tool file + schema/registration edits + 1 test + fixture + docs; <150 LOC; 1 PR). Blocked on FIX-798.

## 2. Overview

Linear issue: [FIX-800](https://linear.app/fixpoint-labs/issue/FIX-800/trading-desk-market-wide-movers-feed-alpha-vantage-top-gainers-losers)

The desk is entirely reactive: every analysis starts from a ticker the user already chose. This spec adds the first market-wide candidate source — a data tool that fetches Alpha Vantage's `TOP_GAINERS_LOSERS` (top gainers, top losers, most-actively-traded US tickers, one call). It is deliberately scoped as a **data foundation**: it produces a raw, normalized list and nothing more. The screening and ranking discipline that turns a noisy movers list into an analysis-worthy shortlist is the hard part, and it lives in the opportunity-scanner issue (FIX-902), which consumes this tool.

## 3. Background & Research

### Alpha Vantage `TOP_GAINERS_LOSERS` shape (verified against the live `demo` endpoint)

Top-level keys: `metadata`, `last_updated`, `top_gainers`, `top_losers`, `most_actively_traded`. Each array element has exactly `ticker`, `price`, `change_amount`, `change_percentage`, `volume` — **all strings**, e.g. `{ "ticker": "CELUW", "price": "0.0019", "change_amount": "0.0016", "change_percentage": "533.3333%", "volume": "153976" }`. `change_percentage` carries a trailing `%`.

Two provider realities the normalizer must handle:

1. **Rate-limit / exhaustion returns HTTP 200** with a `{ "Note": ... }` or `{ "Information": ... }` body rather than an error status. FIX-798's shared AV request helper is responsible for treating those bodies as failures (throw). `fetchAlphaVantageTopMovers()` calls through that helper, so it inherits the behavior — it does not re-implement the check.
2. **The endpoint returns the latest completed session's movers, not intraday-realtime** — and has no historical/as-of parameter. On the **free tier it is end-of-day** (realtime / 15-min-delayed movers are premium-gated). It always returns AV's most-recent snapshot regardless of the desk's as-of `date`. This is acceptable for candidate generation (a scan surfaces recent movers), but two things must be documented so nothing downstream mis-reads it: (a) it is **EOD on a free key**, not live intraday, so an intraday scan gets last-close movers; (b) a back-dated `date` still returns AV's latest snapshot, not that date's movers. `last_updated` (AV's own timestamp) is surfaced as `asOf` and is the authoritative freshness marker — FIX-902 should treat the feed as EOD-fresh unless a premium tier is confirmed.

### How the codebase already solves this

The desk has a mature single-provider, market-wide (date-only) data-tool convention. The closest analog is **`get_futures_curve`** (`get_futures_curve.ts` + `get-futures-curve.spec.ts`): date-only input, Massive-only, `_macro` sentinel fixture directory, degrades to `emptyPayload(source: "unavailable")` on no-key / failure, tagged with a provenance `source`. `get_market_news` and `get_macro_indicators` are the same date-only market-wide shape. This spec mirrors that convention exactly; it introduces no new abstraction.

Key shared machinery reused unchanged:

- `resolveToolPayload(tool, input, ctx, fetchLive)` (`runtime/resolve.ts`) — the single dispatch point for fixture / live / record modes.
- `getOrFetch` (`lib/cache.ts`) — process-scoped 120s TTL cache, invoked by `resolveToolPayload` on the live path. **Cache-key caveat:** `getOrFetch` keys on `JSON.stringify(input)`, so a differing `date` in the same 120s window triggers a *separate* AV call — expensive against the 25/day free budget for an endpoint whose live result is date-agnostic. The `date` cannot simply be dropped from the cache key: `resolveToolPayload` reuses the same `input` for the `_macro/{date}/` fixture path and the recorder, so normalizing it tool-locally would break fixture routing. The resolution is a **caller contract** (see §4 Data flow), not a shared-machinery change: FIX-902 must use a single canonical `date` per live scan batch so movers reads collapse to one AV call. Deeper live-path cache normalization (keying date-agnostic endpoints on a sentinel) is a shared-`resolve.ts` change, out of scope here and flagged for FIX-902 if the batch contract proves insufficient.
- `emptyPayload` (`empty-payloads.ts`) — schema-valid `source: "unavailable"` skeleton.
- `loadFixture` (`runtime/fixtures.ts`) — resolves a no-`ticker` input to the `_macro` sentinel directory.

### Why this approach over alternatives

- **Faithful thin normalization vs. a "candidate" abstraction.** The output is three lists of `{ticker, price, changeAmount, changePct, volume}` — a direct, provider-defined shape. We deliberately do **not** invent a `Candidate` type, a ranking, a score, or a merged/deduped universe. Those encode screening decisions that belong to FIX-902; baking them in here would be speculative surface (BP-038) and would risk drift from whatever the scanner actually needs.
- **Consume FIX-798's provider, don't inline AV.** The AV module, key gate, rate-limit-body handling, and daily-budget guard are FIX-798's deliverables. FIX-800 adds one fetcher that calls through them (BP-028/BP-029 — build at the layer that owns it, compose existing primitives).
- **Unbound to analysts.** Unlike `get_market_news` (bound to the Market Analyst), `get_top_movers` is market-wide candidate data, not per-ticker analysis input. It stays exported-but-unbound, available to a future scan flow / the headless harness.

### Key Decisions & Ramifications (top 5)

1. **Thin normalization, no screening/ranking.** *Alternative rejected:* emit a ranked/scored candidate list. *Ramification:* keeps FIX-800 mechanical and low-risk, but means the tool's raw output is not directly "a shortlist" — FIX-902 must add the screening layer. Locks the screening decision out of the data layer, which is the intended split.
2. **Hard dependency on FIX-798 (currently in Backlog).** *Alternative rejected:* inline a minimal AV fetch in this tool. *Ramification:* FIX-800 cannot start until FIX-798 lands; in exchange we avoid a duplicate provider path and inherit the rate-limit + budget discipline for free. This is a real schedule coupling, called out in Dependencies.
3. **`changePct` stored as a fraction (`5.333333` for `533.3333%`), not the raw percentage.** *Alternative rejected:* keep AV's percentage magnitude. *Ramification:* consistent with `get_futures_curve.changePct` (`0.01` = 1%) so downstream math is uniform, at the cost of a parse step (strip `%`, divide by 100). A consumer expecting "percent" must multiply by 100.
4. **Date-only input; live path returns AV's latest (EOD-on-free) snapshot, not the as-of date's movers.** *Alternative rejected:* attempt historical movers. *Ramification:* AV offers no historical movers and is EOD on the free tier, so back-dated live runs get the latest completed session tagged with AV's `last_updated`. The scan contract treats the feed as EOD-fresh. Fixture/record mode still snapshots deterministically. Documented as a known property, not a bug.
5. **Tool ships unconsumed until FIX-902.** *Alternative rejected:* fold this into FIX-902. *Ramification:* a foundation lands with no runtime consumer in the Phase 1–5 pipeline. Justified because the schema is provider-stable (near-zero rework risk) and the tool is independently exercisable via the record-mode run / headless harness. Surfaced in Open Questions.

### API surface

**Provider fetcher** (`lib/providers/alpha-vantage.ts`):

```ts
/** Market-wide top gainers / losers / most-active via Alpha Vantage
 *  TOP_GAINERS_LOSERS. Latest completed session (EOD on the free tier);
 *  no historical/as-of param. Calls through the shared AV request helper
 *  (key gate, Note/Information rate-limit-as-failure, daily-budget
 *  accounting). Throws on transport/response failure so the tool handler
 *  falls through with one try/catch; per-field coercion never throws. */
export async function fetchAlphaVantageTopMovers(
  input: { date: string },
): Promise<ToolOutput<"get_top_movers">>;
```

- Fetches `function=TOP_GAINERS_LOSERS`.
- Maps each element through a single local helper `num(s)` that returns `null` for anything that is not a real number, so a thin/blank field reads honestly instead of fabricating a zero:

  ```ts
  const num = (s: string | undefined): number | null => {
    const t = s?.trim();
    if (!t) return null;                    // "" and "   " → null, NOT 0 (Number("") === 0)
    const n = Number(t);
    return Number.isFinite(n) ? n : null;   // rejects NaN AND Infinity/overflow
  };
  // change_percentage carries a "%" unit; REQUIRE it, else the value is
  // untrusted → null (a unitless "0.05" must not silently become 0.0005).
  const pct = (s: string | undefined): number | null => {
    const t = s?.trim();
    if (!t || !t.endsWith("%")) return null;
    const n = num(t.slice(0, -1));
    return n === null ? null : n / 100;      // "533.3333%" → 5.333333 (fraction)
  };
  ```

  `price`/`change_amount`/`volume` → `num(field)`; `change_percentage` → `pct(field)`. **This coercion is local and never throws** — a single malformed, blank, or unitless row yields `null` fields with the ticker retained, not a failed payload. (The `Number.isFinite` guard is why the schema does not also need `.finite()`; add it as belt-and-suspenders only if a reviewer prefers the schema to reject non-finite too.)
- `source: "alphavantage"`, `asOf: json.last_updated ?? input.date`. Note the `asOf` provenance asymmetry: on a successful live fetch `asOf` is AV's `last_updated` (EOD timestamp); on the fixture and `unavailable` paths it is the input `date`. FIX-902 should read `asOf` as the freshness marker rather than assuming it equals the requested `date`.
- **Throws only** (via the shared helper) on: no-key, non-2xx, a `Note`/`Information` rate-limit body, top-level `JSON.parse` failure, or a missing/non-array `top_gainers`/`top_losers`/`most_actively_traded`. Do **not** re-implement the rate-limit-body check here. Field-level parsing (above) is explicitly *not* in this throw set.

**Schemas** (`flows/analysis/tools/schemas.ts`):

```ts
// Add "alphavantage" to the sourceTag enum IF FIX-798 has not already.
// moverEntry stays a PRIVATE const — mirror `newsItem` in schemas.ts, which
// is not exported; only the parent schema (topMoversSchema) is public. Export
// the entry only if/when FIX-902 has a concrete need to import the row shape.
const moverEntry = z.object({
  ticker: z.string(),
  price: z.number().nullable(),
  changeAmount: z.number().nullable(),  // kept: AV supplies it directly; deriving from price×changePct would inherit changePct's rounding
  changePct: z.number().nullable(),   // fraction: 0.05 = +5%
  volume: z.number().nullable(),
});
export const topMoversSchema = z.object({
  source: sourceTag,
  asOf: z.string(),
  gainers: z.array(moverEntry),
  losers: z.array(moverEntry),
  mostActive: z.array(moverEntry),
});
// toolInputSchemas:  get_top_movers: z.object({ date: z.string().min(1) })
// toolOutputSchemas: get_top_movers: topMoversSchema
// TOOL_FILE_NAMES:   get_top_movers: "top-movers.json"
```

Every entry field is nullable so a malformed/thin AV row degrades honestly (BP-020/BP-023) rather than dropping the ticker or fabricating a zero. No array cap — AV returns ≤20 per list and the tool is unbound to any prompt, so there is no prompt-budget reason to truncate (BP-038, no speculative knob).

**Reference files for the implementer:** the **handler shape** mirrors `get_market_news.ts` (thin handler → provider fetch → `emptyPayload` degrade), while the **test shape** mirrors `get-futures-curve.spec.ts` (date-only `_macro` fixture + degrade-path coverage). They are different files on purpose — do not look for both patterns in one place.

**Tool handler** (`flows/analysis/tools/data/get_top_movers.ts`) — mirrors `get_market_news`:

```ts
export const get_top_movers = handler({
  name: "get_top_movers",
  description:
    "Market-wide top gainers, losers, and most-actively-traded US tickers (candidate generation; not ticker-scoped).",
  inputSchema: toolInputSchemas.get_top_movers,
  outputSchema: toolOutputSchemas.get_top_movers,
  execute: async (input, ctx) =>
    resolveToolPayload("get_top_movers", input, ctx, async () => {
      if (hasAlphaVantageKey()) {
        try { return await fetchAlphaVantageTopMovers(input); } catch {}
      }
      return emptyPayload("get_top_movers", input);
    }),
});
```

**Empty payload** (`empty-payloads.ts`):

```ts
get_top_movers: (i) => ({ source: "unavailable", asOf: i.date, gainers: [], losers: [], mostActive: [] }),
```

### Data flow

`get_top_movers.execute` → `resolveToolPayload` branches on `dataSource`:
- **fixture** → `loadFixture` reads `fixtures/_macro/{date}/top-movers.json` (no ticker → `_macro`).
- **live** → `getOrFetch("get_top_movers", input, fetchLive)`; `fetchLive` gates on `hasAlphaVantageKey()`, calls `fetchAlphaVantageTopMovers` inside `try/catch`, degrades to `emptyPayload` on throw (no-key, rate-limit body, network, parse). Budget exhaustion surfaces as a throw from FIX-798's helper → same degrade path.
- **record** → live path, then `recordFixture` persists the payload to the corpus.

**Caller contract (budget):** because the live cache key includes `date` (§3 caveat) and each miss costs 1 of 25 free-tier requests/day, a live scan must poll movers with a **single canonical `date`** per batch (e.g. the run's as-of date), so all analysts/steps in the 120s window share one AV call. This is FIX-902's contract to honor; FIX-800 documents it here.

### State management

None. The tool reads only `ctx.session.state.dataSource` (via `pickMode`) like every other data tool. No new session state, resources, or scopes.

### Error handling

Single-provider degrade discipline: any failure (missing key, non-2xx, `Note`/`Information` rate-limit body, JSON parse error, budget exhausted) → `emptyPayload("get_top_movers", input)` tagged `source: "unavailable"`. The tool never throws; a future scan consumer treats `unavailable` as "no candidates this run," not an error.

## 6. Edge Cases & Error Handling

| Case | Expected behavior |
| --- | --- |
| No `ALPHAVANTAGE_API_KEY` | Live path: no fetch, `emptyPayload` (`unavailable`). Test asserts `fetch` not called. |
| AV rate-limit / exhaustion (`{Note}`/`{Information}`, HTTP 200) | Shared helper throws → tool catches → `unavailable`. |
| AV daily budget exhausted (FIX-798 guard) | Helper throws → `unavailable` (degrade, don't throw). |
| Non-2xx / network error | Helper throws → `unavailable`. |
| Malformed numeric string in a row (`price: "N/A"`) | That field → `null`; ticker retained. |
| **Blank / whitespace numeric field (`price: ""` or `" "`)** | `null`, **not `0`** — the `num()` helper trims and rejects empty before `Number()` (guards the `Number("") === 0` trap). |
| Non-finite (`Infinity`/overflow-like) | `null` — `Number.isFinite` guard in `num()`. |
| `change_percentage` without `%` or non-numeric | `changePct` → `null`; row retained. |
| Empty AV arrays | Payload with empty `gainers`/`losers`/`mostActive`, `source: "alphavantage"` — a valid "market quiet" result, distinct from `unavailable`. |
| Back-dated as-of `date` (live) | Returns AV's latest completed session (EOD on free tier), not that date's movers; `asOf` = AV `last_updated`. Documented, not an error. |
| Fixture missing for `_macro/{date}` in fixture mode | `FixtureMissingError` (existing behavior, unchanged). |

Error taxonomy: all live-path failures are non-retryable at the tool layer and collapse to `unavailable`. Retry/backoff, if any, is FIX-798's request helper's concern, not this tool's.

## 7. Testing Strategy

**Verification posture.** This is a thin, unconsumed data tool, so verification matches the weight of its siblings (`get-futures-curve.spec.ts` is mocked-vitest-only) rather than adding heavier ceremony. Two layers:

1. **CI specs (primary, deterministic)** — the mocked vitest behaviors below. These are the regression guard and run on every push.
2. **Real-provider proof (one-time, out-of-CI) = a dedicated record seam.** `get_top_movers` is **unbound** — no `analyze`-flow action or analyst tool list references it — so a `dataSource: "record"` **analyze run will never execute or record it**. The fixture + real-provider proof therefore needs its own explicit seam, not the analyze pipeline. Add a tiny record harness for step 5: a `scripts/record-top-movers.ts` (or a one-off `testBlock(get_top_movers, { input: { date }, session: { state: { dataSource: "record", … } } })`) run once with a real `ALPHAVANTAGE_API_KEY`. That single invocation makes the one real AV call, confirms the fetcher parses AV's live stringly-typed response into a valid `topMoversSchema` payload tagged `source: "alphavantage"`, and writes `fixtures/_macro/2026-05-06/top-movers.json` via the record path. There is no separate gated goal check.

   *Corrections from earlier drafts:* (a) `fsdev block get_top_movers --dataSource live` does **not** work — `fsdev block` resolves a default-exported block from a file path and seeds only `userId`, so `pickMode` defaults to `fixture` and it never reaches AV. (b) "Just do a record-mode analyze run" does **not** work either, for the unbound reason above. The dedicated record seam is the correct mechanism — call it out as a step-5 deliverable.

*Goal-check applicability:* no LLM is involved (data tool), and the real observable outcome is exercised by the record step above, so a *separate* real-model goal check does not apply here — the record run is the real-path evidence (BP-003).

**CI specs** (`fsd:tdd`, vitest, deterministic — mirror `get-futures-curve.spec.ts`, use `testBlock` per AGENTS.md rule 4, `_resetCache()` in `beforeEach`, `chdir` to app root):

Behaviors to test (each a tracer-bullet cycle):
1. **Fixture load** — `dataSource: "fixture"`, input `{ date: "2026-05-06" }` → `source: "fixture"`, non-empty `gainers`, first entry has numeric `price` and `changePct`.
2. **No-key live degrade** — `dataSource: "live"`, `ALPHAVANTAGE_API_KEY` unset → `source: "unavailable"`, `fetch` spy not called, empty arrays.
3. **Live happy path** — key set, `fetch` mocked to return the AV JSON shape (string fields) → `source: "alphavantage"`; assert `change_percentage: "533.3333%"` parses to `changePct ≈ 5.333333` and `price` is a number.
4. **Rate-limit body degrade** — key set, `fetch` mocked to return HTTP 200 `{ "Note": "...limit..." }` → `source: "unavailable"` (proves the helper's body check + tool catch compose). If FIX-798's helper is what throws, this test also guards the integration seam.
5. **Coercion traps (malformed / blank / unitless)** — one mocked live row each with `price: "N/A"`, `price: ""` (and `price: " "`), and `change_percentage: "0.05"` (no `%`) → every trapped field is `null` with the ticker retained. These three assertions are the regression guard for the §4 contract: the blank case would fail if `Number("")`'s `0` leaked through, and the unitless case would fail if `"0.05"` were divided to `0.0005`.

Reference patterns: `test/get-futures-curve.spec.ts` (date-only market-wide, degrade paths), `test/get-insider-transactions.spec.ts` (single-provider degrade), `fsd:write-block-tests` for the mock-context idiom.

## 8. Non-Goals

- **Screening, ranking, filtering, scoring, or deduping** the movers into an analysis shortlist — FIX-902 (opportunity scanner). This tool emits raw normalized lists only.
- **The scan flow / CLI entry point / scheduled job** that turns candidates into analyses — FIX-902, composing with the headless harness (FIX-788, already done).
- **Binding the tool to any analyst generator** or into the Phase 1–5 per-ticker pipeline. It is market-wide foundation data, intentionally unbound.
- **Historical / as-of movers.** AV offers none; not in scope.
- **The Alpha Vantage provider module, key gate, rate-limit-body handling, and daily-budget guard** — all FIX-798. FIX-800 only adds one fetcher + one tool that consume them.
- **A `Candidate` domain type or a schema shared with FIX-771 sleeves / FIX-776 rubric profiles.** Reconciling those "named strategy" concepts is explicitly FIX-902's open question, not this tool's.
- **Short-interest / days-to-cover / borrow-rate crowding signals** (needed for a squeeze strategy) — FIX-810 / FIX-799, consumed later by FIX-902.

*Deepening opportunities observed (not in scope):* none that warrant `fsd:improve-codebase-architecture`. The data-tool convention is already deep and consistent; this tool fits it without friction.
