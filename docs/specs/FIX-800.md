# FIX-800: Trading-desk — market-wide movers feed (Alpha Vantage `TOP_GAINERS_LOSERS`)

Linear issue: [FIX-800](https://linear.app/fixpoint-labs/issue/FIX-800/trading-desk-market-wide-movers-feed-alpha-vantage-top-gainers-losers)
Consumer: **FIX-902** (opportunity scanner) — FIX-800 is its market-wide candidate source. This is a **standalone data prerequisite**, deliberately *not* built ahead of FIX-902 (see Decision 5). Depends on **FIX-798** (the Alpha Vantage provider).

## Part I — The Case *(for the human)*

### 1. Problem — why it matters, why now

Right now the trading desk can only look at a stock you hand it. Every analysis starts from a ticker the user already chose; the desk has no way to see what's moving across the market on its own. To find opportunities instead of just react to them, it first needs a source of market-wide candidates.

This adds one small data tool that asks Alpha Vantage for the day's biggest gainers, biggest losers, and most-actively-traded US stocks, and hands back a clean list. That's the whole job: fetch and tidy the raw list. Deciding which of those names are actually worth a full deep-dive (screening, ranking, running the analysis pipeline) is a separate, harder job that belongs to the opportunity-scanner work (FIX-902), which consumes this tool.

**Why now:** it's the first market-wide candidate source, and it unblocks FIX-902. No existing tool covers it — the desk's current data tools are all either ticker-scoped or narrow market-wide feeds (news, macro, futures curve), none of which surface "what moved today."

### 2. Solution in plain terms

Add a `get_top_movers` data tool that calls Alpha Vantage `TOP_GAINERS_LOSERS`, normalizes its three string-typed arrays (gainers / losers / most-active) into a canonical numeric payload, and plugs into the desk's existing fixture / live / record data-mode machinery. No screening, no ranking, no analyst binding — a raw normalized list and nothing more.

It reuses the desk's mature single-provider, date-only market-wide data-tool convention wholesale. The provider plumbing (the Alpha Vantage module, key gate, rate-limit handling, daily-budget guard) is FIX-798's deliverable; FIX-800 adds one fetcher that calls through it and one tool that exposes it.

**The philosophy that led here.**

- **Tenet 2 (composition over features).** The tool *consumes* FIX-798's shared AV request helper rather than inlining its own Alpha Vantage fetch. The key gate, the `Note`/`Information` rate-limit-as-failure handling, and the daily-budget accounting are primitives FIX-798 owns; FIX-800 composes them. It is a genuinely-new fetcher over a shared provider, not a re-implementation.
- **Tenet 3 (earn every addition).** The output is a faithful thin normalization — three lists of `{ticker, price, changeAmount, changePct, volume}`, the provider's own shape. We deliberately do *not* invent a `Candidate` type, a score, a ranking, or a merged/deduped universe. Those encode screening decisions FIX-902 owns; baking them in here would be speculative surface. Tenet 3 also asks whether a tool with no *immediate* runtime consumer earns its place — and the answer is sequencing: FIX-800 is a **data prerequisite for FIX-902**, and it is *not* implemented ahead of its consumer. The spec is ready; the build lands when FIX-902 is built (or just before), so no unconsumed foundation ever ships. (See Decision 5.)
- **Tenet 4 (absorb infrastructure, not knowledge).** All of it lives under `labs/trading-desk`. The Alpha Vantage single-vendor specifics — the `TOP_GAINERS_LOSERS` response shape, the `%`-suffix parsing, the end-of-day-on-free-tier reality — stay in lab app code and behind FIX-798's provider. No framework package changes; no vendor knowledge leaks up into shared infrastructure.

### 3. Tradeoffs & alternatives

- **The simpler approach weighed: fold this into FIX-902.** FIX-902 (the opportunity scanner) is the only consumer, so a minimal-surface move would be to build the fetch inside FIX-902's first PR. We keep it separate: the schema is provider-defined and stable (near-zero rework risk), the tool is independently exercisable via a record-mode run, and a standalone spec keeps FIX-902's PR focused on the hard part (screening) rather than provider plumbing. The orphan risk that would otherwise argue for inlining is avoided by *sequencing*, not grouping — FIX-800 is not implemented ahead of FIX-902 (see Decision 5), so a ready-but-separate spec never becomes dead catalog surface.
- **The other alternative weighed: inline a minimal AV fetch here** instead of depending on FIX-798. Rejected — it would duplicate provider plumbing (key gate, rate-limit-body handling, budget guard) that FIX-798 owns and that several sibling AV tools also need. Depending on FIX-798 is real schedule coupling (FIX-800 is `blockedBy` FIX-798), and we accept it to keep the provider layer single-owner.
- **Where the genuine complexity is** — not the happy path. Two spots:
  1. **The stringly-typed coercion.** Alpha Vantage returns every field as a string, `change_percentage` carries a trailing `%`, and blank/malformed fields are common. Coercing honestly (a blank must become `null`, never `0`; a unitless `"0.05"` must not silently become `0.0005`) is the part that earns its own regression tests.
  2. **The date-agnostic cache-key caveat.** The live cache keys on `JSON.stringify(input)`, so a differing `date` in the same window triggers a *separate* AV call against the 25/day free budget — even though the endpoint's live result is date-agnostic. The `date` can't simply be dropped (fixture routing and the recorder reuse the same `input`), so the fix is a caller contract for FIX-902, documented here rather than solved by a shared-machinery change.

### 4. Focus practices

The few this change lives or dies by, each tied to a tenet:

1. **Compose the provider, don't inline it** (tenet 2). The fetcher calls through FIX-798's shared AV request helper; it does not re-implement the key gate or the rate-limit-body check. Bespoke code is reserved for the one genuinely-new thing: the movers normalizer.
2. **Thin normalization, no speculative surface** (tenet 3). Emit the provider's own three-list shape. No `Candidate` type, no ranking, no array cap — no knob without a caller.
3. **Honest nulls — never fabricate a zero** (BP-020 / BP-023, live situational). Every entry field is nullable; a malformed, blank, or unitless AV field degrades to `null` with the ticker retained, rather than dropping the row or coercing to `0`. This is the coercion contract the tests guard.
4. **Degrade, never throw** (tenet 1 coherence, BP-020). Any live-path failure — no key, non-2xx, rate-limit body, parse error, budget exhausted — collapses to `emptyPayload(source: "unavailable")`, exactly like `get_futures_curve` and `get_market_news`. A consumer reads `unavailable` as "no candidates this run," not an error.
5. **Prove the real path via the record seam** (tenet 7). Because the tool is unbound, no analyze run exercises it — so the real-provider evidence comes from a dedicated record harness that makes the one real AV call and writes the fixture. The mocked CI specs are the regression guard; the record run is the real-path proof.

### 5. What using it looks like

This is a data tool with no human-facing call site — it is not bound to any analyst and has no `analyze`-flow action referencing it (that's intentional; the scan consumer is FIX-902). So the "usage" that matters is the observable payload shape a consumer reads. A successful live fetch returns:

```jsonc
{
  "source": "alphavantage",
  "asOf": "2026-05-06T16:00:00-04:00",   // AV's last_updated (EOD timestamp), NOT the requested date
  "gainers":    [{ "ticker": "CELUW", "price": 0.0019, "changeAmount": 0.0016, "changePct": 5.333333, "volume": 153976 }, /* … */],
  "losers":     [/* same shape */],
  "mostActive": [/* same shape */]
}
```

A consumer reads it like any other data-tool payload: check `source` (`"alphavantage"` = real data, `"unavailable"` = degrade, `"fixture"` = replay), read `asOf` as the freshness marker (not the requested date — see Decision 4), and treat every numeric field as nullable. `changePct` is a **fraction** (`5.333333` = +533.3333%), matching `get_futures_curve.changePct`, so a consumer wanting a percent multiplies by 100.

The tool is exercised in tests and via the record harness, not from application code, until FIX-902 lands.

### 6. Decisions & rules — the sign-off surface

1. **Thin normalization, no screening/ranking.** *Alternative rejected:* emit a ranked/scored candidate list. *Ramification:* keeps FIX-800 mechanical and low-risk, but the raw output is not directly "a shortlist" — FIX-902 must add the screening layer. Locks the screening decision out of the data layer, which is the intended split.
2. **Hard dependency on FIX-798.** *Alternative rejected:* inline a minimal AV fetch in this tool. *Ramification:* FIX-800 can't start until FIX-798 lands; in exchange we avoid a duplicate provider path and inherit the rate-limit + budget discipline for free. Real schedule coupling, called out in §12.
3. **`changePct` stored as a fraction** (`5.333333` for `533.3333%`), not the raw percentage. *Alternative rejected:* keep AV's percentage magnitude. *Ramification:* consistent with `get_futures_curve.changePct` (`0.01` = 1%) so downstream math is uniform, at the cost of a parse step (strip `%`, divide by 100). A consumer expecting "percent" multiplies by 100.
4. **Date-only input; live path returns AV's latest (EOD-on-free) snapshot, not the as-of date's movers.** *Alternative rejected:* attempt historical movers. *Ramification:* AV offers no historical movers and is EOD on the free tier, so a back-dated live run gets the latest completed session tagged with AV's `last_updated`. The scan contract treats the feed as EOD-fresh. Fixture/record mode still snapshots deterministically. Documented as a known property, not a bug.
5. **Standalone data prerequisite for FIX-902 — not implemented ahead of it.** *Alternative rejected:* build it now / fold this into FIX-902's first PR. *Ramification:* the spec is ready, but the tool is a data feed with no user-facing value on its own, so it is **not built until FIX-902 is** (implemented with it, or just before). Tenet 3 is satisfied by *timing* — no unconsumed foundation ever ships — rather than by an epic grouping. It stays a separate, independently-reviewable spec (provider-stable schema, record-seam-exercisable); it simply waits on the shelf until its consumer is in flight.

**Non-goals (scope boundary):** no screening/ranking/scoring/dedup, no scan flow or CLI entry point, no analyst binding, no historical movers, no `Candidate` domain type, no short-interest/crowding signals, and none of the Alpha Vantage provider module itself — all of those are FIX-902, FIX-798, or FIX-810/799 (full list in §12).

**Size estimate: Small** — 1 tool file + schema/registration edits + 1 test + 1 fixture + docs; core logic well under 100 LOC; 1 PR. Blocked on FIX-798.

## Part II — The Build Plan *(for the implementing agent)*

### 7. Technical design

#### Architecture

All changes are inside `labs/trading-desk`. No framework packages change.

```
lib/providers/alpha-vantage.ts   (created by FIX-798)  → add fetchAlphaVantageTopMovers()
flows/analysis/tools/schemas.ts                        → add schemas + registrations + sourceTag value
flows/analysis/tools/data/get_top_movers.ts            → NEW tool handler
flows/analysis/tools/index.ts                          → export get_top_movers
flows/analysis/tools/empty-payloads.ts                 → add get_top_movers builder
fixtures/_macro/2026-05-06/top-movers.json             → NEW fixture
test/get-top-movers.spec.ts                            → NEW test
README.md, CLAUDE.md                                   → docs
```

**The convention this mirrors.** The desk has a mature single-provider, market-wide (date-only) data-tool convention. The closest analog is **`get_futures_curve`** (`get_futures_curve.ts` + `get-futures-curve.spec.ts`): date-only input, single-provider, `_macro` sentinel fixture directory, degrades to `emptyPayload(source: "unavailable")` on no-key / failure, tagged with a provenance `source`. `get_market_news` and `get_macro_indicators` are the same date-only market-wide shape. This tool mirrors that convention exactly; it introduces no new abstraction.

Key shared machinery reused unchanged:

- `resolveToolPayload(tool, input, ctx, fetchLive)` (`runtime/resolve.ts`) — the single dispatch point for fixture / live / record modes.
- `getOrFetch` (`lib/cache.ts`) — process-scoped 120s TTL cache, invoked by `resolveToolPayload` on the live path. **Cache-key caveat:** `getOrFetch` keys on `JSON.stringify(input)`, so a differing `date` in the same 120s window triggers a *separate* AV call — expensive against the 25/day free budget for an endpoint whose live result is date-agnostic. The `date` cannot simply be dropped from the cache key: `resolveToolPayload` reuses the same `input` for the `_macro/{date}/` fixture path and the recorder, so normalizing it tool-locally would break fixture routing. The resolution is a **caller contract** (see Data flow), not a shared-machinery change: FIX-902 must use a single canonical `date` per live scan batch so movers reads collapse to one AV call. Deeper live-path cache normalization (keying date-agnostic endpoints on a sentinel) is a shared-`resolve.ts` change, out of scope here and flagged for FIX-902 if the batch contract proves insufficient.
- `emptyPayload` (`empty-payloads.ts`) — schema-valid `source: "unavailable"` skeleton.
- `loadFixture` (`runtime/fixtures.ts`) — resolves a no-`ticker` input to the `_macro` sentinel directory.

#### Alpha Vantage `TOP_GAINERS_LOSERS` shape (verified against the live `demo` endpoint)

Top-level keys: `metadata`, `last_updated`, `top_gainers`, `top_losers`, `most_actively_traded`. Each array element has exactly `ticker`, `price`, `change_amount`, `change_percentage`, `volume` — **all strings**, e.g. `{ "ticker": "CELUW", "price": "0.0019", "change_amount": "0.0016", "change_percentage": "533.3333%", "volume": "153976" }`. `change_percentage` carries a trailing `%`.

Two provider realities the normalizer must handle:

1. **Rate-limit / exhaustion returns HTTP 200** with a `{ "Note": … }` or `{ "Information": … }` body rather than an error status. FIX-798's shared AV request helper treats those bodies as failures (throw). `fetchAlphaVantageTopMovers()` calls through that helper, so it inherits the behavior — it does not re-implement the check.
2. **The endpoint returns the latest completed session's movers, not intraday-realtime** — and has no historical/as-of parameter. On the **free tier it is end-of-day** (realtime / 15-min-delayed movers are premium-gated). It always returns AV's most-recent snapshot regardless of the desk's as-of `date`. This is acceptable for candidate generation (a scan surfaces recent movers), but two things must be documented so nothing downstream mis-reads it: (a) it is **EOD on a free key**, not live intraday; (b) a back-dated `date` still returns AV's latest snapshot, not that date's movers. `last_updated` (AV's own timestamp) is surfaced as `asOf` and is the authoritative freshness marker — FIX-902 should treat the feed as EOD-fresh unless a premium tier is confirmed.

#### API surface

**Provider fetcher** (`lib/providers/alpha-vantage.ts`):

```ts
/** Market-wide top gainers / losers / most-active via Alpha Vantage
 *  TOP_GAINERS_LOSERS. Latest completed session (EOD on the free tier);
 *  no historical/as-of param. Calls through the shared AV request helper
 *  (key gate, Note/Information rate-limit-as-failure, daily-budget
 *  accounting). Throws on transport/response failure so the tool handler
 *  falls through with one try/catch; per-field coercion never throws. */
export async function fetchAlphaVantageTopMovers(
  input: { date: string },
): Promise<ToolOutput<"get_top_movers">>;
```

- Fetches `function=TOP_GAINERS_LOSERS`.
- Maps each element through a single local helper `num(s)` that returns `null` for anything that is not a real number, so a thin/blank field reads honestly instead of fabricating a zero:

  ```ts
  const num = (s: string | undefined): number | null => {
    const t = s?.trim();
    if (!t) return null;                    // "" and "   " → null, NOT 0 (Number("") === 0)
    const n = Number(t);
    return Number.isFinite(n) ? n : null;   // rejects NaN AND Infinity/overflow
  };
  // change_percentage carries a "%" unit; REQUIRE it, else the value is
  // untrusted → null (a unitless "0.05" must not silently become 0.0005).
  const pct = (s: string | undefined): number | null => {
    const t = s?.trim();
    if (!t || !t.endsWith("%")) return null;
    const n = num(t.slice(0, -1));
    return n === null ? null : n / 100;      // "533.3333%" → 5.333333 (fraction)
  };
  ```

  `price`/`change_amount`/`volume` → `num(field)`; `change_percentage` → `pct(field)`. **This coercion is local and never throws** — a single malformed, blank, or unitless row yields `null` fields with the ticker retained, not a failed payload. (The `Number.isFinite` guard is why the schema does not also need `.finite()`; add it as belt-and-suspenders only if a reviewer prefers the schema to reject non-finite too.)
- `source: "alphavantage"`, `asOf: json.last_updated` (**required** — do *not* fall back to `input.date`; a success body missing `last_updated` is shape drift and throws, see below). The live path never stamps `input.date`, which on a back-dated run would read as falsely fresh. Note the `asOf` provenance **across modes** (verified against `runtime/fixtures.ts`): on a successful **live** fetch `asOf` is AV's `last_updated` (EOD timestamp); in **fixture** replay the loader preserves the *recorded* `asOf` — it rewrites only `source`, never `asOf` — so a replayed payload carries the snapshot's real recording time, which will generally be older than the requested `date`; only the **`unavailable`/`emptyPayload`** path stamps `asOf: input.date`. FIX-902 must read `asOf` as the freshness marker and must **not** assume it equals the requested `date` — in fixture mode it deliberately won't, so a back-dated replay reads honestly stale rather than falsely fresh.
- **Throws only** (via the shared helper) on: no-key, non-2xx, a `Note`/`Information` rate-limit body, top-level `JSON.parse` failure, a missing/non-array `top_gainers`/`top_losers`/`most_actively_traded`, or a **missing/empty `last_updated`** (a success body without it is shape drift — degrade to `unavailable` rather than fabricate a freshness). Do **not** re-implement the rate-limit-body check here. Field-level parsing (above) is explicitly *not* in this throw set.

**Schemas** (`flows/analysis/tools/schemas.ts`):

```ts
// Add "alphavantage" to the sourceTag enum IF FIX-798 has not already.
// moverEntry stays a PRIVATE const — mirror `newsItem` in schemas.ts, which
// is not exported; only the parent schema (topMoversSchema) is public. Export
// the entry only if/when FIX-902 has a concrete need to import the row shape.
const moverEntry = z.object({
  ticker: z.string(),
  price: z.number().nullable(),
  changeAmount: z.number().nullable(),  // kept: AV supplies it directly; deriving from price×changePct would inherit changePct's rounding
  changePct: z.number().nullable(),   // fraction: 0.05 = +5%
  volume: z.number().nullable(),
});
export const topMoversSchema = z.object({
  source: sourceTag,
  asOf: z.string(),
  gainers: z.array(moverEntry),
  losers: z.array(moverEntry),
  mostActive: z.array(moverEntry),
});
// toolInputSchemas:  get_top_movers: z.object({ date: z.string().min(1) })
// toolOutputSchemas: get_top_movers: topMoversSchema
// TOOL_FILE_NAMES:   get_top_movers: "top-movers.json"
```

Every entry field is nullable so a malformed/thin AV row degrades honestly (BP-020 / BP-023) rather than dropping the ticker or fabricating a zero. No array cap — AV returns ≤20 per list and the tool is unbound to any prompt, so there is no prompt-budget reason to truncate (tenet 3, no speculative knob).

**Reference files for the implementer:** the **handler shape** mirrors `get_market_news.ts` (thin handler → provider fetch → `emptyPayload` degrade), while the **test shape** mirrors `get-futures-curve.spec.ts` (date-only `_macro` fixture + degrade-path coverage). They are different files on purpose — do not look for both patterns in one place.

**Tool handler** (`flows/analysis/tools/data/get_top_movers.ts`) — mirrors `get_market_news`:

```ts
  description:
    "Market-wide top gainers, losers, and most-actively-traded US tickers (candidate generation; not ticker-scoped).",
  inputSchema: toolInputSchemas.get_top_movers,

```

**Empty payload** (`empty-payloads.ts`):

```ts
get_top_movers: (i) => ({ source: "unavailable", asOf: i.date, gainers: [], losers: [], mostActive: [] }),
```

#### Data flow

`get_top_movers.execute` → `resolveToolPayload` branches on `dataSource`:

- **fixture** → `loadFixture` reads `fixtures/_macro/{date}/top-movers.json` (no ticker → `_macro`).
- **live** → `getOrFetch("get_top_movers", input, fetchLive)`; `fetchLive` gates on `hasAlphaVantageKey()`, calls `fetchAlphaVantageTopMovers` inside `try/catch`, degrades to `emptyPayload` on throw (no-key, rate-limit body, network, parse). Budget exhaustion surfaces as a throw from FIX-798's helper → same degrade path.
- **record** → live path, then `recordFixture` persists the payload to the corpus.

**Caller contract (budget):** because the live cache key includes `date` (cache-key caveat above) and each miss costs 1 of 25 free-tier requests/day, a live scan must poll movers with a **single canonical `date`** per batch (e.g. the run's as-of date), so all analysts/steps in the 120s window share one AV call. This is FIX-902's contract to honor; FIX-800 documents it here.

#### State management

None. The tool reads only `ctx.session.state.dataSource` (via `pickMode`) like every other data tool. No new session state, resources, or scopes.

### 9. Edge cases & error handling

| Case | Expected behavior |
| --- | --- |
| No `ALPHAVANTAGE_API_KEY` | Live path: no fetch, `emptyPayload` (`unavailable`). Test asserts `fetch` not called. |
| AV rate-limit / exhaustion (`{Note}`/`{Information}`, HTTP 200) | Shared helper throws → tool catches → `unavailable`. |
| AV daily budget exhausted (FIX-798 guard) | Helper throws → `unavailable` (degrade, don't throw). |
| Non-2xx / network error | Helper throws → `unavailable`. |
| Malformed numeric string in a row (`price: "N/A"`) | That field → `null`; ticker retained. |
| **Blank / whitespace numeric field (`price: ""` or `" "`)** | `null`, **not `0`** — the `num()` helper trims and rejects empty before `Number()` (guards the `Number("") === 0` trap). |
| Non-finite (`Infinity`/overflow-like) | `null` — `Number.isFinite` guard in `num()`. |
| `change_percentage` without `%` or non-numeric | `changePct` → `null`; row retained. |
| Empty AV arrays | Payload with empty `gainers`/`losers`/`mostActive`, `source: "alphavantage"` — a valid "market quiet" result, distinct from `unavailable`. |
| Back-dated as-of `date` (live) | Returns AV's latest completed session (EOD on free tier), not that date's movers; `asOf` = AV `last_updated`. Documented, not an error. |
| Live success body missing `last_updated` | Shape drift → helper throws → `unavailable`. Never stamp `input.date` (would read as falsely fresh on a back-dated run). |
| Fixture missing for `_macro/{date}` in fixture mode | `FixtureMissingError` (existing behavior, unchanged). |

**Error taxonomy:** all live-path failures are non-retryable at the tool layer and collapse to `unavailable`. Retry/backoff, if any, is FIX-798's request helper's concern, not this tool's.

**Second-path checklist (BP-035) for the changed surface:** the *legacy* path is a no-op (new tool, no persisted shape to dual-read). The *null-boundary* path is the whole point of the coercion contract (every field nullable, tested). The *concurrent* path is the cache-key/budget caveat (a single canonical `date` per batch). *Multi-tenant* is n/a (market-wide, no user scoping). *Cost-observability* is the 25/day budget, surfaced via FIX-798's accounting and the caller contract. The *off/new-state* of the one flag that matters — `hasAlphaVantageKey()` false — is the no-key degrade test.

### 10. Testing strategy

**Goal & goal check.** No separate real-model goal check applies: no LLM is involved (data tool), and the real observable outcome — the fetcher parsing AV's live stringly-typed response into a valid `topMoversSchema` payload — is exercised by the record step below, which *is* the real-path evidence (tenet 7). The verification weight matches the tool's siblings (`get-futures-curve.spec.ts` is mocked-vitest-only) rather than adding heavier ceremony. Two layers:

1. **CI specs (primary, deterministic)** — the mocked vitest behaviors below. The regression guard; runs on every push.
2. **Real-provider proof (one-time, out-of-CI) = a dedicated record seam.** `get_top_movers` is **unbound** — no `analyze`-flow action or analyst tool list references it — so a `dataSource: "record"` **analyze run will never execute or record it**. The fixture + real-provider proof therefore needs its own explicit seam. Add a tiny record harness for step 5: a `scripts/record-top-movers.ts` (or a one-off `testBlock(get_top_movers, { input: { date }, session: { state: { dataSource: "record", … } } })`) run once with a real `ALPHAVANTAGE_API_KEY`. That single invocation makes the one real AV call, confirms the fetcher parses AV's live response into a valid `topMoversSchema` payload tagged `source: "alphavantage"`, and writes `fixtures/_macro/2026-05-06/top-movers.json` via the record path. This record run is a **required signoff step**, not optional: the CI specs mock `fetch`, so without a real record run the live fetcher (URL, shared helper, body parsing) is never exercised and could ship broken. Manual fixture curation does **not** substitute for it — if the tool must ship before a real run is possible, mark the live path unverified (§8 step 5) rather than treating a hand-curated fixture as real-path proof.

   *Corrections from earlier drafts:* (a) `fsdev block get_top_movers --dataSource live` does **not** work — `fsdev block` resolves a default-exported block from a file path and seeds only `userId`, so `pickMode` defaults to `fixture` and it never reaches AV. (b) "Just do a record-mode analyze run" does **not** work either, for the unbound reason above. The dedicated record seam is the correct mechanism — a step-5 deliverable.

**CI specs** (`tdd`, vitest, deterministic — mirror `get-futures-curve.spec.ts`, use `testBlock` per AGENTS.md rule 4, `_resetCache()` in `beforeEach`, `chdir` to app root). Each behavior is a tracer-bullet cycle:

1. **Fixture load** — `dataSource: "fixture"`, input `{ date: "2026-05-06" }` → `source: "fixture"`, non-empty `gainers`, first entry has numeric `price` and `changePct`.
2. **No-key live degrade** — `dataSource: "live"`, `ALPHAVANTAGE_API_KEY` unset → `source: "unavailable"`, `fetch` spy not called, empty arrays.
3. **Live happy path** — key set, `fetch` mocked to return the AV JSON shape (string fields) → `source: "alphavantage"`; assert `change_percentage: "533.3333%"` parses to `changePct ≈ 5.333333` and `price` is a number.
4. **Rate-limit body degrade** — key set, `fetch` mocked to return HTTP 200 `{ "Note": "…limit…" }` → `source: "unavailable"` (proves the helper's body check + tool catch compose). If FIX-798's helper is what throws, this test also guards the integration seam.
5. **Coercion traps (malformed / blank / unitless)** — one mocked live row each with `price: "N/A"`, `price: ""` (and `price: " "`), and `change_percentage: "0.05"` (no `%`) → every trapped field is `null` with the ticker retained. These assertions are the regression guard for the §7 coercion contract: the blank case fails if `Number("")`'s `0` leaks through, and the unitless case fails if `"0.05"` is divided to `0.0005`.

Reference patterns: `test/get-futures-curve.spec.ts` (date-only market-wide, degrade paths), `test/get-insider-transactions.spec.ts` (single-provider degrade), `write-block-tests` for the mock-context idiom.
