# FIX-823: Trading-desk — persist last-known price + as-of so holdings can be valued without a live refresh — Implementation Spec

## 1. TLDR

**Plain-language summary.** Right now the trading-desk only remembers *how much* of each stock you own, not *what it's worth*. Every time it needs a dollar value it has to phone out to a price feed and multiply on the spot, and the moment you close the tab that price is forgotten. This change gives the desk a small durable price book — one row per ticker with the last price we saw and when we saw it — so it can value your portfolio instantly from memory, honestly label how old each price is, and let a future "whole household" view add up the same holding across accounts with a normal database query instead of recomputing everything from scratch.

**Technical statement.** Replace the ephemeral user-scoped `portfolioQuotes` FSD resource with a durable, ticker-keyed `app.quotes` Postgres table on the FIX-772 model layer; persist `getQuotes` results there, read them at the analysis seed and in the Portfolio UI via the repository / a REST route, keep market value **derived** (`quantity × price`) through the existing `value-holding.ts` seam, and thread a per-quote `asOf` into that seam so consumers can show honest per-holding staleness.

**Deliverables** (grouped to mirror the Implementation Sequence in §5):

- **Model layer:** Add an `app.quotes` table (`ticker` PK, `price`, `as_of`, `source`, `fetched_at`) to `labs/trading-desk/src/db/schema.ts` via a new Drizzle migration `0007_*`; add `getQuotes(tickers)` + `upsertQuotes(rows)` (and the `QuoteRow`/`QuoteInput` types + `mapQuote` numeric-coercing read boundary) to `labs/trading-desk/src/db/repository.ts`.
- **Write path:** Rewrite `getQuotes`' persistence in `labs/trading-desk/src/flows/portfolio/get-quotes.ts` to `upsertQuotes` into the table (only non-null prices, carrying `source`) instead of `patchState` on the resource; retire `portfolioQuotesResource` from `portfolio-resources.ts` and deregister it in `flow.ts`.
- **Server read path:** Point the analysis seed (`orchestration/guards.ts` → `build-portfolio-context.ts`) at `getQuotes(tickers)` from the repository instead of `ctx.resources.portfolioQuotes.state`.
- **UI read path:** Add `GET /api/portfolio/quotes` route + a `use-quotes.ts` fetch hook; migrate `portfolio-pane.tsx` off `useResource("portfolioQuotes")` to that hook, refetching after the `getQuotes` action.
- **Valuation staleness:** Extend `ResolvedPrice` in `value-holding.ts` with `asOf: string | null` (populated for quote-sourced prices, null for par/statement/unavailable) and surface per-holding `asOf` in `holdings-table.tsx`'s row model.
- **Docs:** Update `labs/trading-desk/README.md` and `labs/trading-desk/CLAUDE.md` — move the quotes cache from the "resources" side of the FIX-772 resource-vs-table criterion to the "tables" side and flip the `FIX-823 (deferred)` marker.
- **Tests:** Repository round-trip + valuation-with-asOf + seed-parity CI specs; a real-path goal check under `goals/trading-desk-portfolio/persist-last-known-price/`.

**Size estimate.** **Medium** (multi-file, single PR, ~300–450 LOC across schema/repo/flow/UI/docs/tests).

## 2. Overview

Linear issue: [FIX-823](https://linear.app/fixpoint-labs/issue/FIX-823/trading-desk-persist-last-known-price-as-of-so-holdings-can-be-valued).

A holding stores `quantity` and (informational) `costBasis` but no notion of what it is worth. Market value is recomputed live every read — in the Portfolio pane and at the analysis seed — from prices held in the transient `portfolioQuotes` resource, which is a per-user KV cache with no query/join/aggregate semantics. This spec promotes that cache to a durable, ticker-keyed `app.quotes` table on the FIX-772 relational model layer, so any consumer (Portfolio UI, analysis seed, the future household view in FIX-762) can value a position from persisted state without a live fetch and can label staleness honestly. Value stays derived at read time; nothing is persisted that couples value to `quantity`.

## 3. Background & Research

### 3.1 How this area works today

- **The lab** lives at `labs/trading-desk/` (package `@flow-state-dev/trading-desk`). FIX-772 moved accounts + holdings from an inline-array resource to a Postgres relational model layer under `src/db/` (Drizzle over PGlite in dev / node-postgres on deploy), reached through a memoized `getRepository()` singleton in `lib/portfolio-db.ts`. Subsequent issues added `ledger_events` (FIX-774), `realized_gains` + `tax_profiles` (FIX-874), and split handling (FIX-876). FIX-773 added a two-level asset taxonomy (`asset_class`/`asset_type`/`attributes` jsonb) and **per-type valuation**.
- **The single valuation seam is `src/flows/portfolio/value-holding.ts`.** `resolveHoldingPrice(holding, quote)` returns `{ price, priceSource }` where `priceSource ∈ "quote" | "par" | "statement" | "unavailable"`: equity/etf/mutual_fund/crypto value off the live quote; cash/money_market at par $1.00; bond/option off the carried per-unit `attributes.markPrice`; everything else `unavailable`. `holdingMarketValue` is uniformly `quantity × price`. Both the Portfolio pane and the analysis seed value through this one module so a holding never values two ways.
- **Prices come from `getQuotes`** (`src/flows/portfolio/get-quotes.ts`), a flow handler that fetches last-close per ticker (bounded, retried fan-out) and — because `session.sendAction` resolves to a request envelope, not the handler's output — writes the whole result to the user-scoped, `flowIsolation:false` `portfolioQuotesResource` (`portfolio-resources.ts`). The pane reads it via `useResource("portfolioQuotes")` after `session.refresh()`; the analysis seed reads `ctx.resources.portfolioQuotes.state` at `guards.ts` and passes `{ quotes, fetchedAt }` into `build-portfolio-context.ts`. Both readers join holdings ⋈ quotes **in JS by upper-cased ticker**.
- **Staleness handling does not exist** beyond a display label. `asOf`/`fetchedAt` are shown ("Prices: live · as of …") but never compared; there is no per-holding as-of. FIX-773's valuation result carries `priceSource` (provenance) but **no timestamp** — the bond `markPrice` is stored bare in `attributes` with no date.

### 3.2 Why a table (against FIX-772's criterion)

FIX-772 deliberately kept the quotes cache a resource and documented the criterion: *"referential integrity? queried relationally outside the turn? serves the user's domain vs. the workflow? → table; else resource."* FIX-823 is precisely the case that flips it: FIX-762's household aggregation is `holdings ⋈ prices GROUP BY ticker`, a relational query a per-user KV resource cannot serve; the desk wants prices persisted across sessions and joinable, not recomputed per turn. The issue's own guidance — *"price is a per-ticker fact, not per-holding"* — argues for one row per ticker, which is also the exact shape FIX-762 will `GROUP BY`. This is not the resource sweet spot (agent-facing session state / scratch) that theses and the PDF-import channel occupy; it is domain data queried outside the turn. Verdict of the necessity gate: **build as scoped.**

### 3.3 Rejected alternatives

- **Value or price on the holding row.** Rejected per the issue: persisting *value* couples it to `quantity` (stale on every trade even when price didn't move); persisting *price* per holding duplicates a per-ticker fact across every account holding it, turning a refresh into an N-row fan-out and inviting divergence. Value stays derived; price lives once per ticker.
- **Keep the resource, add a parallel table (dual-write).** Rejected per FIX-772's single-source-of-truth discipline — a resource shadowing a table reintroduces the dual-write drift FIX-772 warns against. The resource is **retired**, not shadowed.
- **User-scoped quotes table (`(user_id, ticker)` PK).** Rejected: a ticker's last-known price is a global fact (public data, same for everyone); user-scoping duplicates it per user and complicates FIX-762's `GROUP BY ticker`. Global keying is cleaner and multi-tenant-safe (no private data in a price), and it is not poisonable by fixture data because fixture-mode `getQuotes` is not persisted at all (§4.3). The `source` column records provenance (`"live"`, extensible to provider names).

### 3.4 Key Decisions & Ramifications (top 5)

1. **Quotes become a *global* `app.quotes` table keyed by `ticker` alone; `portfolioQuotesResource` is retired (not shadowed).**
   *Alternative rejected:* keep the resource, or make the table user-scoped.
   *Ramification:* one row per ticker, shared across users/flows, is exactly FIX-762's `GROUP BY ticker` shape and avoids per-user duplication; single source of truth (no dual-write drift). Locks in that a refresh by anyone updates the shared last-known price (correct for public price data). Forces the UI read off `useResource` (live SSE) onto a REST hook + explicit refetch — the FIX-772 accounts-migration pattern.

2. **Market value stays *derived* at read time (`quantity × price`) through the existing `value-holding.ts` seam; no `value`/`price` column on `holdings`.**
   *Alternative rejected:* persist value or per-holding price.
   *Ramification:* value never goes stale on a trade; valuation logic stays in one place shared by pane and NAV; the coexistence with FIX-773 per-type valuation is automatic (only live-quoted types consult the table; bonds/options/MMF keep valuing off `attributes`/par). Cost: every consumer must join quotes — accepted (it already does).

3. **Introduce the per-quote `asOf` dimension FIX-773 designed but did not build; thread it through `ResolvedPrice` and the UI row model.**
   *Alternative rejected:* leave as-of at the snapshot level only.
   *Ramification:* delivers honest *per-holding* staleness for quote-sourced prices (AAPL fresh, TSLA 3 days old). Bonds/options keep bare statement marks (`asOf: null`, provenance still shown) — capturing a statement date is deferred (needs import changes). Locks the `ResolvedPrice` shape as the place staleness lives, ready for that follow-up.

4. **`getQuotes` stays a flow action but writes to the repository (`upsertQuotes`) instead of the resource; the pane reads quotes via a new `GET /api/portfolio/quotes` route + hook.**
   *Alternative rejected:* convert `getQuotes` to a REST route.
   *Ramification:* minimal UX-plumbing churn (the pane still dispatches the action and shows progress), mirrors how FIX-772 migrated accounts off `useResourceCollectionList`. Reactivity shifts from SSE `resource_change` to an action-completion refetch — the established post-action `refetch()` idiom already in the pane. Only non-null prices are upserted, so a provider hiccup never nulls a good last-known price.

5. **Add the table via a generated Drizzle migration `0007_*`, eyeballing the emitted SQL.**
   *Alternative rejected:* hand-write the migration.
   *Ramification:* follows the established convention (in-process apply on PGlite dev, `scripts/migrate.ts` on deploy). The drizzle snapshot chain sits at `0005` (the hand-written `0006_fold_legacy_split_ratio.sql` data-fix has no snapshot), so `drizzle-kit generate` diffs against `0005`; the generated SQL must be verified to only `CREATE TABLE app.quotes` and not reconcile the manual `0006` step.

## 4. Technical Design

### 4.1 Data model — `app.quotes` (new table)

In `labs/trading-desk/src/db/schema.ts`, under the existing `appSchema` (`pgSchema("app")`), alongside `accounts`/`holdings`/`ledgerEvents`/`realizedGains`/`taxProfiles`:

```ts
export const quotes = appSchema.table("quotes", {
  ticker: text("ticker").primaryKey(),                       // canonical UPPER-CASE ticker
  price: numeric("price").notNull(),                         // last-known per-unit price (coerced to number on read)
  asOf: timestamp("as_of", { withTimezone: true, mode: "string" }),        // the price's own market/quote time (nullable-honest)
  source: text("source").notNull(),                          // provenance: 'live' | 'fixture' (mirrors the old dataSource)
  fetchedAt: timestamp("fetched_at", { withTimezone: true, mode: "string" })
    .notNull()
    .default(sql`now()`),                                    // when we cached it (cache age, distinct from as_of)
});
```

Rationale for columns: the issue asks for `ticker, price, as_of, source`; `fetched_at` is retained because the retired resource carried an envelope `fetchedAt` (cache-write time) distinct from each quote's `asOf` (market time), and both are useful — `as_of` for honest staleness labeling, `fetched_at` for cache freshness. `price` is `numeric` (not `double precision`) per FIX-772's hard rule — exact in storage, coerced to a JS `number` via `Number(...)` at the read boundary, because downstream does `quantity * price` money math. `price` is `NOT NULL`: an unresolvable ticker gets **no row** (valuation returns `unavailable`), so a failed refresh never nulls out a good last-known price — the write path filters null prices before upsert.

**Migration.** Run `pnpm --filter @flow-state-dev/trading-desk db:generate` (offline; `drizzle.config.ts` has `schemaFilter: ["app"]`, no DB connection needed) to emit `src/db/migrations/0007_*.sql`; commit it. Verify the emitted SQL only adds `app.quotes` (snapshot-chain caveat, §3.4 decision 5). **Prefer the generated path** — `drizzle-kit generate` writes both `0007_*.sql` *and* the matching `src/db/migrations/meta/0007_snapshot.json`, which re-includes `app.quotes` and closes the snapshot chain (the missing `0006` snapshot is a data-fix and stays a one-off gap, harmless once `0007` re-snapshots the full schema). This is the first `db:generate` since the hand-written `0006`; if drizzle-kit balks at the journal/snapshot mismatch and you hand-write `0007_*.sql` instead, you **must also commit a matching `0007_snapshot.json`** (schema-including) — otherwise the *next* `db:generate` diffs against the stale `0005` snapshot and tries to `CREATE TABLE app.quotes` a second time. (The runtime migrators apply from `_journal.json` and don't need snapshots, but the snapshot is required to keep future generation correct — this is why `0007`, a schema migration, differs from the data-only `0006`.) It applies in-process on PGlite dev boot (`getBacking()` → `createMigratedPgliteDb`) and via `scripts/migrate.ts` on deploy — no code change to either runner (both iterate the migrations folder). Add the drizzle imports the table needs if not already present (`numeric`, `text`, `timestamp`, `sql` are all imported in `schema.ts` today).

### 4.2 Repository surface (`src/db/repository.ts`)

Add to `PortfolioRepository` and its factory:

```ts
export type QuoteRow = {
  ticker: string;
  price: number;              // coerced from numeric string
  asOf: string | null;        // ISO
  source: string;             // 'live' | 'fixture'
  fetchedAt: string;          // ISO
};

export type QuoteInput = {
  ticker: string;
  price: number;              // non-null by construction (write path filters nulls)
  asOf: string | null;
  source: string;
};

// on PortfolioRepository:
getQuotes(tickers: string[]): Promise<QuoteRow[]>;   // batch read for a set of tickers (upper-cased); empty tickers → []
upsertQuotes(rows: QuoteInput[]): Promise<void>;     // transactional batch upsert on ticker PK; fetched_at = now()
```

- `mapQuote(row): QuoteRow` is the read boundary — `price: Number(row.price)` (the FIX-772 numeric-coercion rule) **and normalize the timestamp columns to a stable ISO string** the way the existing mappers do: `fetchedAt: new Date(row.fetchedAt).toISOString()` and `asOf: row.asOf ? new Date(row.asOf).toISOString() : null`. `timestamp(..., { mode: "string" })` returns a driver-dependent string shape (PGlite vs node-postgres differ), so passing it through would make UI provenance text and tests driver-dependent instead of the ISO contract the rest of the repository upholds. `source` passes through.
- `getQuotes(tickers)` normalizes to upper-case and uses `inArray(quotes.ticker, tickers)`; returns `[]` for an empty input (never a full-table scan).
- `upsertQuotes(rows)` runs one `db.transaction()`, upper-cases `ticker`, `onConflictDoUpdate` on `ticker` setting `price`/`asOf`/`source`/`fetchedAt = now()`. Empty input is a no-op.
- **Deliberately no `getAllQuotes()` / aggregate queries** — FIX-772's "foundation surface only" discipline. FIX-762 adds its own household aggregate queries when it lands (YAGNI, BP-038).

### 4.3 Write path — `getQuotes` (`src/flows/portfolio/get-quotes.ts`)

The handler already computes `quotes: { ticker, price: number|null, asOf: string|null }[]` and knows `mode` (`fixture|live`). Replace the resource write:

```ts
// was:
await ctx.resources.portfolioQuotes.patchState({ dataSource: mode, fetchedAt: …, quotes });

// becomes: persist LIVE quotes only (see fixture-pollution note below)
if (mode === "live") {
  const repo = await getRepository();
  await repo.upsertQuotes(
    quotes
      .filter((q): q is { ticker: string; price: number; asOf: string | null } => q.price !== null)
      .map((q) => ({ ticker: q.ticker, price: q.price, asOf: q.asOf, source: "live" })),
  );
}
```

**Fixture-mode writes are NOT persisted (prevents global-cache pollution).** `getQuotes`' `dataSource` is caller-controlled and *defaults to `fixture`*. Because `app.quotes` is a single global row per ticker (§4.1), persisting a fixture-mode result would overwrite the shared live last-known price with demo data for **every** user and the analysis seed (which maps rows dropping `source`). So the durable cache holds live prices only — a fixture-mode `getQuotes` is a no-op on persistence. This is safe: the Portfolio pane always requests `live` (CLAUDE.md "Prices"), so fixture-mode `getQuotes` is only ever a dev/test affordance and has no UI valuation path. The `source` column stays (records `"live"`, extensible to provider names later) and documents provenance; it is never `"fixture"` in the table.

Null-priced quotes are also dropped (keep the prior last-known row). `getRepository` is imported from `@/lib/portfolio-db` (the `guards.ts` precedent). The handler's return shape is unchanged (its output is already discarded by the runtime). Remove the now-unused `ctx.resources.portfolioQuotes` reference from the handler and its `resources` declaration.

### 4.4 Retire the resource

`portfolioQuotesResource` is registered on **both** flows (the portfolio flow owns it; the analysis flow registers it so `seedSession` can read it cross-flow). Deleting the export without clearing every registration/import breaks typecheck, so retire it at all sites — do this step **last** among the code steps (§5), once no reader remains:

- **Definition:** delete `portfolioQuotesStateSchema`, `PortfolioQuotesState`, and `portfolioQuotesResource` from `src/flows/portfolio/portfolio-resources.ts` (keep `pdfImportResource` and `thesesCollection`); update the module header (drop the `portfolioQuotesResource` bullet).
- **Portfolio flow:** remove `portfolioQuotes` from the `resources` map (and its import) in `src/flows/portfolio/flow.ts`. `getQuotes` stays a registered action.
- **Analysis flow:** remove the `portfolioQuotesResource` import (`src/flows/analysis/flow.ts:28-31`) and its `resources` registration (`:126`).
- **Analysis seed:** remove the import (`orchestration/guards.ts:38-42`) and the `resources` map entry (`:67`) in `seedSession`, in addition to the `.state` read at `:141` migrated in §4.5.
- **`thesesCollection` doc note (`portfolio-resources.ts:757` region / CLAUDE.md FIX-760 analogy):** its comment describes the collection as *"cross-flow like `portfolioQuotes`"*. Update that analogy to name the pattern (user-scoped `flowIsolation:false`) without naming the retired resource (BP-034 provenance sweep — see §9.3).
- **No data migration / cleanup.** Orphaned user-scoped resource rows left in the framework store are inert (nothing reads an undeclared ref); BP-030 dual-read does not apply because the field is no longer read at all.

### 4.5 Server read path — analysis seed

- `orchestration/guards.ts` `seedSession`: it already calls `getRepository().getPortfolio(uid)` for accounts/holdings. Collect the held tickers from those holdings and call `repo.getQuotes(tickers)`; drop the `ctx.resources.portfolioQuotes.state` read. Map the `QuoteRow[]` to the `QuoteLike[]` (`{ ticker, price, asOf }`) `build-portfolio-context.ts` already accepts — dropping `source` here is safe because the table only ever holds live rows (§4.3), so there is no fixture row to filter out.
- `build-portfolio-context.ts`: signature and math are essentially unchanged (it already takes `quotes: QuoteLike[]` and a `snapshotAsOf`). Two refinements:
  - Source `snapshotAsOf` from the quote rows (e.g. the **oldest** `asOf` among priced live-quoted holdings — honest "as of at least" labeling), instead of the resource envelope `fetchedAt`.
  - No change to the per-holding `holdingMarketValue(h, { price })` call — the table read supplies `price` exactly as the resource did.

### 4.6 UI read path — Portfolio pane

- **New route** `app/api/portfolio/quotes/route.ts`: `GET` takes a **`userId` query param** — mirroring the `accounts/route.ts` precedent exactly, which requires `userId` as a query param under the lab's documented dev-only client-asserted auth posture (there is no server-derived identity in a plain Next route context yet; BP-031 is deferred to whenever real server auth lands, tracked lab-wide). The handler loads the user's holdings' tickers via `getRepository().getPortfolio(userId)` and returns `repo.getQuotes(tickers)` as JSON. (The client passes `userId`; the *ticker set* is derived server-side from holdings — the client never passes a ticker list.)
- **New hook** `components/portfolio/use-quotes.ts`: a fetch hook over that route returning `QuoteRow[]` + a `refetch()`, mirroring `use-portfolio-accounts.ts` — including sourcing `userId` from `useFlowContext()` and passing it as the query param, exactly as `usePortfolioAccounts()` does.
- **`portfolio-pane.tsx`:** replace `useResource(session, "portfolioQuotes")` (`:131`) + the resource-derived `priceMap` with `useQuotes()`; build `priceMap` from the hook's `QuoteRow[]` (same `Map<upperTicker, { price, asOf }>`). **Gate the refetch on the action *completing*, not on `sendAction` resolving.** Retiring the resource removes the `resource_change` SSE projection that used to self-correct a stale read, and `session.sendAction(...)` resolves when the request stream attaches — *before* `upsertQuotes` commits (see `useSession`'s `in_progress`-on-attach behavior; the `report-thesis-panel.tsx` comment documents this for resource writes). So a naive `.then(refetch)` races ahead of the write. The implementer must await the `getQuotes` request reaching a terminal status before calling the quotes `refetch()` (await the request-completion signal the client exposes; if `sendAction` doesn't surface terminal completion, poll the request status). The goal check (§7) is the seam that proves the refetch sees the committed rows. **Provenance line edit:** the existing line (`:759-760`) reads envelope fields `quotes?.dataSource` and `quotes.quotes[0].asOf` that `QuoteRow` doesn't have — derive the "live" label from the rows' `source` and "as of" from the rows' `asOf`/`fetchedAt`.
- **`holdings-table.tsx`:** `buildHoldingRowModel` (`:169-171`) already calls `resolveHoldingPrice(holding, quote)`; with `asOf` added to `ResolvedPrice` (§4.7), add a **`priceAsOf: string | null`** field to `HoldingRowModel` so both the table row and the stacked mobile card can render per-holding staleness next to the existing `priceSource` marker. Name it `priceAsOf`, **not** `asOf` — `buildHoldingRowModel` already has an input param `asOf: Date` (the "now" baseline for holding-term classification, `:163`); reusing the name for the quote date would conflate two concepts. Missing/stale still renders honestly (`—` / provenance tooltip) — the real-money gate is unchanged.

### 4.7 Valuation staleness — `value-holding.ts`

```ts
export type ResolvedPrice = { price: number | null; priceSource: PriceSource; asOf: string | null };

export function resolveHoldingPrice(
  holding: Pick<Holding, "assetType" | "assetClass" | "attributes">,
  quote: { price: number | null; asOf?: string | null } | undefined,
): ResolvedPrice {
  // cash/money_market → par: { price: 1, priceSource: "par", asOf: null }
  // bond/option → statement mark: { price: mark, priceSource: "statement", asOf: null }  // v1: bare mark has no date
  // equity/etf/mutual_fund/crypto → quote: { price, priceSource: "quote", asOf: quote?.asOf ?? null }
  // other/unavailable → { price: null, priceSource: "unavailable", asOf: null }
}
```

`holdingMarketValue` / `holdingUnrealizedPL` are unchanged (they read only `price`). `asOf` is additive and defaulted, so existing callers that pass `{ price }` still type-check. Par is timeless (`asOf: null` is honest — $1.00 is always current). Statement marks are `asOf: null` in v1 (no captured statement date; provenance `"statement"` already signals "not a live quote").

### 4.8 Error handling

| Case | Behavior |
| --- | --- |
| A refresh returns `price: null` for a ticker | Not upserted; the prior last-known row survives and valuation **keeps using it** (with its older `as_of`, shown as staler — the point of a last-known cache). Only when **no** row was ever cached does valuation read `unavailable` → `—`. |
| A ticker has never been fetched | No row; `getQuotes([...])` omits it; valuation → `unavailable` → `—`. |
| PGlite/pg write fails inside `upsertQuotes` | The `db.transaction()` rolls back; the `getQuotes` action surfaces the error as today. Reads are unaffected (last-known rows intact). |
| `getQuotes([])` (no held tickers) | Returns `[]` without a query. |
| Non-live-quoted types (bond/option/MMF/cash) | Never sent through the quote fan-out (`usesLiveQuote` gate, unchanged); never written to `quotes`; valued off `attributes`/par as today. |
| Fixture-mode `getQuotes` dispatch | **Not persisted** — the write is gated on `mode === "live"` (§4.3), so fixture/demo data never overwrites the shared global row. The pane always requests `live`, so this has no UI impact. |

## 5. Implementation Sequence

Each step is independently testable; later steps depend on earlier ones.

1. **Schema + migration.** Add the `quotes` table to `schema.ts`; generate `0007_*.sql`; verify emitted SQL. *Test:* migration applies to a fresh PGlite DB and re-running is a no-op.
2. **Repository.** Add `QuoteRow`/`QuoteInput`, `mapQuote`, `getQuotes`, `upsertQuotes`. *Test:* upsert inserts then updates on ticker PK; `getQuotes(tickers)` returns coerced-number prices; empty input paths.
3. **Valuation seam.** Add `asOf` to `ResolvedPrice`/`resolveHoldingPrice`. *Test:* quote-sourced carries `asOf`; par/statement/unavailable are `null`; market value unchanged.
4. **Write path.** Rewrite `getQuotes` to `upsertQuotes` (non-null filter, `source: mode`). *Test:* dispatching `getQuotes` writes the expected rows; null prices skipped.
5. **Retire the resource.** Remove `portfolioQuotesResource` from `portfolio-resources.ts` + `flow.ts`; fix the `thesesCollection` doc analogy. *Test:* typecheck; flow builds without the resource.
6. **Server read (seed).** Point `guards.ts`/`build-portfolio-context.ts` at `repo.getQuotes(tickers)`; source `snapshotAsOf` from rows. *Test:* seed-parity — the snapshot over table rows equals the pre-change snapshot for a fixed fixture.
7. **UI read.** Add `GET /api/portfolio/quotes` route + `use-quotes.ts`; migrate `portfolio-pane.tsx` off `useResource`; refetch after `getQuotes`; thread `asOf` into `holdings-table.tsx`. *Test:* route returns the user's tickers' rows; row model carries `asOf`.

## 6. Edge Cases & Error Handling

See the table in §4.8. Additional:

| Edge case | Expected behavior |
| --- | --- |
| Same ticker held in two accounts | One `quotes` row; both holdings value from it (the point of ticker keying; FIX-762-ready). |
| Ticker case mismatch (`brk-b` vs `BRK-B`) | All writes/reads upper-case the ticker (the existing convention); the PK is canonical upper-case. |
| Stale price (old `as_of`) | Row is kept and used; the UI labels it via `asOf`. No TTL/eviction in v1 — staleness is surfaced, not enforced (honest-over-hidden). |
| Concurrent refresh of the same ticker | Last upsert wins (`onConflictDoUpdate`); acceptable for a last-known-price cache. |
| A previously-priced holding sold/removed | Its `quotes` row is left (harmless); no cascade needed (quotes are not FK'd to holdings — they're a per-ticker cache, not per-holding domain data). |

Error taxonomy: write failures are fatal to the `getQuotes` action (surfaced), never silent; read failures degrade to `unavailable` → `—`. Nothing retryable beyond the existing provider-fetch retries in `getQuotes`.

## 8. Non-Goals

- **Bond/option statement-mark `asOf` (per-holding statement date).** FIX-773 stores the bond `markPrice` bare with no date; capturing a statement date needs import-path changes. Out of scope — the `ResolvedPrice.asOf` slot this spec adds is where it lands later. Statement marks value exactly as today (`priceSource: "statement"`, `asOf: null`).
- **Household aggregation queries (FIX-762).** This spec provides the ticker-keyed table FIX-762's `GROUP BY ticker` needs but adds no aggregate query surface (`getAllQuotes`, exposure/concentration). FIX-762 owns those.
- **Multi-asset pricing beyond FIX-773 (FIX-773/FIX-801).** No live bond pricing, ETF look-through, or option chain marks. Coexistence only: live-quoted types use the table; others keep `attributes`/par.
- **Price TTL / background refresh scheduling.** No eviction or auto-refresh cadence; the pane's existing auto-fetch-on-ticker-change effect is unchanged. Staleness is surfaced, not enforced.
- **A framework primitive for app-owned price/cache tables.** Lab-local, second app-owned table; no `@flow-state-dev/*` primitive graduated here — findings still feed FIX-664 (per FIX-772's discipline). *(No matching entry found in `docs/internal/out-of-scope/`.)*
- **Deepening flag (follow-up via `fsd:improve-codebase-architecture`):** the holdings ⋈ quotes JS join is duplicated at two read sites (`portfolio-pane.tsx`'s `priceMap`, `build-portfolio-context.ts`'s `priceByTicker`). Note only the **pane's** `Map` build actually changes in this work (its source switches from the resource envelope to the hook's `QuoteRow[]`); `build-portfolio-context.ts`'s internal map build is untouched (only its caller's inputs change upstream). So this is a genuine defer, not a "we're already editing both, pull it in now" case — the duplication is ~2-3 lines per site. If a third consumer appears (likely FIX-762), a shared `valuePortfolio(holdings, quotes)` helper over `value-holding.ts` is the natural consolidation — not in scope here.

## 11. Open Questions

1. **Quotes table keying — global (`ticker` PK) vs user-scoped (`(user_id, ticker)`).** Spec recommends **global** (§3.3/§3.4 decision 1): matches "price is a per-ticker fact," FIX-762's `GROUP BY ticker`, and avoids per-user duplication; multi-tenant-safe (public price data). Low-stakes confirm — the lab is effectively single-user. *Recommendation: global.*
2. **Keep `getQuotes` a flow action vs convert to a REST route.** Spec recommends **keep it an action** (§3.4 decision 4) to minimize UX churn (the pane dispatches it and shows progress). *Recommendation: keep as action.*
3. **`snapshotAsOf` derivation** — oldest `as_of` among priced holdings (honest "as of at least") vs latest `fetched_at`. Spec leans oldest-`as_of` for honest staleness. Cosmetic; either is defensible.

None of these block implementation; all have a recommended default.
