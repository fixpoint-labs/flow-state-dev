# FIX-831: Retract the public middleware contract; keep the internal seam — Implementation Spec

## 1. TLDR

**Plain-language summary:** During early framework work, we published a way for app authors to wrap block execution in custom interceptors (logging, auth, caching). Nothing in the repo actually uses it, and the problems it was meant to solve are already handled better elsewhere — tool caching lives in plain modules, observability uses the trace system, and cross-cutting behavior belongs in lifecycle hooks or capabilities. This change removes that public API so authors aren't faced with a third overlapping way to wrap blocks, while keeping the internal hook point in the engine so we can build a proper public contract later when a real consumer exists.

**Technical statement:** Remove all author-facing middleware registration (`defineFlow`, `BlockConfig`, `createFlowApiRouter` / `createFlowState`) and `Middleware` type exports from `@flow-state-dev/core`, while retaining `composeMiddleware`, `mergeMiddlewareStacks`, and the `executeBlock` wrapping point fed exclusively through internal `RuntimeConfig`.

**Deliverables:**

- **Core:** Remove `middleware` fields from `FlowDefinition`, `FlowInstance`, `FlowInstanceOptions`, `FlowType`, and `BlockConfig`; remove `middleware` passthrough in `defineFlow`; delete `packages/core/src/types/middleware.ts` and its export from `packages/core/src/types/index.ts`.
- **Engine:** Remove `middleware` from `CreateFlowApiRouterOptions` and `CreateFlowStateOptions`; stop re-exporting compose/types from `packages/engine/src/index.ts`; relocate `Middleware` / `MiddlewareFn` / `MiddlewareContext` types into `packages/engine/src/middleware/types.ts` (engine-internal); keep `RuntimeConfig.middleware`, `ExecuteBlockOptions.middleware`, `composeMiddleware`, `mergeMiddlewareStacks`, and the `executeBlock` chain.
- **Engine execution:** Simplify `runAction` to pass only `runtimeConfig.middleware` (drop `flow.middleware` merge); simplify `executeBlock` to use only caller-provided `options.middleware` (drop `block.config.middleware` merge).
- **Tests:** Rewrite `packages/engine/test/middleware.test.ts` to assert the internal seam via `runtimeConfig.middleware` / `executeBlock({ middleware })` and `composeMiddleware` unit tests — no public builder or `defineFlow` registration.
- **Docs:** Delete `docs/architecture/middleware.md`; add `docs/architecture/internal-execution-seams.md`; update `docs/contributing/architecture-reference.md`, cross-linked architecture docs, `packages/engine/README.md`, and `.claude/skills/add-flow/SKILL.md`.
- **Release:** Breaking `minor` changesets on `@flow-state-dev/core` and `@flow-state-dev/engine`.

**Size estimate:** **Medium** — multi-file, single PR, ~200–350 LOC across core, engine, tests, and docs.

## 2. Overview

- **Linear issue:** [FIX-831](https://linear.app/fixpoint-labs/issue/FIX-831/retract-the-public-middleware-contract-keep-the-internal-seam)
- **Category:** Improvement (routes to `fsd:tdd` tracer-bullet discipline during implementation)

Phase 1 ([FIX-56](https://linear.app/fixpoint-labs/issue/FIX-56/middleware-phase-1-internal-seam-readiness)) required internal runtime seams **without** public interceptor APIs. A full public middleware contract shipped early — three registration tiers, `filter`, short-circuit, `compose`, tests, and architecture docs — with **zero consumers** in `packages/`, `labs/`, or `apps/`. This spec retracts that premature public surface and restores the FIX-56 boundary, preserving the engine's composition machinery for Phase 2 ([FIX-57](https://linear.app/fixpoint-labs/issue/FIX-57/middleware-phase-2-public-contracts-and-registration-api)) when a concrete first consumer exists.

## 3. Background & Research

### Industry patterns

Frameworks consistently separate **public registration** from **internal composition**:

- **Koa / Hono:** Public middleware is `(ctx, next) => …`; `compose` is an implementation detail in the executor package ([Koa guide](https://github.com/koajs/koa/blob/HEAD/docs/guide.md), [Hono compose](https://github.com/honojs/hono/blob/main/src/compose.ts)).
- **tRPC:** Public middleware via `.middleware().concat()`; glue types live in `@trpc/server/unstable-core-do-not-import` ([tRPC middleware](https://trpc.io/docs/server/middlewares), [unstable-core PR](https://github.com/trpc/trpc/pull/5355)).
- **Zero-consumer retraction (pre-1.0):** Hard removal with changelog is acceptable when no external adopters exist ([semver 0.y.z](https://semver.org/spec/v1.0.0.html)).

**Correction:** `BlockConfig.middleware` applies to **handler, generator, and router** builders (`extends Omit<BlockConfig, …>`). **Sequencer does not** have a `middleware` field — docs claiming "all 4 block kinds" are inaccurate.

**Cancelled follow-ups:** [FIX-59](https://linear.app/fixpoint-labs/issue/FIX-59) (cache middleware) and [FIX-60](https://linear.app/fixpoint-labs/issue/FIX-60) (observability middleware) — superseded by tool-layer cache and `block_trace` / `TraceStore`.

### Why full retraction (not partial)

Industry research surfaced a "surgical retract" option (drop block-level only, keep global/flow). The issue scope and FIX-56 guardrail require retracting **all** author-facing registration tiers. Global and flow middleware have the same zero-consumer profile and create the same author-facing ambiguity ("how do I wrap a block?") alongside sequencer composition, capabilities, and lifecycle hooks.

### Key Decisions & Ramifications (top 5)

1. **Decision: Retract all three public registration tiers (global, flow, block).**
   - *Alternative rejected:* Keep global/flow middleware on `createFlowApiRouter` / `defineFlow` since they're "more intentional."
   - *Ramification:* Authors lose every `middleware:` option. Cross-cutting behavior must use lifecycle hooks, `.tap()`, capabilities, structured logging, or `errorCapture`. Phase 2 ([FIX-57](https://linear.app/fixpoint-labs/issue/FIX-57)) re-introduces a designed public contract against a real consumer.

2. **Decision: Move `Middleware` types from `@flow-state-dev/core` to engine-internal modules.**
   - *Alternative rejected:* Keep types in core for isomorphic middleware definitions.
   - *Ramification:* Flow definitions in `core`-only packages can no longer reference `Middleware`. Interception types co-locate with the executor (Hono/tRPC pattern). Clean package boundary: core = builders; engine = execution.

3. **Decision: Keep `RuntimeConfig.middleware` as the sole feed path into `executeBlock`.**
   - *Alternative rejected:* Remove middleware machinery entirely.
   - *Ramification:* Framework-owned instrumentation (e.g., future durability middleware referenced in checkpoint comments) can install stacks internally without a public registration API. `createFlowApiRouter` callers pass middleware only via pre-built `runtimeConfig`, not a top-level `middleware` option.

4. **Decision: Hard delete (no deprecation shim).**
   - *Alternative rejected:* `@internal` + `stripInternal` graduated retraction.
   - *Ramification:* Pre-1.0 + zero consumers makes a deprecation window unnecessary. Breaking `minor` changesets on `core` and `engine`. Any external adopter (unlikely) must inline hooks or wait for FIX-57.

5. **Decision: Replace `docs/architecture/middleware.md` with `internal-execution-seams.md` documenting `InternalExecutionSeams` + internal compose, not user registration.**
   - *Alternative rejected:* Demote `middleware.md` to `docs/internal/` unchanged.
   - *Ramification:* Architecture docs no longer advertise a public middleware API. Contributors see the actual extension points: lifecycle hooks (public) and execution seams (internal).

## 4. Technical Design

### Architecture

```
REMOVE (public)
├── defineFlow({ middleware })           → FlowInstance.middleware
├── handler|generator|router({ middleware }) → BlockConfig.middleware
├── createFlowApiRouter({ middleware })  → RuntimeConfig (top-level option)
├── createFlowState({ middleware })
└── export Middleware* from @flow-state-dev/core/types
└── export composeMiddleware from @flow-state-dev/engine

KEEP (internal)
RuntimeConfig.middleware
  └── runAction forwards → ExecuteBlockOptions.middleware
        └── executeBlock → composeMiddleware(stack) → executeCore()
InternalExecutionSeams (parallel seam, unchanged)
  └── interceptBlockInput/Output, lifecycle hooks
```

#### Type relocation detail

Move the contents of deleted `packages/core/src/types/middleware.ts` into `packages/engine/src/middleware/types.ts`. `BlockMiddlewareContext` becomes:

```typescript
export type MiddlewareContext = {
  block: { name: string; kind: BlockKind };
  input: unknown;
};

export type MiddlewareFn = (
  context: MiddlewareContext,
  next: () => Promise<unknown>
) => Promise<unknown>;

export type Middleware = {
  name: string;
  execute: MiddlewareFn;
  filter?: (block: { name: string; kind: BlockKind }) => boolean;
};

export type BlockMiddlewareContext = MiddlewareContext & {
  metadata: ExecutionMetadata;
  blockContext: ExecuteBlockContext;
};
```

`BlockKind` import: from `@flow-state-dev/core/types` (engine already depends on core).

### Data flow (post-change)

1. Framework code (or tests) sets `RuntimeConfig.middleware` when building runtime config.
2. `runAction` reads `options.runtimeConfig.middleware` and passes it to `executeBlock({ middleware })`.
3. `executeBlock` calls `composeMiddleware(middlewareStack, blockInfo)` around `executeCore()`.
4. `BlockMiddlewareContext` includes `metadata` and `blockContext` for server-side middleware (unchanged).

No author path exists to set middleware via flow or block builders.

### Error handling

| Case | Behavior |
|------|----------|
| `composeMiddleware` with empty stack | Pass-through to `execute()` (unchanged) |
| Middleware calls `next()` twice | Throws `Middleware "<name>" called next() multiple times` (unchanged) |
| Middleware throws | Propagates as execution failure (unchanged) |
| Middleware short-circuits (no `next()`) | Returns intercept value; block not executed (unchanged) |
| TypeScript compile-time | `middleware:` on `defineFlow` / block builders / router options becomes a type error |

### Public alternatives mapping

| Former middleware use case | Public alternative |
|--------------------------|-------------------|
| Timing / logging around blocks | Action `onCompleted` / `onErrored`, structured `logger` on `createFlowState` |
| Per-generator metrics | `block_trace` / `TraceStore`, generator `_runtimeHooks` |
| Input/output transformation | `.tap()` on sequencers, handler logic, `InternalExecutionSeams` (framework-internal) |
| Auth / policy gating | HTTP-layer auth ([server/authentication](apps/docs/docs/server/authentication.md)); future FIX-57 middleware |
| Rate limiting / short-circuit | Router branching, handler guards |

## 6. Edge Cases & Error Handling

| Edge case | Expected behavior |
|-----------|-------------------|
| `RuntimeConfig.middleware` is `undefined` | No middleware wrapping; `executeBlock` runs directly (unchanged) |
| `RuntimeConfig.middleware` is `[]` | Empty stack; pass-through (unchanged) |
| Middleware `filter` excludes block kind | Block executes without that middleware (unchanged) |
| Block retried 3 times | Middleware runs on each attempt (unchanged) |
| External code imported `Middleware` from `@flow-state-dev/core/types` | **Compile error** after release — acceptable (zero known consumers) |
| External code used `createFlowApiRouter({ middleware })` | **Compile error** — use `runtimeConfig` internally or wait for FIX-57 |
| `InboundTransportHost.middleware` field | Retained for internal introspection; not a registration API |
| Persisted flow definitions with `middleware` key | **Clean break** — no dual-read needed (zero consumers; BP-030 N/A) |
| Confusion with HTTP middleware in docs | Unchanged — those docs reference Next.js / auth / AI SDK middleware, not block middleware |

**`fsd:tdd`** (Linear category: Improvement). Tracer-bullet cycles per observable behavior below.

7. `Middleware` types are **not** exported from `@flow-state-dev/core/types` (type-level or grep assertion).

## 8. Non-Goals

- **Do not** delete `composeMiddleware`, `mergeMiddlewareStacks`, or the `executeBlock` wrapping point.
- **Do not** redesign `InternalExecutionSeams` or merge it with middleware compose.
- **Do not** build Phase 2 public middleware API — stays in [FIX-57](https://linear.app/fixpoint-labs/issue/FIX-57).
- **Do not** change `block_trace` / `TraceStore`, trading-desk tool cache/record, or HTTP/auth middleware docs.
- **Do not** add a public Docusaurus page for middleware or migration guides (never shipped on flow-state.dev).
- **Do not** re-introduce `middleware` on sequencer config (never existed).

### Deepening opportunities (follow-up via `fsd:improve-codebase-architecture`)

- **Unify interception models:** `InternalExecutionSeams` (sync intercept) and middleware compose (around-`next()`) coexist. Phase 2 public API design should evaluate whether one model subsumes the other.
- **Framework-owned durability middleware:** Checkpoint comments reference "durability middleware" — when built, install via `RuntimeConfig` defaults rather than a new public registration tier.

### Already-rejected directions

- [FIX-59](https://linear.app/fixpoint-labs/issue/FIX-59) cache middleware package — tool-layer cache is sufficient.
- [FIX-60](https://linear.app/fixpoint-labs/issue/FIX-60) observability middleware package — `block_trace` is sufficient.
