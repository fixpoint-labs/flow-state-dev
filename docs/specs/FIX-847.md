# FIX-847: Move presentational components out of @flow-state-dev/react into @flow-state-dev/ui — Implementation Spec

## 1. TLDR

One of our packages is meant to hold only app logic and carry no styling, but a few styled UI widgets ended up there where they can't be themed. This change moves the one widget still worth keeping — a small "which AI model answered" badge — into the styling package, deletes two others that nothing uses, and finishes a half-wired feature so automated "response audit" results actually show up on screen. The result is a cleaner logic package, a themeable badge teams can drop in, and audit findings that finally render.

**Scope was corrected after research** (see §3). Three of the four components named in the issue were overtaken by events: `ApprovalRenderer` already shipped its split (FIX-276 / PR #613), a `ui` `AuditAnnotation` already exists, and `AuditAnnotationProgress` is unused demo code. The real remaining work:

**react (delete dead public exports):**
- Remove `ModelBadge` export + `packages/react/src/components/ModelBadge.ts`
- Remove `AuditAnnotation` export + `packages/react/src/components/AuditAnnotation.ts`
- Remove `AuditAnnotationProgress` export + `packages/react/src/components/AuditAnnotationProgress.ts`

**ui (give the moved/existing components a home):**
- Add `packages/ui/registry/components/model-badge.tsx` (Tailwind reimplementation of `ModelBadge`)
- Add a `model-badge` entry to `packages/ui/registry.json`
- Add an `audit-annotation` entry to `packages/ui/registry.json` (the component file already exists but is not `fsdev ui add`-able)

**patterns (wire the audit emit path):**
- Append an `emit-audit-annotation` `.tap` step to the `responseAuditor` sequencer in `packages/patterns/src/response-auditor/index.ts` that calls `ctx.emit.component("audit-annotation", { results, surfacedResults, overallScore })`, so the existing `ui` `audit-annotation` renderer is fed end-to-end

**consumers / docs / changeset:**
- Repoint `apps/kitchen-sink/components/chat-agent/message.tsx` to import `ModelBadge` from the local `ui` copy
- Changeset + README/docs updates (§9)

**Size: Medium** (multi-package: `react`, `ui`, `patterns`, `apps/kitchen-sink`, docs; ~1 PR, <300 LOC net — most of it deletions).

## 2. Overview

Linear issue: [FIX-847](https://linear.app/fixpoint-labs/issue/FIX-847) · GitHub mirror: #629

`@flow-state-dev/react` is the runtime *logic* layer and is deliberately style-system-free (`sideEffects: false`, no Tailwind, no CSS). Over time it accreted presentational components that style with inline `style={{…}}` and belong in `@flow-state-dev/ui` (the Tailwind, copy-into-your-project shadcn-style registry). This spec finishes evacuating that set. Because most of the originally-listed components are already moved, already deletion-worthy, or already shipped elsewhere, the net change is small and dominated by deletions plus one new `ui` component and one pattern emit-step.

## 3. Background & Research

### What the issue assumed vs. what is true today

The issue (written 2026-06-23) lists four components to move and prescribes "extract embedded logic into a react hook" for each, plus a note about resolution state reaching components via hook/context. Tracing the working tree shows most of this is stale:

| Component | Issue's ask | Reality verified in tree |
| --- | --- | --- |
| `ApprovalRenderer` | move to ui, extract hook | **Done.** FIX-276 / PR #613 (merged) shipped `useApproval` + minimal `ApprovalRenderer` in react and the polished `Approval` card in ui via `chatAssistantRenderers`. Out of scope. |
| `AuditAnnotation` | move to ui | A Tailwind `ui` version (`packages/ui/registry/components/audit-annotation.tsx`) **already exists and is registered** in `chatAssistantRenderers` (`component: { "audit-annotation": AuditAnnotation }`). React's 297-line version has **zero consumers** and reads `block_trace` directly. Nothing emits the `component` item the `ui` version expects, so the audit card never actually renders. |
| `AuditAnnotationProgress` | move to ui | 387-line "kitchen-sink visualization" (gauges + threshold slider). **Zero consumers anywhere.** No `ui` equivalent. Dead code. |
| `ModelBadge` | move to ui, extract hook | 73 lines, pure presentation, no logic. One consumer (`apps/kitchen-sink/components/chat-agent/message.tsx`) that already passes a Tailwind `className`. No `ui` equivalent. **The one clean move.** |

Two framing elements of the issue do not transfer and are dropped:

- **"Extract embedded logic into a react hook"** — `useApproval` earned a hook because it owns resume *transport*. `ModelBadge` has no logic; the audit components' only logic is reading `block_trace`, which is an emit-side/pattern concern, not a transport hook. No hooks are created in this spec.
- **The resolution / `isResolved` note** — applies only to *suspension* renderers (the approval path, already solved). None of these three are suspension renderers.

### How the chosen approach fits existing patterns

- **`ui` registry component** mirrors `approval.tsx` / `task-plan.tsx`: a `.tsx` file under `packages/ui/registry/components/`, styled with Tailwind + `cn()` from `@/lib/utils`, listed in `registry.json` for `fsdev ui add`. (Refs: `packages/ui/registry/components/approval.tsx`, `packages/ui/registry.json:188`.)
- **Pattern emit step** mirrors the debate pattern: `.step(block).tap(emitHandler)` where the handler calls `ctx.emit.component(...)`. (Refs: `packages/patterns/src/debate/index.ts:344`, `packages/patterns/src/debate/blocks/record-argument.ts:64`.) Composing the emit as a `.tap` (not a `.step` that returns the snapshot) follows BP-012 / BP-014 — the block only has the side effect of emitting; it passes its input through and the sequencer's output contract is unchanged.
- **`emit.component` API** is `ctx.emit.component(component: string, data: Record<string, unknown>, options?: { key?, transient?, … })`. The bare `ctx.emitComponent(...)` is `@deprecated`; use `ctx.emit.component(...)`. (Ref: `packages/core/src/types/block.ts:318,356`.)
- **The `ui` `audit-annotation` data contract** (`{ results, surfacedResults, overallScore }`, `packages/ui/registry/components/audit-annotation.tsx:34-38`) is **byte-for-byte the output of the `apply-threshold` block** (`packages/patterns/src/response-auditor/index.ts:100-118`). No data reshaping is needed — the emit step forwards the threshold output verbatim.

### Why this over alternatives

- *Port `AuditAnnotationProgress` to ui* — rejected (user decision): it has zero consumers; theming 387 lines of demo code is unjustified. Delete it; a polished audit-progress can be built fresh in `ui` later as its own issue.
- *Just delete react's `AuditAnnotation` without wiring the emit path* — rejected (user decision 2B): the `ui` renderer is registered but unfed, so audit results render nowhere today. Wiring the emit step makes the feature actually work end-to-end and is the small piece that justifies keeping the `ui` component.
- *Keep `ModelBadge` in react with its `className` escape hatch* — rejected: it violates the package's no-styling charter and the one consumer already styles it via Tailwind, so the inline defaults are dead weight there.

### Key Decisions & Ramifications (top 5)

1. **Scope cut to ModelBadge-move + two deletions + audit emit-wiring.** Alt rejected: build the literal four-component move with hooks. Locks in a Small/Medium PR; rules out creating `useModelBadge`/`useAudit` hooks (there is no logic to host). Risk: a reader expecting the issue's original surface must read this spec to see why three asks shrank — mitigated by §3 and the issue reframe (§7).
2. **`AuditAnnotation` work = delete react copy + wire response-auditor emit (option 2B).** Alt rejected: delete-only, file emit gap separately. Locks the pattern package into this PR (`packages/patterns`); buys a working end-to-end audit card. Cost: a tiny amount of cross-package surface and one new test in `packages/patterns`.
3. **`AuditAnnotationProgress` is deleted, not ported.** Alt rejected: port to `ui`. Locks in removal of a public export (breaking for any external importer → changeset). Rules out a themed progress widget for now; flagged as a possible future `ui` issue in §8.
4. **`ModelBadge` becomes a registry component, NOT a `chatAssistantRenderers` entry.** Alt rejected: auto-register it as a renderer. `ModelBadge` is a decoration consumed *inside* message components (it takes a `ModelIdentity` prop, not an item), so it is not item-type-keyed. Locks in the "copy + import locally" consumption model; rules out it auto-appearing on messages (that would be a separate enhancement to the `ui` `message.tsx`).
5. **Emit gated on `surfacedResults.length > 0` via `.tapIf`.** Alt rejected: always emit. Avoids persisting empty `audit-annotation` component items into the stream when nothing crosses threshold (the `ui` component already returns `null` for empties, but an empty persisted item is still log noise). Ramification: an audit run with no findings emits nothing, consistent with the existing "renders nothing when below threshold" behavior.

### `ui` `ModelBadge` (model-badge.tsx) — API surface

```tsx
"use client";
import type { ModelIdentity } from "@flow-state-dev/core/items";
import { cn } from "@/lib/utils";

export function ModelBadge({
  model,
  className,
}: {
  model: ModelIdentity | undefined;
  className?: string;
}) {
  if (model === undefined) return null;
  const title = [
    `actual: ${model.actual}`,
    model.requested !== undefined ? `requested: ${model.requested}` : null,
    model.gateway !== undefined ? `gateway: ${model.gateway}` : null,
  ].filter(Boolean).join("\n");
  return (
    <span
      title={title}
      className={cn(
        "inline-flex items-center gap-1 rounded-full border px-2 py-0.5",
        "text-[10px] font-medium leading-none text-muted-foreground",
        className,
      )}
    >
      {model.actual}
    </span>
  );
}
```

Notes:
- Drops react's dual-mode inline-`style` mechanism. In `ui`, theming is Tailwind + tokens (`text-muted-foreground`, `border`), matching `approval.tsx` / `audit-annotation.tsx`. `className` still merges via `cn()` so consumers can override.
- Same null-on-undefined and tooltip behavior as react's version (so `<ModelBadge model={item.model} />` stays safe to call with a possibly-absent field).

### Audit emit step — design

In `responseAuditor(...)`, after `.step(thresholdBlock)`:

```ts
const emitAuditAnnotation = handler({
  name: "emit-audit-annotation",
  inputSchema: z.object({
    results: z.array(AnalyzerResultSchema),
    surfacedResults: z.array(AnalyzerResultSchema),
    overallScore: z.number(),
  }),
  // No outputSchema — side-effect-only block (BP-012/BP-014).
  execute: (input, ctx) => {
    ctx.emit.component("audit-annotation", input, { key: "response-audit" });
  },
});

// …sequencer chain…
  .step(thresholdBlock)
  .tapIf((out) => out.surfacedResults.length > 0, emitAuditAnnotation);
```

- `.tap`/`.tapIf` passes the threshold output through unchanged, so `responseAuditor`'s return contract (`{ results, surfacedResults, overallScore }`) is unchanged — existing callers and `goals/` are unaffected.
- `key: "response-audit"` applies the keyed-snapshot pattern: within a request, the latest audit replaces the prior one and replays on reload. Component items are request-scoped, so different requests get distinct cards.
- `data` is the threshold output verbatim; the `ui` `audit-annotation` renderer already consumes exactly this shape.

### Data flow (audit, end-to-end after this change)

`.work()` sidechain → analyzers fan-out → `aggregateResults` → `apply-threshold` (`{ results, surfacedResults, overallScore }`) → **`emit.component("audit-annotation", …)`** → SSE `component` item → `ItemsRenderer` resolves `renderers.component["audit-annotation"]` → `ui` `AuditAnnotation` renders the card.

### Error handling

- `emitAuditAnnotation` is pure side-effect; `ctx.emit.component` does not throw on valid input. No new error path.
- The deletions are compile-time surface removals; the only runtime risk is a dangling import, caught by `pnpm typecheck` (the goal of Step 1's gate).

## 6. Edge Cases & Error Handling

| Case | Expected behavior |
| --- | --- |
| Audit run with no results above threshold | `surfacedResults` empty → `.tapIf` condition false → no component item emitted → nothing renders (matches prior behavior). |
| Audit run with findings | One `audit-annotation` component item per request, keyed `response-audit`; `ui` card renders surfaced results. |
| Re-run / reload within a request | Keyed snapshot replays latest; no duplicate cards. |
| External consumer imported `ModelBadge`/`AuditAnnotation`/`AuditAnnotationProgress`/`AuditAnnotationData` from `@flow-state-dev/react` | Breaking removal → covered by changeset migration note (§9). `ModelBadge` migration: `fsdev ui add model-badge`. |
| `model` is `undefined` on an item | `ModelBadge` returns `null` (unchanged). |
| Consumer relied on react `ModelBadge`'s inline default styles (no `className`) | `ui` version is Tailwind-only; consumers without Tailwind must style via `className`. Noted in migration. |

Error taxonomy: no retryable/fatal runtime errors introduced. The only failure modes are compile-time (dangling imports), surfaced by `pnpm typecheck` — the feedback loop in §7.

## 7. Testing Strategy

**Discipline:** Mixed, but route as **`fsd:tdd`** for the one behavioral addition (the audit emit step) and treat the deletions/move as mechanical refactor guarded by typecheck. (FIX-847 has no Bug/Feature label; add **Enhancement** so `fsd:implement-issue` routes to TDD.)

**Goal & goal check (required, applies to the audit emit path only).**
- **Goal:** running a flow whose generator is wrapped with `responseAuditor` and produces above-threshold findings causes an audit card to actually appear in the stream — the feature that is currently dead (renderer registered, nothing emitted) becomes live.
- **Goal check:** a real-model run that exercises the response-auditor sidechain and asserts a `component` item with `component === "audit-annotation"` (and non-empty `surfacedResults`) appears. Build it as `goals/response-auditor/emits-audit-annotation/run.mts` (see `goals/README.md`) driving `fsdev run` against a flow that mounts `responseAuditor` with a deterministic-ish analyzer, printing PASS when the item is present, FAIL otherwise. The audit sidechain runs on the model output, so a real model is appropriate; the analyzer threshold should be set low enough to reliably surface in the check.
- **No goal check for** the `ModelBadge` move or the two deletions — no observable real-model runtime outcome (UI relocation + dead-export removal). Verification there is `pnpm typecheck` (no dangling imports) + the kitchen-sink still rendering the badge.

**CI specs (mocked, deterministic):**
- *Behaviour — audit emit (TDD tracer):* in `packages/patterns/test/response-auditor.test.ts`, run the auditor with a mock `ctx` and a stub analyzer that returns an above-threshold result; assert `ctx.emit.component` was called once with `"audit-annotation"` and `{ results, surfacedResults, overallScore }`. Add a second case: a below-threshold result emits nothing. Mirror the mock-ctx idiom in `packages/ui/test/generative/info-card.test.ts` (which asserts `emitComponent` calls).
- *Surface — react exports removed:* update `packages/react/test/index.test.ts` (export-surface test) so it no longer expects the three symbols; if there is a positive "these are exported" assertion, invert it or drop it.
- *`ui` registry integrity:* `pnpm --filter @flow-state-dev/ui build` must succeed with the two new `registry.json` entries (the build script validates entries).

Existing references: `packages/patterns/test/response-auditor.test.ts` (auditor test patterns), `packages/ui/test/generative/info-card.test.ts` (emit-assertion idiom), `packages/ui/test/task-plan-state.test.ts` (ui data-extraction test style). ## 8. Non-Goals

- **No headless hooks.** The issue's "extract logic into a react hook" does not apply (see §3); no `useModelBadge`/`useAudit` is created.
- **`ApprovalRenderer`** — already split and shipped in FIX-276 / PR #613. Untouched.
- **No themed `AuditAnnotationProgress` in `ui`.** It is deleted from react. A polished audit-progress widget, if ever wanted, is a fresh `ui` issue — explicitly out of scope.
- **No auto-registration of `ModelBadge` in `chatAssistantRenderers`.** Showing a model badge on messages by default is a separate `ui` `message.tsx` enhancement.
- **No change to the response-auditor's analyzer set, scoring, threshold semantics, or `displayMode`.** `displayMode` remains config-only; the `ui` card ignores it today and this spec does not change that.
- **Deepening opportunities flagged (follow-ups, not this PR):** (a) the `ui` `audit-annotation` defines a local `AuditAnnotationData` that duplicates the `apply-threshold` output shape — a future consolidation could export a shared type from the pattern; (b) `registry.json` was missing entries for components that already existed (`audit-annotation`), suggesting registry-completeness drift worth an audit via `fsd:improve-codebase-architecture`. Neither blocks this spec.
