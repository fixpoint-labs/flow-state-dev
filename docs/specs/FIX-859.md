## 1. TLDR

**Plain-language summary.** The framework talks to AI models through a third-party library that just shipped a new major version. This work moves the framework onto that new version without changing how anything behaves: streaming answers, tool use, structured output, caching, and model fallback must all work exactly as before. It has to land first because every other item in this project builds on the new version.

**Technical statement:** Bump `ai` from `^6.0.93` to `^7`, plus the paired `@ai-sdk/*` provider and MCP package majors, across the whole workspace; re-align the model adapter (`createAiSdkModelResolver`) and its satellites to v7's surface; and prove behavioral parity with the existing mocked suites plus real-LLM goal checks.

**Deliverables:**

- Core: migrate `createAiSdkModelResolver.ts` to the v7 surface — `result.fullStream` → `result.stream`; stream-part mapping updates (`text-delta` payload field is now `text`, `reasoning-delta` → `text`, `tool-input-delta` → `tool-call-delta` with `argsTextDelta`, `source`, `finish-step`/`finish` with `totalUsage`); final-step values read via `await result.finalStep` in `normalizeFinishChunk`; `stepCountIs` → `isStepCount`; system prefix kept in `messages` with `allowSystemInMessages: true` (Key Decision 6); `createModelResolver.ts` moves from `createRequire` to dynamic `import()` (v7 is ESM-only) with the async-loading ripple and a runtime provider-resolution smoke; Google provider table entry `createGoogleGenerativeAI` → `createGoogle`
- Tools: bump `@ai-sdk/mcp`, re-verify `tool()` usage in `create-bash-tool.ts` and the MCP manager path (`packages/tools/src/mcp/manager.ts` — `createMCPClient`, `client.tools()`, tool execution over MCP transports)
- Engine: verify duck-typed error classification; resolve the vestigial `ai` dependency pin
- Tests: update `MockLanguageModelV3` usages if the LanguageModel spec version bumps
- Workspace: bump `ai` / `@ai-sdk/*` pins in apps, labs, examples to keep one SDK major per graph; raise the `zod` floor to `^3.25.76` in `packages/core` and `packages/tools` (currently `^3.24.1`, below `ai@7`'s peer range `^3.25.76 || ^4.1.8`; engine is already at `^3.25.76`)
- Docs: migration note + version references (per §9)
- Changeset (`minor`) for core, engine, tools — plus `cli` if the §7 capture fix (include `item.updated`/`item.done` in `--capture`) ships, since that changes published `fsdev` behavior (BP-022)

**Size:** Large — multi-package, but a single PR (the workspace must move atomically; a split would leave mixed SDK majors mid-stream).

## 2. Overview

[FIX-859](https://linear.app/fixpoint-labs/issue/FIX-859/upgrade-fsd-from-ai-sdk-6-to-ai-sdk-7-core-engine-tools) upgrades the framework's generator provider layer from Vercel AI SDK 6 to AI SDK 7. ### 3.2 AI SDK 7 breaking changes relevant to this surface

Adjudicated against the [official v7 migration guide](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0) and the [v7 `streamText` reference](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text). Verdicts on the review-cycle claims below; the confirmed items are binding on §4.

**CONFIRMED (migration guide):**

- Node.js 22+ required → `engines` bump to `>=22` for the published packages + CI matrix/docs (was a verify-item; now a hard deliverable).
- All packages ESM-only; `require()` unsupported → `createModelResolver`'s `createRequire` loading becomes dynamic `import()` with the async ripple, plus the runtime provider-resolution smoke (typecheck/mocked suites never execute the loader).
- `StreamTextResult.fullStream` renamed to `stream`.
- System messages in `messages` rejected by default → opt-in via `allowSystemInMessages: true` (Key Decision 6 picks this over `instructions`).
- Top-level result properties (`content`, `toolCalls`, …) now accumulate across steps → final-step-only values via `finalStep`; `normalizeFinishChunk` must read from the right object.
- Google provider rename (official codemod `rename-google-generative-ai-to-google`) → provider table entry becomes `createGoogle`.
- `prepareStep` returned `instructions` carry forward into later steps until overridden → generator's message-rewriting `prepareStep` needs the idempotent-rebuild treatment + dynamic multi-step regression test.
- Tool-result content parts canonicalized (single `file` variant replaces `image-*`/legacy `file-*`) → re-verify the `toModelOutput` bridge and recall-tool path.
- `stepCountIs` → `isStepCount` (direct resolver import).
- `onFinish` → `onEnd`, `onStepFinish` → `onStepEnd`; `system` option → `instructions`; telemetry renames (not on our surface, but check no stragglers).
- Usage: `cachedInputTokens` → `inputTokenDetails.cacheReadTokens` — `normalizeUsage` **already reads that nested shape**, so the earlier top-level-keys claim is refuted; add a mocked v7-usage regression to pin it.

**CONFIRMED (v7 `streamText` reference):**

- Tool-argument streaming part is `tool-call-delta` with `argsTextDelta` (v6 `tool-input-delta`/`delta` is gone) → stream mapping update + in-progress `tool_call_progress` `argsDelta` resolver test.
- Text part type stays `text-delta` but the payload field is `text` (the type-rename claim is refuted; the field change is real). `reasoning-delta` likewise carries `text`. Sources arrive as `source` parts; finish metadata as `finish-step`/`finish` with `totalUsage`.

**CONFIRMED (npm registry, verified directly):**

- `ai@7` peers `zod ^3.25.76 || ^4.1.8` → floor bump in core/tools.

**UNRESOLVED — settle at install time (§5 step 1), not from reviewer citations:**

- `@ai-sdk/mcp` redirect default flip (not in the guide) → inspect the v7 `@ai-sdk/mcp` transport options after install; only then decide on a redirect knob (BP-038) and the redirecting-server test.
- Gateway provider folded into `ai` (`createGateway` from `ai`; standalone `@ai-sdk/gateway` possibly stale) → check what v7 actually publishes after install; if moved, it is an import-path move across the resolver + three apps + three docs pages (§9).
- `@openrouter/ai-sdk-provider` v7-spec compatibility → audit at install; an incompatible community provider is a launch blocker to surface, not to paper over.
- `ai/test` mock exports (`MockLanguageModelV3` vs a bumped spec version) → Key Decision 5.

Historical note — the raw review-cycle claims list this section replaces:

- v7 requires Node 22 → if true, `engines` bumps for the published packages + CI matrix/docs.
- v7 packages are ESM-only → if true, `createModelResolver`'s `createRequire`-based dynamic provider loading needs an explicit migration action (dynamic `import()` with the async-loading ripple), not just a version bump — **plus a runtime provider-resolution smoke** (resolve a direct `openai/...`/`anthropic/...`/gateway id through the real loader), because typecheck and the mocked resolver suites never execute this path and would pass while every direct-provider and gateway auto-detection call fails at runtime.
- `result.fullStream` renamed to `result.stream` → resolver consumption + stream-chunk parity test.
- System messages inside `messages` need an explicit opt-in (`allowSystemInMessages` or move to `instructions`) → affects how `generator.ts` builds system-prefix messages. Ramification if the `instructions` path is chosen: `applyCaching` (`caching.ts`) finds its direct Anthropic/OpenRouter cache anchor by searching `request.messages` for `role: "system"`, and `caching.test.ts` fabricates that shape directly — moving the system prefix out of `messages` would silently disable direct cache markers while the mocked suite passes, so `applyCaching` must handle the chosen shape and gain a resolver-level assertion.
- `generateText`/`streamText` result properties changed; final-step-only values move behind `await result.finalStep` → affects the resolver's finish normalization (`normalizeFinishChunk` reads final `text`, `toolCalls`, `finishReason`, `usage`, provider metadata, sources from the awaited result) — renaming the stream iterable alone is not sufficient.
- Tool-result content shapes changed → affects the resolver's `toModelOutput` bridge (see §3.1).
- Google provider factory renamed `createGoogleGenerativeAI` → `createGoogle` → `createModelResolver` loads providers by string factory name (`createModelResolver.ts` provider table), so direct `google/...` resolution would hit the "provider package is not installed" path even with `@ai-sdk/google` present; not covered by typecheck or the mocked suites.
- `prepareStep` return semantics changed (returned `messages`/`instructions` carry forward into later steps; `initialMessages`/`responseMessages` exposed for rebuilding) → `generator.ts` builds a `prepareStep` that rewrites `messages` by slicing the initial system-prefix for dynamic prompt/context/tools with `maxIterations > 1`; if confirmed, this needs an explicit adapter change plus a dynamic multi-step regression test.
- `@ai-sdk/mcp` transport redirects flipped from follow-by-default to reject-by-default → the manager forwards only `type`/`url`/`headers` from `MCPTransportConfig`; if confirmed, decide whether to expose a redirect-policy knob (new surface — weigh against BP-038) and test the redirecting-server case.
- Gateway provider moved into the `ai` package (`createGateway` imported from `ai`; separate `@ai-sdk/gateway` possibly stale on v7) → `createModelResolver` dynamically loads `@ai-sdk/gateway`, and kitchen-sink / knowledge-base / trading-desk import it statically; if confirmed, the migration is an import-path move across all of those, not a version bump of the standalone package — and it includes the published docs, which show `@ai-sdk/gateway` imports in `apps/docs/guides/deploying-to-vercel.md`, `apps/docs/docs/fundamentals/models.md`, and `apps/docs/docs/getting-started/setting-up-models.md` (fold into the §9 docs plan).
- Usage cache counters moved to top-level `usage.cacheReadTokens` / `usage.cacheWriteTokens` → `normalizeUsage` in the resolver maps `cacheReadInputTokens`/`cachedInputTokens` and nested `inputTokenDetails.*` but not those top-level keys; if confirmed, add mapper coverage plus a mocked v7-usage regression test (otherwise `modelUsage.cacheReadTokens` reads zero and cost accounting + the cache parity gate silently miss cache hits).
- Tool-argument streaming part renamed/reshaped (`tool-input-delta` with `delta` → `tool-call-delta` with `argsTextDelta`) → the resolver only handles the v6 `tool-input-delta` shape; if confirmed, update the stream mapping and add a resolver test asserting an in-progress `tool_call_progress` chunk with non-empty `argsDelta` — the tool-loop smoke alone proves completion, not live argument deltas.
- Text streaming part renamed/reshaped (`text-delta` → `type: "text"` with a `text` field) → the resolver only converts the v6 `text-delta` shape to framework `text_delta`; if confirmed, update the mapping and add a resolver test for the v7 part shape.

### 3.3 Key Decisions & Ramifications

1. **Codemod the renames, hand-migrate the seams.** Run the official v7 codemods for mechanical renames (`rename-google-generative-ai-to-google`, `stepCountIs`→`isStepCount`, callback renames), then hand-migrate the resolver's stream/finish/request mapping with the mocked contract suite as the safety net. Alternative rejected: pure codemod (cannot see the duck-typed satellites — caching, fallback, classifier — or the framework chunk mapping) and pure hand-migration (wastes review attention on renames a codemod does deterministically). Ramification: the diff has two visibly different textures; reviewers should read the codemod commits as mechanical and spend attention on the resolver commit.
2. **Bump the entire workspace atomically, not just core/engine/tools.** Alternative rejected: bump only the three named packages. Apps/labs construct provider models (`openai(...)`, gateway models) and hand them to core; a v6 provider model implementing an older LanguageModel spec version handed to a v7 `streamText` is exactly the interop failure a major exists to prevent. Ramification: the PR touches every workspace `package.json` that pins `ai`/`@ai-sdk/*`, and downstream consumers of published FSD packages must bump their own `ai` when they use the escape hatches (`wrapAiSdkModel`, `providerTools`, raw provider models) — this is the content of the migration note.
3. **Behavioral parity is the gate; no new v7 capability adoption.** Alternative rejected: adopt v7 features opportunistically while in the file. Ramification: sibling issues stay unblocked and reviewable; some code may look v6-idiomatic on v7 until siblings land.
4. **Drop engine's vestigial `ai` dependency rather than bump it.** Alternative rejected: bump the unused pin. Engine's only AI SDK contact is structural (symbol/name/statusCode). Ramification: engine no longer expresses a version constraint on `ai`; the classifier's structural detection must be re-verified against v7 error shapes (it was built for realm-safety, which also buys version tolerance). BP-038: subtract before you add.
5. **Mock strategy decided at install, contract suite stays authoritative.** The 48 `MockLanguageModelV3` instantiations update to whatever `ai/test` actually exports on v7 (same name if the LanguageModel spec version held; mechanical rename if it bumped) — inspected at §5 step 1, not guessed now. Alternative rejected: pre-writing a compatibility shim over the mocks (speculative surface, BP-038). Ramification: if the spec version bumped, the mock update commit is large but mechanical; assertions must not be weakened while updating.
6. **Keep the system prefix in `messages` via `allowSystemInMessages: true`, not `instructions`.** v7 rejects system messages in `messages` by default; the opt-in preserves the v6 shape exactly. Alternative rejected: migrating to `instructions` — it moves the system prefix out of `messages`, which silently breaks `applyCaching`'s `role: "system"` cache anchor and the `prepareStep` slice logic, for zero parity benefit. Ramification: FSD stays on an opt-in flag a future major could remove; the `instructions` migration becomes an explicit sibling-issue candidate, and `applyCaching` gains a resolver-level assertion now so any later move cannot silently disable cache markers.

## 4. Technical Design

Per-file plan, ordered by risk. Everything here traces to a CONFIRMED item in §3.2 or a verified in-repo seam in §3.1.

**`packages/core/src/models/createAiSdkModelResolver.ts` (the migration target):**
- Imports: `stepCountIs` → `isStepCount`; verify `generateText`/`streamText`/`Output` names unchanged.
- Request build: add `allowSystemInMessages: true` (Key Decision 6); verify `prepareStep`, `providerOptions`, `abortSignal`, `maxOutputTokens`, `onError` option names against v7 (guide renames `onFinish`-family callbacks; we use `onError` — confirm it survived).
- Stream consumption: iterate `result.stream`; part mapping per the v7 reference — `text-delta` reads `.text` (not `.delta`), `reasoning-delta` reads `.text`, `tool-call-delta` reads `.argsTextDelta` into framework `tool_call_delta`/`argsDelta`, `tool-result` reads `input`/`output`, `source` maps to `source_url`, `finish-step`/`finish` feed finish normalization (`totalUsage` on `finish`).
- Finish normalization: `normalizeFinishChunk` reads final-step-only values from `await result.finalStep`; accumulated values stay on the result where accumulation is what we want. `normalizeUsage` keeps its `inputTokenDetails.*` reads (already v7-shaped) and gains the mocked v7-usage regression.
- Error wrapping and provider search tools: re-verify `AI_NoObjectGeneratedError`/`AI_NoOutputGeneratedError` names and the real Anthropic/OpenAI/Google search-tool factory names against installed v7 packages (mocked factories can't catch renames — §7 seam caveat).
- `toModelOutput` bridge: emit the canonical `file` content variant where the old `image-*`/`file-*` parts were produced; recall-tool path re-verified.

**`packages/core/src/models/createModelResolver.ts`:** replace `createRequire` with dynamic `import()` (ESM-only); provider loading becomes async — cache the import promise per provider so resolution stays single-flight; Google entry → `createGoogle`; gateway import path per the §3.2 install-time check. Failure mode parity: a missing provider package must still produce the same "provider package is not installed" error shape.

**`packages/core/src/blocks/generator.ts`:** `prepareStep` rebuilds the full message array idempotently each step (carry-forward semantics make a partial return sticky); dynamic multi-step regression test asserting no duplicated/stale context across ≥2 tool-loop steps.

**`packages/core/src/models/caching.ts`:** unchanged by design (Key Decision 6 preserves the `role: "system"` anchor); gains a resolver-level assertion that a resolver-built request carries the cache markers.

**`packages/core/src/models/fallbackModel.ts` + `packages/engine/src/errors/classify-provider-error.ts`:** re-verify constructor names / `statusCode` / `Symbol.for("vercel.ai.error")` against v7 error instances; engine drops its vestigial `ai` dependency (Key Decision 4); classifier test gate in §7.

**`packages/tools`:** bump `@ai-sdk/mcp`; re-verify `tool()`; MCP redirect behavior checked at install (§3.2 UNRESOLVED); add the un-injected `createMCPClient` smoke and the `tool()`-through-`providerTools` generator test (§7 seam gaps).

**Workspace:** dep bumps everywhere per Key Decision 2; zod floor; `engines.node >= 22` on published packages + CI matrix/docs; `typecheck` scripts added to kitchen-sink and hello-chat; CLI `--capture` extended with `item.updated`/`item.done` (verification enablement; `cli` changeset); trading-desk `xSearch` re-verify.

## 6. Edge Cases & Error Handling

- **Missing provider package (dynamic import):** the async import failure must surface the same actionable "install @ai-sdk/x" error as the v6 `createRequire` path — not an opaque ESM resolution error.
- **Models that report no usage:** `normalizeUsage` null-guards stay intact (`== null` guards, BP-030-style); the v7-usage regression covers the absent-usage case too.
- **Single-iteration generators:** no `prepareStep` is built for `maxIterations === 1` — the carry-forward change must not alter that path (regression asserts it).
- **Multiple/empty system prefixes:** `allowSystemInMessages: true` with zero system messages and with multi-part prefixes both behave as on v6; `applyCaching` anchor assertion covers the present-prefix case.
- **Stream `error` parts and aborts:** v7 `error` parts route through the same wrapping as v6; `abortSignal` cancellation still yields the framework's cancel path, not an unhandled rejection.
- **Mixed-major graphs:** after the bump, assert the lockfile resolves exactly one `ai` major (guards Key Decision 2 against a stray transitive pin).

## 7. Testing Strategy

**Goal & goal check (required).** Goal: a user's flows behave identically on v7 — streaming text/reasoning/tool deltas render live, structured output validates, multi-step tool loops terminate, caching markers still hit, fallback still falls back. Goal check (real model, out of CI):

1. `pnpm tsx goals/structured-output/recovers-off-schema-output/run.mts` — exercises real structured output + coercion repair on GLM 5.2 (PASS/FAIL printed by the script). Prerequisite: `AI_GATEWAY_API_KEY` — the runner pins `vercel/zai/glm-5.2`, a gateway id, and fails at model resolution without it.
2. `cd apps/kitchen-sink && pnpm fsdev run chat-agent run -i '{"message":"…","mode":"ask"}'` — real streaming + tool loop over the default model group, using the app's `fsdev.config.ts` wiring (the command is `fsdev run <flowKind> <action>`; see `apps/kitchen-sink/CLAUDE.md`). Prerequisite: `AI_GATEWAY_API_KEY` must be set — the default groups are `vercel/...` gateway ids and the config only wires the gateway when that key is present; without it the run fails before the smoke. The message must be one that deterministically requires a tool (ask the agent to use one of its installed tools on concrete input — a plain-text answer must not be able to satisfy it); pass = the NDJSON contains a `tool_call_progress` item reaching `status: "completed"`, a durable `tool_output` item, **and non-empty assistant text streamed via `content_delta` events** (an empty assistant envelope is a FAIL — it would mean live text streaming broke while items still completed), with **no `type: "error"` events** (that is the CLI's actual failure shape — there is no `execution_error` item type in the NDJSON union; with `--capture`, additionally assert `result.success === true`). A text-only completion is a FAIL for this check even with exit code 0.
3. A reasoning parity check: rerun 2 with thinking enabled — kitchen-sink gates Anthropic thinking on `ctx.user.state.thinkingEnabled` (see `flows/chat-agent/run/assistant/assistant.ts`), which is **user-level** state. Set it by running the flow's own action first, and run **both** commands with `STORE_TYPE=filesystem` so the user-state write survives across the two CLI processes (the local profile defaults to `inMemoryStores()`, which would discard the toggle when the setup command exits): `STORE_TYPE=filesystem BASH_PROVIDER=just-bash pnpm fsdev run chat-agent setThinkingEnabled -i '{"thinkingEnabled":true}'`, then rerun the smoke the same way as the same user; pass = reasoning items stream live before the assistant message. `BASH_PROVIDER=just-bash` is required because kitchen-sink's `selectBashProvider()` couples sandbox selection to the store type — `STORE_TYPE=filesystem` alone would switch the bash capability to the host `local` shell, executing tool calls on the reviewer's machine and exercising a different tool-loop path than the step-2 smoke. Thinking is Anthropic-only and the assistant honors a persisted `ctx.user.state.selectedModel` before the Anthropic default, so with a persistent store also pin the model first (`... setSelectedModel -i '{"selectedModel":"vercel/anthropic/claude-sonnet-4.6"}'`) or run against a fresh `.fsdev/data` directory — a stale non-Anthropic selection would make this gate pass with no reasoning stream. Do **not** use the CLI seed flags for this: `--seed-session` writes the wrong tier, and `--seed-user` is currently parsed and echoed into capture metadata but never applied (`run.ts` only applies `seedSession` — a pre-existing CLI bug, log separately). The default `mode: "ask"` run never exercises the reasoning stream, so without this the goal's "reasoning deltas render live" clause is unverified.
4. A caching spot-check: run 2 twice with `AI_GATEWAY_API_KEY` set (kitchen-sink's default groups resolve `vercel/...` gateway ids, exercising gateway `caching: "auto"`), adding `--capture <path>` and `FSDEV_TRACE_OBSERVABILITY=true` — the live stdout stream does not surface cache counters; they are normalized onto the generator `block_trace.modelUsage`.
