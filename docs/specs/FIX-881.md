## 3. Background & Research

### The lab is a leaf — the move is import-safe

Verified by repo-wide grep: **nothing imports `@flow-state-dev/knowledge-base`** outside its own directory, and the only path references to `labs/knowledge-base` are:

- `goals/personal-knowledge-mcp/persists-a-concept-across-stateless-calls/run.mts:69` — `await import("../../../labs/knowledge-base/src/flow.ts")` (plus a prose mention in the header comment). Path depth is identical after the move; only the segment changes.
- `labs/README.md:22` — the directory-table row.
- `pnpm-lock.yaml:440` — the `labs/knowledge-base:` importer key (regenerated by `pnpm install`).
- Provenance comments inside the lab itself (`package.json:2,6`, `README.md`, `src/index.ts:2`, `src/flow.ts:2`, `fsdev.config.ts:2,29`).

All other `okf` / `knowledge-base` hits in the repo are coincidental (`hookfiles` substring in an engine test, a generic `knowledge-base-agent` example name in `packages/cli/README.md`, generic "knowledge base" prose in `apps/docs`).

`pnpm-workspace.yaml` already globs both `labs/*` and `examples/*`, and turbo discovers `typecheck`/`test` from every workspace package, so the lab's ~925-LOC test suite keeps running in CI from the new location with **zero pipeline changes**.

### The examples/ charter tension

`examples/README.md:3` says examples "fit in a single README section… If it's more than a page of code, it probably belongs under apps/ or labs/", and line 9 records trading-desk *leaving* examples for exactly that reason. The knowledge-base is ~1,160 src LOC with a Postgres profile and a bearer-secret guard — it does not meet that bar. But it also no longer belongs in `labs/` (it isn't incubating anymore; it's done), and `apps/` is framework infrastructure. The issue's own labels and direction point at `examples/`, and `examples/hello-chat` is already a full Next.js app, so the charter is aspirational rather than enforced. Resolution: move to `examples/` **and amend the charter** to name a second category — finished reference apps preserved as-is — rather than silently violating it.

### How the OKF question was researched

Industry practice on sharing code between examples splits on one question: is the example meant to be extracted from the repo? Vercel/Next.js keep examples standalone (their shared piece, `@vercel/examples-ui`, is a *published* package so extraction still works); Turborepo/LangChain/Mastra-style monorepos freely let examples import workspace packages because the repo is the distribution unit. On duplication timing, the consistent guidance (Fowler's rule of three, Dodds' AHA, Metz's "duplication is cheaper than the wrong abstraction") is: extract when you know the abstraction's shape *and* a real second consumer exists — and duplication into a **frozen** consumer is the cheapest duplication there is, because the copies never need to stay in sync.

Candidate homes in this repo, assessed against what each package actually exports:

- **`@flow-state-dev/memory`** — model-driven recall tiers (working/episodic/semantic/digest); writes come from LLM observation/consolidation. OKF is deterministic, model-free document CRUD plus on-disk bundle interchange. Same typed-edge primitive underneath, entirely different vocabulary and lifecycle. Scope stretch; rejected.
- **`@flow-state-dev/tools`** — tool blocks over pluggable external providers (search/fetch/crawl/bash). OKF is not a tool block. No fit.
- **`@flow-state-dev/patterns`** — multi-block composition patterns. OKF is a data-adapter + capability, not a composition. No fit.
- **A new dedicated package** — the natural target, and the lab's own README already records the graduation gate: promote "once there is a second consumer… and OKF has stabilized past v0.1." Today there is exactly one consumer; the hub scaffold shipped by this issue is empty. Extracting now would create a package with zero consumers (BP-038). The `okf/` subtree only type-imports `@flow-state-dev/core/types`, so extraction later is low-friction.

### Key Decisions & Ramifications (top 5)

1. **Destination is `examples/`, with the charter amended — not a rename within `labs/`.** Alt: keep it in `labs/` under a new name (e.g. `labs/okf-wiki`). Rejected because the app is finished — "incubating" framing would be false, and the incubation folder should hold things being incubated. Ramification: `examples/` now officially has two tiers (pedagogical snippets + preserved reference apps); the charter text stops matching reality only if we skip the amendment, so the amendment is in scope.
2. **OKF code is neither copied into the hub nor extracted in this issue.** Extraction into a dedicated package (working name `@flow-state-dev/okf`, private until stable) happens in the first Knowledge Hub issue that actually consumes concept CRUD/OKF — expected FIX-883 (the librarian), since FIX-882's staging area is explicitly distinct from the concept collection. Alts rejected: extract now (zero consumers until FIX-883 lands — speculative surface, BP-038); copy into the hub (two *living* copies of the same adapter, the exact divergence BP-038 warns about); fold into `memory`/`tools`/`patterns` (scope stretch / no fit, per research above). Ramification: FIX-883 inherits the extraction as part of its scope, and this spec is the recorded justification; until then the frozen example is the single source of truth to seed from.
3. **The frozen example keeps its embedded OKF copy permanently, even after extraction.** When FIX-883 extracts the package, the example is *seeded from*, not *rewired to*, the new package. Ramification: after extraction there will be one frozen snapshot copy plus one living package copy. This is accepted, deliberate duplication: the example's copy never needs to track OKF changes, and staying self-contained keeps the example copy-paste-able against published `@flow-state-dev/*` packages (a private `okf` package dependency would break that). This is the Vercel-examples split, resolved in favor of self-containedness.
4. **Package renames to `@flow-state-dev/example-knowledge-base`.** Matches the `examples/` naming convention (`@flow-state-dev/example-hello-chat`). Alt: keep the old name ("move as-is, unmodified"). Rejected: BP-034 says finish the rename — provenance that still says "incubation lab" misleads every future reader. The package is `private: true` with zero importers, so the rename is risk-free. Ramification: none beyond grep hygiene.
5. **Frozen means frozen: no functional or type changes ride along.** The diff inside the moved directory is limited to provenance (name, description, README framing, header comments). The known deepening opportunities (`ctx: any` throughout `flow.ts`/`capability.ts`, reserved-id logic split across `okf/types.ts` and `capability.ts`, the near-duplicate `conceptIdFromUri`/`conceptIdFromPath` helpers) are explicitly deferred to §8. Ramification: the review diff is verifiably mechanical — rename detection plus a handful of doc/comment hunks — which is what makes a move of a shipped MCP server safe.

## 6. Edge Cases & Error Handling

| Edge case | Expected behavior |
|---|---|
| Local dev data under `labs/knowledge-base/.fsdev/` (gitignored, dev profile writes there) | Does not move with the git mv. Anyone with local wiki data re-imports the sample bundle or copies `.fsdev/` to the new path manually. Note this in the PR description; no code handling. |
| PR #606 (dev-orchestrator lab) also touches `pnpm-lock.yaml` | Textual lockfile conflict likely on whichever merges second. Resolution is mechanical: rebase, re-run `pnpm install`. |
| knip's `examples/*` glob picks up the moved package before the override is added | Only local `pnpm knip` noise (CI gates on `unlisted,binaries,unresolved`, not unused files). Override in the same PR (step 5). |
| `vitest --passWithNoTests` on the hub scaffold | The scaffold ships one smoke spec, so the flag is a safety net, not load-bearing — consistent with sibling labs. |
| Old package name `@flow-state-dev/knowledge-base` referenced somewhere unnoticed | Grep confirmed zero importers; `pnpm install` + full typecheck would fail loudly if one appears. |
| Someone lands a knowledge-base change concurrently | Area is warm (last touched a few merges ago) but nothing is in flight (verified against all 7 open PRs). Rebase normally. |

Error taxonomy: everything here is a deterministic build/CI failure; nothing is retryable or runtime-degradable.

## 7. Testing Strategy

**Goal.** After the change, (a) the personal knowledge wiki still works end-to-end from its new home — a real MCP client can create a concept over HTTP and read it back in a later stateless session — and (b) the Knowledge Hub shell compiles and executes a flow action for real.

**Goal check.** Already exists for (a): `goals/personal-knowledge-mcp/persists-a-concept-across-stateless-calls/run.mts` — a model-free real run (real `serve()` host, real MCP transport, PGlite-backed prod profile, genuinely separate HTTP requests) that prints PASS/FAIL. Run it after the move; it doubles as proof the path fix landed. For (b): `pnpm --filter @flow-state-dev/knowledge-hub fsdev run` invoking the `ping` action — observable echo output is the pass signal. No LLM is involved in either (the wiki flow is pure CRUD; the scaffold has no generator), which is fine: model-free real-path runs are exactly what these flows do in production.

**Discipline.** This is an Improvement/enabler routed mechanical work, not red-green TDD — the safety net is the *existing* ~925-LOC suite (capability CRUD, OKF import/export/round-trip idempotency, MCP surface auth, user-scope isolation) running unchanged from the new path. The one new behavior (hub `ping`) gets the one new spec (§4.3).

**CI evidence path:** `pnpm typecheck && pnpm test` green at root (turbo picks up both moved and new packages automatically); `pnpm knip` clean.

**Pattern references:** `examples/knowledge-base/test/flow.spec.ts` (post-move) for flow-level test idiom; `fsd:write-block-tests` conventions for the hub smoke spec.

## 8. Non-Goals

- **No OKF package extraction.** Deferred to the first consuming Knowledge Hub issue (expected FIX-883, the librarian). Decision and target shape recorded in §3; FIX-883's spec should cite it.
- **No functional, schema, or type changes to the wiki.** Specifically deferred deepening opportunities in the moved code, to be handled later (candidates for `fsd:improve-codebase-architecture`):
  - Pervasive `ctx: any` in `flow.ts` handlers and `capability.ts` `fns` — the typed capability context is erased.
  - Reserved-id logic split across `okf/types.ts` (`RESERVED_FILENAMES`) and `capability.ts` (recomputed `RESERVED_CONCEPT_IDS`).
  - Near-duplicate helpers `conceptIdFromUri` (`flow.ts`) vs `conceptIdFromPath` (`concepts.ts`).
- **No hub functionality.** No staging collection, no capture verbs, no sweeper, no MCP adapter, no prod profile in the scaffold — FIX-882+ own all of that.
- **No root `tsconfig.json` project-reference addition.** The lab was never referenced there; adding one is unrelated to the move.
- **No Vercel/serverless serving path for the wiki** — documented-not-shipped before the move, unchanged (see the lab README's own limitation note).
- **No rewiring the frozen example onto the future OKF package** — decision 3 in §3 commits the example to staying self-contained even after extraction.
