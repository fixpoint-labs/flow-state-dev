# FIX-898: Recover critical financial evidence from IPO filings — Implementation Spec

## 1. TLDR

When a newly listed company has audited financials in its IPO prospectus but
not yet in the usual structured feeds, the desk today marks revenue, operating
income, and free cash flow unavailable and moves on. That is the wrong
terminal state: "unavailable" should mean every safe recovery path was tried,
not that Company Facts and Yahoo missed. This work adds a bounded recovery
ladder — SEC registration/prospectus filings first, then one capped agentic
extract — and only promotes numbers into the shared financials spine after
hard validation. If recovery still fails, the desk keeps `unavailable` and
records an audit trail so downstream gates can treat thin evidence honestly.

**Technical statement:** Extend the trading-desk statement-tool live chain
(EDGAR companyfacts → Yahoo → empty) with a single-flight critical-source
recovery path that discovers S-1/S-1A/424B\* (and F-1\*) primary documents,
extracts typed statement candidates, validates identity/period/scale/
reconciliation, and writes accepted payloads into `financialsData` via
`writeSubjectSpine` — or preserves `source: "unavailable"` with a structured
`recoveryAudit`.

**Deliverables:**

- **Providers:** Add `REGISTRATION_FORMS` discovery (separate from
  `PERIODIC_FORMS`) and prospectus primary-document fetch helpers under
  `labs/trading-desk/lib/providers/`.
- **Recovery:** Add single-flight critical recovery + pure validation leaf;
  treat sparse companyfacts (`source: "edgar"` with null critical fields) as
  a miss (today only throws fall through); wire into the three statement
  tools; add `edgar-prospectus` source tag + `recoveryAudit` on
  `financialsData`.
- **Disclosure:** Surface registration/prospectus filings without feeding
  them into 10-K/10-Q MD&A extractors (`flows/analysis/tools/data/get_sec_filings.ts`).
- **Tests/fixtures:** SPCX-shaped fixture corpus + unit/spine regressions for
  promote and honest-unavailable paths.
- **Docs:** Lab-local `docs/financials-recovery.md` + CLAUDE/README/fixtures
  updates (no new Docusaurus page).
- **Goal check:** Real-path goal under `goals/trading-desk-financials/` proving
  prospectus recovery populates valuation-critical fields (or honest audit on
  failure).

**Size estimate:** **Large** — multi-file within `labs/trading-desk` (providers,
tools, resource schema, fixtures, docs, goal). Single implementation PR is
fine; no framework package split required.

## 2. Overview

- **Linear:** [FIX-898](https://linear.app/fixpoint-labs/issue/FIX-898/trading-desk-recover-critical-financial-evidence-from-ipo-filings-and)
- **Package:** `labs/trading-desk` (`@flow-state-dev/trading-desk`) — lab app,
  not a framework package change.
- **Why:** The SPCX-shaped failure mode is architectural, not a one-off data
  glitch. Company Facts aggregates periodic XBRL (10-K/10-Q/…). IPO audited
  statements live in S-1 / 424B\* HTML and are invisible to both the statement
  chain and `PERIODIC_FORMS` filings filter. Phase 1 `investigate` can fetch
  pages for memo color but cannot promote typed numbers into `financialsData`,
  so valuation/DCF abstain even when authoritative public financials exist.

## 3. Background & Research

### Industry findings

- SEC **companyfacts** / companyconcept / frames cover periodic forms; IPO
  registration-statement financial XBRL is generally **not required**
  ([Inline XBRL C&DI Q146.12](https://www.sec.gov/rules-regulations/staff-guidance/corporation-finance-interpretations-cfis/inline-xbrl)).
- Filing catalog for S-1 / 424B\* is
  `https://data.sec.gov/submissions/CIK##########.json` (same submissions
  client the desk already uses), with primary HTML under Archives.
- Preferred form order for audited IPO financials: **424B4 → 424B3 → latest
  S-1/A → S-1** (plus **F-1/A → F-1** for foreign private issuers).
- Production vendors treat EDGAR prospectus text as authoritative until the
  first periodic XBRL lands; Yahoo/aggregators routinely lag or stay empty in
  that window.
- Hard promote gates are mandatory for LLM extraction: CIK identity, period
  end, scale (thousands/millions), cross-statement reconciliation (e.g. FCF ≈
  OCF − capex), reject secondary-only / wrong-company / conflicting candidates.

### Codebase findings

| Seam | Today | Gap |
|------|-------|-----|
| Statements | `get_{income_statement,balance_sheet,cashflow}`: EDGAR → Yahoo → `emptyPayload` | No prospectus tier |
| Filings | `PERIODIC_FORMS` = 10-K/Q/8-K only in `edgar-filings.ts` | S-1/424B\* filtered out |
| Investigate | `investigate` preset: fetch + citations on `full` | Citation-only; never writes spine |
| Spine | `writeSubjectSpine` → `financialsData` | Only tool payloads today |
| Valuation | `computeAndStoreSpine` reads statements; DCF abstains on missing FCF | Correct given empty spine |

Closest precedents to follow: statement try/catch → `emptyPayload` honesty;
`extract-holdings-generator` (LLM transcribes, deterministic validate after);
`investigate`/`corroborate` bounds (caps, not open loops); `citationIntegrity`
session audit shape; fixture record/replay preserving `"unavailable"`.

### Why this approach

**Deterministic SEC candidates first, then one bounded LLM recovery, then
honest unavailable** — matches industry practice and the desk's existing
provider-chain idiom. Putting recovery inside the statement tools (before the
fundamentals generator) ensures the spine the analyst and valuation tap see is
already repaired. Using `investigate` as the promote path was rejected: it is
memo-color, cost-gated to `full`, and has no typed write contract.

### Key Decisions & Ramifications (top 5)

1. **Recovery lives in the statement-tool live chain (single-flight), not in
   `investigate` / discovery.**  
   *Rejected:* Promote from Phase 1 investigate fetches into `financialsData`.  
   *Ramification:* Correctness path runs before synthesis; investigate stays
   citation-only. Parallel statement tools must share one recovery attempt
   (module/`getOrFetch`-style single-flight keyed by ticker+date).

2. **`REGISTRATION_FORMS` is a separate allowlist from `PERIODIC_FORMS`.**  
   *Rejected:* Dumping S-1/424B\* into `PERIODIC_FORMS`.  
   *Ramification:* Disclosure MD&A / Item 1A / 8-K extractors stay unchanged.
   Registration filings appear in a dedicated candidate list (and may be
   listed in `recentFilings` with clear form labels) without being fed to
   `latestPeriodic`.

3. **Hard validation is required before any spine write; narrative findings
   never promote.**  
   *Rejected:* Trusting LLM-extracted numbers with soft confidence only.  
   *Ramification:* Wrong-company, stale, secondary-only, scale-ambiguous, or
   unreconciled candidates → reject + audit; fields stay null/`unavailable`.
   No zero-fill, no magnitude guessing.

4. **Critical recovery is not cost-gated by `costPreset`.**  
   *Rejected:* Skipping LLM recovery on `fast` (the investigate pattern).  
   *Ramification:* One bounded recovery attempt may spend a model call on
   `fast` when companyfacts+Yahoo miss — intentional correctness cost.
   Deterministic prospectus HTML extract still preferred (zero model). Caps:
   ≤1 recovery generator invocation, ≤3 document fetches, SEC-first URL set.

5. **`financialsData` gains `recoveryAudit` + `edgar-prospectus` source tag;
   FIX-808 benchmark case is prepared but not blocked on FIX-808 landing.**  
   *Rejected:* Silent empty after failed recovery; waiting for FIX-808 before
   shipping fixtures.  
   *Ramification:* Downstream (FIX-781 evidence sufficiency) can read the
   audit; SPCX fixture + unit/spine tests ship with this issue; factual-
   accuracy benchmark registration is a hook/note for FIX-808.

### 4.2 Data flow

```
statement tool load (live / record — NOT fixture):
  try companyfacts XBRL
       ├─ throw → fall through (today)
       └─ returns source:"edgar" but criticalSparse(payload)? → treat as MISS
            (TODAY this is NOT a miss — mapEdgarCompanyFacts can return edgar+nulls.
             FIX-898 MUST add an explicit sparse→fall-through before promotion.)
  try Yahoo timeseries → usable hit → return (source: yahoo)
  subject ticker && criticalMiss(combined)? →
       single-flight recoverCriticalFinancials(ticker, date)  // run-local Promise map, NOT process TTL getOrFetch
       ├─ submissions → REGISTRATION_FORMS candidates (424B4 > 424B3 > S-1/A > S-1 > F-1*)
       ├─ fetch primary HTML (≤3 docs)
       ├─ deterministic table extract → candidate
       ├─ if insufficient → one bounded LLM extract (non-block leaf) over same docs
       ├─ validateFinancialCandidate(...)
       ├─ PASS → map to statement schemas in USD billions; fill only null/unavailable
       │         sibling fields (NEVER clobber a non-unavailable Yahoo/edgar sibling);
       │         recovery runtime patches recoveryAudit { outcome: "promoted", ... }
       └─ FAIL → empty for this tool's field if still missing;
                 recovery runtime patches recoveryAudit { rejected|no-candidates|extract-failed }
  else → emptyPayload (unavailable); recoveryAudit outcome "skipped" only when
         recovery runtime decides the subject was not a critical miss
```

**Critical miss (trigger):** For the **subject** ticker only (`toSpine === true`),
after companyfacts + Yahoo attempts, the **combined** critical set across
income + cashflow still lacks valuation-critical fields. Use **real schema
field names**:

- Income: `revenue`, `operatingIncome` (from `incomeStatementSchema`)
- Cashflow: `freeCashFlow` **or** extract-time OCF+capex that can compute FCF
  (tool schema has `operating` + `freeCashFlow` — there is **no**
  `capitalExpenditure` on `cashflowSchema`; capex is extract/validation-only,
  then write computed `freeCashFlow` + `operating`)
- Balance (when disclosed): `cashAndEquivalents`, `totalDebt` (not `cash`)

**Sparse companyfacts is a required new branch:** HTTP-success companyfacts with
null critical fields currently short-circuits the chain as `source: "edgar"`.
Recovery never runs unless tools treat that as a miss and fall through (and/or
invoke recovery after observing the sparse payload). Add this before wiring
promotion — otherwise the IPO path is a no-op for the SPCX case.

**Single-flight:** Parallel tools share one **run-local** in-flight Promise per
`(ticker, date)` (do **not** use process-TTL `getOrFetch` for LLM recovery —
failed attempts must not stick across sessions for 120s). Recovery may fill
missing statement fields on the spine but **must not overwrite** a sibling
field that already has a non-`unavailable` provider source.

**`toSpine: false` / peer probes:** Recovery and any `financialsData` patch are
gated on subject ticker / `toSpine === true` only. Peer `load()` paths must not
write the subject spine.

**`recoveryAudit` writer:** The recovery runtime is the **sole** writer of
`financialsData.recoveryAudit` on every outcome (`promoted` / `rejected` /
`no-candidates` / `extract-failed` / `skipped`). Statement tools do not each
race-patch the audit under parallel `getOrPatchState`.

### 4.3 API / types (implementer contracts)

```ts
/** Forms eligible for IPO / registration primary-document recovery. */
export const REGISTRATION_FORMS = new Set([
  "S-1", "S-1/A", "424B4", "424B3", "F-1", "F-1/A",
]);

export type RegistrationCandidate = {
  form: string;
  filingDate: string;
  accessionNumber: string;
  primaryDocument: string;
  url: string; // SEC Archives URL
  cik: number;
  companyName: string;
};

export type FinancialCandidate = {
  ticker: string;
  cik: number;
  companyName: string;
  form: string;
  filingDate: string;
  periodEnd: string;       // fiscal period end from filing context
  /** Multiplier applied to table integers to reach raw USD (e.g. "in thousands" → 1_000). */
  scale: 1 | 1_000 | 1_000_000;
  currency: "USD";         // v1: USD only; reject others
  sourceUrl: string;
  /** Extract-time numbers in raw USD (after scale). Promote maps into schema fields. */
  income: {
    revenue: number | null;
    operatingIncome: number | null;
  };
  cashflow: {
    /** Maps to cashflowSchema.operating on promote. */
    operating: number | null;
    /** Extract-only; used to derive freeCashFlow when FCF not stated. Not a spine field. */
    capitalExpenditure: number | null;
    freeCashFlow: number | null;
  };
  balance: {
    /** Maps to balanceSheetSchema.cashAndEquivalents. */
    cashAndEquivalents: number | null;
    totalDebt: number | null;
  };
  fieldProvenance: Record<string, { sourceUrl: string; excerpt?: string }>;
};

/**
 * On promote: divide raw-USD candidate values by 1e9 and set
 * `unit: "USD billions"` to match companyfacts/Yahoo mappers and DCF consumers.
 * Never leave prospectus dollars on the spine.
 */

export type RecoveryAudit = {
  attempted: boolean;
  outcome:
    | "promoted"
    | "rejected"
    | "no-candidates"
    | "extract-failed"
    | "skipped";
  formsTried: string[];
  urls: string[];
  rejectionReasons: string[];
  recoveredSource?: "edgar-prospectus" | "issuer-ir";
};
```

Extend `sourceTag` with `"edgar-prospectus"`. Extend
`financialsDataStateSchema` with `recoveryAudit: recoveryAuditSchema.optional()`.

Validation rules (all must pass to promote):

| Check | Fail → |
|-------|--------|
| CIK matches `resolveCik(ticker)` | reject wrong-company |
| Conformed name fuzzy-match vs profile/submissions name (non-empty) | reject |
| `periodEnd` present and ≤ run `date` + small grace; not decades stale vs listing | reject stale |
| `sourceUrl` is SEC Archives **or** previously allowlisted issuer IR host discovered from SEC filing links only | reject secondary-only open web |
| `scale` parsed from table header / explicit units — never inferred from magnitude | reject if ambiguous |
| At least revenue + operatingIncome + (FCF or operating+capex) present after scale | reject insufficient |
| If operating + capex + FCF all present: `|FCF − (operating − \|capex\|)|` within tolerance | reject unreconciled |
| No fabricating zeros for missing line items — leave null | n/a |
| Promote normalizes to USD billions | required (see above) |

### 4.4 Bounded LLM recovery

- **When:** Deterministic extract did not yield a validatable candidate.
- **Extract leaf (not a handler-called generator block):** Structured output
  only (`FinancialCandidate` subset). Prompt: transcribe from provided document
  text; never invent; cite excerpt per field. **BP-011:** statement tools are
  handlers — do **not** `block.run` a `generator` from inside them. Use a
  plain async model+schema helper owned by the recovery runtime, or a `router`
  if a true generator block is required (`get_social_sentiment.ts`). The
  `extract-holdings-generator` precedent is for *discipline* (transcribe then
  deterministic validate), not for calling a generator from a handler.
- **Fetches:** Prefer injecting already-fetched HTML/text into the prompt over
  open `search`. Hard-cap ≤3 document fetches; URL allowlist = recovery
  candidate URLs (+ at most one issuer IR prospectus URL linked from those
  docs). No open-ended research loop; no `investigate` preset reuse for
  promotion.
- **Modes:**
  - `fixture` — load fixtures only; never call live recovery (replay recorded
    `edgar-prospectus` / `unavailable` + audit).
  - `live` / `record` — run the live chain **including** recovery, then
    `recordIfRecording` on `record` (same as today's statement tools).

### 4.5 Disclosure surfacing

- `fetchEdgarFilings` / submissions loop: also collect registration forms into
  `recentFilings` (or a sibling `registrationFilings` array if mixing confuses
  consumers — prefer sibling field if disclosure prompts assume periodic-only).
- Do **not** pass registration forms into `latestPeriodic` / red-flag EFTS
  `forms=10-K,10-Q` probes.
- Update `get_sec_filings` description + disclosure prompt only as needed to
  acknowledge prospectus forms as primary disclosure for newly listed issuers.

### 4.6 Error handling

| Case | Behavior |
|------|----------|
| No CIK | Skip recovery; unavailable (same as today for non-US) |
| No registration candidates | `recoveryAudit.outcome = "no-candidates"`; unavailable |
| Fetch/HTML failure | Try next candidate within cap; then extract-failed |
| Validation fail | rejected + reasons; unavailable; **never** partial promote of unvalidated fields |
| LLM timeout/error | extract-failed; unavailable |
| Fixture mode | Load fixtures; preserve recorded unavailable + audit |

## 6. Edge Cases & Error Handling

| Edge case | Expected |
|-----------|----------|
| Established issuer with companyfacts hit | No recovery (`skipped`); existing path unchanged |
| Companyfacts empty, Yahoo hit | No recovery; `source: "yahoo"` |
| S-1 and later 424B4 both present | Prefer 424B4 |
| Only S-1/A amendments | Prefer latest by filingDate |
| FPI with F-1 only | Treat as registration candidate |
| Ticker recycled / CIK mismatch | Reject |
| Table "in thousands" missed | Reject (no magnitude guess) |
| LLM returns narrative without numbers | Reject; unavailable |
| Partial statements (revenue only) | Reject insufficient — do not promote incomplete critical set |
| Peer/benchmark `toSpine: false` calls | Must not trigger subject recovery write |
| Record/replay | Preserve `edgar-prospectus` and `unavailable` + audit |
| Non-US, no CIK, Yahoo miss | Unavailable; recovery skipped/no-candidates |

**Error taxonomy:** Provider HTTP failures are retryable only within existing
provider helpers; validation failures and exhausted candidates are **fatal for
promotion** (honest unavailable). Recovery itself is best-effort once per run.

## 8. Non-Goals

- General open-web scraping into `financialsData`.
- Replacing companyfacts for issuers that already have periodic XBRL.
- Feeding S-1 HTML into 10-K MD&A / risk-factor extractors.
- Making `investigate` / `discover_*` write the financials spine.
- Multi-currency prospectus statements (reject non-USD in v1).
- Promoting `sharesOutstanding` onto `balanceSheetSchema` (not on that schema
  today; extract may ignore share count or leave it off-spine).
- Building the full FIX-808 benchmark suite (only prepare the case/fixture).
- Implementing FIX-781 insufficient-evidence / no-add gate (complementary;
  consume `recoveryAudit` later).
- Framework availability-aware provider selection (FIX-805).
- Paid third-party IPO prospectus APIs as the recovery contract.

**Deepening opportunities (follow-up via `fsd:improve-codebase-architecture`):**

- Factory for the three near-identical statement handlers (BP-024).
- Explicit shared form-allowlist module once registration + periodic coexist.
- Companyfacts `form` field currently unused for preference.
- Single-period statements ignore `ifrs-full` while history uses it.
