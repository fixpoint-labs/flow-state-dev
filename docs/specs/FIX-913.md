# FIX-913: Trading-desk — collapse critical-financials recovery to the LLM tier — Implementation Spec

## 1. TLDR

**Plain-language summary.** When the trading desk can't find a newly-listed company's financials in the usual structured feeds, it falls back to reading the company's IPO prospectus. Today that fallback has two ways to read the prospectus: a hand-written parser that scrapes numbers out of the filing's HTML tables with regular expressions, and, if that fails, a bounded call to a language model. The regex parser is where almost all the bugs and review churn have lived — every prospectus is laid out differently, so the regexes never stop needing patches. Both readers feed the *same* hard safety check before any number is trusted, so the regex parser isn't a safety layer — it's just a fragile optimization in front of the model. This change deletes the regex parser and lets the model be the only reader, keeping the exact same safety check that decides what's allowed onto the books.

**Technical statement.** Remove the tier-1 deterministic prospectus parser (`lib/providers/prospectus-financials.ts`) and collapse `critical-financials-recovery.ts` from a four-step ladder (discover → fetch → deterministic-extract → LLM-extract → validate) to a two-step path (discover → fetch → **LLM-extract** → validate → promote), leaving the hard validator and the single-flight control plane untouched.

**Deliverables:**

## 2. Overview

- **Linear issue:** [FIX-913](https://linear.app/fixpoint-labs/issue/FIX-913/trading-desk-collapse-critical-financials-recovery-to-the-llm-tier) (fast-follow to [FIX-898](https://linear.app/fixpoint-labs/issue/FIX-898/trading-desk-recover-critical-financial-evidence-from-ipo-filings-and)).
- FIX-898 shipped a three-tier critical-financials recovery for newly-listed issuers (the SPCX failure mode): a deterministic HTML-table parser (tier 1), a bounded LLM extractor (tier 2), and a hard validator gate that both tiers funnel through. In practice tier 1 is where essentially all the brittleness and PR-review churn lives, and it is a large optimization in front of a model fallback that already exists and already validates. This spec removes tier 1 so `discover → fetch → LLM-extract → validate` is the whole recovery path, and proves — with a real-model goal check — that the model tier alone can reliably clear the validator on a real filing.

## 3. Background & Research

### 3.1 What FIX-898 built (current state)

`labs/trading-desk/flows/analysis/tools/runtime/critical-financials-recovery.ts` is the single-flight runtime invoked from the three statement tools (`get_income_statement` / `get_balance_sheet` / `get_cashflow`) when both structured providers (EDGAR companyfacts, Yahoo) miss the subject's valuation-critical fields. Its `runRecovery` today:

1. Resolves the ticker's SEC CIK (no CIK → `no-candidates`).
2. Fetches registration candidates (S-1 / 424B* / F-1), cap ≤3 (`fetchRegistrationCandidates`).
3. **Tier 1 loop** — for each candidate: `fetchProspectusPrimaryHtml` → push `urls`/`docs` → `extractProspectusFinancials(html, …)` (the deterministic regex parser) → on a hit, `tryPromote` (validate → promote).
4. **Tier 2** — one bounded `recoverFinancialsExtract` (real `model.generate`) over the fetched `docs` → `tryPromote`.
5. Otherwise an honest `unavailable` audit (`no-candidates` / `extract-failed` / `rejected`).

Every outcome is written exactly once to `financialsData.recoveryAudit` (this runtime is the sole writer). The hard validator (`flows/analysis/lib/validate-financial-candidate.ts`) and the promote mapping (`flows/analysis/lib/financial-candidate.ts`) gate **both** tiers identically.

### 3.2 Why tier 1 goes

- **Churn concentration.** `lib/providers/prospectus-financials.ts` (~359 source) + `test/prospectus-financials.spec.ts` (~462 test) ≈ 821 lines. Parsing arbitrary prospectus HTML tables with regex (revenue regex, scale-note ambiguity, period anchoring, currency detection, footnote markers, total-debt lines) is inherently brittle — every filing is laid out differently — and nearly every review finding on PR #805 landed here.
- **No safety loss.** Deleting tier 1 removes the fragile *transcriber*, not the *gate*. The LLM tier and the deterministic tier already call the identical `tryPromote → validateFinancialCandidate → promoteCandidate` path. "Fall back to the LLM" does not mean "trust the LLM's numbers" — the model finds and transcribes; the validator (CIK/identity, period, currency, explicit scale, completeness, FCF reconciliation) decides what reaches the spine (BP-020).
- **Marginal payoff.** Recovery fires only in a rare corner (companyfacts + Yahoo both miss). The path is already documented as a correctness path that may spend one bounded model call even on `fast`. Tier 1 mostly saved one model call in a rarely-hit path, at the cost of ~820 lines of perpetual edge-case maintenance.

### 3.3 What stays (do NOT touch)

- **The hard validator** (`validate-financial-candidate.ts`) — the real-money safety net. Pure, unit-tested, tier-agnostic. Unchanged.
- **The control plane** (`critical-financials-recovery.ts` scaffolding) — single-flight (`inflight`/`settled`), session-generation supersession (`clearRecoveryForSession`), tenant scoping, module-cache bounding, cancellation via `ctx.signal`, one-bounded-call cost cap. A model-only recovery still needs all of it. Unchanged except for the tier-1 loop body.
- **Discovery + fetch** — `edgar-registration.ts` (`fetchRegistrationCandidates`, `fetchProspectusPrimaryHtml`) and the `get_sec_filings` `registrationFilings` surface. Still needed to feed the model. Unchanged.
- **The LLM extractor** (`recover-financials-extract.ts`) — already the transcribe-strictly-then-validate discipline. Logic unchanged; only its self-describing header docstring is updated.

### 3.4 The load-bearing open question this reduction answers

Tier 1 was implicitly answering *"can the LLM tier reliably clear the validator on a real filing?"* Removing it forces that question into the open. The reshaped **real-model goal check** is where the answer lives — and where the true cost of the reduction (run-to-run stability of the model tier) becomes visible instead of hidden. It is the most consequential *new* deliverable; everything else is deletion and rewiring.

**Scope of what the goal check proves (deliberately narrow).** It exercises the risky step in isolation — `recoverFinancialsExtract` (real model) → `validateFinancialCandidate` → `promoteCandidate` over the SPCX fixture. It does **not** drive the runtime entry (`recoverCriticalFinancials` / `runRecovery`: the fetch loop, the audit write, single-flight) — that wiring is unchanged by this reduction and is covered by the mocked CI specs (§7). The goal proves "model + gate clears a real filing," not the plumbing around it; do not read it as end-to-end recovery coverage.

### 3.5 Key Decisions & Ramifications (top 5)

1. **Delete tier 1 entirely — no flag, no fast-path.**
   - *Alternative rejected:* keep the deterministic parser behind a preference flag as a zero-cost first attempt.
   - *Ramification:* every recovery firing **that fetches at least one document** now spends one bounded model call (still ≤1; a no-candidates or all-fetch-failed exit spends none, because the runtime returns before model resolution); we lose zero-model recovery for cleanly-tabulated filings but remove ~820 lines of brittle, perpetually-patched regex. A flag would preserve the maintenance burden this issue exists to remove.

2. **Preserve the `RecoveryAudit` outcome enum unchanged; collapse only the code paths that set it.**
   - *Alternative rejected:* drop `extract-failed` / the `producedCandidate` flag as "tier-1 leftovers".
   - *Ramification:* no schema change, no migration, and the downstream FIX-781 evidence-sufficiency gate keeps reading the same four `outcome` values. `producedCandidate` is retained but now scoped to the model tier (see §4.4): it still distinguishes "model returned nothing usable" (`extract-failed`) from "model returned a candidate the gates rejected" (`rejected`).

3. **Reshape the goal check from zero-model/zero-network deterministic to a real-model LLM-tier check.**
   - *Alternative rejected:* keep a deterministic goal check (impossible — it directly imported the deleted `extractProspectusFinancials`).
   - *Ramification:* the goal check now requires an inference credential and is model-dependent. Its run-to-run stability report becomes the honest cost signal of the reduction (per the issue: flakiness "must be reported, not hidden"). It no longer advertises "zero models, zero network."

4. **Keep the anti-game / honest-reject arm zero-model (a hand-built poisoned candidate → the pure validator).**
   - *Alternative rejected:* drive the reject arm through the model over stale HTML.
   - *Ramification:* the "validator is not a no-op" guarantee stays deterministic and non-flaky even as the promote arm becomes model-dependent. A model-driven reject arm could fail for the wrong reason (the model returns null) and muddy the signal.

5. **Update the two remaining recovery specs to mock the model tier; the spine spec gains a `vi.mock` it didn't need before.**
   - *Alternative rejected:* leave `financials-recovery-spine.spec.ts` exercising a real extractor (now deleted).
   - *Ramification:* unit-level determinism is preserved by mocking the model everywhere in CI; the **only** real-model proof is the goal check — exactly the split the issue mandates ("Unit-level determinism is preserved by mocking the model in the recovery specs").

### 4.3 `critical-financials-recovery.ts` — the rewiring

Concrete edits to `runRecovery` (current lines ~289–360):

- **Remove** the `import { extractProspectusFinancials } from "@/lib/providers/prospectus-financials";` line.
- The candidate loop stays but loses its extraction body — it becomes a **fetch-and-collect** loop:
  ```ts
  // Fetch each registration candidate's primary HTML (SEC-first, ≤3), collecting
  // the docs the one bounded model call will transcribe over. A per-doc fetch
  // failure is recorded and skipped; a run cancelled between fetches stops here.
  for (const candidate of candidates) {
    ctx.signal?.throwIfAborted();
    let html: string;
    try {
      html = await fetchProspectusPrimaryHtml(candidate.url, ctx.signal);
    } catch (err) {
      rejectionReasons.push(`fetch-failed ${candidate.url}: ${(err as Error).message}`);
      continue;
    }
    urls.push(candidate.url);
    docs.push({ url: candidate.url, text: html, candidate });
  }
  if (docs.length === 0) return finish(null, "extract-failed");

  // Supersession/abort re-check BEFORE resolving the model. `clearRecoveryForSession`
  // (a re-run's seedSession) bumps the session generation but does NOT abort the
  // signal, and the fetch loop above only checks the abort signal — so a run
  // superseded while its fetches were in flight would otherwise fall through and
  // spend a bounded model call (and race the new run's call) before `finish`
  // throws. With tier 1 gone there is no deterministic short-circuit left to catch
  // it first, so this guard is what preserves the ≤1-bounded-call cost cap and
  // single-flight discipline for superseded runs.
  if (currentGen(scope) !== gen) throw new RecoverySupersededError();
  ctx.signal?.throwIfAborted();
  ```
- The tier-2 block (the `try { const model = ctx.resolveModel(...) … }`) stays otherwise **verbatim** — it is now the sole extraction step. Only its leading comment loses the "Tier 2:" framing.
- **New guard (do not skip):** the supersession + abort re-check shown above, inserted **between the fetch loop and `ctx.resolveModel`**. Previously the deterministic tier sometimes promoted (and `finish` threw superseded) before the model call was reached; removing tier 1 makes the model call the only path, so without this guard every superseded run spends a wasted bounded call and races the concurrent re-run. `scope` and `gen` are already in `runRecovery`'s scope; `RecoverySupersededError` and `currentGen` are already imported/defined.
- `tryPromote` and `producedCandidate` stay. `producedCandidate` is now set only inside the model tier's `tryPromote`, so it cleanly means "the model produced a candidate we validated (pass or fail)."
- The module header docstring (lines 16–27, the numbered "recovery ladder is deterministic-first" list) is rewritten to the two-step path and the "may spend one model call on `fast`" note is preserved.

### 4.4 Audit `outcome` semantics (after removal — unchanged enum, reconciled paths)

| `outcome` | When (after tier-1 removal) |
|-----------|------------------------------|
| `no-candidates` | No SEC CIK, discovery threw, or zero candidates |
| `extract-failed` | All candidate fetches failed (`docs.length === 0`), **or** the model returned nothing usable (`recoverFinancialsExtract` → `null`, `producedCandidate === false`) |
| `rejected` | The model produced a candidate that failed the hard gates (`producedCandidate === true`) |
| `promoted` | A model candidate cleared every gate → statements written, `recoveredSource: "edgar-prospectus"` |

The `finish(null, producedCandidate ? "rejected" : "extract-failed")` lines (the LLM-catch path and the trailing "nothing validated" path) are unchanged — they already express exactly this, because `producedCandidate` was always set inside `tryPromote`. The only thing that changes is that `tryPromote` is no longer *also* reachable from a deterministic tier.

### 4.5 The reshaped goal check (`run.mts`)

Drive the real model tier the way the desk does, over the local SPCX fixture (zero network for the docs; one real model call per iteration):

```ts
import { createModelResolver } from "@flow-state-dev/core";
import { recoverFinancialsExtract } from "../../../labs/trading-desk/flows/analysis/tools/runtime/recover-financials-extract";
import { promoteCandidate } from "../../../labs/trading-desk/flows/analysis/lib/financial-candidate";
import { validateFinancialCandidate } from "../../../labs/trading-desk/flows/analysis/lib/validate-financial-candidate";

// Strip the ambient default-model override first: createModelResolver({}) declares
// no intents, and the core resolver THROWS ("FSDEV_DEFAULT_MODEL was set, but no
// intents are declared") when that env var is present. Existing goal runners do
// the same before building a standalone resolver.
delete process.env.FSDEV_DEFAULT_MODEL;
delete process.env.FSDEV_INTENT_PLAN;
delete process.env.FSDEV_INTENT_REASON;

const resolve = createModelResolver({});          // auto-detects the provider gateway from env
const model = resolve("openai/gpt-5.4-mini");     // a GeneratorModel — .generate matches ExtractModel

// Promote arm (model-dependent), looped for stability:
for (let i = 0; i < RUNS; i++) {
  const candidate = await recoverFinancialsExtract(
    model,
    [{ url: SEC_URL, text: spcxHtml, form: "424B4", filingDate: "2026-02-10" }],
    { ticker: "SPCX", cik: 1750000, companyName: "SpaceCo Exploration Inc." },
  );
  // assert: candidate non-null, validateFinancialCandidate(...).ok,
  //         promoteCandidate(...) → source "edgar-prospectus", USD billions,
  //         revenue / operating income / FCF non-null.
}
// report per-run PASS + aggregate (e.g. "5/5 promoted").
```

- **Model:** `openai/gpt-5.4-mini` (goals convention; a small/fast model is appropriate — the task is strict transcription of provided text). `createModelResolver` yields a `GeneratorModel` whose `.generate({ messages, outputSchema, maxTokens, signal })` satisfies the `ExtractModel` interface `recoverFinancialsExtract` expects.
- **Env hygiene (do not skip):** strip `FSDEV_DEFAULT_MODEL` / `FSDEV_INTENT_PLAN` / `FSDEV_INTENT_REASON` before `createModelResolver({})`. With no intents declared, the core resolver throws if `FSDEV_DEFAULT_MODEL` is set in the shell (as it commonly is in the goal/dev environments) — so the runner would fail before ever calling the model. Existing goal runners (e.g. `chat-harness/holds-a-conversation`) strip these for the same reason.
- **Gateway package must resolve (do not skip):** `createModelResolver({})` auto-loads the provider/gateway package from `@flow-state-dev/core` or `process.cwd()` (`tryResolveModulePath`). The Vercel AI gateway (`@ai-sdk/gateway`) is declared under `labs/trading-desk` and `apps/kitchen-sink` — **not** repo root / `goals/` — so a bare `pnpm tsx goals/…/run.mts` from the repo root can throw "Gateway package … is not installed" for an `AI_GATEWAY_API_KEY`-only operator before the stability loop runs. **Run the goal with cwd `labs/trading-desk`** (the pattern the existing trading-desk goals — `trading-desk-headless/fixture-run-clean` etc. — already use, since `fsdev`/gateway resolution is cwd-sensitive); the file-relative `../../../labs/trading-desk/…` imports inside `run.mts` resolve from the file's own location and stay valid regardless of cwd. (Alternatively, pass an explicit `gateways` config to `createModelResolver`; running from the app cwd is the lower-friction match to precedent.) `goal.md`'s **Run** command must show the cwd.
- **Stability loop (locked defaults):** `RUNS = 5`. The promote arm runs 5 times; the check passes **iff `k === RUNS`** (unanimous), always prints `k/5 promoted`, and exits non-zero on any miss. A `k < 5` result is reported, not silently retried (the issue's requirement) — it is the run-to-run stability datum that quantifies the cost of the reduction. These defaults are authoritative (see §7); there is no majority-green interpretation.
- **Anti-game arm (zero-model):** feed a hand-built poisoned `FinancialCandidate` (a decade-stale `periodEnd`) directly to `validateFinancialCandidate` and assert it is rejected with a non-empty reason list — proving the validator is not a no-op, without depending on the model. This preserves the current goal's anti-game guarantee deterministically.

### 4.6 Error handling

Unchanged from the current runtime, with one **strengthened** supersession guard:
- Cancellation (`ctx.signal`) rethrows before any audit write, both during fetch and during the model call — matching generator-block cancellation semantics.
- Supersession (`RecoverySupersededError`) still throws before writing into a reset spine — **and now also before resolving the model** (§4.3 new guard), so a run superseded during its fetches spends no model call and does not race the concurrent re-run's call. This tightens (not just preserves) the ≤1-bounded-call cost cap: pre-collapse, a superseded run could still reach the model call after a deterministic miss; post-collapse it cannot.
- A model/transport error after `producedCandidate` is `true` still resolves to `rejected` (not `extract-failed`), so a transport failure can't overwrite a gate verdict downstream consumers rely on.

## 5. Implementation Sequence

Ordered so the tree type-checks and CI stays green at each step (discipline: **`fsd:tdd`**, behavior-preserving — the existing specs encode the behavior; update them to the collapsed shape, keep them green).

Then per-case overrides: the stale-reject test returns a stale candidate → validator → `rejected`; a new/confirmed `extract-failed` case returns `null`; the "falls back to the ONE bounded LLM extract" test folds into the promote test (there is no deterministic tier to fall back from); drop the "deterministic tier succeeded → model never consulted" assertion. ## 6. Edge Cases & Error Handling

| Case | Expected behavior |
|------|-------------------|
| Cleanly-tabulated prospectus (tier 1 would have parsed it free) | Now costs one bounded model call; still promotes. This is the accepted cost of the reduction. |
| Non-US ticker (no SEC CIK) | `no-candidates`, **zero model spend** (returns before model resolution — resolved before any fetch). |
| No candidates / all document fetches fail | `no-candidates` / `extract-failed`, **zero model spend** (the runtime exits before model resolution). |
| Discovery returns zero candidates | `no-candidates` (unchanged). |
| All candidate fetches fail (`docs.length === 0`) | `extract-failed` (unchanged path, now reached without a deterministic attempt in between). |
| Model returns `null` (no revenue + no operating income, or unspecified scale) | `extract-failed` (`producedCandidate === false`). |
| Model returns a candidate that fails the gates (wrong CIK / stale / non-SEC URL / wrong scale / unreconciled) | `rejected` with reasons — **no fabricated zeros**. |
| Model/transport error after a candidate was produced and rejected | `rejected` preserved (a transport failure must not overwrite the gate verdict). |
| Run cancelled mid-fetch or mid-model-call | Rethrows the abort; no audit written, no promote (unchanged). |
| Concurrent re-run supersedes the in-flight recovery (during fetch) | `RecoverySupersededError` thrown **before `ctx.resolveModel`** (§4.3 guard); writes nothing **and spends no model call**. |
| Concurrent re-run supersedes after the model call started | `finish()`'s existing generation guard throws `RecoverySupersededError`; writes nothing (unchanged). |
| Goal-check promote arm flaky across runs | Report `k/N` honestly — this flakiness IS the measured cost of the reduction (issue requirement). |

Error taxonomy is unchanged: cancellation and supersession are fatal-to-the-run (rethrow); everything else resolves to an honest `unavailable` audit. Nothing that fails `validateFinancialCandidate` reaches the spine.

## 8. Non-Goals

- **The reusable bounded "hunter" pattern** — generalizing recovery into an installable primitive (mission + search/fetch tools + turn/cost budget + per-domain hard-validator) is explicitly a separate issue in FIX-913, to be scoped on its own once this reduction proves the model-tier-plus-validator shape holds. The load-bearing constraint that must travel with any such generalization is **hard-validate-before-promote** (SEC filings are a trusted structured source; the open web is not). Not in scope here.
- **No change to the validator or the promote mapping** (`validate-financial-candidate.ts`, `financial-candidate.ts`) — behavior must be provably unchanged.
- **No change to the single-flight / supersession / tenant / cache control plane** beyond removing the tier-1 loop body.
- **No change to the `RecoveryAudit` schema** (the `outcome` enum stays; §4.4).
- **Multi-currency** recovery stays out (non-USD candidates still rejected).
- **The token-usage cost-accounting seam** — the bounded model call's tokens are still not folded into `block_trace.modelUsage` (it's a direct `model.generate`, not a generator block). That remains the documented follow-up FIX-898 already noted; this reduction does not fix or worsen it (it was already the LLM tier's behavior).
- **Deepening opportunities:** none surfaced in this area that this reduction doesn't already address — the change *is* a deepening (deleting a shallow, brittle module in front of an existing primitive). No follow-up flag needed.
