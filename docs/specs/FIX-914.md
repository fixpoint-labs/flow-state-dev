## 1. TLDR

**Plain-language summary.** Today only one kind of building block — a "sequencer" (a block that runs other blocks in sequence) — gets a private scratchpad it can write notes to while a request runs. Every other kind of block (an agent tracking what it has loaded across its own tool calls, a loop counting its own passes, one branch of a parallel fan-out needing scratch that never leaks to its siblings) has nowhere clean to keep its own notes, so authors reach for four overlapping workarounds and hand-label fields to avoid clashes. This change gives *every* block the same private scratchpad, labelled by the block itself so two blocks never collide, and folds the existing "read the sequencer's notes" and "read a named block's notes" mechanisms into one idea: a block owns its state, and other blocks reach it by address.

**One-sentence technical statement.** Generalize the per-execution-scope state container — today gated to `kind === "sequencer"` — to any block that declares an own-state schema, expose the block's own state via a new `ctx.self` handle, and re-express `ctx.sequencer` / `ctx.targets` as addressing modes over that one primitive (resolution is already unified; this completes it at the container-gate and declaration layer).

**Deliverables.**

- *Core (types):* Add an own-state generic `TState` + `ctx.self: StateRef<TState>` (typed from the block's own `stateSchema`) to `BlockContext` in `packages/core/src/types/block.ts`; thread `TState` through the `handler` / `generator` / `router` / `sequencer` factory signatures (DSL callbacks inherit it).
- *Engine (runtime):* Lift the three container-creation gates (`createExecutionContext.ts:2773-2778`, `sequencer.ts:614`, `executeBlock.ts:301`) from `kind === "sequencer"` to "any block whose *effective* (config + capability-merged) `stateSchema` is present"; bind `ctx.self` directly to that scope node's own container.
- *Engine (live emit):* Confirm the already-generic `state_change` path (`scope-emit.ts`, `scope: "block_instance"`) + transient stripping fire for non-sequencer containers (serves all single-request goals; near-zero new work).
- *Engine (durable checkpoint — new emit site, suspend/resume only):* Add a checkpoint invocation site for non-sequencer stateful blocks (`emitStateSnapshot` is today sequencer-op-loop-only and reads `ctx.sequencer`), keyed on the retry-stable path. Scoped/deferrable — not needed by the single-request goal tests.
- *Core (capability seam — PR2):* Add a new own-state `stateSchema` field to the capability/preset surface + merge + wire it into the block's effective schema (none exists today; the merged surface is currently unconsumed except for the generator's context/tool entries). This is FIX-911's actual dependency.
- *Contract:* State the **fan-out / loop contract** explicitly — a loop-owner accumulates in `ctx.self`; a loop-body / fan-out iteration gets a fresh isolated `ctx.self` per pass — with a regression test.
- *Docs:* CREATE `apps/docs/docs/advanced/block-state.md`; EXTEND the two specialization pages + overview + core/orchestration READMEs + `docs/architecture/state-and-scopes.md`.

**Size: Large** — concentrated in load-bearing engine state plumbing, but mostly *generalizing three gates + one handle*, not new subsystems. Split: **(PR1)** the primitive — three gates + `ctx.self` + already-generic live emit + fan-out/loop contract + tests (durable checkpoint for non-sequencer state is a scoped/deferrable sub-step, needed only for suspend/resume); **(PR2)** the capability own-state seam + a generator-tool-loop demonstrator (the concrete FIX-911 proof — no on-`main` consumer migration, see §11.3); **(PR3)** docs. **PR1 alone unblocks FIX-911.**

## 2. Overview

Flow State Dev has four identity scopes (`request` / `session` / `user` / `org`) plus an execution-lifetime state container that today only sequencers get. Blocks that want their own private state — a generator tracking what it has loaded across its tool loop, a converge-style sequencer counting its own drain passes, a fan-out body needing scratch that never leaks to a sibling — have no clean home, so they borrow the enclosing sequencer's state and hand-namespace fields to avoid collisions.

This spec makes the execution-lifetime container a property of *any* block that declares an own-state schema, keyed by the block itself, and exposes it through a new `ctx.self` handle. Because `ctx.sequencer` and `ctx.targets` are *already* implemented as `getTarget(...)` over the same container mechanism, the change is a net-shrink at the mechanism level: one store, three addressing modes (own / nearest-sequencer / by-name). It directly unblocks FIX-911 (a generator holds its own `activeSkills`, no session-global bag) and simplifies FIX-910 (a converge sequencer's drain counter is its own block state, no `__`-namespacing).

## 3. Background & Research

### 3.1 How this works in the codebase today

- **The container gate is sequencer-only.** A `MemoryStateContainer` is created only when a scope's block `kind === "sequencer"` and it has `config.stateSchema` (`createExecutionContext.ts:2773-2778`, threaded through `sequencer.ts:614` and `executeBlock.ts:301`). Handlers/generators/routers never get one. **This gate is the primary thing FIX-914 generalizes.**
- **Resolution is already unified.** `ctx.sequencer` is literally `getTarget(nearestSequencerName)` (`createExecutionContext.ts:3174-3191`); `ctx.targets.<name>` is a `Proxy` forwarding to `getTarget` (`:2443-2457`). `getTarget` resolves siblings-first then ancestors and throws `AmbiguousBlockNameError` on duplicate names (`:2509-2541`; docs `advanced/state-targets-and-parents.md:53-76`). So "unify sequencer/parent/target" is *already done at the resolution layer* — the fragmentation is only in the declaration/schema keys and the container gate.
- **The container is per-execution-scope-node, not a request sub-slice.** It hangs on `ExecutionParentNode.parentStateContainer` (`createExecutionContext.ts:2000, 2773-2778`), one per sequencer *invocation*, surfaced by block name through `getTarget`. In-memory only (`MemoryStateContainer`, `state-container.ts:52-81`; the no-CAS FIFO-lock behavior lives in `createScopeStateOps`, `state-container.ts:219-416` — never `ConcurrentModificationError`); durability rides a separate `state_snapshot` checkpoint (`emitStateSnapshot`, `sequencer.ts:257-356`), keyed latest-only, transient keys stripped, validated against `stateSchema`.
- **`config.stateSchema` already means "this block's own state."** It exists on every `BlockConfig` (`block.ts:728`) but is honored only for sequencers. `sequencerStateSchema` (`handler.ts:63`) and `targetStateSchemas` (`handler.ts:73`) are **type-only** read-declarations ("what shape I expect on an ancestor"); they create no container.
- **Identity is retry-stable via the path.** `blockInstanceId = ${requestId}:${path}:${attempt}` (`contracts/block-instance-id.ts:50-56`); `path` (`step[N]`/`iter[N]`/`loop[N]`/`branch[name]`) excludes `attempt`. `ctx.idempotencyKey` (public) = `${requestId}:${blockPath}` — a ready-made retry-stable key. Fan-out copies already get distinct scope nodes (`forEach[i]/iter[j]`, `parallel[i]/branch[j]`), and `loopBack` re-runs get a `loop[N]` prefix while the loop-owner's own container is untouched (`sequencer.ts:382-398`).
- **Capability state schemas are type-only.** `defineCapability` copies `sequencerStateSchema`/`requestStateSchema`/`targetStateSchemas`/etc. (`define-capability.ts:74-84`) and `mergeCapabilities` merges them (`capability/merge.ts:316-417`), but **no factory consumes the merged state schemas at runtime** — only the generator reads context/tool entries (`generator.ts:2581-2602`). A capability that "contributes sequencer state" types the ctx but creates no container. FIX-911's skills capability needs this to actually bind state to a generator.

### 3.2 Industry research

Comparable systems key per-node private state and handle fan-out consistently (sources below):

- **LangGraph** keys checkpoints by a `|`-joined node **path** (`checkpoint_ns`) and disambiguates fan-out (`Send`) by **index within a superstep**; per-branch state is **private by default**, merged only through explicit reducers. Documented footgun: subgraph namespaces assigned by *call order* remap under reordering — mitigated by stable unique node names. ([Send](https://reference.langchain.com/python/langgraph/types/Send), [checkpoint_ns](https://github.com/langchain-ai/langgraph/discussions/1326))
- **Inngest** keys each step by a **string id** plus a **per-id occurrence counter** so the same step in a loop gets a distinct, stable slot each iteration — name + occurrence, retry-stable. ([step execution](https://www.inngest.com/docs/learn/how-functions-are-executed))
- **React hooks** = identity-by-position within a stable fiber; the **`key` prop** is the explicit disambiguator for list fan-out. The lesson: *position/path for the common case, an explicit stable discriminator for fan-out.* ([why hooks rely on call order](https://overreacted.io/why-do-hooks-rely-on-call-order/))
- **XState / AWS Step Functions Map** — isolate-per-instance on fan-out, aggregate at fan-in.

The universal rule every system confirms: **isolate per instance on fan-out; merge explicitly at fan-in** — shared-by-default under parallelism silently corrupts. FSD's per-scope-node container model already realizes this: each fan-out iteration is a fresh scope node, so its container is private by construction. FIX-914 adopts **path/scope-node identity** (not a bolt-on name+index) precisely because block state is **request-scoped** — there is no cross-run/cross-code-version replay window where path fragility (LangGraph's footgun) bites.

### 3.3 Why this approach over alternatives

Re-express over the existing per-scope-node container and generalize its gate (BP-029: compose the existing primitive), rather than (a) adding a fifth `ScopeType` (heavyweight new store/keys/persist plumbing for something that is a *partition of one request*, not a new identity axis — category error), or (b) building a name→cell request sub-namespace (re-implements what the scope-node container + `getTarget` already do). Keep `sequencerStateSchema`/`targetStateSchemas` as read-side type sugar over the one store (BP-038: don't grow the config surface), and defer removing any public surface to a later audit-then-remove issue (the issue's explicit discipline).

### 3.4 Key Decisions & Ramifications (top 5)

1. **Generalize the per-scope-node container gate; do NOT add a fifth scope.** Block state is a `MemoryStateContainer` on any stateful block's scope node, exactly as sequencer state is today — not an extension of `ScopeType`. *Locks in:* block state stays in-memory + checkpoint-durable, inheriting the FIFO-lock (no `ConcurrentModificationError`) and `state_snapshot` model for free. *Rules out:* block state living in a persisted scope store, or being addressable across requests. *Ramification:* the container-creation gate, checkpoint emission, and transient-key logic (all sequencer-entangled at `createExecutionContext.ts:2773-2778` + `sequencer.ts:257-356`) must be lifted to "any stateful block" — the main engine surgery.
2. **`stateSchema` = a block's own state, uniformly; add `ctx.self` to read/write it.** No new config key — `stateSchema` already means this for sequencers; honor it on every kind. *Rejected:* a distinct `blockStateSchema` key (redundant surface; `stateSchema` is already the name). *Ramification:* `ctx.self` is the public block-identity/state handle FIX-911 was told to wait for ("no public `ctx.self` until a second consumer" — FIX-914 is that consumer). `sequencerStateSchema`/`targetStateSchemas` stay as read-side type declarations over the same store.
3. **Fan-out contract = private per iteration; loop/sequencer owner accumulates.** This is emergent, not a new mechanism: each `forEach`/`parallel` iteration is a fresh scope node (fresh container), while a `loopBack`-driven loop keeps the owner's single container across passes. *Locks in:* to share across iterations you put state on the enclosing looping block, not the fanned-out body — matching every surveyed system. *Rules out:* shared-across-siblings block state by default (correctly — it is the universal footgun). *Ramification:* resolves the issue's "one real open decision" mechanistically; validated by a regression test, no prototype needed.
4. **Key block-state checkpoints on the retry-stable logical path (`${requestId}:${blockPath}`).** Scope of the fix is narrow: in-flow child instanceIds are always built with `attempt: 0` (`sequencer.ts:420`), so nested block-state checkpoints are *already* path-stable; only the **engine root dispatch** carries an incrementing `attempt` (`executeBlock.ts:206-214`). So the path key matters solely for a **root-level** stateful block across a retry that bumps `attempt` — and `ctx.idempotencyKey` (`= ${requestId}:${blockPath}`, `executeBlock.ts:326`) is a ready-made key already computed there. Today's sequencer checkpoint emits `key: seqRef.instanceId` (`sequencer.ts:341`), and that `key` is **both** the client dedupe key ("clients dedupe on `key`", `sequencer.ts:240`) **and** the durability-store key, so changing it touches the streamed `state_snapshot` contract, not just the store. *Decision:* block-state checkpoints key on the path; whether the wire `key` and the store key diverge (keep instance-id on the wire, path in the store) is settled in the PR1 step-1 spike. *Locks in:* a retried/resumed root-level block reclaims its prior state. *Ramification:* block-state durability shares the in-memory FIFO-lock model with sequencer state but is **not** byte-identical on the checkpoint key.
5. **A capability-contributed `stateSchema` creates a container; do NOT delete `targetStateSchemas`/parent-state.** The capability surface has **no own-state field today** — `sequencerStateSchema` is a sequencer-guarded *read* declaration, semantically distinct from own state, and the merged surface is unconsumed except for the generator's context/tool entries. So the FIX-911 seam requires a **new** own-state field on `CapabilityConfig`/`PresetDef` + a `mergeSurfaceInto` rule + wiring `mergedSurface` into the block's effective `stateSchema` (PR2). Removing the legacy target/parent surface is **out** — follow the FIX-910-style "re-express, prove, then delete" discipline in a later issue (consumers unknown). *Ramification:* net concepts shrink at the mechanism level now; the *public* config surface shrinks later, safely.

### 4.2 API surface

```ts
// BlockContext gains a self handle, typed from the block's own stateSchema.
interface BlockContext</* ... */ TState extends object = Record<string, unknown>> {
  /** This block's own request-scoped state, if it declared `stateSchema`.
   *  Undefined when the block declares no own state. Retry-stable and
   *  isolated per execution instance (private per fan-out iteration). */
  self?: StateRef<TState>;
  sequencer?: StateRef<TSequencerState>;   // unchanged: nearest enclosing sequencer
  targets: InferTargetStatesFromSchemas<TTargets>; // unchanged: by-name
  getTarget<T extends object>(name: string): StateRef<T> | undefined; // unchanged
}
```

`StateRef` is unchanged (`{ name, instanceId, state, input } & ScopeStateOps`). `ctx.self` is the same shape — reads via `ctx.self.state`, writes via `ctx.self.patchState()/incState()/atomicState()/...`. Declaration:

```ts
// Any block kind may now declare its own state. A generator tracks what it has
// loaded across its OWN tool-loop steps within one request — no session-global bag
// (this is the FIX-911 skills case).
const researcher = generator({
  name: "researcher",
  stateSchema: z.object({ loaded: z.array(z.string()).default([]) }),
  model: "openai/gpt-5.4-mini",
  // The context fn re-runs before each tool-loop step and reads the generator's own state.
  context: (_input, ctx) => `Already loaded: ${(ctx.self?.state.loaded ?? []).join(", ")}`,
  prompt: "Research the topic; load documents as needed.",
  tools: { /* loadDoc → await ctx.self!.pushState("loaded", id) */ },
});
```

**Where accumulation happens — and where it does not.** `ctx.self` persists across a block's re-runs *within one scope entry* (a generator across its tool loop, above) and across the passes of a loop that the block *owns* (a sequencer across its own `.loopBack` — the converge drain counter). A block re-invoked as a **loop body** (a step inside an outer `.loopBack`, or a `forEach`/`parallel` iteration) gets a **fresh `ctx.self` each pass** — that is isolation, not accumulation. Cross-pass memory for a loop body still lives on the loop-owning sequencer, reached via `ctx.sequencer` / `ctx.targets` (unchanged; now uniformly available). So for a router, `ctx.self` provides private per-invocation scratch that never leaks between passes, not routing memory across an outer loop.

### 4.3 Data flow

- **Own state (new).** Block declares `stateSchema` → on scope entry the gate creates a `MemoryStateContainer` seeded from schema defaults → `ctx.self` wraps it (`createScopeStateOps` + `wrapStateOpsWithEmit({ scope: "block_instance" })`) → reads/writes hit the FIFO-lock path (no CAS) → at step/terminal boundaries `emitStateSnapshot` checkpoints on the retry-stable path, transient keys stripped.
- **Nearest-sequencer (unchanged).** `ctx.sequencer` = `getTarget(nearestSequencerName)` walks up to the nearest sequencer scope node with a container.
- **By-name (unchanged, now more capable).** `ctx.targets.<name>` / `getTarget(name)` resolves siblings-then-ancestors. A named target that is a handler/generator/router **now has state** if it declared `stateSchema` (previously only sequencer targets did) — a natural generalization, no API change.

### 4.4 Fan-out & loop semantics (the contract)

- **`forEach` / `parallel` fan-out:** each iteration/branch runs in its own scope node → its own `stateSchema` container → **private per iteration**. Two iterations of the same block never see each other's `ctx.self`.
- **`loopBack` loop:** the looping sequencer keeps one container across passes → its own `ctx.self` **accumulates** across iterations (this is how a converge-style drain counter lives on the converge sequencer's own state). Re-executed *bodies* get `loop[N]` scope nodes → their own `ctx.self` is **fresh per pass** (isolation, not accumulation). A loop body that needs cross-pass memory writes it on the loop-owner via `ctx.sequencer` / `ctx.targets`, exactly as today.
- **Generator tool loop:** a generator enters its scope once and iterates the model/tool loop *inside* `execute`, so its `ctx.self` persists across tool-loop steps within one request. This (not a loop body) is the FIX-911 skills case.
- **Retry / resume:** keyed on the retry-stable path, a retried or resumed instance reclaims its own prior state.

### 4.5 State / durability / emit

- **In-memory:** FIFO-lock container — the no-persist mutation path in `createScopeStateOps` (`state-container.ts:219-416`), deep-equal no-op suppression, `version+1`, never `ConcurrentModificationError`. This behavior is identical to sequencer state today (block state reuses the same ops).
- **Checkpoint (suspend/resume only):** a non-sequencer stateful block has no existing checkpoint call site (`emitStateSnapshot` is sequencer-op-loop-only), so this needs a **new emit site** (§4.1); latest-only, keyed on the **retry-stable path** (Decision 4 — a deliberate divergence from sequencer checkpointing, which keys on `blockInstanceId`); transient keys stripped; validated against the effective `stateSchema`. `durable: true` inherited (opt out per block as sequencers do). Not needed by the single-request goal tests — see §5 step 5.
- **Streaming:** `state_change` items already carry `scope: "block_instance"` + `blockInstanceId` (`scope-emit.ts`); non-sequencer containers reuse this path. Sequencer `state_snapshot` items stay trace-only/transient.

### 4.6 Error handling

| Case | Behavior |
|---|---|
| Block declares no `stateSchema` | `ctx.self` is `undefined` (mirrors `ctx.sequencer`); guard with `?.`. |
| `ctx.self` written but no container (impossible if declared) | `noState` throwing ops (existing `getTarget` fallback, `:2463-2478`) — a bug-catch, not a runtime path. |
| Two ancestors share a target name | `AmbiguousBlockNameError` (unchanged). |
| Capability + block both declare `stateSchema` | Merge via existing `extendSchema` (`capability/merge.ts:271-284`); same-field type conflict → build-time error (existing merge semantics). |
| Fan-out sibling reads another iteration's `self` | Not possible — distinct scope nodes; `getTarget` by name resolves the nearest, never a parallel sibling's private cell. |
| Legacy resume (checkpoint written pre-FIX-914) | Sequencer checkpoints unchanged in shape; non-sequencer block state is new, so no legacy records exist to dual-read. Confirm in spike. |

## 6. Edge Cases & Error Handling

| Edge case | Expected behavior |
|---|---|
| `stateSchema` on a handler/generator/router | Container created; `ctx.self` live (in-memory); checkpointed on the retry-stable path only when the block suspends/resumes. |
| No `stateSchema` | `ctx.self` undefined; zero overhead (gate skips). |
| `forEach` N copies of a stateful block | N private containers; no cross-talk. |
| Block as a **loop body** under an outer `.loopBack` | Fresh `ctx.self` each pass (isolation) — cross-pass memory lives on the loop-owner via `ctx.sequencer`. |
| Stateful sequencer over its **own** `.loopBack` | One container; its own `ctx.self` accumulates across passes (converge drain counter). |
| Retry after throw / resume after suspend | Same path key → reclaims prior state (root-level blocks; nested are already attempt-0/path-stable). |
| Named target now stateful (non-sequencer) | `ctx.targets.<name>` returns a live `StateRef` (previously `noState`). |
| Capability + block both declare `stateSchema` | Merged; conflicting field types throw at build time. |
| Transient slot on block state | In-memory only; stripped from checkpoint + `state_change`; resets on resume. |
| Duplicate ancestor names | `AmbiguousBlockNameError` (unchanged). |

**Error taxonomy:** build-time schema conflicts are fatal (non-retryable, as today). Runtime state ops inherit the existing non-throwing FIFO-lock path (no `ConcurrentModificationError`). No new error codes.

## 7. Testing Strategy

**Goal (observable):** an author can declare `stateSchema` on a non-sequencer block and that block carries its own private state across its re-runs within one request — a generator remembers what it loaded across tool-loop steps, and a sequencer counts its own `loopBack` passes in its own state — while a fan-out / loop-body block gets a private cell that never leaks to a sibling or the next pass.

**Goal check (real path, out-of-CI):** `goals/block-state/generator-remembers-across-tool-loop/run.mts` — a real-model generator with a `loadDoc` tool that appends to `ctx.self.loaded`, whose `context` reflects prior loads; PASS = later tool-loop steps see earlier loads (no duplicate load of the same doc / correct accumulation), FAIL otherwise. A second, mock-model assertion drives (a) a sequencer counting its own `.loopBack` drains in `ctx.self` and terminating on the count, and (b) a `forEach` over a stateful block, confirming per-iteration isolation via emitted items. (A real model is needed only for the generator-tool-loop variant — the loop-owner and fan-out variants are pure state behavior and run against a mock/echo model.)

**Discipline:** `fsd:tdd` (feature — red-green-refactor, tracer-bullet slices).

**Behaviours to test (each a tracer-bullet cycle):**

- A handler with `stateSchema` reads/writes `ctx.self`; a block without one has `ctx.self === undefined`.
- A generator's `ctx.self` accumulates across tool-loop steps; a sequencer's own `ctx.self` accumulates across its `.loopBack` passes.
- **A loop-body block's `ctx.self` resets each pass** (isolation) — the corrected fan-out/loop contract; a `forEach` body's `ctx.self` is private per iteration.
- Retry/resume: same-path instance reclaims prior state (`sequencer-checkpoint.test.ts` seam).
- Transient slot on block state: in-memory, absent from checkpoint + `state_change`.
- A capability-contributed `stateSchema` yields a live `ctx.self` on the consumer.
- Regression: `ctx.sequencer` / `ctx.targets` / `getTarget` semantics + ambiguity errors unchanged; `routedSpecialists` parity.

**Reference test files:** `packages/core/test/sequencer.test.ts`, `packages/testing/test/sequencer-state.test.ts`, `packages/engine/test/deterministic-block-id.test.ts`, `packages/engine/test/sequencer-checkpoint.test.ts`, `packages/orchestration/test/task-board/task-board.test.ts` (per-instance isolation contract, `task-board/schemas.ts:46-84`).
