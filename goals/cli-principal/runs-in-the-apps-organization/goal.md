# cli-principal › it runs in the app's organization

**Issue:** FIX-1551 (VG); re-pointed by FIX-1611. Needs FIX-1500 PR-B, which gives kitchen-sink its host resolver.
**Outcome:** A developer runs a kitchen-sink seat from the terminal and it behaves as the app would for a browser visitor. `support.general` answers, and its conversation is stored in the `kitchen-sink` organization, where the app's own pages can see it. Before FIX-1551, the terminal ran in the framework's development organization.
**Re-pointed (FIX-1611).** Until FIX-1611 the seat was `support.mara`, a manager whose run hired a seat, and (c) read the hire's roster row. The page's hiring and the manager are gone; the operator hired over `workforce-admin`, which FIX-1788 has since removed. So the run is now an ordinary question to a specialist, and (c) reads the conversation it stored: the same question, "which organization did the terminal's run write under", asked of the one record every run writes.
**Input:** `fixtures/input.json`: the seat, the action, the message, and the identity the app's resolver names. Held-out: the conversation id is fresh every run, so the check cannot pass on a record an earlier run left behind. Changing the seat to another specialist or the message wording must still pass a correct implementation.
**Signal:** Three checks on one run. (a) The capture's `command.principal` is exactly the fixture's `expect` (`devuser` / `kitchen-sink` / `resolver`). (b) The run completes. (c) A zero-model read of the same filesystem store finds the run's conversation, belonging to `support.general`, stored under `kitchen-sink` and not under `__fsd_default_org__`.
**Anti-game:** A hollow pass would grade the model's transcript, or the CLI's own claim about its identity. Neither proves where the conversation went. This check MUST read the conversation out of the store and must not treat `result.success` alone as proof. It must not reuse a fixed conversation id, or a record from an earlier run passes it.
**Model:** real — kitchen-sink's configured model (no `--model` override)
**Run:** `pnpm tsx goals/cli-principal/runs-in-the-apps-organization/run.mts` (sets `STORE_TYPE=filesystem` for the child `fsdev run`)
**Controls:** none planted. The red is the placeholder ask: the CLI's question to the app replaced with the development default it gave before FIX-1551 (a hand mutation, recorded below). (a) and (c) must fail under it.
