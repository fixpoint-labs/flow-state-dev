# coordinators › it files tasks down the owner's chain

**Issue:** FIX-1794 (epic FIX-1786). Its spec's goal: `specs/issues/FIX-1794/SPEC.md` → "The goal, and how we'll know it's met".

**Outcome:** every task a user's coordinator files for one of its delegates runs in a new session that belongs to that user and acts as them. Only the conversation that filed a task claims, lists, waits on or settles it, even when its worker runs on another flow. The conversation hears how the task ended, once, and can file it again. Another user can't reach any of it.

**Input:**

- Legs a, c and d: a goal-local tree (`fixtures/workforce/`) on the real engine, its HTTP router and a SQLite store, run as its own process (`host.mts`): `desk.lead`, a coordinator routing by judgment, whose delegates are `desk.alpha` and `desk.beta` on the built-in `agent` flow and `desk.sub`, a coordinator. Alice and Bob each sign in with their own verified bearer and act through the shipped clients (the session client, an action client per flow, `createWorkforceClient`). The coordinators' judgment and the `agent` workers' turns are scripted by marks in what they read: `[file:<worker>]` files the message as a task for that worker through the coordinator's own `addTask` tool; `[split:<worker>]` tries to file a piece; `[slow:<ms>]` holds a worker's answer. A line telling a coordinator a task ended files nothing.
- Leg e: Shift Manager's DevTeam install as the commit ships it, its chief of staff on the real model its `WORKER.md` names, served by Shift Manager's own command over a fresh store. Alice is its owner. Through the app she hires two workers on `agent`: one whose `model:` names a model the gateway doesn't serve, so each of its attempts fails on the provider's answer, and one on the chief of staff's own model. She adds both to a new conversation and asks, in the words of `fixtures/asks.json`, for a task for the first, filed again for the second if it fails.
- Held out, picked at run time: every word in a goal or an ask, the workers' ids, the unserved model's id, the missing worker's id. Another wording a person might use for leg e's ask must pass too.

**Signal:** each failure is tagged `<leg>:<assertion>`.

- **a** (Alice's coordinator files a task for `desk.alpha`, whose answer is held 2.5 s): `a:filed` its own `addTask` stored the task on this conversation's board, in the partition its `listDelegates` names, for `desk.alpha`; `a:completed-60s` the task is `completed` within 60 s of the filing; `a:task-session` it ran in exactly one new session, Alice's, a child of the conversation, on `agent`, born naming `desk.alpha`, the task and the conversation's `filingSessionId`; `a:found` `findWorkerSession({ worker, taskId, filingSessionId })` returns that session; `a:one-notice` the conversation holds one `completed` line under `desk.alpha` and acted on one notice, read after a 5 s grace; `a:returned-first` the filing turn ended before the task's run did. The interim rule until FIX-1802: `a:split-refused` a task filed for `desk.sub` completes, and its task session's `addTask`, by its own tool and by the app, is refused, with nothing stored.
- **c** (two of Alice's conversations with `desk.lead`): the second files a task with no assignee (it waits, with three delegates); the first files one for `desk.alpha`, then names the second's task in an `assignTask`; the second assigns its own to `desk.beta`, which holds 4 s; while it runs, the first files another. `c:runs-its-own` each task ran once, in a session of the conversation that filed it, and the first conversation's assign of the other's task was refused; `c:lists-its-own` each conversation's own `listTasks` lists its own tasks and nobody else's; `c:drain-returns` the first conversation's board run, started while the other's task ran, ended before that task did; `c:found-its-own` `findWorkerSession` finds each task's session in its own conversation and in no other.
- **d** (Bob, after Alice hires a worker of her own and files a task for it): `d:refused` Bob opening, posting to and filing on Alice's conversation are each refused; `d:same-answer` in his own conversation, a filing naming Alice's worker is refused with the answer a missing worker gets but for the id, naming it, and his `addDelegate` naming it is refused too; `d:her-rows-untouched` no row of Alice's is written after Bob begins, and no row or session of Bob's names her worker; `d:bobs-own-runs` Bob's own filing for `desk.alpha` runs in a session of his, a child of his conversation; `d:chain-is-hers` every session under Alice's conversations is hers.
- **e** (the chief of staff, a real model): `e:filed` its first turn files a task for the failing worker with `addTask`; `e:errored` the task fails both its attempts; `e:one-notice` the conversation holds one `errored` line under that worker's name, read after a 5 s grace; `e:no-turn-on-retry` the first failure runs the task again with no line and no turn; `e:refiled` the turn the notice woke files the task again with `addTask`, on this conversation's board, its goal carrying the held-out word; `e:reply-names` that turn's reply names the task (its id or its word) and the error the task recorded.

**Anti-game:** no drain, `runTaskBoard` or board read from the check while it waits for a task: it waits until the engine's request store holds nothing running (the request store is read only for that). No row, notice or session is written by a fixture: every change is an action a person sends, a line to a coordinator, or what the system does with them. Every grade reads the store file the run wrote, read-only and without app code (`store.mts`: task rows, sessions, requests, items), except what an action answered, which is what the person saw. Leg c's lists are each conversation's own `listTasks`, never the store. Counts are read after a 5 s grace. Leg e's error is graded against the error the task recorded, so a reply can't pass by quoting the ask.

**Attempts:** leg e runs on a real model, so it runs until it first passes, up to three attempts (`GOAL_ATTEMPTS`), each on a fresh store and a fresh Lab; every attempt is printed and the verdict names the one it passed on. Under a control there is one attempt. Legs a, c and d are scripted and run once.

**Model:** real for leg e: DevTeam's chief of staff's own `model:` (`anthropic/claude-haiku-5-5` at this goal's first commit), gated on a key that serves it (`keysServing`). Legs a, c and d are scripted and need none.

**Model-free run:** `GOAL_LEGS=a,c,d`

**Run:** `pnpm tsx goals/coordinators/files-tasks-down-the-owners-chain/run.mts`. `GOAL_LEGS=a,c,d,e` runs some legs; `GOAL_COMMIT=<sha>` serves another commit from its own tree and install (`git archive` plus `pnpm install`, kept under the system temp directory across runs). Run one goal at a time, with more than 5000 MB free. On demand only, never a CI gate.

**Controls:** each is scratch patches to Workforce modules, applied as the process under test loads them (`goals/lib/module-patch.mjs` through `NODE_OPTIONS`); printed in full by the run, and refused when they never reached the code.

- `GOAL_CONTROL=unpartitioned`: one ledger for all of a user's conversations (`conversation-board/ledger.ts`, both the partition and the board's own ledger, and the task entry's check that a task session works only its own conversation's partition). Leg c must fail **`c:runs-its-own`** (the first conversation's assign reaches the other's task, and its board runs it). `c:lists-its-own` and `c:found-its-own` go red with it. `c:drain-returns` goes red too, but not on the wait: the task it measures ran under the other conversation, so it was never running when the measure starts. It has no isolating red state.
- `GOAL_CONTROL=no-follow-up`: a task's ending reaches the conversation that filed it and nothing follows, no line and no turn (`conversation-board/task-notice.ts`); a retried attempt still runs again. Legs a and e must fail **`a:one-notice`** and **`e:one-notice`**. In leg e, `e:refiled` and `e:reply-names` go red with it: no turn, so nothing is filed again.

**Before-state:** `GOAL_COMMIT=84e9e072e` is `main` just before FIX-1794's second PR merged (#2935, merge `1854a84f0`). Every leg must fail there.
