# delegation › it synthesizes fanned-out worker results

**Issue:** FIX-930 (epic) — verifies the shipped substrate: FIX-918 (delegation via skills-library `agents:` + blocks-as-tools), FIX-927 (board-scoped `taskTools` for mid-drain fan-out), FIX-920/928.
**Outcome:** A coordinator generator, given a team of declared agents, delegates a unit of work to one worker via `addTask` + `runBoard`; that worker fans out follow-up work mid-drain to a second worker; and both workers' results come back and are synthesized into the coordinator's final answer. What a user notices: they get an answer that contains information only the workers held — the coordinator could not have produced it alone.
**Input:** `fixtures/team.json` — a `researcherSecret` token and an `auditSuffix`. Held-out: swap them for any other two distinct strings and a correct implementation still passes. The assertions derive the expected markers from the fixture (`SECRET`, `SECRET+SUFFIX`); nothing is hardcoded. **Marker placement is load-bearing:** `agentPurpose()` copies each worker's first nonempty prompt line into the coordinator's pre-task roster, so both markers must sit on later lines — the first line of each worker prompt is a generic purpose statement.
**Signal:** graded on the coordinator's **terminal output only** — `res.output` and nothing else. No message fallback: worker messages and the coordinator's own intermediate turns both land in `res.items`, so aggregating any of them would let a run whose terminal output is empty pass off an earlier turn. An **empty terminal output is a FAIL** (`z.string()` permits `""`, and it means the caller received no answer). Markers are matched **exactly and case-sensitively** (the fixture code must survive verbatim; a lowercased echo does not count) by substring + boundary — never tokenization — so the held-out contract above genuinely holds for any strings, including ones with `_`, spaces, punctuation, or non-ASCII. A "standalone" marker is a bounded occurrence that is not part of **any** occurrence of a longer graded marker containing it — every containment offset is checked, not just the first, so a fixture like `researcherSecret="A"` / `auditSuffix="+A"` cannot let the auditor-only answer `A+A` pass as a standalone researcher result. The two sides of the A/B are driven by **one shared marker list**, so they cannot drift: the ON answer must carry **every** marker; the OFF baseline must carry **none**.
1. **Delegation** — the coordinator's terminal answer contains `researcherSecret` as a **standalone** token (the `researcher` ran and its own result was synthesized — not merely reported as part of the auditor's longer code).
2. **Fan-out** — the terminal answer contains `researcherSecret + auditSuffix` as a token (the `auditor` ran). This marker is unforgeable by anyone but the fanned-out auditor: the coordinator is told to assign exactly ONE task (to `researcher`) and call `runBoard` ONCE, and it never learns the suffix; the auditor only produces `code+suffix` from a code it is HANDED, and only the researcher holds the secret. So `secret+suffix` proves the researcher enqueued the auditor mid-drain and passed it the secret.
3. **A/B baseline** — a second coordinator (same prompt, same user turn, differing ONLY by the team binding) bound to NO team must produce **neither** graded marker. Any marker in the no-team run — the bare secret *or* the fanned code — invalidates the contrast, since it means the marker was reachable without delegation.
**Anti-game:** the gameable pass is asserting the mechanism ran — that `addTask`/`runBoard` were called, that the board reached `drained`, that a `task-change` fired. All of those can pass while the workers' outputs never reach the coordinator's answer. Two subtler hollow passes are closed explicitly: (a) inline workers default to **client-visible** messages, so a worker's secret lands in `res.items` whether or not the coordinator synthesized anything — hence grading the coordinator's **terminal output alone**, never the worker messages; (b) because `FANNED = SECRET + SUFFIX`, a naive substring check makes `SECRET` present whenever `FANNED` is — hence requiring a **standalone `SECRET` token distinct from `FANNED`**, so a coordinator that dropped the researcher's own result can't pass. (c) the **roster leak** — `agentPurpose()` (`packages/orchestration/src/skills/delegation-surface.ts`) copies each worker's first nonempty prompt line into the delegation roster the coordinator reads BEFORE any task runs, so a marker on line 1 would let a coordinator that never synthesized the researcher's result emit it straight from the roster and satisfy both graded checks. The A/B baseline cannot catch this (no team binding → no roster), so the markers are kept off the first line and `assertNoRosterLeak()` fails the run — before any model call — if one reappears there. That guard calls the REAL `agentPurpose`, so a change to the roster rule surfaces loudly. (d) **baseline asymmetry** — if the ON side accepts a marker the OFF side doesn't reject, a baseline that emitted the fanned code would still read as "clean" and the fan-out would be falsely attributed to delegation; both sides are therefore driven by one shared `GRADED_MARKERS` list. Plus the delegation-ON vs delegation-OFF contrast over the identical prompt/request. Do NOT assert on tool-call counts, board status, or item counts.
