# delegation › it synthesizes fanned-out worker results

**Issue:** FIX-930 (epic) — verifies the shipped substrate: FIX-918 (delegation via skills-library `agents:` + blocks-as-tools), FIX-927 (board-scoped `taskTools` for mid-drain fan-out), FIX-920/928.
**Outcome:** A coordinator generator, given a team of declared agents, delegates a unit of work to one worker via `addTask` + `runBoard`; that worker fans out follow-up work mid-drain to a second worker; and both workers' results come back and are synthesized into the coordinator's final answer. What a user notices: they get an answer that contains information only the workers held — the coordinator could not have produced it alone.
**Input:** `fixtures/team.json` — two **independent** markers, `researcherSecret` (e.g. `QORVIX-7788`) and `auditToken` (e.g. `BRAVO-5521`). Held-out: swap them for any other valid pair and a correct implementation still passes. Two contract rules, both validated at load so a bad fixture throws with a clear message rather than mis-grading:
- **Independent** — neither marker may contain the other. If one were derivable from the other (as it was when the auditor returned `secret + suffix`), a coordinator handed only the auditor's result could print both and pass with the researcher's own output dropped.
- **Sentinel format** — at least 6 characters, starts with a letter, letters/digits/hyphens only, no leading or trailing punctuation. This keeps a marker from colliding with response formatting (a bare `-` would match a Markdown list bullet) and from containing a `$`-substitution sequence (`$ARGUMENTS`, `$1`–`$9`, `${...}`), which the skills runtime's `substitute()` would erase from a worker prompt while the grader still expected the literal.

**Signal:** graded on the coordinator's **terminal output only** — `res.output` and nothing else. No message fallback: worker messages and the coordinator's own intermediate turns both land in `res.items`, so aggregating any of them would let a run whose terminal output is empty pass off an earlier turn. An **empty terminal output is a FAIL** (`z.string()` permits `""`, and it means the caller received no answer). Markers are matched **exactly and case-sensitively** (the fixture code must survive verbatim; a lowercased echo does not count) by substring + boundary, never tokenization. A "standalone" marker is a bounded occurrence. There is no nesting/derivation logic in the grader, deliberately: marker **independence is asserted at fixture load**, which is a strictly stronger guarantee than any after-the-fact exclusion rule. The two sides of the A/B are driven by **one shared marker list**, so they cannot drift: the ON answer must carry **every** marker; the OFF baseline must carry **none**. The two sides match differently on purpose — the ON side requires a *bounded, standalone* occurrence, while the OFF side uses a **plain substring** check, since on the baseline ANY appearance (even embedded, e.g. `prefixCODEsuffix`) proves the marker was reachable without delegation and disqualifies the contrast.
1. **Delegation** — the coordinator's terminal answer contains `researcherSecret` as a standalone occurrence. Only the researcher holds it, so its presence proves the researcher's own delegated result was synthesized.
2. **Fan-out** — the terminal answer contains `auditToken` as a standalone occurrence. **The auditor running at all IS the fan-out proof**: the coordinator is told to assign exactly ONE task (to `researcher`) and call `runBoard` ONCE, so the auditor only ever lands on the board when the researcher enqueues it MID-DRAIN. Only the auditor holds this token, and it never echoes the secret, so the token cannot be derived from the researcher's result.
3. **A/B baseline** — a second coordinator (same prompt, same user turn, differing ONLY by the team binding) bound to NO team must produce **neither** graded marker. **Either** marker appearing in the no-team run invalidates the contrast, since it means the marker was reachable without delegation.
**Anti-game:** the gameable pass is asserting the mechanism ran — that `addTask`/`runBoard` were called, that the board reached `drained`, that a `task-change` fired. All of those can pass while the workers' outputs never reach the coordinator's answer. Two subtler hollow passes are closed explicitly: (a) inline workers default to **client-visible** messages, so a worker's secret lands in `res.items` whether or not the coordinator synthesized anything — hence grading the coordinator's **terminal output alone**, never the worker messages; (b) **derivability** — the auditor originally returned `secret + suffix`, so its result *contained* the researcher's marker and a coordinator handed only the auditor's output could print both, passing with the researcher's result dropped. Standalone-ness forced a separate write but did not make derivation impossible; the fix is structural — the two markers are now **independent fixture values**, so neither can be produced from the other. (c) the **roster leak** — `agentPurpose()` (`packages/orchestration/src/skills/delegation-surface.ts`) copies each worker's first nonempty prompt line into the delegation roster the coordinator reads BEFORE any task runs, so a marker on line 1 would let a coordinator that never synthesized the researcher's result emit it straight from the roster and satisfy both graded checks. The A/B baseline cannot catch this (no team binding → no roster), so the markers are kept off the first line and `assertNoRosterLeak()` fails the run — before any model call — if one reappears there. That guard calls the REAL `agentPurpose`, so a change to the roster rule surfaces loudly. (d) **baseline asymmetry** — if the ON side accepts a marker the OFF side doesn't reject, a baseline that emitted the auditor's token would still read as "clean" and the fan-out would be falsely attributed to delegation; both sides are therefore driven by one shared `GRADED_MARKERS` list. Plus the delegation-ON vs delegation-OFF contrast over the identical prompt/request. Do NOT assert on tool-call counts, board status, or item counts.
