# delegation › it synthesizes fanned-out worker results

**Issue:** FIX-930 (epic) — verifies the shipped substrate: FIX-918 (delegation via skills-library `agents:` + blocks-as-tools), FIX-927 (board-scoped `taskTools` for mid-drain fan-out), FIX-920/928.
**Outcome:** A coordinator generator, given a team of declared agents, delegates a unit of work to one worker via `addTask` + `runBoard`; that worker fans out follow-up work mid-drain to a second worker; and both workers' results come back and are synthesized into the coordinator's final answer. What a user notices: they get an answer that contains information only the workers held — the coordinator could not have produced it alone.
**Input:** `fixtures/team.json` — a `researcherSecret` token and an `auditSuffix`. Held-out: swap them for any other two distinct strings and a correct implementation still passes. The assertions derive the expected markers from the fixture (`SECRET`, `SECRET+SUFFIX`); nothing is hardcoded.
**Signal:** graded on the **coordinator's terminal output only** (`res.output`, or its own final message — never a worker's client-visible message), with codes extracted as exact hyphen-joined tokens so a standalone token is distinct from a longer one that contains it:
1. **Delegation** — the coordinator's terminal answer contains `researcherSecret` as a **standalone** token (the `researcher` ran and its own result was synthesized — not merely reported as part of the auditor's longer code).
2. **Fan-out** — the terminal answer contains `researcherSecret + auditSuffix` as a token (the `auditor` ran). This marker is unforgeable by anyone but the fanned-out auditor: the coordinator is told to assign exactly ONE task (to `researcher`) and call `runBoard` ONCE, and it never learns the suffix; the auditor only produces `code+suffix` from a code it is HANDED, and only the researcher holds the secret. So `secret+suffix` proves the researcher enqueued the auditor mid-drain and passed it the secret.
3. **A/B baseline** — a second coordinator (same prompt, same user turn, differing ONLY by the team binding) bound to NO team must NOT produce `researcherSecret`.
**Anti-game:** the gameable pass is asserting the mechanism ran — that `addTask`/`runBoard` were called, that the board reached `drained`, that a `task-change` fired. All of those can pass while the workers' outputs never reach the coordinator's answer. Two subtler hollow passes are closed explicitly: (a) inline workers default to **client-visible** messages, so a worker's secret lands in `res.items` whether or not the coordinator synthesized anything — hence grading the coordinator's **terminal output alone**, never the worker messages; (b) because `FANNED = SECRET + SUFFIX`, a naive substring check makes `SECRET` present whenever `FANNED` is — hence requiring a **standalone `SECRET` token distinct from `FANNED`**, so a coordinator that dropped the researcher's own result can't pass. Plus the delegation-ON vs delegation-OFF contrast over the identical prompt/request. Do NOT assert on tool-call counts, board status, or item counts.
**Model:** real — `openai/gpt-5.4-mini`
