# flow-instances › it keeps private data with the copy that wrote it

**Issue:** FIX-1323 (builds on FIX-1321 registry cardinality and FIX-1322 owner continuity)
**Outcome:** An operator runs two copies of one flow definition on one server, for the same user and the same org. What each copy stores privately — its user and org state, a private resource with its content, a member of a private collection — belongs to that copy alone: the other copy cannot see it, cannot overwrite it, and each copy still reads its own after a restart. What the app declared shared stays one record both copies read. An ordinary single-copy flow's data stays exactly where it already was.
**Input:** `fixtures/input.json` — the two copy ids, the singleton's id, the private marker each writes, and the one shared value. Held-out: every id and marker is read from the fixture and graded against what the stores and the HTTP routes return afterwards; swapping any of them must still pass a correct implementation.
**Signal:** against the real HTTP router (`createFlowApiRouter`) over on-disk SQLite stores.
(a) Each copy and the singleton run `POST /api/flows/<id>/<session>/actions/run` to completion, writing their marker into isolated user state, isolated org state, the `notes` resource state and content, and a `files/report` collection member; only East also writes the `flowIsolation: false` `directory` resource.
(b) After closing the stores, reopening the same file and building a fresh host, `GET /api/flows/sessions/<session>/state` shows each copy its OWN marker at user and org scope, `…/resources/notes/content` and `…/resources/files/report/content` return that copy's own content, and all three read East's one `directory` value.
(c) In the store: a user cell at `<userId>:<copy id>` and an org cell at `<orgId>:<copy id>` per copy, each holding that copy's marker; no cell at `<userId>:review` or `<orgId>:review`, the bare kind the old key rule used; and exactly one `directory` row at the bare `<userId>`, at version 1.
(d) `POST` addressed to West against East's session is `409 wrong-instance-session`, and a host that registered only West refuses `GET …/state` for East's session. East's user state, org state, resource states and resource content are byte-identical before and after both refusals.

**Anti-game:** a hollow pass would assert only that the requests completed, or read each copy's data back through the same execution context that wrote it — both hold even when the two copies share one cell and the last writer silently wins. So the check MUST close the stores and build a fresh host before every read, so nothing is served from a live context; MUST read through the public HTTP `/state` and resource-content routes, not the store helpers the write path used; MUST assert the value each copy sees is its own AND that the sibling's marker is absent, since one copy reading correctly proves nothing about the other; MUST assert nothing exists at the bare-kind address, because that is precisely where the old rule filed it; MUST check the shared row's version is 1, so "shared" cannot be satisfied by two copies each writing their own row that happens to hold the same string; and MUST re-read every one of East's cells after each refusal, since a refusal that follows an effect is not a refusal. Grading `flowKind` proves nothing — both copies share it.
**Model:** n/a — handlers only; the property under test is where data is stored, not model output.
**Run:** `pnpm tsx goals/flow-instances/keeps-private-data-with-the-copy/run.mts`

> **What the singleton leg covers.** A `cardinality: "singleton"` flow's instance id is its kind, so its keys are the same strings it wrote before this change. The goal runs one alongside the two copies and asserts its cells land at `<userId>:digest` — the compatibility claim, checked rather than argued. It does not prove anything about a collection deployment whose data predates instance ownership: that history is attributed by the offline cutover in `apps/docs/docs/persistence/overview.md`, and the runtime deliberately refuses to guess it.
