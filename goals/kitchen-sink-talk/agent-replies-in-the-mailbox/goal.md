# kitchen-sink-talk › an agent replies in the mailbox

**Issue:** FIX-1594 (VG of the spec's PLAN; the epic FIX-1592's leg c); re-pointed by FIX-1611; converted by FIX-1792 P1

**Outcome:** A person posts to `support.help`, and the specialist the coordinator's best fit picks, `support.devices`, answers in the person's conversation with `support.help` under its own name. The line is still there after a reload, and wakes nobody.

**Re-pointed (FIX-1611).** The folder name is kept so its verdict history stays in one place. Until FIX-1611 this read `support.otto` answering in `support.desk`, beside a second agent member. The team now has one routed help desk, so the answering seat is the routed specialist and "wakes nobody" covers the three it passed over.

**Converted (FIX-1792 P1).** `support.help` is a coordinator worker file on `routing: best-fit`, no longer a mailbox. The specialist no longer posts its answer with a `post-to-mailbox` tool: its turn's reply is handed back to the coordinator, which draws it in the conversation under the specialist's name. An answer goes no further because the coordinator's `rounds:` is 0, not because of an author filter. The controls follow: `no-author-filter` becomes `answers-go-on`, and `post-without-author` (a server-side tool swap, which has no tool to swap now) becomes `no-author-name`, which takes the writer's name off each line the page is served.

**Input:** `fixtures/input.json`: the coordinator, the specialist a post routes to (`support.devices`), the three delegates it passes over (`support.accounts`, `support.fsd`, `support.general`), the `[route:<worker>]` tag the scripted evaluation reads, the scenario marker the scripted model keys on (`[scenario:reply-in-mailbox]`) and the marker it writes on the specialist's answer (`[reply:in-mailbox]`). Held-out: each run posts two lines, each with a fresh `reply-token-…`, and only those tokens are graded, so a line another run or test left behind can never be the one that passes. The second post, with different text, must pass the same way.

**Signal:** one real browser against kitchen-sink's **production build** (built by the run, never assumed), served by `next start` on the scripted model, the in-memory store and **no model key**. Both posts go in from the coordinator's panel; everything graded is read off the page **after one reload**.

- **line**: for each token, the conversation shows exactly one line carrying the token and `[reply:in-mailbox]`: the specialist's answer, kept in the conversation.
- **author**: that line is labelled `support.devices`, not `devuser`.
- **woken-once**: `support.devices` has one session for the conversation, and in it each token appears in exactly one turn, the person's post (`devuser, through support.help: [route:support.devices] [scenario:reply-in-mailbox] …`). `support.accounts`, `support.fsd` and `support.general` hold no session for the conversation with either token. A second turn carrying the token, or another delegate's session, is the specialist's answer waking a seat.

**Anti-game:** no assertion on the reply's wording past its marker, which the script wrote; none on the routing record, a dispatch handle, a package test or a CLI run. Only this run's tokens count. The page is read after a reload, so only what the conversation and the specialists' sessions kept can pass. Which sessions are a specialist's is read from the server by the session's `workerId`, as an index; what each holds is read off the page. Before the reload the run polls the server until the line and the specialist's answer land, then waits 1.5s for a wrongly woken seat to run; none of that is graded.

**Model:** n/a. kitchen-sink's scripted model scripts best fit's evaluation and answers the specialist (epic FIX-1592 D3). Keyless: the server runs with `AI_GATEWAY_API_KEY` empty.

**Run:** `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers pnpm tsx goals/kitchen-sink-talk/agent-replies-in-the-mailbox/run.mts`

**Controls:** on the same command.

- `GOAL_CONTROL=answers-go-on` (`apps/kitchen-sink/lib/coordinator-control.ts`, honoured only under `KITCHEN_SINK_TEST_MODE=1`): the coordinator read with `rounds: 1`, so each answer goes back out. Best fit has no route tag in the answer to read, so it lands on the fallback, `support.general`, handed the specialist's words, token and all. Must FAIL at **woken-once**, and at nothing else.
- `GOAL_CONTROL=no-author-name`: at the page's `fetch`, every session read, action stream and live session stream reaches the page with each message's `agentName` taken off, before and after the reload alike: what the page sees when the server keeps no writer on a line. The line is drawn under no specialist's name. Must FAIL at **author**, and at nothing else.
