# manager-queue-lab › it stands the team and its board up from files

**Issue:** FIX-1430 (the contract gate). Rewritten by FIX-1792 P2: the mailbox is removed, the manager files on its own conversation's board, and its delegates give it the task tools.

**Outcome:** Somebody writes a small tree of Markdown — a manager whose `WORKER.md` names three builders in `delegates:`, and the three builders — and points one call at it. No file declares a board and no file grants a tool: the manager's conversation has a board of its own, its turn holds orchestration's task tools because its delegates take tasks, the board refuses a filing for a worker the manager can't hand a task to, and the manager can say what is queued, running, waiting on a person and done without that reading changing anything.

**Input:** `lab/workforce/` — one team `eng`, a manager on `flow: coordinator` with `delegates:` naming the three builders and `tools: []`, and three builders on the lab's `builder` flow. Held out: the worker ids, the manager's delegates and which flow each worker runs on come off the tree at run time.

**The manager's flow, a call recorded here.** `flow: coordinator` is unchanged in the manager's file; the lab now registers Workforce's coordinator flow under it, and its own `flows/workers/coordinator.mts` is gone (see the lab README: since FIX-1791 the name is the framework's, and a lab flow under it would make this the one tree where it means something else).

**Signal:** seven legs, model-free, over a real `createFlowState` host acted on through its HTTP router as the lab's verified user, with rows read from the store. Every model call the manager's turn makes is answered by a quiet stub that files nothing, except leg (c)'s twin, whose stub calls `createTask` once for a builder that takes no task, to show the call files nothing.

(0) **No file declares a board or grants the task tools.** No `MAILBOX.md` under the tree, and no frontmatter key `boards:`, `boardActions:`, `filing:`, `mailboxes:` or `members:`. Its red state was produced once by hand, not as a control (it edits the tree): a `MAILBOX.md` with `boards: [work]` put back under `teams/eng/mailboxes/queue/` failed leg 0, twice (the file and its key), and nothing else.

(a) **The tree alone hires four workers on the flows their files name.** Its own red arm: one worker's `flow:` rewritten before the hire to a flow nobody registered refuses the whole roster, naming the worker.

(c) **The manager's turn holds the task tools because its delegates take tasks**, read off live turns: with its file's `tools: []`, the turn is handed each of orchestration's task tools (the filer's four since FIX-2081; `answerTask`, added by FIX-1817, left with FIX-2131) once and no catalog tool; with its `tools:` rewritten to `["note"]`, the same four plus `note`; with builders whose `work` entry takes no conversation's task, the same four, since a turn that works steps for itself holds them whoever its delegates are (FIX-2076 D1; no post form is left, FIX-2083). That turn's own `createTask` for a builder answers `unknown_assignee`, naming it as taking no task; the public filing answers `no_delegation_board`; neither stores a row. That last arm is this leg's red state: it fails when the twin's task tools differ from the manager's, and when its `createTask` files a task.

(d) **The board's filing check, both arms.** A filing for `eng.nobody` answers `unknown_assignee`, naming it, and stores nothing; a filing with no assignee, with three delegates, lands `held` and unassigned (`pending` with the not-dispatched mark before FIX-2080); neither runs.

(e) **The queue is a read.** The manager's `listTasks_tasks` leaves the stored rows byte-identical; every stored row lands in exactly one of the lab's four columns; a task its worker is running (its turn held by the host) reads running, a finished task done, and the unassigned held row reads *waiting on you*, never queued: nothing but a person's release starts it. (Before FIX-2080 a separate `blockTask` row carried this leg's *waiting on you*, with its reason; `held` replaced both it and the not-dispatched mark.)

(f) **The manager cancelling a task its worker is running is allowed**: `updateTask_tasks` with `status: cancelled` answers `ok`, the row reads `cancelled` with no output, and the worker's late result is declined. No action settles a task (FIX-2081).

(g) **The task status set has exactly the members it had**, asserted against a written-out list.

**Retired, each with its reason.**

- **(b) a worker folder that declares the board refuses the roster**, with its two refusal trees: no file declares a board, so the leg has no subject (FIX-1792 D1).
- **(h) this issue's diff stays inside `goals/manager-queue-lab/`**, with `lab/diff-check.mts`: it graded FIX-1430's own change set. FIX-1792 converts many goals and packages in one branch, so the fence never described its diff.
- **(i) the drain-width switch runs work at either width**, with `MANAGER_QUEUE_DRAIN_WIDTH`: a conversation board has no drain and no width; each row is handed over at once to a session of its own (see the lab README).
- **Old (e)'s worker-busy strip and lapsed-lease arm, and old (f)'s recovery by the next drain**: both rested on a drain session and a claim taken by hand and left to lapse. On a conversation board the board's own run claims each row at hand-over and no worker drains, so neither has a subject.
- **Old (d), the mailbox's author check**: no mailbox. The board's own check on who a row is for is leg (d) now.
- **The `catalog-door` control**: it moved the door the task tools arrived through, which was the lab's own composition. The lab composes nothing now; the coordinator flow carries the tools, and FIX-1802's tests own that wiring. Leg (c)'s red state is its own twin arm.
- **The `repointed-map` control**: its leg here was old (f)'s identity of a recovered row, retired above. Routing identity is graded by the sibling check's leg (c), where the same control lives.

**Anti-game:** the check MUST read the tool sets off **live turns** of the shipped coordinator flow, not off a resolver called with a context it assembled; MUST read rows from the **store**, before and after a read, rather than trusting that a view writes nothing; MUST stage the running row with a **real held turn**, not a written row; and MUST assert the refusals on the code and the name they carry (`unknown_assignee` naming the worker, `no_delegation_board`, the refused worker's id).

**Model:** n/a — model-free on purpose.

**Run:** `cd goals && pnpm exec tsx manager-queue-lab/it-stands-the-team-and-its-board-up-from-files/run.mts`

**Controls:** none. Each leg that can go red carries its own red arm (a's unregistered flow, c's twin, d's stranger), and the two old controls are retired above.
