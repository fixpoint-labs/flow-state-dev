# shift-manager › a lab is worked through one skinned shell

**Issue:** FIX-1663 (the closure of FIX-1649)

**Outcome:** On one `main` commit with every child merged, a person works the DevForce Lab through Shift Manager in a real browser. They answer an ask from Inbox, follow the task it started to its session and trace, reach every surface the shell promises, and talk to the coder seat while its task runs. The pentest Lab opens in the same shell from its README alone, with no shell code of its own, under the org its store names. With no Shift Manager theme loaded, no reused FSD component carries a Shift Manager value, in light or dark. Someone reusing FSD UI in their own app and a sibling epic's owner each get what the epic promised them, and every child's own check passes on the same commit.

**Input:** `packages/shift-manager/teams/devteam/`, opened as Shift Manager's DevTeam profile on the real harness (`DEVFORCE_LAB_HARNESS=claude-code`) for leg a, and on the lab's scripted harness for leg c. `goals/pentest-lab/lab/` through its committed `fsdev.config.mts` for leg b, a tree Shift Manager was never tested against. Kitchen-sink's tree stands in for neither. Every worker and team name is read from the trees at run time.

**Signal:** each failure is tagged with its leg or part.

- **a1, the Inbox journey.** The EM's ask is in Inbox with its kind, and its detail pane draws its card. Approve leaves the resume stored and the ask gone from Inbox.
- **a2, the task journey.** From Tasks: the task's Session tab draws only items the run session holds, the inspector's trace link is the in-process devtool's `?session=<id>`, and following it opens that session.
- **a3, reach.** Chief of Staff, the org switcher, Jump to (a worker by the name the screens show it under, so `chief-of-staff` as Shift Coordinator; a task; a declared document), Inbox against the store's asks, Tasks in its three groupings, Roster for all teams and for each team row in TEAMS, the theme mark that replaced the Day/Night switch (36bed1297 / #2825: clicked, it reaches night and day and the page takes each), each project's four tabs (a project's Stream is the person's project coordinator conversation, its Board the person's own workstream sessions or a named empty state, its Workstreams its progress, its Brief the row's brief or a named empty state), and the task frame's four tabs and panel slot. Every empty one names what will be there.
- **a4, the person's turn into a running task** (the one step on the real model). While the coder's task runs, a line through the task's own composer is in the running task session as a person's turn before the composer reads delivered, and the next attempt answers in that session. Never retried.
- **b0, the pentest config from the README.** An isolated writer that sees only Shift Manager's README and the pentest tree (minus its config) writes a config to scratch. Every step it had to guess is a failure, as is a reply that declares nothing (it must say `GUESSED: none` when it guessed nothing), and so is a semantic difference from the committed config (flows, org, workers, the page's user and bearer), booted side by side.

**Anti-game:** a hollow pass would be a shell that draws its own rows, a no-theme build that removed more than the theme, or a control that never reaches the code it names. So no assertion reads Shift Manager's own state or a child's output: rows are compared by id with the store, read through the Lab's HTTP routes with the bearer the page was handed. Every scratch patch is printed in full. Each control must fail at its own signal and leave the rest green, or the run says WRONG.

**Model:** leg a's harness is Claude Code; only a4's answer rests on it. It needs a Claude Code account, which the Lab checks before it listens: a sign-in, `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`. `AI_GATEWAY_API_KEY` is the model key for the Lab's other workers and never reaches Claude Code, so it is not enough. With no account the run asks the Lab's own check first and reads leg a BLOCKED, naming what to set, instead of failing at setup. b0's writer is the `claude` CLI. Legs b and c and both journeys are model-free.

**Run:** `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers pnpm tsx goals/shift-manager/a-lab-is-worked-through-one-skinned-shell/run.mts`. `GOAL_PART=a,b0,b,c,d,controls,part2,part3,part4` (the default) picks the parts. For a rerun, `GOAL_CONTROLS` picks the controls, `GOAL_CONTROL_LEGS` the legs a control runs, and `GOAL_CHILDREN` (a regex on the label) part 3's entries. A narrowed control is graded only on the signals of the legs it ran. An unknown part or control name, or a run that reaches no verdict, fails.

**Controls:** each runs legs a, b and c on its own build or server start. When leg a is BLOCKED, each control runs b and c and is graded on their signals alone; a control whose signals all sit on leg a (optimistic-post, worker-session) reads BLOCKED. BLOCKED is never a pass. Leg d's controls are the look check's own, run inside leg d. Every server start that opens DevTeam gets a fresh store in its own scratch directory, never the checkout's `packages/shift-manager/.fsdev/devteam.sqlite`.
