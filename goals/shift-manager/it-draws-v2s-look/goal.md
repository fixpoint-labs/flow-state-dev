# shift-manager › it draws v2's look

**Issue:** FIX-1737 (epic FIX-1649)

**Outcome:** Every screen of Shift Manager is drawn in design v2's look, in the day and night shifts, at a wide and a narrow window. That covers both typefaces loaded, mono on meta text, the title scale, v2's surfaces, square corners, the state squares, the tabs' underline, the highlighter only where something waits on a person, and the frame's widths. Each drawable value equals the Lab's store. The moment a screen drifts from v2, the check names the element, the screen state and the v2 line it broke.

**Input:** Shift Manager as checked out, copied to scratch and built with Vite. Two keyless Labs serve it, each through Shift Manager's own command:
- **DevTeam** (`packages/shift-manager/teams/devteam`). Before the sweep, the check opens a `feature` workstream led by the EM in the first shared project, through the projects flow's `openWorkstream` as the app opens one, and files one feature (`fixtures/input.json`) on its session's board through the EM's `file` door. The board hands it to the coder at once, so one row is running and one ask is pending, as the audit rendered it.
- **This check's desk Lab** (`lab/`). One `shift-coordinator` seat whose model is `@flow-state-dev/testing`'s mock resolver with one scripted reply, beside `front`, a worker on Workforce's `coordinator` flow whose one delegate it is. The desk declares no mailbox, so it has no workstream, and nothing files a task, so it has no board rows. One line is sent through its door before the sweep.

The look table is read against v2 itself (`specs/epics/FIX-1649/assets/design/v2/shift-manager-v2.dc.html`).

**Signal:** Chromium walks every screen by clicking: task, Tasks, Shift Coordinator, Inbox, Roster and project on DevTeam (the project the workstream is open in, on its Board, which draws a lane for each workstream session the person opened there, holding that session's tasks), and Shift Coordinator, Inbox, Tasks and Roster on the desk, where Inbox is empty. It picks the day and night themes with the sidebar's theme mark, and toggles the window width (1600 and 1100), in place. On the desk it then reopens Shift Coordinator, sends a second line and holds its delivery check, so Shift Coordinator is graded working too (the sidebar's dot, the sub line and the thinking line, each required), in both shifts at 1600. It reads the computed style of every visible element in one `page.evaluate` per screen state. Each failure is tagged `<leg> [<screen> <shift> <width>]` and cites the v2 line.

- **type**: for every family and weight the page's text is set in, `document.fonts` holds a loaded face. Each row's family, size, weight, tracking and line height match.
- **surface**: each row's surface token and border. Radius 0 on every element, except the registry parts the theme's radius can't reach.
- **marks**: the highlighter sits on every needs-you element and nothing else. Also graded: v2's state squares (fill and edge), the selected tab's 2px info underline, with none on the others, and text v2 paints blue.
- **layout**: the sidebar is 248px and the rail 340px. The rail drops below 1180px, and the frame holds a 900px minimum. Shift Coordinator's column is 720px in v2's padding.
- **content**: the stream composer's @-mentions are the store's running members. The Board tab's count is the store's rows. The Stream's feed names one author per stored line and pending member ask, and marks each such ask NEEDS YOU. The Board's columns stand in v2's order. The sidebar's Inbox count is the store's pending asks, highlighted exactly when there is one, and each workstream's dot is the store's (needs you, else running, else none). Shift Coordinator's sub line counts the store's workers. It offers no suggestions, since its one (who is on call) went with On Call. Inbox's sub-line, filter counts, selected title (the ask's message), *From the session* calls and reply lines, and its empty sentence equal the store's asks, rows, seats and session items. Tasks' summary, Queued count, column order, shown ids (the rows in flight) and TIME (within the sweep's clock) equal the store's rows. Roster's columns and group sub-lines are v2's, every WAITING entry matches a stored parked row (its id and title) or pending ask (its kind and message), and the waiting tasks are exactly the store's parked rows. The empty Inbox counts running sessions, so rows that share one run session count once.
- **totality**: every painting element inside a graded region (the sidebar, the tabs, the composers, the screen titles, Shift Coordinator's centre, slice C's workstream, Board, task, team strip and project Board regions, and slice D's Inbox list and detail, Tasks' header and table, Roster's columns, groups and waits) is covered by a look-table row or a named exception. Every row matches at least its expected number of elements, so a missing element fails as surely as an extra one.

Which regions are graded whole grows with each slice's screens: Shift Coordinator's centre joined with slice B (`rows/sidebar-and-shift-coordinator.mts`), and the workstream's header, feed and Board, the task's activity line, an ask in its session and the inspector's needs banner, and the project's team strip and Board lanes with slice C (`look-c.mts`), and Inbox's list and detail, Tasks' header and table, and Roster's columns, groups and waits with slice D (`screens-inbox-tasks-roster.mts`). Each slice's rows, exceptions and regions live in a file of their own, spread into `run.mts`'s table. The fonts, the radius and the highlighter are graded on every element of every screen now.

Retired under BR-24: the workstream screen (its Stream) and its Board tab on DevTeam, with **content**'s composer @-mentions, Board count and feed lines, and slice C's workstream header, feed and five-column Board rows there. Neither Lab declares a mailbox now, so neither draws a mailbox workstream to open. The rows stay in the table for a Lab that serves one. FIX-1792 P4 removed the mailbox from Workforce and Shift Manager's mailbox workstream level, and the sub line with it now reads `watching <n> workers`: **content** grades that count against the store's workers. The proving legs: **content** still grades Shift Coordinator's watching line against the store's workers; and the project's Board lane now holds the running row, graded by its state square (`project lane running square`, citing the shipped `TasksPanel.tsx`), with the task's text listed as an exception like the board card.

**Anti-game:**
- Computed values are graded, never class names. A border is compared at the whole pixel Chromium computes, so v2's 1.5px box reads as 1px.
- Each row cites a v2 line, and setup fails if that line no longer holds the row's declaration. v2 sets no radius anywhere; setup fails if it ever does.
- No row exists that v2 doesn't draw, except the sidebar header's and the project Board's lanes. The header's theme mark, the app's name and the theme name are the shipped design that replaced v2's shift switch (36bed1297 / #2825). A project's Board shipped as a lane per workstream session the person opened, each holding that session's tasks as a list (b2f2d4c2), in place of v2's grid of every workstream across the five columns; v2's columns are graded on a workstream's Board tab. The goal follows both: their rows cite the shipped source line instead of v2's, and setup fails if the line no longer holds the row's declaration. Elements v2 doesn't draw are otherwise listed as exceptions, each with a reason.
- **content** is read with this check's own requests to the Lab's routes, never from Shift Manager's state.
- No registry copy is edited, and no behaviour check is weakened.
