# shift-manager › it shows and stops a task run

**Issue:** FIX-1664. Converted onto the lead's own conversation board by FIX-1792 P3: the run-lab's mailbox and its org-scoped board are gone.

**Outcome:** A person opens one task in Shift Manager and watches that task's own run live, can stop it, and sees every other act and value the task screen draws either working from a shipped read or saying what arrives and who ships it, or that it is not planned in the first cut. From the task itself, with no model turn, they release a held task, cancel a running one, retry it, and see a failed task's error (FIX-2382).

**Input:** the run-lab (`packages/shift-manager/test/fixtures/run-lab/`), served by Shift Manager's command, with the devtool it serves beside it. Its tree (its `workforce/`) is one team: a coordinator, a lead whose `WORKER.md` names three delegates (which gives its conversation the task tools), and those three, two on one shared flow and one on a flow of its own, each taking tasks through Workforce's task entry. At boot the Lab files its tasks on the lead's own conversation's board through `createTask_tasks`, and each runs at once in a task session of its own on its worker's flow. Each run is a scripted stub, no model: it opens with a reasoning item and one tool call with its result, as a coding harness does, then narrates a step a second and runs until aborted. The second worker on the shared flow gets two short tasks that finish; the rows are read once both have, so a short run still running is never taken for a running one, and a board that doesn't settle within 30 s fails **store**. One task depends on a running one, so nothing claims it. Served with `RUN_LAB_TASK_ACTIONS=1`, the Lab also files three rows for the task's action row: one filed held on the board (`createTask({ held: true })`), one more running task to cancel, and one with one try whose run throws, so its row reads `errored` with that error. The goal tells them apart by their goals, so no other leg picks one. Every worker and flow name is read from the tree at run time, and the board is found as the lead's one conversation.

**Signal:** each failure tagged `[<row>] <leg>`, over seven rows: the running task on the shared flow, the running task on a worker's flow of its own, a finished run, the unclaimed row, and the action rows `held`, `cancelled` and `failed`. A running task is *running* here, never *held*, which is the board's word for a row that waits to be released. Each is reached by clicking, from Tasks or, once done, from Jump to, opened with ⌘K as the sidebar footer's tip says (a conversation's board has no workstream Board tab to click a card on), never by a typed URL.

- **store** (precondition): the lead's conversation board, read through the conversation and kept to its own rows, holds those seven rows, the action rows `held`, running and `errored`.
- **items equal the run session's**: the Session's items equal, by id and in order, the task's items in the run session's stored state plus its request's stream, read through the flow the session records as its owner and filtered by core's `itemsForTask`. The store is read before and after the screen, so the screen must hold everything the first read held and nothing the second doesn't.
- **live**: the next item the request stores for the task is drawn within 2 s, with no reload.
- **the request reads aborted first**: after Interrupt, once the view reads `aborted`, the request record read through its own flow already reads `aborted`, and the view's word is *interrupted*. The row's run link is unchanged afterwards.
- **inspector**: the worker equals the tree's delegate the row is assigned to. The start time equals the row's. The plan steps equal the plan the run's request points to (a harness keeps its plan under its conversation and leaves a pointer under the request; core's `readPlanTarget` follows it), and the file paths equal what the run recorded under its request id, or the inspector says the harness records none. The trace link is the address of the devtool Shift Manager serves with `?session=` the run's session, and the session id is shown beside it. Clicking it opens a page where the devtool has the run's session open.
- **gaps**: Hand off, reassign, Open PR and *also post* are disabled. The composer takes a message on a running task and on the finished one, since every worker flow has a door (FIX-1789) and a message picks a finished task up again (FIX-1764). Each of the others, the Diff and Checks tabs, the Brief's missing fields and acceptance, and the inspector's harness, acceptance and reviewer lines carry a gap line that names its owner or says *not planned in the first cut*.
- **no run**: the unclaimed row says no run has started, and Interrupt is disabled.
- **release** (`held`): Release in the task frame's action row. The board's row leaves `held` for `pending` within 10 s, or `in_progress` once the board has handed it on.
- **cancel** (`cancelled`): Cancel, confirmed once, on a running task. The row reads `cancelled` within 10 s; the run's request, read through its own flow, leaves `in_progress` within the lease's renewal bound (a third of the lease, plus 15 s: the stub isn't harness-manager's, so it stops when its next renewal is refused); and the row still reads `cancelled` after, never `errored`.
- **retry** (`cancelled`, then `failed`): Retry on the cancelled row, and on the failed one. The board counts one more try on the same row within 10 s, and no row is added.
- **error** (`failed`): the error the board stores on the row is in the task frame's error banner and on its Tasks row's error line.
- **reach**: each row opens by clicking, and the page throws nothing. A row that doesn't open fails here, naming the rows Tasks drew and the row's status in the store now, and its other legs are skipped.

**Anti-game:** a hollow pass would be a Session showing some other session's items, a view that draws *interrupted* on its own word, a screen that reads every run through the board's flow, or an action button that only looks pressed. So the check never reads Shift Manager's state. Its oracles are the tree on disk and the store, read by this script through the Lab's routes and through each run's own flow. Items are compared by id, never as text on the page. Each action is graded on the board's row and the run's request record; the only page text an action leg reads is the board's own refusal, quoted in a failure. No run is on the board's flow (the lead's), so a screen that assumes the board's flow can't pass any row.

**Model:** n/a (the scripted run stub).

**Run:** `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers pnpm tsx goals/shift-manager/it-shows-and-stops-a-task-run/run.mts`

**Controls:** each rebuilds Shift Manager with one module swapped for a module under `controls/` (`src/lib/run.ts` unless it says otherwise). The build fails if the swap never fired.

- `GOAL_CONTROL=worker-session`: the Session reads the newest other session on the run's flow, or on any flow when the run's flow has no other, and follows no stream. Must fail at **items equal the run session's**.
- `GOAL_CONTROL=optimistic-interrupt`: Interrupt draws *interrupted* without calling abort. Must fail at **the request reads aborted first**.
- `GOAL_CONTROL=board-flow`: every run is opened through the board's flow (the lead's), not the flow its session names. Must fail at **items equal the run session's** on every run row, since no run is on the lead's flow.
- `GOAL_CONTROL=wrong-board` (swaps `src/lib/reads.ts`): the frame's action row is built against board id `"plan"`, not `"tasks"`. Must fail at **release**, **cancel** and both **retry** legs, each row unchanged, with the refusal on the page.
- `GOAL_CONTROL=no-error-body` (swaps the `error` registry copy): `ErrorBody` draws nothing. Must fail at **error**, on the frame and on the Tasks row. The action row has no part in drawing an error, so `wrong-board` can't redden that leg.

**What changed in the conversion, and why.** A conversation's board opens one task session per task, so the per-worker seat's shared session has no subject: its two short tasks now finish in two sessions, and the finished row is graded the same way (BR-24; `packages/shift-manager/test/run.test.ts` holds that each task's session holds only its own items). Only the conversation that filed a task runs it, and it runs at once, so the row "filed after the only drain" became a task that depends on a held one. The board is no longer an org row a mailbox session reads: it is the lead conversation's partition of the person's conversation ledger, so the store is read through that conversation and filtered to its partition, and items are attributed by the ledger's collection (`tasks`). A finished task is no longer on a workstream's Board tab, so it is reached from Jump to. `board-flow` used to pass the rows on the drainer's flow, since the drainer ran them; the lead runs none, so it now fails every run row.

**Before-state:** `GOAL_PAGES=<dir>` serves pages built elsewhere instead of building. Pages built from FIX-1662's shell, which had only the placeholder task frame, fail every leg on every row.
