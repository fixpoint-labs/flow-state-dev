# shift-manager › workers talk together

**Issue:** FIX-2242, the closure of epic FIX-2070 (`specs/issues/FIX-2242/SPEC.md` → "The goal, and how we'll know it's met"; the plan in `DECISIONS.md` → "The plan in full").

**Outcome:** on one `main` commit with every other child merged, in Shift Manager on a real model and a durable host, a worker calls another and uses the answer in the request that asked, across a crash between the log write and the dispatch; a message to a task lands in that task's session; a task's midway question reaches its filer while the filer waits on a call; every message lands once; a ring stops inside one typed message's budget; and none of the removed names is in source. Each child's own check walks its leg on a calm host; this one walks the legs together, so they collide (D1).

**Input:**

- Shift Manager's DevTeam install as the commit ships it, served by Shift Manager's own command over a SQLite store file (`DEVTEAM_STORE`), killed and restarted on the same file. Alice is its owner; the clients are the shipped ones, loaded from the commit under test.
- The cast and world are `workers-message-each-other`'s (`legs.mts` → `hireTeam`, `openConversations`): Researcher (a standard agent worker), Helper A (with Helper B as its delegate), Helper B and the herald. This goal hires two more, `ring-one` and `ring-two`, each told to pass every message it hears on to the other.
- Leg c's crash is FIX-2240's `exit-after-row` fault (`workers-message-each-other/faults.mts`), through `goals/lib/module-patch.mjs`, firing only on Helper A's messages (its sender parameter).
- Held out, picked at run time: the codename, the launch topic and city, the ring's word, and the task's fact.

**Signal:** each failure is tagged `<leg>:<assertion>`; the run prints every assertion it reached beside its verdict, and which team's *after* each leg walks.

- **Scene ac** (a with c): Alice tells Researcher a codename. The server is restarted with the fault, and Alice asks Helper A to get the codename from Researcher with a call (`wait: true`). The server kills itself after the call's row is written, before its dispatch, and is restarted without the fault. `c:lands-once` within 120 s Researcher's conversation holds exactly one received item for the call's id, and the row is `delivered`, `deliveredAs` naming a request whose dispatch stamp is Helper A's pass (`worker-message-resend` from Helper A's conversation). `a:answer-in-request` Helper A's request that made the call, replayed by the durable host, completes: its call reads `answered` with the codename, its last line to Alice holds the codename, and no other line from Alice ran in that conversation after it. A killed request the host never replays is a finding, not a pass by waiting again. `a:one-place` the log holds one row from Helper A to Researcher since the line, the call's, at hop 1. `a:no-relay` Researcher's turn on the call sends no message, and Helper A's conversation gains no received item from Researcher.
- **Scene ed** (e with d): Researcher's turn stops for Alice (`suspendForUser`). In one line Alice has Helper A file Helper B a task whose brief needs the launch city, which only Helper A is told, then call Researcher with `deadline: 150000`. Once Helper A's request reads as parked, Alice starts the ring on its own line (`ring-one`, told to message `ring-two`) and asks the herald to say hello to every worker. `e:filer-hears` Helper B's task asks midway, and Helper A's conversation (the filing session) holds exactly one received item from Helper B naming the task and the question, heard on `onMessageReceived`. `e:heard-while-calling` that item is stored before the parked call resolved: before Helper A's request went on, and before the call's `deadlineAt`. `e:steer-releases` the task's steer answering that question is from its filer, and the task ends `completed` on attempt 1. `e:kept-once` the call answers `running` with `recipient: "waiting_on_person"` at its deadline; after Alice approves Researcher's stop, Helper A, told only to get the answer, waits again by call id and gets `answered` with 42, writing no new row: the log holds one row from Helper A to Researcher since the line. `d:per-request` the herald's turn sends 3 and the fourth is refused `per_request_limit`. `d:seventh-refused` the ring's exchange holds exactly 6 sent messages and a seventh send is refused `budget`, and the ring started while leg e's call was parked (after the call's row, before Helper A's request went on).
- **Scene b**: Helper A's conversation files Helper B a task through the board's own action; the herald messages it with `{ task }` as soon as its session exists, and again once it finished. `b:in-task-session` the first lands in the task's session and its turn runs after the task's turn ended; the second is answered there from the task's history (the fact only its goal held). `b:task-unchanged` the row's status, attempts, output and session read the same after the second message as when the task finished, on attempt 1.
- **sweep** (D2): `sweep:no-old-path` none of the vocabulary sweep's `message-names` and `message-reply-to` rows (`goals/vocabulary/one-word-per-thing/rules.mjs`) has a hit in the served tree's packages, apps and architecture pages, tests included, each at its row's own scope; the vocabulary sweep's `--control` still reports every plant.
- **j1** (*uses Shift Manager*, in a browser as Alice after the walk; it grades the screen only, so a j1 failure with the scenes green is a drawing bug): `j1:own-item` Researcher's conversation draws the crashed call once, from Helper A, with a mark saying it is a call; Helper A's conversation draws the call's tool line answered, and no received item from Researcher. `j1:states` the Messages view lists the crashed call once, `delivered`; the parked call once, reading answered; and the ring's six, delivered. `j1:opens-side` the crashed call's recipient link opens Researcher's conversation, and its sender link Helper A's.

  Where this differs from the spec's plan, and why: the spec has the Messages view list the ring's seventh `refused`. A budget refusal writes no row (FIX-2238: a refused send spends nothing, which `3:refused-pays-nothing` grades), so there is no seventh to list; `j1:states` grades the six instead, and `d:seventh-refused` reads the refusal from the sending turn's tool output.

**Anti-game:** nothing is seeded: every change goes through an action or a line from Alice. Sessions' stored items, the message log (through Alice's roster session) and the board's own task read are read as Alice. Sent messages are counted from each turn's own tool outputs. A fault that never fired, a stop that never opened, or a task that never asked midway is a setup failure, not a grade, and a control's red counts only when it is on its named assertion and not a setup failure. A structural miss on any attempt is a finding (FIX-2087 D1); only a judgment miss, what the model chose to write, earns another attempt.

**Model:** real. Researcher, the helpers, the herald and the ring on `openai/gpt-5.4-mini` (Researcher's file; each hire names it), the Shift Coordinator on `anthropic/claude-haiku-5-5` (its file). Both through `AI_GATEWAY_API_KEY`; without one the run is blocked and says so.

**Run:** `pnpm tsx goals/shift-manager/workers-talk-together/run.mts` (`unset FSDEV_DEFAULT_MODEL` first). `GOAL_SCENES=ac,ed` runs some scenes, in the order ac, ed, b, sweep, j1; `GOAL_COMMIT=<sha>` serves another commit from its own tree and install; `GOAL_KEEP_STORE=1` keeps the store. On demand only, never a CI gate; the sweep's CI half is the vocabulary sweep's two rows.

**Controls:** each is a scratch patch applied as the process under test loads it, printed in full by the run and refused when it never reached its code. A control runs the scenes it needs.

- `GOAL_CONTROL=no-debt` (FIX-2240's): the send owes no wake, so nothing sends the crashed call again. Scene ac must fail **`c:lands-once`**.
- `GOAL_CONTROL=send-again` (FIX-2239's): waiting again sends the call again, as a new call. Scene ed must fail **`e:kept-once`**.
- `GOAL_CONTROL=task-to-conversation` (FIX-2160's): a `{ task }` message lands in the conversation that filed the task. Scene b must fail **`b:in-task-session`**.
- `GOAL_CONTROL=no-question-message` (FIX-2241's): a board tells no filer its task's question. Scene ed must fail **`e:filer-hears`**.
- `GOAL_CONTROL=no-hop-cap` (FIX-2238's): an exchange has no budget. Scene ed must fail **`d:seventh-refused`**.
- `GOAL_CONTROL=call-holds-session` (new): a call holds its turn in-process until its deadline instead of parking on the wait gate (`messages/call.ts`), so its session keeps its place and the question waits for the call to end. Scene ed must fail **`e:heard-while-calling`**.
- **Before-state:** `GOAL_COMMIT=e2c190e64`, `main` before FIX-2238: legs a, b, c and e must fail, and the sweep. Leg d can pass there, since FIX-1989's hop limit already stopped a ring at 6.
