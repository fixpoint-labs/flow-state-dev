# task-board › it hands a row to a worker in its own session

**Issue:** FIX-1302
**Outcome:** A board seat that holds a `dispatcher({ type: "task" })` stops running its rows inline. Each claimed row is handed to the worker the flow declares under `task.actions`, that worker runs in a child session of its own, and the durable row comes back settled carrying what the worker produced. What a user notices: the drain returns promptly instead of blocking on the work, and the finished result is still on the board afterwards.
**Input:** `fixtures/input.json` — the seat name, the entry name, the task ids and goals, and a `salt` every worker echoes into its output. Held-out: swap any of them and a correct implementation still passes; every assertion reads the fixture and none reads a literal. The seat and the entry are deliberately different strings, and the check refuses a fixture that spells them the same — a board that addressed the entry by its seat name would pass an input where the two coincide.
**Signal:** One `runAction` over a real `createFlowState` runtime — not a stubbed `dispatchOperation` — followed by `dispose()`, which is the shutdown drain that waits for dispatched children. Passes when: the drain request reaches `completed`; every ledger row reaches `completed` with an output carrying the held-out salt; every row names a session that is not the drain's; each row's worker ran exactly once; and the drain's session has one child per row at coordinate `task:<entry>`.
**Anti-game:** Four hollow passes are closed. (1) **A board that settled rows without running anything** — status alone is not asserted; each row's output must carry the fixture salt. (2) **A seat that ran the worker inline** — the loud one, and the reason this goal exists. The rows settle identically either way, so the check asserts the session each row ran in differs from the drain's, and that the drain has children at the entry's coordinate. (3) **A redispatch loop** — settling is not enough, so a real counter in the worker asserts exactly one run per row; a board that handed the same row off repeatedly settles it and fails here. (4) **A stubbed seam** — the check must not supply its own `dispatchOperation`; the runtime installs the real one, so the host accepting the dispatch and minting the child is part of what passes.
**Model:** n/a — model-free. The outcome is a row moving through the real dispatch seam into a real child session; a worker that called a model would add spend and flakiness without adding discrimination.
**Run:** `pnpm tsx goals/task-board/hands-a-row-to-a-worker-in-its-own-session/run.mts`

> Why this goal exists: the six hand-off scenarios in `packages/integration-tests` all supply their own `dispatchOperation` and replay the captured envelope by hand. That is the right shape for asserting claim, gate and lease behaviour, and it cannot prove the real host accepts the dispatch, derives the child session, and runs the entry — the one thing the protocol is for.

> **Discriminates against the inline shape**, and is checked: swapping the dispatcher seat for the worker block itself (and dropping the `task` entries the flow then must not declare) still settles both rows with the held-out salt, and fails on `handedOff`, on both rows running in the drain's session, and on the absent children.
