# user-scope › it keeps a user's data in the org it was saved in

**Issue:** FIX-1790 (epic FIX-1786)
**Outcome:** A user who works in two organizations sees, in each, only what they saved there, on an ordinary app flow with no pin and no hired worker. Alice saves her user state, a shared user-scoped resource and a flow-isolated one while working in Acme. Her next run in Acme reads all three back. The same flow, for Alice in Globex or for Bob in Acme, reads none of them, by a run, the `/state` route or the resource routes.
**Input:** `fixtures/input.json` — two users, two orgs and three markers; `fixtures/notes-app.ts` — the app flow, which trusts two headers as the verified principal the way a host's resolver would. Held-out: every id and marker is read from the fixture. Ids carrying `:` are in the default fixture; a run with other users, orgs (uppercase, `.`, `/`, a space) and markers must pass too.
**Signal:** against the real HTTP router (`createFlowApiRouter`) over on-disk SQLite stores, the store closed and reopened between the save and every read.
(a) Alice in Acme opens a fresh session and runs `read`: the run records her user state marker and both resource markers (`a:run-state`, `a:run-shared`, `a:run-isolated`), `GET …/state` shows the user state marker (`a:state-route`), and `GET …/resources/notes` and `…/resources/scratch` list the shared and the flow-isolated markers (`a:shared-route`, `a:isolated-route`).
(b) Alice in Globex, then Bob in Acme, each run `read` in a fresh session: none of the three markers appears in what the run recorded, in `/state`, or in either resource route (`b:globex-shared`, `b:globex-state`, `b:globex-isolated`, `b:bob-shared`, `b:bob-state`, `b:bob-isolated`), and the run did record something (`b:<who>-ran`).
**Anti-game:** a hollow pass would assert on key strings (proving the derivation, not what a caller sees), on a hired worker (whose cell already had the org), or on a fixture that writes the new cell directly. So the check MUST NOT assert on any storage key; it MUST write only through the action route and read only through a run and the public routes; it MUST read leg b with the same user in another org, not only another user, since another user was always separate; it MUST cover user state AND a flow-isolated resource, not just a shared one; and it MUST reopen the store before reading, so nothing is served from the context that wrote it. A leg-b read that never ran would see nothing and pass, so `b:<who>-ran` requires the run's own record.
**Model:** n/a — handlers only; the property under test is where data is stored.
**Run:** `pnpm tsx goals/user-scope/keeps-a-users-data-in-the-org-it-was-saved-in/run.mts`
**Controls:** `GOAL_CONTROL=cross-org-key` on the same command drops the org from every user key at the store boundary (the key derivation without the org). It must FAIL leg b on `b:globex-shared` (Globex reads Alice's shared marker); `b:globex-state` and `b:globex-isolated` fail with it. Leg a and `b:bob-*` stay green, because another user was never in Alice's cell.
