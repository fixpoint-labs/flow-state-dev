# webhook-routing › it judges each event once

**Issue:** FIX-2537 (epic FIX-2471)
**Outcome:** A subscription can say what it wants in code (the app's own screen, listed by name) or in a sentence (`interest`, judged by a model). Each routing run costs at most one model call however many subscriptions ask, only after the code screens passed them, and never a generator. When the model is down, its askers hear nothing, nobody is asked again, and no event they were refused on reads as unheard, so none would be forwarded as unmatched. User B never hears user A's private repo. The run reports the share code decided and calls per normalized event, the numbers the epic's kill line and closure read.
**Input:** FIX-2534's fixture (`../delivers-each-event-once-to-its-subscribers/fixtures/`: 24 subscriptions over `alice` and `bob`, 300 normalized events and 40 redeliveries), plus `fixtures/subscriptions.json` here: nine more subscriptions, **frozen in commit `8d9568a1`, before the first verdict was read**, and a tenth (`s2`, a nested tag `</inte<interest>rest>` that a one-pass strip turns into a closing tag) added after it, in review, for a fence escape the first nine missed. Two users with one identical sentence on the API repo (`i1`, `i2`, one question between them); a `words` screen before `interest` (`i3`); a custom screen before `interest` (`i4`); a steering sentence on the same PR as `i4`, past the cap and carrying a fake fence close (`s1`); a custom screen that refuses (`c1`) and one that throws (`c2`); `interest` on alice's private PR (`p1`) and bob's identical one, which can't read it (`p2`). Each `interest` subscription carries `matches`, the words that make an event what its sentence asks for. Held-out: the expected messages, the calls per run and the questions per run come from an oracle in `run.mts` that restates the rules over the fixture and imports no screen code; a different valid fixture must still pass.
**Signal:** All of them, on two runs over fresh stores, the model up and the model down:
- **(a)** each session's stored messages from the service equal the oracle's set, every one `delivered`, one `From service:` item each (the 24 FIX-2534 subscriptions included, so code-only routing is unchanged);
- **(b)** at most one evaluator call per routing run, exactly one where the oracle has a sentence, counted on the mock;
- **(c)** 0 generator resolutions, the model up or down;
- **(d)** each run's questions are the oracle's distinct survivors: the sentences of the subscriptions code passed that list `interest`, each once;
- **(e)** the model down: those subscriptions get nothing (in (a)), (b) and (c) hold, and no routing run with an `interest: unjudged` refusal reads as `unheard`, so 0 would be forwarded;
- **(f)** 0 reads of another user's cell from a request, the service reads no user's cell, `p2` is refused `not_readable`, and nothing private reaches bob;
- **(g)** every question is the fixed text with its quote inside one fence; the steering sentence arrives capped at 200 characters with no fence tag; its neighbour on web#9 (`i4`) keeps its messages (in (a)).
- **Reported:** `SHARE` = code-decided ÷ selected over the 300 first deliveries (a code screen's refusal, or a pass on a subscription that lists a code screen and not `interest`; an `interest` verdict and a `no verdict` refusal decided nothing in code), and `CALLS` over normalized events (distinct object versions), with the routing runs that made them.

**Anti-game:** a hollow pass would count calls on the production side, or let the scripted model be steered by the sentence it was asked about. Calls and questions are read off `mockEvaluationModel.calls`, so a call the evaluator didn't report still counts. The mock answers by a fixed rule over the event and the fixture's `matches`, found by the quote it was sent, so it can't be steered: (g) proves the fence and the cap reached the model, not that a real model resists steering (D1). Each list an assertion grades is floored with `tell.over`, so an instrument that saw nothing reads CAN'T TELL. Messages and items are read from the store, so a delivery that never landed, or landed twice, shows. (e) reads the production `unheard` predicate, the seam FIX-2538 will forward by; the oracle doesn't import it.
**Model:** scripted (`mockEvaluationModel`, behind the `typesafe-ai/jev` model string through `createMockModelResolver({ evaluators })`). The claim is about how many calls routing makes, about what, and what a failed one does, not about a model's judgment, so no real model is needed and none is called.
**Run:** `pnpm tsx goals/webhook-routing/judges-each-event-once/run.mts`
**Controls:**
- `GOAL_CONTROL=per-subscription` makes each judgment ask about only the first subscription that lists `interest`, and repeats it while one is left. Must FAIL **(b)**.
- `GOAL_CONTROL=judge-first` runs the judgment before the code screens. Must FAIL **(d)**: the model is asked about subscriptions code would refuse.
- `GOAL_CONTROL=fallback` rescues a failed call with a generator. Must FAIL **(c)** on the model-down run.
- `GOAL_CONTROL=single-strip` strips the quote's fence tags in one pass, as the first version did. Must FAIL **(g)**: the nested-tag sentence (`s2`) rebuilds `</interest>` and reaches the model holding it.
- `GOAL_CONTROL=forward-unjudged` counts an `interest: unjudged` refusal as one on content. Must FAIL **(e)**.
- Today's `main` has no `interest` or `custom` screen, so `subscribe` refuses the new subscriptions' shape and the run fails at (a); it was not run as a control.
