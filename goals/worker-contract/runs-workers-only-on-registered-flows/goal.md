# worker-contract › it runs workers only on registered flows

**Issue:** FIX-1789
**Outcome:** An app runs a worker only on a flow it registered as a worker flow. Before any worker runs, each registered flow is shown to take the configuration a real hire supplies, to have one door, and to declare any `writtenBy` as the contract's whole field. A flow kept for declared workers refuses a hired worker. The built-in `agent` keeps a worker's own state off org scope, and a shared note names who wrote it.
**Input:** `fixtures/workforce/` — five worker files (one per registered flow, `helper` on the built-in `agent` with one skill) — and `fixtures/flows.ts`: an app flow (`triage`), a coordinator whose delegates live in session state (`coordinator`, kept for declared workers), a flow writing a shared resource (`sharer`), a flow writing org data of its own on purpose (`org-keeper`), and three flows each breaking one rule (`doorless`, `numbered` with `seatId` as a number, `loose-attribution` with an optional `writtenBy`). `fixtures/input.json` holds the org, the two users, the worker ids, the note, and bob's own stored worker. Held-out: the ids, users and texts are read from the fixture and graded against what boot refuses and what the store holds.
**Signal:** on the real path — `readWorkforce`, `hireWorkforce`, `createFlowState` with in-memory stores, `runAction` for two users of one org, `reloadHiredSeats` — and no model.
(a) Hiring the files against all eight flows throws one boot error naming `doorless` (no door), `numbered` (`seatId`) and `loose-attribution` (`writtenBy`), naming none of the five that meet the contract, and saying nothing was hired. No worker names a broken flow, so the refusal is about the flows, not a worker.
(b) After alice's and then bob's run on `helper` (the built-in `agent`), every skills-drawer write alice's run made landed in user scope, none in the org's cells, and bob's run read or wrote none of the cells alice's run wrote. Alice's note through `sharer` is stored at org scope as `{ text, writtenBy: { userId: alice, workerId: support.scout } }`. The `org-keeper` flow, which writes org data by its author's choice, registered and wrote its row.
(c) Bob's hired worker (a stored roster row with his owner pin) naming `coordinator` is not reloaded: the reload's problem names `"coordinator"` and says it is kept for declared workers, and the stored row is byte-identical after. The declared `support.coord` on the same flow runs.
**Anti-game:** a hollow pass would grade what `workerFlowProblems` returns, or the flow's declarations. This check never calls the contract function: leg a reads the error `hireWorkforce` throws at boot; leg b records every read and write the real `agent` run makes against the store, and fails when alice's run wrote no drawer row at all (an empty set would pass the org check vacuously); leg c reads the reload's own problems and the stored row. Each broken flow is one an author could write and breaks exactly one rule; the `numbered` flow names every configuration key, so only the value is wrong.
**Model:** n/a — handlers and a scripted generator. The property is which flows boot and where a run's state lands, not model output.
**Run:** `pnpm tsx goals/worker-contract/runs-workers-only-on-registered-flows/run.mts`
**Controls:** none in the runner. The spec names today's `main` as the control, and the runner cannot load there: `workerFlows`, `sharedResource` and `writeShared` do not exist on `main`. So each leg's control reverts that leg's mechanism to `main`'s behaviour, one at a time, and must fail that leg only:
- In `packages/workforce/src/hire.ts`, comment out `checkWorkerFlows(flows);` (no registration check, as on `main`). Must FAIL `[a] the app … hired`.
- In `packages/workforce/src/agent-worker-flow.ts`, comment out `scope: "user",` (the drawer at the library's org default, as on `main`). Must FAIL `[b] alice's drawer rows are in the org's cells` and `[b] bob's run touched alice's drawer`.
- In `packages/workforce/src/hire.ts`, make the standard-only `if` false (no standard-only, as on `main`). Must FAIL `[c] bob's hired worker runs on the kept flow`.
