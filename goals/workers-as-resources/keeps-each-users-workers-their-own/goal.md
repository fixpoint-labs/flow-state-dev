# workers-as-resources › it keeps each user's workers their own

**Issue:** FIX-1788 (epic FIX-1786)
**Outcome:** In one org, each user's workers are theirs alone: another user can't open, read, run or create a session with them. Every worker runs on one shared copy of the flow it names, with its own memory on the built-in `agent`. A user hires or forks a worker without a restart and can't change a standard one.
**Input:** `fixtures/workforce/` — two `WORKER.md` standard workers on two flows: one on `agent` holding a skill, one on the app's own `research` flow. `fixtures/input.json` — the org, two users, the fork's and the hire's ids, the hire's instructions and the marker each worker's configuration carries. `fixtures/app.ts` — the app: `agent` bound to the installation, the `research` worker flow, and the roster flow with `hire`, `fork` and `fire`, behind a principal two headers name. Held-out: the standard workers' ids come from the tree and every other id and marker from the fixture, so another tree, other ids or other markers must pass too.
**Signal:** two processes of the app, each the real HTTP router over one on-disk SQLite file, the second started before anything is hired. Every call goes through the shipped clients (`createWorkforceClient`, `createSessionClient`, `createClient`).
(a) Alice forks the standard `agent` worker (`a:fork`) and hires one of her own (`a:hire`), and her roster lists both beside the standard workers, each with its flow (`a:roster`). `ensureWorkerSession` opens one session per worker, twice the same one, and a turn in each answers with its own configuration's marker and no other's: the standard worker and its fork (`a:standard`, `a:fork-answers`), the hire through the second process (`a:second-host`), and the `research` worker (`a:research`). Every agent turn asks for the standard worker's skill by name: the standard worker and the fork answer with it, and the hire, which holds none, doesn't (`a:own-memory`). Neither process's registry changes, and none holds a copy named for a worker (`a:one-copy`).
(b) Bob's roster lists none of Alice's workers (`b:reads-worker`); his `findWorkerSession` for her hire finds nothing (`b:find`); opening her session (`b:open`), running a turn in it (`b:run`) and creating a session naming her worker (`b:create`) are refused. A session created with no worker (`b:no-worker`), a turn whose input names a worker, on both flows (`b:names-worker`), a turn that moves a `research` session to another worker, after which the session still answers as its own (`b:reassign`), and Alice's hire, which runs on `agent`, given a session on `research` (`b:other-flow`) are each refused.
**Anti-game:** a hollow pass would read the session's stored `workerId` (proving what was written, not what a caller reaches), seed a worker row directly, register a copy per worker that happens to answer right, or let the model say whatever the check wants. So the check MUST NOT assert on a stored `workerId` or any key string; it MUST hire and fork only through the roster flow's actions; it MUST grade each answer by the markers the turn's prompt held, read back from the request's output over the routes; it MUST reach the hire through a process started before the hire; and it MUST count the registry, not trust that nothing was minted. A refusal counts only when the call threw or its run ended other than `completed`.
**Model:** n/a, a scripted model: `agent` answers with the markers its prompt held. Access is under test, not answers.
**Run:** `pnpm tsx goals/workers-as-resources/keeps-each-users-workers-their-own/run.mts`
**Controls:** `GOAL_CONTROL=org-scoped-workers` keeps the users' workers at org scope, in the app's wiring. It must FAIL leg b on `b:reads-worker` (Bob reads Alice's worker); `b:create` fails with it, and leg a stays green. `GOAL_CONTROL=no-create-check` drops the worker flows' create check. It must FAIL leg b on `b:create` (Bob's create naming Alice's worker writes a session); `b:other-flow` fails with it, and leg a stays green.
