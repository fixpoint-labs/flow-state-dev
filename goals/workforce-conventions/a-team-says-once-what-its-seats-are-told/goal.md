# workforce-conventions › a team says once what all its seats are told

**Issue:** FIX-1377 (optional `TEAM.md`; builds on FIX-1367's `WorkerConfig` admission and FIX-1389's shared team walk)
**Outcome:** Someone writes one house rule once, in their team's `TEAM.md`, instead of pasting it into every worker file on that team. Every seat on that team is given it — as a setting of its own, beside the seat's own instructions rather than merged into them — and a seat on a team that wrote no such file is given nothing extra, with nothing added to its bag at all.

**Why a non-agent kind.** The claim is about *every hireable kind*, not about the built-in `agent`. An end-to-end run of the agent kind would be green for a mechanism that only ever worked on the one kind that happens to compose a prompt, which is exactly the narrowness worth ruling out. The kind here calls no model, so a pass cannot be coming from anything an agent does.

**Input:** `fixtures/input.json` — the three seat ids, each one's own setting and instructions, the team layer's exact bytes, and the team's description. `fixtures/workforce/**` carries the same thing as files: `teams/pentest/TEAM.md`, two workers under it, and a `teams/billing/` with a worker and **no** `TEAM.md`. Held-out: every id, setting and instruction string is read from the fixture and graded against what the running blocks reported, so swapping any of them still passes a correct implementation. **Each seat's own `desk` differs from its schema's default on purpose** — a setting dropped on the way to the flow would otherwise read back as the default and pass.

**Signal:** against the real HTTP router (`createFlowApiRouter`) over on-disk SQLite stores, matching its siblings. The records come from the real loader (`readWorkforce`), never hand-built: the folders are half of what is under test.

(a) `readWorkforce` reads the tree with no errors of any of its three kinds and produces three records. `teams` carries **only** the team that wrote a file, and that record's `description` is the one the file declared — asserted here because nothing else consumes it yet, so a description validated and then dropped would otherwise go unnoticed. One `hireWorkforce` call turns all three records into seats of the non-agent kind.
(b) Each seat runs `POST /api/flows/<id>/<session>/actions/run` to completion. After closing the stores, reopening the same file and building a fresh host, `GET /api/flows/sessions/<session>/state` shows what a block **nested inside the action** read from `ctx.flow.config`: for the two seats on the team with a file, its team's instructions **and** its own, as two separate values matching the two files byte for byte, plus its own desk.
(c) The seat on the team with no `TEAM.md` carries **no `teamInstructions` key at all**, and its own instructions are unchanged. Absence is graded on `Object.hasOwn` inside the running block, not on the value: an empty string reads back falsy and would slip past a truthiness check, and absent-not-empty is precisely what this feature promises.
(d) The same key **is** present for the two seats whose team wrote one. Without this leg, (c) is equally consistent with the key never reaching anybody, which would pass every absence check in the file.

**Anti-game:** a hollow pass would assert the hires returned and the requests completed — true even when every seat holds nothing, or one shared layer. So the check MUST read the values back through `/state` rather than off the returned instance, because the claim is that the settings reached a RUNNING BLOCK and a bag asserted on the instance proves only the mint; MUST read from a **nested** block rather than the action root, since a root-only read proves nothing about the context spread that carries values down; MUST close the stores and rebuild the host first, so nothing is served from a live context; MUST compare both layers against the fixture's exact bytes, since a layer that arrived trimmed, reflowed or concatenated onto the other is the failure the two-settings decision exists to prevent; MUST assert the two values are not equal to each other, since one merged string written into both fields would satisfy a pair of presence checks; MUST assert the sibling team's seat holds NO layer, since one shared bag is always right for somebody; MUST grade that absence on the KEY rather than the value; MUST carry leg (d), or the absence in (c) is unfalsifiable; and MUST use a kind with no model, since an agent run cannot distinguish the contract from the agent kind's own prompt path.

**What this goal does NOT claim.** Nothing here says a seat's instructions *win* over its team's. The prompt order is a unit check elsewhere (`packages/workforce/test/team-instructions-seam.test.ts`), and even there it asserts position only: assembly is plain concatenation with no precedence mechanism, so which line a model follows when the two contradict is the model's behaviour, not the framework's.

**Model:** n/a — handlers only, by construction. The property under test is which settings reach a running block.
**Run:** `pnpm tsx goals/workforce-conventions/a-team-says-once-what-its-seats-are-told/run.mts`
