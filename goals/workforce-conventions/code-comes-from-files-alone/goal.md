# workforce-conventions › its code comes from files alone

**Issue:** FIX-1357; re-pointed by FIX-1611; rewritten by FIX-1792 P4; bundle leg restored by FIX-1879
**Outcome:** Someone adds a worker kind to their app by writing one file in `workforce/flows/workers/`, named from a `WORKER.md`, and it registers and runs. Nothing is written anywhere in the app's source to wire it: not on a `hireWorkforce` call, not in a barrel, not in a registry line. What registers the code is a committed module of static imports that `fsdev gen` writes and checks, and each worker on the kind runs on the settings its own file declares.
**Rewritten (FIX-1792 P4).** Legs (a) to (c) ran on kitchen-sink's one piece of workforce code, the `escalate` tool block: (a) counted the block's name in the compiled chunks of a real `next build`, (b) had a specialist file a case onto the help desk's `escalations` board over HTTP against `next start`, and (c) scanned the app for a hand registration of the block. The escalation feature was removed with the mailboxes (FIX-1792 BR-14), and with it the block, the board and the route the post went through; the app now carries no workforce code at all (its `workforce.gen.ts` maps are empty). So the three legs have no subject, and the `no-filing` control went with them. FIX-1879 brought the production-bundle guarantee back in two legs. **(a)** returns on the app's own build: kitchen-sink carries no workforce code now, so the leg plants one block file for the length of one build and removes it afterwards. That is the failure FIX-1429 fixed, the app's entry points never reaching `workforce.gen.ts`, and only the app's own build can catch it. **(e)** proves the same thing outside Next, on this folder's fixture host: an esbuild bundle run from outside the repository. The HTTP filing that (b) did and the source scan that (c) did are not restored; with no workforce code in the app, they have nothing to grade. The letters stay so the log reads straight, and its `fsdev gen --check` now runs from this folder, so the generator resolves from the goals package's dependencies (since FIX-1771 the command finds it in the nearest `package.json`, and the repository root's names none).
**Input:** Two subjects. **The app:** `apps/kitchen-sink/`, whose `workforce/hire.ts` imports `workforce.gen.ts` and is reached from the app's flow config; leg (a) plants one block in its `workforce/blocks/` for one build. **The fixture host,** `fixtures/workforce/`: one team (`support`), two workers (`ada`, `grace`) whose files both name `flow: desk-clerk` and declare different `desk:` values, one custom kind at `flows/workers/desk-clerk.ts`, and its committed `workforce.gen.ts`. Held out: `desk` is declared only in the two `WORKER.md` files and read only by the kind's own schema; nothing in the runner supplies it.
**Signal:** Three legs, model-free. **(a)** A block file named with a fresh `code-from-files-probe-…` token is planted in `apps/kitchen-sink/workforce/blocks/`; the app's own `fsdev gen` puts it on the generated module, the workspace packages are built (`pnpm packages:build`, as the app's deploy build and CI do), and `next build` builds the app. The token must then appear in compiled `.js` chunks under `.next` (not file-trace manifests), and the hand-wired `chat-agent`, `rich-text-component` and `weekly-digest` must appear too, as the positive control on the same probe. The plant and `workforce.gen.ts` are restored when the leg ends. **(d)** `fsdev gen --check` agrees the generated module is the tree's; the runner imports the kind's module by no route but the generated module; both workers hire from that module's `kinds` map onto `desk-clerk`; and each one's `answer` names the desk *its own file* declared (`front` for ada, `back` for grace), the two answers differing. **(e)** `bundled-host.mts`, whose only route to the kind is the same generated module, is bundled and minified with esbuild into one file; the bundle carries the kind's own answer block (`desk-clerk-answer`); written to an empty temporary folder outside the repository and run there with plain `node`, each worker answers with the desk its own file declared. PASS prints both legs' answers and the bundle's size; any mismatch is a FAIL.
**Anti-game:** A hollow pass would assert that two workers came back, which survives an implementation that hired both onto one shared configuration, or a runner that imported the kind by hand. So (d) grades a value only the discovered kind declares and only each worker's own file supplies: the two workers sit on **one** kind and differ only in `desk`, so anything keyed by kind rather than by worker gives both the same answer and fails. The runner reaches the kind only through the generated module, and says so by checking its own imports; `fsdev gen --check` is what makes the generated module the tree's rather than a file written to pass. Leg (e) is the deployment half: a host that found its kinds by scanning `flows/workers/` at run time passes (d) from the source tree and finds no folder beside the bundle, which is exactly what the `runtime-scan` control builds. The workers' `WORKER.md` records reach the bundle as data, because an app deploys them beside its code; the code is what the leg grades.
**Model:** none. The fixture's kind answers with a handler, and leg (a) only builds the app.
**Run:** `pnpm tsx goals/workforce-conventions/code-comes-from-files-alone/run.mts`
**Controls:** on the same command. Each names the assertions it must fail; the runner tags every failure `[leg:assertion]`.
- `GOAL_CONTROL=stripped-import` (this runner's): after `fsdev gen` writes the planted block onto kitchen-sink's generated module, its import and map entry are removed before `next build`. Must FAIL `a:chunks`, and nothing outside leg (a).
- `GOAL_CONTROL=shared-settings` (this runner's): both fixture workers hired on the first worker's settings. Must FAIL `d:answers` and `d:differ`, and nothing outside leg (d).
- `GOAL_CONTROL=runtime-scan` (this runner's): the bundle is built with the generated module swapped for one that lists `flows/workers/` beside the running code and imports what it finds. Must FAIL `e:bundled` and `e:answers`, and nothing outside leg (e).
