# workforce-conventions › its code comes from files alone

**Issue:** FIX-1357
**Outcome:** Someone adds a worker kind to their app by writing one file in `workforce/flows/workers/`, names it from a `WORKER.md`, and the seat hires and runs. No kind is written anywhere in the app's source — not on a `hireWorkforce` call, not in a barrel, not in a registry line — and the app behaves the same deployed as it does locally, because what registers the kind is a committed module of static imports rather than a scan that happens while the app runs.
**Input:** `apps/kitchen-sink/workforce/` — one team (`support`), two seats (`ada`, `grace`) whose files both name `flow: desk-clerk` and declare different `desk:` values, one custom kind at `flows/workers/desk-clerk.ts`, one custom block at `blocks/desk-note.ts`, and the committed `workforce.gen.ts`. Held out: `desk` is declared only in the two `WORKER.md` files and read only by the kind's own schema — nothing in the runner supplies it.
**Signal:** Both seats hire under `support.ada` and `support.grace`; each one's `answer` action, run over the real HTTP route **against the app as built for Next**, comes back naming the desk *its own file* declared (`front` for ada, `back` for grace); and a scan of `apps/kitchen-sink/**` outside `workforce.gen.ts` finds no literal that registers a kind. PASS prints both seats, both desks and the scanned file count; any mismatch is a FAIL.
**Anti-game:** A hollow pass would assert that two seats came back, or that the action returned 200 — both survive an implementation that hired every seat onto one shared configuration, or onto the built-in `agent` kind, which would not know `desk` at all. So the check grades on a value only the discovered kind declares and only the seat's own file supplies: the two seats sit on **one** kind and differ only in `desk`, so anything keyed by kind rather than by seat gives both the same answer and fails. The source scan is the inverse probe — it fails if the kind reaches the registry by any route other than the generated module, which is the only thing that makes "from files alone" true rather than merely convenient. Running against the **Next-built** app rather than the source tree is what makes it a check of the decision: a design that scanned the tree at run time passes on plain Node and returns an empty map here.
**Model:** none — the kind's action is a handler that reads its own settings; no model is contacted.
**Run:** `pnpm tsx goals/workforce-conventions/code-comes-from-files-alone/run.mts`
