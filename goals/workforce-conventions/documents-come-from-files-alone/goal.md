# workforce-conventions › a team's documents come from files alone

**Issue:** FIX-1354
**Outcome:** Someone drops a Markdown file into a team's `resources/` folder and that team has the document — no TypeScript written for it, nothing registered, and the document reaching a flow through the resource surface the framework already has. Documents every team shares and documents belonging to one team are both expressible, and which one a document is follows from where it sits. Two teams can each have a document of the same name without colliding. A folder that was meant to hold a document and doesn't gets named, so an app can refuse to boot short — the same bargain the worker loader already makes.
**Input:** `fixtures/workforce/` — an org-level `code-of-conduct`, two teams that each have a `handbook`, a folder where a file should be (`teams/marketing/resources/glossary/RESOURCE.md`, the mistake an author arriving from `workers/` makes), and a stray `notes.txt`. `fixtures/input.json` holds the expected refs, settings and per-document markers. Held out: nothing in the loader knows any of these values; swap the tree and `input.json` together for another valid pair and a correct implementation still passes.
**Signal:** The documents read are exactly the three refs the tree describes, keyed as the atlas keys them (`code-of-conduct` at org level, `teams/<id>/handbook` for a team's); each record's `declared` equals what its file wrote; each document's body contains the marker written only in its own file and none of another's; `errors` names exactly the folder-shaped slot; the stray file is not reported; and the records become a resource map `defineFlow` accepts with every body intact. PASS prints the documents, the reported slot and what the flow installed; any mismatch is a FAIL.
**Anti-game:** A hollow pass here would count documents, or assert `documents.length === 3`, or check that each record merely *has* a body — all of which survive a loader that hands every document the same content, or that keys by bare name. So the check must not assert on shape, on counts alone, or on any value the loader itself produced. It grades against the fixture: the marker tokens (`LANTERN-2208`, `THISTLE-6194`, `QUARRY-3157`) appear in exactly one file each on disk, so a body can only carry the right one if that file was actually read. The two same-named `handbook` documents are the cross-contamination probe — anything keyed by bare name collapses them and fails. The folder-shaped slot is the Decision-1 probe: skipping it in silence is exactly the failure the file-not-folder shape has to make loud. And the install step is run through the real `defineFlow`, so a ref form the framework would reject at startup fails here rather than in an app.
**Model:** none — the loader reads files and returns data, and the install half builds resource definitions; no model is contacted.
**Run:** `pnpm tsx goals/workforce-conventions/documents-come-from-files-alone/run.mts`
