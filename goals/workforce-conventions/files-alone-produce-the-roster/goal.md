# workforce-conventions › it produces the roster from files alone

**Issue:** FIX-1335
**Outcome:** Someone describes their AI workers in folders — one Markdown file each, grouped by team — points the app at the root, and the app has its workers: every one with its own identity, its own settings and its own instructions, and nothing registered anywhere in the path. A worker whose shape is code rather than a document is read too, with the path to that file recorded and never opened. A folder that was supposed to be a worker and isn't gets named, so the app can refuse to boot a worker short.
**Input:** `fixtures/workforce/` — two teams, a worker called `lead` in each, a thin seat with no instructions, a folder holding only a `worker.ts`, a folder holding both a `WORKER.md` and a `worker.ts`, a folder whose worker file is mistyped (`WORKERS.md`), and a team-level `resources/` folder. `fixtures/input.json` holds the expected identities, settings, per-worker body markers, and per-worker code paths with the marker written inside each of those files. Held out: nothing in the loader knows any of these values; swap the tree and `input.json` together for another valid pair and a correct implementation still passes.
**Signal:** The returned roster is exactly the four identities the tree describes; each record's `declared` equals what its file wrote; each worker's body contains the marker written only in its own folder and none of another worker's; each worker that has a `worker.ts` records a path that opens to a file carrying that folder's own marker, and every worker without one records nothing; `errors` names exactly the mistyped folder, and the `worker.ts`-only folder is **not** in it; `resources/` is not reported. PASS prints the roster, the code paths inspected and the reported slot; any mismatch is a FAIL.
**Anti-game:** A hollow pass here would count workers, or assert that `workers.length === 4`, or check that each record merely *has* a body or *has* a `codePath` — all of which survive a loader that hands every worker the same instructions, invents a default set, or fabricates a plausible path string. So the check must not assert on shape, on counts alone, on presence, or on any value the loader itself produced. It grades against the fixture: the body markers (`TIDEPOOL-4417`, `SANDPIPER-9023`) appear in exactly one folder each on disk, so a body can only carry the right one if that folder's file was read. The code markers (`KESTREL-7781`, `ALBATROSS-3312`) are written *inside* the `worker.ts` files, which the loader never opens — the goal opens the path the loader recorded and looks for them, so a recorded path can only pass if it points at the right file. The two same-named `lead` workers are the cross-contamination probe: anything keyed by bare name puts one body on both and fails. The thin seat is the inverse probe — it must come back with no instructions, so an invented default persona fails. And the `worker.ts`-only folder must appear in the roster and **not** in `errors`, so a loader that treats the second door as a near-miss fails rather than passing quietly.
**Model:** none — the loader reads files and returns data; no model is contacted.
**Run:** `pnpm tsx goals/workforce-conventions/files-alone-produce-the-roster/run.mts`
