# workforce-seats › a non-agent seat receives its skills

**Issue:** FIX-1367 (thin `WorkerConfig` admission for hireable kinds; builds on FIX-1356's skills file convention and FIX-1325's seat factory)
**Outcome:** An app defines a worker flow kind with **no model and no generator in it**, composes the admission contract into its settings schema, and hires two seats from a workforce tree that declares skills at three levels — an `org/skills/` folder, a team's, and one beside a worker. Each seat runs an action to completion through the real HTTP route, and a block **nested inside that action** reads the skills its own folders declared off `ctx.flow.config.seatSkills`, in level order. Neither seat holds the other's team-level or own-folder skills; both hold the org folder's. With the contract stripped from that same kind, the whole roster refuses at the hire, the message names the worker and the fix, and nothing is registered.

**Why a non-agent kind.** The claim this issue makes is about *every hireable kind*, not about the built-in `agent`. An end-to-end run of the agent kind would be green for a mechanism that only ever worked on the one kind that happened to declare the key — which is exactly the defect being removed. The kind here calls no model, so a pass cannot be coming from anything an agent does.

**Input:** `fixtures/input.json` — the two seat ids, each one's own setting, and the skill names each one's folders declare. `fixtures/workforce/**` carries the same thing as files: `org/skills/house-style/`, `teams/support/skills/triage-tone/`, `teams/support/workers/desk/skills/escalation/`, `teams/billing/skills/dunning/`, and a `WORKER.md` per seat. `fixtures/no-contract/` is the control tree. Held-out: every id, setting and skill name is read from the fixture and graded against what the running blocks reported, so swapping any of them still passes a correct implementation. **Each seat's own setting differs from its schema's default on purpose** — a setting dropped on the way to the flow would otherwise read back as the default and pass.
**Signal:** against the real HTTP router (`createFlowApiRouter`) over on-disk SQLite stores, matching its siblings in this family. The records come from the real loader (`readWorkforce`), never hand-built: the folders are half of what is under test.
(a) `readWorkforce` reads the tree with no errors and produces two records; one `hireWorkforce` call turns them into two seats of the non-agent kind.
(b) Each seat runs `POST /api/flows/<id>/<session>/actions/run` to completion. After closing the stores, reopening the same file and building a fresh host, `GET /api/flows/sessions/<session>/state` shows what a block **nested inside the action** read from `ctx.flow.config`: its own skill names as a **sequence** in level order (org, team, own), and its own desk.
(c) Neither seat's list equals the other's; neither holds a skill from the other's team or worker folder; both hold the org folder's.
(d) The same kind with `workerConfigSchema()` removed and nothing else changed: the hire throws, naming the worker and `workerConfigSchema()`, returns nothing, and the good seats' addresses 404 on a host built from what came back.

**Anti-game:** a hollow pass would assert the hires returned and the requests completed — true even when every seat holds an empty catalog, or one shared one. So the check MUST read the skills back through `/state` rather than off the returned instance, because the claim is that the bag reached a RUNNING BLOCK and a bag asserted on the instance proves only the mint; MUST read from a **nested** block rather than the action root, since a root-only read proves nothing about the context spread that carries the value down; MUST close the stores and rebuild the host first, so nothing is served from a live context; MUST compare the names as an ordered **sequence**, since a set check passes for a bag assembled backwards and level order is part of the promise; MUST assert each seat does NOT hold its sibling's folders, since one shared bag is always right for somebody; MUST use a kind with no model, since an agent run cannot distinguish the contract from the agent kind's own path; and MUST assert the control refusal left **nothing** registered, since a refusal after a partial hire is not a refusal.
**Model:** n/a — handlers only, by construction. The property under test is which settings reach a running block.
**Run:** `pnpm tsx goals/workforce-seats/a-non-agent-seat-receives-its-skills/run.mts`
