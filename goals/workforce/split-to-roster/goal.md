# workforce › it splits a task to its delegates

**Issue:** FIX-1997 (epic FIX-1996); rewritten for FIX-2081 (epic FIX-2056), where a task reaches only its filer's delegates, and for FIX-2077, where a split task stays running and its output is its worker's answer. Its spec's goal: `specs/issues/park-on-task/SPEC.md` → "The goal, and how we'll know it's met".

**Outcome:** a worker on a task can get a result from one of its delegates by filing a piece and ending its turn. Nothing runs while it waits. The piece's ending wakes it, and its task completes with the worker's own report as its answer. The person's desk hears the task end, never the piece.

**Input:**

- One in-process host on the real engine and a SQLite store, acted on over its HTTP router as one verified person (`goals/lib/client-actions`). The tree in `fixtures/workforce/`: `crew.desk` on a goal-local `desk` flow, the person's conversation, whose turn runs no model and records every message it is handed, delegate `crew.reporter`; `crew.reporter` (A) on the built-in `agent` flow and a real model, delegates `crew.helper`, `crew.keeper` and `crew.broken`; `crew.keeper` (B), `crew.broken` and `crew.helper` on a goal-local `taker` flow. B answers with the round's codename after a 4 s hold; `crew.broken` fails every attempt; `crew.helper` holds no codename.
- The person files each task for A from the desk with `createTask_tasks`, naming the delegate that keeps the codename. The ask doesn't mention `wait`, pieces or the task tools.
- Held out, made at run time: the codename, fresh per leg and held only in B's answer.

**Signal:** each failure is tagged `<leg>:<assertion>`.

- **1** `1:piece-to-delegate` A's task session filed a piece for its delegate `crew.keeper`. `1:waiting-while-b-works` read the moment A's own turn has ended while B's piece still runs, and nothing runs in A's task session: A's task is `in_progress`, waiting on its piece with no lease, and A's task session has no request running. A turn ends one of two ways, each after its end-of-request check has run: its request finalized (the task waits on `filed`), or it parked on the wait gate of B's piece, a `getTask` wait (the request `suspended`, the piece's wait slot naming it; the task waits on `wait`). A parked request runs nothing and holds nothing (FIX-2124). B's piece ending before A's turn does, or while a request still runs in A's task session, fails it too. An event, not a delay: it was read halfway through B's hold until 2026-10-22, which a model that took longer than 2 s to write its reply after filing could miss with nothing wrong. `1:report-is-output` A's task is `completed` with its output, the woken turn's report, holding the codename, after B's piece completed.
- **2** `2:reads-the-failure` `crew.broken`'s piece failed for good, a turn in A's task session was woken by that failure, and A's task ended through that turn: `completed` with its answer, or `errored` when it threw (FIX-2077 D3).
- **3** `3:settles-once` the host is stopped (no drain) the moment B's piece is `completed`, while A's task is still `in_progress` and no `onTaskSettled` request in A's task session has ended or started the turn it wakes (the request itself is filed with B's ending, so no poll sees one without the other), so the stop lands between B's ending and A's woken turn; then it starts again over the same store and the person lists the desk's tasks. A stop polled too late is set aside and tried again with a fresh task, up to 3 attempts. A's task completes, and the desk acted on its `completed` notice once and its turn was handed it once. The host is durable (it keeps wakes), so the notice the stop cut off is delivered again after the start: crash recovery of a notice needs durable execution (FIX-2078), and on a host without it the split task stays running. Every leg runs on that host.
- **4** `4:desk-hears-tasks-only` across legs 1 to 3, after a last `listTasks` on the desk, every notice the desk acted on and every notice turn it ran names a task the person filed, never a piece.

**Anti-game:** every grade reads the store (task rows, requests, session state) or what the desk's own turn was handed, never the model's tool arguments or prompt. The codename is fresh per leg and only B's answer holds it, so an answer holding it came through B. `1:report-is-output` reads the output, which is the last woken turn's answer; A's first turn ran before B answered, so only a turn woken by B's ending can hold the codename. Leg 3 says where the stop landed; a stop after A's task settled fails it rather than passing vacuously.

**Model:** real for A: the goals library's default model through the gateway (`gatewayModel(goalModel())`; `GOAL_MODEL` overrides). Gated on a key that serves it (`keysServing`); without one the run is blocked, not failed.

**Run:** `pnpm tsx goals/workforce/split-to-roster/run.mts`. `GOAL_LEGS=1,2,3,4` runs some legs. On demand only, never a CI gate.

**Controls:** each is a scratch patch to Workforce applied as the process loads it (`goals/lib/module-patch.mts`), printed by the run and refused when it never reached the code.

- `GOAL_CONTROL=first-answer`: only an answer given before the task first waited is noted (`task-board/task-request.ts`, `noteAnswer`). An answer from a request admitted while the task waits never counts, whether that request is a turn woken by B's ending (the task waits on `filed`) or a `getTask` wait's resume (it waits on `wait`). So when A ends its turn, the task completes with A's first answer, from before B answered. When A parks on a `getTask` wait, the task keeps waiting with no answer. Leg 1 must fail **`1:report-is-output`**, alone, on either path. Until FIX-2127 it patched only the woken turn's `noteTaskAnswer` (`conversation-board/task-settled.ts`), which a parked turn's resume never runs.
- `GOAL_CONTROL=hold-session`: a `getTask` wait holds its request open for 2 s past B's hold before it takes the piece's wait slot (`tasks/helpers/wait-on-task.ts`, before `markWait`), so A's turn runs on in its session while B works. Leg 1 must fail **`1:waiting-while-b-works`**, alone. Red only on a run where A waits with `getTask`; a model that ends its turn instead never reaches the patch.
- `GOAL_CONTROL=wake-coordinator`: a task session files on the board above it, the desk's (`conversation-board/board.ts`, the resolver's partition), and stamps the desk as the filer of what it files (`tasks/collection/get-or-create.ts`, the delivery's `ownSession`). So A's pieces land on the desk's board and their endings are delivered to the desk. Leg 4 must fail **`4:desk-hears-tasks-only`**. Leg 1 goes red with it (A's piece fails at the desk's hand-over, and A's task completes from its first turn); it has no isolating red state. A notice goes to a row's filer, not to the board's owner (FIX-2078), so until FIX-2127, when it moved only the partition, the desk heard nothing and leg 4 held.

**Before-state:** `main` at `ce4dbe52` (the merged spec, before FIX-1997) fails leg 1: A's `dispatchTask` for `crew.keeper` is refused `unknown_assignee`. Since FIX-2081 a task reaches only its filer's delegates, so `crew.keeper` is one of A's; a piece for a non-delegate is refused, which `goals/task-tools/five-tools-one-rule-per-field/` leg c grades. The `delegates-only` control is retired with the roster reach it put back.
