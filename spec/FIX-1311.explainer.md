# FIX-1311 — Default ChannelFlow / channel kind floor

## 1. Today

```mermaid
flowchart LR
  WORKER["WORKER.md"] --> MINT["record to flow instance"]
  MINT --> SEAT["one worker instance"]
  CHANNEL["a channel"] -.-> NOKIND["no kind to run on"]
  APP["the app"] -->|"hand-builds it, every time"| NOKIND
  POST["a post"] -->|"runs on the poster's turn"| APP
```

A worker in a file becomes one running flow instance. A channel has no kind behind it, so
every app assembles one, and the conversation ends up split across whoever spoke last.

## 2. After (proposed)

```mermaid
flowchart LR
  CH1["CHANNEL.md — standup"] --> BIND["openChannels"]
  CH2["CHANNEL.md — triage"] --> BIND
  BIND -->|"a named session each"| INST["one ChannelFlow instance"]
  INST --> S1["session: standup<br/>members · charter · transcript"]
  INST --> S2["session: triage<br/>members · charter · transcript"]
  CUSTOM["flow: my-channel"] --> INST2["that kind's own instance"]
  POST["a post"] -->|"request into the session"| S1
```

A channel kind is a flow kind: one built-in kind, one instance. A channel is a named
session on it, carrying its own members and transcript. Your own kind adds an instance,
not a copy per file.

## 3. Where the decision fell

```mermaid
flowchart TD
  ISSUE["FIX-1311"] --> KIND["the built-in kind, its binder, a fan-out slot the app addresses"]
  ISSUE --> MEMBERS["members and charter live in session state"]
  MEMBERS -.-> L1341["live join and leave: FIX-1341"]
  ISSUE --> PROOF["one session, one user: the author label carries attribution"]
  ISSUE --> BOUND["an unbound session id is not a channel"]
  ISSUE --> INPROC["posting from another flow: in-process hosts only"]
  ISSUE --> OUT["left alone: roster, delete, brief, housekeeper, CAS"]
  ISSUE --> OPENER["the opener for an undeclared channel"]
  OPENER --> COLLAB["still unowned, on the Collab side"]
  classDef gap stroke-width:3px,stroke-dasharray: 4 3
  class COLLAB gap
```

The floor is the kind, its binder, and an app-addressed fan-out slot. Three limits are
decided, not deferred: a session belongs to one user, an unbound id is refused, cross-flow
posting needs in-process dispatch. The undeclared opener stays unowned.
