# FIX-1352: W3 — Rooms file convention (system + dynamic; either-source) — Implementation Spec

## Part I — The Case *(for the human)*

### 1. Problem — why it matters, why now

An app can describe its workers in files today. Each worker is a folder with a `WORKER.md`
in it, and the app reads that folder at startup to find out who it employs. Nothing else
about a team can be described that way. The rooms those workers talk in, the resources they
share, the skills they can reach for — all of that still has to be written in code.

This epic adds file conventions for four of those things: rooms, channels, resources, and
skills. Rooms is first out of the gate, and that is the real stake here. Whatever rooms
does becomes the default the other three copy — where the folder sits, what the file's
header may say, what happens when someone mistypes it, what an error looks like. Get it
wrong and we pay for it three more times inside this epic, and then every app author pays
for it once per convention they learn.

**Why now** — the other three conventions are queued behind this one. They will be written
by different agents in different sessions. Absent a settled shape they will each invent
one, and the epic's back half turns into reconciliation work.

**The honest part.** Of the four, rooms is the *least* useful to ship on its own. A worker
file earns its keep the moment it is read, because hiring turns it into something that
runs. A room file has nothing equivalent: the thing that would seed a room, bind it to a
session or a board, or delete it, is Collab — and Collab is explicitly held out of this
epic. So this convention buys us a settled shape and one durable guarantee. It does not
buy a running feature. That is a legitimate thing to ship first, but it should be bought
with open eyes, and Decision 1 is where you do that.

### 2. Solution in plain terms

Keep the shape that already shipped and extend it. A room becomes a folder under its team
with a `ROOM.md` inside it, exactly as a worker is a folder with a `WORKER.md`. Reading the
tree reports bad folders instead of crashing, so one mistyped room never costs an app its
other rooms. One header key is required (`description`), one is refused by name, and
everything else an author writes is carried through untouched for whoever claims it later.

Two things are genuinely new, and both exist to preserve the guarantee FIX-1341 asked us
not to lose:

**A room may be declared in a file or in code, and the same room declared in both is
refused.** The app is told which room, and which two places declared it. There is no rule
that says one of them quietly wins.

**Whether a room counts as a "system" room is derived from where it was declared, never
written in the file.** An author cannot type a key that makes their room undeletable. That
is the whole reason the guarantee is worth anything once deletion exists.

**Philosophy** — tenet 2 (composition over features): a room is a convention over the
sessions, boards, and dispatch that already exist, not a new Channel type beside them.
Tenet 3 (earn every addition): the public surface grows by one reader and one reconciler,
and the directory walk is *shared* with the worker reader rather than copied into a second
355-line file. Tenet 5 (one convergence point for an invariant): the collision refusal
lives at the single place the two declaration sources meet, not at each of them.

**In tension with tenet 3, and worth naming:** an addition that nothing consumes has not
obviously earned its place. A room manifest is inert in W3. The case for shipping it anyway
is that it is the shape three more conventions inherit and the carrier of a lock that is
much harder to add retroactively — not that it does anything yet. Decision 1.

### 6. Decisions & rules — the sign-off surface

1. **W3 ships the room *declaration*. It does not ship the room *roster*.** The two-lane
   roster the issue describes — rooms seeded at boot, dynamic rooms minted by Collab
   helpers, system rooms enforced as undeletable — stays with Collab RC. W3 ships the file
   convention, the reader, and the reconciliation rule that the roster will later be built
   on.
   *Rejected:* building the two-lane roster now, as the issue's "desired outcome" reads
   literally. It cannot be built: there are no Collab helpers to mint a dynamic room and no
   delete verb for "undeletable" to refuse, so the dynamic lane would be a lane with
   nothing in it and the undeletable flag a guard over an operation that does not exist.
   *Locks in:* we accept a convention that does nothing until its first consumer lands. If
   the lab Proof (FIX-1355) does not end up declaring rooms in files, we will have shipped
   layout consistency and nothing else — recoverable, since it is one small reader we would
   delete, but it would mean this issue ran a cycle early and should have been sequenced
   after the lab instead.

2. **The same room id declared in a file and in code is refused at startup, naming both
   sources. There is no precedence rule.**
   *Rejected:* code-wins (file is a default) and file-wins (code is an override). Either
   one means an app can be running a room nobody can point to the declaration of, which is
   the failure mode this project has spent an epic removing.
   *Locks in:* an app that declares a room in both places stops booting instead of quietly
   running one of them. It also locks the *direction* of any future change: adding an
   explicit opt-in override later is additive and breaks nobody, whereas shipping a
   precedence rule now and tightening it later breaks every app that came to depend on it.
   We are choosing the reversible order.

3. **A room's `system` status is derived from the declaration path, and a `ROOM.md` that
   writes `system:` is refused by name.**
   *Rejected:* `system: true` as ordinary frontmatter an author writes.
   *Locks in:* when the delete verb exists, there is exactly one place to enforce
   "undeletable" and exactly one way a room can have become undeletable. No author, and no
   helper that writes a file, can mint an undeletable room by typing a key.

**Non-goals** — seeding rooms into anything; opening sessions, boards, or dispatch targets
from a room file; a delete verb or its enforcement; Collab helpers and the dynamic lane; a
`teams/<id>/team.md` as a third declaration source; and Channel / MessageBoard / TeamFlow
L1 types, per the epic's invent-kill.

**Size:** Small — 4 production files · 14 test behaviours · 1 doc surface · 1 PR.

### 3. Tradeoffs & alternatives

**The simpler approach, considered and rejected.** Copy `read-workforce-directory.ts`,
replace "worker" with "room", ship it. It is faster today and it is what will happen three
more times if this spec does not say otherwise — four near-identical directory walks, each
free to drift in how it refuses a symlink or reports an unreadable folder.

Rejected because the duplication is *already proven rather than hypothetical*. Two
directory readers exist today — `readWorkforceDirectory` in `workforce` and
`readSkillsDirectory` in `orchestration` — and both independently re-implement the same
things: refuse symlinks without following them, skip editor droppings, collect per-entry
failures into an `errors[]` instead of throwing, require a `description`. Extracting the
walk on the *second* caller is ordinary de-duplication. Waiting until the fourth is how a
convention drifts.

**The alternative on scope.** Ship nothing in W3 and fold rooms into Collab RC, where the
roster actually gets built. That is a coherent position and its argument is Decision 1's
own risk read back: an inert convention is a liability if nothing arrives to use it. It
loses because the shape question is real and immediate — three more conventions are queued
behind this one now, not when Collab opens — and because the either-source rule is far
cheaper to establish before there is a roster than to retrofit into one.

**What we are accepting.** A reader whose output nothing consumes until a later issue, and
a small amount of refactoring in a loader that currently works, justified by a second
caller rather than a fourth.

### 5. What using it looks like

An app declares two rooms in files and one in code, then reconciles them into one list.

```
workforce/teams/engineering/rooms/standup/ROOM.md
workforce/teams/engineering/rooms/incidents/ROOM.md
```

```md
---
description: Where the engineering team posts daily status.
members: [engineering.lead, engineering.analyst]
---

Post what you finished, what you're on, and what's blocking you.
```

```ts
import { readRoomsDirectory } from "@flow-state-dev/workforce/loader";
import { reconcileRooms } from "@flow-state-dev/workforce";

const { rooms, errors } = await readRoomsDirectory("./workforce");
if (errors.length) throw new Error(/* same fail-on-errors shape as workers */);

const roster = reconcileRooms(rooms, {
  declaredInCode: [
    { id: "engineering.escalations", declared: { description: "Paging channel." }, body: "" },
  ],
});
```

```ts
roster;
// [ { id: "engineering.escalations", system: true, origin: "code",  declared: {…}, body: "" },
//   { id: "engineering.incidents",   system: true, origin: "file",  declared: {…}, body: "…" },
//   { id: "engineering.standup",     system: true, origin: "file",  declared: {…}, body: "…" } ]
```

Declaring `engineering.standup` in code as well is the refusal:

```
reconcileRooms refused 1 of 4 rooms; nothing was reconciled:
  - room "engineering.standup" — declared in a file (teams/engineering/rooms/standup)
    and in code. A room's id is its identity and must have one declaration; there is no
    precedence rule. Remove one.
```

And a file that tries to declare its own status is refused when the tree is read:

```
errors;
// [{ path: "teams/engineering/rooms/standup",
//    error: Error('ROOM.md in "standup/" declares `system:`, which is not a setting a
//                  room declares. A room is a system room because it was declared, not
//                  because it said so.') }]
```

## Part II — The Build Plan *(for the implementing agent)*

### 7. Technical design

**Where the tree puts a room.** `teams/<teamId>/rooms/<roomName>/ROOM.md` — the `rooms`
slot sits beside `workers` under the same team folder, and a room is a folder holding a
fixed-name Markdown file, exactly as a worker and a skill are. The atlas's §06 tree already
draws `resources/` and `skills/` as siblings of `workers/`; `rooms/` joins them at that
level.

Folder-per-room rather than `rooms/<name>.md` is deliberate and is the point where this
spec is setting a precedent rather than following one. Both existing readers are
folder-per-thing with a fixed uppercase manifest inside, a room folder can later hold a
sibling file without a second convention being invented, and the cost is one directory
level for a folder that will often hold one file. That cost is real; consistency across
four conventions is worth more than removing it from one.

**Identity.** `<teamId>.<roomName>`, minted from the two folder names, with the same
segment rules the worker id already uses: lowercase letters, digits, single hyphens, 64
characters maximum, `_meta` reserved, and no `.` inside a segment because `.` is the
joiner. Reuse the existing validator rather than restating the rules. Note the honest
difference from workers: a worker id must avoid `/` because it becomes a route segment, and
a room id has no such proven constraint today — it is adopted for consistency and because a
room id is expected to become a session or board key, not because a failure has been
observed. Do not claim the routing justification for rooms.

**The record.**

```
RoomManifest {
  id: string                        // "engineering.standup"
  declared: Record<string, unknown> // frontmatter verbatim, minus nothing
  body: string                      // Markdown below the fences, or ""
}
```

Identical in shape to `WorkerManifest`, and deliberately so — an author and a consumer who
know one know the other. It lives beside `WorkerManifest`, node-free, so the reader and the
reconciler never hold two spellings of it.

**Two exports, split the way the package is already split.** The existing package draws a
hard line: `./loader` touches `node:fs` and the root stays isomorphic. Rooms follows it
exactly.

- `readRoomsDirectory(root)` → `{ rooms, errors }`, on the `./loader` subpath. Walks the
  tree, builds no roster, decides nothing. Same error contract as the worker reader:
  `errors[]` keyed by a slash-separated path relative to the root, structural folders
  reported under their own path when they cannot be listed, throws only when `root` itself
  is unreadable.
- `reconcileRooms(fileRooms, { declaredInCode })` → the roster, at the package root. No
  filesystem. Collects every problem and throws once naming all of them; returns nothing
  partially. This is `hireWorkforce`'s refusal discipline, reused rather than re-invented.

**The shared walk.** Extract what the worker reader and the room reader both need into one
internal module under `packages/workforce/src/loader/` — not a new public export. What
moves: `classify` (lstat without following symlinks, keeping `absent` and `unreadable`
distinct), `openStructuralDirectory`, the symlink and unreadable error wordings,
`IGNORED_ENTRIES`, and the segment validator. What does *not* move: anything that knows
what a worker or a room is. The reader for each slot supplies its slot folder name, its
manifest filename, its required key, and its refused key.

Keep it an extraction, not a framework. Do not build a generic "convention registry" or a
config-driven walker that the other three conventions plug into — that design should be
made when the third convention exists and its shape is known, not guessed at from the
second. Two callers justify sharing the walk; they do not justify parameterising it into a
product.

**Provenance, and why it is a field rather than a flag an author writes.** The reconciler
stamps each entry with `system: true` and `origin: "file" | "code"`. Both declaration paths
produce system rooms — that is what the lock means by "declared in code *or* under
`teams/<id>/rooms`". `origin` exists because the collision message has to name both places,
and because an operator debugging a roster needs to know where a room came from. Dynamic
rooms never travel this path at all; when Collab mints them they will carry `system: false`
and the reconciler will not be involved.

The refusal of a literal `system:` key belongs in the *reader*, where the file is, and it is
the rooms-specific instance of a pattern the package already has: `WORKER.md` refuses
`persona:` by name, in one shared message constant, checked in both the loader and the
factory because a hand-built record never passes the loader. Do the same here — check it in
the reader and again in the reconciler, since a code-declared room is exactly the hand-built
case.

**Where "undeletable" is enforced — and it is not here.** The question the issue asks is
answerable but the answer is "none of the three, yet." The loader cannot enforce it: it has
no store and no delete verb. The Collab helper must not be the enforcement point: a helper
is one path to deletion and anything that reaches the store directly goes around it, which
is a guard with a door beside it. Enforcement belongs to whatever owns the delete verb —
the roster store, in Collab RC. What W3 owes that store is the one thing it cannot
reconstruct later: an un-forgeable `system` stamp and a single place it was applied. Do not
build a guard in this issue for an operation that does not exist.

**What the other three conventions inherit.** This is the part of the design that is not
about rooms. Conventions 2–4 (FIX-1353 channels, FIX-1354 resources, FIX-1356 skills)
should take these as settled and deviate only with a stated reason in their own spec:

1. **Path shape.** `teams/<teamId>/<slot>/<name>/<THING>.md` — folder per thing, fixed
   uppercase manifest name, slot folder plural and lowercase, sitting beside `workers/`.
2. **Identity.** `<teamId>.<name>`, dot-joined, minted in one helper from the folder names,
   with the shared segment validator. The folder is the identity; a `name:` key in
   frontmatter is not a second spelling of it.
3. **Frontmatter dialect.** The one shared dialect (`splitFrontmatter` +
   `parseFrontmatterYaml` from `orchestration`). No second dialect, no per-convention YAML
   parser.
4. **Required and refused keys.** `description` required and non-empty. Unknown keys
   carried verbatim. Each convention may refuse *one* key by name where accepting it would
   let a file lie about something the framework decides — and that refusal is a shared
   message constant checked at every entry point, not just the file one.
5. **Error reporting.** `{ things, errors }`. Per-entry problems collected, never thrown.
   Structural folders reported under their own path when they cannot be listed. Throw only
   when the root itself is unreadable. Callers are told to treat a non-empty `errors` as
   fatal.
6. **Package split.** The reader touches `node:fs` and ships on a `./loader`-style subpath;
   anything that turns records into something the app uses stays isomorphic at the root.
7. **Two sources for one thing is a refusal, not a precedence rule** (Decision 2), and any
   status the framework grants is derived from the path, never declared in the file
   (Decision 3).

**What is rooms-specific and should not be copied blindly.** The `system` / `origin`
provenance pair exists because rooms have two declaration sources and a later deletion
guarantee; a convention with one source needs neither field, and inventing them for
symmetry would be cargo cult. The either-source reconciler itself is rooms-specific for the
same reason — resources and skills are declared in files only, as far as this epic's floor
goes. And the folder-per-thing call is the one most likely to genuinely not fit
**resources** (FIX-1354): if resources turn out to be many small declarations, a
folder each is heavy, and that spec is entitled to argue for `resources/<name>.md` —
provided it says so rather than drifting.

### 8. Implementation sequence

1. **Extract the shared walk.** Move `classify`, `openStructuralDirectory`, the symlink and
   unreadable wordings, `IGNORED_ENTRIES` and the segment validator into an internal module
   under `src/loader/`. `readWorkforceDirectory` now imports them. → *verify:* the 31
   existing `read-workforce-directory` tests and the 23 `hire` tests pass unchanged, with
   no edits to either test file. A diff that touches those tests means the extraction
   changed behaviour.
2. **Add `RoomManifest` and the refused-key constant** beside `WorkerManifest`. → *verify:*
   typecheck; the constant is imported by both the reader and the reconciler.
3. **Add `readRoomsDirectory`** on the `./loader` subpath, walking `teams/<id>/rooms/`. →
   *verify:* the reader's own test behaviours in §10, including each error class.
4. **Add `reconcileRooms`** at the package root, with the collision refusal and the
   provenance stamp. → *verify:* the reconciler behaviours in §10, including that a
   code-declared room cannot bypass the refused-key check.
5. **Export both** from the package's `index.ts` / `loader/index.ts`, and document them in
   the package README. → *verify:* an import of each from the package name resolves.

**Removals** — none. Nothing is being replaced; the extraction moves code without deleting
a public surface. If step 1 leaves any helper in `read-workforce-directory.ts` that is no
longer referenced, delete it in that step rather than leaving it behind.

### 9. Edge cases & error handling

Inherited from the worker reader and expected to behave identically — a room folder with no
`ROOM.md`; a `ROOM.md` with no frontmatter; a missing, empty, or non-string `description`;
a folder name breaking the segment rules; a symlink anywhere on the path, refused rather
than followed; a directory that exists but cannot be listed, reported under its own path; a
file (rather than a folder) sitting in the `rooms/` slot, skipped in silence because it does
not occupy a room slot; `.DS_Store` and friends ignored.

New to rooms:

- **`system:` declared in a file** → an `errors[]` entry naming the file, with the message
  explaining that the status is derived. Not a silent strip.
- **`system:` present on a code-declared record** → a `reconcileRooms` refusal. This is the
  second-path case: the reader never sees it.
- **The same id from both sources** → a refusal naming the id and both sources, collected
  with any others so one run names all of them, and nothing is returned.
- **The same id twice within the code-declared list** → the same refusal wording as
  `hireWorkforce`'s duplicate-roster case. A roster problem, reported with the rest.
- **No `rooms/` folder under a team** → not an error. A team may have no rooms; the walk
  simply does not go that way, matching how an absent `workers/` behaves.
- **`reconcileRooms` called with no code-declared rooms** → the file list, stamped, in id
  order. The option is optional.

13. Every collision in one run is named in a single refusal, not just the first.
14. A code-declared record carrying `system:` refuses — the second path around the reader.

**Why no site page yet, and what would change that.** `apps/docs` is published
documentation for people building on the framework. A page for rooms today could only
describe reading a file and getting a record back — the room does nothing, because nothing
binds it. Publishing that invites adoption of a surface with no runtime behind it, and the
page would then need rewriting the moment a consumer lands. The site page belongs with the
first consumer: whichever of FIX-1355 (the lab Proof) or Collab RC first makes a declared
room *do* something writes `rooms-on-disk.md` as a sibling to the existing
`workers-on-disk.md`, in the `Orchestration` sidebar category directly after it. If review
disagrees and wants the page now, the counter-argument is reasonable and this is a cheap
reversal — write it short, and say plainly in the lead what a room file does not yet do.

The internal atlas (`docs/atlas/workforce.html`, §06 and §14) describes the rooms roster as
proposed and Collab-later. Decision 1 keeps that description accurate, so no atlas edit is
required by this change; if Decision 1 is overturned, §14 needs updating in the same change
set.

### 12. Dependencies, open questions & follow-ups

**Dependencies.** None blocking. This issue touches `packages/workforce` only, and the two
in-flight W3 issues that also touch it are disjoint: FIX-1342 (kinds map / seat contract)
works on `hire.ts` and the seat teach, and FIX-1357 (kinds + blocks boot scan) is designing
the *code* registration door, not the document tree. The one file both this issue and
FIX-1342 could touch is `hire.ts`; this spec does not modify it, only reuses its refusal
wording as precedent. Sequence FIX-1352's PR after FIX-1342's merges if both are in flight,
to keep the workforce package's diff readable.

**Raised to the epic, not decided here — rooms and L2 channels may be one convention, not
two.** FIX-1353 asks for a file convention for "L2 channels as sessions/boards". On the
atlas's own description, a room *is* a named thing that binds sessions and boards, and a
channel is the session/board composition that backs it. If both issues ship a file
convention, the epic gets `ROOM.md` and `CHANNEL.md` declaring substantially the same
binding — the exact fragmentation this epic is trying to avoid. The shape proposed here is
deliberately compatible with folding them: a room's frontmatter carries uninterpreted keys,
so a `binds:` or `kind: dm | group` key can land later without a second file type. This is
a cross-cutting scope question about two issues, so it goes to the epic as a non-blocking
note rather than being settled inside this spec.

**Follow-up.** When the third convention (FIX-1354 or FIX-1356) is built, revisit whether
the shared walk should become a parameterised slot reader. Deliberately not done now — see
§7, "Keep it an extraction, not a framework."

**Noted for the implementer, not a blocker:** the lock in FIX-1341 names three declaration
sources — code, `teams/<id>/rooms`, and "team config". There is no team-level config file in
the tree today (the loader reads no file at the `teams/<id>` level), so this spec implements
two sources. Adding a team config file later would be a *third* way to declare a room, which
is precisely the shape Decision 2 exists to refuse; if it is ever wanted, it should replace a
source rather than join them.

## Spec evolution *(the change story)*

- **Spec drafted** — framed as the shape-setter for the epic's four file conventions rather
  than as a rooms feature, because rooms is inert until Collab and its real value now is the
  shape the other three inherit. Approach: extend the shipped `WORKER.md` convention to a
  `rooms/` slot, extract the shared directory walk on its second caller, and preserve the
  FIX-1341 lock with a collision refusal plus a derived `system` stamp rather than a
  precedence rule. Scope cut to declaration-only; the two-lane roster stays with Collab RC.
