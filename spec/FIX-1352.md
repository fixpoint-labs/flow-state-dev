# FIX-1352: W3 — Rooms file convention (either-source; declaration-only) — Implementation Spec

## Part I — The Case *(for the human)*

### 1. Problem — why it matters, why now

An app can describe its workers in files today. Each worker is a folder with a `WORKER.md`
in it, and the app reads that folder at startup to find out who it employs. Nothing else
about a team can be described that way. The rooms those workers talk in, the resources they
share, the skills they can reach for — all of that still has to be written in code.

This epic adds file conventions for four of those things: rooms, channels, resources, and
skills. Rooms is first out of the gate, and that is the real stake here. Whatever rooms
does becomes the default the other three copy — where the folder sits, what the file's
header may say, what an error looks like. Get it wrong and we pay for it three more times
inside this epic, and then every app author pays for it once per convention they learn.

**Why now** — the other three conventions are queued behind this one and will be written by
different agents in different sessions. Absent a settled shape they will each invent one,
and the epic's back half turns into reconciliation work. Rooms is also the *least* useful of
the four to ship alone: what would make a room do something is Collab, which is held out of
this epic. Decision 1 is where you buy that trade knowingly.

### 2. Solution in plain terms

Keep the shape that already shipped and extend it. A room becomes a folder under its team
with a `ROOM.md` inside it, exactly as a worker is a folder with a `WORKER.md`. Reading the
tree reports bad folders instead of crashing, so one mistyped room never costs an app its
other rooms. One header key is required (`description`), one is refused by name, and
everything else an author writes is carried through untouched for whoever claims it later.

Two rules are new, and both exist to preserve the guarantee FIX-1341 asked us not to lose:
a room may be declared in a file **or** in code, and the same room declared in both is
refused rather than silently resolved; and whether a room counts as a "system" room is
derived from where it was declared, never written in the file. Decisions 2 and 3.

**Philosophy** — tenet 2 (composition over features): a room is a convention over the
sessions, boards, and dispatch that already exist, not a new Channel type beside them.
Tenet 3 (earn every addition): the public surface grows by one reader and one reconciler,
and the directory walk is shared with the worker reader rather than copied. Tenet 5 (one
convergence point for an invariant): the collision refusal lives at the single place the two
declaration sources meet, not at each of them.

**In tension with tenet 3, and worth naming:** an addition that nothing consumes has not
obviously earned its place. Decision 1.

### 6. Decisions & rules — the sign-off surface

1. **W3 ships the room *declaration*. It does not ship the room *roster*.** The two-lane
   roster the issue describes — rooms seeded at boot, dynamic rooms minted by Collab
   helpers, system rooms enforced as undeletable — stays with Collab RC. W3 ships the file
   convention, the reader, and the reconciliation rule the roster will later be built on.
   *Rejected:* building the two-lane roster now, as the issue's desired outcome reads
   literally. It cannot be built: there are no Collab helpers to mint a dynamic room and no
   delete verb for "undeletable" to refuse, so the dynamic lane would be a lane with nothing
   in it and the undeletable flag a guard over an operation that does not exist.
   *Locks in:* we accept a convention that does nothing until its first consumer lands. If
   the lab Proof (FIX-1355) does not end up declaring rooms in files, we will have shipped
   layout consistency and nothing else — recoverable, since it is one small reader we would
   delete, but it would mean this issue ran a cycle early and should have been sequenced
   after the lab.

2. **The same room id declared in a file and in code is refused at startup, naming both
   sources. There is no precedence rule.**
   *Rejected:* code-wins (file is a default) and file-wins (code is an override). Either
   means an app can be running a room nobody can point to the declaration of, which is the
   failure mode this project has spent an epic removing.
   *Locks in:* an app that declares a room in both places stops booting instead of quietly
   running one of them. It also locks the *direction* of any future change: adding an
   explicit opt-in override later is additive and breaks nobody, whereas shipping a
   precedence rule now and tightening it later breaks every app that came to depend on it.
   We are choosing the reversible order.

3. **A room's `system` status is derived from the declaration path, and a `ROOM.md` that
   writes `system:` is refused by name.**
   *Rejected:* `system: true` as ordinary frontmatter an author writes.
   *Locks in:* when the delete verb exists, there is exactly one place to enforce
   "undeletable" and exactly one way a room can have become undeletable. No author, and no
   helper that writes a file, can mint an undeletable room by typing a key.

**Non-goals** — seeding rooms into anything; opening sessions, boards, or dispatch targets
from a room file; a delete verb or its enforcement; Collab helpers and the dynamic lane; a
`teams/<id>/team.md` as a third declaration source; and Channel / MessageBoard / TeamFlow
L1 types, per the epic's invent-kill.

**Size:** Small — 4 production files · 8 test behaviours · 1 doc surface · 1 PR.

### 3. Tradeoffs & alternatives

**The simpler approach, considered and rejected.** Copy `read-workforce-directory.ts`,
replace "worker" with "room", ship it. It is faster today and it is what will happen three
more times if this spec does not say otherwise — four near-identical directory walks, each
free to drift in how it refuses a symlink or reports an unreadable folder.

Rejected because the duplication is *already proven rather than hypothetical*. Two
directory readers exist today — `readWorkforceDirectory` in `workforce` and
`readSkillsDirectory` in `orchestration` — and both independently re-implement the same
things: refuse symlinks without following them, skip editor droppings, collect per-entry
failures into an `errors[]` instead of throwing, require a `description`. Extracting the
walk on the *second* caller is ordinary de-duplication. Waiting until the fourth is how a
convention drifts.

**The alternative on scope.** Ship nothing in W3 and fold rooms into Collab RC, where the
roster actually gets built. Coherent, and its argument is Decision 1's risk read back. It
loses because the shape question is real and immediate — three more conventions are queued
behind this one now, not when Collab opens — and because the either-source rule is far
cheaper to establish before there is a roster than to retrofit into one.

### 5. What using it looks like

An app declares two rooms in files and one in code, then reconciles them into one list.

```
workforce/teams/engineering/rooms/standup/ROOM.md
workforce/teams/engineering/rooms/incidents/ROOM.md
```

```md
---
description: Where the engineering team posts daily status.
members: [engineering.lead, engineering.analyst]
---

Post what you finished, what you're on, and what's blocking you.
```

```ts
import { readRoomsDirectory } from "@flow-state-dev/workforce/loader";
import { reconcileRooms } from "@flow-state-dev/workforce";

const { rooms, errors } = await readRoomsDirectory("./workforce");
if (errors.length) throw new Error(/* same fail-on-errors shape as workers */);

const roster = reconcileRooms(rooms, {
  declaredInCode: [
    { id: "engineering.escalations", declared: { description: "Paging channel." }, body: "" },
  ],
});
```

```ts
roster; // ReconciledRoom[]
// [ { id: "engineering.escalations", system: true, origin: "code",  declared: {…}, body: "" },
//   { id: "engineering.incidents",   system: true, origin: "file",  declared: {…}, body: "…" },
//   { id: "engineering.standup",     system: true, origin: "file",  declared: {…}, body: "…" } ]
```

Declaring `engineering.standup` in code as well is the refusal:

```
reconcileRooms refused 1 of 4 rooms; nothing was reconciled:
  - room "engineering.standup" — declared in a file (teams/engineering/rooms/standup)
    and in code. A room's id is its identity and must have one declaration; there is no
    precedence rule. Remove one.
```

## Part II — The Build Plan *(for the implementing agent)*

### 7. Technical design

**Where the tree puts a room.** `teams/<teamId>/rooms/<roomName>/ROOM.md` — the `rooms`
slot sits beside `workers` under the same team folder, and a room is a folder holding a
fixed-name Markdown file, as a worker and a skill are. The atlas (`docs/atlas/workforce.html`
§06) is canonical for this tree and already draws `resources/` and `skills/` as siblings of
`workers/`; `rooms/` joins them at that level.

Folder-per-room rather than `rooms/<name>.md` is the one place this spec sets a precedent
rather than following one. Both existing readers are folder-per-thing with a fixed uppercase
manifest inside, and a room folder can later hold a sibling file without a second convention
being invented. The cost is one directory level for a folder that will often hold one file;
that cost is real, and consistency across four conventions is worth more than removing it
from one.

**Identity.** `<teamId>.<roomName>`, minted from the two folder names using the *existing*
segment validator, not a restatement of its rules. One honest difference from workers: a
worker id must avoid `/` because it becomes a route segment, and a room id has no such
proven constraint today — it is adopted for consistency and because a room id is expected to
become a session or board key. Do not claim the routing justification for rooms.

**Two record types.** The input record mirrors `WorkerManifest` exactly, deliberately, so an
author and a consumer who know one know the other:

```
RoomManifest    { id, declared, body }              // what a file (or a code declaration) says
ReconciledRoom  { id, declared, body, system, origin }  // what the reconciler returns
```

`ReconciledRoom` is a named exported type, not an inline shape. It is what Collab RC will
consume and what the roster store will later check `system` on, so it needs one spelling
that both this issue and that one import — not a structural type each side re-derives.
`origin: "file" | "code"` exists because the collision message must name both places and an
operator debugging a roster needs to know where a room came from. Both declaration paths
produce `system: true`; dynamic rooms never travel this path at all, and when Collab mints
them they will carry `system: false`.

**Two exports, split the way the package already splits.** `./loader` touches `node:fs`; the
root stays isomorphic. Rooms follows that line exactly.

- `readRoomsDirectory(root)` → `{ rooms, errors }`, on the `./loader` subpath. Walks the
  tree, builds no roster, decides nothing. Same error contract as the worker reader.
- `reconcileRooms(fileRooms, { declaredInCode })` → `ReconciledRoom[]`, at the package root.
  No filesystem. Collects every problem and throws once naming all of them; returns nothing
  partially. This is `hireWorkforce`'s refusal discipline, reused rather than re-invented.

**The shared walk.** Extract what both readers need into one internal module under
`src/loader/` — not a new public export. What moves: `classify` (lstat without following
symlinks, keeping `absent` and `unreadable` distinct), `openStructuralDirectory`, the symlink
and unreadable error wordings, `IGNORED_ENTRIES`, and the segment validator. What does not
move: anything that knows what a worker or a room is. Each slot's reader supplies its slot
folder name, manifest filename, required key, and refused key.

Keep it an extraction, not a framework. Do not build a generic convention registry or a
config-driven walker for the other three conventions to plug into — that design should be
made when the third convention exists and its shape is known, not guessed from the second.

**The refused key.** Refusing `system:` in the reader is the rooms-specific instance of a
pattern the package already has: `WORKER.md` refuses `persona:` by name, in one shared
message constant, checked in *both* the loader and the factory because a hand-built record
never passes the loader. Do the same here — reader and reconciler — since a code-declared
room is exactly the hand-built case.

**Where "undeletable" is enforced — and it is not here.** The issue's question is answerable,
and the answer is "none of the three, yet." The loader has no store and no delete verb. The
Collab helper must not be the enforcement point: a helper is one path to deletion and
anything reaching the store directly goes around it, which is a guard with a door beside it.
Enforcement belongs to whatever owns the delete verb — the roster store, in Collab RC. What
W3 owes that store is the one thing it cannot reconstruct later: an un-forgeable `system`
stamp applied in a single place. Do not build a guard in this issue for an operation that
does not exist.

**What conventions 2–4 inherit — where to read it, not a copy of it.** The shipped
`WORKER.md` pair (`packages/workforce/src/loader/read-workforce-directory.ts` and
`hire.ts`) plus the atlas §06 tree are canonical for the general shape: path layout, dot-
joined team-qualified identity minted from folder names, the one shared frontmatter dialect
from `orchestration`, `description` required and unknown keys carried verbatim, the
`{ things, errors }` reporting contract, and the node-reader / isomorphic-root package split.
FIX-1353 / 1354 / 1356 should read those two files and deviate only with a stated reason in
their own spec. This spec does not restate those rules, because a restatement is a copy that
goes stale when the originals move and nothing fails when it does.

**What is rooms-specific and should not be copied.** Three things here are *not* the general
shape:

- **The `system` / `origin` provenance pair** exists because rooms have two declaration
  sources and a later deletion guarantee. A convention with one source needs neither field,
  and adding them for symmetry would be cargo cult.
- **The either-source reconciler** is rooms-specific for the same reason — resources and
  skills are file-declared only, as far as this epic's floor goes.
- **Folder-per-thing is the call most likely not to fit resources** (FIX-1354). If resources
  turn out to be many small declarations, a folder each is heavy, and that spec is entitled
  to argue for `resources/<name>.md` — provided it argues, rather than drifting.

What *should* generalise beyond rooms is the pair of rules in Decisions 2 and 3: two sources
for one thing is a refusal rather than a precedence rule, and any status the framework grants
is derived from the path rather than declared in the file.

### 8. Implementation sequence

1. **Extract the shared walk.** Move `classify`, `openStructuralDirectory`, the symlink and
   unreadable wordings, `IGNORED_ENTRIES` and the segment validator into an internal module
   under `src/loader/`. `readWorkforceDirectory` imports them. → *verify:* the 31 existing
   `read-workforce-directory` tests and the 23 `hire` tests pass **with no edits to either
   test file**. A diff touching those tests means the extraction changed behaviour.
2. **Add `RoomManifest`, `ReconciledRoom`, and the refused-key constant** beside
   `WorkerManifest`. → *verify:* typecheck; the constant is imported by both new modules.
3. **Add `readRoomsDirectory`** on the `./loader` subpath, walking `teams/<id>/rooms/`. →
   *verify:* §10 behaviours R1–R2.
4. **Add `reconcileRooms`** at the package root, with the collision refusal and the
   provenance stamp. → *verify:* §10 behaviours C1–C4.
5. **Export both** from `index.ts` / `loader/index.ts` and document them in the package
   README. → *verify:* an import of each from the package name resolves.

**Removals** — none; the extraction moves code without deleting a public surface. If step 1
leaves an unreferenced helper behind in `read-workforce-directory.ts`, delete it in that step.

### 9. Edge cases & error handling

**Inherited from the worker reader, and expected to behave identically** — a room folder with
no `ROOM.md`; no frontmatter; a missing, empty, or non-string `description`; a folder name
breaking the segment rules; a symlink anywhere on the path; a directory that exists but
cannot be listed, reported under its own path; a file rather than a folder in the `rooms/`
slot, skipped in silence; editor droppings ignored; an absent `rooms/` folder, which is not
an error because a team may have no rooms; a root with no `teams/`, which is empty; an
unreadable root, which throws. These are the worker reader's contract and are covered by
behaviour R1, not by ten restatements of it.

**New to rooms** — `system:` declared in a file (an `errors[]` entry, not a silent strip);
`system:` on a code-declared record (a `reconcileRooms` refusal, since the reader never sees
it); the same id from both sources; the same id twice within the code-declared list, using
`hireWorkforce`'s duplicate-roster wording; and `reconcileRooms` called with no code-declared
rooms, which returns the file list stamped and id-ordered.

**Not claimed:** that the workforce suite is green on this pin. `vitest` was not installed in

**Behaviours to test** (TDD, per the Feature label). The reader's inherited contract is
already pinned by the worker reader's 31 tests; rooms does not re-test it folder by folder.

Reader —
- **R1.** The reader honours the worker reader's contract on the rooms path: two rooms in one
  team load with team-qualified ids, verbatim frontmatter and body; and each error class
  (missing `ROOM.md`, bad `description`, bad segment name, symlink, unreadable structural
  folder) lands in `errors` under its own path rather than throwing. One table-driven test.
- **R2.** A `ROOM.md` declaring `system:` lands in `errors` with the derived-status message.

Reconciler —
- **C1.** File-declared and code-declared rooms merge into one id-ordered `ReconciledRoom[]`,
  each stamped `system: true` with the correct `origin`.
- **C2.** The same id from both sources refuses, naming the id and both sources, returning
  nothing.
- **C3.** Every collision in one run is named in a single refusal, not just the first.
- **C4.** A code-declared record carrying `system:` refuses — the second path around the
  reader.

**Regression guard for the extraction:** the existing 31 + 23 tests pass unmodified.

### 12. Dependencies, open questions & follow-ups

**Dependencies.** None blocking. This issue touches `packages/workforce` only, and the two
in-flight W3 issues that also touch it are disjoint: FIX-1342 (kinds map / seat contract)
works on `hire.ts` and the seat teach, and FIX-1357 (kinds + blocks boot scan) designs the
*code* registration door, not the document tree. This spec does not modify `hire.ts`, only
reuses its refusal wording as precedent. Sequence this PR after FIX-1342's if both are in
flight, to keep the package's diff readable.

**Raised to the epic, not decided here — rooms and L2 channels may be one convention.**
FIX-1353 asks for a file convention for "L2 channels as sessions/boards". On the atlas's own
description a room *is* a named thing binding sessions and boards, and a channel is that
binding. If both ship a file convention the epic gets `ROOM.md` and `CHANNEL.md` declaring
substantially the same thing. The shape here is deliberately compatible with folding them: a
room's frontmatter carries unknown keys verbatim, so a `binds:` or `kind:` key can land later
without a second file type. Noted on FIX-1351; not settled inside this spec.

**Follow-up.** When the third convention (FIX-1354 or FIX-1356) is built, revisit whether the
shared walk should become a parameterised slot reader. Deliberately not done now — §7.

**Noted for the implementer, not a blocker:** FIX-1341 names three declaration sources —
code, `teams/<id>/rooms`, and "team config". There is no team-level config file in the tree
today, so this spec implements two. A third source would be exactly the shape Decision 2
refuses; if it is ever wanted, it should replace a source rather than join them.

## Spec evolution *(the change story)*

- **Spec drafted** — framed as the shape-setter for the epic's four file conventions rather
  than as a rooms feature, because rooms is inert until Collab and its real value now is the
  shape the other three inherit. Approach: extend the shipped `WORKER.md` convention to a
  `rooms/` slot, extract the shared directory walk on its second caller, and preserve the
  FIX-1341 lock with a collision refusal plus a derived `system` stamp rather than a
  precedence rule. Scope cut to declaration-only; the two-lane roster stays with Collab RC.
- **After spec review** — retitled from "system + dynamic" to "either-source;
  declaration-only", because the old title advertised the dynamic lane that Decision 1 defers
  to Collab RC and a skimmer would expect two-lane roster work in W3. Compressed throughout
  (no direction change), and named `ReconciledRoom` as an exported type — the reconciler's
  output shape was previously unnamed, which would have left Collab RC and the implementer
  re-deriving it independently.
