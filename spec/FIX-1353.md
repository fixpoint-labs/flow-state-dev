# FIX-1353: W3 — L2 channels as sessions/boards (not Channel L1) — Implementation Spec

## Part I — The Case *(for the human)*

### 1. Problem — why it matters, why now

W3's floor asks for four file conventions. Two of them — rooms and L2 channels — are the
same thing named twice.

The rooms lock (FIX-1341) defines a room as a named thing that *"binds existing L1 sessions
/ boards / dispatch."* This issue defines a channel as collaboration that *"composes as
sessions/boards over existing dispatch."* One predicate, two spellings. The atlas goes
further and calls its four channel kinds **rooms**, the direct-message case included.

**Why now** — the rooms spec (FIX-1352) is in review and ships the reader for a declared
room. If this issue ships a second manifest beside it, every author declaring a team
afterwards has to guess which folder a thing goes in, and no rule in the tree answers the
guess. Cheap to prevent this week. A migration once apps have both trees.

### 2. Solution in plain terms

Fold this issue into rooms. One convention, one file type, one noun. "Channel" stays a
useful word for what a room is *for*, but it is not a second declared thing, so it gets no
file, no reader, and no folder.

The issue also asks for **composition** — making a declared room actually open a session or
fan a post out to a board. That half is not dissolved, it is already owned elsewhere
(Decision 2).

**Philosophy** — tenet 3 (earn every addition): the surface this adds is zero, which is the
right size for a concept that already exists under another name. Tenet 2 (composition over
features): the epic's invent-kill said no Channel *type*; the same argument one level up says
no channel *file*.

### 6. Decisions & rules — the sign-off surface

1. **A room is the L2 channel. This issue ships no `CHANNEL.md`, no reader, and no
   `channels/` folder.**
   *Rejected:* a second manifest sharing the room reader's dialect and identity rules. It
   reads cheap — same walk, different filename — but it buys nothing anyone could name, and
   it charges every future author a permanent question the tree cannot answer.
   *Locks in:* one folder for the thing people talk in. Reversible cheaply for roughly one
   release: while nothing in the repo declares a room, splitting the two later is renaming a
   folder. Once apps declare rooms in files, splitting is a migration.

2. **The composition half stays where it is already tracked — the board issue (FIX-1311) and
   Collab (FIX-1341). It does not move into W3.**
   *Rejected:* building the session/board binding here, as the issue's "file-convention **+
   composition**" reads literally. It cannot be built: nothing in the repo is a message
   board, the helper that would open a session for a team is unwritten, and seeding or
   binding a room at boot is Collab's roster, which this epic holds out by name.
   *Locks in:* W3 finishes as **three** file conventions plus the lab, not four.

**Non-goals** — a `CHANNEL.md`; a `channels/` slot; a channel reader; binding a room to a
session, board, or dispatch target; the message board; Collab's roster; Channel /
MessageBoard / TeamFlow L1. No documentation change and no atlas edit (§11).

**Size:** Zero production code. Four recordings (§8) — one comment and three Linear edits.

### 3. Tradeoffs & alternatives

Two file types (same reader, different manifest name) is the shape the floor implies, and
two readers is the heavier version of it. Both fail the same test: nothing could say what
makes a declaration a channel rather than a room. Membership, binding kind, and
declared-versus-minted each collapse back into rooms, and two readers additionally runs into
the epic's invent-kill and the shared-walk extraction FIX-1352 just argued for.

The alternative that would have kept this issue's slot is different in kind: give the rooms
convention its missing **consumer** — one helper that opens a session for a declared room.
It is buildable today and would answer FIX-1352's own stated risk. It is a Collab call and an
epic-level scope change, so it is raised in §12 rather than absorbed here.

### 4. Focus practices

**BP-003, narrowed to what a subtraction can prove.** The case rests on absence proofs, and
absence proofs expire — §10 states them as decision-time evidence with a date and a pin, not
as invariants the repo must keep.

### 5. What using it looks like

An author declaring a pentest team gets one place to put the thing the team talks in:

```
workforce/teams/pentest/rooms/findings/ROOM.md
```

```md
---
description: Where the pentest team posts findings.
kind: group
members: [pentest.scanner, pentest.analyst]
---

Post the finding, the asset it is on, and the severity you assessed.
```

No code reads `kind` today, and none needs to — the room reader carries unclaimed keys
verbatim (FIX-1352 §7), so a binding key lands with zero reader changes whenever Collab wants
one. What the author does **not** get is a second folder called `channels/`, and a standing
decision about which of the two to use.

## Part II — The Build Plan *(for the implementing agent)*

### 7. Technical design

**The atlas never proposed a channel manifest.** It names `WORKER.md` 45 times and names
neither `ROOM.md` nor `CHANNEL.md` once. The second file type entered at the epic floor's
wording, where *"L2 channels (sessions/boards)"* reads as a fourth sibling of rooms /
resources / skills rather than as the communication view of rooms. This is the one design
finding that is this issue's own.

**Everything else is already written down.** The record shape a channel file would have
declared (identity from folder names, required `description`, unclaimed keys carried
verbatim, the `{ things, errors }` contract), and the no-caller reasoning that defers
machinery with nothing to consume it, are FIX-1352 §7 and §12. Read them there; this spec
does not restate them.

**Where the composition half already lives:** a DM is atlas §16's `openDm` (proposed,
unwritten); a group is FIX-1311 (Backlog, nothing in `packages/` implements it); seeding and
the roster are FIX-1341 → Collab RC (held out of this epic by name). Nothing is unowned, and
building any of it here would be building Collab RC inside W3.

### 8. Implementation sequence

No code ships. Four recordings — one comment and three Linear edits:

1. **Answer FIX-1352's §12 open block** (*"rooms and L2 channels may be one convention —
   raised to the epic, not decided here"*) so it resolves rather than shipping unanswered.
   → *Status:* done — the Architect posted the answer on spec PR #1711.
   → *Fallback if it ever needs re-posting and #1711 has closed:* put it on FIX-1352's Linear
   document and issue instead. Once the spec PR closes, Linear is the durable copy and a
   comment on a closed PR is not where the next reader looks.
2. **Correct the epic's floor.** FIX-1351 item 2 ("L2 channels as sessions/boards") is
   removed; item 1 becomes the rooms/channels convention. → *verify:* the epic description
   lists three conventions plus the lab.
3. **Correct the lab's scope line.** FIX-1355 reads *"exercises rooms / L2 channels /
   resources / skills conventions."* Drop the third. → *verify:* the issue description.
4. **Close FIX-1353 as folded**, not as done, pointing at FIX-1352 and at §12's follow-ups.
   → *verify:* issue state and the closing comment.

**Removals** — the epic floor's item 2, and FIX-1355's channel clause. Nothing in
`packages/`.

### 9. Edge cases & error handling

**None — there is no runtime here to have edge cases in.** The two ways the *decision* could
be wrong, for completeness: if the composition half was the primary ask, this is a re-gate of
the epic's floor rather than a design answer (Decision 2); and if a channel later needs a
field a room must not have, it is a key on the room file until a key genuinely cannot express
it, so the cost of being wrong is one key, not one file type.

### 10. Testing strategy

**No behaviours to test — no code ships.**

**Decision-time evidence only.** These three ran at `7aa5ad4b0` to settle Decision 1. They
are absence proofs, so they go stale the moment the sibling issues ship — roughly when this
issue closes. They are why the decision was made, not an invariant to re-check later.

| Claim, at `7aa5ad4b0` | Command | Result |
| --- | --- | --- |
| The atlas never proposed a channel manifest | `grep -oE 'CHANNEL\.md\|ROOM\.md\|WORKER\.md' docs/atlas/workforce.html \| sort \| uniq -c` | `WORKER.md` ×45; the other two `0` |
| A `channels/` slot would be new — the loader walks one slot | `grep -oE '"(workers\|rooms\|channels\|resources\|skills)"' packages/workforce/src/loader/read-workforce-directory.ts` | `workers` ×2, nothing else |
| The message board (FIX-1311) is unbuilt, so a group channel binds to nothing | `grep -rEn '\b(subscribers\|subscription)\b' --include='*.ts' packages/orchestration/src/` | `0` matches |

FIX-1352 §10 carries the rest of the shared-convention evidence; it is not duplicated here.
The workforce suite is **not** claimed green on this pin — `vitest` is not installed in the
authoring worktree, and nothing in this spec depends on it.

### 11. Documentation plan

**No documentation change and no atlas edit.** Nothing user-facing moves — no export is
added, removed, or renamed, and no behaviour differs — and the rooms page that would carry
the vocabulary is already deferred to its first consumer by FIX-1352's docs plan. The one
instruction for whoever writes it is in §13. The atlas's own dual-noun wording is a separate
epic pass (§12), not a deliverable here.

### 12. Dependencies, open questions & follow-ups

**Dependencies.** None; no code ships.

**Raised to the epic, not decided here:**

- **The consumer reshape (§3)** — one helper that opens a session for a declared room. The
  strongest alternative use of this issue's slot, and it crosses the epic's Collab fence.
- **Every W3 convention is built before its only consumer.** The lab (FIX-1355) is sequenced
  last and is the first thing that would declare a room, resource, or skill in files.
  FIX-1352's Decision 1 names this for rooms; it is the epic's ordering, not a rooms problem,
  and it is cheaper to change now that one of the four conventions has dissolved.
- **The atlas still says "rooms / L2 channels" in several W3 places** (post-#1709). Manifests
  are unaffected, but authors keep meeting two nouns for one thing. Worth a separate atlas
  pass at the epic's convenience — deliberately not done in this issue.

**Open questions.** None.

### 13. Review notes for the implementer

- **For whoever writes the rooms documentation page** (FIX-1355 or Collab RC, per FIX-1352's
  docs plan): use *room* as the noun throughout, and say in one sentence that a room is what
  the team talks in — so a reader arriving with the word "channel" lands on the right page
  and stops looking for a second one.

## Spec evolution *(the change story)*

- **Spec drafted** — framed as the fold question the epic left open rather than as a channel
  feature. Verdict: one convention, one file type; this issue ships no code, the file half
  folds into FIX-1352, and the composition half stays on FIX-1311 and FIX-1341.
- **After spec review** — direction approved unchanged; what shrank was the document. The
  three-shape walk compressed to a paragraph, §7 now cites FIX-1352 instead of re-deriving
  it, the predicate-sameness argument is stated once and referenced after, and §10 keeps only
  the three fold-specific checks — now marked decision-time-only, because absence proofs go
  stale exactly when this issue closes. §8 gained a fallback for a closed #1711. All thirteen
  numbered sections stay: the template mandates them, so §4, §9 and §11 are compressed to one
  real answer each rather than dropped.
