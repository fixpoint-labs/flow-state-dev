# FIX-1353: W3 — L2 channels as sessions/boards (not Channel L1) — Implementation Spec

## Part I — The Case *(for the human)*

### 1. Problem — why it matters, why now

W3's floor asks for four file conventions. Two of them — rooms and L2 channels — are the
same thing named twice.

The rooms lock (FIX-1341) defines a room as a named thing that *"binds existing L1 sessions
/ boards / dispatch."* This issue defines a channel as collaboration that *"composes as
sessions/boards over existing dispatch."* One predicate, two spellings. The atlas goes
further and calls its four channel kinds **rooms**, the direct-message case included.

**Why now** — the rooms spec (FIX-1352) is in review and ships the reader for a declared
room. If this issue ships a second manifest beside it, every author declaring a team
afterwards has to guess which folder a thing goes in, and no rule in the tree answers the
guess. Cheap to prevent this week. A migration once apps have both trees.

### 2. Solution in plain terms

Fold this issue into rooms. One convention, one file type, one noun. "Channel" stays a
useful word for what a room is *for*, but it is not a second declared thing, so it gets no
file, no reader, and no folder.

The issue also asks for **composition** — making a declared room actually open a session or
fan a post out to a board. That half is not dissolved, it is already owned elsewhere
(Decision 2).

**Philosophy** — tenet 3 (earn every addition): the surface this adds is zero, which is the
right size for a concept that already exists under another name. Tenet 2 (composition over
features): the epic's invent-kill said no Channel *type*; the same argument one level up says
no channel *file*.

### 6. Decisions & rules — the sign-off surface

1. **A room is the L2 channel. This issue ships no `CHANNEL.md`, no reader, and no
   `channels/` folder.**
   *Rejected:* a second manifest sharing the room reader's dialect and identity rules. It
   reads cheap — same walk, different filename — but it buys nothing anyone could name, and
   it charges every future author a permanent question the tree cannot answer.
   *Locks in:* one folder for the thing people talk in. Reversible cheaply for roughly one
   release: while nothing in the repo declares a room, splitting the two later is renaming a
   folder. Once apps declare rooms in files, splitting is a migration.

2. **The composition half stays where it is already tracked — the board issue (FIX-1311) and
   Collab (FIX-1341). It does not move into W3.**
   *Rejected:* building the session/board binding here, as the issue's "file-convention **+
   composition**" reads literally. It cannot be built: nothing in the repo is a message
   board, the helper that would open a session for a team is unwritten, and seeding or
   binding a room at boot is Collab's roster, which this epic holds out by name.
   *Locks in:* W3 finishes as **three** file conventions plus the lab, not four. If you would
   rather W3 shipped something that makes a room *do* something, that is a bigger epic and
   should be asked for as one — see the reshape in §3.

**Non-goals** — a `CHANNEL.md`; a `channels/` slot; a channel reader; binding a room to a
session, board, or dispatch target; the message board; Collab's roster; Channel /
MessageBoard / TeamFlow L1.

**Size:** Zero production code. One rule settled, two scope lines corrected, one issue
closed (§8).

### 3. Tradeoffs & alternatives

Three shapes were priced.

**One convention, two file types** — same reader, same dialect, different manifest name.
This is the shape to beat, because it is what the epic's floor implies. It loses on a
question nothing could answer: *what makes a thing a channel rather than a room?* Every
candidate collapsed. Membership? Rooms have members. Binding kind? The lock already has one
room binding sessions *and* boards. Declared versus minted? That is the lock's own two lanes,
and a minted thing has no file at all. A convention that cannot state its own membership test
is one authors get wrong quietly and repeatedly.

**Two conventions, two readers** — dead on the epic's invent-kill, and on the shared-walk
extraction FIX-1352 just argued for. Nothing discharged the burden.

**The reshape worth naming, and rejected rather than ignored:** give the rooms convention its
missing *consumer* instead — one helper that opens a session for a declared room. Buildable
on what ships today, and it would answer FIX-1352's own stated risk that W3 ships a
convention nothing uses. It loses because it is Collab's row on the atlas, not W3's, and
because it is a different issue than the one written. Raised to the epic (§12).

### 4. Focus practices

- **BP-003 (verification evidence).** Every claim here was executed or read out of the named
  source, not recalled — §10 carries the commands, including the one claim narrowed rather
  than asserted because the suite cannot run in this worktree.
- **BP-039 (lead with the problem).** The finding leads; the derivation is §3 and §7.
- **Tenet 3 (earn every addition).** The deliverable is a subtraction. Attaching a token
  deliverable so the issue feels worked is the failure mode to resist.

### 5. What using it looks like

An author declaring a pentest team gets one place to put the thing the team talks in:

```
workforce/teams/pentest/rooms/findings/ROOM.md
```

```md
---
description: Where the pentest team posts findings.
kind: group
members: [pentest.scanner, pentest.analyst]
---

Post the finding, the asset it is on, and the severity you assessed.
```

No code reads `kind` today, and none needs to — room frontmatter carries unclaimed keys
verbatim, so a binding key lands with zero reader changes whenever Collab wants one. What the
author does **not** get is a second folder called `channels/`, and a standing decision about
which of the two to use.

## Part II — The Build Plan *(for the implementing agent)*

### 7. Technical design

**The vocabulary, quoted rather than argued.**

| Source | Says |
| --- | --- |
| FIX-1341 lock, and atlas §14 | A room is L2; rooms *"bind existing L1 sessions / boards / dispatch."* |
| FIX-1353 (this issue) | A channel is L2; channels *"compose as sessions/boards over existing dispatch."* |
| Atlas §08, routing matrix | Its four *channel* kinds are labelled *"Four rooms"* — DM included — and its table is the *"Talk / Room table."* |

The two definitions are the same predicate. §08 and §14 are two *views* of one noun (how it
is delivered; what is on the roster), not two nouns.

**What a second file type would have had to declare.** Identity (`<teamId>.<name>` from
folder names), a required `description`, a member list, and which L1 shape it binds to. The
first three are the room record exactly. The fourth is a frontmatter key.

**Why folding is compatible rather than lossy.** FIX-1352's reader carries unknown
frontmatter keys through untouched, so `kind: group` is already legal today and arrives
unchanged at whatever claims it. A *validated* enum is deliberately not proposed: the binding
taxonomy has two members on the atlas and zero consumers in code, so an enum shipped now is
one we would widen before anything read it.

**Where the composition half already lives.**

| The ask | Its existing home | State |
| --- | --- | --- |
| A DM — one static session with one worker | Atlas §16 `openDm`, a thin L2 helper over `create_session` | Proposed, on W2's row; unwritten |
| A group — a board plus one session per subscriber | FIX-1311, the message board | Backlog; nothing in `packages/` implements it |
| Seeding rooms, binding them, the system/dynamic roster | FIX-1341 → Collab RC | Held out of this epic by name |

Nothing here is unowned. Building any of it under FIX-1353 would be building Collab RC
inside W3.

**The no-caller test, applied one level up.** FIX-1352 deferred its reconciler because
nothing declares a room in code, so the machinery would guard a door nobody uses. The same
test run here is stricter: a channel convention would have no caller on *either* side —
nothing declares a channel, and nothing consumes one. A file type in that position is not a
door with no caller, it is a second name for a door that already exists.

**No atlas edit is required, and that is itself the finding.** The atlas names `WORKER.md` 45
times and names neither `ROOM.md` nor `CHANNEL.md` once. It never proposed a channel
manifest. The second file type entered at the epic floor's wording, where *"L2 channels
(sessions/boards)"* reads as a fourth sibling of rooms / resources / skills rather than as
the communication view of rooms.

### 8. Implementation sequence

No code ships. Four recordings, in order, once Decision 1 is approved:

1. **Answer FIX-1352's open block.** Its §12 carries *"rooms and L2 channels may be one
   convention — raised to the epic, not decided here."* Post this spec's answer on its spec
   PR so that block resolves instead of shipping unanswered. → *verify:* the comment lands;
   FIX-1352's author confirms nothing in their spec changes (it should not — their shape is
   already fold-compatible, which is why this was answerable at all).
2. **Correct the epic's floor.** FIX-1351 item 2 ("L2 channels as sessions/boards") is
   removed; item 1 becomes the rooms/channels convention. → *verify:* the epic description
   lists three conventions plus the lab.
3. **Correct the lab's scope line.** FIX-1355 reads *"exercises rooms / L2 channels /
   resources / skills conventions."* Drop the third. → *verify:* the issue description.
4. **Close FIX-1353 as folded**, not as done, with a pointer to FIX-1352 and to §12's
   follow-up. → *verify:* issue state and the closing comment.

**Removals** — the epic floor's item 2, and FIX-1355's channel clause. Nothing in
`packages/`.

### 9. What could make this wrong

Not runtime edge cases — there is no runtime. Three ways the fold could be the wrong call,
and what each would look like:

- **The composition half was the primary ask, not the file half.** Then the answer is not
  "fold" but "this is Collab, which the epic holds out" — a re-gate of the epic's floor
  rather than a design question. Decision 2 is where that shows up; it is flagged at the gate
  rather than decided quietly.
- **A channel needs a field a room must not have.** Nothing found. If one appears, it is a
  key on the room file until a key genuinely cannot express it — the reader already carries
  unclaimed keys, so the cost of being wrong here is one key, not one file type.
- **A third binding kind appears.** Costs nothing, because the key is unvalidated by design
  (§7).

### 11. Documentation plan

**No documentation change, and no atlas edit.** Nothing user-facing changes: no export is
added, removed, or renamed, and no behaviour differs. The only place a reader could be
misled is the rooms page, which FIX-1352's plan defers to the first consumer. One instruction
for whoever writes it is recorded in §13 — it is a sentence in a future page, not a page this
issue ships.

### 12. Dependencies, open questions & follow-ups

**Dependencies.** None blocking; no code ships. The only coupling is to FIX-1352: approving
this answers the block its §12 raised.

**Follow-ups, both raised to the epic rather than decided here:**

- **The reshape from §3** — one helper that opens a session for a declared room, giving W3's
  conventions a consumer instead of a fourth convention. It is the strongest alternative use
  of this issue's slot, and it crosses the epic's Collab fence, so it is the epic's call.
- **Every W3 convention is built before its only consumer.** The lab Proof (FIX-1355) is
  sequenced last and is the first thing that would declare a room, a resource, or a skill in
  files. FIX-1352's Decision 1 names this risk for rooms; it is not a rooms-specific risk, it
  is the epic's sequencing. Worth the epic's attention now that one of the four conventions
  has dissolved and the ordering is cheaper to change.

**Open questions.** None. The gate is Decisions 1 and 2.

### 13. Review notes for the implementer

- **For whoever writes the rooms documentation page** (FIX-1355 or Collab RC, per FIX-1352's
  docs plan): use *room* as the noun throughout, and say in one sentence that a room is what
  the team talks in — so a reader arriving with the word "channel" lands on the right page
  and stops looking for a second one.

## Spec evolution *(the change story)*

- **Spec drafted** — framed as the fold question the epic left open rather than as a channel
  feature, because the two definitions in play are the same predicate and the atlas already
  treats them as one noun. Verdict: one convention, one file type; this issue ships no code,
  the file half folds into FIX-1352, and the composition half stays on FIX-1311 and FIX-1341
  where it is already tracked. The reshape that would have kept the slot — a helper giving the
  rooms convention a consumer — is priced in §3 and raised to the epic rather than absorbed.
