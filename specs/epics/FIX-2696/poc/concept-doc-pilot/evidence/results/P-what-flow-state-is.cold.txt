**R1. What is an app in Flow State?**
The page does not say. It never defines "app" formally. It uses "app" informally (e.g., Desk) for what Alice builds: a server started from `fsdev.config.ts` that combines installed kits, her own flows, owned files like `workforce/`, and pages in `src/app/`.

**R2. What is a kit?**
A kit is a feature an app installs with one config object, such as `workforce`, `harnesses` or `claudeCode`. Kits can be listed in any order, and a kit that depends on another (like `claudeCode` on `harnesses`) loads after it. A kit changes another kit only through slots the other leaves open.

**R3. What is a flow?**
A flow is what the server serves: named actions, each running a tree of blocks, plus the state they keep. Alice writes her own (like `triage`) and lists it in `flows`. Kits can also install flows (e.g., `harnesses` installs `coder`), and `agent` is the built-in flow that answers with a model and tools.

**R4. What is a block?**
A block is one typed step in a flow, such as a model call, plain code, a check or a choice between paths. In `triage`, one block labels a request and the next files a ticket. The page says there are five kinds, but only names these four.

**R5. Which one do you change for each?**
(a) A worker's instructions: the body of its `WORKER.md`. (b) Adding a whole feature such as coding agents: the kit config, or the slot fill, in `fsdev.config.ts`. (c) One step inside how a request is handled: edit that block in your flow.
