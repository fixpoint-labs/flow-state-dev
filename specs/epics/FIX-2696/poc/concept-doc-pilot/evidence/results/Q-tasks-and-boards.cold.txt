**P2.1.** The other two research tasks are unaffected. A failure doesn't stop other tasks, so they keep running and can finish as `completed`. Compare can never run, so the board cancels it, labels it `skipped`, and records which task caused it. When nothing is ready and no worker is active, the board stops with "Blocked by failures".

**P2.2.** The page does not say that a newly added task runs on its own. Tasks persist as rows in the collection's scope, so they outlive the request. They get worked when the `drain` action is run, and tasks added while a drain is running are picked up. The page's own examples rerun the drain (for example after a user answers a hold), which suggests a new drain run is needed for tasks added afterward.
