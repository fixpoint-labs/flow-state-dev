**R1.** An app is what Flow State hands you instead of just parts: a team of AI workers (agents briefed in plain files), a page to talk to them, and a backend that streams answers, keeps what they learned, and resumes runs after a crash. The code is in your repo and the data is in your database.

**R2.** A kit is a feature you install, a bundle an app lists in its config (e.g. `fsdev.config.ts`). It brings its flows, the files it reads from your repo, and its views, and it can open slots for other kits to fill.

**R3.** A flow is a backend you call over HTTP. A client runs one of its actions (such as `chat`), and the flow streams results back as they are produced and keeps typed state between calls. Flows are built from blocks.

**R4.** A block is one of the typed pieces that flows (and so kits) are built from. There are five kinds: generator, handler, sequencer, router and evaluator. Blocks can nest, and any block can be handed to a model as a tool.

**R5.** (a) A worker's instructions: edit its Markdown `WORKER.md` file (the starter layer). (b) A whole feature such as coding agents: add a kit to the config. (c) One step inside how a request is handled: change a block, since flows are built from blocks.
