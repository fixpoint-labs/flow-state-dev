## 3. RIGHT claims

About 45 claims checked out. Ten representative ones:

1. **Frontmatter:** `description` is the only required line in a `WORKER.md`. `packages/workforce/README.md:115`
2. **Refused keys:** a file may not declare the framework-supplied settings (`workerSkills`, `workerTools`, `workerPackages`, `workerId`, `teamInstructions`). They are refused by name. `README.md:112`, `worker-config.ts:123`, `:132`
3. **Door:** `respond` is the one public action that takes `{ message }`. `worker-door.ts:30`, `:73-101`
4. **Roles:** `contributor`, `manager` and `coordinator` are the roles. The built-in `agent` flow is a contributor, plus manager when given a board. The built-in coordinator flow has all three. `worker-roles.ts:40`; `agent-worker-flow.ts:1492`; `coordinator-flow.ts:1811`
5. **Standard workers are read, not stored:** they are read from the files each time, and editing one makes the user's own copy under the same id, read before the file. Reset deletes the copy. `workers/standard-workers.ts:3-12`; `workers/hire-blocks.ts:11-14`, `:262-277`
6. **Own-worker storage:** an own worker is a row at `workforce/workers/*` in user scope. `workers/keys.ts:15`
7. **Hire, fork and fire:** all three refuse a standard worker's id. Every write is checked against the flow's schema first, and a refused write changes nothing. `hire-blocks.ts:138-151`
8. **Roster view:** it is user-scoped and keyed by worker id. A standard worker the user edited is listed once, as their copy, still standard, on its file's team, with `edited: true`. `workers/roster-view.ts:49-100`
9. **Delegates:** the check passes only if the worker is on this user's roster now, its row can be read, and its flow declares `contributor`. Another user's worker gets the same answer as one that doesn't exist. `delegates/delegate-check.ts:62-77`. A standard worker may name only standard workers, and the session list is copied once from the worker's default. `worker-config.ts:195-215`
10. **Session ids:** the id is derived from user, org, flow and criteria. A create at another user's derived id is refused, and a racing create reads the winner back. `workers/derive-session-id.ts:1-17`, `:171`
